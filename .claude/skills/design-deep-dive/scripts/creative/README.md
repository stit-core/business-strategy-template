# Утилиты creative

Утилиты подачи сайта: проверяют арт-дирекцию, подачу секций в плане страницы, спецификацию движения, каталог стека и
реестр клише, прогоняют собранную или сверстанную страницу по визуальным проверкам и воротам эффектов, собирают
референсы. Нормы и числа живут в базе `kb/creative/` и у соседей; утилиты их читают, а не держат в коде: база, соседние
утилиты, выходы и блокировки находятся через `../lib/kbpaths.py`, запуск — Python окружения скилла (`$DDD_HOME/venv`,
`../install.sh`). Выходы по умолчанию — `$DDD_HOME/out/creative/<утилита>/` или ключ `--out`; в репозиторий утилиты не
пишут. Утилиты с браузером берут замок браузера сами (`kbpaths.lock('browser')`; вложенный вызов из процесса, который его
уже держит, не ждёт, внешняя обёртка `flock` не нужна) и ждут свободной памяти; клиент референсов держит свой слот
`browser-refs`. `ffmpeg` и `ffprobe` утилиты находят через `kbpaths` (`DDD_FFMPEG`, `DDD_FFPROBE`, `$DDD_HOME/bin`, PATH).

| утилита | что делает | самопроверка |
|---|---|---|
| `spec_check.py` | подача секций в плане, спецификация движения, варианты подачи блоков, проекции для входа холста, форма ключа `x-canvas-map` | `--selftest` |
| `ad_check.py` | арт-дирекция поверхности сайта: файл проекта или примеры базы | `--selftest` |
| `validate_stack.py` | каталог стека `../../kb/creative/07-stack-implementation/stack.yaml` | `--selftest` |
| `registry_check.py` | реестр клише и его стыки: ключи `--allow` проверок и статусы приёмов каталога эффектов | `--selftest` |
| `marketing_audit.py` | визуальные проверки страницы: профиль `marketing` поверх `../ui/ui_audit.py` и свои проверки подачи | `--selftest` |
| `motion_check.py` | движение собранной страницы во времени: запись, метрики, сверка со спецификацией, ворота эффектов, слой подачи по режимам | `--selftest` |

## `spec_check.py` — подача, движение, вход холста

Числа уровней — `kb/creative/01-creative-direction/ambition-levels.yaml`: пики и акценты (`section_distribution`),
секции с фирменным приёмом (`signature_moves_max`), петли в зоне видимости, свойства движения и blur (`motion_hints`,
`property_exceptions`); пределы времени и смещения первого экрана — токены `motion.marketing` (`hero-scene-max`,
`group-total-max`, `shift-hero`). Ключ `--levels ФАЙЛ` подставляет другой файл той же формы.

| команда | что проверяет или собирает |
|---|---|
| `plan ПЛАН [--overlay T] [--spec S] [--out F]` | `treatment` секций и страницы: схема page-plan с подсхемой `treatment` v1 и правила уровня (секция ≤ страницы, конверсия — L0, пики, акценты, петли, эффекты каталога, цели слотов); нормы облика — предупреждение (облик выбирает заказчик), схема, ссылки в пустоту и уровень эффекта — ошибка; спецификацию движения находит по `page.treatment.motion_spec_ref` |
| `spec СПЕЦ [--plan ПЛАН] [--overlay T]` | спецификация движения: схема, id секций и целей, эффекты, токены (и у дорожек со своей длительностью и кривой), имена переменных токенов в дорожках — `--` + путь токена через дефисы (MS-06), свойства не шире уровня (`page.properties_allowed` — не шире уровня, моменты — не шире страницы), LCP, стаггер, петли; примитив набора движения — есть в `kb/creative/11-motion-code/primitives.yaml`, уровень, класс, эффекты и опции (MS-25); момент без примитива, эффекта и пометки `custom` — MS-26 (warning); план находит по `refs.page_plan`; нормы MS-08, MS-09, MS-10, MS-23, снятые записью арт-дирекции (`refs.art_direction` → `exclusions.lifted_markers[]`: `marker` — id правила, `decision_ref` — запись `decisions[]`), — `warning` со строкой «принято решением арт-дирекции», без записи или с решением, которого нет в `decisions[]`, — `error` |
| `moments СПЕЦ`, `motion-md СПЕЦ`, `values СПЕЦ --out DIR` | строки моментов для брифа холста — всё описание момента: дорожки со своей длительностью и кривой, стаггер, станции, выход, прерывание, пружина, привязка, примитив набора или эффект, свой код, источник чисел, заметка; блок движения входа холста; JSON чисел на секцию для модуля эффекта |
| `blocks [--yaml F]` | `block-treatments.yaml` против каталога блоков site, эффектов и реестра клише |
| `levels [--check]` | списки `effect:<id>` по `level_min` каталога; `--check` — сверка с `x-effect-levels` и условиями L0, L1 `treatment.schema.json` |
| `canvas-map [ФАЙЛ …]` | форма ключа `x-canvas-map` и покрытие: у каждого поля источника есть правило; без файлов — все файлы базы с этим ключом |

Пути — от файла: план или спецификация проекта (`docs/projects/<slug>/site/<surface>/plans/<page>.yaml`,
`…/design/<surface>/motion/<page>.motion-spec.yaml`) подаются аргументом, ссылки между ними разрешаются от файла.
Коды выхода: 0 — ошибок нет, 1 — есть, 2 — сбой запуска.

## `ad_check.py` — арт-дирекция

`ad_check.py [ФАЙЛ …] [--json]` — файл проекта `docs/projects/<slug>/design/<surface>/art-direction.json` или, без
аргументов, примеры базы. Проверяет схему `art-direction.v1`, поля паспорта визуала (`handoff.visual_dna`) против схемы
ai-media и правила вне схемы: ссылки на направления, территории и решения, макроструктуры словаря site, контраст палитр,
уровень против эффектов, движения и плавной прокрутки (потолок и запреты уровня — из `ambition-levels.yaml`), профиль
бюджета, ключи `--allow` (`kb/common/tells.yaml`, раздел `checks`) с решением, ссылки с префиксом (`effect:`, `cliche:`,
префиксы словаря site, `fact:` по `refs.facts`). Направлений меньше трёх (схема — от одного до пяти), пара направлений
различается меньше чем по двум осям, территории — меньше трёх материальных семейств: предупреждение, а не ошибка —
законно при строгом бренде или референсе заказчика (поля `inputs.brand_expression_mode`, `inputs.references_given`),
решает заказчик. Ключ без решения и снятая примета без решения — предупреждение, у документа `approved` — ошибка.

## `validate_stack.py` — каталог стека

Обязательные поля, словари `kind` и `status`, условие у `conditional`, уровни, альтернативы, платформы заказчика; ссылки
`use_for` — только `effect:<id>` каталога эффектов; вес `size_br` — число или словарь «сцена → КБ» (у three, R3F,
model-viewer, paper-shaders — всегда словарь: вес зависит от сцены и способа загрузки), `size_net_kb` — вес по сети на
странице. Печатает, какие эффекты каталога без записи стека.

## `registry_check.py` — реестр клише

Структура записей и кластеров, коды обнаружения, ссылки `cliche:<id>` в файлах базы (ошибки); расхождения — ключ
`k3_allow` записи снимает проверку утилиты макета, которая ловит другую примету, или проверка с ключом ловит примету
записи без ключа (примета записи — её id или запись `kb/common/tells.yaml` со ссылкой `also` на неё); статус приёма в
каталоге эффектов (`cliche.status`) расходится с записью реестра или ссылается в пустоту. Реестр утилита не правит:
печатает находки, код выхода 1 — если они есть. `--json` — итог одним JSON.

## `marketing_audit.py` — визуальные проверки страницы

`marketing_audit.py URL|ФАЙЛ.html [--level L0|L1|L2] [--art-direction ФАЙЛ] [--allow cliche:…] [--acceptance]` — один
сбор computed styles на прогон и два набора порогов: `consumer` (пресет `ui_audit.py`) и `marketing` — профиль
`../ui/data/marketing-profile.yaml` (`ui_audit.load_profile`, `apply_profile`) плюс пересчёт по узлам, свои проверки
MKT-* и приметы реестра клише. Числа — из данных: хроматических по уровню — `chromatic_max`, шкала длительностей —
токены `motion.marketing` и эталонные токены ui, порог одинакового появления и доля полосы 270–320° — записи реестра
клише (доля — из арт-дирекции, если она передана), надзаголовки — число владельца COPY-C-18 (text), окна прогонов —
`kb/common/acceptance-widths.yaml` (первая ширина, телефон ниже первого брейкпоинта на таче, reduce, вылет на
`overflow_only`). Находка несёт id приметы (`kb/common/tells.yaml`, раздел `checks`: ключи `ui_audit:<id>` и
`marketing_audit:<id>`); в отчёте приметы сведены без повторов. Выход — сводка Markdown, находки JSON и блок «правило →
найдено → порог → где» для правки (`<имя>.marketing.md`, `<имя>.marketing.json`, `<имя>.fix.txt`); `--profile-md` —
таблица профиля.

## `motion_check.py` и `scroll_record.py` — движение собранной страницы

`motion_check.py ЦЕЛЬ --level L0|L1|L2 [--modes desk,mob,rm,nojs,nogl] [--spec motion-spec.yaml]` записывает страницу
в режимах десктопа, телефона, сокращённого движения, без JS и без WebGL, считает метрики (сеть по фазам, LCP, CLS, TBT,
петли, бегущая строка, колебания, вспышки, пауза, WebGL, Tab-проход), сверяет моменты со спецификацией движения по
DOM-контракту (`data-section`, `data-slot`, `data-moment`) и выносит вердикт ворот
`kb/creative/09-ai-execution-evaluation/effect-gates.yaml` (пороги по `threshold_ref` — из `ambition-levels.yaml`).
`report --in DIR` пересчитывает ворота без браузера. Запись прокрутки и движение в паузах — модуль `scroll_record.py`.

Пороги ворот живут у владельцев величин: `threshold_ref` — путь в уровне `ambition-levels.yaml` (`budgets.effects.*`,
`motion_hints.*`), `profile.<путь>` — профиль страницы site `budgets.yaml` (с `--page-type` — `<тип>@<уровень>` с
исключениями; метрики страницы — LCP, TBT, вес, шрифты — в воротах эффектов зеркало D), `effects.yaml#<id>.<путь>` — запись
каталога эффектов (скорость бегущей строки); поле есть, а числа нет (wasm-рантаймы подачи, EG-WEIGHT-11) — N/A, пока числа
нет в данных.
Числа, по которым утилита считает находку сама (полоса и минимум периода колебаний, путь колеса, «движется на 6-й секунде»,
заставка, предел маленького JS, который грузится и в reduce), — поле `limits` строки ворот. Окно первого экрана — `budgets.yaml` `conditions.first_screen` (`--wait` — своё), телефон — дескриптор и CPU
`conditions.lab_mobile` (UA — HeadlessChrome); каждый режим — на тихой машине (общий тяжёлый замок, замок браузера и
creative — `page_gates.heavy_lock`; `--no-lock` — прогон без замков). Отчёт `<out>/gates.md` и `<out>/gates.json` (`presentation`)
показывает слой подачи по режимам — JS эффектов, JS и wasm 3D (EG-WEIGHT-02), wasm-рантаймы подачи 2D (EG-WEIGHT-11), видео
первого экрана — против одного порога EG-WEIGHT-01 уровня; картинка первого экрана — ссылкой на бюджет ассета ai-media
(`thresholds.yaml#thresholds.budget.image`). Кнопку паузы и переключатель движения утилита узнаёт по общему списку
подписей `page_gates.PAUSE_LABELS`.
Переключатель движения принимается только с атрибутом `data-motion` контракта (`reduced` · `full` · `paused`); станции
скраба — край цели после округления до целого (половина — от нуля), допуск включительно. Прелоадер или входной экран
(EG-A11Y-28) — слой на весь экран в первые секунды: длительность и видимая «Пропустить». `--f83 SEL …` делегирует контраст
по буквам `page_accept.py` (только первый экран). Вердикт страницы ставит `page_gates.py --motion DIR` (2.2.2, вспышки,
reduce; метрики страницы — зеркалом).

## `motion_probe.py` — замер движения референса и сверка

`motion_probe.py probe ЦЕЛЬ [--out DIR] [--viewport 1440x900] [--mobile] [--scroll-step 0.33] [--settle-ms 1200]
[--max-s 60] [--frames] [--clock] [--no-lock] [--json]` — понравившийся сайт или копия прототипа (`dc_to_html.py convert
--motion`) → паспорт движения по схеме `kb/creative/09-ai-execution-evaluation/motion-passport.schema.json`:
`<выход>/passport.json` и сводка по-русски `<выход>/passport.md` со строками «что взять» для `values.measured` записи референса. Снимает
события CDP `Animation` (CSS-анимации, переходы, WAAPI, шкалы прокрутки), таймлайны GSAP и ScrollTrigger, Lenis и
другие библиотеки, движение скриптом через инлайн-стили по кадрам (кривая — именованная и подбор `cubic-bezier`),
прокрутку шагами (скраб, догон сглаживания, закрепления, станции); `--clock` — детерминированные кадры через
`page.clock`. Выход — `$DDD_HOME/out/creative/motion-probe/<хост>-<хеш>/`, кадры (`--frames`) — только там. Правила
чужих сайтов — `kb/creative/02-references-moodboards/02-refs-client-and-library.md §8`: UA как есть, без маскировки;
защита, вход или запрет robots.txt — код 3 и статус «закрыто, сайт смотрит человек».
`motion_probe.py compare A B [--json] [--out DIR]` — паспорт против паспорта (референс против прототипа) или против
спецификации движения: пары моментов, разница длительности и задержки, расстояние кривых, шаг стаггера, длины в vh;
код 1 — есть «далеко» или момент спецификации без замера. Пороги «близко / далеко» — `x-compare` схемы паспорта
(`[мнение]`). Документ — `kb/creative/03-live-sites-measured/03-reference-motion-probe.md`.

## `motion_smoke.py` — живая проверка набора движения

`motion_smoke.py [--root DIR] [--page demo.html] [--modes static,desk,rm,reduced,paused,nojs,phone,demos] [--shots]
[--json ОТЧЁТ]` — набор движения `kb/creative/11-motion-code/examples` в Chromium: `static` — код набора не строит DOM и
не ходит в сеть, одно глобальное имя, пружина та же, что у рантайма сцен 3D, переменные токенов есть в
`marketing-tokens.json`, пример артборда — по формату холста; `desk`, `rm`, `reduced`, `paused`, `nojs`, `phone` —
появления дошли до конечных состояний, невидимого текста нет, стаггер, счётчики, петли и пауза, такты сцен, указатель,
долгие кадры, ни одного запроса наружу; `demos` — страницы демо и якоря эффектов из `primitives.yaml`. Код 0 — годно.
Прогон всех режимов — около четырёх минут; замок браузера утилита берёт сама.

## `recipe_check.py` — рецепты

`recipe_check.py РЕЦЕПТ.recipe.yaml … [--ledger OUT.md]` — схема рецепта, ссылки на блоки, роли и типы страниц словаря

## `refs_client.py` — клиент референсов

Библиотека референсов заказчика (`~/.local/share/creative-refs/`), мудборд и выгрузки; режимы «поиск» и «ассистент»,
частоты и паузы по площадкам. Основной путь — площадки листает заказчик, агент записывает ссылку, роль, «брать / не брать»
и значения; клиент — по месту. Вход в площадки делает только заказчик в своём терминале (`login`), клиент не читает и не
печатает cookie и токены, не маскирует автоматизацию (UA как есть, `navigator.webdriver` не трогается). Работы Dribbble,
Behance, Dprofile записываются без превью и без автора — ссылкой на работу; превью — только наш снимок живого сайта.
FWA — hold (площадку листает заказчик), Behance — режим `off` по умолчанию.

- `lib export --format base-safe` — для цитирования в базе: id, источник, ссылка, название, даты, медиа, `take`,
  `dont_take`, `roles`, `notes`; без автора и превью.
- `lib export --format brief` — записи `$defs/reference` брифа сайта и арт-дирекции: `ref`, `url`, роль, «брать / не
  брать», значения текстом (строки замера движения — `measured` со способом `method` и паспортом `passport`; палитра
  снимка — `estimated`), снятие (дата и окно замера), `source: creative-library`; закрытый сайт — в `note` словами
  «сайт смотрит человек».
- `handoff <мудборд> --out DIR` — референсы на холст: папка refs со снимками сайтов (JPEG ≤ 2000 px) и README.md
  строками референсов в форме файла референсов входа холста (`../../references/claude-design.md` § 6), строки замера
  движения — в значениях референса, с паспортом; работы площадок — ссылкой.
- `motion <ref|URL> [--mobile] [--frames] [--dry-run]` — замер движения сайта записи: зовёт `motion_probe.py probe`
  подпроцессом (Python окружения скилла) и ждёт итог. Код 0 — строки «что взять» паспорта в `values.measured`,
  `values.method: [probe]`, `values.passport` — id паспорта, статус, время и окно замера — в `probe`; код 3 (закрыто
  защитой, входом или robots.txt) — пометка «сайт смотрит человек» без чисел, защита — ещё и пауза хоста; код 2 — сбой,
  запись не меняется. Записи нет — отказ с подсказкой `get <URL>`; работы площадок и страницы галерей не мерятся;
  пауза, интервал и лимит в сутки — по ключу хоста, как у `get`. Паспорт и кадры — только в выходе `motion_probe.py`.
