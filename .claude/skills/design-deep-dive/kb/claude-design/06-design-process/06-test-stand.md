# Стенд, слепые пары и правило решения: как сравнивать пути, настройки и варианты

Как честно решить «X лучше Y» для путей работы (типы артефактов Design и Design System,
`kit` в сессии, Claude Design в интерфейсе руками заказчика), настроек (effort, форма входа, размер пакета правок) и вариантов одного
проекта. Основа: два готовых брифа стенда (`stand/`), правило решения, проверенное симуляцией на странице стенда, и метод слепых пар
ai-media — канон `../../ai-media/13-routing-matrix/01-stand-method.md`, код `../../../scripts/ai-media/stand_run.py`.
Какие тесты гонять — README базы, «План тестов» (T-1…T-6). Сами тесты на Claude не проводились — `[не проверено]`.

## Выжимка для агента

1. **Делай**: сравнивай только на одном входе (бриф, ДС, референсы, ассеты от одного коммита), в одном канале, по ≥ 2 прогона на
   условие, каждый прогон — новая сессия и своя копия входа. `[практика]` → §3
2. **Знай**: модель одна — Opus 5.5 (решение заказчика); сравниваются пути и настройки, а не модели. `[решение заказчика]` → §1
3. **Делай**: стенд — S1 «Кварц» (лендинг предзаказа) и S2 «Смена» (панель на 4 экрана); перед тестом заменить синтетические
   картинки реальными кадрами и ассетами, убрать поля другого исполнителя. `[проверено: сборка брифов]` → §2
4. **Знай**: все продукты стенда вымышлены: тест не должен зависеть от знаний модели о реальном бренде. `[мнение базы]` → §2
5. **Делай**: кадры для суждения снимает Claude одной командой для всех условий, а не исполнитель; первая сборка — без вмешательства.
   `[практика]` → §3
6. **Делай**: заказчик судит вслепую попарно: без имён условий, стороны случайны, 10 % повторов со сменой сторон, контрольная пара
   (размытая копия), одинаковая пара. `[проверено: страница на фиктивных кадрах]` → §5
7. **Делай**: два вопроса на пару: «Какую страницу вы бы отдали клиенту по этому брифу?» (A / B / = / обе не годятся) и «Какая
   выглядит спроектированной под этот продукт, а не собранной из шаблона?» (A / B / =). `[практика: ai-media]` → §5
8. **Делай**: «X лучше Y», только если нижняя граница 95 % Уилсона доли голосов X > 0,5 **и** X выиграл большинство видов в ≥ 75 %
   пар прогонов; иначе «неразличимы → умолчание» (дешевле или проще). `[проверено: симуляция]` → §6
9. **Знай**: 1 бриф × 2 прогона (12 пар) ловит только сильный перевес (≥ 0,84 голосов — в 76–86 % случаев) и даёт 8–16 % ложных
   «лучше»; стратегию решать только на двух брифах. `[проверено: симуляция]` → §6
10. **Делай**: автоматика не должна противоречить вердикту (у «лучшего» W и доля пунктов приёмки не хуже), иначе «неразличимы».
    `[мнение базы]` → §6
11. **Делай**: голосование не засчитывать, если контрольная пара выиграла или повторы со сменой сторон перевёрнуты больше чем в
    половине. `[проверено: ai-media]` → §6
12. **Делай**: рубрика Claude — второе мнение: Opus 5.5 в отдельной сессии, кадры под буквами, 3 прогона с перестановкой сторон;
    решают заказчик и правило. `[решение заказчика]` → §7
13. **Делай**: варианты одного проекта — ≤ 4 (одному голосующему на 4+ интервал 0,44–1,00), пары различаются ≥ 2 осями, с critical
    не показывать. `[проверено: страница вариантов]` → §8
14. **Делай**: лидер берётся, если нижняя граница Уилсона выше точечных оценок остальных (или разрыв Брэдли — Терри ≥ 150 при
    согласованных повторах); иначе — по брифу и меньшему W доводки. `[практика: ai-media]` → §8
15. **Делай**: сливать части, а не стили: токены донора — в ДС, секция донора — референсом «брать»; «смешай A и B» — усреднение.
    `[мнение]` → §8
16. **Делай**: строка журнала на прогон и файл итога теста; после теста — заменить `[не проверено]` в файлах базы. `[мнение базы]` → §9

## 3. Условия честности

1. Один вход: коммит `iter-00 input`; каждому прогону — `git worktree` от него; одинаковые референсы, ассеты, ДС, `ACCEPTANCE.md`.
2. Одинаковые правила у условий: одинаковый набор скиллов и `CLAUDE.md` (или отдельный конфиг без пользовательских у всех).
3. Effort — одинаковый или «рекомендованный» у каждого и записан в журнал; модель и effort внутри сессии не менять.
4. ≥ 2 прогона на условие; новая сессия на прогон; первая сборка без вмешательства до кадров.
5. Кадры снимает Claude одной командой для всех условий (`04` §4): первый экран 1440 и 390 + карта страницы 1440.
6. Слепота: на странице нет имён условий, прогонов и путей; ключи — рядом со страницей, не внутри.
7. Контроль качества голосования: 10 % повторов со сменой сторон, контрольная пара (размытая копия), одинаковая пара.
8. Рекомендацию Claude показывать после голосования — не подсказывать.

## 4. Что меряем

| Что | Чем | Порог «лучше» |
|---|---|---|
| выбор заказчика | слепые пары: 3 вида × пары прогонов | правило §6 |
| приёмка | доля пройденных пунктов `ACCEPTANCE.md` A–H по проверке Claude | выше на ≥ 20 п. п. |
| дефекты | W = 3·critical + major по слою скриптов (`04` §3) | ниже на ≥ 30 % |
| шаблонность | маркеры ui 11/04 и приметы `05` §3 | < 4 маркеров; 0 примет major |
| честность | числа, подписи, отзывы, сток, хотлинк | 0 |
| мобильная | вылет, навигация, тело, цели на 390 и 360 | 0 critical |
| цена | минуты, доля лимита до и после (`/usage`), раунды до приёмки | записать |

## 5. Страница слепых пар

```bash
T=../../scripts/claude-design/stand_page.py          # читает ai-media stand_run.py по абсолютному пути (заголовок файла)
python3 $T selftest                                     # фиктивные кадры → страница → проверка слепоты → голоса → вердикт
python3 $T build --manifest review/stand/vote1.tsv --out review/stand/vote1 --title "Стенд S1 · голосование 1"
# заказчик: vote1/index.html → «Кто голосует» → ← A · → B · ↓ равно · X обе не годятся → «Скачать голоса (JSON)»
python3 $T tally votes-<имя>.json --key review/stand/vote1.key.json --runs review/stand/vote1.runs.json --out review/stand/vote1-tally.md
python3 $T power --designs 1x2,1x3,2x2,3x2 --out review/stand/power.md    # мощность правила для размеров стенда
```

- Манифест — TSV, строка на прогон: `test`, `brief`, `brief_text`, `condition`, `run`, `shots_dir`; базовые прогоны повторять под каждым
  тестом, где они — база. Пары строятся внутри «тест | бриф | вид» между разными условиями.
- Виды по умолчанию — `desktop-1440x900-00`, `mobile-390x844-00`, `desktop-1440x900-map` (файлы `<вид>.jpg` в `shots_dir`). Первые экраны
  даёт `mockup_checks.py page --shots`; карту — уменьшенный полный кадр `kit/shot.py` в JPEG, или без неё (`--views`). Имена
  `desktop-…-00`, `mobile-…-00` — у собранной страницы; у копии артборда кадр назван по копии.
- Объём: 2 условия × 2 прогона × 3 вида = 12 пар; 3 условия — 36; ≈ 20 с на пару; пилот на одном брифе с тремя условиями ≈ 42 пары,
  ≈ 14 мин заказчика.
- Разброс прогонов: два прогона базы подписать разными условиями (+ 3 пары) — доля «равно» и перекос внутри одного условия
  показывают шум; при разбросе ≥ 0,3 добавить третий прогон.

## 6. Правило решения

1. Голосование засчитано: контрольную пару выиграла настоящая картинка, повторы со сменой сторон совпали хотя бы в половине.
2. По паре условий X / Y (все брифы и виды теста вместе): доля голосов X, ничья = ½, «обе не годятся» — отдельно. **X лучше**, если
   нижняя граница 95 % Уилсона > 0,5 **и** X выиграл большинство видов в ≥ 75 % пар прогонов (виды одного прогона не независимы);
   симметрично для Y; иначе **«неразличимы → умолчание»**.
3. Нижняя граница Уилсона при доле p и n голосах: `(p + z²/2n − z·√(p(1−p)/n + z²/4n²)) / (1 + z²/n)`, z = 1,96. На 12 парах «лучше»
   начинается с 10 побед из 12 (граница 0,55); 9 из 12 — 0,47, «неразличимы».
4. Автоматика не противоречит: у «лучшего» W и доля пунктов приёмки не хуже; противоречит — «неразличимы» с записью причины.
5. Стратегия (смена основного пути) — только при одном направлении вердикта на двух брифах (S1 и S2).

| Средняя доля голосов за лучшее | 1 бриф × 2 прогона (12 пар) | 1 × 3 (27) | 2 × 2 (24) | 3 × 2 (36) |
|---|---|---|---|---|
| 0,50 (разницы нет): ложные «лучше» | 8–16 % | 7–14 % | 6–12 % | 5–9 % |
| ≈ 0,76–0,79 | 53–62 % | 64–80 % | 68–83 % | 74–89 % |
| ≈ 0,84–0,87 | 76–86 % | 92–98 % | 92–98 % | 96–100 % |

Симуляция: скрытое качество прогона с разбросом σ 0,15–0,30, 3 вида, 12 % ничьих. Следствие: пилот — «сильный перевес или
неразличимы»; тонкие настройки — умолчание, пока нет вердикта. `[проверено: симуляция]`

## 7. Рубрика Claude — второе мнение

Рубрика ui 13/02: 10 измерений 0–5, веса клиентского сервиса — контраст 3, иерархия 3, отступы 3, консистентность 2, плотность 2,
состояния 2, типографика 2, выравнивание 2, цвет 2, различимость 2. Судья — Opus 5.5 в отдельной сессии без контекста сборки, кадры
под случайными буквами, 3 прогона с перестановкой сторон; расхождение порядка между прогонами — «неразличимы». Без рубрики судья на
«какой лучше» — монетка (51,58 %). Судья-Opus в опыте с 3D выбирал «богаче» в 3 из 4 пар, и все три выбора — брак: рубрика штрафует
избыточность, решающий голос — у человека. Запись — рядом с голосами заказчика.

## 8. Варианты одного проекта

| Ситуация | Вариантов | Путь |
|---|---|---|
| бренд, палитра ролями, гарнитуры и форма страницы заданы | 0 | одна сборка; разнообразие здесь — шум |
| направление не выбрано, вкус неизвестен | 2–4 направления (`01` §5) → 1–2 сборки | выбор заказчика |
| важный лендинг, заказчик хочет видеть разное | 2–3 (максимум 4) сборки по осям | слепые пары |
| следующие страницы того же сайта, рабочие экраны | 0 (0–2 — раскладка, не стиль) | система закреплена после первой страницы |

- Дёшево — варианты первого экрана (hero + следующая секция), полная страница — победителю; победителя проверять целиком.
- До показа: у каждого варианта 0 critical (≤ 1 правка; остался critical — снять); разнообразие — таблица осей по фактам замера
  (гарнитуры, фон OKLCH, тип hero, приметы) и силуэты 200 px: совпадение ≥ 3 из 4 осей — пересобрать или снять.
- Выбор на холсте (страница «Направления») — по имени, не слепой; для важного выбора — страница слепых пар (§5, ≤ 4 варианта).
- Правило: нижняя граница Уилсона лидера выше точечных оценок остальных (или Брэдли — Терри ≥ 150 при согласованных повторах) — берём;
  лидеры пересекаются — по брифу и меньшему W доводки, один уточняющий вопрос; «обе не годятся» у всех — назад к направлениям с тем,
  что не понравилось. Модели и варианты в интервале лидера равны — берётся дешевле в доводке.
- Слияние частями: палитра, гарнитуры, радиусы донора — правкой ДС (новая версия системы); композиция секции донора — кадром-референсом
  с «брать: 2fr / 1fr, картинка слева; не брать: цвета, шрифты, тексты»; после слияния — полный слой проверок и силуэт против доноров.
- Один раунд вариантов на проект; второй — только если ни один не прошёл ворота, и сначала переписать бриф.

## 9. Журнал и итоги

- Строка на прогон: тест, бриф, условие, прогон, путь, модель и effort, релизы типов и контракт, sha входа, минуты, доля лимита до и
  после, раунды, W, доля пунктов приёмки, маркеры, приметы major, путь к кадрам. Числа — из файлов, не из пересказа.
- Итог теста — файл результата (условия, засчитано ли голосование, вердикт с интервалом, медианы автоматики, цена, решение); метки
  `[не проверено]` в файлах базы меняются на `[проверено: <тест>, <дата>, <условия>, <n>]`, опровергнутое правило переписывается.

## Частые ошибки

1. Сравнивать на разных брифах, по одному прогону, с вмешательством по ходу или по кадрам исполнителя.
2. Дать одному условию пользовательские скиллы и `CLAUDE.md`, а другому — нет.
3. Считать «неразличимы» победой нового варианта; решать стратегию по пилоту на одном брифе.
4. Судить только hero и только 1440.
5. Засчитывать голосование с проигранной контрольной парой; показывать рекомендацию Claude до голосования.
6. Тестировать на синтетических заглушках вместо реальных кадров и ассетов.
7. Не записывать версии, sha входа и лимит до и после — прогон нельзя повторить.
