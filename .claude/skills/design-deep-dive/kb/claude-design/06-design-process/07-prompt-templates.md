# Шаблоны заданий по этапам Claude Design: направления, ДС, макет, правки, мобильная, движение, аудит

Семь заданий, которыми сессия Claude Code (или субагент Opus 5.5 для аудита) ведёт
работу по этапам холста Design и артефакта Design System. Основа — набор шаблонов, написанный для другой модели-исполнителя (там
тоже не прогонялся), приёмы роликов и правила этой базы; все шаблоны — `[не проверено]`, проверка — тесты `06-test-stand.md`.
Правила формата типов в шаблоны не вписываются: их отдаёт инструмент `Artifact` при каждом создании и чтении
(`../05-design-artifacts/02` §2).

   `[мнение базы]` → §Как пользоваться
2. **Делай**: в каждом задании — вход (файлы `input/`, ДС, холст), выход (страница холста, артефакт, файл), рамки «не менять» и
   «готово» с числами. `[практика]` → все шаблоны
3. **Делай**: решения, а не прилагательные: hex, px, оси, число моментов движения; бан-лист — `05-default-look.md` §6. `[консенсус]`
4. **Не делай**: не пересказывай правила формата типа в задании — ссылайся на ответ инструмента; пересказ устареет с новым релизом.
   `[мнение базы]`
5. **Делай**: язык задания — русский; тексты сайта — дословно из copy deck; довода за английский для Claude нет. `[мнение базы]`
6. **Делай**: стоп называй явно: «выбирает заказчик», «Keep»; «Keep» макета принимает и структуру, и облик, а правку структуры
   поднимают в план страницы или экраны (`../../../references/claude-design.md § Правки заказчика`). `[практика]` → §3
7. **Делай**: аудит — субагентом или новой сессией Opus 5.5 без контекста сборки; судья по рубрике — тоже (`04` §6).
   `[решение заказчика]` → §7
8. **Знай**: проверка результата — только по постоянной просьбе заказчика (правило типа). `[исходник: SKILL.md типа]`
9. **Делай**: «не закончено» — не больше двух продолжений подряд, дальше — ревью и новая формулировка. `[документация]`
10. **Делай**: мобильная для видео-hero и сложного скролла — отдельным заданием после приёмки десктопа; для прочих — пороги 390 уже

## Как пользоваться

| Этап | Шаблон | Выход | Стоп |
|---|---|---|---|
| дизайн-система | §2 | артефакт Design System | «Keep» заказчика |
| направления | §1 | страница «Направления» | выбор заказчика |
| макет и прототип | §3 | страница «Макет и прототип», iter-01 | проверки по просьбе (`04`), «Keep» заказчика — структура и облик |
| правки | §4 | iter-NN, паспорт | «Keep» или стоп по числам (`03` §5) |
| мобильная | §5 | артборды 390 и 360 | пороги 390 и ресайз |
| движение | §6 | прототип с моментами | греп и reduced motion |
| аудит | §7 | `AUDIT.md` | ≥ 1 находка, триаж |

Порядок этапов — этапы скилла: `../../../references/phases.md`; место ДС относительно ассетов — `§ Порядок ассетов и ДС` (сайт — ключевые
ассеты до ДС, кабинет — ДС первой). Холст после входа начинается с макета (§3) — облик ДС на утверждённых текстах; дальше — правки (§4),
мобильная (§5) и движение (§6) отдельными раундами, свежий аудит (§7) и приёмка. Плейсхолдеры — `<…>`. Путь к холсту и ДС — из
`ARTIFACTS.md`. Если в проекте есть код, перед §1–§2 — шаг «повтори существующее приложение точными значениями, новое — расширением
его словаря; одной строкой — с чем сверился» (`../04-claude-code-native/01` §4.2).

## 1. Направления

```text
Задание: направления для <продукт> по брифу input/brief.yaml. Холст <url>, страница «Направления». Макет не делать.
Прочитай: бриф, факты, референсы input/refs.md (брать / не брать, значения), README ДС, если есть.
Сделай <число по роду продукта: сайт — creative 01/01 §6, приложение — ui 11/02 §2.4> направлений, по артборду на ширинах приёмки
десктопа и телефона: первый экран с настоящим заголовком и кнопкой из copy deck. Числа первого экрана (first_viewport) —
диапазоном или по замеру метрик шрифта.
У каждого: имя (не меняется между ходами); тезис одной фразой; фон, текст и акцент в hex и роль акцента; гарнитуры заголовков и
текста с кириллицей; макроструктура и композиция hero одной фразой; что берёт из какого референса и чего избегает; главный риск.
Каждая пара различается ≥ 2 осями из: бумага (тёмная / средняя / светлая), стиль заголовков, тон акцента, макроструктура.
Тёплая бумага или антиква — не больше чем у одного и только если их требует бриф или бренд. Бан-лист — 05 §6.
Под артбордом — стикер «мотивация / компромисс»; над рядом — заметка-таблица «направление × 4 оси».
Публикация — после «прочитать → слить». Стоп: выбирает заказчик (имя или ремикс «B + акцент из C»).
```

## 2. Дизайн-система

```text
Задание: артефакт Design System для <продукт> из реальных источников. Экраны не делать.
Источники: input/tokens (DTCG), DESIGN.md, бренд (логотип SVG, шрифты), стили кода <tokens.css, site.css — если есть>.
Нечего взять — маленькая первая система: 6–10 цветов, 5–7 стилей текста, 4 шага отступов, 3 радиуса — с пометкой в README.
Имена токенов — как CSS-переменные кода (color-accent, space-4); usage у каждого; контраст пар числом: текст / фон и на акценте
≥ 4,5, приглушённый ≥ 4,5, фокус ≥ 3; слабую пару источника не чинить молча — в «известные проблемы».
Длительности и кривые — в components/bundle.css. README — бренд-бук: голос, основы, иконография, компоненты, правила использования
с именами токенов, запреты (05 §6), доступность, источник. Компоненты — каждый, названный в экранах, с превью и состояниями.
Обложка и индекс — последними, один вызов публикации. Стоп: «Keep» заказчика — до экранов.
```

## 3. Макет и прототип

```text
Задание: макет <страницы | экранов> на странице «Макет и прототип» с установленной ДС «<ns>».
Вход: направление «<имя>»; план страницы input/page-plan (секции по порядку, одна работа у каждой, других нет) или экраны
(закрытый список маршрутов, состояния); input/ (бриф, факты, copy deck, ассеты, ACCEPTANCE.md); README ДС.
Артборды — все ширины приёмки из input/brief.yaml (build.viewports.artboards), тёмная тема — твиком, если она есть
в ДС. Значения — только из токенов ДС, литералами.
Тексты — утверждённые строки copy deck дословно, литералами в разметке, не твиками. Числа, имена, цены — только из фактов;
пропуск — видимая заглушка [ЦЕНА]. Картинки — только загрузки с подписью и alt из input/assets.md; пустой слот — заглушка
«placeholder».
Приложение: у каждой коллекции — загрузка, пусто при первом входе, пусто после фильтра, одна запись, ошибка загрузки —
артбордами страницы «Состояния».
Твики — только рычаги: акцент (3–4 образца), радиус, тема, плотность.
Форма результата: <статичные экраны | кликабельный путь «<кнопка> → <экран>»: is_interactive и ссылки>.
На 390: навигация видна, тело ≥ 16 px, цели ≥ 44 px, одна колонка, без вылета. Бан-лист — 05 §6.
Ничего сверх задания (разделы, отзывы, цифры); замеченное — строкой «предлагаю ещё».
Публикация — после «прочитать → слить»; коммит iter-01. Проверки — только по постоянной просьбе заказчика (04).
Стоп: «Keep» заказчика по странице или экрану — он принимает и структуру, и облик.
```

## 4. Правки

```text
Задание: пакет правок iter-<NN>, холст <url>. Сначала прочитай живую версию и слей правки заказчика (коммит «customer»).
Пункты — не больше 7, по тяжести:
#<N> · <critical | major | minor> · <ширина> · где: <артборд, селектор или токен>
   Симптом: <что сейчас, с числом>. Цель: <что должно быть, с числом и токеном>. Не менять: <соседнее>.
Keep: <что проверено и хорошо>. Ничего сверх списка; замеченное — строкой «предлагаю ещё».
До правки — эхо: номер → артборд и селектор → уровень (элемент / компонент / токен) → какие метки заденет; уровень — самый узкий.
После: diffshots по HTML-копиям — 0 «НЕОЖИДАННО»; кадры всех рамок; «было → стало» и статусы fixed / not fixed / blocked;
публикация после «прочитать → слить»; коммит iter-<NN>; паспорт review/iter-<NN>/NOTES.md.
```

Редизайн — отдельным заданием: одно слово настроения + «сохранить дословно» + что можно менять + план до работы (`03` §8).

## 5. Мобильная версия

```text
Задание: мобильная версия принятого десктопа — отдельный раунд. Десктоп 1440 и 1280 не меняется: любое отличие кадра — дефект.
Тот же сюжет: те же секции в том же порядке, те же тексты и CTA. Перекомпоновка под палец, не сжатие: одна мысль на экран,
без многоколоночных раскладок ниже 768, без текста на пёстрой картинке без подложки.
На 390 и 360: навигация видна (кнопка меню ≥ 44 × 44), тело ≥ 16 px, цели ≥ 44 px (не меньше 24), вылет 0 — и на 320.
Видео-hero: на узких экранах — файл 9:16 из ассетов, не обрезка 16:9; файла нет — постер.
Ресайз 1440 → 390 → 1440 без перезагрузки: медиа первого экрана видно не позже чем через 1 с.
Готово: кадры на всех ширинах приёмки; брейкпоинты перечислены; статусы пунктов.
```

## 6. Движение

```text
Задание: движение для принятой статичной страницы. Раскладку, тексты и цвета не менять.
Тезис движения: <одна фраза>. Моменты — эти и только эти, не больше 3:
1. <триггер> → <элемент> → <свойство от → до>, <мс>, <кривая>; 2. …; 3. …
Библиотека и свойства — из входа motion: <стек уровня брифа; свойства спецификации движения> (L0 — только CSS, transform и opacity). Библиотека на холсте —
модулем с CDN, под живой сценой — постер. Без перехвата прокрутки; на первом экране ничего
дольше 600 мс; ничего не движется под читаемым текстом; при prefers-reduced-motion — конечные состояния.
Длительности и кривые — токены движения из components/bundle.css ДС; на холсте — показать в прототипе (Play).
Проверка: нет «transition: all» и анимации width, height, top, left; невидимого после анимации текста — 0.
```

Уровень движения берётся из брифа (`none / subtle / expressive / cinematic`, `01` §6); `cinematic` — только на готовых роликах.
Моменты, станции, раскадровка, сокращённое движение и запасной вариант — из спецификации движения `motion-spec`
(`../../../references/claude-design.md § Вход холста`): исполнитель движение сам не выбирает. Что холст исполняет и как положить
на него библиотеку и модель — `../05-design-artifacts/03-what-canvas-runs.md` §1, §3.

## 7. Аудит свежим контекстом

```text
Ты — аудитор макета без контекста сборки. Ничего не правь; результат — AUDIT.md.
Вход: ACCEPTANCE.md, README ДС (правила и запреты), бан-лист 05 §6, машинный отчёт <checks.md, shots.json, ui_audit> — числа не
перепроверяй, ищи то, что числа пропускают; кадры всех ширин <папка>, мелкий текст — вырезом.
Находка: что (названная проблема) · где (артборд и #N или регион словами) · тяжесть (critical — нарушает пункт приёмки или
«выглядит как шаблон»; major — выглядит сгенерированным или мешает; minor — вкус) · как исправить одной строкой.
Структурный отпечаток (hero по центру + три равные карточки + CTA + футер) — critical, даже при хорошем оформлении.
Любое число, имя, логотип или цитата не из фактов и copy deck — critical.
Отбрось срабатывания, которые — сознательный выбор ДС или брифа, и назови их. Итог: «N critical · M major · K minor» и три правки
с наибольшим эффектом. Ноль находок не принимается: найди минимум три или объясни, почему каждая проверенная область в порядке.
```

Триаж — у Claude сборки: находки против брифа отбросить с причиной, дубли слить, critical и major — в один пакет (`03` §2).

## Частые ошибки

1. Шаблон без входа (`input/`, ДС, принятый предыдущий этап) — задание вырождается в «одну фразу».
2. Несколько этапов в одном задании (макет + мобильная + движение) — правка расплывается, проверка тоже.
3. Правила формата типа, переписанные в задание, — устаревают с новым релизом; ссылаться на ответ инструмента.
4. «Сделай лучше» вместо пунктов с числами и «Keep».
5. Аудит в той же сессии, что и сборка, — самоотчёт вместо второго мнения.
6. Третье и четвёртое «продолжи» подряд вместо ревью и новой формулировки.
7. Задание без стопа — работа идёт дальше этапа, заказчик не успевает выбрать.
8. Макет на неутверждённых текстах — после «Keep» тексты меняются, и принятую по ним раскладку принимают заново.
9. Правка структуры только на холсте — план страницы или экраны расходятся с макетом; её поднимают в план или экраны.
