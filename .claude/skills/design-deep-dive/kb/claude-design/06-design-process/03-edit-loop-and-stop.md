# Цикл итераций и правок: пакет ≤ 7 пунктов, формат пункта, эхо, прогресс, стоп и смена стратегии

Раунд правок холста Claude Design из сессии Claude Code: правки заказчика мышью и
твиками на claude.ai, правки Claude чатом по номерам `#N`, доказательство локальности `diffshots`, синхронизация «прочитать → слить →
опубликовать». Основа: протокол `#N` и `kit` (`../04-claude-code-native/01` §2, проверены смоуком), связка артефактов с репозиторием
(`../05-design-artifacts/01` §6, проверена публикацией демо), цикл арт-директора и формат замечаний, написанные для другой
модели-исполнителя (случаи из роликов — `[практика другого исполнителя]`, пороги — позиция базы). Бюджет для Claude не мерился —
`[не проверено]`.

## Выжимка для агента

1. **Делай**: итерация = слить правки заказчика из живой версии → свои правки → проверки → «прочитать → слить → опубликовать» →
   коммит исходников `iter-NN`. `[проверено: публикация демо]` → §1
2. **Не делай**: не публикуй поверх непрочитанной живой версии: редакторы сохраняют её сами, сервер отклоняет; `force` стирает правки
   заказчика — только по его прямой просьбе. `[проверено]` → §1
3. **Делай**: адрес правки — номер `#N` из `marks.json` того снимка, который видел заказчик; номер один на всех ширинах и темах и живёт
   между итерациями. `[проверено: kit]` На `.dc.html` метки `kit` не проверены. `[не проверено]` → §1
4. **Делай**: пакет — до 7 пунктов по тяжести (ориентир, а не жёсткий предел): раскладка и иерархия → честность → мобильная → цвет и контраст → типографика →
   форма → движение. `[мнение базы]` Лимит выведен из управляемости другой модели; для Claude, возможно, выше. `[спорно]` → §2
5. **Делай**: мобильную переделку — отдельным раундом, не вперемешку с десктопными пунктами. `[практика другого исполнителя]` → §2
6. **Делай**: пункт = один дефект: где (артборд, селектор или токен), симптом с числом, цель с числом и токеном, «не менять». Жёсткое
   правило выполняется в 92,3 % случаев против 70,4 % у мягкого. `[исследование]` → §2
7. **Знай**: дефект называет проверяющий: модели сами находят свой визуальный дефект лишь в 27 % случаев. `[исследование]` → §2
8. **Делай**: в каждом пакете — «Keep» (что проверено и хорошо) и «ничего сверх списка»; замеченное сверх — строкой «предлагаю ещё»,
   не правкой. `[исходник: пересказ]` → §2
9. **Делай**: эхо до правки — номер → артборд и селектор → уровень (элемент → компонент → токен) → какие метки заденет; уровень —
   самый узкий; после — «Применено: …». `[мнение]` → §3
10. **Делай**: «сделай лучше / премиальнее» без числа → 2–3 конкретных варианта твиком на холсте или `--set` в `kit`, выбор заказчика.
    `[мнение]` → §3
11. **Не делай**: не принимай правку без `diffshots` (0 «НЕОЖИДАННО») и снимков всех рамок (1440, 390, темы); только пиксели —
    ненадёжно. `[проверено: kit]` → §1
12. **Делай**: мера прогресса — W = 3·critical + major; прогресс — W(N) ≤ 0,7·W(N−1) и нет новых critical вне пунктов.
    `[мнение базы]` → §5
13. **Делай**: регресс вне пунктов — откат своих правок итерации (git), правки заказчика сохранить; «ушла не туда» дважды — переписать
    бриф, а не формулировку. `[мнение базы]` → §4
14. **Делай**: две итерации без прогресса — сменить стратегию: сузить задачу, починить вход или ДС, свежая сессия, назад к
    направлениям. `[практика]` `[документация]` → §6
15. **Делай**: стоп по успеху — 0 critical и 0 major, маркеров < 4 и хрома < 3, рубрика ≥ 3 (контраст ≥ 4), приёмка A–H пройдена,
    аудит свежим контекстом нашёл ≥ 1 проблему и её critical закрыты. `[мнение базы]` → §5
16. **Делай**: бюджет — сборка + ≤ 3 раунда на экран (+ 1 после аудита), дальше решает заказчик; время и долю лимита мерить.
    `[мнение базы]` `[не проверено]` → §5
17. **Делай**: редизайн — одно слово настроения + «сохранить дословно» (имя, тексты, секции, маршруты, ассеты, CTA) + что можно
    менять + план до работы. `[практика другого исполнителя]` → §8
18. **Делай**: после каждой итерации — паспорт в `review/iter-NN/NOTES.md`: версии, W, решение, статусы пунктов. `[мнение базы]` → §7

## 1. Раунд целиком

```text
0 Claude   вход собран и проверен (02 §6) → коммит «iter-00 input»; бюджет раундов согласован
1 Claude   read url + list scope=files → слить правки заказчика (чужие ключи и createdOnFiles — как есть) → коммит «iter-NN customer»
2 Claude   по постоянной просьбе заказчика: HTML-копии артбордов → kit shot.py --prev → кадры с метками #N; проверки 04
3 Заказчик пакет ≤ 7 «#22: высота ≥ 44 · #16: текст «…» → «…» · Keep» — или правка мышью и твиками на холсте
4 Claude   эхо до правки (§3)
5 Claude   правка исходников → diffshots --expect 16,22 --strict → 0 «НЕОЖИДАННО» → read живой версии → слить → publish → «iter-NN»
6 Claude   «было → стало» по пунктам, статусы, W; замеченное сверх — «предлагаю ещё: …»
7 Заказчик «Keep» / новый пакет / «откат iter-NN»
```

- Мелкие числовые правки дешевле сделать заказчику мышью и твиками: модель на них не тратится; Claude забирает их чтением.
- Проверка локальности на артефакте — дифф исходников `.dc.html` в git (изменены только названные элементы) плюс `diffshots` по
  HTML-копиям. Как рендерить `.dc.html` локально без страницы типа — открытый вопрос (`../05-design-artifacts/01` §7).
- Отказ публикации после слияния — прочитать весь артефакт и `list scope=files`, слить ещё раз; третий отказ — стоп и сообщение заказчику.

## 2. Пакет правок и формат пункта

```text
#N · critical|major|minor · ширина или «все» · где: артборд, селектор или токен
   Симптом: что сейчас, с числом — «подписи 10,5 px», «вылет 459 px от pre#wide-code», «#b08947 на #f4f1ea = 2,86:1»
   Цель:    что должно быть, с числом и токеном — «16 px, line-height 1,5 (--fs-body)», «--color-muted, 6,1:1»
   Не менять: соседнее, что должно остаться как есть
Keep: что проверено и хорошо. Ничего сверх списка; замеченное — строкой «предлагаю ещё».
```

Короткая грамматика заказчика (`../04-claude-code-native/01` §2.3): `#N: свойство старое → новое`, `#N–#M`, «все кнопки: …»,
«токен --имя: …», «везде: углы 8», «покажи #29 с space-section=120» (предпросмотр без правки файлов). Ответ — «Keep», «откат iter-NN»
или новый пакет. Состав пакета: все critical, затем major по порядку тяжести; minor — только в тех же файлах и если пунктов < 7.

| Тема | Пример цели в пункте |
|---|---|
| мобильная (отдельный раунд) | вылет 0 на 390, 360, 320; кнопка меню ≥ 44 × 44 открывает ссылки разделов; тело 16 px; цели ≥ 44 px; десктоп не меняется |
| типографика | строка текста ≤ 68ch; кегли только из шкалы; интерлиньяж тела 1,5, заголовков 1,15; h1 ≤ 2 строк на 1440 и ≤ 4 на 390 |
| ритм | между секциями — `--space-section` (96 px на 1440, 64 на 390); внутри группы ≤ половины промежутка между группами |
| цвет и контраст | «было/нужно» числом; замена на существующий токен, новых цветов нет |
| движение | свойства по уровню брифа (L0 — `transform`, `opacity`); один момент вместо «появления всего»; reduced motion — конечное состояние |
| ассеты и подписи | слот → файл загрузки; подпись и alt — дословно из списка ассетов; фокус и кадрирование не трогать |
| честность | каждое число не из фактов — строкой: «12 000+» → факт F3 или `[PLACEHOLDER: что]` |
| приметы дом-стиля | примета поимённо + альтернатива токеном: «фон секций — --color-bg #fbfbfc, без кремовой тонировки» (`05` §3) |

## 3. Эхо и уровень правки

- До правки: «N1 #22 = Main.dc.html · `.service-card > a` · элемент — заденет только #22; N2 #7 · `.btn` · компонент — заденет #7, #15,
  #34, #122; остальное не трогаю». После: «Применено: N1 #22 min-height 26 → 44; …» — журнал в чате и в `NOTES.md`.
- Уровень — самый узкий: элемент (одно правило) → компонент (класс) → токен (всё, что его использует). Системная ошибка чинится в
  токене или ДС, а не в каждом экране; «применить ко всему» — предпросмотр → список затронутых меток (`diffshots --expect all`) → «Keep».
- Решение — блок с вариантами и рекомендацией; применённое — эхом «Applied: … → …»; план переписывается «как решено сейчас».

## 4. Решение по итерации

| Условие | Решение |
|---|---|
| публикация не прошла, чужие ключи потеряны | прочитать, слить заново; ключи и маркер индекса — как в живой версии |
| 0 critical и 0 major, маркеров < 4 | рубрика → аудит свежим контекстом → заказчик |
| есть critical или major; прогресс есть (или это первая сборка) | пакет ≤ 7 |
| новые critical вне пунктов (регресс) | откат своих правок итерации (`git checkout <sha> -- <файлы>`), правки заказчика — сохранить; узкая задача |
| «ушла не туда»: сменились жанр, структура, имена, тексты; > 30 % изменений вне пунктов | откат; второй раз — переписать бриф или вернуться к направлениям |
| нет прогресса 2 итерации подряд | смена стратегии (§6) |
| бюджет исчерпан | стоп; заказчику — что осталось и цена ещё одного раунда |

## 5. Прогресс и стоп

- W = 3·critical + major по всем проверкам (`04-checks.md` §3); прогресс — W(N) ≤ 0,7·W(N−1) и нет новых critical вне пунктов.
- После каждого раунда — весь слой проверок на всех ширинах, а не только пункты: правка ломает соседнее. Статусы пунктов — `fixed`,
  `not fixed`, `blocked`, `regressed`; незакрытые — первыми в следующий пакет.

| Стоп | Условие |
|---|---|
| успех → аудит → заказчик | 0 critical, 0 major (с учётом разрешённых брифом примет); маркеров < 4 из 34 и хрома < 3; рубрика ≥ 3 по каждому измерению, контраст ≥ 4; hero не «100vh по центру», не «Hero → 3 фичи → CTA → футер», hero целиком в 1280 × 800; приёмка A–H пройдена |
| аудит закрыт | аудит свежим контекстом нашёл ≥ 1 проблему, все её critical закрыты; ноль находок — неудачный аудит, повторить (`04` §7) |
| бюджет | сборка + ≤ 3 раунда на экран (+ 1 после аудита); «не закончено» подряд ≤ 2 продолжений; один раунд вариантов на проект |
| жёсткий | отказ публикации трижды, потеря правок заказчика, реальные данные клиента в публичной ссылке — стоп и сообщение заказчику |

Время раунда и доля лимита подписки для Claude не мерились (тест T-4 README базы); до замера бюджет — в раундах. `[не проверено]`

## 6. Смена стратегии

| Стратегия | Когда |
|---|---|
| сузить задачу: одна секция или один класс дефектов за раунд | дефекты разбросаны, правка «задевает всё» |
| починить вход, а не экран: шрифт, факт, токен, ДС | дефект из входа (нет гарнитуры, нет факта, неясная система) |
| свежая сессия с резюме и пакетом | длинный контекст, возвращаются старые ошибки |
| «сохранить что есть и попробовать совсем другой подход» | правка по кругу; совет help center Claude Design `[документация]` |
| назад к направлениям или переписать бриф | «ушла не туда» дважды, жанр не держится |
| принять с открытыми minor | остались мелочи, заказчик согласен |

## 7. Паспорт итерации (`review/iter-NN/NOTES.md`)

```yaml
iteration: 3                           # kind: directions | mockup | fix | mobile | motion | audit | stop
model: {id: claude-opus-5-5, effort: xhigh}
artifacts: {design: {url, version, release}, design_system: {url, version, release}, contract: 0.2.47}
synced: {read_at: "…", merged_customer_edits: 4, force: false}
limit_share: {before: 0.12, after: 0.19}   # /usage до и после
checks: {critical: 0, major: 2, minor: 3, W: 2, markers: 2, rubric_min: {states: 3}, diffshots_unexpected: 0}
items: {N1: fixed, N2: "not fixed", N3: blocked}
decision: fix                           # accept | fix | rollback | change-strategy | stop
reason: "2 major: контраст подписей на 390, фокус на тёмной полосе"
decisions: [{what: "тёплая бумага разрешена", who: заказчик, source: "ответ Q3", when: "…"}]
```

Числа — из файлов (ответы инструмента, `diff.md`, отчёты проверок), не из пересказа. Без паспорта через неделю неизвестно, на какой
модели, релизе типа и версии получен результат.

## 8. Редизайн и антипримеры

```text

Сохранить дословно: название продукта, все тексты copy deck, секции и их порядок, маршруты и якоря, ассеты и подписи, CTA и цель.
Менять только: палитру (варианты ДС <A | B>), гарнитуру заголовков, раскладку hero и секции <id>, ритм отступов.
До работы — план из 6 строк на стикере (макроструктура, hero, шрифты, hex ролями, движение, что остаётся); после одобрения — макет.
```

## Частые ошибки

1. Номер `#N` из старого снимка — всегда `marks.json` того снимка, который видел заказчик.
2. Правка класса вместо элемента без предупреждения — все кнопки перекрашены; уровень называть в эхе.
3. Приёмка по одному кадру 1440 — ломаются 390 и тёмная тема.
4. Публикация без чтения живой версии или откат с потерей правок заказчика мышью.
5. Мобильная переделка вперемешку с десктопными пунктами; больше 7 пунктов.
6. Четвёртый и пятый раунд той же формулировкой вместо смены стратегии.
7. Правка оценкой или эмоцией вместо места, числа и «Keep».
