# Проверки макета: слои от дешёвых к дорогим, пороги и что делать при провале

Как Claude проверяет макет холста и его HTML-копии: скрипты → глаза по приёмам →
рубрика → аудит свежим контекстом → заказчик. Основа: слой проверок, отработанный на тестовых и публичных страницах (утилиты
проверены на подброшенных дефектах), `kit` (cd 04/01 §6, смоук), рубрика и маркеры ui. Тип Design
запрещает самопроверку без просьбы (cd 05/01 §7): просьба даётся один раз на проект.

## Выжимка для агента

1. **Знай**: проверка — по постоянной просьбе заказчика, данной один раз на проект (запись в `ARTIFACTS.md`, отзывается в любой
   момент); без неё — не открывать, не снимать, не перечитывать результат. `[решение заказчика]` `[исходник: SKILL.md типа]` → §1
2. **Делай**: слои по порядку — скрипты → глаза → рубрика → аудит свежим контекстом → заказчик; дорогой слой не запускать, пока
   дешёвый красный; после каждой правки — весь слой скриптов на всех ширинах, не только пункты. `[практика]` → §2
3. **Делай**: кадры — свои, на ширинах приёмки: артборды холста 1440, 1280, 1024, 768, 390, 360 (+ тёмная тема твиком);
   вылет на 320, ресайз и зум — на сборке.
   `[решение заказчика]` → §1
4. **Не делай**: не принимай по отчёту модели («совпадает на 100 %», «все ворота пройдены», «полностью адаптивно») — свежий аудит
   такие отчёты опровергал. `[консенсус]` → §2
5. **Делай**: проверяй и числами, и глазами: глаза поймали бейджи на подписях при счётчике 0, `ui_audit.py` — контраст 2,55:1, который
   глаза пропустили. `[проверено: kit]` → §2
6. **Делай**: честность — всегда critical: сток и хотлинк, подпись не из списка ассетов, число не из фактов, отзыв без источника,
   «рыба». `[мнение базы]` → §3 D
7. **Делай**: мобильная — до вкуса: вылет 0, навигация на 390 видна, тело ≥ 16 px, цели ≥ 44 px (не меньше 24). `[консенсус: ux]` → §3 B
8. **Делай**: ресайз 1440 → 390 → 1440 без перезагрузки — скриптом (медиа первого экрана ≤ 1 000 мс); наложения текста подтверждай
   глазами — на декоративных слоях проверка шумит; canvas и WebGL — только глазами. `[проверено: утилита на тестовых и публичных
   страницах]` → §3 B, §4
9. **Знай**: детекторы — вход, диагноз — порог ui 11/04: ≥ 4 маркеров из 34 или ≥ 3 «хрома» = шаблон. Заказанную брифом примету
   разрешать явно, иначе ложный major. `[консенсус]` `[проверено]` → §3 C
10. **Делай**: глазами — 10 приёмов за 10–15 минут по всей странице, не только hero. `[практика]` → §5
11. **Делай**: рубрика — две задачи: баллы 0–5 по 10 измерениям (+ гейты лендинга) и отдельно место дефекта (из машинного отчёта или
    `#N`); отчёт — первым; 3 прогона, находка из ≥ 2. Без рубрики судья на «какой лучше» — монетка (51,58 %), с описанными
    критериями — корреляция с экспертами ≈ 0,99. `[исследование]` → §6
12. **Делай**: судья — Claude Opus 5.5 в отдельной сессии без контекста сборки; решает человек; рубрика штрафует избыточность: судья
    выбирал «богаче» в 3 из 4 пар, и все три — брак. `[решение заказчика]` `[проверено: опыт с судьёй]` → §6
13. **Делай**: аудит свежим контекстом — без правок, находка «что / где / тяжесть / как исправить»; ноль находок — аудит не удался.
    `[практика]` `[исследование: ux]` → §7
14. **Знай**: только заказчик решает вкус и выбор варианта, факты, права на фото и логотипы, тон. `[практика]` → §8
15. **Знай**: ложные находки известны — «сайдбар» `ui_audit.py` на лендинге, «кремовая палитра» на заказанной бумаге, «длинное тире»
    на русском тексте, «нет навигации» на одноэкранной арт-странице. `[проверено]` → §9

## 1. Когда и что проверять

- Просьба заказчика — одна на проект: строка в `ARTIFACTS.md` («проверки макета разрешены: дата, кто; отзыв — в любой момент»).
  Отзыв — проверки только по отдельной просьбе.
- Объект: артборды холста (смотрит заказчик в редакторе), их HTML-копии (`kit`: кадры, метки, `diffshots`, скрипты), на этапе кода —
  сборка. Локальный рендер `.dc.html` без страницы типа — открытый вопрос (`../05-design-artifacts/01` §7). `[не проверено]`
- Ширины приёмки — `../../common/acceptance-widths.yaml`: артборды всех ширин и вылет на 320 на сборке; тёмная тема — если есть.

## 2. Слои

| Слой | Что | Инструменты | Время | Ворота дальше |
|---|---|---|---|---|
| 0 публикация | принята, правки заказчика слиты, чужие ключи целы | ответ `Artifact`, `git diff` | 1–2 мин | зелёное |
| 1 скрипты | вылет, мобильная, шрифты, честность, приметы, контраст, фокус | `kit/shot.py`, `../../scripts/claude-design/mockup_checks.py page` и `resize`, `ui_audit.py` | 3–6 мин машины | 0 critical |
| 2 глаза | композиция, иерархия, наезды, подписи против картинок, вся страница | свои кадры, карта страницы, вырезы | 10–15 мин | нет новых critical и major |
| 3 рубрика | 10 измерений 0–5 + гейты лендинга | Opus 5.5, отдельная сессия, PNG | 5–10 мин | ≥ 3 по каждому, контраст ≥ 4 |
| 4 свежий аудит | второе мнение без контекста сборки | субагент или новая сессия (`07` §7) | 5–15 мин | ≥ 1 находка, critical закрыты |
| 5 заказчик | вкус, факты, выбор варианта | холст, страница слепых пар (`06` §5) | 3–10 мин | одобрение |

Метрики — скрининг, а не вердикт: связь «метрика ↔ восприятие» на 12 интерфейсах не значима (ui 13/02 §3.8). `[исследование]`

Проверки макета — слой ниже ворот страницы: чек-лист `SITE-*` они не заменяют (`../../../references/claude-design.md § Приёмка`);
вес и LCP — числа профиля страницы, замер — после сборки.

## 3. Проверка → порог → при провале

Тяжесть: critical — итерацию не принимать, пункт первым в пакете; major — в тот же пакет; minor — если в пакете есть место (`03` §2).

**A. Публикация и сборка**

| Проверка | Порог | При провале |
|---|---|---|
| публикация, слияние | принята; чужие ключи и маркер индекса сохранены | прочитать живую версию, слить заново (`03` §1) |
| консоль, 404, битые картинки | пусто | major; critical, если ломает показ |
| изменены только свои файлы | `git diff` ⊆ файлов пунктов | откат лишнего; critical «не трогать» |

**B. Адаптив и вёрстка** (поля — `kit/shot.py`, проверки — `mockup_checks.py`)

| Проверка | Порог | При провале |
|---|---|---|
| горизонтальный вылет (`overflow_px`) | 0 на всех ширинах, включая 360 и 320 | critical: элемент-виновник и ширина |
| навигация на телефоне | кнопка меню ≥ 44 × 44 или ≥ 2 видимые ссылки; у частей артборда `<Имя>-<ширина>-<N>` — в первой части | major |
| тело на телефоне | ≤ 25 % абзацев внутри `main` (≥ 8 слов) мельче 16 px | major |
| мелкий текст (`small_text_elements`) | 0 узлов < 12 px | major |
| цели касания (`small_targets_24`, `_44`) | 0 < 24 px (кроме ссылок в тексте), основные ≥ 44 px | major |
| ресайз 1440 → 390 → 1440 без перезагрузки | медиа первого экрана ≤ 1 000 мс, вылета нет, кадр после возврата ≠ ≤ 0,02 | major; critical, если hero пуст |
| hero в 1280 × 800 | заголовок, лид и CTA в первом экране; низ hero ≥ 1,3 × верхнего отступа | major |
| наложение строк текста | 0 пар (кроме заданных брифом слоёв); подтвердить глазами | major: пара и координата |
| текст исчез после анимации (`invisible_text`) | 0 при reduced motion | major |
| шрифты (`fonts_missing`) | пусто: объявленный шрифт реально отрисован; метрический двойник системного шрифта пропажей не считается | major: подключить файл или семейство |
| один h1, `lang` | 1 (у частей артборда `<Имя>-<ширина>-<N>` — в первой части); `lang` = язык сайта | minor |

**C. Приметы дом-стиля и шаблонный хром** — таблица `05-default-look.md` §3.

| Проверка | Порог | При провале |
|---|---|---|
| приметы без заказа брифом | кластер примет не сложился | член сложившегося кластера — major: примета поимённо + альтернатива токеном; одиночная примета — minor: вопрос заказчику, было ли это решением |
| маркеры экрана приложения | диагноз — ui 11/04 §1.3 | ≥ 3 хрома — major; иначе minor пакетом |
| структура «Hero → 3 фичи → CTA → футер», подвал-отпечаток | нет | major: форма страницы из плана |
| площадь акцента | ≤ 5 % вьюпорта | minor `[спорно]` |

**D. Честность: факты, тексты, ассеты**

| Проверка | Порог | При провале |
|---|---|---|
| сток, заглушечные сервисы, хотлинк | 0 | critical: только загрузки; пустой слот — заглушка «placeholder» |
| подписи и alt против списка ассетов | 100 % дословно; картинка-загрузка `/_blob/<id>` находится через реестр загрузок: колонка «id загрузки» списка ассетов, затем «Загрузки» `ARTIFACTS.md`; подписи и alt — у `<img>`; постер и источники видео, источники `<picture>` и фоновые загрузки холста сверяются со списком ассетов без подписей | critical (подпись), major (alt) |
| числа против колонки фактов и copy deck | 0 чисел вне белого списка (даты источников число не «легализуют») | critical: факт или `[PLACEHOLDER: что]` |
| текст против copy deck | ≤ 10 % блоков (≥ 3 слов) вне copy deck | major |
| отзывы, имена, логотипы клиентов | 0 без источника | critical |
| «рыба» (lorem, «Feature 1», «John Doe») | 0; `[PLACEHOLDER]` — только из списка «Нет» | critical |
| JSON-LD и мета против фактов | совпадает | major |

Для HTML-копий и сборки — `mockup_checks.py page --facts --copy --assets-readme`; сверка чисел — ещё и text
`../../../scripts/text/claims_check.py` (вход `html`).

**E. Система, доступность, движение, вес**

| Проверка | Порог | При провале |
|---|---|---|
| значения вне токенов | холст: каждый литерал ∈ значений токенов ДС; `kit` и код: 0 литералов вне `tokens.css` | major |
| контраст | текст ≥ 4,5:1, крупный ≥ 3:1 после наложения альфы; градиент и фото под текстом — F83 по буквам (ai-media 10/03 §1), а не глазами | major |
| фокус с клавиатуры | виден на каждой остановке (Tab × 20) | major |
| `ui_audit.py` (пресет, 1440 + 390 тач, reduced motion) | нет blocker и serious | major |
| движение | `transition: all` 0; анимация width, height, top, left 0 | minor; major, если дёргает раскладку |
| вес и LCP (после сборки) | числа профиля страницы (SG-WEIGHT-01) | major |

**F. Композиция и вкус**: рубрика ≥ 3 по каждому измерению, контраст ≥ 4 (§6); «брать» референсов есть, «не брать» нет; силуэт
200 px отличается от референсов и соседних вариантов; маркеров и примет нет и ниже первого экрана; вкус — заказчик.

## 4. Команды

```bash
K=../../scripts/claude-design/kit; P=design; R=review/iter-03; U=http://127.0.0.1:8765/landing.html
python3 $K/shot.py $P $R --tiles --prev review/iter-02/marks.json --min-free-gb 2       # кадры, метки, поля проверок
python3 $K/diffshots.py review/iter-02 $R --expect 16,22 --strict                       # локальность правки
python3 ../../scripts/claude-design/mockup_checks.py page $U --views 1440x900,390x844 --facts input/facts.md \
  --copy input/copy.md --assets-readme input/assets.md --uploads ARTIFACTS.md --allow "<что заказал бриф>" --json $R/checks.json --md $R/checks.md
python3 ../../scripts/claude-design/mockup_checks.py resize $U --shots $R/resize                        # ресайз без перезагрузки
python3 ../../scripts/ui/ui_audit.py $U --preset consumer --viewport 1440x900 --viewport 390x844 \
  --touch --reduced-motion --tab 20                                                     # контраст, фокус, состояния
```

Ключ `--uploads` — реестр загрузок холста (`ARTIFACTS.md`, таблица «Загрузки»); без ключа утилита берёт файл в папках выше списка
`--assets`. Браузер — один за раз (свободная память ≥ 2 ГБ). Утилита `mockup_checks.py` — копия без правок: id проверок в выводе пока старые,
подкоманда `watch` не нужна (заголовок файла). Входы — markdown-таблицы: у фактов колонка, начинающаяся с «Факт» (или «Текст на
странице»), у ассетов — «Файл», «Подпись», «Alt» (`02` §3); YAML text — переводить в таблицу или адаптировать утилиту. Покрытие —
36 из 37 подброшенных признаков, 0 ложных на чистой странице (оценка сверху: признаки подбросил автор). Слепые зоны: canvas и WebGL
(< 12 текстовых узлов или холст > 50 % экрана) и ряд цифр мельче 28 px — глазами; одноэкранная арт-страница — без проверки навигации.

## 5. Глазами: 10 приёмов за 10–15 минут

1) Карта всей страницы: форма = план, хрома и повторов секций-шаблонов нет нигде. 2) Первый экран 1440, 1280, 390: заголовок, лид и
CTA видны, hero не «стопка по центру». 3) Прищур (размытие 6–10 px): группы пятнами, у главного блока воздух, нет «клетки» линий.
4) Линейка в 4 местах: подпись–поле 4–8 px, поле–поле ≥ 2×, одинаковые отступы карточек, кнопка = полю по высоте. 5) Подписи против
картинок. 6) Телефон по экранам сверху вниз: навигация, одна мысль на экран, текст не на пёстром фоне. 7) Наложения и обрезки: 0.
8) Tab × 10: фокус виден и не обрезан. 9) Рядом с референсом: «брать» есть, «не брать» нет, силуэт не совпадает. 10) Три вопроса:
«Откуда это? Есть ли голос? Заметил бы я, если бы это исчезло?»

## 6. Рубрика: судья-Opus в отдельной сессии

- Две задачи — два вызова: (а) баллы 0–5 по 10 измерениям (иерархия, консистентность, отступы и ритм, цвет, типографика,
  выравнивание, состояния, плотность, различимость, контраст; якоря —
  `../../ui/13-evaluation-checklists/02-rubrics-and-vlm-critic.md` §1) и гейты лендинга; (б) место дефекта — не просить
  координаты у модели (IoU < 0,20 у всех), брать из отчёта скриптов или `#N`.
- Машинный отчёт — первым (нашёл нарушение контраста, а судья поставил 4 — балл опускается до 2); кадры — PNG без потерь, 1440, 1280,
  390, подписи координат по краям (сетка поверх кадра вредит).
- Замечание = ожидаемое + разрыв + что сделать + регион словами, иначе не засчитывается; ≤ 12 замечаний; ≥ 2 сильные стороны;
  «не закончено» — пометка, а не дефект. 3 прогона, находка — из ≥ 2; в сравнении — стороны переставлять, расхождение = «неразличимы».
- Гейты лендинга: hero не 100vh со всем по центру; не «Hero → 3 фичи → CTA → футер»; ≤ 1 эффект наведения на элементе; фокус без
  затухания; акцент ≤ ≈ 5 % площади; навигация и подвал — не отпечаток шаблона; hero целиком в 1280 × 800; нет нарисованного хрома
  браузера и телефона; подписи кнопок в одну строку.
- Калибровка на своих страницах (8–12 размеченных кадров; few-shot даёт +55 % качества критики) — не сделана. `[не проверено]`
  Что проверяет калибровочный набор и что даёт доверие судье — `../../common/judge.md` §6.

## 7. Аудит свежим контекстом

Без правок; вход — `ACCEPTANCE.md`, README ДС, бан-лист, машинный отчёт («числа не перепроверяй, ищи то, что числа пропускают»),
кадры всех ширин. Находка: что (названная проблема) · где (артборд и `#N` или регион) · тяжесть (critical — нарушает MUST или
«выглядит как шаблон»; major — выглядит сгенерированным или мешает; minor — вкус) · как исправить одной строкой. Структурный
отпечаток (hero по центру + три равные карточки + CTA + футер) и любое число, имя, логотип или цитата не из фактов — critical. Итог
«N critical · M major · K minor» и три правки с наибольшим эффектом. Триаж Claude: отбросить находки против брифа (с причиной) и дубли;
critical и major — ≤ 1 раунд. Ноль находок — повторить с «найди минимум три или объясни, почему каждая проверенная область в порядке».

## 8. Только заказчик

Вкус, выбор варианта и направления (согласие людей о вкусе — Fleiss κ 0,29–0,31, модель на попарном «лучше» — монетка → страница
слепых пар, `06` §5); факты — числа, имена, цены, даты, отзывы (свободный вопрос на каждый пропуск); права на фото и логотипы (список
ассетов с источником); тон и формулировки (2–3 варианта заголовка рядом); «узнаётся ли продукт» (кадр без логотипа: «это ваш продукт?»);
любое отступление от брифа — одним блоком, с ценой в раундах.

## 9. Ворота и ложные находки

| Ворота | Условие |
|---|---|
| итерация принята к правке | публикация и слияние зелёные |
| итерация без правок | 0 critical и 0 major по A–E (с учётом разрешённых примет); маркеров < 4, хрома < 3 |
| готово к вкусу | + рубрика ≥ 3 по каждому измерению, контраст ≥ 4; гейты «не по центру», «не шаблон», «1280 × 800» пройдены |
| к заказчику | + свежий аудит нашёл ≥ 1 проблему, её critical закрыты |
| приёмка | заказчик одобрил; открытые `[PLACEHOLDER]` перечислены |

Ступени — ориентир раунда правок, а не остановка этапа: `mockup_checks.py` завершает прогон кодом 2 только при `critical` и при
сложившемся кластере примет, `major` идёт строкой отчёта. Этап держат пять гейтов (`../../../references/phases.md § Принципы всех

Ложные: `ui_audit.py` J2/J3 «сайдбар» на лендинге; «кремовая палитра» детектора на заказанной бумаге и «частый шрифт» на брендовой
гарнитуре; «длинное тире» на русском тексте из copy deck (норма набора); проверка навигации на одноэкранной арт-странице; `I1` контраста
для текста поверх фото (считается к фону страницы); счётчик эмодзи по `\p{Extended_Pictographic}` ловит «©» и «↔».

## Частые ошибки

1. Проверять без просьбы заказчика — нарушение правила типа; спросить или сослаться на постоянную просьбу.
2. Смотреть только hero и только 1440; пропускать 360, 320 и ресайз; после правки проверять только пункты.
3. Считать находку детектора вердиктом без триажа ложных.
4. Сверять числа со всей таблицей фактов (годы из дат источников «легализуют» выдумку) или не сверять без таблицы.
5. Просить судью «какой лучше?» без рубрики; просить координаты; один прогон вместо трёх.
