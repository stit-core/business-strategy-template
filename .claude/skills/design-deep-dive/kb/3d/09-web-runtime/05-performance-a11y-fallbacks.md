### 2.3. Решение «3D или постер» и подстройка после старта

| условие | как узнать | что делать |
|---|---|---|
| нет WebGL2 | `canvas.getContext('webgl2')` = null | постер (он уже на странице) |
| экономия трафика | `navigator.connection?.saveData` (Chromium; заголовок `Save-Data: on`) | постер, без видео-петель |
| мало памяти | `navigator.deviceMemory < 2` (Chromium) | постер или телефонный набор |
| reduce | `matchMedia('(prefers-reduced-motion: reduce)')` | 3D можно, но один кадр и без автодвижения |
| tier 0 (detect-gpu) | блок-лист, программный рендер | постер |
| медленный кадр | медиана интервалов кадров: three.js — > 20 мс в первые 2–3 с; свой движок — > 24 мс на 40 занятых кадрах | по порядку: плотность пикселей → лишние проходы (пост, тени) → петли → постер |
| ошибка загрузки / декодера | исключение в `boot()` | остаться на постере, `console.error` один раз |

[проверено: A/07, hero-lazy (WebGL2, saveData, deviceMemory, reduce); документация: A 02 §5.1; подстройка по кадру — F1/06 (код
работает), эффект на телефоне — не проверено]. `navigator.connection` и `deviceMemory` есть только в Chromium — в Safari условия
пропускаются (3D грузится) [документация: MDN].

```js
// three r186 — [проверено] подстройка качества по времени кадра первых секунд
export function createQualityGovernor(renderer, { maxDpr = 1.5, minDpr = 1, budgetMs = 20, onDegrade } = {}) {
  let dpr = Math.min(devicePixelRatio, maxDpr), samples = [], last = 0, done = false;
  return function frame(now) {                         // вызывать в начале каждого кадра цикла с временем rAF
    if (done) return dpr;
    if (last) samples.push(now - last);
    last = now;
    if (samples.length < 90) return dpr;               // ≈ 1,5 с при 60 Гц
    samples.sort((a, b) => a - b);
    const median = samples[samples.length >> 1];
    if (median > budgetMs && dpr > minDpr) {           // медленно: снизить разрешение и сообщить (выключить пост, тени)
      dpr = Math.max(minDpr, dpr * 0.8);
      renderer.setPixelRatio(dpr);
      onDegrade?.({ median, dpr });
      samples = []; last = 0;                           // ещё одна проверка после понижения
    } else done = true;
    return dpr;
  };
}
```

Регулятор выше — для сцены three.js с текстурами и MSAA: он стартует с DPR ≤ 1,5, держит память буферов (§1.2) и снижает
только вниз. У сцены своего движка — бюджет пикселей холста и множитель плотности 0,7…1 в обе стороны: медиана 40 занятых
кадров > 24 мс → ×0,85, < 12,5 мс → ÷0,85; ниже 0,7 не снижать — «нечётко» заметнее, чем 50 кадров/с; сниженная плотность
дала отзыв заказчика «модели нечёткие» (`../16-js-scenes/01-engine.md` §6) [проверено] ПК, [кейс] телефон. Порядок
деградации у обоих — плотность → лишние проходы (пост, тени) → петли → постер (там же) [практика].

## 3. Цикл отрисовки: только когда нужен

- Правило: рисовать, если (блок виден) и (вкладка активна) и (есть движение: анимация без reduce, взаимодействие, загрузка);
  иначе один кадр и `setAnimationLoop(null)` — 0 вызовов в покое [проверено: A/07, hero-lazy: reduce — 0 вызовов, движение 0 %].
- Статичная модель с орбитой — рендер по требованию: кадр на событие `change` контролов и на resize; инерция контролов
  (`enableDamping`) требует кадров, пока она не затухнет [практика: A 02 §5.4; manual «Rendering on demand»].
- Замер рынка: 25 из 33 наградных сайтов рисуют каждый кадр без движения, Spline — 192 вызова в покое; 13 из 16 не реагируют на reduce;
  Stripe рисует кадр и останавливается [проверено: A 04 §6].
- Время для анимации — только `Timer`/`delta` (частота rAF — 60/120/144 Гц) [V:YyqBdN71nFs 12:03; V:sqkSrTq1Kos 08:11]; после паузы —
  `timer.reset()`, иначе скачок [проверено: F1/01 исходник `Timer.reset`].

```js
// three r186 — [проверено] цикл только при видимости, открытой вкладке и без reduce; кадр по требованию
export function createRenderLoop(renderer, scene, camera, host, { animate = null, onFrame = null } = {}) {
  const reduce = matchMedia('(prefers-reduced-motion: reduce)');
  let visible = true, paused = false, dirty = true, on = false;
  const animating = () => !!animate && !paused && !reduce.matches;
  const draw = () => { renderer.render(scene, camera); dirty = false; };
  const tick = (t) => {
    onFrame?.(t);
    if (animating()) { animate(t); dirty = true; }
    if (dirty) draw();
    if (!animating()) { renderer.setAnimationLoop(null); on = false; }   // кадр по требованию нарисован — стоп
  };
  const update = () => {
    const want = visible && !document.hidden && (animating() || dirty);
    if (want !== on) { renderer.setAnimationLoop(want ? tick : null); on = want; }
  };
  const io = new IntersectionObserver((es) => { visible = es[0].isIntersecting; update(); });
  io.observe(host);
  document.addEventListener('visibilitychange', update);
  const onReduce = () => { dirty = true; update(); };     // пользователь включил reduce во время просмотра
  reduce.addEventListener('change', onReduce);
  update();
  return {
    invalidate() { dirty = true; update(); },           // кадр по требованию: controls 'change', resize, смена материала
    setPaused(p) { paused = p; dirty = true; update(); },
    get running() { return on; },
    dispose() { io.disconnect(); document.removeEventListener('visibilitychange', update); reduce.removeEventListener('change', onReduce); renderer.setAnimationLoop(null); on = false; },
  };
}
```

Без движения цикл живёт один кадр: `invalidate()` → кадр → `setAnimationLoop(null)`; при анимации — пока блок виден, вкладка открыта и
нет reduce [проверено: F1/06 — 0 вызовов после `setPaused(true)` и одного кадра].

## 4. Вызовы отрисовки, инстансинг, LOD, текстуры

### 4.1. Меньше вызовов

| приём | числа | где делать |
|---|---|---|
| инстансинг повторов (`InstancedMesh`, `BatchedMesh`; из Blender — GN-инстансы + `EXT_mesh_gpu_instancing`) | 1000 мешей → 1 вызов; 900 объектов — 20 КБ вместо 0,8–24 МБ | Blender (E 01 §4.7) или JS [V:EhZwt9P4GP4 02:13; проверено: E/08, E/17] |
| палитра-текстура вместо материалов | лендинг Bruno Simon 375 → 222 вызова | Blender (UV в палитру) [V:EhZwt9P4GP4 05:22; V:H1oNuKChsdU 23:59] |
| слияние статики с одним материалом | меньше вызовов и памяти | gltf-transform `join` (теряет имена — E 03 §4.1) или `BufferGeometryUtils.mergeGeometries` [V:BH1R29YvLOk 31:57] |
| 2–3 материала на сцену | вызов = меш × материал | Blender [V:H1oNuKChsdU 24:13; E 04 §4.5] |
| без transmission и лишних теней | transmission ×2, тень — +проход | `01` §6.3, §7 [проверено] |
| `renderer.sortObjects = false` при малом перекрытии | снимает сортировку на CPU | JS [V:EhZwt9P4GP4 12:37] |

### 4.2. Отсечение и LOD

- Frustum culling (`object.frustumCulled = true`) включён по умолчанию; для инстансов — по общему габариту. Автоматического
  отсечения невидимого (occlusion) нет: `WebGPURenderer` умеет запрос `object.occlusionTest`/`renderer.isOccluded()`, отсекать —
  своим кодом; для «миров» — зоны/комнаты своим кодом [V:CHYxjpYep_M 02:04; V:EhZwt9P4GP4 08:28; W7 §8].
- LOD: `THREE.LOD` (уровни — отдельные меши из Blender Decimate) или прогрессивная загрузка (Needle Progressive, пример
  `webgl_loader_gltf_progressive_lod`) — для hero-продукта обычно не нужен: 50 тыс. треуг. хватает на весь диапазон [практика: A 02 §4.4].
- Сцены по секциям: смонтированы активная и соседние, остальные — `dispose()` (`01` §9) [практика: Shopify через A 02 §4.4].

### 4.3. Текстуры

Формат по цели (замер F1/03 на Camera_01, 9 карт 1024²): WebP q80 — 940 КБ, GPU 48 МБ, ΔE к PNG 0,10; KTX2 ETC1S — 1157 КБ, GPU 12 МБ,
первый кадр при CPU ×4 108 мс против 206 мс у WebP, ΔE 0,25; UASTC с RDO для нормалей и ORM — 5,6 МБ (для веба тяжело) [проверено:
F1/03]. Разрешение — самый дешёвый рычаг: 2048 → 1024 делит вес в 2,3 раза и память в 4 раза (E/18). Подробно — `06` §3.

## 5. Доступность и SEO

### 5.1. Смысл — в HTML

- `<canvas>` не кандидат LCP; страница «только canvas» не даёт LCP вовсе; H1, текст, цена, CTA — в исходном HTML (ИИ-краулеры JS не
  исполняют) [проверено: A/04; исследование: Web Almanac 2025 через A 02 §6.1].
- Декоративный canvas — `aria-hidden="true"` (без фокусируемых потомков у него и предков); смысловой — у `<img alt>` постера рядом
  [проверено: hero-lazy; документация: XA2 §6]. Голому `<canvas aria-label>` нужна роль — `aria-label` на неинтерактивном элементе
  запрещён спецификацией (XA2 §3.3); ближайший готовый шаблон для интерактивной сцены — `<div role="region" aria-labelledby tabindex="0">`
  вокруг canvas (XA2 §8.11) [документация; для 3D-вьюера — вывод F1].
- Текст поверх 3D — на подложке: контраст 4,5:1 (1.4.3) при любом кадре сцены; правил для «текста на меняющемся изображении» в
  соседних базах нет — проверять худший кадр [документация: XA1 §5.2; вывод F1].
- Товар в поиске: `schema.org/3DModel` через `Product.subjectOf` и Merchant `virtual_model_link` — A `02` §6.1.

### 5.2. Движение

- Reduce — «уменьшить, а не убрать»: остановить автоповорот и покачивание, параллакс, камеру от прокрутки, автопролёт; оставить ручное
  вращение, мгновенную смену и индикатор загрузки; кроссфейд постер → canvas — мгновенный (hero-lazy: `transition: none`) [документация:
  UM3 §3.1–3.2, XM3 §7.3; проверено: hero-lazy].
- Слушать `change`: `matchMedia('(prefers-reduced-motion: reduce)').addEventListener('change', …)` — пользователь может включить reduce
  во время просмотра [документация: XM3 §7.2; проверено: A/07].
- WCAG 2.2.2 (A): движение, которое запускается само (в т. ч. при появлении в области видимости), длится > 5 с и идёт рядом с другим
  контентом, требует паузы/стопа/скрытия; прелоадер исключён, только если контент не показан параллельно [документация: UM3 §2.2]. Hero с
  автовращением — нужна кнопка (hero-lazy: `<button aria-pressed>` 44 px, фокус-обводка 3 px + белый ореол по XA2 §7.2) [проверено: hero-lazy].
- WCAG 2.3.1: не больше 3 вспышек в секунду (bloom-«вспышки», глитч) [документация: XM3 §7.1].
- Вестибулярные факторы: доля экрана под движением, рассогласование с прокруткой (параллакс, scrolljacking), большая дистанция камеры
  за короткое время; колебания около 0,2 Гц (период ≈ 5 с) — избегать; hero-lazy качается с периодом ≈ 16 с [документация: UM3 §1.2,
  XM3 §7.4; проверено: hero-lazy]. Не больше одного постоянно движущегося элемента на экране (XM3 §2.3).

### 5.3. Интерактивный вьюер: клавиатура и указатель

| требование | как | источник |
|---|---|---|
| достижим с клавиатуры, Tab не захвачен | контейнер `tabindex="0"`, стрелки вращают только в фокусе, Tab уходит дальше | XA1 §6.1 (ловушка «карта, забирающая стрелки») |

| видимый фокус (2.4.7, 2.4.11) | `:focus-visible { outline: 3px solid #000; box-shadow: 0 0 0 6px #fff }` | XA2 §7.2 |
| имя и роль (4.1.2) | нативные `<button>`; панель — `role="toolbar"`, угол — `role="slider"` с `aria-valuenow` | XA2 §8.2, §8.8 |
| автоповорот как карусель | стоп при фокусе, пауза — первым элементом | XA2 §8.2 |

[документация: соседние базы — применение к 3D — вывод F1; не проверено скринридером]. model-viewer 4.x закрывает клавиатуру

### 5.4. Ожидание загрузки

Постер — мгновенный результат; индикатор поверх него — только если 3D просили явно (кнопка «Смотреть в 3D»): показывать через 200–300 мс,
держать ≥ 300–500 мс, определённый прогресс с 5 с, «Отменить / остаться на фото» с 10 с; прогресс не должен висеть на 99 % (после
скачивания — «декодирование», «шейдеры») [документация: XS2 §2.2–2.5, §4.1–4.6]. Для автозагрузки hero индикатор не нужен: постер уже
показан, 3D — улучшение. Прогресс по байтам — `loadGLB({ onProgress })` в `01` §3.2 (при brotli на лету `content-length` врёт).

## 6. Запасные варианты

### 6.1. Постер = 3D

Постер рендерится из того же GLB, тем же тонмаппингом и тем же кадром (hero-lazy: `index.html?poster` → `make_poster.py`, AVIF 19,8 КБ
с альфой) — при подмене картинка не «прыгает»; постер из Blender допустим, только если материал запечён и вид — «Khronos PBR
Neutral» (A/07: постер с процедурной этикеткой при белой GLB-модели) [проверено: hero-lazy, A/07]. Размер < 80 % вьюпорта и
`fetchpriority="high"` + `<link rel="preload" as="image">` — тогда он LCP (52 / 460 мс) [проверено: hero-lazy, A/04]. Любая ошибка
(нет WebGL2, 404, декодер, зависший CDN) — страница остаётся на постере [проверено: F1/02 — зависший запрос к CDN].

### 6.2. Потеря контекста

Норма страницы — постер сразу; живая сцена не возвращается на старом холсте: рантайм сцен снимает её и оживляет заново на
свежем холсте при следующем подлёте, не раньше чем через 3 с и не больше одного раза, дальше место — постер насовсем
(`../16-js-scenes/02-stage-runtime.md` §2). Для three.js это `dispose()` рендерера и новый `WebGLRenderer` на клоне холста
[практика]. `onRestored` в коде ниже — запасной путь одиночной сцены three.js без рантайма: three пересоздаёт ресурсы сам
[проверено].

```js
// three r186 — [проверено] потеря и восстановление WebGL-контекста: постер вместо пустого canvas
export function handleContextLoss(renderer, host, { onLost, onRestored } = {}) {
  const canvas = renderer.domElement;
  const lost = (e) => { e.preventDefault(); renderer.setAnimationLoop(null); host.classList.remove('is-live'); onLost?.(); };
  const restored = () => { onRestored?.(); host.classList.add('is-live'); };   // three пересоздаёт ресурсы сам; цикл — снова по правилам §3
  canvas.addEventListener('webglcontextlost', lost);
  canvas.addEventListener('webglcontextrestored', restored);
  return () => { canvas.removeEventListener('webglcontextlost', lost); canvas.removeEventListener('webglcontextrestored', restored); };
}
```

`e.preventDefault()` в `webglcontextlost` обязателен, иначе браузер не вернёт контекст [документация: MDN]. Проверка —
`renderer.getContext().getExtension('WEBGL_lose_context').loseContext()` / `.restoreContext()` [проверено].

## Частые ошибки

1. Цикл `renderer.setAnimationLoop(tick)` навсегда — рендер вне экрана, в скрытой вкладке и при reduce (25 из 33 сайтов) [проверено].
2. Reduce через CSS-медиазапрос для WebGL — цикл продолжает крутиться; нужен `matchMedia` + `change` [документация: XM3 §7.2].
3. Полный DPR 2,625–3 на телефоне (Spline: TBT 1,9 с) [проверено].
4. Один набор ассетов для телефона и десктопа [проверено: A/04, hero-lazy].
5. KTX2 «везде, потому что лучше» — на телефоне с медленной сетью и текстурами 512² транскодер съедает выигрыш (+1,9 с) [проверено: hero-lazy].
6. Решение по detect-gpu без других сигналов (iPhone всегда tier 1) [проверено].
7. Первый кадр 3D по первому draw call зонда — это PMREM окружения [проверено].
8. Автоповорот без кнопки паузы (2.2.2) и «дыхание» с периодом 4–6 с [документация: UM3 §2.2, XM3 §7.4].
9. Орбита только перетаскиванием (2.5.7) и стрелки, перехваченные без фокуса [документация: XA1 §12.3, §6.1].
10. Прелоадер на весь экран поверх H1 — LCP 31,6 с у Immersive Garden [проверено].
11. `aria-hidden` на контейнере, внутри которого есть кнопки [документация: XA2 §6].
12. Потеря контекста без `preventDefault()` — пустой прямоугольник до перезагрузки [документация: MDN].
