## 4. Решения и почему (числа — README «Итоги фазы 2», NOTES «Фаза 2 — KB3», rules.md)

- **Телефон, набор**: окно 700 px кадра T по ширине сцены (клавиша 82 px кадра → 43,9 CSS px); тот же ракурс, что на десктопе
  (A/C `setViewOffset`, B — CSS-обрезка) — так лучи и обводы клавиш верны без правок; буква на отпускании (свайп не печатает).
- **ГРИП постера A**: KB2 ошибся в диагнозе — BokehPass размывал, но ap 0,16 даёт кружок в 10–20 раз меньше f/2,8; стандартный
  шейдер даёт ореол (ap 0,7) и двоение (1,5) → свой «разброс как сбор» с радиусом по тонкой линзе камеры Blender.
- **WebP вместо KTX2 для атласа C** (отступление от ответа 4 — по доказательствам): ETC1S сиреневит серые PBT, транскодер Basis
  212 КБ br; WebP −229 КБ br и цвет как у A/B.
- **three по намерению**: EG-PERF-01 считает длинные кадры всей фазы прокрутки, «отложить до паузы» не помогает; загрузка по
  первому нажатию/касанию/клику или остановке ≥ 2,5 с на разделе с 3D → 0 мс длинных кадров в прокрутке у A и C.
- **Телефонный GLB C** `-si 0.4`: 107 → 42,8 тыс. треуг., без видимой разницы на телефоне.
- **Шток A** двигается с колпачком (крестик сквозь нажатый колпачок).
- **Откат итерации** «тени слоёв + AO 4,5 см в разборке A/C» — без видимой разницы.
- **Очередь**: сначала один тяжёлый вход на вариант (судья + ворота), с 03:30 — по правилу v2.2 два входа (картинки/marketing без
  «тишины», замеры времени — в «тишине»).
