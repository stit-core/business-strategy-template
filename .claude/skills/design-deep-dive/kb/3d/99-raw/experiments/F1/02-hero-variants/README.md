# F1/02 — hero «постер → 3D после LCP» на телефонном профиле: способы подключить three, compileAsync, декодеры свой домен / CDN, KTX2 / WebP

Цель: проверить паттерн A/07 на профиле Pixel 7 (CPU ×4, 1,6 Мбит/с, 150 мс RTT; `site_probe.py --mobile --throttle --quick`) в
вариантах, которые агент выбирает при сборке страницы. Один модуль `hero.js` (скачать GLB один раз, декодеры — по `extensionsUsed`
файла, кадр по габариту, замеры этапов в `window.__t`), страницы-варианты генерирует `make_pages.py`, прогон — `run_probe.py`
(локальный сервер `serve_br.py` отдаёт предсжатые brotli-файлы, как хостинг; jsDelivr — настоящий CDN через сеть заказчика).
Модели: `assets/product.glb` (A/07, meshopt, 47 КБ), `assets/camera_ktx2.glb` / `camera_webp.glb` (Camera_01, Poly Haven CC0,
`gltfpack -cc -tc|-tw -ts 0.25`: текстуры 512², 656 / 564 КБ).

| вариант | как подключён three | JS передано, КБ | three загружен, мс | 1-й кадр модели, мс | TBT, мс (прогоны) |
|---|---|---|---|---|---|

| v2_min_naive | import map → jsDelivr `three.module.min.js` (он импортирует **неминифицированный** `three.core.js`) | 401 | 3 742 | 4 920 | 299 / 418 |
| v3_min_remap | как v2 + ключ-URL `…/build/three.core.js` → `three.core.min.js` | 243 | 3 374 | 5 948 | 1660 (1 прогон; 2-й завис на CDN — остался постер) |
| v4_bundle | esbuild (`--bundle --splitting --minify`), свой домен, br | **174** | **1 994** | **3 727** | 361 / 867 |
| v5_bundle_nocompile | как v4, без `compileAsync` | 174 | 2 179 | 4 167 | 854 (1 годный прогон) |
| v6a_ktx2_cdn | v4 + KTX2, транскодер с jsDelivr | 210 + wasm 240 | 1 886 | 8 709 | 598 (1 годный) |

LCP во всех вариантах — постер `<img>` 404–482 мс; CLS 0; ошибок консоли 0. Переназначение ядра (v3) отдельно проверено 3/3
(грузятся только `three.module.min.js` + `three.core.min.js`, первый кадр на десктопе 2,2–2,6 с).

Выводы:
1. **Бандлер на своём домене — лучший путь**: JS 174 КБ br, three готов через 2,0 с против 3,4–3,8 с у import map с jsDelivr, первый
   кадр 3,7 против 4,9–5,9 с. [проверено]
2. **`*.min.js` с jsDelivr без настройки почти не экономит** (401 против 443 КБ): min-модуль тянет неминифицированное ядро 204 КБ br.
   Ключ-URL в import map (`"https://cdn.jsdelivr.net/npm/three@0.186.0/build/three.core.js": "…/three.core.min.js"`) даёт 243 КБ. [проверено]
3. **`compileAsync` не снимает долгие задачи** (TBT 867 против 854 мс, в пределах шума): `compile()` внутри синхронный; выигрыш —
   первый `render()` 14 мс против 541 мс (компиляция не попадает в кадр перехода постер → canvas). Гипотеза A «снимает долгие задачи»
   не подтверждена. [проверено; исходник r186 — F1/01]
4. **Транскодер KTX2 с CDN** — +0,8–1,2 с к первому кадру на медленной сети (чужой домен, gzip вместо br: 240 против 199 КБ). [проверено]
5. **KTX2 против WebP на медленной сети**: KTX2 (656 КБ + транскодер) — первый кадр 7,5–7,9 с, WebP (564 КБ) — 5,8–6,8 с: байты
   решают; выигрыш KTX2 по CPU и памяти — F1/03. [проверено]
6. **Метрика зонда `first_draw_ms` ≠ первый кадр модели**: первый вызов отрисовки — это PMREM из RoomEnvironment (≈ 1,9 с), модель —
   позже (`window.__t.firstFrame`). Для ворот качества — метка страницы, а не первый draw call. [проверено]

Ограничения: 2 прогона на вариант (режим экономии заказчика), машину нагружали соседние агенты → TBT шумит ×2; первый проход v5/v6a
пришёлся на пересборку бандла без .br (отброшен); эмуляция телефона на Iris Xe. Версии: three 0.186.0, esbuild 0.28.2, Chromium
(Playwright), `site_probe.py` (A). 23.09.2026.
