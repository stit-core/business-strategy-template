## 1. Hard-surface продукт (кейс наушников, D1/03)

### 1.1. Форма

Паспорт 60,6 × 21,7 × 45,2 мм; корпус — один `rounded_slab` (углы r 10,5, кромка 8,5 мм, `power` 2,6, 10/8 сегментов);
разрез на базу и крышку по шву z = 33,5 мм (`bisect_plane` + `edgeloop_fill`, зазор 0,3 мм, файл 02 §3.3); светодиод Ø 1,8 мм
от габарита базы (8 мм ниже шва на передней стенке). Итог: 3 объекта, 1 976 треуг., 1 227 вершин glTF, 53,4 КБ,
`KHR_materials_clearcoat` и `KHR_materials_emissive_strength` [проверено]. Вид на рендере — «как настоящий»: мягкая
кромка без стыка, тонкий шов, контраст плоских граней и тугих скруглений.

### 1.2. Двигающаяся часть

Правило волны 1 (C1 `04 §5.2`, M2.4, M2.9): часть, которая двигается на сайте, — отдельный объект, origin на оси движения.
Крышка кейса: `set_origin(lid, (0; 9,7; 33,5) мм)` — задняя кромка на высоте шва; открытие на 100° — `rotation_euler.x = −100°`
у объекта, вершины не меняются; в glTF origin = точка вращения в JS (E `01 §4.9`) [проверено]. То же у папки D1/04
(передняя панель на оси сгиба) и у крышки ноутбука (C1/12 делал поворот вершин — для анимации на сайте нужен объект с pivot).

```python
# Blender 5.2.2 — [проверено] крышка на петле: pivot на оси, открытие поворотом объекта
import sys, math; sys.path.insert(0, "../../scripts/3d")
import bpy, d1lib as D, bpyx
from mathutils import Vector
bpy.ops.wm.read_factory_settings(use_empty=True)
C = D.fresh_collection("ASSET_box")
W, DP, H, seam = 0.06, 0.04, 0.03, 0.022
base = D.rounded_slab("Base", W, DP, seam, 0.008, (0.004, 0.0), C, corner_seg=8)
lid = D.rounded_slab("Lid", W, DP, H - seam, 0.008, (0.0, 0.004), C, corner_seg=8)
lid.location.z = seam + 0.0003                                     # шов 0,3 мм
hinge = Vector((0, DP / 2 - 0.001, seam + 0.0003))                 # ось петли — задняя кромка на высоте шва (ось X)
D.set_origin(lid, hinge)
bpy.context.view_layer.update()
assert (lid.matrix_world.translation - hinge).length < 1e-6
lid.rotation_euler.x = math.radians(-100)                          # открыть: поворот объекта, вершины не трогаем
bpy.context.view_layer.update()
pts = [lid.matrix_world @ v.co for v in lid.data.vertices]
low = [p for p in pts if p.z < seam]                               # что опустилось ниже шва при откидывании…
print(len(low), round(max(p.y for p in pts), 4))
assert all(p.y > DP / 2 - 0.0015 for p in low)                     # …только позади базы: пересечения с базой нет
```

### 1.3. Детали и перфорация

Вырезы — булевы EXACT с очисткой или контур с отверстиями (файл 05 §3); перфорация ≥ 20–30 отверстий — 10 тыс. треуг. на
ладонь (D1/03 решётка 7 × 7) — для веба карта (альфа/нормали) на простой пластине [мнение D1]. Кнопки, светодиоды, линзы —
отдельные мелкие формы, координаты от габарита корпуса (файл 01 §1.2).

## 2. Мокап устройства со скриншотом (телефон, D1/02)

- Корпус: `rounded_slab` 71,5 × 147 × 7,8 мм, углы r 11,5 (`rrect` — экран повторяет корпус с отступом), кромка 1,1 мм;
  материалы корпуса по нормали граней (рамка/спинка/стекло) — один объект, 3 слота [проверено].
- Экран: отдельный объект — скруглённый прямоугольник (рамка 1,8 мм, r 9,8 мм), **UV 0–1 на всю видимую область**
  (`u = x/w + 0,5`, `v = y/h + 0,5`), триангулирован BEAUTY, на 0,1 мм над стеклом; материал `Screen`: картинка → Base Color и
  Emission Color, Emission Strength 1,0, roughness 0,08. На листе D1/02 верхняя карточка скриншота — у верха экрана: UV не
  перевёрнута и не растянута [проверено]. В three экран находят по имени материала/узла и подменяют `map` (видео,
  `HTMLTexture`) — A `01 §21.2`.
- Островок камер: `rounded_slab` 34 × 34 × 1,1 мм, r 8,5 мм, выступает из спинки; 3 линзы — `lathe` (кольцо с фаской
  0,4 мм и утопленное на 30 % высоты стекло), координаты от угла корпуса; кнопки — от длины корпуса (10/20/30 % по Y).
- Ориентация: телефон стоит экраном к −Y (в glTF — +Z, «к зрителю»), повороты применены в вершины; общий pivot — пустышка
  `Phone` в центре корпуса (вращение в JS — вокруг центра) [проверено].
- Экран-градиент из ColorRamp или шума — в glTF белый (M4.1, opus в C1/11); скриншот — только картинкой [проверено E/12].

```python
# Blender 5.2.2 — [проверено] экран мокапа: UV 0–1 на всю область и материал Screen
import sys, os, tempfile; sys.path.insert(0, "../../scripts/3d")
import bpy, bmesh, d1lib as D, bpyx
bpy.ops.wm.read_factory_settings(use_empty=True)
sw, sd, r, z = 0.0679, 0.1434, 0.0098, 0.0079
bm = bmesh.new(); uvl = bm.loops.layers.uv.new("UVMap")
f = bm.faces.new([bm.verts.new((x, y, z)) for x, y in D.rrect_pts(sw, sd, r, 10)])
for loop in f.loops:
    loop[uvl].uv = (loop.vert.co.x / sw + 0.5, loop.vert.co.y / sd + 0.5)
bmesh.ops.triangulate(bm, faces=[f], quad_method="BEAUTY", ngon_method="BEAUTY")
screen = D.obj_from_bm(bm, "Phone_Screen", smooth_angle=None)
img = bpy.data.images.new("ui", 64, 128); img.generated_type = "COLOR_GRID"
path = os.path.join(tempfile.mkdtemp(), "ui.png"); img.filepath_raw = path; img.file_format = "PNG"; img.save()
mat, p = bpyx.principled("Screen", roughness=0.08, emission_strength=1.0)
tex = mat.node_tree.nodes.new("ShaderNodeTexImage"); tex.image = bpy.data.images.load(path)
bpyx.link_sockets(mat.node_tree, (tex, "Color"), (p, "Base Color"))
bpyx.link_sockets(mat.node_tree, (tex, "Color"), (p, "Emission Color"))
bpyx.assign_material(screen, mat)
us = [d.uv for d in screen.data.uv_layers["UVMap"].data]
assert min(u.x for u in us) > -1e-6 and max(u.x for u in us) < 1 + 1e-6 and max(u.y for u in us) > 0.99
print(len(screen.data.polygons), mat.name)
```

## 4. Логотип и 3D-текст (D1/05)

### 4.1. Логотип из SVG

`d1lib.svg_mesh(name, svg, size, depth, bevel, bevel_res, resolution_u)`: `bpy.ops.import_curve.svg` → масштаб к ширине
`size` → `fill_mode='BOTH'`, extrude, bevel с `offset = −bevel` → меш → сварка → вертикально лицом к −Y, низ на z = 0.
Логотип 120 × 102 × 12 мм (лист с отверстием `evenodd` + капля): `resolution_u` 6 — гранёный контур (956 треуг.), 16 —
гладкий (2 556 треуг., 74 КБ), неманифолда 0 [проверено]. Толщина 8–12 % ширины и фаска ≈ 1 % ширины (bevel 0,01 на
иконке превращает её в «каплю» — Polyfjord выбрал ≈ 0,00105 [V:zthvZvw-yJE 06:33]); bevel_resolution 9 и resolution 32 —
только для рендера [06:47–07:03]; для веба 2 и 12–16 (D1/05).

### 4.2. 3D-текст

`text_mesh(..., resolution_u=6, bevel_res=2)` для заголовка (2 472 треуг. на «Nova» 0,1 м), 3–4/1 для подписей (1 060);
12/4 — 6 880 без видимой пользы в кадре 384 px [проверено]. Текст в канвасе не индексируется и не участвует в LCP —
дублировать HTML (A `01 §8.2`, `04`); 3D-текст «хромированный заголовок» — клише (A §22).

## 5. Абстрактная скульптура и блобы (D1/06)

### 5.1. Лента

Цоколь — тело вращения Ø 170 × 28 мм с фасками 2/4 мм; главная форма — `sweep` по торическому узлу (2, 3) R 75, r 34 мм,
420 точек, сечение-«капсула» 34 × 7,5 мм (`rrect_pts` с r = половина толщины), закрут 3 оборота, узел поставлен вертикально
(поворот 90° по X) и утоплен в цоколь на 4 мм; акцент — золотой шар Ø 26 мм на цоколе (≈ 0,1 главной формы). 26 400 треуг.,
593 → 117,5 КБ (meshopt) [проверено]. Варианты пути: спираль (`helix_pts` с `taper`), лиссажу, Безье через
`catmull_rom_pts` — ритм даёт закрут и сужение, а не число деталей.

### 5.2. Капля/блоб

5 перекрывающихся шаров (шаг ≈ 0,6 суммы радиусов, по спирали к вершине) → `sdf_blob_gn(voxel=3,5 мм, fillet 10, Mean 3/4)`
→ шум 4 мм → утопить в цоколь на 4 мм: 18 788 треуг., 346 → 79 КБ [проверено]. Анимированный «живой» блоб — шейдер
на странице, не Blender (A `01 §5`); хромированный/радужный блоб — клише (A §22).

## 6. Low-poly мир и изометрия (D1/07)

### 6.1. Low-poly

- Сегменты — параметрами: окружность 16 вершин читается круглой, 8 — «почти», 6 — предел; сфера 16 колец достаточно, 8 —
  полосы; «please don't hit decimate» [V:H1oNuKChsdU 11:10, 12:10, 26:17] (через заметки помощника и W4). D1/07: остров —
  тело вращения 12 сегментов, ствол 6, крона 7, камень — икосфера 1 [проверено].
- `shade_flat` + дрожание вершин по seed (18 мм на остров Ø 1 м; 8 мм на камень 4 см) — «рукотворность» без шума.
- Одна палитра-текстура 8 × 1 px (`Closest`), UV каждой грани → центр ячейки цвета; 1 материал на сцену, 2–3 на игру
  [V:H1oNuKChsdU 23:42]; для AR — палитра, не вершинные цвета (A `05 §3.2`) [проверено].
- «Атомарный размер» — минимальный размер полигона, одинаковый по сцене [V:H1oNuKChsdU 13:07]; граница стиля ≈ 8 тыс.
  полигонов на ассет [01:53] (через помощника) [практика].
- Цена flat: вершин glTF ×1,5–3,7 к гладкому (D1/01; E/03) — для low-poly это нормально, треугольников мало.

```python
# Blender 5.2.2 — [проверено] low-poly: палитра-текстура и окраска граней через UV
import sys, os, random, tempfile; sys.path.insert(0, "../../scripts/3d")
import bpy, d1lib as D, bpyx
from mathutils import Vector
bpy.ops.wm.read_factory_settings(use_empty=True)
PAL = ["#7CB36B", "#5E9451", "#8A6A4F", "#6B5242"]                     # трава, листва, ствол, земля (sRGB hex)
img = bpy.data.images.new("palette", len(PAL), 1)
img.pixels.foreach_set([c for h in PAL for c in (int(h[1:3], 16) / 255, int(h[3:5], 16) / 255, int(h[5:7], 16) / 255, 1.0)])
path = os.path.join(tempfile.mkdtemp(), "palette.png"); img.filepath_raw = path; img.file_format = "PNG"; img.save()
mat, p = bpyx.principled("LowPoly_Palette", roughness=0.85)
tex = mat.node_tree.nodes.new("ShaderNodeTexImage"); tex.image = bpy.data.images.load(path); tex.interpolation = "Closest"
bpyx.link_sockets(mat.node_tree, (tex, "Color"), (p, "Base Color"))
isl = D.lathe("Island", [(0.0, -0.55), (0.34, -0.22), (0.52, 0.0), (0.0, 0.035)], segments=12, smooth_angle=None)
rng = random.Random(1)
for v in isl.data.vertices:                                          # дрожание вершин по seed — воспроизводимо
    v.co += Vector((rng.uniform(-1, 1), rng.uniform(-1, 1), rng.uniform(-1, 1))) * 0.018
uv = isl.data.uv_layers["UVMap"]
for poly in isl.data.polygons:
    k = 0 if poly.normal.z > 0.6 else 3                              # верх — трава, бока — земля
    for li in poly.loop_indices:
        uv.data[li].uv = ((k + 0.5) / len(PAL), 0.5)
isl.data.shade_flat(); bpyx.assign_material(isl, mat)
print(len(isl.data.polygons), bpyx.object_stats(isl)["tris"])
assert bpyx.object_stats(isl)["tris"] < 200 and not isl.data.polygons[0].use_smooth
```

### 6.2. Изометрия

Истинная изометрия — орто-камера, азимут 45°, угол места 35,264° (`frame(..., ortho=True, az=45, el=35.264)`), без
перспективных искажений (D1/07; C1 паспорт стиля `04 §3.1`). Стены комнаты — коробки 0,1–0,15 м с фаской, не плоскости
(M2.13); мебель — `rounded_slab`; draw calls сводить общими материалами/палитрой (C1/15: комната 29 → 3 вызова после optimize).
Клише: «изометрическая комната разработчика» (A §22) — делать только сцену реального продукта.

## 7. Форма под материал (стекло, металл)

- **Стекло**: реальная толщина стенок (2–4 мм у бокала/флакона; `lathe_shell`), кромка — опорные петли + лёгкий валик, иначе
  «странный блик» [V:Sv2wqwsvx-8 11:16–12:21]; столешница из плоскости с Solidify + Bevel без петель — чёрное пятно в стекле
  [16:32] (через W3). Плоскость без толщины не преломляет правдоподобно; в glTF толщина — `KHR_materials_volume` (E `01 §6.2`).
  [не проверено в D1 — форма; материал и рендер — D2]
- **Металл/хром**: отражает окружение — любые ошибки нормалей видны сильнее всего; фаски 3 сегм. + harden + WN обязательны
  (на тёмном глянце D1/01 разница вариантов C и D видна сразу) [проверено]; большие плоскости без изгиба на хроме
  читаются «зеркалом» — нужна кривизна или фаски, которые «ловят» HDRI [мнение].
- **Мягкий пластик/глина**: пухлая кромка, матовость 0,5–0,6 — форма важнее материала (D1/04) [проверено].

## 8. Маскот из простых форм

Рецепт по правилам этого файла и файла 01 (отдельно не строился — `[не проверено]`): тело — капсула/`rounded_slab`/SDF-капля
(крупная форма); голова 0,6–0,8 ширины тела, врастает на 10–20 % (средняя); конечности — `sweep` по короткой кривой со
сужением (средние); глаза и щёки — мелкие формы, утоплены на 30–40 % (группа 2–3). Для анимации: каждая часть — отдельный
объект, pivot в суставе (`set_origin`), либо скелет ≤ 254 костей (A `05 §3.4`, H). Механические персонажи — пересекающиеся
части, каждая целиком к кости/родителю, дешевле скиннинга [V:H1oNuKChsdU 27:30] (через W4). Сложная органика («как на
фото») — генератор или библиотека по разрешению (C1 `04 §4`, G). Клише: «3D-маскот в стиле Pixar-игрушки» (A `01 §12.1`).

|---|---|---|

| текст | хромированный 3D-заголовок | HTML-текст + 3D-логотип |

## Частые ошибки

1. **Мокап телефона с экраном-градиентом из нод** — в glTF белый (M4.1) [C1/11 opus].
2. **Экран без UV 0–1** — скриншот растянут/перевёрнут [проверено: D1/02 — проверка по карточке у верха].
3. **Крышка/дверца поворачивается вокруг своего центра** — отрывается от корпуса (M2.4) [C1/11 sonnet].
4. **Все части кейса одним мешем без шва** — нельзя открыть на сайте; шов — разрезом, части — объектами [D1/03].
5. **Иконка из примитивов по умолчанию** — масштаб, парящие точки, «суп» (M3.1, M2.2) [проверено].
6. **Low-poly из гладких сфер 32 сегмента или через Decimate** (M2.14) [C1/11 haiku; V:H1oNuKChsdU 26:17].
7. **Стены-плоскости в изометрии** (M2.13) [C1/11 sonnet].
8. **Логотип с `resolution_u` 3–6 на крупных дугах** — гранёный контур [проверено].
9. **Скульптура — труба постоянного сечения или шары без сглаживания поля** [проверено].
10. **GLB для набора статичных иконок** — в 5–30 раз тяжелее предрендера [A/06; D1/04].
