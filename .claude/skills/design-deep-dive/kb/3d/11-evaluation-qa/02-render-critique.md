## Выжимка для агента

1. **Порядок**: `scene_check` (числа) → рендер камеры сайта + 4 студийных ракурса + глина → автопроверки картинки → вопросы
   по брифу → попарное сравнение с прошлой версией. Картинку смотрят, когда числа уже чистые. → §1 `[проверено]`
2. **Студийный лист не показывает масштаб**: `render_views.py` ставит камеру по габариту, кружка 2,22 м выглядит как 0,095 м;
   масштаб — только паспорт (`01 §3`). → §1 `[проверено]` (M2.1)
3. **Глина (`--clay`) — для формы**, цвет отвлекает от фасок и стыков; **workbench** — случайный цвет на объект: видно
   разбиение на части и парящие детали. → §1 `[документация: render_views.py]`
4. **Силуэт в чёрном** из альфы ракурса: читается ли объект в 128–300 px без света и материала. → §2 `[проверено]`
5. **Автопроверки картинки кодом** (`image_checks`): доля кадра и поля, пересвет на объекте, пересыщение, провалы в чёрное,
   центр «веса» после размытия (squint test). Функция проверена; пороги — стартовые `[не проверено]`. → §2
6. **Разделяйте «ошибку» и «вкус»**: ошибка — нарушает бриф, физику или веб (масштаб, парение, обрезка, серый материал,
   процедура, клиппинг на товаре); вкус — трети, настроение, реквизит, ГРИП, клиппинг окна. Ошибка блокирует, вкус — выбор
   среди годных. → §3 `[практика: Price, W3]`
7. **Критик правит ошибку, а не замысел**: разборы Andrew Price зрители критикуют именно за подмену замысла (комментарии 889,
   827, 387 лайков: «не чинит, а меняет»); правка вкуса — только с обоснованием по брифу. → §3.2 `[V:XK5weMlS47M комментарии]`
8. **Один фокус, самый контраст — на герое**; второе пятно сопоставимого веса — дефект композиции (вкус с высокой ценой). → §3 `[V:O8i7OKbWmRM 01:42, 04:17]`
9. **Товар с брендовым цветом**: клиппинг и пересыщение на товаре — ошибка; в атмосферном hero клиппинг окна — вкус. → §3 `[V:Z8AAX-ENWvQ 15:55]`
10. **VLM-судья — только попарно и вопросами по брифу**, не баллами 1–10: баллы геометрии Pearson 0,17–0,37 с людьми, попарно
    0,66–0,77 при 0,79 у пары экспертов, вопросы 88,7–91,5 % против 72,8 % у целостной оценки. → §4 `[исследование: C2 03 §7]`
11. **Два порядка в двух чистых вызовах**, засчитывать согласованный ответ; ≤ 2 картинок за вызов (7 картинок → 100 % ответов
    «по позиции» у 7B); «оба плохи» — разрешённый ответ. → §4 `[исследование: C2 03 §7.2]`
12. **Судья не перекрывает код**: в J/02 судья выбрал «богаче» (кофе, дым, градиент) в 3 парах из 4, а код — вариант без
    ошибок; все три выбора судьи — `fail` (масштаб ×5–25, процедурный градиент не доедет до glTF). → §4.2 `[проверено]`
13. **Вопросы по брифу ловят то, где код слеп**: «видны заломы/прорастание» различил скульптуру с M2.3, которую код не флагует;
    вопросы-очевидности («ручка есть?») у сильных моделей почти всегда «да» — не тратьте на них вызовы. → §4.2 `[проверено]`
14. **VLM-критика нужна** для: прорастания на виду, «супа из примитивов», стиля серии, композиции, смысла («текст читается»,
    «экран светится»). **Не нужна** для: масштаба, касаний, кадра, материалов, бюджета — это числа. → §4.1
15. **Эталон рядом**: сравнивать с утверждённым ассетом серии или прошлой версией, не «в пустоту» — без эталона судья награждает
    «чистое, но неверное». → §4 `[исследование: C2 03 §7.2 п. 8]`
16. **Остановка**: 2–3 визуальные итерации без выигрыша в попарном сравнении — стоп на лучшем (C1 `04 §8.3`). → §5

## 2. Автопроверки картинки кодом

```python
# run: system
# Python 3 + numpy + Pillow — [проверено] автопроверки RGBA-ракурса render_views.py
import json
import numpy as np
from PIL import Image, ImageFilter

def image_checks(path):
    """Доля кадра, поля, пересвет и пересыщение на объекте, провалы в чёрное, центр «веса» после размытия (squint test)."""
    im = np.asarray(Image.open(path).convert("RGBA")).astype(np.float32) / 255.0
    a = im[..., 3] > 0.5
    h, w = a.shape
    if not a.any():
        return {"fill": 0.0}
    ys, xs = np.nonzero(a)
    rgb = im[..., :3][a]
    mx, mn = rgb.max(1), rgb.min(1)
    sat = np.where(mx > 0, (mx - mn) / np.maximum(mx, 1e-6), 0)
    lum = rgb @ np.array([0.2126, 0.7152, 0.0722], np.float32)
    L = np.zeros((h, w), np.float32)
    L[a] = np.abs(lum - lum.mean()) + sat * 0.5          # «вес» пятна: контраст к среднему + насыщенность
    blur = np.asarray(Image.fromarray((L / max(L.max(), 1e-6) * 255).astype(np.uint8)).filter(ImageFilter.GaussianBlur(w * 0.05)), np.float32)
    gy, gx = np.mgrid[0:h, 0:w]
    wsum = blur.sum() or 1.0
    Image.fromarray(np.where(a, 0, 255).astype(np.uint8)).save(path.replace(".png", "_silhouette.png"))  # силуэт в чёрном
    return {"fill": round(float(a.mean()), 3),
            "margins": [round(float(xs.min() / w), 3), round(float(1 - (xs.max() + 1) / w), 3),
                        round(float(ys.min() / h), 3), round(float(1 - (ys.max() + 1) / h), 3)],
            "clipped": round(float((mx >= 0.98).mean()), 4),
            "oversat": round(float(((sat > 0.85) & (mx > 0.3)).mean()), 4),
            "crushed": round(float((lum < 0.03).mean()), 4),
            "weight_center": [round(float((gx * blur).sum() / wsum / w), 3), round(float((gy * blur).sum() / wsum / h), 3)]}

import os, shutil, tempfile
C1 = "99-raw/experiments/C1/12-protocol-objects/out/"
tmp = tempfile.mkdtemp()
res = {}
for k in ("mug", "laptop", "rocket", "logo"):
    p = os.path.join(tmp, k + ".png")
    shutil.copy(C1 + f"views_{k}/view_0_az35_el20.png", p)
    res[k] = image_checks(p)
print(json.dumps(res, ensure_ascii=False))
assert all(0.05 < r["fill"] < 0.9 for r in res.values())
```

пересыщение 0 у всех, кроме логотипа (#FF5A36 — 4,4 % пикселей: насыщенный бренд, это вкус, а не ошибка); провалов в чёрное 0;
центр веса 0,46–0,60 по X [проверено]. Стартовые пороги (не откалиброваны на парах «плохо/хорошо» — `[не проверено]`):

|---|---|---|---|
| `clipped` | > 1 % пикселей **товара** | окно, луч, блик металла в атмосферном hero | Price [V:Z8AAX-ENWvQ 15:55]; False Color без красного на предмете [V:5UCc3Z_-ibs 08:49] |

### 3.1. Где проходит граница

Ошибка — то, что нарушает бриф, физику или контракт экспорта, и её можно назвать числом или вопросом да/нет по брифу. Вкус —
выбор между годными вариантами. Price в двух роликах сам разделяет: клиппинг окна и ГРИП — художественный выбор, Specular 0,5 и
затвор 180° — технические умолчания [V:Z8AAX-ENWvQ 15:55, 20:03 + комментарии]; баланс «не догма, а умолчание», фокус
субъективен (дракон или викинг — спор зрителей) → «проверять вес измерением, а не намерением» [V:O8i7OKbWmRM, комментарии].

### 3.2. Критик не переписывает замысел

В «Fixing Your Renders» Price переделывает четыре присланные работы; самые популярные комментарии — не спор о качестве, а о
замысле: «you are not "fixing" these renders, you are changing them based on the concept» (889 лайков), «you didn't fix the first
two images, but made them entirely your own» (827), «changed it from a warm and welcoming… to a cold and detached, industrial
room» (387), «should be more about bringing the artist's vision to life rather than forcing your own» (63); автор первой работы:
ракурс «должен был быть с дрона» (1 700) [V:XK5weMlS47M комментарии]. Правила для агента-критика:
- замысел = паспорт (ракурс, настроение, палитра, реквизит); критика по пунктам «вкус» не меняет паспорт без вопроса к брифу;
- правка «ошибки» — сразу; правка «вкуса» — как вариант рядом (попарное сравнение), исходный остаётся;
- формулировка замечания: «пункт → что видно → число/вопрос → правка», без «сделай красивее».

## 4. VLM-судья

### 4.1. Когда нужен

| вопрос | кто отвечает | почему |
|---|---|---|
| масштаб, касания, кадр, материалы, бюджет, экспортируемость | код (`01`, `03`) | числа точнее: CADTests F1 0,962 против 0,549 у VLM-судьи; нормали кодом 83 % против 46,9 % (C2 `03 §7`) |
| «есть ли X, какого цвета Y, стоит ли Z на W» | VLM: вопросы да/нет по ракурсам | 88,7–91,5 % против 72,8 % у целостной оценки (Eval3D, C2) |
| прорастание на виду, «суп из примитивов», заломы | VLM: вопрос по брифу + глина | код численно не отличает законный стык (J/01) |
| какой из двух годных вариантов лучше (вкус) | VLM попарно, два порядка | 0,66–0,77 согласия с людьми при 0,79 у пары людей (C2) |
| соответствие серии | VLM попарно с эталоном серии + метрики D2 | без эталона — «чистое, но неверное» |
| «оценка 1–10» | никто | Pearson 0,17–0,37 даже у сильных моделей, «думай дольше» не помогает (C2 `03 §7.3`); точный вопрос да/нет надёжнее балла — и в практике доклада [V:vM39qhXle4g ≈22:39] (W12) |

правильность; **сначала отсев кодом, потом вкус судьёй среди прошедших**. 4 пары — иллюстрация, не статистика.

### 4.3. Протокол вызова судьи

- Вход: 2 картинки (лист 4 ракурсов каждого варианта или 2 крупных кадра), эталон серии — отдельным вызовом «новое против
  эталона»; не больше 2 изображений за вызов.
- Два вызова в чистых контекстах: (A, B) и (B, A); засчитывать совпавший ответ; несовпадение = «ничья».
- Один критерий за вызов (композиция, или стыки, или материал), ответ — буква + одна причина; «оба плохи» разрешён.
- Судья не слабее генератора (слабый самокритик ломает: откаты 26–28 %, C2 `03 §7.2` п. 9).
- Вопросы по брифу — только различающие (что может быть «нет»): «видны ли заломы на стыках», «читается ли надпись», «видно ли
  дно», «есть ли второе яркое пятно вне героя».

```text
Шаблон (для одного из двух вызовов; во втором картинки переставлены):
Ты оцениваешь 3D-ассет для hero-блока сайта. Бриф: <одна строка из паспорта>.
Картинка 1 и картинка 2 — два варианта, по 4 ракурса. Критерий: <один критерий из рубрики §3, пункты 10–16>.
Ответь строго: "1", "2", "ничья" или "оба плохи" и одну причину (≤ 15 слов). Не оценивай размер — он проверен кодом.
```

## 5. Цикл правки и остановки

Приоритет исправлений (C1 `04 §8.1`): отсутствующее → парящее и пересекающееся → пропорции → края → материалы → свет → кадр.
Одна причина — одна правка в `P`, затем полный `build(P)` и снова `scene_check` → рендер. Останов: утверждения ok и рубрика без «нет»
по «ошибкам» → экспорт; 2–3 визуальные итерации без выигрыша в попарном сравнении → лучший вариант и описание остатка;
параллельные варианты (2–4 `P`) лучше длинной цепочки правок (C2 `03 §8.1`).

## Частые ошибки

- Судить по снимку вьюпорта MCP вместо рендера (M6.2): чужой ракурс, оверлеи, серые материалы в фоне.
- Спрашивать «оцени от 1 до 10» — шум; спрашивать «что улучшить» без критерия — судья меняет замысел.
- Показывать судье 7–9 картинок разом в одном порядке — ответы по позиции.
- Засчитывать выбор судьи, когда оба варианта не прошли код: судья «выбирает лучшее из плохого» (почти не говорит «оба плохи»).
- Считать студийный лист доказательством масштаба — лист нормализует размер.
- Исправлять «вкус» как «ошибку»: переписывать настроение и реквизит без брифа (жалоба зрителей на Price).
- Добавлять зерно и ГРИП в PNG для сайта — сжатие WebP/AVIF портит зерно, фон сайта чистый (W3).

## Открытые вопросы и противоречия

- Пороги `image_checks` (пересвет 1 %, пересыщение 10 %, чёрное 5 %) — стартовые, не откалиброваны на парах «плохо/хорошо» (D1/02,
  04, 06; D2/04) — `[не проверено]`.
- J/02 — один судья, один контекст, 4 пары: согласованность порядков не измерена честно; нужна серия в чистых контекстах и
  калибровка на DB-3DME (предложение C2) — вне экономного объёма.
- «Богаче» против «правильнее»: судья предпочёл opus в 3 из 4 пар — в части «вкуса» он, возможно, прав (кофе, дым — удачный
  реквизит); спор решает бриф. Кандидат в рубрику: «реквизит, усиливающий историю» — вкус с высокой ценой.
- Протокольные объекты C1 сделаны аккуратно, но «первая попытка» opus местами привлекательнее — довод за best-of-N по вкусу
  после отсева кодом (C2 `03 §8.1`), а не за «протокол всегда лучше».
- Рубрика W3 «False Color без красного» реализована как доля `max(RGB) ≥ 0,98` после вида (AgX/Neutral) — это не то же, что
  сцена-линейная экспозиция; точная проверка — рендер с видом False Color `[не проверено]`.
