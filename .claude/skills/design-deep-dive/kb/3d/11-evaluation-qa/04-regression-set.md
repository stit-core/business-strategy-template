## Выжимка для агента

1. **Набор проверяет две вещи**: агента (новая модель или промт строит эталоны заново по брифу и паспорту) и сами проверки
   (после правки порогов отрицательные контроли обязаны падать, положительные — не получать новых замечаний). → §3–4 `[проверено: базовая линия]`
2. **Агенту отдаётся бриф и паспорт, не эталонный скрипт**; эталонный скрипт, `.blend`, GLB и картинки — только для сравнения. → §3
3. **Регрессия** = вердикт хуже базового; новый код WARN/ERROR; вес GLB или треугольники +20 %; ошибка исполнения там, где её
   не было; попарный судья в двух порядках предпочёл эталон по критерию вкуса; отрицательный контроль перестал ловиться. → §4
4. **Прогон дешёвый**: 11 сцен + 26 GLB + 2 анимации — 57 с без рендеров; страницы (`--pages`) — ещё 12–16 с на каждую. → §2 `[проверено]`
5. **Отрицательные контроли обязательны**: ноутбук sonnet (парение, масштаб), кружка opus (масштаб ×23 — видна только паспорту),
   дерево haiku (вне кадра), турнтейбл без сэмплов (крутится назад). Базовая линия: 4 из 4 пойманы. → §1.3 `[проверено]`
6. **Сырые GLB дают `review`** (подсказка «геометрия не сжата») — это норма эталона до постобработки; эталоны K уже сжаты
   (Meshopt) и проходят `pass`. Сравнивать сырое с сырым, сжатое со сжатым. → §2
7. **Бюджет — флагами** `qa_pipeline glb --max-tris --max-kb` по паспорту: поле инстансов K (212 400 треугольников за 1 вызов)
   падает при бюджете hero 100 тыс. — для фона-поля бюджет другой, его пишет паспорт. → §2 `[проверено]`
8. **Метрики прогона агента**: доля исполнившихся с первого раза, доля `pass` кодом после ≤ 2 правок, итераций до `pass`,
   время и токены, доля побед в попарном сравнении с эталоном. → §3.2
9. **Эталон меняется только осознанно**: новый базовый прогон — `run_set.py --label baseline-<дата>` после приёмки человеком. → §4

## 3. Прогон агента на наборе

### 3.1. Процедура

1. Для каждого эталона агенту даются: бриф (`brief`), паспорт (`passport`: габариты, касания, бюджет, стиль), паспорт стиля
   серии (для иконок), целевой формат (GLB или страница). Эталонный скрипт и картинки не показываются.
2. Агент работает по своему протоколу (`../04-ai-agents-mcp/04`): `build(P)` → `scene_check` → рендер → правка; лимит — 3
   визуальные итерации и 2 повтора на ошибку исполнения; итог — `.blend`, GLB, кадр камеры, лист 4 ракурсов.
3. Проверка кодом: `qa_pipeline.py scene` (паспорт из манифеста) и `glb` (с `--max-tris/--max-kb` из паспорта), анимация —
   `three_probe.py` + проверка эталона (`anim_check`), страница — `page` в двух режимах (десктоп, reduce) и телефонной эмуляции.
4. Попарно с эталоном: лист 4 ракурсов нового против эталонного, два вызова в чистых контекстах (A, B) и (B, A), по одному
   критерию «вкуса» рубрики (`02 §3`, пункты 10–16); засчитывается совпавший ответ.
5. Запись результата: `results_<модель-или-промт>_<дата>.json` + таблица метрик §3.2.

### 3.2. Метрики версии агента

| метрика | как считать | ориентир из базы |
|---|---|---|
| исполнимость с первой попытки | доля эталонов без исключения на первом `build(P)` | C1/11: haiku 0/8, sonnet и opus 8/8 |
| годность кодом | доля `pass`/`review` без ERROR после ≤ 2 правок | протокол C1/12: 8/8 без ERROR |
| точность масштаба | доля без `dims_mismatch` | «первые попытки» C1/11: 0/24; протокол 8/8 |
| итерации до годности | среднее число `build(P)` до вердикта без ERROR | протокол C1/12: 1–4 |
| бюджет | вес GLB и треугольники против эталона (±20 %) и паспорта | таблица §1.1 |
| вкус | доля согласованных побед нового в попарном сравнении с эталоном | J/02: судья предпочитает «богаче» — только среди прошедших код |
| цена | время и токены на эталон | волна 2: 0,8–0,95 млн токенов на тему (для масштаба) |

### 3.3. Что считать регрессией

| сигнал | регрессия, если | пример |
|---|---|---|
| вердикт стадии | хуже базового (pass → review, review → fail) | `c1-phone` сцена pass → review |
| коды | появился новый WARN/ERROR | `floating_part` у эталона, где его не было |
| бюджет | вес GLB или треугольники > +20 % к эталону или сверх паспорта | 26 400 → 40 000 треугольников |
| исполнимость | исключение там, где базовая версия исполнялась | новое `KeyError: 'Emission'` (M1.2) |
| анимация | углы и позы вне допуска ±1° / ±1 мм | четверти 318 / 228 / … |
| вкус | эталон выигрывает в обоих порядках по ≥ 2 из 4 критериев вкуса | композиция и силуэт хуже |
| проверки | отрицательный контроль перестал ловиться или положительный получил новый код | после правки порогов `scene_check` |

Не регрессия: другие имена объектов при тех же проверках; другой, но годный по рубрике вкус (решает попарное сравнение); сжатый
GLB вместо сырого (вес меньше).

## 4. Уход за набором

- Эталон добавляется, если у него есть бриф, паспорт или числа (`numbers.json`), скрипт сборки и хотя бы одна картинка; запись —
  в `make_manifest.py`, затем `python3 make_manifest.py` (проверяет, что пути существуют) и новый базовый прогон.
- После правки порогов `scene_check.py`/`qa_pipeline.py`: `run_set.py --label chk --compare baseline` — у положительных не должно
  появиться новых кодов, отрицательные — ловиться; иначе порог откатывается.
- Базовая линия меняется только после приёмки человеком (новое значение — осознанное): `--label baseline-<дата>`.
- Объём: GLB ≤ 600 КБ, картинки — листы 1536 × 384; `.blend` хранятся только у C1/12 и контролей C1/11 (у остальных — скрипт).

## Частые ошибки

- Давать агенту эталонный скрипт «для примера» — прогон меряет копирование, а не умение.
- Сравнивать сырой GLB агента со сжатым эталоном K (или наоборот) — ложный «+400 % веса».
- Считать `review` сырого GLB регрессией: подсказка о сжатии у сырого — норма.
- Перегенерировать базовую линию после каждой неудачи — набор перестаёт ловить регрессии.
- Прогонять только положительные эталоны: без отрицательных контролей ослабленный порог проверки выглядит как «стало лучше».

## Открытые вопросы и противоречия

- У D1, D2, H нет сохранённых `.blend` — базовая линия сцены есть только у C1/12; пересборка их скриптами — 1–60 с, но это уже
  «новый прогон», а не эталон `[не проверено]`.
- Попарный судья против эталона — протокол описан, на наборе не прогнан (экономия); J/02 показал, что судья без отсева кодом
  выбирает «богаче» — отсев обязателен.
- Эталоны K ещё меняются; итоговый состав — после отчёта K (для него — раздел «Для K» в заметках J).
- Реальные телефоны и Safari — вне стенда; мобильные числа страниц — эмуляция (`03 §6`).
- Пороги «+20 %» по весу и треугольникам — `[мнение]`: выбраны как заметно больше шума экспорта (±1–2 %), не откалиброваны.
