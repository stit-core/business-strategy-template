Важность: **Б** — блокер (не отдавать), **В** — важно (исправить или письменно объяснить), **Ж** — желательно. Способ: **К** —
кодом (утилита или функция, указана), **Р** — рендер + рубрика / вопрос по брифу / попарное сравнение, **Ч** — человек или
бриф (решение заказчика, лицензия, реальное устройство). Вердикт: любой непройденный **Б** → `fail`; **В** без объяснения → `review`.

## Выжимка для агента

1. Идите по стадиям сверху вниз: бриф → сцена → геометрия → материалы → кадр → рендер → экспорт → анимация → страница → права;
   блокер на ранней стадии останавливает работу — на поздних стадиях его не лечат. → §1–10
2. Всё, что помечено **К**, гоняется одной командой `qa_pipeline.py scene | glb | page` (≈ 2 с сцена, 2–10 с GLB, 12–16 с
   страница); **Р** — после чистого **К**; **Ч** — в отчёт заказчику. → `03 §1`
3. Где пункт в разных папках расходится (центр кадра против третей, поля 8–12 против 10–15 %, AgX против Neutral, вызовы ≤ 10
   против ≤ 30/60) — здесь указано нормализованное значение и причина, противоречие — в «Открытых вопросах». → §11

## Частые ошибки

- Проходить чек-лист глазами целиком: пункты **К** — одной командой `qa_pipeline`, глазами — только **Р**.
- Лечить блокер ранней стадии на поздней: масштаб — в паспорте и `build(P)`, не на странице через `scale`.
- Считать чек-лист одной папки полным: у экспорта (08) нет кадра, у страницы (09) нет паспорта.
- Отдавать без отчёта о **Ч**-пунктах: лицензии, реальные устройства, решения заказчика — пишутся явно.
