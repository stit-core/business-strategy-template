## 4. Слепота, два порядка, сессия

- Имена файлов пары нейтральные (`img/p07-1.jpg`, `p07-2.jpg`), подписи вариантов видны только в итогах (поле `from` — для отчёта).
- Каждая пара — два испытания (`<id>:0` без переворота, `<id>:1` с переворотом сторон); порядок испытаний перемешан по семени голосующего,
  одна пара подряд дважды не идёт.
- Ответы: ← левый, → правый, ↓ одинаково, X оба слабо, Z вернуть предыдущий; время ответа пишется (`ms`) — ответ < 0,5 с стоит
  перепроверить повтором [предложение RC, не калибровано].
- Видео-пары: оба ролика стартуют одновременно с начала, без звука, по кругу.
- Хранилище: общая база страницы (опубликованная приватная страница claude.ai — **только с согласия заказчика**) → локальный

## 6. ИИ-судья — только отсев брака

| можно | нельзя |
|---|---|
| найти брак среди прошедших ворота и числа: прорастание на виду, «суп из примитивов», обрезка, второе яркое пятно, нечитаемая надпись | решать «вау» и выбирать между годными вместо людей |
| сравнить два кадра одного состояния по одному критерию | оценивать движение (видит конечные кадры), вес, скорость, контраст в числах |
| сортировать N вариантов перед людьми (при согласии с заказчиком ≥ 0,8) | судить свои же кадры в том же контексте (агент-автор не судит) |

Протокол вызова (`02-render-critique.md §4.3` + рубрика `vlm_judge`): ≤ 2 картинки за вызов; два вызова в **чистых контекстах** с
переставленными картинками; засчитывается совпавший ответ, расхождение — «ничья»; один критерий за вызов; ответ «1», «2», «ничья» или
«оба плохи» и одна наблюдаемая причина с местом в кадре; доля побед позиции A вне 0,35–0,65 — судья смещён, партию не использовать;
10 % пар повторить позже.

```text
Шаблон (один из двух вызовов; во втором картинки переставлены):
Ты — арт-директор, ищешь брак в 3D-кадрах для сайта. Бриф: <одна строка паспорта предмета>. Картинка 1 и картинка 2 — два варианта
одного состояния (<состояние>), один размер. Критерий: <один: стыки и прорастание | обрезка и кадр | читаемость надписей | второе яркое пятно>.
Ответь строго: "1", "2", "ничья" или "оба плохи" и одну причину (≤ 15 слов) с местом в кадре. Не оценивай красоту в целом и движение.
```

Почему так: в J/02 судья выбрал «богаче» (кофе, дым, градиент) в 3 парах из 4, и все три выбора — брак по коду (масштаб ×5–25,
процедура, которая не доедет до glTF) [проверено]; баллы 1–10 у VLM согласуются с людьми на Pearson 0,17–0,37, попарно — 0,66–0,77
[исследование: C2 `../04-ai-agents-mcp/03-research-llm-3d.md §7`].

## 7. Правила решения

**Пара у одного голосующего**: оба порядка за одну сторону → победа стороны; разные ответы (включая «одинаково» в одном из порядков)
→ ничья; «оба слабо» в обоих порядках → «оба слабо»; одного ответа нет → «—».

**Счёт стороны по набору пар** (рубрика `pairwise.procedure` п. 6): `(победы + 0,5 × ничьи) / (пары с решением без «оба слабо»)`;
рядом — строгая доля побед и интервал Уилсона 95 %.

**Правило L2 против якорей** (рубрика `pass_rule.L2`): у лучшего варианта против якорей класса — победа или ничья в ≥ 2 из 3
(concept ≈ page, craft, motion); плюс все ворота без FAIL B. При одном вопросе против якоря — «не посчитать»; с 26.09 01:25 пары с якорями —
по двум вопросам (concept и craft: z-anchor / z-anchor-craft, k-anchor / k-anchor-craft, v-anchor / v-anchor-craft), `tally.py` считает L2
по ним; motion у якорей не снят (живые сайты без согласия не снимаем) — реестр T15 корневого README.

**Решение по дорогам** (план испытания, выжимка `15-showcase/_shared/digests/04-code-3d-inventory.md` F): доля побед гибрида C над кодом A в парах C ↔ A
(craft, page, motion) ≥ 0,75 → «Blender обязателен» для такого продукта; 0,4–0,75 → «по бюджету»; < 0,4 → «код достаточен».
Цена гибрида — рядом (рецепт 15 §9: ≈ +1,5 ед. десктоп, +1,9 ед. телефон у «Звена»).

| голосов «C лучше» из 5 пар C ↔ A (1 голосующий, без ничьих) | доля | Уилсон 95 % | решение по порогу |
|---|---|---|---|
| 5 | 1,00 | [0,57; 1,00] | обязателен |
| 4 | 0,80 | [0,38; 0,96] | обязателен (но интервал захватывает «по бюджету») |
| 3 | 0,60 | [0,23; 0,88] | по бюджету |

Интервалы посчитаны функцией `wilson()` из `rc_vote_tally.py` [проверено: RC-checks]. Вывод: с одним голосующим решение — «выбор

# run: skip — [проверено: 99-raw/notes/trial/RC-checks/rc_vote_tally_test.py → RC_CHECK_OK] итоги голосования (только чтение)

Ядро подсчёта — те же правила, что у страницы (`verdicts()` в `vote/index.html`):

```python
# [проверено: 99-raw/notes/trial/RC-checks/rc_vote_tally.py; самопроверка rc_vote_tally_test.py] Python 3 — отрывок [не исполняется] # run: skip
def pref(ans):
    if not ans:
        return None
    if ans["c"] == "equal":
        return "="
    if ans["c"] == "both_bad":
        return "x"
    left_is_a = not ans["flip"]
    return "A" if (ans["c"] == "left") == left_is_a else "B"


def verdict(doc, pid):
    x, y = pref(doc["answers"].get(pid + ":0")), pref(doc["answers"].get(pid + ":1"))
    if x is None or y is None:
        return "—"
    if x == "x" and y == "x":
        return "x"
    if x == y and x in ("A", "B"):
        return x
    return "="


def side_score(results, side):
    """results: список 'A'/'B'/'='/'x'; side — 'A' или 'B'. → (счёт с полуничьими, строгая доля, n, Уилсон строгой доли)."""
    dec = [r for r in results if r in ("A", "B", "=")]
    n = len(dec)
    if not n:
        return None
    w = sum(r == side for r in dec)
    t = sum(r == "=" for r in dec)
    return {"score": round((w + 0.5 * t) / n, 3), "wins": w, "ties": t, "n": n, "win_share": round(w / n, 3),
            "wilson95": wilson(w, n), "both_bad": sum(r == "x" for r in results)}
```

Самопроверка: пробные голоса дают те же вердикты, что показала бы страница (скульптура — A, кейс/остров — «оба слабо», кейс/скульптура —
B); синтетика «C победил / ничья / A победил» даёт счёт C 0,5 → «по бюджету», одиночный вопрос против якоря → «не посчитать»
(`RC-checks/rc_vote_tally_test.out.txt`).

## Частые ошибки

- Показывать в паре кадры разного размера или кодировки (наш 1440 против якоря 1024) — выигрывает «крупнее», а не «лучше».
- Засчитывать ответ одного порядка — позиционный сдвиг: у Claude-v1 согласованность при смене порядка 23,8 %, у GPT-4 — 65 %
  (Zheng и др., 2023) [исследование: рубрика `principles`].
- Спрашивать «оцени от 1 до 10» — шум; спрашивать сразу обо всём — ответ по одному впечатлению.
- Давать ИИ-судье 3+ картинки или судить в контексте, где он видел варианты раньше.
- Смешивать пробные голоса с боевыми; брать в долю гибрида пары, где A — не код 3D.
- Решать «нужен ли Blender» по одной паре или по мнению автора варианта.
- Публиковать страницу голосования без согласия заказчика (правило испытания; публикация — приватная ссылка).
