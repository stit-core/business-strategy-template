## Выжимка для агента

1. **Сырой GLB из Blender не выкладывать**: 252k треуг. = 7.1 МБ float32; постобработка даёт 0.35–0.56 МБ по сети (brotli) без видимой разницы (ΔE ≤ 0.26) → §2.1 [проверено]
2. **Считать три веса**: байты по сети (после brotli), время декодирования, память GPU. Draco выигрывает только первое; KTX2 — только третье; WebP/AVIF — только первое → §1.1 [проверено]
3. **Геометрия по умолчанию — Meshopt + квантование** (`gltf-transform optimize` или `gltfpack -cc`): декодирование 6–8 мс на 252k треуг., память GPU −30–38 %, сжимает морфы и анимацию; декодер 7 КБ br → §2.3 [проверено] [S18]
4. **Draco** — только когда важен размер без gzip/brotli и нет морфов: 383 КБ против 822 КБ, но декодирование 45–57 мс (тёплое) и 0.28–0.45 с холодное, в GPU снова float32, морфы не сжимает (1.10 → 0.98 МБ); декодер 58 КБ br → §2.2 [проверено] [S18]
5. **Встроенное сжатие экспортёра не использовать**: Meshopt экспортёра 5.2 без квантования (2.2 МБ против 0.82 МБ у gltfpack), Draco экспортёра = тот же Draco → §2.7 [проверено]
6. **Инстансинг бьёт любое сжатие**: 900 объектов — 20–61 КБ и 1 вызов против 0.8–24 МБ развёрнутой геометрии → §2.6 [проверено]
7. **`gltf-transform optimize` по умолчанию ломает адресуемые сцены**: join/flatten склеивает 36 объектов в 4 и теряет имена, simplify режет 252k до 94k, palette сливает материалы → для сцен с JS-логикой `--flatten false --join false --simplify false` → §4.1 [проверено]
8. **gltfpack по умолчанию выбрасывает extras, имена неанимированных узлов и свои атрибуты** (`_WAVE`): `-ke -kn` возвращают extras и имена, `-vpf` убирает узлы деквантования; свои атрибуты не сохраняются никак (кроме `_ID`, `_BATCHID`, `_FEATURE_ID_n`) → §4.3 [проверено] [S8]
9. **Квантование добавляет узел-обёртку** (деквантование): имя остаётся у родителя, меш — ребёнок (`hero_orb` → `hero_orb_1`); в JS искать меш через `traverse(o => o.isMesh)` → §2.4 [проверено]
10. **Упрощение по базовой форме портит морфы**: `-si 0.5` на морф-меше — IoU 0.82 в деформированной позе; для морфов и скиннинга `--simplify false` → §2.5 [проверено]
11. **`--vertex-layout separate`** при квантовании: three r186 заливает interleaved-буфер отдельно на каждый тип — 8.2 МБ GPU против 5.6 МБ при том же файле → §2.4 [проверено]
12. **Память текстур**: любая JPEG/PNG/WebP/AVIF в GPU = RGBA8 + мипмапы: 2048² = 21.3 МБ, 1024² = 5.3 МБ; 9 карт 2k = **192 МБ**. KTX2 остаётся сжатой: 2048² = 5.3 МБ (BC7/ASTC), 2.7 МБ (ETC1/BC1) → §3.1 [проверено] [S7]
13. **Разрешение — самый дешёвый приём**: 2048 → 1024 делит вес в 2.3 раза и память в 4 раза при ΔE 0.70 → §3.5 [проверено]
14. **WebP q80 для передачи** (6.19 → 3.17 МБ, ΔE 0.53, кодирование 1.1 с); AVIF q60 лишь на 5 % меньше, а кодируется 23 с → в конвейере агента WebP → §3.3 [проверено]
15. **KTX2 для памяти и телефона**: ETC1S — цвет (мылит нормали, SSIM 0.91), UASTC — нормали и ORM, но без RDO огромен (6 → 30 МБ файл, загрузка 352 мс) → §3.4 [проверено] [S7]
16. **Телефон**: `gltfpack -cc -tc -ts 0.5` из JPEG/PNG-исходников → Camera_01: 6.05 → **1.53 МБ**, GPU текстур 192 → **12 МБ**, тёплая загрузка 33 мс → §3.6 [проверено]
17. **gltfpack -tc не перекодирует WebP-вход**: текстуры остаются WebP, а KHR_texture_basisu пишется в required → для KTX2 экспортировать `export_image_format="AUTO"` (JPEG/PNG) → §4.3 [проверено]
18. **gltfpack из npm (WASM) не умеет -tc/-tw** («built without BasisU/WebP support») — нужен нативный бинарник (`99-raw/tools/bin/gltfpack-1.2/gltfpack`) → §1.2 [проверено] [S8]
19. **`optimize --texture-compress ktx2`** на 9 картах 2k шёл 548 с → в конвейере агента `etc1s`/`uastc` по слотам или `gltfpack -tc` (3.8 с) → §4.1 [проверено]
20. **KTX2 на странице требует** `KTX2Loader.setTranscoderPath(...).detectSupport(renderer)`; транскодер 212 КБ br, холодный старт ≈ 0.6 с; на Linux+Mesa three отключает ASTC/ETC и транскодирует в BC7 → §3.4 [проверено] [S10] [S18]
21. **Размер текстур кратен 4** (KTX2), лучше степень двойки; ≤ 2048 для веба, ORM и шероховатость можно в ¼ площади цвета → §3.5 [документация: S4, S7]
22. **Не кодировать KTX2 из JPEG**, если есть PNG: артефакты JPEG усиливаются блочным сжатием [S7] (в E/18 источник был JPEG — оценка качества пессимистична) → §3.4 [документация: S7]
23. **Draco + Meshopt вместе** — оба расширения в required, нужны оба декодера; не включать → §2.2 [проверено]
24. **AR-выдача отдельно**: Scene Viewer не поддерживает Draco, Meshopt и KTX2, морфы и цвет вершин; ≤ 100k треуг., ≤ 2048², ≤ 10 МБ (15 — ошибка) → отдельный несжатый GLB → §6.1 [документация: S13, по A-notes]
25. **Бюджет первого экрана, телефон** (сцена или мир; для одного героя продуктового лендинга строже — 3D ≤ 0,8 МБ, ≤ 50 тыс., ≤ 30 вызовов: `../01-web-3d-landscape/02-when-3d-budgets-loading.md` §3.1, ворота `../09-web-runtime/05-performance-a11y-fallbacks.md` §7.2): GLB ≤ 1–1.5 МБ по сети, ≤ 50–100k треуг., ≤ 15–30 вызовов, текстуры ≤ 1024² KTX2, память текстур ≤ 32–64 МБ, DPR ≤ 1.5 → §6.5 [мнение: синтез S13–S18 и замеров E/17, E/18, E/24]
26. **Бюджет первого экрана, десктоп** (сцена или мир; герой продукта — ≤ 1,5 МБ, ≤ 100 тыс., ≤ 60 вызовов, A §3.1): GLB ≤ 3 МБ, ≤ 200–300k треуг., ≤ 30–50 вызовов, текстуры ≤ 2048² (WebP или KTX2), память текстур ≤ 128 МБ → §6.5 [мнение: синтез]
27. **Реальность наградных сайтов** (33 сайта, десктоп): вес страницы — медиана 12.6 МБ, 3D-ассеты 2.6 МБ, первый 3D-кадр 14 с, draw calls при прокрутке — медиана 13, p90 33; мобильные версии легче в 1.5–6 раз → §6.2 [исследование: замеры агента A, S18]
28. **Вершины считать в glTF, а не в Blender**: flat-шейдинг ×3.7, швы UV +10 % (`01` §4.1) → §6.4 [проверено]
29. **Проверять бюджет замером**: `gltf_load_bench.py` (загрузка, первый кадр, память GPU), `gltf_web_inspect.py` (вызовы, треугольники), валидатор → §6.6 [проверено]
30. **Сервер**: GLB отдавать с brotli/gzip — meshopt-данные рассчитаны на дожатие (c1: 822 → 353 КБ), Draco не дожимается (383 → 383) → §2.1 [проверено] [S8]

## 1. Что сжимает что

### 1.1. Три веса ассета

| метод | байты по сети | время декодирования в браузере | память GPU | что трогает |
|---|---|---|---|---|
| gzip/brotli сервера | ↓ (сильно для meshopt и сырых буферов, слабо для Draco и картинок) | ≈ 0 | — | всё |
| KHR_mesh_quantization (int8/int16 вместо float32) | ↓ | 0 (данные сразу в GPU) | **↓** | позиции, нормали, UV, морфы |
| EXT/KHR_meshopt_compression | ↓↓ | единицы мс (wasm 7 КБ br) | = квантованному | вершины, индексы, морфы, анимация, инстансы |
| KHR_draco_mesh_compression | ↓↓↓ (без gzip) | десятки–сотни мс (wasm 58 КБ br, воркеры) | float32 (как сырой) | только вершины и индексы примитива |
| упрощение (simplify, `-si`) | ↓ | — | ↓ | треугольники |
| инстансинг (EXT_mesh_gpu_instancing) | ↓↓↓ | — | ↓↓↓ | повторяющиеся меши |
| WebP / AVIF | ↓↓ | декодирование картинки (браузер) | RGBA8 + мипмапы — **не меняется** | текстуры |
| KTX2 ETC1S / UASTC | ≈ / ↑ | транскодирование (wasm 212 КБ br) | **↓ в 4–8 раз** | текстуры |
| ресайз текстур | ↓ | — | ↓ (квадратично) | текстуры |

[проверено]; размеры декодеров — замер агента A (A/03) [S18].
Спецификация meshopt прямо рассчитывает на квантованные и переупорядоченные данные под GPU и дожатие gzip [S2]; квантование
«static PBR mesh: 48 байт на вершину → 20 байт» [S3].

### 2.2. Draco

- Декодирование в wasm-воркерах (`DRACOLoader.workerLimit = 4` по умолчанию [S11]); первый файл страницы платит за загрузку
  декодера: 139–450 мс холодного старта в опытах; тёплое декодирование 252k треуг. — 45–57 мс, 288k — 85–152 мс
  [проверено].
- В GPU Draco-геометрия — float32, как сырая (c1: 7.2 МБ против 4.4 МБ у квантованного meshopt).
- Сжимает только атрибуты и индексы примитива; морф-таргеты и анимация остаются как есть (c4: 1.10 → 0.98 МБ) [S1]
  [проверено]. Draco может менять порядок и число вершин [S1].
- Уровень экспортёра 0–10, «higher values currently not supported» выше 6; квантование экспортёра 14/10/12/10/12 бит
  (позиции/нормали/UV/цвет/прочее) [S19: params.json E/01].
- gltfpack Draco не поддерживает вовсе (ни на вход, ни на выход) [S8].
- Draco и Meshopt в одном файле (оба флага экспортёра) → оба расширения в `extensionsRequired`, примитив сжат Draco —
  странице нужны оба декодера [проверено].
- Практики: Bruno Simon сжимает модели Draco «primarily through quantization» [S21]; `gltfjsx -T` в разборе Codrops даёт
  Draco и −90 % [S23]. Для страницы с одним-двумя крупными статичными мешами и без brotli на хостинге Draco оправдан.

### 2.3. Meshopt + квантование

- `EXT_meshopt_compression` (vendor) и `KHR_meshopt_compression` (Release Candidate) — сжатие на уровне bufferView для
  вершин, индексов, морфов, анимации и атрибутов инстансов [S2]; three r186 поддерживает оба с `setMeshoptDecoder` [S12].
- Декодирование в основном потоке wasm (7 КБ br): 252k треуг. — 6–8 мс, 288k — 20 мс [проверено].
- Морфы и анимация: c4 1.10 МБ → 0.26–0.31 МБ; ΔE 0.72–0.74 из-за квантования дельт морфов (незаметно глазом)
  [проверено].
- gltfpack: `-c` — сжатие, `-cc` — сильнее, с расчётом на gzip/brotli; `-cz` — KHR_meshopt_compression с высоким уровнем [S8].
  gltf-transform: `meshopt --level high` (по умолчанию в optimize) [S9].
- Файлы без сжатия, но с квантованием (`gltfpack` без `-c`, `gltf-transform quantize`) требуют `KHR_mesh_quantization` в
  required — three r111+ [S3] [S8].

### 2.4. Квантование: биты, узлы деквантования, раскладка буфера

- По умолчанию gltfpack: позиции 14 бит, UV 12, нормали/касательные 8, цвета 8 [S8] (экспортёр при `export_use_gltfpack`
  передаёт те же `-vp 14 -vt 12 -vn 8 -vc 8`, но с `-noq` по умолчанию, §2.7). Визуально: ΔE2000 three↔three ≤ 0.26 на c1 и c2,
  0.72–0.74 на морфах [проверено].
- Целочисленные позиции хранятся в сетке объекта; обратное преобразование записывается в TRS узла. Если у узла анимация или
  дети, инструмент вставляет **дочерний узел деквантования**: gltfpack `-cc` на c2 — 36 → 70 узлов; gltf-transform на
  анимированном `hero_orb` — меш переехал в ребёнка `hero_orb_1` [проверено].
  `gltfpack -vpf` (float-позиции) не вставляет узлов ценой размера (12.1 → 12.9 КБ) [проверено] [S8].
- three r186 загружает interleaved-буфер (`--vertex-layout interleaved`, умолчание gltf-transform) отдельной копией на каждый
  тип компонентов: `gltf-transform quantize` дал 8.2 МБ GPU против 5.6 МБ с `--vertex-layout separate` при одинаковом файле;
  для больших мешей добавлять `--vertex-layout separate` [проверено].

### 2.5. Упрощение

- `gltf-transform optimize` упрощает по умолчанию (`--simplify true`, ошибка 0.0001 от габарита) [S9]: c1 252k → 94k треуг.,
  ΔE 0.26 — на гладком high-poly почти незаметно, но меняет силуэт тонких деталей [проверено].
- `gltfpack -si 0.5`: c1 252k → 126k; на морф-меше c4 9024 → 4512 треуг. и IoU 0.82, ΔE 3.81 в деформированной позе — упрощение
  считается по базовой форме и не видит, куда уходят вершины морфов [проверено].
- Правило: упрощать в Blender (Decimate/ремеш с контролем глазами, агент D1) или `--simplify false`; автоматическое упрощение —
  только для статичных гладких мешей с запасом по детализации.

### 2.6. Инстансинг

- 900 икосфер: инстансы — 61 КБ сырых / 20 КБ gp_cc, 1 вызов; развёрнутые — 23.6 МБ сырых / 0.78 МБ gp_cc brotli, 13.5 МБ GPU
  [проверено].
- Инстансы задаются в Blender (GN + `export_gn_mesh` + `export_gpu_instances`, или связанные дубликаты) — `01` §4.7. gltf-transform
  `optimize` сам создаёт инстансы из ≥ 5 одинаковых мешей (`--instance`, `--instance-min 5`) [S9]; gltfpack — по `-mi` [S8].

### 2.8. Выбор

| ситуация | геометрия | команда |
|---|---|---|

| AR (Scene Viewer) | без сжатия (§6.1) | отдельный GLB |

## 3. Текстуры

### 3.1. Память GPU: почему WebP не спасает телефон

«Файл ≠ память GPU» — `[консенсус]`: E/18 и F1/03 замером, W7 и пять роликов W13 (Мажуга: одна 2K-текстура WebP — 22,37 МБ в GPU против 2,8 МБ у KTX2).

Любая JPEG/PNG/WebP/AVIF после декодирования браузером заливается в GPU как RGBA8 (4 байта на пиксель) плюс мипмапы (+⅓):

| размер | RGBA8 + мипмапы | KTX2 → BC7 / ASTC 4×4 / ETC2 RGBA (1 байт/пикс.) | KTX2 → ETC1 / ETC2 RGB / BC1 (0.5 байт/пикс.) |
|---|---|---|---|
| 512² | 1.3 МБ | 0.35 МБ | 0.17 МБ |
| 1024² | 5.3 МБ | 1.3 МБ | 0.7 МБ |
| 2048² | **21.3 МБ** | 5.3 МБ | 2.7 МБ |
| 4096² | 85 МБ | 21.3 МБ | 10.7 МБ |

Замер (E/18, `gltf_load_bench.py`): Camera_01 с 9 картами 2048² — **192 МБ** текстур в GPU для JPEG, WebP и AVIF одинаково;
KTX2 — 48 МБ (здесь BC7); `-ts 0.5` (1024²) — 12 МБ [проверено].
KTX Artist Guide: лампа StainedGlassLamp — 13 МБ файла, 96 МБ в GPU; после KTX — 10 МБ и 21 МБ; утка (PNG 512²) — 118 КБ файла и
1.5 МБ GPU против 116 КБ и 277 КБ у ETC1S [S7]. MDN: мипмапы — +30 % памяти; гарантированный минимум `MAX_TEXTURE_SIZE` — 4096
[S16, по A-notes].

Во что транскодирует `KTX2Loader` r186 (приоритеты из исходника) [S10]:

| исходник KTX2 | порядок выбора целевого формата |
|---|---|
| ETC1S | ETC2 (1) → ETC1 (2) → BC7 (3) → BC1/BC3 (4) → PVRTC (5) → несжатый RGBA32 |
| UASTC | ASTC 4×4 (1) → BC7 (2) → ETC2 (3) → ETC1 (4) → BC3 (5) → PVRTC (6) → RGBA32 |

- Телефоны (ETC2/ASTC) получают ETC1S как ETC → 0.5 байта/пиксель для RGB; десктоп без ETC — BC7 (1 байт) или BC1.
- **Linux, не Android**: если драйвер Mesa объявляет ASTC, ETC и BPTC одновременно, KTX2Loader отключает ASTC/ETC1/ETC2
  («Mesa drivers for AMD and Intel GPUs expose ETC1, ETC2 and ASTC even though the hardware doesn't support these» —
  программная распаковка в драйвере) [S10]. Поэтому в опытах на Iris Xe всё транскодировалось в BC7.
- UASTC-данные при отсутствии ASTC/BC7 спецификация советует транскодировать в несжатый RGBA [S4] — на старых телефонах
  выигрыш по памяти пропадает.

### 3.3. WebP и AVIF

- Уменьшают только передачу: память GPU та же, что у JPEG (192 МБ) [проверено].
- WebP q80 — половина веса при ΔE 0.53 и кодировании 1.1 с на 9 карт; AVIF q60 — ещё −5 % при кодировании в 20 раз дольше
  (23.4 с) и чуть более долгой загрузке (93 мс против 83) [проверено].
- Спецификация EXT_texture_webp: WebP на 25–34 % меньше JPEG и на 26 % меньше PNG; фолбэк PNG/JPEG необязателен [S5].
  EXT_texture_avif в основной ветке Khronos нет — только открытый PR #2235 [S6]; three r186 его поддерживает [S12].
- three r186 грузит WebP без проверки поддержки браузером (в `GLTFTextureWebPExtension` нет детекта) [S12]; все актуальные
  браузеры WebP поддерживают — фолбэк не нужен.
- Экспортёр Blender с `export_image_format="WEBP"` даёт q75 (−57 %) за 2 с, но без ресайза; `export_image_add_webp` — +30 % веса
  без пользы для three (`01` §11) [проверено].
- Карты нормалей в JPEG/WebP с потерями получают пятна (JPEG q75: ΔE 1.14, p95 4.2); KTX Artist Guide: «If normal maps are too
  noisy, use JPEG or PNG instead» [S7] [проверено].

### 3.4. KTX2: ETC1S и UASTC

- **ETC1S** (BasisLZ): маленький файл (6.19 → 4.51 МБ), дешёвая транскодировка, заметно мылит сложные карты: ΔE 2.16, SSIM 0.907,
  на нормалях теряются детали [проверено]. Руководство: для больших однотонных
  областей, монохромных карт, стилизованной графики, интерфейса [S7].
- **UASTC**: высокое качество, но **без RDO** файл огромен: 30.4 МБ из 6.19 МБ JPEG, загрузка 352 мс (zstd + транскод); `--zstd 18`
  по умолчанию, это не RDO [проверено]. Руководство: UASTC — для упакованных карт
  (ORM), нормалей, clearcoat [S7]; спецификация: «as a general rule, textures with color data should use ETC1S while textures with
  non-color data should use UASTC» [S4].
- Смешанный вариант (UASTC для normal/occlusion/metallicRoughness, ETC1S для цвета) без RDO — 23.5 МБ: вес съедают UASTC-данные
  [проверено]. Настройки из KTX Artist Guide для качества (toktx):
  `--encode uastc --uastc_quality 4 --uastc_rdo_l .5 --uastc_rdo_d 65536 --zcmp 22` (нормали: `--uastc_rdo_l .25`),
  `--encode etc1s --clevel 4 --qlevel 255`, для данных `--assign_oetf linear --assign_primaries none`, `--genmipmap` [S7]
  [документация; в E/18 не прогонялось].
- Цветовое пространство в KTX2 обязано совпадать с назначением: цвет — BT.709 + sRGB, данные — linear [S4]; gltf-transform и
  gltfpack выставляют его по слоту материала.
- Источники для KTX2 — PNG, не JPEG: блочное сжатие усиливает артефакты JPEG [S7]. В E/18 исходники были JPEG (так их отдаёт
  Poly Haven) — оценка качества ETC1S пессимистична.
- На странице: `KTX2Loader` + транскодер (`libs/basis/`, 212 КБ br [S18]); холодная загрузка первого KTX2-файла 0.6–0.7 с (скачивание
  wasm), тёплая — 68–79 мс, как у JPEG [проверено].
- `gltf-transform optimize --texture-compress ktx2` на 9 картах 2k работал 548 с (UASTC с RDO для данных) — для конвейера агента
  медленно; `gltfpack -tc` — 3.8 с, `gltf-transform etc1s` — 3.6 с [проверено].
- Практика: Andrew Woan — запечённые текстуры в KTX2 через `gltf-transform etc1s --quality 255` (тёмная «грязная» сцена прятала
  артефакты) [S24]; Bruno Simon — ETC1S и UASTC [S21]; наградные сайты из замера A: igloo 49 KTX2 (12.7 МБ), messenger 10 KTX2,
  shopify-editions — KTX2 ETC1S «видео-атласы» [S18].

### 3.5. Разрешение

- 2048 → 1024: вес 6.19 → 2.63 МБ (×2.3), память 192 → 48 МБ (×4), ΔE 0.70 [проверено].
- `gltf-transform optimize` по умолчанию ограничивает текстуры 2048 (`--texture-size 2048`) [S9]; gltfpack `-ts 0.5` масштабирует
  все текстуры вдвое, `-tl N` ограничивает размер [S8].
- KTX2 требует размеров, кратных 4; степень двойки — для совместимости мипмапов [S4] [S7]. Scene Viewer предупреждает выше 2048²
  [S13]; KTX Artist Guide: «usually no larger than 2048x2048», ORM можно в ¼ площади базового цвета (1024 → 512) [S7].
- Экспортёр Blender разрешение не меняет — ресайз всегда в постобработке [проверено].

### 3.6. Какой формат текстур когда

| цель | формат | команда | ожидание (Camera_01) |
|---|---|---|---|
| десктоп, один hero-объект, важен вес | WebP q80, ≤ 2048 | `gltf-transform optimize … --texture-compress webp --texture-size 2048` | 6.19 → 2.45–2.51 МБ, GPU 192 МБ |
| десктоп, много объектов / конфигуратор | KTX2 (ETC1S цвет, UASTC+RDO данные) | `gltf-transform etc1s`/`uastc --slots …` или `gltfpack -tc` | GPU ×4 меньше |
| телефон | KTX2 + ресайз ×0.5 | `gltfpack -i in.glb -o out.glb -cc -tc -ts 0.5` | **1.53–1.57 МБ, GPU 12 МБ, 31–33 мс** |
| запечённый свет (плавные градиенты) | WebP q85+ или UASTC | — | ETC1S полосит [не проверено на картах света] |
| карты нормалей | PNG / WebP q90+ / UASTC | — | JPEG и ETC1S портят |
| AR (Scene Viewer) | PNG/JPEG, ≤ 2048 | без KTX2/WebP | §6.1 |

## 4. Постобработка: команды

### 4.1. gltf-transform optimize: что делает по умолчанию

| флаг (умолчание) | что делает | чем опасен |
|---|---|---|
| `--compress meshopt` | квантование + meshopt | узел деквантования у анимированных/родительских мешей |
| `--flatten true` | уплощает граф сцены | родители-пустышки исчезают, трансформации «впекаются» |
| `--join true` (`--join-meshes`, `--join-named` true) | сливает меши с одним материалом | 36 объектов → 4, имена теряются («Mesh016») |
| `--instance true` (`--instance-min 5`) | инстансы из ≥ 5 одинаковых мешей | — |
| `--palette true` (`--palette-min 5`) | палитровые текстуры, слияние материалов | материалы для смены цвета в JS сливаются |
| `--prune true` (`--prune-attributes true`) | удаляет неиспользуемое | UV у примитивов с материалом без текстур удаляются (хорошо) |
| `--resample true` | дедупликация ключей анимации без потерь | — |
| `--simplify true` (ошибка 0.0001) | упрощение meshoptimizer | 252k → 94k; морфы и тонкие детали |
| `--texture-compress auto` | пережатие в исходном формате | — |
| `--texture-size 2048` | ограничение размера | — |
| `--weld true` | слияние одинаковых вершин | — |
| глобально `--vertex-layout interleaved` | раскладка буфера | в three +46 % памяти GPU у квантованного меша (§2.4) |

[S9] [проверено]. «Безопасный» профиль для сцен с JS-логикой:
`--flatten false --join false --simplify false` (при необходимости `--palette false --instance false`).

### 4.2. Команды (проверены в опытах)

```bash
# gltf-transform 4.5.0, gltfpack 1.2 (нативный), toktx 4.4.2 — [проверено: 99-raw/experiments/E/17, E/18, E/24-presets/presets.py (POST)]
BASE=$DDD_HOME
export PATH="$BASE/bin/KTX-Software-4.4.2-Linux-x86_64/bin:$BASE/bin/gltfpack-1.2:$PATH"
cd "$BASE/node"                                     # npx берёт gltf-transform из локального node_modules
IN=/abs/path/raw.glb

# 1) статичный hero для десктопа: meshopt + квантование + WebP, текстуры ≤ 2048, без упрощения
npx --no-install gltf-transform optimize "$IN" /abs/path/hero.glb --compress meshopt --texture-compress webp --texture-size 2048 --simplify false

# 2) анимация, морфы, скиннинг, инстансы, адресуемые узлы: без flatten/join/simplify
npx --no-install gltf-transform optimize "$IN" /abs/path/anim.glb --compress meshopt --texture-compress webp --flatten false --join false --simplify false

# 3) телефон: KTX2 (ETC1S) + текстуры ×0.5 + meshopt (вход — JPEG/PNG, не WebP!)
gltfpack -i "$IN" -o /abs/path/mobile.glb -cc -tc -ts 0.5

# 4) отдельные шаги (E/17, E/18)
npx --no-install gltf-transform meshopt "$IN" /abs/path/m.glb                       # квантование + meshopt
npx --no-install gltf-transform quantize "$IN" /abs/path/q.glb --vertex-layout separate
npx --no-install gltf-transform draco "$IN" /abs/path/d.glb
npx --no-install gltf-transform resize "$IN" /abs/path/r.glb --width 1024 --height 1024
npx --no-install gltf-transform webp "$IN" /abs/path/w.glb --quality 80
npx --no-install gltf-transform etc1s "$IN" /abs/path/e.glb                         # нужен toktx в PATH
npx --no-install gltf-transform uastc "$IN" /abs/path/u.glb --slots "{normalTexture,occlusionTexture,metallicRoughnessTexture}"
npx --no-install gltf-transform prune "$IN" /abs/path/p.glb
```

Пути к файлам — абсолютные: команды запускаются из папки `node`. `npx --no-install` не даёт npm скачать пакет заново.

### 4.3. gltfpack: флаги и что он выбрасывает

| флаг | что делает |
|---|---|
| (без флагов) | квантование (`KHR_mesh_quantization`), оптимизация кэшей вершин, слияние мешей неанимированных узлов, упрощение графа |
| `-c` / `-cc` / `-cz` | meshopt-сжатие; сильнее с расчётом на gzip; KHR_meshopt_compression с высоким уровнем |
| `-tc` / `-tu` / `-tw` | KTX2 ETC1S / UASTC / WebP (только нативный бинарник) |
| `-ts R`, `-tl N`, `-tq N` | масштаб текстур, предел размера, качество |
| `-si R`, `-sa` | упрощение до доли R, агрессивное |
| `-mi` | EXT_mesh_gpu_instancing для повторяющихся мешей |
| `-kn`, `-km`, `-ke` | сохранить именованные узлы / материалы / extras |
| `-vpf` | float-позиции: без узлов деквантования |
| `-noq` | без квантования |

[S8]. Проверено на файле с узлами «Cube.001»/«hero_orb», extras и атрибутом `_WAVE` [проверено]:

| вариант | имена | extras | `_WAVE` | лишние узлы | КБ |
|---|---|---|---|---|---|
| исходный | обе | есть | есть | — | 52.8 |
| gltfpack `-cc` | только анимированный `hero_orb` | **нет** | **нет** (warning) | 2 | 12.1 |
| gltfpack `-cc -ke -kn` | обе | есть | нет | 2 | 12.3 |
| gltfpack `-cc -ke -kn -vpf` | обе | есть | нет | 0 | 12.9 |
| gltf-transform optimize | обе | есть | **есть** | 1 | 19.4 |

Прочие особенности gltfpack: Draco и KHR_animation_pointer не поддерживает; неизвестные расширения выбрасывает; свои атрибуты
вершин сохраняет только `_ID`, `_BATCHID`, `_FEATURE_ID_n`, инстансный `_COLOR_0`; имена морфов (`targetNames`) сохраняет всегда [S8].
**`-tc` на WebP-входе** не перекодирует картинки (остаются WebP), но объявляет KHR_texture_basisu обязательным — экспорт для
gltfpack только с JPEG/PNG [проверено].

### 4.4. Что сохраняется после постобработки (сводка)

| данные | gltf-transform optimize (умолч.) | optimize `--flatten false --join false` | gltfpack `-cc` | gltfpack `-cc -kn -ke` |
|---|---|---|---|---|
| имена узлов | теряются при join/flatten | да (+ узел деквантования) | только анимированные | да (+ узлы деквантования) |
| extras (`userData`) | да | да | нет | да |
| свои атрибуты `_имя` | да | да | нет | нет |
| клипы, морфы, скиннинг | да | да | да | да |
| инстансы EXT_mesh_gpu_instancing | да | да | да | да |
| материалы для смены в JS | сливаются (palette) | сливаются, если не `--palette false` | сливаются | да с `-km` |

[проверено: 99-raw/experiments/E/17, E/24, E/28; S8, S9].

## 5. Анимация и морфы при сжатии

- Draco не трогает морфы и анимацию: c4 1.10 → 0.98 МБ; meshopt сжимает и их: 0.26–0.31 МБ [проверено].
- Сэмплированная анимация из Blender (ключ на каждый кадр, `01` §9.2) сжимается `resample` без потерь (дедупликация одинаковых
  ключей) и meshopt-фильтрами; anim_trs из E/24: 58 → 17.5 КБ [проверено].
- Упрощение морф-мешей (`-si`, `--simplify`) ломает деформированные позы (IoU 0.82) — выключать [проверено].
- Скиннинг после optimize: SkinnedMesh + кости, клип 2.46 с, 6 треков; валидатор предупреждает `NODE_SKINNED_MESH_NON_ROOT` —
  норма [проверено].

## Частые ошибки

1. Выкладывать GLB прямо из экспортёра: 252k треуг. = 7.1 МБ, 9 карт 2k = 192 МБ GPU [проверено].
2. «Сжимать» картинки параметром `export_image_quality`/JPEG в экспортёре: исходные JPEG копируются байт в байт; Codrops (Fanton)
   называет это «texture compression tool» — на исходных JPEG он ничего не делает [проверено] [S23].
3. Включать Meshopt экспортёра вместо постобработки: без квантования, 2.2 МБ против 0.8 МБ [проверено].
4. Draco для морфов и анимации — они остаются несжатыми [проверено].
5. Draco и Meshopt одновременно — оба декодера обязательны [проверено].
6. `gltf-transform optimize` с умолчаниями на сцене, где JS ищет объекты по имени, — объекты слиты и переименованы
   [проверено].
7. gltfpack без `-kn -ke` — пропали extras и имена; со своими атрибутами для шейдера — пропали и они [проверено].
8. `npx gltfpack -tc` из npm — «built without BasisU/WebP support» [проверено].
9. `gltfpack -tc` на GLB с WebP-текстурами — картинки остаются WebP, а файл требует KHR_texture_basisu [проверено].
10. UASTC без RDO «для качества» — файл ×5 и загрузка 352 мс [проверено].
11. ETC1S на картах нормалей — детали мылятся (SSIM 0.91) [проверено].
12. Ожидать, что WebP/AVIF уменьшат память GPU, — нет, только передачу [проверено].
13. AVIF «потому что меньше» — +5 % выигрыша за ×20 времени кодирования [проверено].
14. Автоматическое упрощение морф-мешей — ломает деформированные позы (IoU 0.82) [проверено].
15. Считать бюджет по вершинам Blender — в glTF их больше (flat, швы UV) [проверено].
16. Забыть `KTX2Loader`/`MeshoptDecoder`/`DRACOLoader` на странице — исключение при загрузке (`01` §7.1) [S12].
17. Модель по памяти берёт путь декодера из старых примеров (`examples/js/libs/draco/…`) — в three@0.186.0 его нет (404 на
    jsDelivr); декодер для glTF — `examples/jsm/libs/draco/gltf/` (wasm 192 КБ; полный `libs/draco/` — 286 КБ), транскодер
    Basis — `examples/jsm/libs/basis/` (wasm 527 КБ без сжатия) [S11] [проверено: curl jsDelivr 2026-09-23, ../../scripts/3d/gltf_load_bench.py].
18. Декодеры с CDN в продакшене — холодная загрузка 0.3–0.7 с на каждом новом визите; выкладывать рядом с сайтом [проверено].
19. Отдавать AR-площадке (Scene Viewer) сжатый GLB — Draco/Meshopt/KTX2 там не поддерживаются [S13].
20. Размер текстур не кратен 4 → KTX2 невалиден [S4].

## Открытые вопросы и противоречия

1. **Кодирование KTX2 из JPEG**: в E/18 исходники — JPEG Poly Haven; KTX Artist Guide требует PNG [S7] — качество ETC1S/UASTC
   в таблице занижено; настройки RDO из руководства не прогонялись.
2. **Телефоны не мерились**: все времена — Chromium на Iris Xe (Linux/Mesa → BC7). На Android (ETC2/ASTC) и iOS (ASTC) другие
   форматы транскодирования и время; нужна проверка на устройствах (агент J).
3. **Сеть не моделировалась** в моих замерах (локальный сервер); сетевые оценки — пересчётом или по замерам агента A.
4. **Бюджеты §6.5** — синтез, а не эксперимент восприятия: пороги треугольников/вызовов для «плавно на среднем телефоне» надо
   подтвердить замером FPS на реальных устройствах.
5. **Scene Viewer**: таблица требований на странице Google рендерится скриптом; я прочитал таблицу валидатора (10/15 МБ, 2048²,
   100k треуг., 10 материалов, 1 UV, 254 кости), остальное — по заметкам агента A. Список «поддерживаемых расширений» в
   валидаторе (unlit, texture_transform, pbrSpecularGlossiness) сформулирован двусмысленно.
6. **Codrops 2026 против замера**: совет «обновиться до 5.2 ради Meshopt в экспортёре» [S22] — замер показывает, что без
   квантования эта опция втрое уступает gltfpack/gltf-transform.
7. **EXT_texture_avif** не ратифицирован (PR #2235 открыт), но three его поддерживает; судьба расширения неясна.
8. **KHR_meshopt_compression** — Release Candidate; gltfpack пишет его только по `-ce khr`/`-cz` [S8]; поддержка вне three не проверялась.
9. **GPU-память геометрии** в three при interleaved-буферах — поведение r186; в других рантаймах (Babylon, model-viewer) не проверялось.
