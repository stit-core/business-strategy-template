## Выжимка рецепта

1. **Код доводит продуктовую L2-сцену до «предмет в мире» без единого байта ассетов**: v3 = v2 + 7 приёмов под флагами (студия
   PMREM по сценам, IK за курсором, мир вокруг, AO, свет по сюжету + пост, микродеталь, процедурная фактура) + в окончательном виде p3 контровой свет в дымке и след инструмента;
   JS 3D 234,1 / 135,7 КБ br (десктоп/телефон, L2 ≤ 350/250), 3D-ассеты 0 КБ [проверено: CD/10, CD/19, CD/23; `zveno/a-code/numbers.json`].
2. **Сильнейший приём — отклик продукта на ввод**: рука тянется к курсору (аналитическая IK на 2 звена + основание + кисть), на
   телефоне — к точке касания; 0,5 КБ br, в тишине — в пределах шума кадра; в покое 0 кадров [проверено].
3. **Худший «на рубль» — N8AO**: +1,23 мс кадра в тишине и 77,6 КБ br (таблица синего шума и денойз в пакете) за тонкую тень под
   крышками; статичные стыки дешевле запечь в Blender (рецепт 15) [проверено].
4. **Остальное — по ≤ 1,3 КБ br, цена в миллисекундах** (тишина, десктоп 1440×900 DPR 1,5, Δ к кадру без приёмов 1,35 мс): студия
   +0,06, мир +0,48, свет по сюжету + пост +0,82, деталь +0,10, фактура +0,10 мс, контровой в дымке +0,37; вся v3 в окончательном виде
   p3 — 4,72 мс (p2 в том же прогоне 4,35, фаза 2 — 4,31; v2 — 1,43), телефон-режим 0,53 (v2 0,38) [проверено].
5. **Мир вокруг — самый заметный после IK**: тёмный пол с отражением предметов (½ + размытие ¼ по высоте), туман по высоте во всех
   материалах, горизонт и ореол одной формулой с фоном; пол **не должен отражать студию** — иначе серая вуаль под текстом [проверено].
6. **Neutral давит тёмные тона в 5–10 раз**: фон, туман, горизонт задавать «до тона» обратной функцией (`preTone`), иначе ступенька на
   горизонте или чёрный фон; фон к странице ΔE 2,50 [проверено].
7. **Интерактив не заходит в текст**: цель IK ограничена колонкой текста **по содержимому** (Range строк), а не по блоку — в фазе 1
   край флекс-строки дал `minX` 0,6, и рука к тексту не тянулась вовсе; у текста рука **указывает** на курсор (цель ≤ 1,95 м) [проверено].
8. **Вес приёма — только настоящим вырезанием кода** (`esbuild --define` в условиях `if (__CD_X__ && …)`), пост — отдельным `import()`
   (телефон его не качает), крюк GLB — только в сборке `--glb` [проверено].
9. **Телефон — уровень low**: студия, IK касанием, туман и горизонт без зеркала, деталь без винтов; без тени, AO, поста, фактуры;
   винты «в каждом кадре» давали длинные кадры прокрутки 4,44 % → 0,21 % после выноса из low [проверено].
10. **Ворота в тишине — 0 провалов** (итог CD3, вид p3, 26.09 02:29–02:34): десктоп LCP 68 мс, TBT 83 мс, первый кадр 3D 1142 мс; Pixel 7
    (CPU ×4, 1,6 Мбит/с) LCP 644 мс, TBT 162 мс, первый кадр 3106 мс; reduce — 0 вызовов; `motion_check` L2 0/0/0. Под нагрузкой соседей (load 24–31) TBT той же v2 растёт до 634–827 мс —
    мерить только в тишине и парой «база + новое» [проверено].
11. **Клавиатура A (процедурная модель) близка к Blender на общем плане**: верх белых колпачков 94,3 против 92,5 L*, средняя ΔL*
    объекта +2,7 (медиана |ΔL*| 2,8); Blender выигрывает макро с ГРИП, контактные тени, переотражения и матовый пескоструй [проверено: KB фаза 1–2].
12. **Потолок кода** (мнение CD + кадры KB/Z): свет ≈ ⅚, материал ≈ ⅗, атмосфера ≈ ⅗, деталь ≈ ½, движение ≈ ⅚ — не закрыты
    запечённый GI/AO, фактура с износом, уникальная форма начинки, фотореализм неподвижного кадра → Blender или гибрид [мнение: CD `14-code-3d/01 §2`];
    слепые пары (заказчик, 26.09, 1 судья — `15-showcase/vote/results.md`): код v3 > v2; главный кадр «Звена» B > A > C, A > C и в разборке, «сустав
    изнутри» A > B, скан — ничья; клавиатура A = C по кадрам, в движении набора C > A; ИИ-отсев нашёл у A брак кадра: искры-точки на тёмных крышках J2/J3,
    шов по середине медного цилиндра и лесенку по кромке чаши в разрезе (`99-raw/notes/trial/AJ/pass2.md`, пары z-hero-ab, z-inside-ab).

## 1. Бриф-пример и границы

«Запуск промышленного манипулятора (L2): рука собирается по прокрутке, фиксация модуля — вспышкой кольца, скан сустава показывает
начинку, рука тянется к читателю; тёмная страница `#101215`, 3D первого экрана — после постера» (`15-showcase/zveno/art-direction.md`, раздел A).

| бери код | не бери код (или только его) → куда |
|---|---|
| продукт отвечает на ввод: курсор, касание, клавиши, прокрутка ведёт механику | неподвижный премиальный кадр (постер, станции, рентген) → Cycles (рецепт 13) или свой рендер той же сцены |
| сборка/разборка, скан «внутрь», свет по сюжету | ≥ 30 уникальных форм, износ, начинка «как CAD» → модель Blender + код (рецепт 15) |
| повторы по правилу: винты по окружности, кабель, маркировка шрифтом страницы | статичный GI/AO стыков → запекание (рецепт 15), не N8AO |
| вес важнее фотореализма: 0 КБ ассетов | «реальное место» → сплат (`../14-code-3d/README.md`, дерево) |

## 5. Код: отрывки общего модуля `15-showcase/_shared/code3d/src/`

IK на два звена + основание + кисть; `A` — точка указателя, когда цель упёрлась в границу текста: рука не лезет в текст, а указывает.

```js
// [проверено: 15-showcase/_shared/code3d/src/ik.js; кадры 99-raw/experiments/CD/out/p2/look/sheet-ik*.jpg] three r186 — отрывок
export function solveIK(T, prevJ1, out, P = {}, A = null) {
  const tilt = P.tilt ?? 0.55, reach = P.reach ?? 1;
  const r = Math.max(0.45, Math.hypot(T.x, T.z));
  const up = clamp(T.y, 0.35, 2.5) - SH_Y;
  // рука тянется «от себя»: ось f звена смотрит от цели (как в рабочей позе v2), углы — зеркально
  out.j1 = wrapNear(Math.atan2(T.x, T.z) + Math.PI, prevJ1);
  let ang = Math.atan2(up, r) - tilt;                              // инструмент смотрит на цель с наклоном вниз
  if (A) {                                                         // прицел: A в вертикальной плоскости руки (r вдоль направления на T)
    const ra = (A.x * T.x + A.z * T.z) / r, ua = A.y - SH_Y, dr = ra - r, du = ua - up;
    if (dr * dr + du * du > 0.0025) ang = clamp(Math.atan2(du, dr), -1.45, 0.5);
  }
  const tu = Math.cos(ang), tv = Math.sin(ang);
  let wu = r - LC * tu, wv = up - LC * tv, d = Math.hypot(wu, wv);
  const dmax = (LA + LB) * reach - 0.03, dmin = Math.abs(LA - LB) + 0.08;
  if (d > dmax) { wu *= dmax / d; wv *= dmax / d; d = dmax; } else if (d < dmin) { wu *= dmin / d; wv *= dmin / d; d = dmin; }
  const g = Math.acos(clamp((LA * LA + d * d - LB * LB) / (2 * LA * d), -1, 1));
  const e1 = Math.atan2(wv, wu) + g;                               // локоть вверх
  const eu = LA * Math.cos(e1), ev = LA * Math.sin(e1);
  const t2 = Math.atan2(eu, ev), a2 = Math.atan2(wu - eu, wv - ev), a3 = Math.atan2(tu, tv);
  out.j2 = clamp(-t2, -1.3, 1.3); out.j3 = clamp(-(a2 - t2), -2.75, 2.75); out.wr = clamp(-(a3 - a2), -2.1, 2.1); out.roll = P.roll ?? 0.35;
  return out;
}
```

Фон, туман и горизонт «до тона» — обратная функция Khronos PBR Neutral для тёмных цветов:

```js
// [проверено: 15-showcase/_shared/code3d/src/util.js; фон к странице ΔE 2,50 — CD metrics_final_v3] — отрывок
export function preTone(hex, exposure) {
  const c = new Color(hex);                                       // линейные значения
  const ym = Math.min(c.r, c.g, c.b);
  let off;
  if (ym < 0.04) { const xm = Math.sqrt(ym / 6.25); off = xm - ym; } else off = 0.04;
  return new Color((c.r + off) / exposure, (c.g + off) / exposure, (c.b + off) / exposure);
}
```

## Частые ошибки (молчаливые — ни ошибки, ни предупреждения)

| ошибка | симптом | исправление | метка |
|---|---|---|---|
| `scene.environment = pmrem.fromScene(...)` | металл чёрный, белый серый | `.texture` у цели рендера | CD/04 |
| ореол фона в экранных координатах | ступенька на горизонте | ореол в мировом направлении одной формулой в фоне и тумане | CD/04 |
| тёмный пол отражает студию PMREM | фон L* 13 вместо 5, серая вуаль под текстом | `envMapIntensity` 0,06, `specularIntensity` 0,18 — отражает только зеркальный проход | CD/04 |
| зерно OVERLAY | пересвет 3,9 % | SOFT_LIGHT 0,05 (0,12 — крапинка +5/255 в тёмных) | CD/06 |
| bloom «яркость > 1 только у кольца» | светится лак (блики HDR 2–3 ярче оранжевого: яркость 0,21·R) | порог 3,4, вспышка ×16 | CD/06 |
| `compileAsync` без буфера поста | длинная задача 2,2 с перед первым кадром | компилировать в целевом буфере (`setRenderTarget(post.target())`) | CD/08 |
| N8AO + MSAA композитора | первый кадр 0,5–1,35 с | `multisampling: 0` + FXAA | CD/08 |
| MSAA 4 HalfFloat + анизотропный Physical | «искры»-квадраты bloom | MSAA композитора выключен всегда (заодно −1,8 мс) | CD/12 |
| FXAA в общем EffectPass | кадр без тона, пересвет 11,5 % | FXAA — отдельным проходом после тона | CD/08 |
| граница IK по блоку DOM | рука к тексту не тянется (`minX` 0,6) | по содержимому (Range) | CD/14 |
| хвост IK 0,9 с | motion_check: петля под текстом (S) | отсечка 0,45 с, как у прокрутки | CD/08 |
| рантайм-флаг вместо define | вес «без приёма» тот же | условие `if (__CD_X__ && …)` + `--define` | CD/10 |
| средняя `el/n` с зависанием в окне | fx 8,7 мс вместо 3,95 | ожидание простоя перед замером; медиана интервалов rAF при `--disable-gpu-vsync` непригодна | CD/15 |
| мерили под нагрузкой соседей | «v3 не проходит TBT» | тишина + пара «база/новое» в одном прогоне | CD/08 |
| `BufferGeometry.clone()` делит `userData` | у всех клавиш ряда надпись последней | метки клонов хранить отдельно | KB |
| RectAreaLight + PMREM из тех же панелей | свет дважды, пересвет | `environmentIntensity` 0,1–0,15 | KB |

## Чек-лист

- [ ] Каждый приём под флагом и define сборки; цена — мс в тишине и КБ br вырезанием; лист «приём за приёмом»?
- [ ] IK/касание: границы текста по содержимому, хвост ≤ 0,45 с, 0 кадров в покое?
- [ ] Фон/туман/горизонт через `preTone`; пол не отражает студию; лампы студии белые?
- [ ] AO — только если прирост доли побед окупает ≈ 2,8 ед. цены; иначе запечь (рецепт 15)?
- [ ] Пост отдельным чанком, телефон его не качает; MSAA композитора 0 + FXAA отдельным проходом?
- [ ] Уровень low: без тени, зеркала, AO, поста и «невидимой» детали; длинные кадры прокрутки ≤ 2 %?
- [ ] Ворота в тишине парой «база + новое»: LCP, TBT, первый кадр 3D, reduce 0 вызовов, motion_check L2?

## Открытые вопросы и противоречия

1. **Выжимка планирования ставила AO в топ-10 «вау на рубль» (4-е место, «3/2/2»)** — испытание: худший «на рубль» (77,6 КБ br,
   +1,23 мс). Три AO на одном стенде (CD3, пропускная после простоя): N8AO pmndrs +1,04 мс, N8AO на EffectComposer +1,76, SSAO +1,90,
   GTAO +3,26 мс; вес 77,6 / 77,6 + 2,4 / 4,7 + 2,4 / 7,1 + 2,4 КБ br — все «тонкий эффект»; статичный AO — запекать (`14-code-3d/05`,
   CD `HANDOFF-3.md §4`, `CD/out/cd3/ao_tsl_summary.json`).
2. **«Выборочный bloom: яркость > 1 только у кольца»** (выжимка C.5) — ошибочно в формулировке; рабочий — порог 3,4 HDR + вспышка.
3. **Контровые ±135° в PMREM-студии** — нейтрально (линия на кромке есть, тёмные крышки у низа сливаются с фоном) — в отличие от Cycles (рецепт 13).
4. Приёмы 8 и 10 сделаны CD3 (§3), 9 неприменим; шум шероховатости лака не сделан. Ветка WebGPU/TSL (CD3): кадр 0,71 мс (GLSL) / 1,13
   (WebGPU) / 1,04 (откат), первый кадр 196–216 / 92–94 / 307–323 мс, вес 153,1 / 260,5 КБ br — TSL-материал сам по себе не повод
   (правило 49 корневого README, `14-code-3d/08`).
5. Агент-часы по приёмам не журналировались — в «вау на рубль» знаменатель пока без времени агента.
6. Клавиатура A: 126 тыс. треугольников в кадре раздела (десктоп) — выше бюджета героя 100 тыс.; ворота не меряют, т. к. 3D не в первом
   экране [спорно: к сценам ниже первого экрана бюджет героя не применяется явно].
7. Голосование заказчика (26.09, 1 судья, `15-showcase/vote/results.md`): v3 > v2, но главный кадр «Звена» B > A, у клавиатуры A = C по кадрам и
   C > A в движении набора; «IK — сильнейший» поштучно не проверен (пар «с IK / без» не было) — суждение авторов; блок VOTE `15-showcase/VERDICT.md`.
