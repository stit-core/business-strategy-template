## Выжимка рецепта

1. **Причина «аккуратного каталога» найдена в коде базы**: `rk.studio`/`d1lib.stage` ставят ключ на ≈ 83° к главной грани — белый кейс
   рецепта 01 выходит L* 68 при hex L* 96; стена циклорамы в 9,5r от центра при лампах на 4r — фон L* 55–59 при странице 91–95.
   Для героя эти помощники не брать [проверено: замер выжимки `15-showcase/_shared/digests/02-quality-playbook.md` B0–B3; KIT §2].
2. **Этюд света — 4 схемы на одной модели в одном кадре** (960×540, Cycles 32 спп + OIDN, 4,6–21 с на кадр) выбирает схему за минуту
   машины у всех четырёх предметов; сравнивать при **выровненной экспозиции** (одна цель p95), иначе сравнивается экспозиция, а не
   свет [проверено: Z, KB, SD, VD — листы `15-showcase/*/judge/*light*`; SD `rules.md`].
3. **Лучшие схемы разные**: тёмная студия с полосами (Z), низкий скользящий ключ + два контровых (KB, рядные колпачки), низкое
   боковое солнце (SD, разрез), тёплый ключ сзади-справа + фронт (VD, по брифу) — правило «ключ 30–45° к главной грани» верно для
   выпуклого товара с гранью, а не для рельефа и разреза [проверено: Z, KB, SD; VD — отступление по брифу].
4. **Фон — не лампой «на глаз», а числом к цвету страницы**: своя лампа фона (KB, ΔE 0,8–1,8), прозрачный кадр + ловец теней с
   запеканием на цвет страницы (SD, ΔE 0–1), мир для лучей камеры = CSS-градиент страницы через обратную кривую Neutral (Z, ΔE 1,7–1,9)
   [проверено: KB, SD, Z].
5. **Предметный свет — только на предмет** (light linking Cycles): пол без пятна ключа и бликов софтбоксов, у пола своё «солнце» 50°
   как мягкая тень касания (Z); у ленты и крышки флакона — свои лампы (VD) [проверено: Z, VD].
6. **HDRI — только отражения** (обесцвеченный встроенный `studio.exr`, сила 0,06–0,5, камера его не видит); на глянцевом полу HDRI у
   горизонта даёт белое пятно — маска по углу места для непервичных лучей [проверено: Z фазы 1–2, VD].
7. **Цели-числа до глаз** (`img_metrics.py`): белая грань ≥ 85 L* (у белого лака на тёмном — **p75 маски лака**), пересвет ≤ 1 %,
   объект − фон ≥ 10–15 L*, фон к странице ΔE ≤ 3, шум ≤ 2,5·10⁻³ **по гладким участкам**; блик 0,1–1 % — только для глянцевой полосы
   на цветном/тёмном товаре [проверено: Z, KB, SD, VD; пороги уточнены решением оркестратора 25.09].
8. **Сдвиг кадра Blender меряется в долях стороны, по которой вписан сенсор** (AUTO — большая сторона, VERTICAL — высота): при
   `sensor_fit VERTICAL` и 16:10 `shift_x −0,2` сдвигает на 0,125 ширины [проверено: Z фаза 2; арифметика — RC-checks].
9. **Итог по числам «до → после»**: белое 68 → 92–95 L* (Z, KB, SD), фон стены L* 55–59 → ΔE 0–1,9 к странице у выбранных кадров
   (исключения с причиной — §5), пересвет флакона 1,89 → 0,28 % (VD) — §7 [проверено: numbers.json предметов].
10. **Финал героя — Cycles 128 спп + OIDN**: 20–45 с (Z 1600×1000), 41–104 с (SD, KB), 68 ± 8 с (VD 1280×720); секвенции — Cycles
    20–40 спп + OIDN (9–13 с на кадр), EEVEE дешевле ×3, но без ловца теней, GI и анизотропии [проверено: Z, KB, SD, VD].
11. **2–4 варианта и ≤ 2–3 итерации с откатом** дали лучший кадр у всех: Z H1 → H1c/H4m, KB H1–H3 → H2 (макро), SD H1–H3 → H1b,
    VD v1 → v5 → i1–i3 (i2 ухудшил фон — i3 исправил) [проверено: `rules.md` дорожек].
12. Красота решается глазами и слепым голосованием, числа — только ворота: у всех дорожек «шум» и «блик» по умолчанию мерили не то
    (рёбра, надписи, широкие белые зоны) — метод меряется маской (§5). Слепое голосование заказчика (26.09, 1 судья): главный кадр
    «Звена» B (Cycles) > A (код) > C (гибрид); «Сдано» — B > A во всех 4 парах; Velmora — ничья с нейросетью по всем кадрам облёта;
    против якорей класса — ничьи, Shopify — победа по идее (L2 проходят все три) — `15-showcase/vote/results.md`, блок VOTE `15-showcase/VERDICT.md`.

def inv_neutral(target_lin):
    """Вход сцены, который Neutral превратит в target (для тёмных и средних тонов, peak < 0,76)."""
    t = list(target_lin)
    m_out = min(t)
    m_in = math.sqrt(m_out / 6.25) if m_out < 0.04 else m_out + 0.04
    off = m_in - m_out
    return tuple(v + off for v in t)

Лампа-полоса под фаску (KB): блик ляжет длинной линией, если лампа стоит по зеркальному направлению взгляда камеры от нормали фаски.

```python
# [проверено: 12-recipes/examples/13-wow-light-hero/src/brender.py, chamfer_strip()] Blender 5.2.2 — отрывок [не исполняется] # run: skip
def chamfer_strip(st, cam, point, normal, along, name, E=2.4, dist=0.34, length=0.5, width=0.012):
    """Лампа-полоса по зеркальной формуле: блик ляжет длинной линией на фаску с нормалью normal в точке point."""
    v = (cam.matrix_world.translation - point).normalized()
    n = normal.normalized()
    r = (2 * n.dot(v) * n - v).normalized()
    pos = point + r * dist
    return kbr.area(st, name, pos, point, E, dist, length, width, xdir=along)   # kbr — 12-recipes/examples/13-wow-light-hero/src/kbr.py
```

`setViewOffset` three) в сдвиг Blender; числа проверены на замере Z (центр J2 0,519 W у H1c против 0,595 W у v2 — ровно 0,2 − 0,125).

```python
# run: system
# Python 3 — [проверено] доля кадра ↔ shift Blender; сверка с замером Z
def shift_for(frac_w, frac_h, W, H, sensor_fit="AUTO"):
    """Доли кадра (x — ширины вправо, y — высоты вниз, как setViewOffset three) → (shift_x, shift_y) Blender."""
    S = max(W, H) if sensor_fit == "AUTO" else (W if sensor_fit == "HORIZONTAL" else H)
    return frac_w * W / S, -frac_h * H / S


def frac_of(shift_x, W, H, sensor_fit="AUTO"):
    """Обратное: какой доле ширины равен shift_x Blender."""
    S = max(W, H) if sensor_fit == "AUTO" else (W if sensor_fit == "HORIZONTAL" else H)
    return shift_x * S / W


sx, sy = shift_for(0.2, 0.0, 1600, 1000, "VERTICAL")
assert abs(sx - 0.32) < 1e-9 and sy == 0.0
got = frac_of(0.2, 1600, 1000, "VERTICAL")            # что получилось в фазе 1
assert abs(got - 0.125) < 1e-9
assert abs((0.2 - got) - (0.595 - 0.519)) < 0.002      # разница центров J2 на листе Z: 0,076 ширины
assert shift_for(0.17, 0.0, 1920, 1080, "AUTO") == (0.17, -0.0)
assert abs(shift_for(0.0, -0.13, 780, 1688, "VERTICAL")[1] - 0.13) < 1e-9
print("shift: VERTICAL 1600x1000, 0,2 ширины → shift_x", round(sx, 3), "; shift_x 0,2 без пересчёта = доля ширины", got)
```

Отрицательный `shift_x` уводит кадр влево — предмет встаёт правее (−0,17 → центр на 0,67 ширины); положительный `shift_y` опускает
предмет в кадре (портрет телефона KB: +0,13 — Ё в нижней половине, верх под H1; в чек-поинте был знак наоборот — KB `rules.md`).

## Открытые вопросы и противоречия

1. **Паспорт по умолчанию базы** (`00-how-to-use.md §3`: `rk.studio(E_key=2.5)`, мир = фон × 0,4) против этого рецепта (свой свет,
   мир ≤ 0,15) — для героя действует этот рецепт; `rk.studio` остаётся для чернового кадра. В реестр противоречий.
2. **«Ключ 30–45° к главной грани»** — не универсален: рельеф (KB — скользящий 15–20° сбоку, «новое правило»), разрез (SD — 83°,
   прямо не проверено), бриф с контровым ключом (VD — 138°). Формулировка правила: «ключ лепит главную форму; угол — по типу формы».
3. **Порог блика 0,1–1 %** снят для белого на тёмном (Z) и не выполним для белого товара вообще (KB H1 2,4 %, H3 4,8 %); порог шума
   2,5·10⁻³ у SD не выполнен даже по ровным участкам (10,6–14·10⁻³) при невидимом шуме — пороги `img_metrics` не откалиброваны [спорно].
4. **«Мир 0–0,15»** — для тёмной студии; оборот на светлом фоне раздела (KB, прозрачный + ловец) потребовал мир 0,45 и экспозицию
   0…+0,15 (иначе верх колпачков 66,8 L*), небо с солнцем у SD — 0,42–0,68.
5. **Лампы белые** против тёплого ключа брифа (VD): белые полосы дали «холодный каталог»; работает «тёплое — только на бликах».
6. Постер KB hero2 v1: медиана фона к `#1C1D20` ΔE 7,39 (градиент своей лампы фона; постер во весь первый экран, стык со страницей —
   только нижний край) при цели ≤ 3; v2 (KB3) — ΔE 6,77 (портрет 3,24 против 3,55 у v1), всё ещё выше цели: градиент лампы фона
   не доведён; стык постера со страницей глазами отдельно не проверялся, ИИ-отсев (AJ) по кадрам первого экрана клавиатуры брака не нашёл
