## 7. Импорт без сборки: import map и ловушка автоминификации jsDelivr

Для тестовых страниц и лёгких демо (без Vite/esbuild) — импорт прямо из CDN через `<script type="importmap">`. Проверено
волной 2 (F1): **jsDelivr `three.module.min.js` тянет неминифицированное ядро** — версия с `.min` в пути не гарантирует
реально минифицированный код у всех подресурсов; собственный бандлер на своём домене был быстрее (174 против 443 КБ br,
первый кадр 3,7 против 4,9 с) [проверено: F1, `09-web-runtime/01 §…`]. Для прод-сайта — бандлер; для быстрого прототипа —
import map, но замерить вес перед тем, как считать решение окончательным:

```html
<!-- three r186 — [проверено: ../../scripts/3d/web_view.py, F1 09-web-runtime/01] -->
<script type="importmap">
{ "imports": {
    "three": "https://cdn.jsdelivr.net/npm/three@0.186.0/build/three.module.js",
    "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.186.0/examples/jsm/"
} }
</script>
```

Версию в обоих путях (`three` и `three/addons/`) держать одинаковой — иначе загрузчики (GLTFLoader и т. п.) из
`examples/jsm` могут разойтись с ядром по внутреннему API.

## 8. Совместимость с three r186 (peer dependencies)

`@react-three/fiber` требует `three ≥0.156`; `drei` — `three ≥0.159` и `@react-three/fiber ^9`; `postprocessing` —
`three ≥0.168 <0.187` (**при апгрейде three до 0.187+ сломается** — проверять перед обновлением ядра); `@react-three/
postprocessing` 3.2.2 — `postprocessing ^6.36` и `@react-three/fiber ≥9.7`; `model-viewer` несёт свой three ^0.183 изолированно; `troika-three-text` —
`three ≥0.125`; `three-stdlib` — `three ≥0.128`, но фактически может расходиться поведением с текущим r186 (см. п.8).
Правило: перед апгрейдом three проверять таблицу peer у каждого используемого пакета через `npm view <пакет>
peerDependencies` — не полагаться на «обычно совместимо».

## Частые ошибки

- **Ставить `@needle-tools/engine` без проверки тарифа** — Hobby молча ограничивает до некоммерческого использования
  и лого; для сайта заказчика нужен Pro, это статья расходов, не только техническое решение.
- **Считать `@theatre/studio` частью безопасного рантайма** — AGPL требует раскрытия исходников при сетевом
  использовании; ставить в собранный бандл продакшена нельзя без юридической проверки.
- **Импортировать `A-Frame` через обычный `npm install` в CI** без `--allow-git` — падает на git-зависимости.
- **Сравнивать вес `@paper-design/shaders` «6 КБ» с реальной загрузкой страницы** — это разные измерения (минимальный
  esbuild-бандл против полной сетевой загрузки), не взаимозаменяемые числа.
- **Путать Spark (`@sparkjsdev/spark`, сплаты) и spark.js (Ludicon, сжатие текстур)** — оба называются «Spark» в
  разговоре, разный код и разное назначение.
- **Грузить `drei`'s `useGLTF` и ожидать поведения three r186** — используется `three-stdlib`, отдельная версия
  загрузчиков; нестандартные расширения glTF (`-ce khr`) могут не поддерживаться.
- **Оставлять `leva`/`lil-gui` в продакшен-сборке** — лишний вес и открытая панель параметров на боевом сайте.

## Открытые вопросы и противоречия

1. **`@paper-design/shaders` — 6 КБ br (A/03) против 119 КБ по сети (K)** — разная методика (минимальный импорт
   esbuild+brotli против полной страницы с jsDelivr); не разрешено этой волной, требует одного контролируемого
   замера двух путей загрузки одновременно — кандидат волне 4/X.
2. **`@splinetool/runtime` без лицензии в npm** — только ToS сайта; для коммерческого использования в проекте
   заказчика нужна отдельная юридическая проверка (не блокирует, но не должно считаться «свободным MIT»).
3. **Unicorn Studio цена/лицензия редактора** — за логином, вендорское заявление «≈50 КБ gzip» не проверено
   независимым замером этой волной (только рантайм-обёртка `unicornstudio-react` подтверждена как MIT).
4. **`@needle-tools/engine` latest = 6.0.0-alpha.3, stable = 5.1.13** — для продакшена ставить `@stable`, не
   `latest`; в реестре A обе версии присутствуют, файлы базы должны явно указывать, какую ставить (кандидат для S
   при синтезе выжимки).
