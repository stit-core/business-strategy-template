# 16 · Сцены на JS: свой движок на WebGL2, рантайм сцен на прокрутке, маленькие объекты, длинные сцены-миры, приёмы вау

3D для сайта делается JavaScript-кодом: свой движок на WebGL2 без библиотек рисует сцену в `<canvas>` места, рантайм
страницы ведёт её по прокрутке, стенд снимает постеры и мерит цену кадра. Два масштаба: маленькое 3D — предмет или символ
в блоке — и длинная сцена-мир на всю страницу, где движутся сотни и тысячи объектов и на каждом такте что-то происходит.
Blender — подспорье: модель GLB идёт через three (`../09-web-runtime/`), гибрид — `../14-code-3d/`. Нормы — опыт проекта
сайта-портрета (25 сцен, серия из 10 студийных моделей, рантайм, стенд; замеры на Intel Iris Xe и решения заказчика в Play),
набор `examples/` и разборы студий из открытых источников.

## Выжимка папки

1. **Свой движок WebGL2 — путь по умолчанию, когда форма описывается кодом** (поля расстояний, аналитика, инстансы,
   процедурный мир, частицы, линии): 3–26 КБ min+gz на сцену против 174–293 КБ br у three и R3F; на холсте Claude Design
   работает без сети. Библиотека — когда есть GLB с PBR из Blender, физика многих тел или код команды на three.
   `[проверено]` → `01` §10, `06` §1
2. **Один контракт для всех сцен**: фабрика `(canvas, opts)` → ручка, `{pending, destroy}` или `null`; методы рантайма и
   стенда; в `window` — только строка регистрации в `STAGE_SCENES`. `[проверено]` → `01` §1
3. **Чёткость — бюджетом пикселей, а не потолком DPR**: 4,6 МП ПК, 1,9 МП телефон при DPR ≤ 2; множитель плотности 0,7…1 с
   гистерезисом 24 / 12,5 мс. `[проверено]` ПК, `[кейс]` телефон → `01` §6
4. **Кадр — только при изменении**: вне экрана и в скрытой вкладке 0 кадров, своя жизнь — ≈ 30 кадров/с, не больше одной
   отрисовки за кадр. `[проверено]` → `01` §7
5. **Цвет**: линейный расчёт → Khronos PBR Neutral → sRGB вручную; фон места — `preTone`, шва с секцией нет; дизеринг.
   `[проверено]` → `01` §5
6. **Рантайм прокрутку не перехватывает**: `scrub`, `beats` — шаги с доигрышем (шаг 480 / 420 px, линия 60 %, сцена
   доигрывает такт пружиной ω 2,4–3,6 за 1,3–2,0 с), `glide`, `play`; пружина — критически демпфированная, без перелёта.
   `[проверено]` → `02` §3–6
7. **Живых сцен ≤ 2 на ПК и 1 на телефоне**: оживление на подлёте ≤ 0,5 окна, сон за экраном, уничтожение дальше 1,5 окна,
   свежий холст на каждую жизнь. `[проверено]` → `02` §8
8. **Постер — всегда под холстом**; раскадровка вместо сцены — в обзоре холста, при «уменьшить движение» и на программном
   рендере. `[проверено]` → `02` §9–11
9. **Текст — только HTML**: подписи тактов стоят в окне сцены, у сцены свой стиль, текст — факт места; под текстом —
   тихие зоны в шейдере. `[проверено]` → `02` §13, `03` §7
10. **Между двумя сценами — статичный блок**. `[проверено]` → `02` §14
11. **Малое 3D** — SDF-объект в коробке в студийном свете, одно парение на серию, действие по касанию: 4,7–13 мс при
    3,7 МП. `[проверено]` → `03`
12. **Длинная сцена-мир** — инстансы и шейдер от 1–2 uniform, камера по ключам прогресса монотонными кубиками, мир в мире,
    LOD по следу пикселя: 4,4–11 мс при 4,4 МП, ≤ 8–10 мс, чтобы помещались две живые. `[проверено]` → `04`
13. **Сцену выбирают по смыслу места**: предмет и факты бизнеса, станции сюжета; зрелище вокруг знака без фактов не
    берут; «вау» — одна механика, а не набор эффектов. `[кейс]` → `05` §1, §7
14. **Одна сцена — один файл** на холсте, на сайте и в кабинете; меняется только обвязка места. `[проверено]` → `06` §4

## Два масштаба

| | малое 3D: предмет, символ в блоке | длинная сцена-мир на всю страницу |
|---|---|---|
| холст | карточка 747×560 (1,7 МП при DPR 2), полоса 1440×560–640 (3,2–3,7 МП); плитка 800×400 — только постер | окно 1440×760 (4,4 МП) с полем закрепления 3,2–4,2 тыс. px; телефон 390×600 |
| движок | студийный SDF или «один шейдер» (`03`) | инстансы + шейдер, HDR и свечение (`examples/world-template.js`) или процедурный мир одним шейдером (`04`) |
| прокрутка | `scrub` по проходу полосы (ω 6,5) или своё парение и окно появления 18 с | `beats` (5–7 точек покоя, ω 2,4–3,6), `glide` для маршрута |
| жизнь | парение 11–23 с, наклон к курсору, действие по касанию | импульсы, огни, дыхание камеры; курсор подсвечивает, касание пускает волну |
| текст | рядом с моделью в своей трети полосы, подписи по якорям | HTML-карточки тактов в окне сцены, тихие зоны |
| цена | 4,7–13 мс при 3,7 МП, в карточке — меньше по пикселям | 4,4–11 мс при 4,4 МП; дороже 13 мс — не брать |

Все строки — `[проверено]`.

## Что брать: свой движок или библиотека

| задача | чем | почему |
|---|---|---|
| предмет, знак, символ из простых тел | свой движок: студийный SDF или «один шейдер» (`03`) | полное разрешение в коробке, 0 КБ ассетов, без сети на холсте |
| фон или полоса с мелкой деталью: точки, линии, решётки, процедурный мир | свой движок «один шейдер» (`examples/scene-template.js`) | 1 вызов, 4,8 КБ; DPR как у объекта |
| длинная сцена-мир: сотни и тысячи объектов, путь камеры, смена миров | свой движок, многопроходный мир (`04`) | инстансы и шейдер, 16–30 вызовов, 9–26 КБ |
| частицы, линии света, адвекция, типографика полем, бесконечный зум | свой движок (`05` §3) | всё — числа и шейдер |
| модель из Blender с PBR-материалами, текстурами, скелетом | three.js (09/01) | загрузчики GLB, KTX2, meshopt своими не окупаются; 154–174 КБ br |
| витрина товара «покрутить», AR | model-viewer (09/02, 09/06 §2) | клавиатура, подпись, AR из коробки |
| кабинет на React, команда пишет на three, нужны GLB и drei | R3F (09/02) или свой движок в хуке (`06` §3) | R3F — чанк 293 КБ br после первого экрана |
| физика многих тел со столкновениями | библиотека физики + three | своя физика окупается на единицах тел |
| compute: сотни тысяч частиц с логикой, отсечение на GPU | WebGPU + TSL с откатом (14/08) | в WebGL2 нет compute |
| продукт с CAD и живой страницей | гибрид: GLB модулями + код (14/README) | форма — Blender, жизнь — код |
| сцена тяжелее пределов холста, со сборкой или сервером | лабораторная страница вне холста (cd 05/03 §4) | холст её не исполнит |

Правило в одну строку: **форма описывается кодом — свой движок; форма пришла из Blender — three; продукт с CAD — гибрид**.

- **Бюджет пикселей холста**: 4,6 МП ПК, 1,9 МП телефон, DPR ≤ 2; тяжёлым сценам — 3,2–3,4 и 1,2–1,6 МП (`01` §6).

- **Вызовы**: 1 у сцены «один шейдер», 16–30 у многопроходного мира; в покое — 0.
- Все числа — `[проверено]` на одной машине (Iris Xe, Chromium headless, ANGLE Vulkan); телефонный кадр мерился на
  десктопном GPU — числа телефона `[кейс]` (`../../common/evidence.md § Оговорки к числам`).

## Как запустить набор

Утилиты — `../../../scripts/3d/stage_stand.py` (кадр, лист кадров, `perf`, `bench`) и `../../../scripts/3d/stage_smoke.py`
(живые режимы на `examples/demo.html`, reduce, программный рендер); окружение — `../../../scripts/README.md`. Команды — из
папки скилла `.claude/skills/design-deep-dive/`:

```bash
PY=~/.cache/design-deep-dive/venv/bin/python; O=~/.cache/design-deep-dive/out/3d/stand
W='m=world src=world-template.js variant=hero'
$PY scripts/3d/stage_stand.py --selftest
$PY scripts/3d/stage_stand.py shot  $O/world-p0.png $W w=1440 h=760 dsf=2 p=0               # постер места
$PY scripts/3d/stage_stand.py sheet $O/world.jpg 3 "$W w=1440 h=760 p=0" "$W w=1440 h=760 p=0.5" "$W w=1440 h=760 p=1"
$PY scripts/3d/stage_stand.py perf  $W w=1440 h=760 dsf=2 --budget 17                       # ритм: медиана ≤ 17 мс — ok
$PY scripts/3d/stage_stand.py bench $W w=1440 h=760 dsf=2 ps=0.15,0.5,0.85                  # цена кадра на ПК
$PY scripts/3d/stage_stand.py bench $W w=390 h=600 dsf=3 mobile                             # цена телефонного кадра
$PY scripts/3d/stage_smoke.py --shots --json ~/.cache/design-deep-dive/out/3d/stage-smoke.json   # gpu · reduced · soft
python3 -m http.server 8016 -d kb/3d/16-js-scenes/examples   # demo.html руками; demo.html?force3d — живые и на программном рендере
```

- Своя сцена проекта — рядом со своей копией `stand.html`: `stage_stand.py … --root DIR m=<имя> src=<файл>.js`.
- Своя страница — `stage_smoke.py --root DIR --page <файл>` с местами `#s-beats`, `#s-play`, `#s-glide`, `#s-world`.
- `--soft` — программный рендер SwiftShader: кадры годны, замеры — нет. Замок браузера утилиты берут сами.
