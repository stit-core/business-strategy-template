# 01 · Свой движок сцены на WebGL2: контракт, сборка, цвет и тон, чёткость бюджетом пикселей, кадр по изменению, ввод

Движок сцены — файл JavaScript без библиотек, который рисует одну сцену в `<canvas>` места на странице. Рантайм (`02`)
зовёт его методы по прокрутке и видимости, стенд — по параметрам адреса; ни тот, ни другой не знают, что у сцены внутри.
Нормы — из опыта проекта сайта-портрета (25 сцен, серия из 10 студийных моделей, рантайм и стенд; замеры на встроенной
графике Intel Iris Xe и решения заказчика по раундам правок) и из набора `examples/`. Как сцена живёт на странице — `02`,
малое 3D — `03`, длинная сцена-мир — `04`, где исполняется — `06`.

## Выжимка для агента

1. **Сцена — фабрика `(canvas, opts)`**: возвращает ручку, `{pending: true, destroy}` при асинхронной сборке или `null`
   без WebGL2; в `window` — только строка регистрации в `STAGE_SCENES`. `[проверено]` → §1
2. **Методы рантайма** — `setVisible`, `wake`, `scrub`, `setIdle`, `setPlaying`, `setTexture`, `destroy`; **методы
   стенда** — `setTime`, `setHover`, `tap`, `pulse`, `redraw`, `info`. Один файл сцены служит концепту и сайту: без
   `opts.variant` кадр стоит по центру, как на странице концепта. `[проверено]` → §1
3. **Сборка асинхронная**: шейдеры без проверки статуса, `KHR_parallel_shader_compile`, опрос раз в 40 мс; ручку «в
   сборке» рантайм снимает без ожидания. Готовность — 20–120 мс у одношейдерной сцены, 0,2–0,5 с с подготовкой полей
   расстояний и Canvas 2D. `[проверено]` → §2
4. **Ошибка шейдера и нет WebGL2 — статус и постер**: `onStatus('shader-error', журнал)`, `loseContext()`, в консоли
   страницы ни одной ошибки. `[проверено]` → §2
5. **Потеря контекста — постер сразу**: сцена себя не восстанавливает, её снимает рантайм и оживляет на свежем холсте при
   следующем подлёте, не больше одной попытки. `[проверено]` (повторная попытка — `[практика]`) → §3
6. **`destroy()` освобождает контекст сразу** (`WEBGL_lose_context.loseContext()`); холст снятого контекста не
   переиспользуется. `[проверено]` → §3
7. **Текстуры — до 4 слотов**, до прихода картинки — прозрачный тексель 1×1; мипы и анизотропия 4; маски знаков и букв
   — полями расстояний, а не мипами. `[проверено]`; фото в `SRGB8_ALPHA8`, данные в `RGBA8` — `[практика]` → §4
8. **Цвет считается в линейном**: hex → линейный в JS, литералом в GLSL; тон — Khronos PBR Neutral; выход — sRGB вручную.
   `[проверено]` → §5
9. **Фон, который стыкуется с секцией, — `preTone`**: обратная «пятка» Neutral, после тона фон попадает ровно в hex места
   (ΔE ≈ 0, шва нет). Без неё тёмный фон `#16181D` выходит почти чёрным. `[проверено]` → §5
10. **Дизеринг ±½ младшего разряда после sRGB**, шум зависит от t: полос в тёмных градиентах нет, кадр при заданном t
    одинаков. `[проверено]` → §5
11. **Чёткость — бюджетом пикселей, а не потолком DPR**: `dpr = max(0,5, min(экран, 2, √(бюджет / площадь CSS))) ·
    множитель`; бюджет холста 4,6 МП ПК и 1,9 МП телефон, тяжёлым сценам 3,2–3,4 и 1,2–1,6. `[проверено]` ПК, `[кейс]`
    телефон → §6.1
12. **Множитель плотности 0,7…1 с гистерезисом**: медиана 40 занятых кадров > 24 мс → ×0,85; < 12,5 мс → ÷0,85; после шага
    окно заново. Ниже 0,7 не снижать: «нечётко» заметнее, чем 50 кадров/с. `[проверено]` → §6.2
13. **Бюджет кадра**: эффект-накладка поверх страницы — ≤ 2 мс GPU; сцена-секция — одна живая: медиана интервала кадров
    ≤ 17 мс (60 кадров/с) на эталонной встроенной графике, цена кадра желательно ≤ 8–10 мс, чтобы помещались две живые;
    замер — `stage_stand.py perf` и `bench`. `[проверено]` → §6.3
14. **Порядок деградации**: множитель плотности → лишние проходы → петли → постер. `[практика]` → §6.4
15. **Кадр — только при изменении**: вне экрана и в скрытой вкладке 0 кадров; одна своя жизнь — ≈ 30 кадров/с; скраб
    помечает кадр «грязным» — не больше одной отрисовки за кадр. `[проверено]` студия, `[практика]` миры → §7
16. **Курсор — без касаний** (сглаживание τ 0,35–0,45 с), **касание — отпускание со сдвигом < 6 px**, не чаще раза в
    0,34 с; холст `touch-action: pan-y`; части сцены выбираются проекцией в CSS px, без чтения GPU. `[проверено]` → §8
17. **Кадр детерминирован по p, t, курсору и касанию**: план мира — генератор с постоянным зерном, движение — от `uTime`;
    постеры и кадры раскадровки снимает стенд, и они совпадают с живой сценой. `[проверено]` → §9
18. **Вес — 3–26 КБ min+gz на сцену** (набор: шаблон 4,8, мир 9,2, рантайм 4,4) против 174–293 КБ br у three и R3F.
    `[проверено]` → §10
19. **Три вида движков — один контракт**: «один шейдер», студийный SDF-движок с моделями-плагинами, многопроходный мир.
    `[проверено]` → §11, §12

## 1. Контракт

Регистрация — одна строка и единственная запись в `window`:

```js
(window.STAGE_SCENES = window.STAGE_SCENES || {})['<имя>'] = function (canvas, opts) {
  // getContext('webgl2'); нет контекста — onStatus('no-webgl') и return null
  // сборка программ (§2) → ручка, {pending: true, destroy} или null
};
```

Ручка — объект с методами; кто их зовёт:

| метод | кто зовёт | что делает |
|---|---|---|
| `setVisible(v)` | рантайм | `false` — цикл кадров стоит (сон за экраном), `true` — пуск цикла |
| `wake()` | рантайм | пуск цикла после возврата во вкладку (`visibilitychange`) |
| `scrub(p)` | рантайм | прогресс 0..1, уже сглаженный пружиной рантайма (`02` §4); сцена добавляет дотяг τ 0,12 с; при живом цикле — пометка «грязный кадр», без цикла — один кадр сразу |
| `setIdle(on)`, `setPlaying(on)`, `isPlaying()` | рантайм (кнопка паузы) | своя жизнь сцены — парение, импульсы, время — стоп и пуск |
| `setTexture(i, img, {data})` | рантайм | картинка в слот 0..3; `data: true` — маска или поле без sRGB-декодирования |
| `destroy()` | рантайм | снять слушатели, `ResizeObserver` и цикл, освободить цели кадра и контекст |
| `setTime(t)`, `setHover(x, y, on)`, `tap(x, y)`, `pulse(v)` | стенд | состояние кадра: время, курсор и точка касания в −1..1 от центра холста, фаза импульса касания |
| `redraw()` | стенд | кадр сразу, прогресс без дотяга |
| `info()` | стенд, рантайм | `{w, h, dpr, scale, draws, …}`: буфер, плотность, множитель, число отрисовок; мир добавляет `instances`, `hdr`, `beats` |

Опции фабрики:

| ключ | что |
|---|---|
| `mobile` | телефонная раскладка: своя композиция кадра, бюджет 1,9 МП |
| `rtl` | зеркальная композиция: сдвигаются кадр и тихие зоны, геометрия и текстуры не зеркалятся |
| `variant` | место на странице; без него — кадр по центру и без тихих зон, как на странице концепта |
| `background` | hex фона места → `preTone` (§5) |
| `palette` | hex палитры сцены; у шаблона — `{bg, haze, key, cool}`, по умолчанию нейтральная: графит, тёплый ключ, холодный отсвет |
| `layout` | `{shift: [x, y], quiet: [x0, x1, k], quietY: [низ, верх, k низа, k верха]}` — сдвиг объектива и тихие зоны (`03` §7, §8) |
| `driven`, `pin` | прогресс ведёт рантайм; окно сцены закреплено |
| `idle` | своя жизнь включена; стенд без `live` её выключает — время стоит |
| `maxDpr`, `pxMax` | потолок плотности (2) и бюджет пикселей холста (§6) |
| `preserve` | `preserveDrawingBuffer` — для снимка стенда |
| `onReady(h)` | асинхронная сборка: ручка или `null` (§2) |
| `onStatus(code, log)` | `ready`, `no-webgl`, `shader-error`, `context-lost` |
| `onFrame({w, h, anchors})` | якоря в CSS px холста — по ним HTML-подписи встают рядом с героем (`02` §13) |

Из `window` сцена только читает: `devicePixelRatio`, `innerWidth`, `innerHeight`, `matchMedia`, `performance`. Сборка
бандла сцен в проекте оборачивала каждую сцену в IIFE и падала на любой другой записи в `window` `[проверено]`: десятки
сцен живут на одной странице и на одном холсте, общее имя — конфликт. Проверка без бандлера `[практика]`:

```bash
grep -nP 'window\.(?!STAGE_SCENES\b|devicePixelRatio\b|innerWidth\b|innerHeight\b|matchMedia\b|performance\b)' scenes/*.js
```

## 2. Асинхронная сборка

Шейдеры компилируются и линкуются без проверки статуса: чтение `COMPILE_STATUS` или `LINK_STATUS` сразу после вызова
останавливает поток до конца компиляции. С расширением `KHR_parallel_shader_compile` и `opts.onReady` фабрика сразу
возвращает ручку «в сборке» и опрашивает `COMPLETION_STATUS_KHR`; по готовности проверяет `LINK_STATUS` и отдаёт в
`onReady` ручку или `null` `[проверено]`. Выдержка из `examples/scene-template.js`:

```js
var khr = gl.getExtension('KHR_parallel_shader_compile');
// … createShader, compileShader, attachShader, linkProgram — без проверки статуса
if (opts.onReady) {
  var off = false;
  var poll = function () {
    if (off) { return; }
    if (gl.isContextLost()) { opts.onReady(null); return; }
    if (khr && !gl.getProgramParameter(prog, khr.COMPLETION_STATUS_KHR)) { setTimeout(poll, 40); return; }
    var h = linked(); if (!h) { loseGl(); } opts.onReady(h);   // linked(): LINK_STATUS, журнал — в onStatus
  };
  setTimeout(poll, 0);
  return { pending: true, destroy: function () { off = true; loseGl(); } };
}
return linked();
```

- Многопроходная сцена ждёт все программы: опрос идёт, пока хоть одна не готова (`examples/world-template.js`).
- Ошибка — `onStatus('shader-error', журнал сборки)` и `loseContext()`; рантайм пишет одну строку `console.warn` и
  оставляет постер. Ошибок страницы нет `[проверено]`.
- Готовность от фабрики до `onReady` на Iris Xe: одношейдерные 20–120 мс; с подготовкой Canvas 2D и полей расстояний —
  225–511 мс; шаблон набора — 45 мс `[проверено]`. Подготовка (план мира, маски букв, поля) идёт до `onReady` и прячется
  за постером: холст проявляется поверх постера только готовым (`02` §2).
- Без расширения сборка синхронна на первом `getProgramParameter`: сцена та же, но длинная задача на главном потоке —
  повод держать сцену на одной-двух программах или собирать её в простое страницы (`06` §2) `[практика]`.
- Порядок — компилировать все шейдеры, потом линковать все программы, статус читать позже; точность — `precision highp
  float`: на мобильных GPU `mediump` бывает 16-битным, и в тёмных градиентах и полях расстояний это видно `[документация]`
  (MDN, WebGL best practices).

## 3. Потеря контекста и снятие

- **Потеря** (`webglcontextlost`): `preventDefault()`, `alive = false`, стоп цикла, `onStatus('context-lost')`. Сцена не
  пересоздаёт ресурсы по `webglcontextrestored`: её снимает рантайм, на месте остаётся постер `[проверено]`.
- **Повторная жизнь**: рантайм оживляет сцену при следующем подлёте не раньше чем через 3 с и не больше `retryLost = 1`
  раза; дальше место — постер насовсем (`failed`) `[практика]` (`02` §2.2).
- **Снятие** (`destroy()`): слушатели ввода, `ResizeObserver`, цикл, цели кадра (`freeRT()` у мира) и
  `WEBGL_lose_context.loseContext()` — контекст освобождается сразу, а не при сборке мусора `[проверено]`. Браузер держит
  ограниченное число живых контекстов WebGL (cd 05/03 §3.4), а сцены на странице создаются и снимаются по ходу прокрутки.
- **Свежий холст на каждую жизнь**: `getContext('webgl2')` у холста с потерянным контекстом возвращает тот же потерянный
  контекст. На странице сайта рантайм заменяет холст клоном, на холсте Claude Design разметка монтирует его заново
  (`06` §1) `[проверено]`.

```js
var lost = function (ev) { ev.preventDefault(); st.alive = false; if (st.raf) { cancelAnimationFrame(st.raf); st.raf = 0; } status('context-lost'); };
canvas.addEventListener('webglcontextlost', lost);
function destroy() {                                      // метод ручки: handle.destroy
  st.alive = false;
  if (st.raf) { cancelAnimationFrame(st.raf); st.raf = 0; }
  if (ro) { ro.disconnect(); }
  canvas.removeEventListener('webglcontextlost', lost);   // и слушатели ввода
  loseGl();                                               // WEBGL_lose_context.loseContext(): контекст освобождается сразу
}
```

Проверка — `canvas.getContext('webgl2').getExtension('WEBGL_lose_context').loseContext()` из консоли у живой сцены: на
месте постер, ошибок нет; на следующем подлёте сцена оживает один раз.

## 4. Текстуры

- **Слоты**: до 4; пока картинка не пришла, в слоте прозрачный тексель 1×1, признак прихода — `uTexOn`. Картинки места —
  атрибут `data-tex`; рантайм грузит их `Image` с `crossOrigin = 'anonymous'` и отдаёт в `setTexture` по `load` (`02` §1)
  `[проверено]`.
- **Загрузка**: `UNPACK_FLIP_Y_WEBGL = false`, `UNPACK_PREMULTIPLY_ALPHA_WEBGL = false`, `generateMipmap`,
  `LINEAR_MIPMAP_LINEAR`, анизотропия 4 при `EXT_texture_filter_anisotropic` `[проверено]`.
- **Формат**: фото — `SRGB8_ALPHA8`, выборка сразу отдаёт линейное значение и смешивается со светом сцены без ручного
  декодирования; маски, поля и данные — `RGBA8` (`setTexture(i, img, {data: true})`) `[практика]`.
- **Маски знаков и букв** — поля расстояний (EDT Фельценшвальба — Хуттенлохера, TinySDF): край острый на любом размере, без
  «плашек» грубых мипов у бинарной маски `[проверено]`. Поле строится один раз при сборке — это и есть подготовка
  0,2–0,5 с из §2.
- **Шрифт в Canvas 2D** — после `document.fonts.ready`, иначе маска собирается системным шрифтом; поле пересобирается,
  когда шрифт пришёл `[проверено]`. Контуры букв, вшитые в сцену, ожидания не требуют.

## 5. Цвет и тон

- **Расчёт — в линейном.** Палитра — hex в JS, перевод в линейный `hexLin` и литералом в GLSL; бренд подставляет свои hex
  через `opts.palette` `[проверено]`.
- **Тон — Khronos PBR Neutral** у студии и у HDR-миров: тёмное почти не трогает, светлое сжимает к белому без смены
  оттенка; пятка `x − 6,25x²` при min < 0,08, иначе −0,04; сжатие с 0,76, десатурация 0,15 `[проверено]`. Часть миров
  проекта брала мягкое плечо — линейно до 0,55, дальше экспонента — с выцветанием ярчайшего к белому `[кейс]`.
- **Выход — sRGB вручную** (кусочная функция, степень 1/2,4): холст по умолчанию считает свои значения sRGB и сам не
  кодирует `[проверено]`.
- **Фон места — `preTone`**: обратная функция пятки. Пятка давит тёмное: `#16181D` в линейном 0,008 после неё выходит
  0,0004 — rgb(1, 5, 15) вместо (22, 24, 29), шов с секцией и «чёрная дыра». `preTone` поднимает фон так, что после тона он
  попадает ровно в hex места; одна цепочка тона на весь кадр — шва нет `[проверено]` (расчёт и стыки мест проекта).
- **Страж оттенка** при сложении тёплого и холодного света: в сведении зелёный не ниже min(R, B), или полоса оттенков
  262–330° уводится к краям — сиреневому неоткуда взяться `[кейс]`.
- **Дизеринг** после sRGB: ±½ младшего разряда белым шумом, зависящим от t `[проверено]`.

```glsl
vec3 neutralTone(vec3 c){                         // Khronos PBR Neutral
  const float sc = 0.76; const float ds = 0.15;
  float x = min(c.r, min(c.g, c.b)); float off = x < 0.08 ? x - 6.25*x*x : 0.04; c -= off;
  float pk = max(c.r, max(c.g, c.b)); if (pk < sc) { return c; }
  const float d = 1.0 - sc; float np = 1.0 - d*d/(pk + d - sc); c *= np/pk;
  float g = 1.0 - 1.0/(ds*(pk - np) + 1.0); return mix(c, vec3(np), g);
}
vec3 oetf(vec3 c){ c = clamp(c, 0.0, 1.0); return mix(c*12.92, 1.055*pow(c, vec3(1.0/2.4)) - 0.055, step(vec3(0.0031308), c)); }
float hash(vec2 p){ p = fract(p*vec2(443.897, 441.423)); p += dot(p, p.yx + 19.19); return fract((p.x + p.y)*p.x); }
// конец main(): тон → sRGB → дизеринг; шум зависит от t, поэтому кадр при заданном t одинаков
// fragColor = vec4(oetf(neutralTone(col)) + (hash(gl_FragCoord.xy + fract(uTime)*17.0) - 0.5)/255.0, 1.0);
```

```js
function srgbToLin(c) { return c <= 0.04045 ? c / 12.92 : Math.pow((c + 0.055) / 1.055, 2.4); }
function hexLin(h) {
  var n = parseInt(String(h).replace('#', ''), 16);
  return [srgbToLin(((n >> 16) & 255) / 255), srgbToLin(((n >> 8) & 255) / 255), srgbToLin((n & 255) / 255)];
}
function preTone(h) {                             // обратная пятка Neutral: после тона фон = hex места
  var c = hexLin(h), m = Math.min(c[0], c[1], c[2]), off = 0.04;
  if (m < 0.04) { var x = Math.sqrt(m / 6.25); off = x - m; }
  return [c[0] + off, c[1] + off, c[2] + off];
}
```

`preTone` точна, пока фон после пятки ниже начала сжатия (пик < 0,76) — тёмные и средние фоны. Светлый фон места — открытый
вопрос (§ Открытые вопросы).

## 6. Чёткость и бюджет кадра

### 6.1. Бюджет пикселей

```
dpr = max(0,5, min(devicePixelRatio, maxDpr = 2, √(pxMax / (cssW · cssH)))) · scale
pxMax: 4,6 МП ПК, 1,9 МП телефон; тяжёлым сценам — 3,2–3,4 МП ПК и 1,2–1,6 МП телефон
```

### 6.2. Множитель плотности

- **Окно** — 40 интервалов занятых кадров (прогресс, ввод, импульс); медиана (`[20]`) > 24 мс → ×0,85, но не ниже 0,7;
  медиана < 12,5 мс → ÷0,85 до 1; после любого шага окно очищается — между 12,5 и 24 мс множитель стоит (гистерезис).
  Ниже 0,7 не снижать: «нечётко» заметнее, чем 50 кадров/с `[проверено]`.
- **Что в окно не идёт**: прореженные кадры своей жизни (≈ 31 мс) и кадры перетаскивания — они читались бы как медленные
  `[проверено]`.
- **Студии — тот же приём**: darkroom `satus` — DPR шагами −0,25 при < 40 кадрах/с, не ниже 1, после трёх смен
  направления — фиксация `[исходник]`.
- **Потолок частоты — не тяжёлая сцена**: GPU-таймеров на телефонах нет, множитель смотрит на интервалы кадров, а ровные
  33,3 мс бывают потолком частоты — энергосбережение iOS держит 30 кадров/с. По такому ритму плотность снижается зря; в
  наборе различения нет (§ Открытые вопросы) `[практика]`.

```js
function adapt(dt) {                               // examples/scene-template.js: только на занятых кадрах
  if (st.frames.length >= 40) { st.frames.shift(); } st.frames.push(dt);
  if (st.frames.length < 40) { return; }
  var md = st.frames.slice().sort(function (a, b) { return a - b; })[20];
  if (md > 0.024 && st.scale > 0.7) { st.scale = Math.max(0.7, st.scale * 0.85); st.frames = []; }
  else if (md < 0.0125 && st.scale < 1) { st.scale = Math.min(1, st.scale / 0.85); st.frames = []; }
}
```

### 6.4. Порядок деградации

1. Множитель плотности — до 0,7 (§6.2).
2. Лишние проходы — тени 2048 → 1536, ступени свечения, второй уровень мира.
3. Петли — своя жизнь сцены (парение, импульсы) останавливается; прогресс по прокрутке и отклик остаются.
4. Постер.

- Порядок — `[практика]`: множитель держит чёткость, пока сцена живая; постер — последний шаг. Reduce и программный рендер
  дают постер и раскадровку сразу, без шагов (`02` §11).
- Студии идут тем же путём: глобус GitHub — 4 ступени: DPR 2 → 1,5, реже лучи указателя, геометрия до ≈ 65 % `[кейс]`.

## 7. Кадр только при изменении

- `running = alive && visible && !document.hidden`; иначе кадр не планируется — 0 кадров `[проверено]`.
- **Занят** (`settling`): прогресс догоняет цель, курсор или присутствие догоняют указатель, гаснет импульс касания, есть
  «грязный» кадр — полный темп. **Своя жизнь** (`ambient`: `idle` и не на паузе) без занятости — ≈ 30 кадров/с: кадр
  пропускается, если с прошлого прошло меньше 31 мс. **Ничего** — цикл стоит `[проверено]` студия, `[практика]` миры.
- `scrub` при живом цикле только ставит `dirty`; без цикла — один кадр сразу: сцена рисуется не чаще раза за кадр, как бы
  часто её ни звал рантайм `[проверено]`.
- `dt` ограничен 0,05 с: после паузы и скрытой вкладки движение не прыгает `[практика]`.
- **Пробуждение и сон у студий** — тот же приём: короткую анимацию дорисовывает окно пробуждения (`wake(2000)` у darkroom
  `satus`), пружина сообщает остановку — по ней цикл засыпает (`damp` из пакета `maath` возвращает `false`) `[исходник]`;
  второстепенный слой живёт реже основного — бегущая текстура 12 кадров/с при 60 у сцены (Active Theory) `[кейс]`.
- В покое сцена не рисует вовсе — вызовов 0 и в обычном режиме, и в reduce (ворота `reduce_dc` и `dc`,
  `../09-web-runtime/page-3d-gates.yaml`).

```js
function running() { return st.alive && st.visible && !document.hidden; }
function ambient() { return st.idle && !st.userPaused; }                                  // своя жизнь сцены
function step(now) {
  st.raf = 0;
  if (!running()) { st.last = 0; return; }                                                // вне экрана — 0 кадров
  var busy = settling();                                                                  // прогресс, ввод, импульс, dirty
  if (!busy && !ambient()) { st.last = 0; st.frames = []; return; }                       // покой — цикл стоит
  if (!busy && st.last && now - st.last < 31) { st.raf = requestAnimationFrame(step); return; }   // своя жизнь ≈ 30 к/с
  var dt = st.last ? Math.min(0.05, (now - st.last) / 1000) : 1 / 60; st.last = now;
  if (busy) { adapt(dt); }                                                                // множитель плотности (§6)
  if (ambient()) { st.time += dt; }
  st.p += (st.pT - st.p) * (1 - Math.exp(-dt / 0.12));                                     // дотяг прогресса τ 0,12 с
  draw(); st.dirty = false;
  st.raf = requestAnimationFrame(step);
}
function kick() { if (!st.raf && running()) { st.last = 0; st.raf = requestAnimationFrame(step); } }
function change() { if (st.raf) { st.dirty = true; } else { draw(); kick(); } }               // одна отрисовка на изменение
```

Проекция точки мира в CSS px — общая для выбора частей и для якорей HTML-подписей `[проверено]`:

```js
// M — матрица вида-проекции (по столбцам), p — точка мира; f = 1 / tan(fov / 2)
function toCss(M, p, cssW, cssH) {
  var x = M[0] * p[0] + M[4] * p[1] + M[8] * p[2] + M[12], y = M[1] * p[0] + M[5] * p[1] + M[9] * p[2] + M[13];
  var w = M[3] * p[0] + M[7] * p[1] + M[11] * p[2] + M[15];
  if (w <= 0) { return null; }                                     // за камерой
  return { x: (x / w * 0.5 + 0.5) * cssW, y: (0.5 - y / w * 0.5) * cssH, depth: w };
}
function pick(M, parts, px, py, cssW, cssH, f) {                   // parts: [{c: [x, y, z], r}]
  var best = -1, bestDepth = Infinity;
  parts.forEach(function (part, i) {
    var s = toCss(M, part.c, cssW, cssH); if (!s) { return; }
    var rad = part.r * f / s.depth * cssH * 0.5;                   // экранный радиус части
    if (Math.hypot(px - s.x, py - s.y) <= rad && s.depth < bestDepth) { best = i; bestDepth = s.depth; }
  });
  return best;
}
```

## 12. Студийный SDF-движок и модели-плагины

### 12.1. SDF в ограничивающем объёме

- **SDF-объект рисуется в полном разрешении внутри ограничивающего объёма**: луч пересекается с коробкой модели
  `BMIN..BMAX`, марш идёт только внутри — ≤ 140 шагов, шаг 0,92·d, попадание при d < 0,00022·t; минимум d/(t·px)
  запоминается, и промах ближе 1,25 px смешивается с фоном — край без лесенки при DPR ≤ 2 под бюджетом пикселей (§6.1)
  `[проверено]`.
- **Студия вокруг** — отражение на полу маршем ≤ 64 шагов, мягкая тень ≤ 28–32 шагов, контактная тень AO 4 пробы
  `[проверено]`.
- **Цена**: 4,7–13 мс при 3,7 МП, 1,3–3,2 мс при 0,56 МП на Iris Xe `[проверено]`.
- **Полноэкранный SDF без ограничивающего объёма** (рельеф во всю сцену, метаболы) — 12–14 мс при 4,6 МП: ему ½ разрешения
  или фон без мелкой детали `[проверено]`. Форма поля и нормаль — `03` §2.

```glsl
// коробка модели и марш внутри неё; uPx — угловой размер пикселя: 2·tan(fov/2) / высота буфера
vec2 boxHit(vec3 ro, vec3 rd, vec3 bmin, vec3 bmax){
  vec3 inv = 1.0/rd, t0 = (bmin - ro)*inv, t1 = (bmax - ro)*inv;
  vec3 tn = min(t0, t1), tf = max(t0, t1);
  return vec2(max(max(tn.x, tn.y), max(tn.z, 0.0)), min(min(tf.x, tf.y), tf.z));
}
vec3 marchBox(vec3 ro, vec3 rd){                  // x — t, y — покрытие пикселя формой, z — 1 при попадании
  vec2 b = boxHit(ro, rd, BMIN, BMAX);
  if (b.x > b.y) { return vec3(-1.0, 0.0, 0.0); }
  float t = b.x, best = 1e9, tb = b.x;
  for (int i = 0; i < 140; i++){
    float d = map(ro + rd*t), k = d/(max(t, 1e-3)*uPx);        // расстояние до формы в пикселях
    if (k < best) { best = k; tb = t; }
    if (d < 0.00022*t) { return vec3(t, 1.0, 1.0); }
    t += 0.92*d;
    if (t > b.y) { break; }
  }
  return vec3(tb, 1.0 - smoothstep(0.0, 1.25, best), 0.0);    // промах ближе 1,25 px — частичное покрытие края
}
// в main(): vec3 h = marchBox(ro, rd); if (h.y > 0.0) { col = mix(col, shade(ro + rd*h.x, rd), h.y); }
```

### 12.2. Кадр студии

Кадр — один фрагментный шейдер `[проверено]`:

1. Луч камеры → пол или фон. **Пол**: отражение модели облегчённым маршем ≤ 64 шагов, контактная тень AO 4 пробы, мягкая
   тень ключа ≤ 28 шагов, тёплая полоса света. **Фон**: пятно студии, привязанное к модели, тёплый отсвет со стороны ключа.
2. `mix(фон места, кадр, edgeK())` — края кадра гаснут в фон места: 0,24 высоты по бокам, 0,17 сверху и снизу (`03` §6).
3. Модель — марш в коробке (§12.1).
4. Цвет точки (`matAt`: стекло или свой материал) → своё свечение модели → Neutral → sRGB → дизеринг.
5. Окружение — три мягких софтбокса в гномонической проекции и градиент; студия поворачивается к курсору (`03` §3).

### 12.3. Модель — плагин ядра

Одна запись в реестре моделей ядра (одна строка в `window` на реестр, как у сцен) и объект частей. Ядро держит студию,
камеру, цикл, ввод, парение и тон; модель — форму, материал и свою жизнь `[проверено]`:

| часть | что |
|---|---|
| GLSL | `map(p)` — поле формы; `mapIn(p)` — для внутреннего прохода стекла; `matAt(p)` — материал точки; `glassBody`, `innerGlow`, `decal` — печать и гравировка с ящичным фильтром по следу пикселя; `extraGlow`, `shadeOther` |
| константы | `BMIN/BMAX` — коробка в осях модели по всем её состояниям; параметры отражения, AO, тени, полосы света, ширина ободка; гашение краёв полосой у широких сцен |
| JS: кадр и поза | `frame` — центр кадра, размер, угол и дальность камеры; `pose(st)` → `{R, O}`; `restPose` |
| JS: жизнь | `step(st, dt)`; `window(kind)` — окна автодвижения (появление 18 с, пробуждение 9–11 с); `start`, `finish`, `busy` |
| JS: ввод и прокрутка | `scrub`, `seek`, `tap`, `release`, `trigger`, `pause` |
| JS: страница | `uniforms(gl, loc, st, tex)`, `textures`, `anchors()` — точки для HTML-подписей, `idle` — `{bob, sway, tilt, hoverYaw, hoverTilt}` |

- **Парение — в ядре, одно для всех моделей сайта**: подъём 1,2 % размера сцены (сумма синусов 11,3 и 17,9 с), рыскание
  3,5° (14,7 и 23,3 с), наклон 1,2° (12,1 с); к курсору — 10° и 5° `[проверено]` (`03` §4).
- **Цена**: 4,7–13 мс при 3,7 МП, 1,3–3,2 мс при 0,56 МП; ядро 8,8 КБ + модель 2,4–9,5 КБ min+gz `[проверено]`.
- В набор ядро не входит: модель собирается на `examples/scene-template.js` по рецепту `03` §11, серия — по этому разделу
  `[практика]`.

## Частые ошибки

- **Потолок DPR вместо бюджета пикселей** (1,5 на телефоне, 1 у «фона» с мелкой деталью) — отзыв «нечётко» `[проверено]`.
- **Множитель только вниз, с полом 0,55** — сцена мылится навсегда после одной тяжёлой секунды `[проверено]`.
- **Прореженные кадры своей жизни в окне множителя** — интервалы 31 мс читаются как медленный кадр, плотность падает зря.
- **Кадр каждый rAF в покое и по нескольку отрисовок за кадр от скраба** — батарея и чужие кадры прокрутки (§7).
- **Фон места через тон без `preTone`** — тёмный фон уходит в чёрный, шов с секцией (§5).
- **Нет OETF или двойное кодирование** (sRGB-текстура плюс ручное декодирование) — кадр темнее и насыщеннее hex.
- **Запись в `window` сверх регистрации** — сцены одного холста перетирают друг другу имена.
- **Холст после `loseContext()` в работе** — `getContext` вернёт потерянный контекст, сцена молча не рисует.
- **`LINK_STATUS` сразу после `linkProgram`** — параллельная компиляция теряется, длинная задача на главном потоке.
- **Бинарная маска знака мипами** — «плашки» по краю на малом размере; маска — полем расстояний (§4).
- **Касание как наведение** — подсветка «залипает» на телефоне; курсор — только `pointerType !== 'touch'`.
- **`touch-action: none` на холсте** — страницу не пролистать пальцем над сценой.
- **`Math.random()` в плане мира** — постер и раскадровка не совпадают с живой сценой.
- **Абсолютные мс из разных прогонов на общей машине** — сравнивать только внутри одного прогона (§9).

## Открытые вопросы и противоречия

- **SDF и DPR.** 09/04 (выжимка п.7, §2.5, §10, «Частые ошибки», чек-лист) и `../12-recipes/11-shader-background.md`
  (п.3) требуют «фон ≤ 1, объект ≤ 1,5, SDF — ½ разрешения». Правило выведено на полноэкранных метаболах без
  ограничивающего объёма (1,07 против 7,04 мс при 1440×900 DPR 1). Норма этой папки: SDF-объект в коробке — в полном
  разрешении при DPR ≤ 2 под бюджетом пикселей (4,7–13 мс при 3,7 МП) со сглаживанием края по минимуму d/(t·px);
  ½ разрешения — полноэкранному SDF без объёма и размытому фону; фон с деталью в 1–2 px (точки, линии, решётки) — DPR как
  у объекта.
- **Регулятор качества.** 09/05 (выжимка п.13, §2.3 `createQualityGovernor`: maxDpr 1,5, minDpr 1, ×0,8 при 20 мс,
  только вниз) и 14/09 (выжимка п.1, §1: DPR ≤ 1,5 десктоп и ≤ 1,25 телефон) ограничивают DPR. Норма этой папки — бюджет
  пикселей и множитель 0,7…1 в обе стороны с гистерезисом 24 / 12,5 мс (§6); уровни качества — по бюджету пикселей и
  составу проходов, а не по DPR.
- **Ворота DPR.** `../09-web-runtime/page-3d-gates.yaml` (ключ `dpr`: телефон 1,5, десктоп 2) режет чёткую сцену
  телефона. Норма этой папки — ворота по пикселям холста: ≤ 1,9 МП телефон, ≤ 4,6 МП ПК и DPR ≤ 2.
- **Бюджет на эффект и бюджет сцены.** 09/04 §10: «≤ 2 мс GPU на эффект на Iris Xe при 1440×900». Сцена-мир и модель
  в полосе — не эффект поверх страницы, а вся секция: 3–14 мс при 4,4–4,6 МП. Норма этой папки — §6.3: эффект-накладка
  ≤ 2 мс, сцена-секция — по ритму и цене кадра; порядок деградации — §6.4 (у creative 05/03 §4.3 — «без петель» первым
  шагом).
- **Потеря контекста.** 09/05 (выжимка п.23, §6.2) пересоздаёт ресурсы по `webglcontextrestored`. Норма этой папки —
  постер сразу, оживление рантаймом на свежем холсте при следующем подлёте, одна попытка (§3).
- **Фон кадра к странице.** 14/02 (выжимка п.5, чек-лист) держит ΔE ≤ 3 у three с экспозицией; свой движок без экспозиции
  даёт ΔE ≈ 0 — норма этой папки строже, приём `preTone` тот же.
- **Светлый фон места.** `preTone` обращает только пятку Neutral; для фона с пиком после пятки ≥ 0,76 нужно обратное плечо
  или фон вне тона `[не проверено]`.
- **Телефон.** Бюджет 1,9 МП, множитель и цена кадра телефона — `[кейс]`: телефонный кадр мерился на десктопном GPU;
  нагрев и заполнение реального телефона не проверены.
- **`SRGB8_ALPHA8` для фото** — приём набора без замера на проекте `[практика]`: сверка с декодированием sRGB в шейдере
  (цвет фото на стыке со светом сцены) не делалась.
- **Ритм 30 кадров/с.** Множитель набора не отличает тяжёлый кадр от потолка частоты (энергосбережение iOS, 30 кадров/с):
  нужен признак «интервалы ровно кратны 16,7 мс» или пауза снижения на таком ритме `[не проверено]`.
- **Точный буфер при дробном DPR экрана.** Когда бюджет не ограничивает плотность, точный размер буфера в физических пикселях
  даёт `ResizeObserver` с `box: 'device-pixel-content-box'` (`devicePixelContentBoxSize`); набор округляет `cssW · dpr` —
  на экранах 125 % и 150 % возможна лёгкая мыльность пересэмплинга `[не проверено]`.
- **«0 кадров в покое».** 14/07 §1: кадров в покое — 0. Норма этой папки: сцена без своей жизни — 0 кадров; со своей
  жизнью (парение, импульсы) — ≈ 30 кадров/с на экране, это петля с паузой (`02` §12); вне экрана, в скрытой вкладке и в
  reduce — 0.
