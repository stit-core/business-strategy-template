# 02 · Рантайм сцен на странице: место, режимы прокрутки, пружина, предел живых сцен, постер и раскадровка

Рантайм — один скрипт страницы без библиотек (`examples/stage-runtime.js`, 4,4 КБ min+gz): находит места со сценами по
атрибутам разметки, считает прогресс прокрутки, оживляет и усыпляет сцены, держит постер, раскадровку, паузу и подписи
тактов. Прокрутку он не перехватывает. Сцена внутри места — движок по контракту `01`. Нормы — опыт проекта сайта-портрета
(10 сцен на местах макета, решения заказчика в Play) и набор `examples/`.

Слова раздела: **место** — секция страницы со сценой; **окно** — видимая часть места высотой H; **точка покоя** — значение
прогресса, на котором сцена стоит; **такт** — переход к следующей точке покоя по шагу прокрутки; **заставка** — точка
покоя 0; **поле** — длина прокрутки закреплённого места.

## Выжимка для агента

1. **Место — разметка с атрибутами, облик — CSS страницы**: `section[data-stage][data-mode]…`, внутри — окно, постер,
   холст, подписи, кнопки, шаги, раскадровка. `[проверено]` → §1
2. **Жизнь места**: постер → сборка → живая сцена → постер; ошибка — одна строка `console.warn` и постер навсегда. Холст
   проявляется поверх постера за 800 мс. `[проверено]` → §2
3. **Четыре режима**: `scrub` — прогресс = прокрутка; `beats` — шаги с доигрышем; `glide` — путь с инерцией; `play` —
   сама играет. «На каждой секции своя логика прокрутки» — решение заказчика. `[проверено]` → §3
4. **Прогресс ведёт критически демпфированная пружина** с точным решением за шаг: без рывка и без перелёта; 95 % пути — за
   4,74/ω с. Скраб ω 6,5 (0,73 с). `[проверено]` → §4
5. **Шаги с доигрышем** (`beats`): текст карточками идёт обычной прокруткой, такт — последняя карточка за линией 60 % окна,
   сцена доигрывает его сама пружиной ω 2,4–3,6 (1,3–2,0 с); шаг 480 px ПК, 420 телефон — 3–4 щелчка колеса.
   `[проверено]` → §5
6. **Поле шагов** = заставка 0,78 H + 480 px на такт + хвост 0,45 H + выход 0,45 H; 5–7 точек покоя — 3,2–4,2 тыс. px.
   `[проверено]` → §5
7. **Путь с инерцией** (`glide`, ω 2, хвост 2,4 с) — только карта и маршрут `[кейс]`; **сама играет** (`play`) — полоса без
   закрепления, старт при ≥ 40 % видимости, один раз, 9–10 с, финал держится, пауза обязательна `[проверено]` → §6
8. **Выход закреплённой сцены**: последние ≈ 8 % прогресса — спокойный кадр, хвост 0,45 H, окно гаснет в фон места на
   последних 0,45 H и только потом уезжает. `[проверено]` → §7
9. **Живых сцен ≤ 2 на ПК и 1 на телефоне**: оживление на подлёте ≤ 0,5 высоты окна, сон за экраном, уничтожение дальше
   1,5 высоты, свежий холст на каждую жизнь. `[проверено]` → §8
10. **Постер — всегда в разметке под холстом**: кадр покоя той же камеры, снятый стендом; у `play` — ещё кадр финала.
    `[проверено]` → §9
11. **Раскадровка вместо закрепления** — в обзоре холста, при «уменьшить движение» и на программном рендере: кадры точек
    покоя с подписями, ни одного контекста WebGL. `[проверено]` → §9–11
12. **У каждой живой сцены — пауза** (останавливает и свою жизнь); у закреплённой — «Пропустить» и рельс тактов на ПК.
    `[проверено]` → §12
13. **Весь текст — HTML поверх холста**: подписи тактов стоят в окне и сменяются своим входом, у каждой сцены свой стиль;
    текст — смысл и факт места, а не описание эффекта. `[проверено]` → §13
14. **Между двумя сценами — статичный блок**; длинная главная — все сцены главами с оглавлением, страница раздела повторяет
    свою сцену. `[проверено]` → §14
15. **Телефон**: одна живая сцена, шапка 64 px, шаг 420 px, портретная композиция, без рельса, раскадровка в 2 колонки.
    `[кейс]` → §15
16. **Проверка** — `stage_smoke.py` (такты по одному колесом, живых ≤ 2, reduce и программный рендер — только раскадровка)
    и стенд `stage_stand.py`. `[проверено]` → §16

## 1. Подключение и разметка места

```html
<script src="scenes/<имя>.js"></script>          <!-- регистрирует window.STAGE_SCENES['<имя>'] -->
<script src="stage-runtime.js"></script>
<script>new StageRuntime(window.STAGE_SCENES, { header: 72, headerPhone: 64 }).mount(document);</script>
```

Атрибуты места читает рантайм; облик — CSS страницы (образец — `examples/demo.html`):

| атрибут | что |
|---|---|
| `data-stage="<имя>"` | сцена из `STAGE_SCENES` |
| `data-mode` | `scrub` · `beats` · `glide` · `play` (§3) |
| `data-beats="0,0.25,…,1"` | точки покоя тактов (`beats`) |
| `data-tempo` | ω пружины: `beats` 2,4–3,6 (по умолчанию 3), `glide` 2, `scrub` 6,5 |
| `data-pin`, `data-exit` | поле закрепления и длина выхода, px (`glide`, закреплённый `scrub`) |
| `data-dur` | длительность `play`, с (по умолчанию 9) |
| `data-range="a,b"` | отрезок прокрутки полосы, который становится прогрессом 0..1 (`scrub`) |
| `data-variant`, `data-bg`, `data-tex`, `data-rtl` | место для сцены (`opts.variant`), hex фона, картинки слотов, зеркальная композиция |

Внутри места: `[data-window]` — окно; `[data-poster]` — постер `<img>`; `[data-canvas]` —
`<canvas hidden aria-hidden="true">`; скрытый абзац с описанием сцены; `[data-caps] > [data-cap][data-k]` с полоской
`[data-fill]` — подписи тактов; `[data-from][data-to]` — надписи на отрезках прогресса; `[data-rail] > [data-dot]` — рельс;
`[data-skip]`, `[data-pause]` — кнопки; `[data-veil]` — затемнение выхода; `[data-steps] > [data-beat]` — блоки шагов;
`[data-story]` — раскадровка. Состояния: `[data-live]` — сцена ожила; `[data-stage-story]` — раскадровка вместо
закрепления; `[data-on]` — подпись или надпись видна; `--fill` — доля пути до следующего такта; `aria-current="step"` у
текущей точки рельса; `aria-pressed` у паузы. Опции рантайма — `examples/README.md`.

## 2. Жизненный цикл места

`poster → loading → live → poster`; `failed` — навсегда постер `[проверено]`.

### 2.1. Оживление и снятие

- **Оживление** (`start`): опции места → фабрика сцены; `{pending}` — ждём `onReady`; ручка готова — картинки слотов,
  начальный прогресс, `data-live` на месте, холст проявляется поверх постера (прозрачность 0 → 1 за 800 мс, CSS)
  `[проверено]`.
- **Снятие** (`drop`): `destroy()` ручки и сборки, холст заменяется свежим клоном (`01` §3), пауза скрывается
  `[проверено]`.

### 2.2. Потеря контекста и ошибка сцены

- **Ошибка сцены** (нет сцены, нет WebGL2, шейдер не собрался): одна строка `console.warn` и постер насовсем (`failed`);
  ошибок страницы нет `[проверено]`.
- **Потеря контекста**: сцена сообщает `context-lost` (`01` §3) — рантайм снимает её, на месте сразу постер. Повторная
  жизнь — при следующем подлёте, не раньше чем через 3 с, на свежем холсте; после второй потери (`retryLost` = 1) — постер
  насовсем. Восстановления по `webglcontextrestored` нет: `getContext` у холста с потерянным контекстом возвращает тот же
  потерянный контекст, свежий холст надёжнее `[проверено]` (повторная попытка — `[практика]`).
- **Проверка**: `WEBGL_lose_context.loseContext()` из консоли у живой сцены — постер, ошибок нет; на следующем подлёте сцена
  оживает один раз; вторая потеря — постер насовсем.

```js
// examples/stage-runtime.js: потеря контекста — постер сразу, одна повторная жизнь через ≥ 3 с, дальше — постер насовсем
function lose(rt, s) {
  rt.drop(s); s.lost += 1; s.cool = performance.now() + 3000;    // reconcile не оживит место раньше s.cool
  if (s.lost > rt.o.retryLost) { s.failed = true; }
}
```

## 3. Режимы прокрутки

| режим | прогресс | как ведёт сцену | параметры | где | метка |
|---|---|---|---|---|---|
| `scrub` | доля прохода полосы через окно `(vh − top) / (vh + h)` или доля поля закрепления | пружина ω 6,5 — 95 % за 0,73 с | `range`, `pin`, `exit` | серия моделей, страницы концептов | `[проверено]` |
| `beats` — шаги с доигрышем | такт: последняя карточка `[data-beat]`, чей центр прошёл линию 60 % высоты окна | цель — точка покоя такта, сцена доигрывает её пружиной ω `tempo` | `beats`, `tempo` 2,4–3,6 | длинные сцены-миры, листание, туннель карточек, зал витрин, зум | `[проверено]` |
| `glide` — путь с инерцией | доля прокрутки поля `pin` | мягкая пружина ω 2 с длинным хвостом | `pin`, `exit`, `tempo` 2 | маршрут по карте | `[кейс]` |
| `play` — сама играет | время: старт при видимости ≥ 40 % полосы, один раз за просмотр | `0,5 − 0,5·cos(π·t / dur)`, финал держится | `dur` 9–10 с | короткая история-полоса: форма из капель, рост сети, созвездие | `[проверено]` |

Слушатель `scroll` один — на `document`, `passive` и `capture` (ловит и прокрутку внутренних окон, так живёт холст Claude
Design); пачка событий — один кадр рантайма `[проверено]`. Скорость и направление прокрутки рантайм не меняет: колесо,
клавиши, якоря и поиск по странице работают как обычно (creative 05/01 §6.2).

## 4. Пружина

Критически демпфированная, точное решение за шаг `dt` — устойчива на любой частоте экрана `[проверено]`:

```js
function spring(x, v, target, w, dt) {           // examples/stage-runtime.js: [x, v] через dt секунд
  var d = x - target, e = Math.exp(-w * dt), c = v + w * d;
  return [target + (d + c * dt) * e, (v - w * c * dt) * e];
}
```

- Стоп, когда |x − цель| < 4·10⁻⁴ и |v| < 1,6·10⁻³; рантайм зовёт `scrub` сцены, только когда значение изменилось.
- Без рывка в начале и без перелёта: быстрый жест, проскочивший несколько тактов, доводит сцену до последнего такта одним
  движением; шаги колеса по 120 px сливаются в одно движение.
- 95 % пути — за 4,74/ω с:

| ω | 6,5 | 3,6 | 3,2 | 3 | 2,8 | 2,6 | 2,4 | 2 |
|---|---|---|---|---|---|---|---|---|
| 95 % пути, с | 0,73 | 1,32 | 1,48 | 1,58 | 1,69 | 1,82 | 1,98 | 2,37 |

- Сцена добавляет свой дотяг τ 0,12 с (`01` §7). Пружина с отскоком для прогресса прокрутки запрещена.
- Основание: движение по колесу без пружины заказчик назвал «резко, неплавно» `[проверено]`.

## 5. Шаги с доигрышем (`beats`)

- **Текст — карточками обычной прокруткой** поверх закреплённого окна; сцена не едет за пальцем, а доигрывает такт до точки
  покоя сама. «Один раз крутнул — произвело действие, а не втупую прокрут» — слово заказчика, режим — ответ на него
  `[проверено]`.
- **Такт** — последний блок `[data-beat]`, чей центр прошёл линию 60 % высоты окна; цель — его точка покоя из
  `data-beats`; доигрыш — пружиной ω 2,4–3,6, то есть 1,3–2,0 с `[проверено]`.
- **Шаг** — 480 px на ПК, 420 px на телефоне: такт включается через 3–4 щелчка колеса, карточка следующего такта видна снизу
  сразу `[проверено]`.
- **Поле** — сумма блоков шагов: заставка 0,78 H (телефон 0,7 H) с заголовком и подсказкой «Листайте — сцена идёт по
  шагам» → блок 480 px на каждый такт → у последнего такта ещё хвост 0,45 H (телефон 0,5 H) и выход 0,45 H. У
  `[data-steps]` — `margin-top: −H`: блоки идут поверх окна. Окно 760 px: 4 точки покоя — 2,7 тыс. px, 5 — 3,2, 7 — 4,2
  (≈ 355–460vh при окне 900 px) `[проверено]`.
- **Точек покоя 5–7**: заставка → 3–5 событий → финал; одна необязательная точка делит длинный переход пополам (`04` §6)
  `[проверено]`.
- **Затемнение под заставкой** — градиент 0,72 → 0 к 56 % ширины под заголовком; гаснет к p = 0,45 × точка первого такта
  `[практика]`.
- **Рельс, «Пропустить» и пауза** — §12; прокрутка не перехватывается.

## 6. Путь с инерцией, сама играет, скраб

- **`glide`** — прогресс = доля прокрутки поля `pin`, пружина ω 2 (95 % за 2,4 с); надписи — на отрезках прогресса
  (`data-from`, `data-to`); поле — `pin + exit` px (у проекта 3 400 + 342). Хвост длиннее секунды держит маршрут «на
  инерции» — только карта и маршрут `[кейс]`.
- **`play`** — полоса без закрепления (высота 480–760 px ПК, 360–560 телефон); старт, когда видно ≥ 40 % полосы, один раз
  за просмотр; ход `0,5 − 0,5·cos(π·t / dur)` за 9–10 с; финал держится; пауза сдвигает время проигрыша на свою длину.
  Движение дольше 5 с рядом с контентом — пауза обязательна (WCAG 2.2.2, 09/05 выжимка п.16) `[проверено]`.
- **`scrub`** — прогресс = доля прохода полосы через окно или поля закрепления; пружина ω 6,5; `data-range` берёт отрезок
  прохода (например, `0.1,0.9`) `[проверено]`.

## 7. Закрепление и выход

- **Окно** — `position: sticky` под шапкой (72 px ПК, 64 px телефон), высота H: 760 px ПК, 600 px телефон `[проверено]`.
- **Прогресс закреплённой сцены** — `(шапка − r.top) / (r.height − H − exit)`; `exit` вычитается только у `glide`.
- **Конец сцены**: последние ≈ 8 % прогресса — спокойный кадр (ключи камеры на 0,92 и 1 совпадают, `04` §4); хвост
  последнего такта 0,45 H; затем окно гаснет в фон места на последних 0,45 H — прозрачность `xo²·0,94` у `[data-veil]` —
  и только потом уезжает. Основание — слово заказчика «доскроллил до конца — и сразу вниз уходят… не очень комфортно»
  `[проверено]`.

```js
// выход (examples/stage-runtime.js, frame): xo — доля пройденного выхода, окно гаснет в фон места до открепления
var xo = live ? clamp01(1 - (r.bottom - (top + H)) / c.exit) : 0;
s.exitEl.style.opacity = (xo * xo * 0.94).toFixed(3);
```

## 8. Сколько сцен живёт

- **Предел**: живых не больше 2 на ПК и 1 на телефоне (`maxLive`, `maxLivePhone`) `[проверено]`; совпадает с пределом
  контекстов уровня L2 (`../../creative/01-creative-direction/ambition-levels.yaml`, `budgets.effects.webgl_contexts`).
- **Кандидаты**: места на постере, не `failed`, после остывания потери контекста, ближе 0,5 высоты окна к окну; порядок —
  по дистанции, затем по удалённости центра места от центра окна.
- **Вытеснение**: при полном пределе снимается самая далёкая живая — дальше кандидата или на той же дистанции, но дальше
  от центра больше чем на 80 px.
- **Сон и уничтожение**: сцена за экраном спит (`setVisible(false)` — 0 кадров); дальше 1,5 высоты окна — уничтожается
  с `loseContext()`; на каждую жизнь — свежий холст `[проверено]`.
- Вне режима «вживую» (§10, §11) живых сцен нет.

## 9. Постер и раскадровка

- **Постер** — `<img data-poster>` под холстом, всегда в разметке: кадр покоя той же камеры (p = `poster_p`, по умолчанию
  0; t = 2; DPR 2; фон места), файл вида `scene-<сцена>-<место>[-m].jpg`; у `play` — ещё кадр финала `-end` для обзора
  `[проверено]`. Постер — запасной вариант при любой ошибке и кандидат LCP вместо холста (09/05 выжимка п.14, `06` §2).
- **Широкий постер** ставит `object-position` равным сдвигу героя в кадре: при обрезке узкого окна герой не уходит
  `[проверено]`.
- **Раскадровка** (`[data-story]`) — вместо закрепления: поле не держит длинную прокрутку (высота `auto`), под окном с
  заставкой — кадры точек покоя с подписями тактов (ПК 600 px DPR 1, телефон 360 px DPR 2; JPEG качества 84–86) и
  строка «Раскадровка · в Play N шагов: прокрутка запускает такт, сцена доигрывает его сама» `[проверено]`.
- Кадры постеров и раскадровки снимает стенд в точках покоя (`stage_stand.py shot`, `sheet`) — они совпадают с живой
  сценой (`01` §9).

## 10. Обзор холста и Play

Холст Claude Design режим не сообщает: признак «вживую» — эвристика `[проверено]`, рантайм берёт её функцией `isLive`:

```js
// «вживую» (Play): окно не выше 1700 px и страница или окно-предок с прокруткой длиннее окна на 40 px
function viewMode(root) {
  var vh = window.innerHeight || 0, el = root, doc = document.scrollingElement || document.documentElement;
  if (vh > 1700) { return false; }
  if (doc.scrollHeight > vh + 40) { return true; }
  for (; el && el !== document.body; el = el.parentElement) {
    var oy = getComputedStyle(el).overflowY;
    if ((oy === 'auto' || oy === 'scroll') && el.scrollHeight > el.clientHeight + 40) { return true; }
  }
  return false;
}
var rt = new StageRuntime(window.STAGE_SCENES, { isLive: function () { return viewMode(place); } }).mount(document);
setInterval(function () { rt.layout(); rt.frame(); }, 1500);   // режим холста меняется без resize — опрос раз в 1,5 с
```

В обзоре — постеры и раскадровки, ни одного контекста; далёкие артборды холста «спят» (cd 05/03 §2). Где и как сцена
живёт на холсте — `06` §1.

## 11. «Уменьшить движение» и программный рендер

- **Reduce** — `matchMedia('(prefers-reduced-motion: reduce)')` при монтировании и по `change`: раскадровка вместо
  закрепления, живых сцен нет; длинного поля нет — «Пропустить» и рельс скрыты, а прокрутка кнопками при reduce —
  мгновенная, без плавности; подписи — без сдвигов, размытия и масок `[проверено]`. Это станции вместо движения
  (creative 05/01 §4).
- **Программный рендер** — `isSoftware()`: контекст с `failIfMajorPerformanceCaveat: true` не создаётся, а без флага
  создаётся — рисует процессор; иначе `RENDERER` и `UNMASKED_RENDERER_WEBGL` по
  `/swiftshader|llvmpipe|softpipe|software|basic render/i`. Итог — постеры и раскадровка, ни одного живого контекста;
  стенду — флаг `force3d` `[проверено]` (`failIfMajorPerformanceCaveat` — `[практика]`).

```js
function isSoftware() {                          // examples/stage-runtime.js
  try {
    var free = function (g) { var x = g && g.getExtension('WEBGL_lose_context'); if (x) { x.loseContext(); } };
    var gl = document.createElement('canvas').getContext('webgl2', { failIfMajorPerformanceCaveat: true });
    if (!gl) { var any = document.createElement('canvas').getContext('webgl2'); free(any); return !!any; }
    var r = String(gl.getParameter(gl.RENDERER) || ''), ext = gl.getExtension('WEBGL_debug_renderer_info');
    if (ext) { r += ' ' + String(gl.getParameter(ext.UNMASKED_RENDERER_WEBGL) || ''); }
    free(gl);
    return /swiftshader|llvmpipe|softpipe|software|basic render/i.test(r);
  } catch (e) { return false; }
}
```

## 12. Пауза, «Пропустить», рельс

- **Пауза** (`[data-pause]`, `aria-pressed`, подпись «Остановить движение сцены») — у каждой живой сцены: стопорит пружину
  и проигрыш (время `play` сдвигается на длину паузы) и свою жизнь сцены (`setIdle(false)`, `setPlaying(false)`)
  `[проверено]`. Одна кнопка на место; переключатель «меньше движения» на всю страницу — creative 05/01 §4.4.
- **«Пропустить»** — прокрутка к низу поля минус шапка (`scrollBy`, `smooth`; при reduce — `auto`) `[проверено]`.
- **Рельс тактов** — только ПК и от 3 тактов: точки справа, текущая — `aria-current="step"`, масштаб 1,5; клик — прокрутка
  так, чтобы блок такта встал на линию 60 % `[проверено]`.

## 13. Текст и подписи тактов — HTML-слой

- **Весь текст — DOM поверх холста**: заголовок заставки, подписи тактов, надписи на отрезках, метки, которые сцена двигает
  `transform` по своим якорям (`onFrame({anchors})`, `01` §8). Холст — `aria-hidden`, описание сцены — скрытым абзацем для
  экранного диктора, подписи тактов — `aria-live="polite"`; части сцены, которые нажимаются, дублируют кнопки HTML
  `[проверено]`. Текст в холсте не индексируется и не читается (09/05 выжимка п.15).
- **Подписи стоят в окне сцены** и сменяются своим входом, а не едут лентой за прокруткой: «прижимаются к концу сцены…
  некрасиво» — отзыв заказчика на ленту `[проверено]`.
- **У каждой сцены свой стиль подписи** — одинаковые «плашечки» во всех сценах заказчик отклонил `[проверено]`:

| стиль | вход |
|---|---|
| титры | слова проявляются по одному: шаг 45 мс, сдвиг 0,5 em, размытие 5 px → 0 |
| заметка на столе | лист ложится с поворотом −7° → −1° |
| интерфейс | строка прорисовывается сканом (`clip-path`, 0,75 с) |
| дата | крупная дата выезжает снизу |
| этикетка | сначала линия, затем этикетка |
| сноска | линия растёт, слова идут за ней |
| легенда | панель легенды |

- Под подписью — полоска пути до следующего такта (`--fill`); текущая подпись яркая, соседние приглушены; последняя гаснет
  вместе со сценой `[проверено]`.
- **Подпись — смысл и факт места**: деловое утверждение с фактом, а не описание эффекта («мир в мире», «город растёт»)
  `[проверено]`. Факты подписей — из фактов продукта, тексты — по copy deck (`CLAUDE.md` §3).

## 14. Ритм страницы

- **Между двумя сценами — статичный блок** (глава, факты): «чтобы оно не шло одним потоком» — слово заказчика
  `[проверено]`. Совпадает с правилом пиков уровня L2: между пиками — спокойная секция (creative 05/01 §5.5).
- **Длинная главная** — все сцены сайта главами с разделителем и оглавлением; страница раздела повторяет свою сцену
  `[проверено]`.
- **Место по смыслу**: сцена встаёт туда, где она сопровождает смысл секции; новый блок ради сцены допустим (`05` §1)
  `[проверено]`.
- **Первый экран главной** — один проход движения короче 5 с без паузы (синемаграф фона); живые сцены — ниже первого
  экрана `[кейс]`.

## Частые ошибки

- **Перехват колеса, своя скорость прокрутки** — запрещено на всех уровнях (creative 05/01 §6.2); шаги с доигрышем
  прокрутку не трогают.
- **Шаг 100–150vh у сцены с доигрышем** — «долго крутишь, ничего не происходит»; шаг `beats` — 480 / 420 px.
- **Сцена идёт за прокруткой там, где нужен такт** — «резко, неплавно» и «втупую прокрут»; станции сюжета — `beats`.
- **Пружина с отскоком у прогресса** — камера проскакивает ключ и возвращается.
- **Подписи лентой за прокруткой** — «прижимаются к концу сцены»; подписи стоят в окне.
- **Открепление сразу после последнего такта** — «сразу вниз уходят»; хвост и затемнение выхода (§7).
- **Одинаковые подписи во всех сценах** — «плашечки»; у каждой сцены свой вход.
- **Две сцены подряд без статичного блока** — «одним потоком».
- **Больше двух живых контекстов** — браузер снимает самый старый; предел 2 / 1 (§8).
- **Холст снятой сцены в работе** — сцена молча не рисует; свежий холст на каждую жизнь.
- **Нет постера** — в обзоре холста и в статичной копии на месте сцены пустой прямоугольник (cd 05/03 §5).
- **`play` дольше 5 с без паузы** — нарушение WCAG 2.2.2.
- **Reduce с длинным полем** — пустая прокрутка без сцены; в reduce поле — `auto`, на месте раскадровка.
- **Ожидание, что холст сообщит режим Play** — не сообщает; эвристика §10.
- **Текст и подписи в холсте** — не индексируются, не читаются диктором, не переводятся.

## Открытые вопросы и противоречия

- **Длина шага и сцены.** creative 05/02 §4.1 («шаг сцены 100–150vh; L2 — ≤ 400vh и ≤ 5 шагов на секцию»), creative
  05/01 §7.1 (сцена прокрутки 100–150vh на шаг, токен `scroll.step-vh` 120) и `motion_hints.scroll_scene_length_vh` уровня L2
  в `../../creative/01-creative-direction/ambition-levels.yaml` описывают скраб с закреплением. Норма этой папки — отдельный
  класс «шаги с доигрышем» (`beats`): шаг 0,5–0,6 экрана (480 / 420 px), 5–7 точек покоя, поле до 4,2 тыс. px (≈ 460vh при
  окне 900 px); скраб с закреплением — 100–150vh на шаг.
- **Предел поля и станций.** Токен `scroll.pin-l2-max-vh` = 400 (`../../creative/04-visual-language/marketing-tokens.json`) и
  `scene.stations` ≤ 6 в `../../creative/09-ai-execution-evaluation/motion-spec.schema.json` уже норм `beats` с 7 точками
  покоя и полем до 460vh.
- **Скраб и такт.** creative 05/02 §4.2 и 05/01 §7.2 («скраб догоняет за 0,5–1 с; `damp` λ 4–6»): скраб папки согласен
  (ω 6,5 → 0,73 с); такт `beats` (1,3–2,0 с) и `glide` (2,4 с) длиннее — это переход по событию прокрутки, а не скраб;
  хвост `glide` больше секунды — только для карт и маршрутов, `[кейс]`.
- **Пружины.** creative 05/01 §7.3 («пружины — только геометрия от указателя; крупные фоны не пружинят») и поле `model:
  spring` спецификации движения. Норма этой папки — критически демпфированная пружина без перелёта ведёт прогресс прокрутки
  всей сцены; пружина с отскоком — запрещена.
- **Привязка к станциям.** creative 05/02 §4.2 называет `snap` частичным перехватом. `beats` прокрутку страницы не
  двигает: страница стоит, где её оставил человек, доигрывает только сцена — это не `snap`; отметить в нормах creative.
- **Порядок деградации.** creative 05/03 §4.3 («p95 > 24 мс → без петель, скраб — станциями, DPR ниже») и строка §4.2
  «WebGL, 3D → постер, DPR ≤ 1,5». Норма этой папки — порядок деградации `01` §6.4: множитель плотности → лишние проходы
  → петли → постер.
- **Один холст на страницу или холст на место.** Студии держат один контекст на всю страницу: фиксированный холст и
  DOM-прокси (`r3f-scroll-rig` у 14islands, `satus` у darkroom), один контекст на все секции CMS (Resn) `[исходник]`
  `[кейс]` — это снимает предел контекстов и повторную сборку сцен, но требует общего движка, порталов и одной цепочки
  кадра. Набор держит холст на место с пределом 2 / 1 живых: сцены независимы, падают поодиночке и переносятся по одной
  `[практика]`. Браузер при избытке живых контекстов снимает самый старый (исходник Blink); точный предел по платформам —
  `[не проверено]`.
- **Полоса без закрепления.** Холст можно не закреплять, а вести вместе со страницей: смещение подгоняется в каждом кадре,
  рендер — с запасом ≈ 25 % сверху и снизу (`WebGL-Scroll-Sync` у Lusion) `[исходник]`; рантайм набора держит такие
  полосы обычным потоком страницы (`scrub`, `play`).
- **Виртуальная прокрутка** у миров кампаний (перехват колеса и касания) — жанр, а не норма: рантайм прокрутку не
  перехватывает (§3), продуктовой странице она запрещена (creative 05/01 §6.2).
- **Потеря контекста.** 09/05 (выжимка п.23, §6.2) пересоздаёт ресурсы по `webglcontextrestored`; норма этой папки —
  постер сразу и повторная жизнь на свежем холсте (§2.2, `01` §3).
- **Режим холста** — эвристика (§10): если тип холста начнёт сообщать Play, эвристика уходит.
- **Числа телефона** — `[кейс]`: реальные телефоны не мерились.
