# План ресёрча: Blender и нейросети для 3D на сайтах

Дата старта: 22 сентября 2026. Оркестратор: Opus 5.5. Исполнители: Opus-агенты, 4–6 на волну, 3 волны и синтез,
параллельно трек видео. Соседние базы: `../ux/` (UX) и `../ui/` (визуальный слой интерфейсов).

## Зачем

Строится система генеративного дизайна: нейросети (генерация картинок, Blender, кодогенерация) под управлением
агента проектируют и собирают сайты и интерфейсы. Эта база отвечает на вопрос, как агент **с помощью Blender**
(Python API, MCP-сервер, фоновый режим) делает красивые и сложные 3D-модели, сцены, рендеры и анимации для
**веб-дизайна** — лендингов, продуктовых и маркетинговых сайтов — и как это потом живёт на странице в JavaScript
(three.js и другие движки): эффекты, модели, прокрутка, интерактив. Читатель — ИИ-агент (и человек, который его
настраивает): зашёл, прочитал выжимку, понял, каким инструментом и каким приёмом пользоваться, при
необходимости углубился.

Главный риск темы: знания нейросетей о Blender и three.js устаревают быстрее, чем о UX. В интернете горы кода под
Blender 2.7x–3.x, а на машине стоит 5.2.2 LTS, где часть API удалена (например, `Action.fcurves`,
`scene.node_tree`, `use_auto_smooth`, `BLENDER_EEVEE_NEXT`). Поэтому каждое техническое утверждение, где это
возможно, **проверяется запуском** на этой машине, а версия пишется рядом с правилом.

## Рамки

В фокусе:
- 3D на сайтах: hero-объекты, витрины продукта, сторителлинг на прокрутке, абстрактные и генеративные фоны,
  3D-типографика, частицы, стекло и преломление, мокапы устройств, 3D-иконки и иллюстрации (предрендер),
  изометрические сцены, маскоты; альтернативы реалтайму — рендер в картинку, секвенция кадров, видео с альфой,
  гауссовы сплаты;
- Blender как производственный инструмент под управлением агента: модель данных и Python API (`bpy`, `bmesh`,
  ноды), MCP for Blender, фоновые скрипты, моделирование кодом (процедурное, geometry nodes, hard-surface,
  low-poly, стилизация), материалы, свет, камера, рендер, управление цветом, анимация, запекание, экспорт glTF;
- веб-рантайм: three.js (WebGL и WebGPU, TSL), React Three Fiber и drei, Babylon.js, PlayCanvas, model-viewer,
  Needle Engine, Spline как альтернатива; шейдеры, постобработка, анимация на прокрутке, производительность,
  доступность и запасные варианты;
- нейросети для 3D: агенты, пишущие код Blender (исследования и практика), генераторы 3D из текста и
  картинки, библиотеки ассетов и лицензии;
- проверка результата: рендеры с ракурсов, валидаторы, браузерный стенд, критика визуально-языковой моделью;
- YouTube: как правильно работать в Blender, как не работать, паттерны и антипаттерны, фишки.

Вне фокуса: игры как жанр (берём только переносимые приёмы), кино и VFX-пайплайны, риг персонажей для
анимационного кино, ручная скульптура как искусство, инженерный CAD, 3D-печать, AR/VR как отдельные продукты
(упоминаются, если лендинг даёт «посмотреть в AR»). UX и визуальный слой интерфейса — в соседних базах.

Границы с соседями (ссылаться, не дублировать): движение как токены и `prefers-reduced-motion` —

## Окружение (проверено оркестратором 22.09.2026)

- **Blender 5.2.2 LTS** (`blender` из PATH, сборка 2026-09-15). Фоновый режим работает: EEVEE через EGL
  на Intel Iris Xe (кадр 480×270 ≈ 4 с), Cycles только на CPU (20 потоков). Экспортёр «Khronos glTF Blender I/O
  v5.2.40», Draco и Meshopt доступны. Встроенный Python 3.13 с numpy, OpenImageIO, MaterialX, USD, OpenVDB.
  Проверено в 5.2.2: `Material.use_nodes` и `World.use_nodes` устарели (удаление в 6.0), новые материалы и миры
  сразу с нодами; `scene.node_tree` нет — `scene.compositing_node_group`; у `Action` нет `fcurves` (слои и слоты);
  движки `BLENDER_EEVEE`, `BLENDER_WORKBENCH`, `CYCLES` (`BLENDER_EEVEE_NEXT` не принимается); у EEVEE нет
  `use_bloom`, `use_gtao`, `use_ssr`; вид по умолчанию — AgX; RNA занижает динамические перечисления (движки,
  view transform) — читать текущее значение и ловить `TypeError`.
- **Аддоны пользователя**: MCP for Blender (аддон 1.7, протокол 7; сервер `mcp-for-blender` 2.0.3 подключён к сеансу
  оркестратора как `mcp__blender__*`) и MPFB. MCP-мост поднимается только в Blender с окном; в фоне команды не
  выполняются. Телеметрия выключена дважды: `DISABLE_TELEMETRY=true` у сервера и галочка в настройках аддона (по
  умолчанию в аддоне она включена).
- **Браузерный стенд**: Chromium (Playwright) без окна рисует WebGL2 на реальной видеокарте через ANGLE (GL и
  Vulkan), `navigator.gpu` есть. jsDelivr доступен. Версии npm на 22.09.2026: three 0.186.0, @react-three/fiber
  9.7.0, drei 10.7.8, @babylonjs/core 9.27.1, playcanvas 2.22.3, @google/model-viewer 4.3.1, @needle-tools/engine
  6.0.0-alpha.3, @splinetool/runtime 2.0.55, gsap 3.15.0, lenis 1.3.26, postprocessing 6.39.5; @theatre/core 0.7.2
  не обновлялся с мая 2024.
- **glTF-инструменты** (`../../scripts/3d/node`): gltf-transform 4.5.0, gltfpack 1.2, gltf-validator, meshoptimizer,
  draco3dgltf. Нет `toktx` (KTX2).
- **Видео**: yt-dlp 2026.08, локальный STT Qwen3-ASR (как в `../ux`).
- **Ограничения железа**: нет CUDA — Cycles на GPU и локальные генераторы 3D (TRELLIS, Hunyuan3D) недоступны,
  только облачные API; 15 ГБ ОЗУ на всех агентов.

Утилиты и их проверка — `../../scripts/3d/README.md`.

  08-export-gltf/                  ← контракт экспорта glTF, запекание, сжатие, бюджеты, валидация
  09-web-runtime/                  ← three.js, R3F, другие движки: загрузка, свет, шейдеры, прокрутка, производительность
  10-ai-3d-generation-assets/      ← генераторы 3D из текста и картинки, библиотеки ассетов, лицензии, доводка
  11-evaluation-qa/                ← проверка: рендеры, топология, валидаторы, браузерный стенд, VLM-критика, чек-листы

Каждый содержательный файл устроен как в соседних базах: метаданные → «Выжимка для агента» (правила «делай /
не делай» с меткой и `→ §`) → разделы с деталями и **проверенным кодом** → «Частые ошибки» (включая ошибки
нейросетей) → «Чек-лист» → «Открытые вопросы и противоречия» → «Источники». В каждой папке `README.md`: список
файлов и выжимка на 10 строк.

## Метки доказательности

| Метка | Значение |
|---|---|
| `[проверено]` | Запущено на этой машине: Blender 5.2.2 / three r186 / Chromium; рядом ссылка на эксперимент `99-raw/experiments/…` |
| `[документация]` | Официальная документация или спецификация: Blender Manual, Python API, release notes, Khronos glTF и расширения, документация three.js, pmndrs, Babylon, MDN, W3C |
| `[исследование]` | Работа с измерением: статья, бенчмарк, эксперимент с описанной методикой; год и выборка рядом |
| `[консенсус]` | Несколько независимых авторитетных практиков или источников сходятся |
| `[практика]` | Устоявшийся приём индустрии без первоисточника с измерением (туториалы, студии, форумы) |
| `[мнение]` | Один автор |
| `[спорно]` | Источники расходятся; позиция базы — с условием |
| `[не проверено]` | Код или утверждение не удалось проверить запуском, хотя это возможно в принципе |
| `[V:<id> mm:ss]` | Ссылка на дайджест видео; рядом одна из меток выше |

Всё, что зависит от версии, помечается версией: `(Blender 5.2)`, `(three r186)`, `(glTF 2.0 + KHR_materials_…)`,
`(2026-09)`.

## Как расширять базу

1. **Источник.** Читать целиком (`99-raw/tools/fetch.py` или `render_fetch.py` → кэш `99-raw/cache/`), первичные в приоритете; в
   разделе «Источники» файла — запись `[S<n>]` с URL, автором, годом; у правила — метка и `→ §`. Библиографию пересобрать:
   `python3 99-raw/tools/sources_collect.py` (перезаписывает `90-sources/sources.tsv` и README; `--dry` — только сводка).
2. **Файл или раздел.** Структура как у соседних файлов (метаданные → «Выжимка для агента» → разделы с проверенным кодом → «Частые
   ошибки» → «Чек-лист» → «Открытые вопросы и противоречия» → «Источники»); строка в таблице и выжимке README папки; затем
   `python3 ../../scripts/maint/check_links.py --only NN` (≈ 7 с; ложные ERROR на сокращениях «A `01 §22`» смотреть глазами) и карта файлов
   корневого README — `python3 99-raw/notes/wave4/S2/make_map.py --apply` (числа строк `wc -l`, описания — в скрипте). Противоречие
   с существующим правилом — строкой в реестр корневого README («тема → позиция → условие → где»), а не молчаливой правкой.
3. **Дайджест видео.** Наборы `99-raw/prompts/wave2-W*.md` (W1, W2, W5, W6, W8–W11) для 50 роликов P2/P3 отложены (транскрипты на диске); запуск,
   порядок (первыми — W9, W11, W10, W6, W2: на их ролики уже 55 ссылок `[V:…]` без дайджеста) и цена — `91-videos/README.md`, разделы
   «Что отложено» и «Как запустить отложенный набор»: дайджестер Sonnet, `_common-W-digests.md` + промт набора + список неразобранных
   роликов; ≈ 0,4–0,5 млн токенов и 30–35 мин на набор, все восемь ≈ 2,5–3,5 млн. Перенос правил из дайджеста в файлы `01–13` —
   только агентом этой папки, с меткой и таймкодом.
4. **Метки.** Легенда — раздел «Метки доказательности» выше и корневой README; версия рядом с правилом; непроверенное —
   `[не проверено]`, один источник — `[мнение]` / `[исследование, единичный источник]`. В выжимку корневого README — только правила
   с меткой не ниже `[консенсус]` или `[проверено]`, с числом или условием.
5. **Прогон кода.** Весь код базы — `bash 99-raw/experiments/X/01-rerun/run_all.sh` (≈ 12 мин, одна копия Blender; `SCR=<временная
   папка>`, до и после — `snapshot.py save/restore`: раннеры пишут в свои папки; шаги `STEPS="B O C1 D1 D2 E G H I J L K F1 F2 X04"`,
   команды каждого — в самом скрипте и в `99-raw/experiments/X/01-rerun/README.md`). Один файл — `python3 ../../scripts/3d/run_doc_blocks.py
   <файлы.md> --json r.json` (python — в свежем `blender -b`, bash — из корня; JS — раннеры F2/09 и H/30; `# run: skip` или
   `[не проверено]` в первых строках блока — пропуск). Помощники: `python3 ../../scripts/3d/blender_run.py ../../scripts/3d/test_bpyx.py`
   (25/25) и `../../scripts/3d/test_agent_helpers.py` (помощники U, 4/4); рецепты — `../../scripts/3d/run_recipes.py` (≈ 3 мин).

   core,negative,k --compare baseline` (≈ 57 с); 4 отрицательных контроля обязаны падать; новую базовую линию писать только осознанно.
7. **Атлас инструментов** — `python3 99-raw/tools/atlas_collect.py [--refresh] [--offline]` (без `--refresh` — из кэша за секунды);
   новый инструмент — одна запись `E(...)` в `ENTRIES`; вручную — только лицензия, ограничения и «ценность для агента»; GitHub без
   токена — 60 запросов в час на машину.

9. **Глоссарий.** Термины — из раздела «Термины» отчёта нового агента; данные и сборка — `99-raw/notes/wave4/S2/` (`gloss_latin.txt`,
   `gloss_cyr.txt`: «термин ¦ EN ¦ определение ¦ папка ¦ регэксп ¦ где»; `make_glossary.py` находит «Где» по базе, `--check` — проверка),
   таблицы потом вставить в `00-glossary/README.md` вместо раздела «Термины». Не больше ≈ 350 терминов; новое «ложное слово» — строкой в
   «Ложные друзья и путаницы».
10. **Правила для будущих агентов.** Субагентов и помощников не запускать; заметки `99-raw/notes/waveN/<агент>-notes.md` с разделом
    `## СТАТУС` — после каждых 3–5 источников или эксперимента (сеть заказчика рвётся: упавший агент продолжает с места по статусу,
    `SendMessage` по id); итоговые файлы — по одному и рано (первый — не позже середины работы), затем отчёт с разделом «Что должна
    учесть следующая волна»; источники — нужными разделами (8–12 новых), видео — через дайджесты; эксперименты — минимум, рендеры
    ≤ 1024 px, Cycles ≤ 64 сэмплов, одна копия Blender на агента, Blender с окном — только по замку `GUI_LOCK` в `99-raw/notes/`;
    настройки и файлы заказчика не трогать; без явного «стоп» агенты уходят в эксперименты — давать минимум и срок. **Калибровка
    расхода**: тематический агент в экономном режиме волны 3 — 0,3–0,6 млн токенов и 30–45 мин (K 567, J 576, I 536, O 328 тыс.);

    ещё ≈ 2 млн на девятерых.
