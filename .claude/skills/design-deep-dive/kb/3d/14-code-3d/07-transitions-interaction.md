# 07 · Переходы и интерактив кодом: продукт отвечает указателю, свет отвечает сюжету, рендер по требованию, составные переходы

Дорожка CD · 25–26.09.2026 · фазы 2–3 (окончательно) · three 0.186.0 · код — `15-showcase/_shared/code3d/src/scene.js` (`frame`, `storyFrame`, `scanFrame`,
`ikTarget`), `zveno/a-code/js/main.js` (границы текста, касание) · ворота — `scripts/creative/motion_check.py` 0.1.3.

## Выжимка для агента

1. **Сильнейший ход кода — продукт отвечает вводу**: рука тянется к указателю (IK), на телефоне — к точке касания; кадры рисуются только
   по вводу, в покое 0 вызовов. Этого нет ни у кадра Blender, ни у видео. Цена — 0,5 КБ br и ≈ 0,2 мс CPU в кадре. `[проверено]`
2. **Интерактив не заходит в текст**: цель ограничивается колонкой текста **по содержимому** (Range строк и кнопок), а не по блоку
   (флекс-строка кнопок во всю ширину давала границу правее руки). У текста рука **указывает** на курсор (цель поднята до ≥ 1,2 м от плеча,
   инструмент нацелен на настоящую точку указателя). `[проверено]`
3. **Хвост после ввода ≤ 0,45 с** — и у прокрутки, и у указателя: `motion_check` сбрасывает счётчик WebGL на +0,5 с паузы и снимает второй
   раз на +1,2 с; хвост IK 0,9 с дал «петли под текстом» (EG-A11Y-16/17, S). Тот же пиксель указателя (синтетические события зонда) — без кадров. `[проверено]`
4. **Свет по сюжету вместо неона**: вспышка фиксации модуля — точечный свет **над лаком** (0,7 м к камере от центра модуля), узкая LED-полоса
   кольца и bloom выше порога 3,4; плоскость скана светит на начинку. Свет в 1,5 см от лака (фаза 1) выжигал свой корпус — пятно 4,5 % кадра;
   стало 0,84 %. `[проверено]`
5. **Переход «модули → внутри» кодом без второго рендера**: смена фазы сцены (`story` → `scan`) при прокрутке + срез плоскостью с кромкой.
   Составной переход через render targets (приём 9) на странице «Звена» **неприменим**: между сценами — секция `specs`, холст скрыт; он
   нужен страницам, где сцены идут подряд без HTML между ними. `[проверено: J/04; разметка a-code]`
6. **Ввод оставляет след (фаза 3)**: точка захвата руки, ведомой курсором, рисует пунктир путевых точек (0,4 с, ≈ 0 мс) — видно, что руку
   «программируют ведением». Жизнь следа ≤ хвоста 0,45 с — иначе кадры в покое. `[проверено]`

## 1. Правила с числами

| Правило | Число | Метка |
|---|---|---|
| сглаживание прокрутки | τ 90 мс, после 0,28 с без ввода — 30 мс; отсечка 0,45 с | `[проверено]` |
| сглаживание указателя (камера) | τ 160 → 40 мс; сдвиг камеры от указателя 0,03 рад при IK (0,06 без IK) | `[проверено]` |
| IK | τ 110 → 35 мс, отсечка 0,45 с; вес IK — первый экран (гаснет до выпрямления) и «первое движение» | `[проверено]` |
| касание (телефон) | сдвиг ≤ 12 px и ≤ 600 мс, не по ссылке/кнопке/карточке → цель руке; граница — выше H1 | `[проверено]` |
| граница текста | `minX = max(right содержимого title, lead, actions, facts; рамки карточек) / innerWidth · 2 − 1 + 0,08` (1440: 0,159; 1280/1920: 0,139) | `[проверено]` |
| кадры в покое | 0 (десктоп, телефон, reduce) — site_probe 5 точек × 2 снимка | `[проверено]` |
| reduce | сцена не грузится, станции-картинки; кнопка «Меньше движения» останавливает WebGL без перезагрузки (новый холст) | `[проверено]` |
| вспышка фиксации | окно `bump(u, 0.84, 0.92, 1.0)` локального времени модуля; свет 3,2 · вспышка, дальность 2,6 м | `[проверено]` |
| «пробуждение» первого экрана | 1,2 с один раз через 650 мс после первого кадра, только если прокрутка < 5 % | `[проверено]` |

## 2. Частые ошибки

| Симптом (ворота) | Причина | Правка |
|---|---|---|
| EG-A11Y-16/17 «петля под текстом» | хвост IK 0,9 с; зонд колеса двигает мышь | отсечка 0,45 с, тот же пиксель — без кадров |
| EG-A11Y-27 белый корпус под белым H1 | цель IK без границы | граница по DOM по содержимому |
| рука «тянется» не к тексту, а вправо | граница по блоку флекс-строки (1312 из 1440 px) → `minX` 0,6 | `Range.selectNodeContents` |
| рука складывается «к зрителю» | цель в плоскости 0,8 м перед рукой, ближе 1 м к оси | плоскость через ось, подъём цели, прицел |
| вспышка — пятно на пол-кадра | весь поясок ×16 + свет в 1,5 см от лака + bloom 5 уровней | LED-полоса, свет над лаком, bloom 4 уровня r 0,45 |
| кадры идут после остановки | накопление AO/TRAA по кадрам | N8AO `accumulate: false`; временные приёмы — только с нормой «сходится ≤ 0,45 с» |

## 3. Чек-лист

- [ ] продукт отвечает вводу (указатель, касание, прокрутка), свет — сюжету; неон без функции — нет;
- [ ] граница текста по содержимому; контраст H1/лида над живым 3D ≥ 3 / 4,5 (EG-A11Y-27) при 5 положениях указателя;
- [ ] хвосты ≤ 0,45 с; 0 вызовов в покое; reduce — станции, кнопка паузы;
- [ ] вспышки не чаще 3 в секунду и не на пол-экрана (WCAG 2.3.1 — `motion_check` покадрово).

## 4. Не проверено (кандидаты фазы 3)

- Составной переход «модули → внутри» через render targets (маска-скан превращается в портал), `webgpu_portal`, drei `MeshPortalMaterial` —
  `[документация: S21, S22, S23 дайджеста 04]`; цена — +1 рендер только на время перехода, ограничение EG-CHOR-01 (≤ 6 «вау»-переходов на L2).
- Курсор как фонарь/рентген (проявление начинки под указателем) — `[документация: S26]`.
- Клавиатура как ввод для IK (стрелки двигают цель) — альтернатива для не-мыши; сейчас клавиатура руку не двигает.
