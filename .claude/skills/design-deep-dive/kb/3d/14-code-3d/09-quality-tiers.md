## Выжимка для агента

1. **Два уровня по устройству, выбор до загрузки three**: `quality: 'low'` при `(max-width: 40rem), (pointer: coarse)`, иначе `'high'`.
   Уровень — бюджет пикселей холста и состав проходов, а не потолок DPR: high — 4,6 Мпикс (тяжёлой сцене 3,2–3,4), low —
   1,9 Мпикс (тяжёлой 1,2–1,6), DPR ≤ 2 (`../16-js-scenes/01-engine.md` §6: `[проверено]` ПК, `[кейс]` телефон). low —
   Standard вместо Physical, без тени, зеркала, AO, поста, анизотропных крышек и винтов; остаются студия, IK (касание), туман,
   горизонт, деталь без винтов. `[проверено]`
2. **Пост — отдельным `import()`-чанком**: телефон его не качает (JS 134,3 против 231,2 КБ br у десктопа — пост 97 КБ br, из них N8AO ≈ 77).
   `[проверено]`
3. **Цена по уровням в тишине** (Iris Xe, пропускная «окно / число кадров» после ожидания простоя): телефон-режим 412×915 DPR 1,25 —
   v2 0,38 мс, v3 0,51 (+0,13), вид p3 0,53; десктоп 1440×900 DPR 1,5 — v2 1,43, v3 4,31 мс (фаза 2), вид p3 4,72 (CD3). *Исправлено по
   T12*: прежние 0,51 / 0,68 и 1,79 / 4,94 мс — медиана длительности кадров (замер 20:18), метод непригоден (`01` §8.3). Под нагрузкой
   соседей (load 24–27) те же наборы давали 1,9 → 2,1 и 3,4 → 5,9 мс: абсолютные мс сравнивать только внутри одного прогона.
   `[проверено: CD/09, CD/15; CD3 — CD/HANDOFF-3.md §4]`
4. **low выкидывает не только тяжёлые проходы, но и «невидимую работу в каждом кадре»**: винты (≈ 4 px на 390 px, матрицы 86 экземпляров
   каждый кадр) дали LoAF прокрутки телефона 4,44 % против 1,29 % у v2 (S в motion_check); без них — 0,21 %. `[проверено]`
5. **Гибрид — свой GLB для телефона** (`glb.lowUrl`: сегменты ниже, AO 512²) и Physical → Standard в адаптере; вызовы телефона с J2 из GLB
   36 против 35 у кода, треугольники 27 против 18 тыс. `[проверено]`

## 1. Состав уровней

| Приём | high (десктоп) | low (телефон) | Цена high → low |
|---|---|---|---|
| материалы | Physical (лак clearcoat, анизотропия алюминия и крышек) | Standard (без лака и анизотропии) | меньше ALU на фрагмент |
| тень ключа | PCF 2048², раз в кадр | нет | −1 проход сцены |
| мир | пол-зеркало ½ + размытие ¼, туман, горизонт | туман, горизонт, тёмный пол без зеркала | −1 проход сцены, −4 прохода размытия |
| пост | N8AO ½, bloom, Neutral, LUT, зерно, виньетка, FXAA | нет (тон — рендерер), чанк не качается | −97 КБ br, −8…10 проходов |
| деталь | винты InstancedMesh, кабель, маркировка, риски, швы | без винтов | −86 матриц в кадре |
| IK | указатель | касание (граница — выше H1) | = |
| контровой свет в дымке (приём 8, фаза 3) | эллипс за рукой, лучи pmndrs в ½ | вместо лучей — ореол фона/тумана ×5 и шире (22 вместо 36) только в «модулях» (0 мс: те же шейдеры, другой uniform) | десктоп +0,37 мс, +6/+7 вызовов; телефон 0 `[проверено]` |
| след инструмента (приём 10, фаза 3) | пунктир 96 точек, 0,4 с | есть (1 вызов при движении; телефон 0,54 → 0,53 мс) | ≈ 0 `[проверено]` |
| плотность | бюджет 4,6 Мпикс (тяжёлой сцене 3,2–3,4), DPR ≤ 2 | бюджет 1,9 Мпикс (тяжёлой 1,2–1,6), DPR ≤ 2 | чёткость та же, меньше проходов; цены п.3 сняты при DPR 1,5 / 1,25 |
| вызовов в кадре («модули» / «скан») | 92 / 40 (p3: 98 / 47) | 35 / 12 | `[проверено]` |

## 2. Правила с числами

| Правило | Число | Метка |
|---|---|---|
| бюджет кадра телефон-режима на Iris Xe | ≤ 2 мс (гипотеза дайджеста 04 Q/14) — v3 0,51 мс в тишине, вид p3 0,53 (*исправлено по T12*: было 0,68 — медиана) | `[проверено]` |
| бюджеты героя | ≤ 50/100 тыс. треугольников, ≤ 30/60 вызовов в покое, JS 3D L2 ≤ 250/350 КБ br | `[документация: KIT §5]` |
| длинные кадры прокрутки (EG-PERF-01) | ≤ 2 % кадров (телефон v3 0,21 % после выноса винтов) | `[проверено]` |
| первый кадр 3D | ≤ 2 / 5 с (десктоп/телефон); в тишине v3 1,15 / 3,0 с (фаза 1) | `[проверено]` |
| адаптивное качество по кадру | сначала множитель плотности 0,7…1 (медиана 40 занятых кадров > 24 мс → ×0,85, < 12,5 мс → ÷0,85), затем лишние проходы, петли, постер (`../16-js-scenes/01-engine.md` §6); ZERO снижает уровень при медиане > 22 мс | `[проверено]` ПК, `[кейс]` телефон; `[документация: S25]` |

## 3. Частые ошибки

| Ошибка | Последствие | Правка |
|---|---|---|
| один бандл на всё | телефон качает пост 97 КБ br | пост — `import()` только при high |
| low = «без поста», деталь та же | LoAF прокрутки ×3,4 | всё, что меньше 5 px на 390 px и считается каждый кадр, — только high |
| сравнение мс из разных прогонов | ложные выводы (×2 от нагрузки соседей) | чередование наборов в одном прогоне, тишина (`slot_run --heavy`) |
| среднее `el/n` за замер без ожидания простоя | одно зависание 1 с даёт ×2 к «цене кадра» | ждать простоя перед замером (компиляция вне окна), затем пропускная `el/n` по 2,5 с, медиана 3 чередованных повторов, счёт зависаний > 50 мс (*исправлено по T12*: было «медиана длительности кадров») |
| медиана интервалов rAF при `--disable-gpu-vsync` | двугорбая (пачки 0,1–0,3 мс и блокировки очереди GPU 0,3–1,3 с), квант `performance.now()` 0,1 мс: в том же прогоне v3 десктоп 0,65 мс при пропускной 4,31, телефон 0,1 при 0,51 | пропускная после простоя (строка выше); *исправлено по T12* — `01` §8.3, `CD/rules.md`, `CD/out/p2/q/summary.json` |

## 4. Чек-лист

- [ ] уровень выбран до `import('./three-scene.js')`; плотность — бюджетом пикселей холста (DPR ≤ 2, ≤ 4,6 / 1,9 Мпикс);
  пост и GLB-загрузчик — отдельные чанки;
- [ ] low проверен `motion_check --modes mob` (LoAF, длинные кадры), не только site_probe;
- [ ] мс — в тишине, парой «эталон и вариант» в одном прогоне, пропускной «окно / число кадров» после ожидания простоя, не медианой
  интервалов rAF (*исправлено по T12*, `01` §8.3).

## 5. Не проверено (кандидаты)

Третий уровень (планшет/слабый ноутбук: без зеркала, bloom только), FSR/TAAU (рендер 0,5 + апскейл, r184 WebGPU), множитель плотности по
медиане кадра у сцены three.js (у своего движка — `../16-js-scenes/01-engine.md` §6), `renderer.info` по уровням на реальных телефонах — `[документация: дайджест 04 §B.5, S24, S25]`.
