# 06 · Compute, частицы и симуляции кодом: когда оправданы, во что обходятся, как откатываться на WebGL2

Дорожка CD · 25–26.09.2026 · фазы 2–3 (окончательно) · three 0.186.0 · compute и симуляции в испытании **не строились** (для лендинга
«Звена» не нужны — `08`); приём 10 «след инструмента» сделан в фазе 3 без compute (§2) — файл собирает проверенное и документацию, с явными метками. Опыт входа в WebGPU (вес и откат) — `08-webgpu-tsl-migration.md`.

## Выжимка для агента

1. **Частицы — только «со смыслом»** (клише `particle-swarm` в реестре): след траектории инструмента при «первом движении», поток
   «питание по шине» в кольце, пыль в луче. Шар частиц/облако без функции — не брать (KIT §4.8). `[документация: KIT §4.8, дайджест 04 §C.10]`
2. **Дешёвый путь на WebGL2 — морфинг/смещение в вершинном шейдере**: 40 тыс. частиц с поверхности и морфинг — 1,06 мс кадра на Iris Xe.
   `[проверено: F2/02, 09-web-runtime/04 §1]` Для «следа кисти» хватает кольцевого буфера позиций кисти (N×vec3 uniform/текстура) и `Points`
   с затуханием по возрасту — без compute.
3. **Compute (`instancedArray` + `compute()` в TSL) — только с `WebGPURenderer`**: вход в WebGPU — +107 КБ br к той же сцене
   (`tsl` 260,6 против `WebGLRenderer` 153,1 КБ br, CD/18); на откате WebGL2 compute эмулируется (transform feedback), атомики — только WebGPU.
   `[проверено: CD/18 — вес; документация: S4, S13, S16 — compute]`
4. **Симуляции (ткань Верле 31×31, жидкость MLS-MPM 32 768 частиц, вода)** — примеры r186 только на WebGPU; физика Rapier 0.20 — wasm
   0,5–2,4 МБ, вне бюджета JS 3D L2 (≤ 250/350 КБ br) до действия пользователя. `[документация: S4, S28, S33]`
5. **Ворота слепы к WebGPU**: `motion_check` перехватывает только вызовы WebGL — на WebGPU «0 кадров в покое» будет ложно чистым; для
   WebGPU-страниц мерить `site_probe.py` (перехват `GPURenderPassEncoder.draw*`). `[документация: дайджест 04 §B]`

## 2. Приём «частицы, которые объясняют» для «Звена» — сделан (фаза 3, CD/22)

След инструмента (`_shared/code3d/src/trail.js`): кольцевой буфер **96 точек с равным шагом 3,5 см по пути** точки захвата (IK за курсором и
«первое движение»; новые точки рождаются только когда рука движется), `Points` с `ShaderMaterial`: размер 7,5 см в мире и яркость по возрасту,
жизнь **0,4 с** (укладывается в хвост 0,45 с — 0 кадров в покое), `#ff6a2a` × 2,2 аддитивно, ниже порога bloom (не неон). Первый вариант —
сплошная линия (шаг 1,2 см) — читался «проволокой» рядом с кабелем; пунктир читается как путевые точки записанной траектории («программируют
рукой»). Цена: 1 вызов при движении, телефон 0,54 → 0,53 мс (без изменений), вес 0,9 КБ br (сборка без следа — `CD/out/kb.json`). Кадр —
`99-raw/experiments/CD/out/cd3/final/trail-1600/hero.png`. На WebGPU тот же след через `instancedArray` ничего не добавил бы — вход в WebGPU
окупается только compute-симуляцией (сотни тысяч частиц, поля). `[проверено]`

## 3. Частые ошибки

| Ошибка | Последствие | Правка |
|---|---|---|
| WebGPU ради частиц на лендинге без отката | ≈ 16 % аудитории без WebGPU получают откат — худший первый кадр | WebGL2-частицы в вершинах, WebGPU — только если нужен compute |
| частицы крутятся в покое | «петля» в воротах (EG-A11Y-09/16/17), батарея | жизнь частиц привязана к движению, хвост ≤ 0,45 с |
| проверка покоя `motion_check` на WebGPU | ложное «0 вызовов» | `site_probe.py` с перехватом WebGPU |
| физика wasm в первом экране | +0,5–2,4 МБ до взаимодействия | грузить после действия пользователя |

## 4. Чек-лист

- [ ] у частиц есть функция в сюжете (решение в `art-direction.md`, клише `particle-swarm`);
- [ ] WebGL2-путь (вершины) по умолчанию; WebGPU — только compute, с замером отката;
- [ ] 0 кадров в покое, reduce без частиц, покой проверен инструментом, который видит этот бэкенд.
