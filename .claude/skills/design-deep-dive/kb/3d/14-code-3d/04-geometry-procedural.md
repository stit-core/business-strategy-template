## Выжимка для агента

1. **Промышленный продукт кодом = токарные профили + фаски + слияние по материалу.** `LatheGeometry` из точек профиля `[r, y]` с фаской
   1–3 % (12 мм на корпусе r 0,235), крышка — профиль «борт → канавка → плато → купол» (12 точек); модуль = группа мешей **по материалам**
   (`mergeGeometries`), ≤ 3–5 вызовов на модуль: рука из 8 модулей + начинка = 49/17 вызовов с тенью (v2), 15,5 тыс. треугольников. `[проверено]`
2. **Повторяющуюся деталь — одним `InstancedMesh`**: 86 винтов на всю руку = 1 вызов на проход; матрица экземпляра = матрица модуля ×
   локальная (считать только в кадре, `instanceMatrix.needsUpdate`). Цена +0,1–0,6 мс, 0,7 КБ br — но **на телефоне матрицы в каждом кадре
   дали LoAF прокрутки 4,44 % против 1,29 % у v2** → деталь, невидимая на 390 px, не входит в low. `[проверено]`
3. **Кабель — `TubeGeometry` по `CatmullRomCurve3` с провисом до напольного разъёма**, не «к горизонту»: в перспективе кабель к горизонту
   читается линией вверх («висит в воздухе»). 90 сегментов × 10 по окружности, слит с разъёмом в один вызов. `[проверено]`
4. **Маркировка — атлас canvas 1024×512 шрифтом страницы** и наклейки-заплатки по цилиндру (`decalCylY`) и торцу (`decalCapX`) с
   `polygonOffset −2`; текстура перерисовывается, когда шрифт загрузился (`document.fonts.ready`, ≤ 400 мс). `[проверено]`
5. **Кинематика — невидимые шарниры** (`rig.js`: `PIVOTS` родитель/смещение/ось), видимый модуль лежит в корне и получает
   `T(разнос) · шарнир.matrixWorld · R(доворот)` — так разнос, пружина, IK и сюжет не ломают иерархию, а модуль можно подменить
   **GLB-пустышкой с тем же именем** (гибрид). `[проверено]`
6. **IK руки — аналитическая на 2 звена + основание + кисть** (0,5 КБ, +0,2 мс CPU в тишине). У текста у такой руки (вылет 2,6 м, до колонки
   текста ≈ 0,6 м от оси) есть только три позы: лезть в текст, складываться к зрителю, или **поднять цель и нацелить схват на курсор**
   («указывает») — выбрана третья (лист `CD/out/p2/look/sheet-ik5.jpg`). `[проверено]`
7. **Граница колонки текста — по содержимому, не по блоку**: `Range.selectNodeContents(el).getBoundingClientRect()`; флекс-строка
   кнопок во всю ширину контейнера давала `minX = 0,6` (правее оси руки) — в фазе 1 рука на странице вообще не тянулась к тексту. `[проверено]`

## 2. Модуль из GLB вместо процедурного (гибрид)

Контракт — `15-showcase/_shared/code3d/README.md`: пустышка `base…grip` в точке шарнира, оси three, метры `scene.js`, роли материалов по имени.
Адаптер (`glb-modules.js`) отбрасывает TRS пустышки (позу ставит кинематика), сохраняет TRS детей (квантование gltf-transform лежит в них),
клонирует материалы (исходник GLB не трогает; кольцо и светодиод — свой экземпляр на модуль: вспышка горит у одного), считает центр
габарита для пружины. Проверено на J2 дорожки Z: модуль встал точно в шарнир во всех 8 состояниях, 6/6 ролей, 0 ошибок консоли; кадр hero
88 вызовов / 88 тыс. треугольников против 94 / 77 тыс. у кода (N8AO выключен — в GLB запечённый AO). `[проверено]`

Крюк v2 (фаза 3, для всей руки Z: 88 тыс. треуг., 23 материала): **начинка отдельным GLB** (`glb.innerUrl`) — основной файл без узла
`j3_inner` на 119 КБ br легче (798 → 679), начинка (121 КБ br без AO) приходит в простое через ≈ 51 мс после первого кадра и подменяет
начинку-заглушку кода; **KTX2** (`build.sh --ktx2`, KTX2Loader по требованию, транскодер со своего домена) — на одном атласе 2048²
проигрывает по сети (+301 КБ br), выигрывает память GPU (−74 %). Ловушка: сцена glTF с именем «inner» принималась за узел начинки — корень
сцены теперь не узел, поиск — extras `zveno_inner` → `j3_inner` → `inner`. Разрезатель готового GLB (meshopt, без gltf-transform) —
`99-raw/experiments/CD/hook2/split_inner.mjs`. `[проверено]`

## 3. Частые ошибки

| Симптом | Причина | Правка |
|---|---|---|
| модуль из GLB «уехал» или в 4 раза меньше | TRS узла-меша сброшен вместе с квантованием (gltf-transform кладёт масштаб деквантования в узел) | модуль = пустышка, меши — её дети; адаптер предупреждает, если узел модуля — меш |
| вспышка фиксации зажигает все кольца | общий материал кольца у всех модулей GLB | экземпляр материала `ring`/`led` на модуль |
| кабель «висит в воздухе» | уходит к горизонту | короткий кабель к напольному разъёму |
| «искра» на винтах | зеркальная головка (шерох. 0,32) ловит полосу студии | шерох. 0,5, темнее |
| рука под заголовком | цель IK без границы | граница по DOM **по содержимому** (Range), для карточек — по рамке |
| рука складывается у оси | цель ближе 1,2 м к плечу | поднять цель / нацелить инструмент, а не тянуть цель вбок (вбок — в текст) |
| LoAF прокрутки на телефоне | матрицы 86 винтов в каждом кадре | винты только в high |

## 4. Чек-лист

- [ ] профили с фасками; слияние по материалу; вызовов ≤ 5 на модуль;
- [ ] повторы — `InstancedMesh`, матрицы в кадре, телефон без мелочи < 5 px;
- [ ] кабель/реквизит касается пола; наклейки — атлас шрифтом страницы;
- [ ] шарниры = контракт `rig.js`; модуль GLB подменяется по имени; начинка — `j3_inner`;
- [ ] IK: граница текста по содержимому, комфорт ≥ 1,2 м, прицел на курсор, хвост ≤ 0,45 с, 0 кадров в покое;
- [ ] треугольники ≤ 50/100 тыс., вызовы в покое 0.

## 5. Не проверено (кандидаты)

`LoftGeometry` (r185) для корпусов переменного сечения, CSG (three-bvh-csg, manifold-3d wasm) для пазов, `BatchedMesh` для разных деталей
одним вызовом — `[документация: дайджест 04 §B.10, S2, S37]`; `CCDIKSolver` для скелетных рук — `[документация: webgl_animation_skinning_ik]`.
