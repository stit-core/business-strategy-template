## Выжимка папки (12 строк)
1. Сначала задача страницы: продукт — предрендер/видео/model-viewer/hero-GLB; кампания — миры, частицы, история на прокрутке (`02` §7).
2. 25 из 70 эффектов не требуют Blender (шейдеры, CSS, пост, глобус, сплаты, Spline) — `01` §23.
3. Предрендер и видео из Blender в 10–100 раз легче реалтайма против текстурного GLB с JS (hero AVIF 4–14 КБ, вращение 2 с видео 40–60 КБ); для детальной формы без текстур видео ≈ GLB (VP9 1 с 124 КБ против 117 КБ) — выигрыш в 0 КБ JS и точном свете — `05` §2, `../12-recipes/08-sequence-video-alpha.md`.
4. Canvas не участвует в LCP: H1/постер в HTML, 3D — после `load` в простое; проверенный код — `02` §4.2.
5. Бюджет продуктового лендинга: ≤ 3 МБ телефон / ≤ 7 МБ десктоп, 3D героя ≤ 0,8 / 1,5 МБ, ≤ 30 / 60 draw calls, DPR ≤ 1,5 / 2 — `02` §3.1.
6. Медиана наградных 3D-сайтов — 12,6 МБ, первый 3D-кадр 14 с: антиориентир — `04` §4.
7. Стек по умолчанию: свой движок на WebGL2 для объекта, фона и мира (0,7 КБ br у SDF-примера, живёт на холсте без сети); под модель GLB — three 0.186.1 vanilla (бандлер, 108,5–158,2 КБ br), R3F 9.8 для React, model-viewer 4.4 для витрины и AR — `06` §2, `03` §12.
8. three ломает API почти каждый релиз (`HDRLoader`, `Timer`, `RenderPipeline`…) — сверять с таблицей `03` §2.3.
9. WebGPU/TSL — только для compute/сплатов/TSL-эффектов; откат на WebGL2 встроен и проверен — `03` §2.2.
10. Reduced motion и стоп вне экрана обязательны (13 из 16 лидеров их игнорируют); процедурные материалы запекать, постер = GLB — `05` §3.1.
11. WebGPU — у 85,8 % браузеров, но по реальным адаптерам Linux 18 %, Android 75 %: откат на WebGL2 и постер обязательны; в headless без GPU WebGPU уходит на программный SwiftShader — в отчёт замера `backend` и `isFallbackAdapter` — `06` §3.
12. Модель пишет классический three по памяти и путает TSL, R3F 10 и r187: версия без `^` в npm и import map, `tsc` с типами three той же версии, headless-прогон с провалом на `deprecated` в консоли — `06` §4; лицензии `lygia`, GSAP, Needle, Spline — `06` §6.
