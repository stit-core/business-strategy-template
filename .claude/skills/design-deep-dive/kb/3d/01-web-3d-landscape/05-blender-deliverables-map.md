Волна 1 · агент A · 2026-09-23 · главный вход для агентов волны 2 (D1, D2, F, G, H) · опирается на каталог
`01-effects-catalog.md` (70 эффектов), замер 33 сайтов (`04-reference-sites-measured.md`) и эксперименты
`99-raw/experiments/A/06-deliverable-sizes` (одна сцена в каждом виде поставки), `07-lazy-hero-pattern`,

## Выжимка для агента

1. Blender отдаёт сайту **18 видов поставок** (§1): GLB шести разновидностей, AR-версию, данные (точки, пути, маркеры), карты (нормали/глубина/matcap/lightmap/AO), окружение, картинки, секвенции, видео (в т. ч. с альфой), VAT; для 25 из 70 эффектов каталога Blender не нужен вовсе. [практика; проверено: A/06]
2. Выбор поставки начинается с вопроса «нужна ли интерактивность»: нет → картинка/секвенция/видео (рендер), да → GLB (модель + запечённые материалы) → `02-when-3d-budgets-loading.md` §7. [проверено]
3. Одна и та же сцена (7,3 тыс. треуг.) в разных поставках: hero 1024² — AVIF 4–6 КБ / WebP 10–14 КБ; 48 кадров вращения — WebP 183–386 КБ, AVIF 105–186 КБ; видео 2 с — stacked AV1 14–39 КБ, VP9-alpha 19–61 КБ, H.264 13–81 КБ; GLB 172 КБ → Draco 23 КБ / Meshopt 47 КБ (+ декодер и ≥ 110 КБ br three) → §2. [проверено]
4. **Процедурные материалы не переживают экспорт glTF** (банка с процедурной этикеткой в вебе белая) → любой GLB, кроме «цвет + шероховатость», требует запекания в текстуры → §3.1, `../08-export-gltf/`. [проверено]
5. **Постер и GLB должны совпадать**: рендерить постер из того же состояния модели, что уходит в GLB (после запекания), иначе при замене постера на 3D картинка «прыгает» → §3.1. [проверено]
6. Для AR — **отдельный GLB** без Draco/KTX2/морфов/вершинных цветов, ≤ 100 тыс. треуг., ≤ 10 материалов, текстуры ≤ 2048², 1 UV, 1 анимация, ≤ 10 МБ; USDZ — через model-viewer на лету или отдельно → §3.7. [документация Google]
7. Данные для веба (точки частиц, пути камеры, маркеры) — **не** меш: бинарный Float32 или JSON с осями three (Blender Z-up → `[x, z, -y]` или экспорт glTF с +Y up) → §3.8–3.10. [практика: Codrops 2026-07-07]
8. Пустышки (Empty) — дешёвый канал Blender → JS: точки меток, цели lookAt, спавн, коллайдеры, пивоты; в glTF это узлы с именами и `extras` (Custom Properties) → §3.10. [практика: Woan, Codrops 2026-08-24]
9. Картинки из Blender — PNG RGBA 8 бит (`film_transparent`) → кодирование вне Blender: AVIF q55–60 / WebP q80–85 с альфой; PNG в продакшен не отдавать (в 30–100 раз тяжелее) → §3.13. [проверено]
10. Секвенции: два набора (десктоп — больше кадров и размер, телефон — меньше), WebP/AVIF, имена `f_0000.webp`; рендер EEVEE ≈ 0,7 с/кадр 512² на Iris Xe → §3.14. [проверено]
11. Видео с альфой: VP9-alpha WebM + HEVC-alpha (кодируется только на macOS) либо stacked-alpha (AV1 + HEVC x265, двойная высота) + WebGL-шейдер; оба пути проверены в Chromium (альфа 0/255) → §3.15. [проверено]
12. Для перемотки видео прокруткой — all-intra (`-g 1`, в 3–4 раза тяжелее) или секвенция → §3.15. [проверено]
13. Симуляции (ткань, мягкие тела, разрушение) — запекать и отдавать как shape keys (десятки кадров) или VAT (текстура позиций, много кадров) → §3.16, `../07-animation/`. [практика: Codrops 2025-08-20, 2026-09-19]
14. Цвет: вид по умолчанию AgX высветляет брендовые цвета (красный → розовый) → для продуктовых рендеров Standard или Khronos PBR Neutral (есть в 5.2.2), в three — `NeutralToneMapping` → §3.13, `../06-materials-lighting-render/`. [проверено: A/06; отчёт V]
15. Приёмка каждой поставки — скриптом: `gltf_check.py` (валидатор + inspect), `web_view.py` (модель в three r186), `render_views.py` (ракурсы), размеры файлов против бюджета `02 §3.1` → §4. [практика]

## 3. Разновидности поставок: требования и приёмка

### 3.1. GLB: меш + PBR с запечёнными текстурами (основная поставка реалтайма)
- Требования: применённые модификаторы (или «apply modifiers» в экспорте), масштаб применён, origin осмысленный, нормали
  наружу, UV без перекрытий для запекания; материал — Principled BSDF с **текстурами**, а не процедурными нодами
  (запечь: Base Color, Roughness/Metallic → ORM, Normal, AO; при статичном свете — Combined/lightmap).
- Формат: GLB (Meshopt или Draco), текстуры KTX2 (ETC1S для цвета/ORM, UASTC для нормалей) или WebP; 1–2 атласа на объект. Сжимать постобработкой (`gltf-transform optimize` / `gltfpack -cc`), а не встроенным Meshopt экспортёра 5.2 — у него нет квантования (агент E: 2,2 МБ против 0,82 МБ у gltfpack на 252 тыс. треуг.) [проверено E: `../08-export-gltf/03`].
- Размер-ориентир: hero 0,2–1,5 МБ; в выборке лидеров GitHub-маскоты 250–360 КБ, Lando 350–470 КБ на модель [проверено].
- Постер: рендерить из **запечённой** версии (A/07: постер с процедурной этикеткой не совпал с белой 3D-моделью) [проверено].
- Детали запекания и экспорта — `../08-export-gltf/` (E), материалы — `../06-materials-lighting-render/` (D2).

### 3.2. GLB с вершинными цветами / палитрой (low-poly, стилизация)
- Вершинные цвета или 1 палитра-текстура 64–256 px на всю сцену, плоские/сглаженные нормали по углу, AO — в вершинные
  цвета. Малый вес (0,1–1 МБ), 1 материал → мало draw calls. Scene Viewer вершинные цвета **не** поддерживает → для AR
  палитра-текстура [документация Google].

### 3.3. GLB с морф-таргетами (shape keys)
- Для мимики, «надувания», переходов формы; одинаковая топология; экспорт Shape Keys (+ нормали морфов по нужде).
- Размер растёт линейно с числом форм × вершин; Meshopt/квантование обязательно; Scene Viewer морфы не поддерживает
  [документация]. Подробно — `../07-animation/` (H).

### 3.4. GLB со скелетом и анимациями
- ≤ 254 костей и 4 веса на вершину (лимит AR/рекламы Google), 1–3 клипа (Idle, Hover, Intro), корневое движение — по
  договорённости с JS; в Blender 5.x анимации — Actions со слотами (у `Action` нет `fcurves` — `PLAN.md`), экспорт
  «Animation» в glTF → `AnimationMixer` [документация Google; дрейф — `../03-bpy-api/`].

### 3.5. GLB с анимацией трансформаций и камерами
- Разлёт деталей, пролёт камеры, раскрытие; в JS — `mixer.setTime(progress × duration)` для прокрутки. Камеры
  экспортируются как узлы glTF (включить Cameras в экспорте) [практика].

### 3.6. GLB с вариантами материалов
- `KHR_materials_variants`: один меш, несколько материалов-вариантов; экспортёр glTF Blender поддерживает варианты
  (проверка переноса — E). В вебе: three (варианты в `userData`), model-viewer (`variant-name`) [документация three:
  webgl_loader_gltf_variants].

### 3.7. AR-версия (Scene Viewer / Quick Look)
- Лимиты Scene Viewer: ≤ 100 тыс. треуг. (идеал 30–50 тыс.), ≤ 10 материалов (2 с альфой), 1 меш на материал,
  текстуры ≤ 2048², кости ≤ 254, 4 веса, 1 UV, ≤ 10 МБ (15 — ошибка), расширения только `KHR_materials_unlit`,
  `KHR_texture_transform`; без морфов и вершинных цветов; 1 анимация (первая, по кругу); тени не запекать; +Y вверх,
  фронт к +Z, 1 ед. = 1 м [документация Google].
- USDZ: model-viewer генерирует на лету из GLB (без анимаций); для анимаций — отдельный USDZ (экспорт USD из Blender —
  проверка E/H) [документация model-viewer; не проверено].

### 3.8. Точки для частиц
- Выборка поверхности: Geometry Nodes «Distribute Points on Faces» (плотность/число) → «Realize» → атрибут позиции
  (и цвет, нормаль при нужде) → запись бинарника Float32 (x, z, −y) скриптом; для морфинга — **одинаковое число точек** и
  стабильный порядок на каждую форму [практика; код — D1, агент B: `../03-bpy-api/` (bmesh/атрибуты, `foreach_get`)].
- Формат: `.bin` Float32 little-endian (12 Б/точка) или glTF с `POINTS`-примитивом; квантование до Int16 — ×2 меньше.

### 3.9. Пути (камера, объекты, текст)
- Кривая Безье/NURBS → оценённый меш кривой → вершины в мировых координатах → JSON `[[x, z, -y], …]` (Blender Z-up →
  three Y-up); число точек задаёт `resolution_u` кривой; объект брать по имени, не `active_object` [практика: Codrops
  2026-07-07; дополнение A].
- Альтернатива — анимированная камера (Follow Path) → glTF-анимация камеры [практика].

### 3.10. Маркеры (пустышки) и метаданные
- Пустышки → узлы glTF: точки аннотаций, цели камеры, спавн, упрощённые коллайдеры, пивоты; Custom Properties →
  `extras` (включить в экспорте); соглашение имён (`hotspot_*`, `collider_*`, `cam_*`) фиксируется для JS [практика: Woan;
  каталог V — «соглашения об именах управляют поведением в JS»].

### 3.11. Карты: нормали, высоты, глубина, matcap, lightmap, AO
- Для 2.5D-эффектов над картинками: вместе с кадром — Z (глубина) и Normal passes (PNG16/EXR → WebP/PNG16).
- Matcap — рендер сферы в нужной студии (квадрат 256–1024, EXR/PNG) → `MeshMatcapMaterial` (Lusion: `matcap.exr` 590 КБ)
  [проверено: замер].
- Lightmap/AO — запекание во 2-й UV; в three `lightMap`/`aoMap` читают UV1 (второй набор) — проверка соответствия
  (E, F) [не проверено здесь].

### 3.12. Окружение (HDRI)
- Обычно — готовые HDRI (Poly Haven, CC0; G) в 1k для веба (0,4–0,6 МБ HDR); свой — рендер панорамы студии из Blender
  (камера Panoramic equirectangular, EXR) → `HDRLoader` (r180+) → PMREM [практика; сайты: Lando 378 КБ, Mana 425 КБ].
- Без файла: `RoomEnvironment` (three) — 0 КБ, нейтральный студийный свет (A/07) [проверено].

### 3.13. Предрендер PNG/WebP/AVIF с альфой
- Blender: PNG RGBA 8 бит, `film_transparent`, размер = 2× CSS-размера для ретины (1024² под 512 CSS); view transform
  — Standard или Khronos PBR Neutral для брендовых цветов (AgX высветляет) [проверено: A/06; отчёт V].
- Кодирование: AVIF q55–60 (Pillow/avifenc), WebP q80–85; `<picture>` с AVIF → WebP → PNG-запас [проверено]. Для рендеров с альфой и ровным фоном AVIF вдвое меньше WebP (A/06), а для фото-текстур PBR — лишь на 5 % при кодировании ≈ 23 с (агент E, `../08-export-gltf/03` п. 14) → картинки-кадры: AVIF + WebP; текстуры GLB: WebP/KTX2 [проверено A и E].
- Серия (иконки): одна студия, одна камера, одна палитра — паспорт серии (`../../ui-research/07-iconography-imagery/02` §5).

### 3.14. Секвенции кадров
- Рендер N кадров (анимация или поворот скриптом — A/06 делает поворот без анимационной системы), имена с нулями
  (`f_0000.png`), два набора: десктоп (например, 120–200 кадров 1080–1440 px) и телефон (60–100 кадров 720 px) —
  ориентир OPTIKKA/Apple [практика]; кодирование WebP q80 (или AVIF), отдельная папка на набор.
- Оценка: 48 кадров 768² WebP ≈ 0,4 МБ (простая сцена); фотореализм — в 3–10 раз больше [проверено: A/06, порядок].

### 3.15. Видео (в т. ч. с альфой)
- Без альфы: H.264 (`libx264 -crf 23 -preset slow -movflags +faststart`) + AV1/VP9 первым `<source>`; постер — первый кадр.
- С альфой (проверено A/06 в Chromium 153): VP9 `-pix_fmt yuva420p -c:v libvpx-vp9 -crf 40 -b:v 0`; stacked:
  `-filter_complex "[0:v]format=pix_fmts=yuva444p[main];[main]split[main][alpha];[alpha]alphaextract[alpha];[main][alpha]vstack"`
  → AV1 (`libaom-av1 -cpu-used 6 -crf 40`) и HEVC-запас (`libx265 -crf 28 -tag:v hvc1`); воспроизведение stacked — шейдер
  WebGL2 (RGB — верхняя половина, альфа — нижняя, фильтрация `NEAREST`) [проверено: A/06; практика: Archibald 2024,
  Shopify 2026]. HEVC-alpha нативно — только кодирование на macOS [практика].
- Для прокрутки: all-intra (`-g 1`) — точная перемотка, ×3–4 к весу [проверено].

### 3.16. VAT и запечённые симуляции
- Shape keys — для десятков кадров (ткань кнопки, Codrops 2025-08-20: Cloth → Lightwave MDD → импорт как shape keys →
  glTF). VAT — для сотен кадров: текстура позиций/смещений (float EXR или PNG16) × кадры + меш с UV-индексом вершины
  (Houdini VAT: 3500 точек × 50 кадров → EXR 1024×200, 1,7 МБ) [практика]. В Blender 5.2 путь VAT (аддон или GN +
  запись атрибутов в текстуру) — не проверен → H [не проверено].

### 3.17. Объёмные данные и SDF
- Редко для сайтов: облака/дым — как 3D-текстура (Data3DTexture) из OpenVDB (есть в Python Blender 5.2) или
  процедурно в шейдере; SDF для raymarching обычно пишут формулой, а не запекают [не проверено; кандидат для F/D2].

### 3.18. Ничего (эффекты без Blender)
- Шейдерные фоны, эффекты над картинками, пост-луки, CSS 3D, глобус cobe, Spline, сплаты — 25 эффектов каталога
  (`01-effects-catalog.md` §23). Агенту: не тратить время Blender, а в лучшем случае отрендерить постер-запас.

## Частые ошибки

- Экспорт процедурного материала без запекания — в вебе «голый» цвет [проверено].
- Постер отрендерен до запекания/с другими настройками — скачок при замене на 3D [проверено].
- PNG из Blender в продакшен (443 КБ против 4–10 КБ AVIF/WebP) [проверено].
- Видео с альфой только в VP9 — в Safari прозрачности нет; только HEVC-alpha — в Chrome нет → оба или stacked [практика].

- Пути/точки с осями Blender (Z-up) — всё «лежит на боку» в three [практика].
