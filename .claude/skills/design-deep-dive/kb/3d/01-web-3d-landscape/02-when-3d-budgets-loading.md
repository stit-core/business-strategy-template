## Выжимка для агента

1. 3D оправдан, когда **снимает неопределённость о товаре** (форма, размер, механизм, материал) или **является сообщением** бренда/кампании; «чтобы было красиво» на странице с конверсией — нет → §1, дерево §7. [исследование: Tan и др. 2022; мнение: NN/g]
2. Единственное полевое исследование с продажами (Tan, Chandukala, Reddy, J. of Marketing 2022, косметика): AR связан с ростом продаж у **менее популярных брендов, нишевых и более дорогих товаров** и у новых клиентов; эффект — там, где высока неопределённость → §1.1. [исследование]
3. «+94 % конверсии от 3D» (Shopify 2020–2022) — **маркетинг с самоотбором** (сравнивают тех, кто сам открыл 3D); не использовать как прогноз → §1.2. [мнение вендора]
4. Плохое 3D/AR вредит восприятию товара (NN/g: «нет ресурсов на качественное AR — не делайте») → лучше предрендер, чем кривой реалтайм → §1.3. [исследование, n = 11]
5. `<canvas>` **не кандидат LCP**; страница «только canvas» не даёт LCP вовсе; полноэкранный постер Chromium отбрасывает как фон → LCP становится H1; постер ≤ 80 % вьюпорта или видео — становятся LCP → держи H1/постер в HTML → §2.1. [проверено: A/04; документация web.dev]
6. 3D бьёт не по LCP, а по **TBT/INP**: разбор JS three (≈ 0,5–1 МБ несжатого), компиляция шейдеров, PMREM, декод GLB — долгие задачи 200–400 мс даже в лёгком герое → грузить после `load` в простое, декодеры в воркерах; `compileAsync` долгие задачи не снимает (внутри синхронный `compile()`), но делает первый `render()` дешёвым (14 против 541 мс, F1 `../09-web-runtime/01-threejs-core.md` §3.4) → §2.2, §4. [проверено: A/07, F1/01–02]
7. INP считает только клик, тап и клавишу; прокрутку и наведение — нет; но долгие задачи рендера задерживают любой клик → непрерывный тяжёлый рендер вредит INP косвенно → §2.2. [документация web.dev]
8. Резервируй место под 3D (`aspect-ratio` или размеры) — CLS 0 в паттерне A/07 → §2.3. [проверено]
9. Тяжесть коррелирует с провалом LCP в поле: страницы ≥ 5 МБ проходят LCP у 44 % мобильных против 72 % у самых лёгких (Web Almanac 2025) → §3. [исследование, корреляция]
10. Бюджет продуктового лендинга (позиция базы): всего ≤ 3 МБ телефон / ≤ 7 МБ десктоп; 3D-ассеты героя ≤ 0,8 / 1,5 МБ; JS 3D ≤ 200 КБ br; ≤ 50 / 100 тыс. треугольников героя; ≤ 30 / 60 draw calls; текстуры ≤ 1024–2048²; DPR ≤ 1,5 / 2 → §3.1. [спорно: синтез документации и замеров]
11. Для AR-файла действуют жёсткие лимиты Google: ≤ 100 тыс. треугольников (идеал 30–50 тыс.), ≤ 10 материалов, 1 UV, текстуры ≤ 2048², ≤ 10 МБ (15 — ошибка), **без Draco/KTX2/морфов/вершинных цветов** → отдельный файл → §3.2. [документация]
12. 3D-реклама (DV360 Swirl): ≤ 3 МБ, ≤ 30 000 вершин, ≤ 15 draw calls (лучше 1) — хороший «строгий» ориентир и для hero-объекта → §3.2. [документация]
13. Медианный наградной 3D-сайт — 12,6 МБ, первый 3D-кадр 14 с, LCP 5,8 с: это **антиориентир** для продукта → §3.3, `04-reference-sites-measured.md` §4. [проверено]
14. Память GPU считай формулой: RGBA8 = w × h × 4 Б × 1,33 (мипы) → 2048² ≈ 21 МБ, 4096² ≈ 85 МБ; KTX2 (ETC1S/BC1 ≈ 0,5 Б/px, UASTC/BC7/ASTC 4×4 = 1 Б/px) в 4–8 раз меньше; JPEG/PNG/WebP в памяти GPU — всегда несжатые → §3.4. [расчёт; документация MDN]
15. Порядок загрузки: HTML-текст и постер → `load` → (видим или простой) динамический `import('three')` → GLB → `compileAsync` → первый кадр → плавная замена постера → §4.1, код §4.2. [проверено]
16. Не грузи декодер, который модель не использует: Draco ≈ 58 КБ br, Basis/KTX2 ≈ 212 КБ br, Meshopt ≈ 7 КБ br → для лёгкой геометрии Meshopt выгоднее Draco по «модель + декодер» → §4.3. [проверено]
17. GLB без Draco/Meshopt отдавать с Brotli на сервере; после Draco/Meshopt Brotli почти ничего не даёт; кэш — хэш в имени + `Cache-Control: immutable` → §4.3. [практика; проверено на сайтах: GLB с br у Immersive Garden, Lacoste]
18. three из CDN без бандлера в r186 — `three.module.min.js` jsDelivr **только с ключом import map** `…/build/three.core.js` → `…/build/three.core.min.js`: без него min-модуль тянет неминифицированное ядро (204 КБ br, экономия ≈ 10 %); лучше бандлер со своего домена (109–174 КБ br) → §4.3, `../09-web-runtime/01-threejs-core.md` §1.2. [проверено: A/03, A/07, F1/01–02]
19. Запасной вариант обязателен: нет WebGL2 / tier 0 / `saveData` / `deviceMemory < 2` / reduce → постер (или видео) того же ракурса → §5. [проверено]
20. detect-gpu — грубый сигнал: Iris Xe получил tier 3 (сопоставлен с Intel Arc), любой iPhone — tier 1 FALLBACK (Safari скрывает GPU), база бенчмарков заморожена с 12.2025 → решай по нескольким сигналам и по фактическому FPS первых секунд → §5.2. [проверено]
21. Reduce: один кадр и стоп цикла (A/07: 0 draw calls в покое); 13 из 16 наградных сайтов этого не делают — не копируй их → §5.3. [проверено]
22. Вне экрана и в скрытой вкладке — стоп `setAnimationLoop(null)`; рендер по требованию для статичных сцен (OrbitControls `change`) → батарея и нагрев → §5.4. [проверено: A/07; практика]
23. Телефон: DPR ≤ 1,5 (так делают Lusion, Oryzo, GitHub — канвас 618×1259 при CSS 412×839), отдельный лёгкий набор ассетов (Igloo: 2,8 МБ против 16,6 МБ десктопа) → §5.4. [проверено]
24. SEO: весь смысловой текст — в исходном HTML (ИИ-краулеры не исполняют JS — Web Almanac 2025); 3D-модель товара — `schema.org/3DModel` через `subjectOf` и Merchant `virtual_model_link` → §6.1. [документация Google; исследование]
25. Доступность: декоративный canvas `aria-hidden="true"`; интерактивный просмотрщик — фокусируемый, с подписью (`alt` у model-viewer) и управлением с клавиатуры; петли > 5 с — кнопка паузы (WCAG 2.2.2); не более 3 вспышек/с (WCAG 2.3.1) → §6.2. [документация; см. `../../ux/08-accessibility/`]
26. Ворота «Enter/Click to start» и прелоадеры на 18–30 с — только для кампаний/игр; на продуктовой странице контент и CTA доступны сразу → §7. [проверено: 13 из 33 наградных сайтов с воротами/прелоадерами]
27. Замер — обязательная ворота качества: `site_probe.py` (десктоп + Pixel 7 с CPU×4 и медленным 4G) до и после 3D; сравнивать TBT, LCP, вес, draw calls → §8. [проверено]

### 1.2. Заявления вендоров (не использовать как факт)
- Shopify: «торговцы, добавившие 3D, видят +94 % конверсии в среднем» (changelog 2022-05-11; твит 2020: «взаимодействия с
  товарами с 3D/AR дали на 94 % выше конверсию») — **самоотбор**: 3D открывают уже заинтересованные; методика не
  опубликована. [мнение вендора]
- Shopify blog 2026: Rebecca Minkoff — смотревшие 3D на 44 % чаще кладут в корзину, AR — на 65 % чаще покупают;
  Oakywood — средний чек +458 % (совпало с переездом с Etsy). [мнение вендора, самоотбор/смешение факторов]
- Google Merchant: «3D и AR часто дают более сильное вовлечение». [мнение вендора, без чисел]
- Контент-фермы тиражируют «−40 % возвратов», «+94 %», «+40 % от 360°» без первоисточника — не цитировать. [мнение]
- Совет самого Shopify корректен методически: сравнивать товары с 3D и **сопоставимые** товары без него, а не
  посетителей, открывших и не открывших 3D.

### 1.3. Когда 3D помогает, когда вредит (синтез)
| Помогает | Вредит |
|---|---|
| Товар с неочевидной формой, размером, механизмом (мебель, обувь, гаджеты) — [исследование: Tan и др.] | Страница, где задача — быстро прочитать и купить (прайсинг, лиды) — главный поток занят 3D |
| Бренд/кампания, где 3D и есть сообщение (Shopify Editions, Lusion) | Низкое качество модели/света — [исследование: NN/g] |
| Объяснение устройства (взрыв-схема, разрез) | 3D вместо контента (текст в canvas, ворота) — нет LCP, SEO, a11y [проверено] |
| Настройка варианта (цвет, комплектация) | Телефоны среднего уровня: TBT 1–7 с при CPU×4 [проверено] |
| Портфолио студии, рекрутинг, награды | Непрерывный рендер без движения — батарея, нагрев [проверено: 25 из 33 сайтов] |

## 2. Core Web Vitals и 3D

### 2.1. LCP (≤ 2,5 с на p75; > 4 с — плохо)
- Кандидаты LCP: `<img>`, `<image>` в SVG, `<video>` (постер или первый кадр — что раньше), фон `url()`, блочный текст;
  `<canvas>` в списке нет [документация: web.dev]. Эвристики Chromium исключают элементы с opacity 0, **элементы на весь
  вьюпорт (фон)** и низкоэнтропийные заглушки.
- Эксперимент A/04 (Chromium 153): только WebGL-canvas → **ни одной записи LCP**; canvas + H1 → LCP = H1; полноэкранный
  `<img>`-постер + H1 → LCP = **H1** (постер отброшен как фон); постер 80 %×80 % → LCP = IMG; `<video>` 80 % → LCP = VIDEO
  (первый кадр); заголовок, нарисованный в 2D-canvas → записей нет. [проверено]
- Следствия: (1) H1 в HTML даёт быстрый LCP даже на тяжёлом 3D-сайте (Lusion: LCP H1 2,7 с при 16 МБ); (2) прелоадер,
  закрывающий H1, тянет LCP (Immersive Garden: 31,6 с) [проверено]; (3) постер-картинку продукта < вьюпорта грузить с
  `fetchpriority="high"` и `<link rel="preload" as="image">`; (4) у сайтов, где всё в canvas (Messenger, Bruno Simon), LCP
  в лаборатории нет, а поле посчитает первый появившийся текст/картинку. [проверено]

### 2.2. INP (≤ 200 мс) и TBT (лабораторный заменитель, цель < 200 мс на средней мобильной технике)
- INP учитывает клик, тап, клавишу; прокрутка, наведение, зум — нет [документация: web.dev]. 3D ухудшает INP через
  **задержку ввода** (главный поток занят) и **задержку отрисовки** (тяжёлый кадр рендера после обработчика).
- Источники долгих задач 3D: разбор и выполнение JS three/R3F (0,5–4 МБ несжатого), создание PMREM, **компиляция
  шейдеров** (первый рендер каждого материала), декод текстур на главном потоке, парсинг большого JSON glTF, физика.
  Паттерн A/07: одна долгая задача 222 мс (десктоп) / 394 мс (CPU×4) даже для 7 тыс. треугольников [проверено].
- Замер наградных сайтов: TBT до прокрутки — медиана 290 мс на десктопе, при CPU×4 — 0,26–7,1 с [проверено].
- Меры: грузить 3D после `load` в простое (`requestIdleCallback`); декодеры Draco/KTX2 — в воркерах (так устроены
  `DRACOLoader`, `KTX2Loader` в three); `renderer.compileAsync(scene, camera)` до первого кадра — TBT не снижает (F1/01: внутри синхронный `compile()`), но убирает тяжёлый первый `render()` (опирается на
  `KHR_parallel_shader_compile`, MDN советует параллельную компиляцию); меньше материалов = меньше программ; не создавать
  объекты в цикле кадра; тяжёлое — в воркер (OffscreenCanvas для рендера целиком — редкость). [документация; практика]

### 2.3. CLS (≤ 0,1)
- Canvas, вставленный без зарезервированного места, сдвигает вёрстку. `aspect-ratio`/явные размеры контейнера → CLS 0
  [проверено]. Постер и canvas — в одном абсолютно позиционированном контейнере.

(медиана 12,6 МБ) против норм платформ (3–15 МБ на **одну** модель) — разные жанры, для продукта — нормы платформ.

### 3.4. Память GPU и треугольники — формулы
- Текстура в памяти GPU: `w × h × байт_на_пиксель × 1,33` (мипы; MDN: «мипмапы — около 30 % сверху»). RGBA8 = 4 Б/px:
  1024² ≈ 5,3 МБ, 2048² ≈ 21 МБ, 4096² ≈ 85 МБ. Сжатые форматы из KTX2: ETC1S → ETC1/BC1 ≈ 0,5 Б/px (2048² ≈ 2,7 МБ),
  UASTC → ASTC 4×4/BC7 = 1 Б/px (2048² ≈ 5,3 МБ). PNG/JPEG/WebP/AVIF распаковываются в RGBA8 — вес файла не равен весу в
  памяти [расчёт; MDN: «JPG может быть меньше PNG по файлу, но в памяти одинаков» — discoverthreejs]. Пример: Igloo —
  KTX2 12,7 МБ в сети, heap JS 286 МБ [проверено].
- Бюджет памяти GPU (позиция): текстуры ≤ 64 МБ десктоп / ≤ 32 МБ телефон; MDN рекомендует «бюджет видеопамяти на
  пиксель» (приём Google Maps) — масштабировать кэш под размер окна [документация].
- Геометрия: вершина glTF без сжатия ≈ 32–48 Б (позиция 12, нормаль 12, UV 8, касательная 16); 100 тыс. треугольников
  ≈ 50–60 тыс. вершин ≈ 2–3 МБ несжатых; квантование Meshopt/Draco — в 4–8 раз меньше [проверено по порядку: A/06 —
  7,3 тыс. треуг. = 172 КБ → Draco 23 КБ, Meshopt 47 КБ].
- Draw calls: каждый меш × материал = 1 вызов; инстансинг/`BatchedMesh` и слияние по материалу сводят сотни объектов к
  единицам; MDN: «пакетируйте вызовы, атласы текстур» [документация].

## 4. Стратегии загрузки

### 4.1. Порядок (проверенный паттерн A/07)
1. HTML: H1, текст, CTA, контейнер героя с `aspect-ratio` (CLS 0) и `<picture>`-постером (AVIF → WebP) того же ракурса,
   `fetchpriority="high"` + `<link rel="preload" as="image">`. Постер < вьюпорта → он LCP (A/07: 72 мс десктоп, 412 мс
   телефон с троттлингом) [проверено].
2. Проверки: WebGL2, `navigator.connection.saveData`, `navigator.deviceMemory`, `prefers-reduced-motion` (reduce не
   запрещает 3D, а запрещает самопроизвольное движение).
3. Триггер загрузки: герой рядом с экраном (`IntersectionObserver`, `rootMargin: '200px'`) **и** после `load` в
   простое (`requestIdleCallback`, таймаут 2 с).
4. Динамический `import('three')` и лоадеров; GLB (Meshopt/Draco); окружение; `await renderer.compileAsync()`.
5. Первый кадр → класс `is-live` → кроссфейд постер → canvas (при reduce — без анимации перехода).
6. Цикл только при видимости, активной вкладке и без reduce; иначе один кадр и `setAnimationLoop(null)`.

### 4.2. Код (три r186, vanilla)
```js
// three r186 — [проверено] (десктоп, reduce, Pixel 7 CPU×4; 0 ошибок консоли)
const hero = document.getElementById('hero');                 // контейнер с aspect-ratio и <picture>-постером
const reduce = matchMedia('(prefers-reduced-motion: reduce)');
const saveData = navigator.connection && navigator.connection.saveData;
const lowMem = navigator.deviceMemory && navigator.deviceMemory < 2;
const hasWebGL2 = (() => { try { return !!document.createElement('canvas').getContext('webgl2'); } catch (e) { return false; } })();

if (hasWebGL2 && !saveData && !lowMem) {
  const io = new IntersectionObserver((es) => {
    if (!es.some(e => e.isIntersecting)) return;
    io.disconnect();
    const idle = window.requestIdleCallback || ((cb) => setTimeout(cb, 200));
    if (document.readyState === 'complete') idle(boot, { timeout: 2000 });
    else addEventListener('load', () => idle(boot, { timeout: 2000 }), { once: true });
  }, { rootMargin: '200px' });
  io.observe(hero);
}                                                              // иначе остаётся постер

async function boot() {
  const THREE = await import('three');
  const { GLTFLoader } = await import('three/addons/loaders/GLTFLoader.js');
  const { MeshoptDecoder } = await import('three/addons/libs/meshopt_decoder.module.js');
  const { RoomEnvironment } = await import('three/addons/environments/RoomEnvironment.js');
  const renderer = new THREE.WebGLRenderer({ antialias: true, alpha: true, powerPreference: 'high-performance' });
  renderer.setPixelRatio(Math.min(devicePixelRatio, 1.5));
  renderer.toneMapping = THREE.NeutralToneMapping;             // ближе к цвету бренда, чем AgX/ACES
  renderer.domElement.setAttribute('aria-hidden', 'true');
  hero.appendChild(renderer.domElement);
  const scene = new THREE.Scene();
  scene.environment = new THREE.PMREMGenerator(renderer).fromScene(new RoomEnvironment(), 0.04).texture;
  const camera = new THREE.PerspectiveCamera(30, 1, 0.1, 50);
  camera.position.set(0, 1.4, 4.6); camera.lookAt(0, 0.55, 0);
  const size = () => { const r = hero.getBoundingClientRect(); renderer.setSize(r.width, r.height, false);
    camera.aspect = r.width / r.height; camera.updateProjectionMatrix(); };
  size();
  const gltf = await new GLTFLoader().setMeshoptDecoder(MeshoptDecoder).loadAsync('product.glb');
  const model = gltf.scene; scene.add(model);
  await renderer.compileAsync(scene, camera);                  // шейдеры заранее
  const timer = new THREE.Timer();                             // r183+: вместо Clock
  const draw = () => renderer.render(scene, camera);
  const tick = () => { timer.update(); model.rotation.y += 0.35 * timer.getDelta(); draw(); };
  addEventListener('resize', () => { size(); draw(); });
  draw(); hero.classList.add('is-live');                       // CSS: постер → canvas
  let visible = true;
  const update = () => { const run = visible && !document.hidden && !reduce.matches;
    renderer.setAnimationLoop(run ? tick : null); if (!run) draw(); };
  new IntersectionObserver((es) => { visible = es[0].isIntersecting; update(); }).observe(hero);
  document.addEventListener('visibilitychange', update);
  reduce.addEventListener('change', update);
  update();
}
```
Результат A/07: LCP = постер (десктоп 72 мс, reduce 60 мс, телефон 412 мс), первый 3D-кадр 1,5 / 1,8 / 5,5 с, TBT
172 / 161 / 369 мс, CLS 0, draw calls в покое 3 / **0** / 3, canvas на телефоне 494×494 при CSS 330 (DPR 1,5) [проверено].
Импорт-карта (`three` → jsDelivr `build/three.module.js`, `three/addons/` → `examples/jsm/`) годится для прототипа; в
продакшене — бандлер или `*.min.js` с переназначением `three.core.js` → `three.core.min.js` (§4.3).

Вариант без своего кода (model-viewer 4, атрибуты из документации) [не проверено запуском]:
```html
<!-- model-viewer 4.3.1 — [не проверено: атрибуты по документации modelviewer.dev/docs] -->
<script type="module" src="https://ajax.googleapis.com/ajax/libs/model-viewer/4.3.1/model-viewer.min.js"></script>
<model-viewer src="product.glb" poster="poster.avif" alt="Красная банка с металлическим ободом"
  loading="lazy" reveal="auto" camera-controls touch-action="pan-y" tone-mapping="neutral"
```

`loading="lazy"` (= `auto`) грузит модель у вьюпорта; `reveal="manual"` + `dismissPoster()` — загрузка по клику; Draco- и

`meshoptDecoderLocation`; `minimumRenderScale` снижает разрешение до 0,5 при падении FPS (держит 38–60 fps) [документация].

### 4.3. Сжатие, декодеры, CDN, кэш
- Геометрия: Meshopt (`EXT_meshopt_compression`) — декодер ≈ 7 КБ br, декод быстрый; Draco — сильнее сжимает (A/06:
  172 → 23 КБ против 47 КБ Meshopt), но декодер ≈ 58 КБ br (wasm 48 + обёртка 10) и воркер [проверено]. Для
  героя < 1 МБ — Meshopt; для тяжёлой статичной геометрии — Draco. Подробно — `../08-export-gltf/`.
- Текстуры: KTX2 (Basis ETC1S — мелкий файл и память; UASTC — качество) + транскодер ≈ 212 КБ br (один раз на сайт);
  WebP/AVIF в glTF (`EXT_texture_webp`/`EXT_texture_avif`) — меньше файл, но полная память GPU [проверено: A/03; расчёт §3.4].
  Лидеры массово на KTX2 (Igloo 49 файлов, Steven 4K-атласы) [проверено].
- HTTP: GLB без Draco/Meshopt отдавать с Brotli (Immersive Garden, Lacoste отдают GLB с `br`) [проверено]; после
  квантования Brotli выигрывает мало [практика]. `Content-Type: model/gltf-binary`; хэш в имени + `Cache-Control:
  public, max-age=31536000, immutable` [практика].
- Предзагрузка GLB, если 3D — главное содержимое первого экрана: `<link rel="preload" href="model.glb" as="fetch"
  crossorigin>` (иначе двойная загрузка) [практика, не проверено].
- three без бандлера в r186: `build/*.min.js` удалены из пакета; jsDelivr отдаёт автоминифицированные `three.module.min.js`
  (90 КБ br), но он импортирует неминифицированный `./three.core.js` (204 КБ br) — нужен ключ-URL в import map `…/three.core.js` → `…/three.core.min.js` (104 КБ br; `../09-web-runtime/01-threejs-core.md` §1.2); неминифицированные `three.module.js` + `three.core.js` — 391 КБ [проверено:
  A/03, A/07]. С бандлером (esbuild/Vite) и именованными импортами — 109–160 КБ br [проверено].
- Декодеры хостить у себя рядом с сайтом (CDN третьих лиц — лишние DNS/TLS и риск CSP); путь `DRACOLoader.setDecoderPath`,
  `KTX2Loader.setTranscoderPath` [практика].

### 4.4. Прогрессивная загрузка и LOD
- Сначала низкая детализация, потом полная: three `webgl_loader_gltf_progressive_lod` (пример r186), Needle —
  «Progressive Asset Streaming (LOD)» (есть в бесплатном плане), SuperSplat — потоковый SOG с бюджетом гауссиан на
  устройство [документация].
- Сцены по секциям: монтировать активную и соседние, остальные `dispose()` (Shopify Editions) [практика].
- Секвенции: первые 10 кадров сразу, остальные в фоне, ±5 кадров по направлению прокрутки (OPTIKKA) [практика].

## 5. Запасные варианты

### 5.1. Матрица «условие → что показать»
| Условие | Как узнать | Что показать |
|---|---|---|
| Нет WebGL2 / контекст не создан | `getContext('webgl2')` = null; событие `webglcontextcreationerror` | постер (рендер Blender того же ракурса) или видео |
| Программный рендер / блок-лист | detect-gpu `tier: 0` (SwiftShader → BLOCKLISTED, A/05) | постер |
| `Save-Data` | `navigator.connection.saveData`, заголовок `Save-Data: on` | постер, без видео-петель |
| Мало памяти | `navigator.deviceMemory < 2` (Chromium) | постер или лёгкий GLB |
| Reduce | `prefers-reduced-motion: reduce` | 3D можно, но статичный кадр; переходы мгновенные (Lenis сам: `respectReducedMotion: true`) |
| Потеря контекста (моб. Safari) | `webglcontextlost` / `webglcontextrestored` | вернуть постер, пересоздать сцену при восстановлении |
| Низкий FPS первых секунд | drei `PerformanceMonitor`, model-viewer `render-scale` | снизить DPR ×0,8, выключить пост-эффекты, затем упрощённая сцена (Codrops 2025-02-11) |
| Нет WebGPU | `navigator.gpu?.requestAdapter()` = null | three `WebGPURenderer` сам уходит на WebGL2-бэкенд |

### 5.2. Уровни GPU — осторожно
- @pmndrs/detect-gpu (бывш. `detect-gpu`): tier 0 (< 15 fps, нет WebGL, блок-лист), 1 (≥ 15), 2 (≥ 30), 3 (≥ 60); данные
  gfxbench **заморожены с декабря 2025**; бенчмарки по умолчанию с unpkg (лучше свой `benchmarksURL`) [документация].
- Эксперимент A/05: Iris Xe → tier 3 «intel arc» (ошибочное сопоставление), SwiftShader → 0 BLOCKLISTED, iPhone → 1
  FALLBACK (модель скрыта), Adreno 610 → 2, Adreno 740 → 3, Mali-G52 → 1 [проверено].
- Позиция: tier 0 — надёжный сигнал для запаса; tier 1–3 — только стартовый пресет, дальше — фактический FPS
  (PerformanceMonitor) и память. Shopify Editions использует уровни 0–3 с ограничением телефонов «агрессивно — память
  важнее пикового бенчмарка» [практика].

### 5.3. Reduced motion
- Технически: `matchMedia('(prefers-reduced-motion: reduce)')` + подписка на `change`; при reduce — один кадр и стоп цикла
  (A/07: 0 draw calls в покое), переходы сцен — мгновенные или кросс-фейд, прокрутка не двигает камеру «сама» (Lenis
  при reduce выключает сглаживание: проверено на 1.3.26, `latest` в npm — 1.3.27) [проверено; документация Lenis].
- Токены движения, пороги длительности — `../../ui/08-motion/`, `../../ux-research/06-feedback-states-motion/03`.
- Практика рынка: 13 из 16 проверенных наградных сайтов не реагируют на reduce, Stripe — образец (рисует кадр и
  останавливается) [проверено].

### 5.4. Телефон, батарея, нагрев
- DPR ≤ 1,5 (лидеры: canvas 618×1259 при CSS 412×839); Spline в полном DPR 2,625 → TBT 1,9 с [проверено].
- Отдельный лёгкий набор: Igloo 2,8 МБ против 16,6 МБ десктопа; Apple на телефоне 3D не грузит вовсе [проверено].
- Рендер по требованию для статичных сцен (OrbitControls → `change` → один кадр) и стоп вне экрана — меньше нагрев и
  разряд батареи (discoverthreejs: «меньше включаются вентиляторы, меньше расход батареи на телефоне») [практика].
  Battery Status API для решений не использовать (ограничен в браузерах) [мнение].
- Safari: Lenis упирается в 60 fps, в режиме энергосбережения — 30 fps [документация Lenis].

## 6. SEO и доступность

### 6.1. SEO
- Весь смысловой текст, заголовки, цены, характеристики — в **исходном HTML** (не в canvas, не только после JS):
  ИИ-краулеры не исполняют JS (Web Almanac 2025 со ссылкой на Vercel) [исследование]; текст в canvas не индексируется и
  не становится LCP [проверено].
- 3D-модель товара для Google Shopping/Search — атрибут `virtual_model_link` (Merchant) или разметка schema.org
  (`Product.subjectOf` → `3DModel` → `encoding.contentUrl` на .gltf/.glb); модель доступна краулеру (robots.txt),
  валидна по Khronos glTF-Validator; модерация до 2 недель [документация Google].
```html
<!-- schema.org 3DModel — пример Google Merchant (разметка) [документация, не проверено валидатором] -->
<script type="application/ld+json">
{"@context":"https://schema.org/","@type":"Product","name":"Банка 355 мл","image":"https://example.com/can.jpg",
 "subjectOf":{"@type":"3DModel","encoding":{"@type":"MediaObject","contentUrl":"https://example.com/can.glb"}},
 "offers":{"@type":"Offer","price":"19.00","priceCurrency":"USD","availability":"https://schema.org/InStock"}}
</script>
```
- WebGL-текст для эффектов — только как дубль прозрачного, но существующего HTML-текста (Codrops 2025-06-05) [практика].

### 6.2. Доступность (кратко; полностью — `../../ux/08-accessibility/`)
- Декоративный canvas: `aria-hidden="true"`, без фокуса; информация не только в 3D.
- Интерактивный просмотрщик: фокусируемый, подпись (`alt` у model-viewer, `aria-label` у своего), клавиатура (стрелки —
  встроены в model-viewer), видимый фокус; жесты перетаскивания не единственный способ (кнопки поворота) — WCAG 2.5.7.
- Движение: петли > 5 с — пауза/стоп (WCAG 2.2.2); не более 3 вспышек/с (2.3.1); reduce (§5.3).
- Текст поверх 3D — на сплошной подложке или с достаточным контрастом при любом кадре сцены (NN/g: текст на
  изменчивом фоне нечитаем) [исследование].
- AR-кнопка — с текстовой подписью «View in your space / Посмотреть у себя» (NN/g: иконки AR непонятны) [исследование].

  --quick` (Chromium 153, WebGPU включён; см. `04-reference-sites-measured.md` §1).
- Пороговые значения (позиция базы для продуктового лендинга): LCP-элемент — HTML/постер; вес ≤ 3 МБ (телефон);
  TBT страницы целиком (CPU×4) ≤ 600 мс, вклад 3D ≤ 300 мс (§3.1; ворота `../09-web-runtime/05-performance-a11y-fallbacks.md` §7.2); draw calls в покое ≤ 30 (телефон); при reduce — 0 draw calls в покое; 0 ошибок консоли; canvas на
  телефоне ≤ 1,5 × CSS-размер.
- Ограничения лаборатории: headless не заменяет полевые CWV (CrUX/RUM, `web-vitals` `onLCP/onINP`) [документация web.dev].

## Частые ошибки

- Считать, что 3D «портит LCP»: canvas не участвует в LCP; LCP портят прелоадеры поверх H1 и тяжёлые постеры на весь
  экран (которые к тому же исключаются как фон) [проверено].
- Грузить three и GLB в `<head>` синхронно — долгие задачи до первого взаимодействия (TBT, INP).
- Постер из Blender с процедурным материалом, а GLB без него — «подмена» при появлении 3D [проверено].
- Один GLB на веб и AR (Draco/KTX2 ломают Scene Viewer) [документация].
- Draco-декодер ради модели на 50 КБ (декодер ≈ 58 КБ br) — выбирать Meshopt [проверено].
- Верить «+94 % конверсии» как прогнозу — самоотбор [мнение вендора].
- Решать «3D или нет» только по detect-gpu: iPhone всегда tier 1 FALLBACK, встроенная графика бывает завышена [проверено].
- Бесконечный цикл рендера без движения и при reduce, рендер в скрытой вкладке [проверено: 25 из 33 сайтов].
- Полный DPR 2,6–3 на телефоне [проверено: Spline — TBT 1,9 с].
- Нейросеть по памяти: `THREE.Clock` (устарел с r183, есть `Timer`), `renderer.outputEncoding = sRGBEncoding` (удалено;
  `outputColorSpace`), `RGBELoader` (устарел с r180, `HDRLoader`), `physicallyCorrectLights` (удалено) → `03-runtime-landscape.md` §2.

## Открытые вопросы и противоречия

- Нет рандомизированных исследований «3D на сайте vs фото» с продажами; единственное полевое — AR в приложении
  косметики (Tan и др. 2022). Нужен поиск в CHI/JMR 2023–2026 — задача волны 3 (J) или отдельного агента.
- Позиция бюджета §3.1 — синтез (документация платформ + замер лидеров + лабораторный паттерн); порогов на реальных
  телефонах среднего класса нет → волна 2 (F) и 3 (J): стенд с реальными устройствами или BrowserStack.
- Текстуры: Scene Viewer (2048²) против Merchant («4K лучше всего, до 8K») — документы Google противоречат.
- Эвристика Chromium «полноэкранный элемент = фон» может измениться; Safari и Firefox LCP считают иначе (Safari — с 2025
  частично) — не проверено.
- Батарея/нагрев не измерены (headless без датчиков) — опора на практику.
- Влияние WebGPU на TBT/INP (компиляция пайплайнов) не измерено; в выборке только 2 WebGPU-сайта.
