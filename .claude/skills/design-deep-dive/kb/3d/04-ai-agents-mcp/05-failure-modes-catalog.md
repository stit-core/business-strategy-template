## Выжимка для агента

1. **Исполнимость зависит от модели на порядок, форма — нет**: haiku — 8 из 8 скриптов с исключением, sonnet и opus — 0
   из 8; но годных по рендеру у sonnet 1 из 8. → §1 `[проверено]`
2. **«Исполнилось» — не проверка**: главный класс ошибок сильных моделей — масштаб, кадр, стыки и экспортируемость, не
   API. → M6.1 `[проверено: 11]`
3. **Масштаб в реальных метрах**: кружка у трёх моделей 1,4–2,2 м, телефон 1–2,9 м, ракета 5,7 м (×10–25). Детектор —
   габарит ассета против паспорта. → M2.1 `[проверено: 11, 16]`
4. **Парящие и отделённые детали** — у sonnet камера телефона вне корпуса, три плиты ноутбука висят в воздухе (экран в
   0,451 м от основания). Детектор — зазор пар частей по BVH. → M2.2 `[проверено: 11, 16]`
5. **Поворот вокруг своего центра вместо оси** (крышка ноутбука) разрывает сборку. → M2.4 `[проверено: 11]`
6. **Камера углами Эйлера «на глаз»** — объект вне кадра у haiku 3/3, обрезан у sonnet 7/8; opus с `to_track_quat` — 0/8.
   Детектор — проекция габаритов в кадр. → M3.7 `[проверено: 10, 11]`
7. **Логотип `text_add` лежит в плоскости XY** — спереди видно ребро; поворот на 90° по X обязателен. → M2.12 `[проверено: 11]`
8. **`transform_apply(scale=True)` применяет и location, и rotation** (умолчания оператора True; проверено в 5.2.2) — все pivots в нуле мира. → M2.9 `[проверено: 11]`
9. **`join` после `materials.append` без индексов граней** — всё одного цвета (дерево haiku коричневое целиком). → M4.9 `[проверено: 11]`
10. **`materials.clear()`/`pop()` обнуляют `material_index`** — сначала слоты, потом индексы. → M1.10 `[проверено: 12]`
11. **Процедурные материалы не доходят до GLB**: градиент экрана из ColorRamp (opus), thin film, displacement. → M4.1 `[проверено: 04, 11, 12]`
12. **Вход `Emission` (3.x) вместо `Emission Color`** уронил 3 из 8 скриптов haiku посередине — без света и камеры. → M1.2 `[проверено: 11]`
13. **Ноды по локализуемому имени** — `nodes["Principled BSDF"]` в 23 из 24 скриптов; на русском интерфейсе — None/KeyError
    (агент B). → M1.3 `[проверено: 11; B/15]`
14. **Скрипт стирает сцену пользователя без спроса**: `select_all` + `delete` (haiku, sonnet — 16 из 16), удаление
    **всех** объектов файла (opus — 8 из 8), `orphans_purge` (haiku 8/8). → M6.6 `[проверено: 11]`
15. **Cycles «для красоты»**: 24 из 24 скриптов ставят CYCLES; без числа сэмплов — 4 096 (sonnet), 1920×1080 ×128 (opus) —
    вызов MCP рискует превысить 180 с. → M6.7 `[проверено: 11]`
16. **Тёмный «киношный» фон (0,01–0,05)** у sonnet 8/8 — не совпадает со светлой страницей. → M3.6 `[проверено: 11]`
17. **Цвет: числа sRGB как линейные** — (0,85; 0,35; 0,25) в AgX выглядит бледно-розовым, а не терракотой; hex → линейный

18. **Суп из примитивов без фасок** — «компьютерный» вид; флаги `raw_sharp_edges` у 20 из 24 сцен по старому аудиту (с ложными: торцы в стенке, мелкие линзы, low-poly); по уточнённому правилу J — 11 из 32, 0 из 8 протокольных. → M3.1–M3.2 `[проверено: 10, 11]`

20. **`sys.exit()` в коде закрывает Blender пользователя без сохранения**; `KeyboardInterrupt` глушит мост. → M7.1–M7.2 `[проверено: 09]`
21. **«Communication error with Blender» ≠ сбой связи** — это исключение в коде. → M7.3 `[проверено: 14]`
22. **Проверка снимком вьюпорта** — чужой ракурс, в фоне серые материалы. → M6.2 `[проверено: 04]`
23. **Повтор шага после ошибки плодит дубли** (`Ceramic.001`, `Mug.001`) — идемпотентный `build(P)`. → M6.5 `[проверено: 05]`
24. **Экспорт без сжатия и с лишним**: куб 12 треуг. с текстурой 1k — 2,27 МБ; комната — 29 вызовов отрисовки; после
    `gltf-transform` — 326 КБ и 3 вызова. → M5.2–M5.3 `[проверено: 04, 15]`
25. **Инструменты с чтением файлов по пути от модели** (Hunyuan `input_image_url`, Rodin `input_image_paths`) — канал утечки
    при инъекции промта; CVE-2026-10661 не исправлена в 2.0.3. → M7.6 `[проверено: 13]`

## 1. Как собрана эмпирика

**«Первая попытка» (C1/11).** Три субагента-модели Claude (haiku, sonnet, opus; сентябрь 2026) без контекста базы и без
инструментов получили одинаковый промт: «ИИ-ассистент дизайнера, `execute_blender_code`, Blender 5.2.2, сцена по
умолчанию; 8 независимых скриптов (mug, phone, tree, rocket, sculpture, laptop, logo NOVA, room): модель, материалы, свет,
камера для рендера и GLB». Каждый скрипт исполнен как `execute_blender_code` (заводская сцена, `exec(code, {"bpy": bpy})`,
`redirect_stdout`), затем .blend, аудит (`scene_audit.py`), экспорт GLB, рендер из камеры сцены (≤640 px, ≤32 сэмплов),
4 студийных ракурса `render_views.py`, габариты без служебных объектов [проверено].

**По протоколу (C1/12).** Те же 8 объектов: паспорт, идемпотентный `build(P)` на проверенных функциях, аудит, рендер,
критика, правка; затем GLB, валидатор, браузер [проверено: 12].

**M1.9 — `transform_apply` переносит начало координат.**

```python
# Blender 5.2.2 — [проверено]
import bpy
bpy.ops.mesh.primitive_cube_add(size=1, location=(0.6, 0.6, 0.35))
ob = bpy.context.active_object
ob.scale = (0.6, 0.4, 0.03)
# антипример: bpy.ops.object.transform_apply(scale=True)  → location становится (0, 0, 0): все три флага по умолчанию True
bpy.ops.object.transform_apply(location=False, rotation=False, scale=True)
print(tuple(ob.location), tuple(ob.scale), tuple(round(d, 3) for d in ob.dimensions))   # (0.6, 0.6, 0.35) (1, 1, 1) (0.6, 0.4, 0.03)
```

**M4.9 — `join`, затем слоты без индексов граней.**

```python
# Blender 5.2.2 — [проверено]
import bpy
bpy.ops.mesh.primitive_cylinder_add(radius=0.1, depth=1.0, location=(0, 0, 0.5)); trunk = bpy.context.active_object
bpy.ops.mesh.primitive_ico_sphere_add(radius=0.5, location=(0, 0, 1.3)); crown = bpy.context.active_object
for o in bpy.context.selected_objects:
    o.select_set(False)
trunk.select_set(True); crown.select_set(True); bpy.context.view_layer.objects.active = trunk
bpy.ops.object.join()
trunk.data.materials.append(bpy.data.materials.new("Bark"))
trunk.data.materials.append(bpy.data.materials.new("Leaves"))
for p in trunk.data.polygons:                     # без этого цикла вся модель — первого материала
    p.material_index = 1 if p.center.z > 0.85 else 0
print(sorted({p.material_index for p in trunk.data.polygons}))   # [0, 1]
```
Лучше — не сливать части с разными материалами, а держать их отдельными объектами коллекции ассета.

## 13. Частоты и сверка с исследованиями

Наши 24 скрипта — малая выборка; исследования (по разбору C2, `03-research-llm-3d.md`) дают фон для приоритетов.

| Наблюдение C1 (24 скрипта) | Что говорят исследования (по C2) | Приоритет проверки |
|---|---|---|
| исключения: haiku 8/8, sonnet 0/8, opus 0/8; все 8 падений — API 3.x или выдуманный API | 3DCodeBench (Blender 5.0, 12 моделей): однопроходная исполнимость 0,46–0,91; ~90 % отказов — несовпадения API версии; 2 повтора по traceback → 0,974 | повтор по трассировке ≤2 раз; справка 5.2 (M1) |
| исполнилось, но негодно: sonnet — 8 из 8 скриптов без исключений, годен 1 | «исполнимость ≠ форма»: агентная оболочка поднимает исполнимость до 0,973 без роста качества формы | рендер + утверждения обязательны (M6.1) |
| парящие детали (sonnet: телефон, ноутбук, полка) | главный дефект у всех 12 моделей — оторванные и парящие части; у Opus 4.7 «простые парящие примитивы» при лучшей исполнимости | зазоры пар частей (M2.2) — первым |
| масштаб ×10–25 у всех трёх моделей | кластер отказов «правдоподобные пропорции при неверных размерах»; двойное масштабирование (3D-PreMise) | габарит против паспорта (M2.1) |
| камера «на глаз» у слабых моделей, у opus — по `to_track_quat` | камера и свет — самые трудные домены правок (EZBlender) | проекция в кадр (M3.7) |
| процедурные материалы (градиент экрана, thin film) у opus | шейдерные графы >22 нод теряют валидность; процедурное в веб — только запечённым | аудит `procedural_textures`, браузер (M4.1) |
| стирание сцены пользователя в 24 из 24 скриптов | промты бенчмарков требуют «очистить сцену» — модели переносят это в работу с чужой сценой; `prompts.yml` Blender Lab: «не изменяй разрушительно без подтверждения» | своя коллекция, контрольная точка (M6.6) |

Порядок проверки по стоимости и частоте: (1) исключение → трассировка; (2) габарит и зазоры (утверждения, < 1 с);
(3) кадр (аудит); (4) рендер камеры и 4 ракурса (2–10 с); (5) экспортируемость и бюджет (`gltf_check`, `web_view`);
(6) эстетика по рубрике `04 §7`.

## Частые ошибки

(при работе с этим каталогом)
1. **Лечить симптом флагом**: снять `interpenetration`, сдвинув часть, хотя стык был верным (ручка в стенке) — сначала
   рендер.
2. **Считать отсутствие исключений проверкой** — M6.1.
3. **Путать масштаб объекта и размер ассета**: исправлять M2.1 масштабом объекта создаёт M2.10.
4. **Чинить M3.7 сдвигом объекта** — объект уезжает из начала координат; двигать камеру.
5. **Копировать фрагмент 3.x из интернета при M1.2** — таблица дрейфа B.
6. **Перепроверять API памятью модели** — `bpy_probe.py`/`bpy_api_lookup Type.prop`.

## Открытые вопросы и противоречия

- **Выборка мала**: 8 объектов × 3 модели, по одному прогону; разброс между прогонами одной модели не измерен.
  Частоты — ориентир, не статистика. Исследования (3DCodeBench, 12 моделей × 212 категорий) дают согласующуюся картину:
  главный дефект формы — парящие части, исполнимость и форма не связаны (C2 `03 §2.2`).
- **Годность «по рендеру» оценена мной** (один оценщик, без попарного судьи и людей) — `[мнение C1]`.
- **Порог «касается» 1 мм** и «габарит ±5 %» — выбраны, не откалиброваны.
- **opus писал 56 минут** на 8 скриптов с самописной библиотекой — это не «первая попытка» в интерактивном смысле;
  sonnet — 35 минут; сравнение по времени некорректно.
- **Эффект локализации (M1.3)** проверен агентом B в фоне; у пользователя интерфейс не проверялся.
- **M5.1 (ориентация)** в эмпирике не встретилась — правило по документации экспортёра (агент E).
