### A4. Рубрика «эффектности» K (`CR/09-ai-execution-evaluation/04-effectiveness-rubric.md`, `effectiveness.rubric.json` v0.1)
- **Порядок:** сначала ворота — любой провал B означает «не принимается». Потом профиль из 5 критериев: concept, craft, motion, uniqueness, clarity.
- **Как ставится балл:** судья отвечает только A / B / ничья / оба плохи в паре. Балл выводится из доли побед: ≥ 0,75 → 4; ≥ 0,75 и против якоря L2 → 5; 0,4–0,75 → 3.
- **craft у страниц с 3D** — меньшая из двух подоценок: «типографика и композиция» и «ремесло медиа» (`criteria.craft.sub.media`, введено по X-63). Якоря ремесла медиа: 3 — «Звено» v1, 4 — «Звено» v2, 5 — мир hubtown и Illoca.
- **Проход L2:** все критерии ≥ 3; concept ≥ 4 и motion ≥ 4; против якорей L2 своего класса — победа или ничья минимум в 2 из 3 (concept, craft, motion). Якоря L2: unseen.co, illoca.unseen.co, hubtown.co.in, lisa.locomotive.ca.
- **Процедура:**
  - каждая пара — в двух порядках, расхождение считается ничьей; 10 % пар повторяются;
  - motion оценивают `motion_check.py` и человек по записи, не VLM;
  - калибровка — заказчик и не меньше 2 дизайнеров, 20–30 пар;
  - VLM-судье можно доверить сортировку, только если его согласие с заказчиком ≥ 0,8 (нижняя граница Уилсона ≥ 0,65, n ≥ 20).
- **Опыт K/03 [П]:** судья-агент узнаёт известные сайты, поэтому его 100 % согласованность — не доказательство.

Прочие пробелы:
- **Нет реальных устройств.** Телефон, Safari и Firefox не мерились — только эмуляция CPU ×4 и WebKit в Playwright.
- **Нет слепой оценки людьми.** Ни одна 3D-пара не оценена вслепую. Нет опыта «та же сцена кодом против ассета из Blender» (J № 4) — это главный недостающий опыт.
- **Не внесены предложения J2 (§11.8):** у `3d-scene` в `effects.yaml` нет варианта «световой проход кодом» и его цены; в `BR/12-recipes/01-hero-product.md` нет ветки «студия кодом без HDRI».
- **Нет L2-примера «бренд без продукта» кодом.**
- **Нет уровней качества по устройству.** У Shopify их 4; у ZERO качество адаптивно снижается при кадре около 22 мс [S24, S25].
- **Слепая зона ворот на WebGPU.** `motion_check.py` перехватывает только вызовы WebGL — на WebGPU покой будет «чистым» ложно. Перехват `GPURenderPassEncoder.draw*` уже есть в `site_probe.py` и `fx_probe.py`.
- **Конфликт ворот с временными приёмами.** TRAA, временной GTAO и накопление сходятся за несколько кадров после остановки, а `motion_check` снимает счётчик на +0,5 с. Нужна норма «накопление ≤ 0,45 с» или исключение из ворот.
- **Переход на WebGPU ломает текущий код:** скан на `onBeforeCompile` и пост на pmndrs. Кроме того, pmndrs 6.39.5 не примет r187.
- **Нет детерминированных кадров** (фиксированные время и зерно шума) для попарной оценки. Звук не рассматривался.

## C. Топ-10 приёмов кодом: «вау на рубль»

Вау / цена / риск — по шкале 1–5:
- **вау** — ожидаемый прирост concept, craft или motion;
- **цена** — КБ, мс кадра, агент-часы;
- **риск** — клише, доступность, откат, зрелость.

Цена и условия по пунктам:
1. **Студия v3:** +0–2 КБ br, около +0,1–0,3 мс; подходит для L1 и L2. На телефоне — как у v2: без тени, Standard.
2. **Интерактив:** своя IK — 0 КБ; кадры рисуются только при вводе, ворота покоя сохраняются. Для клавиатуры и тача нужна альтернатива или автопоказ; в reduce — станции.
3. **Мир вокруг:** +1 рендер сцены в четверть пикселей — по оценке +0,3–0,8 мс, не замерено. На телефоне пол без отражения.
4. **AO:** на Iris Xe в половине разрешения ожидаю 1–3 мс (оценка по 0,3 мс на RTX 2080). Нужны MRT с нормалями. Временной фильтр конфликтует с зондом покоя (см. B).
5. **Bloom и финиш:** 1,9 мс по нашему замеру pmndrs. На телефоне — только CSS-зерно (0,63 мс). Клише `neon-glow` уже снято решением d-glow: свечение — функция продукта.
6. **Микродеталь:** сборку — в задачи подготовки сцены; держать ≤ 50/100 тыс. треугольников (сейчас 15,5 тыс.). Главная цена — агент-часы.
7. **Процедурная фактура:** нужен `WebGPURenderer` или дубль на GLSL в `onBeforeCompile`; программы компилировать через `compileAsync`.
8. **Объём:** фальшивый — около 0,1–0,3 мс; настоящий не замерен и требует WebGPU. Дымка должна двигаться только от прокрутки, в reduce — один кадр.
9. **Составной переход:** второй рендер нужен только на время перехода. Ограничения ворот: EG-CHOR-01 (не больше 6 «вау»-переходов на L2) и вспышки.
10. **Частицы:** WebGPU-сборка +≈ 60–85 КБ br; откат — морфинг (40 тыс. точек — 1,06 мс [П]). Клише `particle-swarm` допустимо, только если частицы несут смысл.

Вне десятки (дорого или узко):
- **SSGI и SSR** — 8–14 мс даже на RTX 2080; годятся для постеров, не для живого кадра.
- **three-gpu-pathtracer** — постеры и станции без Blender, офлайн.
- **`LightProbeGrid`** — запекание статичного окружения в браузере (WebGPU); кандидат заменить запекание в Blender (гипотеза D4).
- **Стекло, дисперсия, иридесценция** — высокий риск клише.
- **SDF-«жидкое стекло» и метаболы** — хороши для бренда без продукта.
- **Сплаты** — нужна съёмка; Spark весит 744 КБ br.
- **Rapier** — wasm 0,5–2,4 МБ.
- **Ткань и жидкость на compute** — только WebGPU.
- **3D-текст** — только как дубль HTML.
- **Звук** — выключен по умолчанию.

## F. Как мерить «вау» в испытании

Рабочее определение на рубрике K, без новых шкал:
1. **Годность.** Ворота без B (site, `motion_check`, `marketing_audit`), бюджет L2 (JS 3D ≤ 250/350 КБ br, 3D первого экрана ≤ 0,8/1,5 МБ), 0 вызовов в покое. Reduce и отсутствие WebGL — станции-картинки.
2. **«Вау» страницы — правило прохода L2 по голосам людей.**
   - Все критерии ≥ 3; concept и motion ≥ 4.
   - Против якорей класса — победа или ничья минимум в 2 из 3 (concept, craft, motion).
   - Якоря: illoca.unseen.co (история продукта) и hubtown.co.in (мир).
   - Плюс 3 референса класса «запуск продукта» — например, oryzo.ai, shopify.com/editions/spring2026, apple.com/macbook-pro.
   - Все кадры снимаются нашим инструментом в той же кодировке; ворота «Enter» у якорей — после клика.
3. **Ремесло медиа.** Цель дороги «код» — 5, то есть ничья с hubtown и Illoca. Нынешнюю «4» у v2 сначала нужно подтвердить людьми.
4. **Пики.** Каждый пик (разборка и сборка, скан, первое движение) — отдельная пара листов кадров. «Вау» есть, если не меньше 2 пиков выиграли у якоря или сыграли вничью.
5. **Запоминаемость** — это якорь 5 рубрики («пересказывается одной фразой»). Через сутки судья пересказывает страницу одной фразой. Засчитывается, если названы продукт и главный приём; порог — доля ≥ 60 %. Это гипотеза, её нужно откалибровать.

Судьи:
- Решающий голос — заказчик; плюс не меньше 2 дизайнеров, вслепую.
- Каждая пара — в двух порядках, расхождение считается ничьей.
- Сессии по 10–15 минут; 20–30 пар на круг. Чтобы различить 70/30, нужно 50–70 голосов — это 3 судьи × 20 пар.
- Motion оценивают только люди — по парам записей по 10 с. `motion_check` — ворота, а не мера «вау».
- VLM-судья только отсеивает брак — и только после согласия с заказчиком ≥ 0,8. Агент-автор не судит.

Круг испытания — 5 вариантов: v2; «код v3» (приёмы 1–9 из C); «гибрид v3» (Q/15); Illoca; hubtown. Пары для людей:
- v3 против v2;
- v3 против Illoca;
- v3 против hubtown;
- гибрид против v3;
- гибрид против hubtown.

Что считать успехом:
- **Минимум:** люди подтверждают, что v2 проходит правило L2 против Illoca и что ремесло медиа ≥ 4.
- **Цель:** «код v3» проходит правило L2 против hubtown при 3D первого экрана ≤ 1,5 МБ и воротах 0/0/0.
- **Решение по дорогам:** если гибрид выигрывает у v3 по craft с долей ≥ 0,75 — Blender обязателен для L2-продукта; при доле 0,4–0,75 — решает бюджет; ниже 0,4 — дороги «код» достаточно.
- **Воспроизводимость:** не меньше 2 из 3 свежих прогонов агента по рецепту проходят пункты 1–2.
- **«Вау на рубль»** — для ранжирования приёмов:
  - числитель — прирост доли побед против v2;
  - знаменатель — цена в единицах: 1 единица = 1 мс кадра на Iris Xe (DPR 1,5) = 50 КБ br = 0,5 МБ ассетов = 2 агент-часа;
  - приём попадает в выжимку, если отношение ≥ 0,1 и ворота не провалены;
  - веса единиц — гипотеза, их нужно откалибровать.
