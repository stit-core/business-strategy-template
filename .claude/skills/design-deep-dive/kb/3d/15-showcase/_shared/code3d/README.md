# `_shared/code3d` — общий код 3D «Звена»: сцена «код v3» + гибридный крюк (модули из GLB)

Пишет только дорожка CD (KIT §1). Потребители: страница **A** `zveno/a-code/` (чистый код) и страница **C** `zveno/c-hybrid/`
(ассет Blender дорожки Z + всё живое кодом). three **0.186.0** (npm-trial, WebGLRenderer), postprocessing 6.39.5, n8ao 2.0.1, esbuild 0.28.2.
Состояние: **крюк v1 готов 25.09.2026 ≈ 20:43** (проверен на `99-raw/experiments/Z/out/web_lean/j2.glb`, лист `99-raw/experiments/CD/sheet-hook-glb.jpg`);
**крюк v2 (KTX2, начинка отдельным GLB) — 26.09.2026 00:34**, проверен на GLB всей руки Z (`zveno/c-hybrid/assets/zveno.glb`, KTX2 — `Z/out/c_web/zveno_ktx2.glb`).
Журнал версий — `CHANGELOG.md`.

## Выжимка для агента

1. Сборка страницы: `_shared/code3d/build.sh <страница>/js [--glb | --ktx2]` → `js/three-scene.js` + `js/chunks/` (три чанка: three, пост, GLB-загрузчик;
   с `--ktx2` — ещё чанк KTX2Loader, качается только для GLB с KTX2, и транскодер basis в `js/basis/`).
   **Без `--glb` крюка в бандле нет** (страница A не платит: чанк three байт в байт как в фазе 1). С `--glb`: +19,9 КБ br чанк загрузчика
   (GLTFLoader + MeshoptDecoder), +5,9 КБ br в чанке three. Итог JS: A 230,1 / 133,3 КБ br (десктоп/телефон), C 256,3 / 159,5 + сам GLB.
2. Включить гибрид — одна опция в `main.js`: `createScene(canvas, { …, glb: { url: 'assets/zveno.glb', lowUrl: 'assets/zveno-low.glb' } })`;
   v2: `innerUrl: 'assets/zveno-inner.glb', innerLowUrl: …` — начинка J3 отдельным файлом (после первого кадра, в простое).
   Модуль, найденный в GLB по имени, заменяет процедурный; ненайденные остаются кодом (можно подменять по одному — так проверен J2).
3. **Контракт GLB**: модуль = **пустышка** с именем `base | j1 | j2 | l1 | j3 | l2 | wrist | grip` (или extras `zveno_module`), точка пустышки =
   шарнир, оси = оси three (Y вверх), метры `scene.js`; геометрия — дети пустышки. Свой TRS пустышки код **отбрасывает** (позу ставит
   кинематика), так что GLB можно выгружать в любой позе. Роли материалов — по имени или extras `role` (таблица ниже).
4. Что делает код поверх GLB: кинематика и разнос, IK за курсором/касанием, студия PMREM по сценам (отражения), ключ/контровой, свет по сюжету
   (вспышка фиксации — LED и лак кольца **своего** модуля), пол-отражение, туман по высоте в материалах GLB, пост (bloom/тон/LUT/зерно/FXAA),
   скан-срез J3 по материалам GLB, маска для `img_metrics`. Что выключается: процедурная деталь заменённых модулей (винты, наклейки,
   риски, швы), **N8AO по умолчанию** (в GLB запечённый AO; вернуть — `glb.ao: true`), приём `texture` (материалы GLB не трогает).
5. Паритет: сцена разложена по модулям без изменения поведения — `look: 'p1'` без поста даёт **те же пиксели**, что бандл фазы 1
   (mean 0, max 0 на hero/locking/first-move/scan-half; маски — 0; вызовы/треугольники/программы — те же). `[проверено: CD/11]`

## API

`createScene(canvas, opts)` → `{ ready, resize(w, h, mobile), set(phase, t, instant), pointer(x, y), tap(x, y), ikBounds(minX, minY), intro(ms),
renderNow(), stop(), dispose(), stats(), mask(), flags, look, renderer }` — как у v2/v3, `main.js` страницы «Звена» подходит без правок
(кроме строки с `glb`). `stats().glb` — отчёт крюка (модули, меши, треугольники, роли, есть ли AO, габарит, предупреждения), `stats().modules` —
источник каждого модуля (`glb`/`code`).

| Опция | По умолчанию | Что |
|---|---|---|
| `context`, `dprMax`, `quality` | —, 1,5, `'high'` | как v2: `'low'` — телефон (Standard, без тени, зеркала, поста, винтов) |
| `flags` | всё, что влезает в качество | `{studio, ik, world, ao, fx, detail, texture}` — выключить приём (стенды: `?f=-ao`) |
| `look` | `'p2'` | `'p1'` — параметры фазы 1 (сверка), `'p2'` — доводка фазы 2 |
| `glb` | нет | `'url'` или `{ url, lowUrl?, only?: ['j2', …], map?: {j3: 'j2'}, materials?: 'glb' \| 'code', ao?: false, sides?: 'front' \| 'keep', innerUrl?, innerLowUrl?, ktx2?: true \| 'путь/basis/', ktx2Workers?: 2 }` (v2 — последние четыре) |

- `only` — брать из GLB только эти модули; `map` — модуль кода ← узел GLB с другим именем (проба: `{j3: 'j2'}` проверяет скан на GLB-материалах);
- `materials: 'code'` — геометрия GLB, материалы кода по роли + запечённый AO из GLB (опыт «что даёт геометрия, а что — материал»);
- `ao: true` — N8AO поверх запечённого AO; `sides: 'keep'` — оставить doubleSided из Blender (по умолчанию FrontSide: тыльные грани закрытых тел не нужны);
- v2: `innerUrl` / `innerLowUrl` (телефон) — начинка отдельным GLB (раздел «Крюк v2»); `ktx2: true` — качать транскодер параллельно с GLB (иначе — по
  требованию, когда в GLB найден `KHR_texture_basisu`), строка — свой путь к `basis_transcoder.js/.wasm`; `ktx2Workers` — воркеров транскодера (2).
- `stats().glb.load` — `{url, bytes, fetch_ms, parse_ms, ktx2}` основного GLB; `stats().glbInner` — отчёт начинки (`bytes`, `fetch_ms`, `parse_ms`,
  `total_ms`, `tris`, `layers`, `warnings` или `error`; `null` — ещё не пришла).

## Контракт GLB (что ждёт код)

| Что | Требование | Почему |
|---|---|---|
| узлы модулей | пустышка `base`, `j1`, `j2`, `l1`, `j3`, `l2`, `wrist`, `grip` (имя или extras `zveno_module`); меши — её дети | код ставит пустышке матрицу `T(разнос)·шарнир·R`; меш на самом узле модуля — предупреждение: его TRS (там может сидеть квантование) сохраняется, модуль должен лежать в начале координат |
| точка и оси | точка пустышки — шарнир; оси three (Y вверх; экспорт glTF +Y); метры `scene.js` | высоты шарниров в покое: j1 0,34 · j2 0,935 · j3 2,145 · wrist 3,115 · grip 3,415; `l1` = точка `j2`, `l2` = точка `j3` (звено висит на шарнире сустава) |
| вложенность | любая: вложенные модули, начинка, кабель открепляются | GLB можно выгружать одной иерархией руки |
| начинка J3 | узел `j3_inner` (или extras `zveno_inner`) в системе J3; дети по ролям; extras детей `spread` (м вдоль X при разведении), `spin` (доля угла ротора) | станции «скан»/«внутри»: слои разводятся и крутятся; без узла — начинка кода; вращающиеся детали — с началом на оси X |
| начинка отдельным GLB (v2) | `innerUrl`: файл, где есть узел начинки (как строкой выше; поиск — extras `zveno_inner` → имя `j3_inner` → имя `inner`, **корень сцены не считается**), слои j3in_* — его **прямые** дети; остальные узлы файла не используются; основной GLB — **без** начинки (если она там есть, `innerUrl` не качается, предупреждение в `stats().glb.warnings`) | начинка нужна только станциям «скан»/«внутри» — не в бюджете первого экрана; до её прихода в «скане» стоит начинка кода (заглушка) |
| кабель | узел `cable` (или extras `zveno_prop: 'cable'`) — ставится с мировой матрицей из GLB | процедурный кабель тогда выключен |
| роли материалов | extras `role` или имя: `led` (led/emit/glow), `decal` (decal/print/etch/label/lbl), `ring` (ring/lock), `shell`, `cap`, `alu` (alu/tube), `steel` (steel/screw/bolt), `rubber`, `copper`, `pcb`, `dark` (graph/dark/black/base/collar) | `led`, `ring` — свет по сюжету: у каждого модуля свой экземпляр (вспышка горит у одного); `decal` — без тени и не в зеркале |
| светодиод кольца | emissive + `KHR_materials_emissive_strength` | базовая сила = «под питанием»; вспышка × (1 + 6·вспышка), лак кольца на вспышке светится `#ff4d14` |
| сжатие | `EXT_meshopt_compression`, `KHR_mesh_quantization`, `EXT_texture_webp`, `KHR_texture_transform` — да; **KTX2 (`KHR_texture_basisu`) — да со сборкой `--ktx2`** (v2); Draco — нет | декодер meshopt — внутри чанка, транскодер basis — `js/basis/` своего домена, без сети; без `--ktx2` GLB с KTX2 — ошибка → модули кода (в консоль `info`, не `error`) |
| AO | `occlusionTexture` (любой `texCoord`) | N8AO по умолчанию выключен |
| постобработка gltf-transform | `--flatten false --join false --palette false` (или `gltfpack -kn -ke`) | иначе теряются узлы модулей и материалы по ролям (KIT §5) |
| телефон | `lowUrl` — свой GLB (сегменты ниже, AO 512²), Physical → Standard делает код | бюджет телефона: ≤ 50 тыс. треугольников, ≤ 0,8 МБ 3D первого экрана |

## Крюк v2 (26.09): KTX2 и начинка отдельным GLB — как включить и что мерили

**Как включить.**
```bash
_shared/code3d/build.sh zveno/c-hybrid/js --glb      # WebP (по умолчанию): начинка отдельным GLB работает и так
_shared/code3d/build.sh zveno/c-hybrid/js --ktx2     # + KTX2: чанк KTX2Loader (≈ 20 КБ br, только по требованию) и js/basis/ (213 КБ br)
# основной GLB без начинки + GLB начинки из готового GLB Z (валидатор Khronos 0/0; AO начинки — --inner-ao=keep|drop):
node 99-raw/experiments/CD/hook2/split_inner.mjs assets/zveno.glb assets/zveno-main.glb assets/zveno-inner.glb --inner-ao=drop
```
`main.js`: `glb: { url: 'assets/zveno-main.glb', lowUrl: 'assets/zveno-low-main.glb', innerUrl: 'assets/zveno-inner.glb', innerLowUrl: 'assets/zveno-low-inner.glb' }`
(+ `ktx2: true`, если основной GLB — KTX2 и транскодер нужно качать параллельно с ним).

**Как работает.** GLB качается `fetch`-ем, крюк заглядывает в JSON-чанк: есть `KHR_texture_basisu` → догружается чанк `ktx2.js` (один
KTX2Loader на страницу, 2 воркера, `detectSupport` — на Linux/Mesa three сам выключает эмулируемые ETC/ASTC, ETC1S идёт в BC7), после
последнего GLB воркеры закрываются. Начинка: `ready` собирает сцену с начинкой кода (заглушка), первый кадр рисуется, после него —
`requestIdleCallback` → GLB начинки → роли/туман/тени как у модулей → подмена в «большом» J3 (геометрия заглушки освобождается) →
программы «скана» компилируются в простое тем же целевым буфером. Если страница открыта сразу на «скане» (восстановление прокрутки) —
начинка ждётся до первого кадра (без подмены на глазах); переход на «скан» раньше простоя — загрузка сразу. Ошибка — начинка кода, в консоли `info`.

**Что мерили** (стенд `99-raw/experiments/CD/hook2/` — `hook2.html` + `hook2_run.py`, раздача `serve_br` «как хостинг», br, холодный кэш;
Chromium 153 headless, ANGLE GL, Intel Iris Xe; десктоп 1440×900 DPR 1,5 high, телефон-режим 412×915 DPR 1,25 low). Вес и память — точные;
время — см. строку «тишина».

| Вариант (GLB Z 25.09 21:30) | Сеть 3D, КБ br: GLB + начинка + транскодер + чанк | Память текстур GLB в GPU | Кадр «внутри» |

На реальной сети решает вес: на телефонном троттлинге (1,6 Мбит/с) +301 КБ br KTX2 — это ≈ +1,5 с до первого кадра, −62 КБ br основного

**Вывод для C.** Начинку — отдельным GLB (−119 КБ br первого экрана на десктопе, −62 на телефоне; начинка приходит через ≈ 50 мс после первого
кадра — задолго до «скана»). KTX2 на этом GLB (6 текстур, один атлас 2048²) по сети проигрывает (+301 КБ br: транскодер 213 КБ br дороже всей
экономии), первый кадр на месте +18…25 мс; выигрывает память GPU (−21 МБ, −74 %) и снимает длинную задачу 53–68 мс заливки атласа. Для страницы
с одним атласом — **WebP**; KTX2 окупается, когда атласов 2048² несколько (память, длинные задачи заливки) или транскодер уже в кэше (несколько
страниц сайта с KTX2).

## Вид фазы 2 (`look: 'p2'`, по умолчанию) — что изменилось против фазы 1 (`look: 'p1'`)

IK указывает на курсор у текста (цель поднята ≤ 1,95 м, до плеча ≥ 1,2 м, схват нацелен на указатель); кольцо — лак ниже сжатия Neutral +
узкая LED-полоса (атрибут `band` = uv.y пояска); вспышка — свет по сюжету 0,7 м над лаком, bloom 4 уровня r 0,45; студия «сборка» без тёплого
отражателя; кромка скана — оранжевая полоса + тонкое ядро; MSAA композитора выключен всегда. Для GLB: светодиод модуля (`led`) горит «под
питанием» базовой силой из GLB и × (1 + 6·вспышка) на фиксации, лак кольца GLB на вспышке — едва (0,02 от кода). Числа — `14-code-3d/01` §8.

## Вид фазы 3 (`look: 'p3'`, страница A) — что добавлено к p2

p3 = p2 + **контровой свет в дымке** (приём 8: светящийся эллипс R 1,9 м × 0,65 в 2,5 м за целью камеры, `GodRaysEffect` pmndrs — заслонение
глубиной сцены, радиальная свёртка в ½, плотность 0,5, ADD в HDR до тона; только десктоп с постом; сила 0 — эффект не считается) + **след
инструмента** (приём 10, `src/trail.js`: пунктир 96 точек с шагом 3,5 см по пути точки захвата, жизнь 0,4 с, только при движении руки —
IK и «первое движение»; телефон тоже). Параметры — `LOOKS.p3` в `scene.js` (подбор через `?lk=beamExp:0.12,…` на стенде `preview.html`).
Цена в тишине: +0,37 мс кадра десктоп (4,35 → 4,72), телефон 0; +2,6 КБ br десктоп / 1,1 телефон (`build.sh --no-beam --no-trail` — без них; `CD/out/kb.json`). Умолчание сцены —
**p2** (страница C не меняется без явного `look: 'p3'`). Подбор и числа — `14-code-3d/05-atmosphere-post.md` §3, `06` §2. `[проверено: CD/21, CD/22]`
