## Выжимка для агента

1. **Порядок**: тип страницы → секции (UX) → слоты → ступень лестницы дешевизны (текст → SVG → CSS/шейдер → картинка → видео →
   3D) → источник (генерация, правка реального, реальное, код, шаблон) → план ассетов YAML (§8) → D, E, N, K, J. ИИ — способ
   сделать картинку или видео, а не ступень → §1. [консенсус: ui 07/02 §1.2; мнение A]
2. **Слоты с частотой у лидеров** (43 сайта): hero с визуалом — 40, крупные картинки контента — 40, иконки SVG — 40, og:image —
   41, крупный CSS-градиент — 22, видимое видео — 20, логотипы клиентов — 15 (у SaaS/ИИ — 9 из 13), WebGL — 13, видео в hero —
   10, Lottie — 5, фото в отзывах — 4 → §2.1. [проверено: замер]
3. **ИИ уместен**: фоны, атмосфера, сцена без людей, текстуры, абстракция, иллюстрации фич и пустых состояний по паспорту
   стиля, фон вокруг **реального** товара, фон OG. **Нельзя**: лица клиентов и авторов отзывов, команда и офис, логотипы, товар
   «как есть», скриншоты интерфейса, текст кириллицей в пикселях → §2.1, `03-…` §1. [исследование; документация]
4. **Hero**: бокс ≈ 1,6:1 и 74 % первого экрана (медианы лидеров); мастер ≥ 2560 px (полноэкранный — 3840), AVIF/WebP, ≤ 150 КБ;
   **на телефоне — отдельный кадр 4:5 или 9:16** со своей зоной текста (так у 8 из 10 измеренных), ≤ 80 КБ → §2.2, §4. [проверено: замер]
5. **Hero — LCP-кандидат**: `loading="eager"`, `fetchpriority="high"`, CSS-фон — через `<link rel=preload>`; canvas LCP не бывает;
   hero, видимая часть которого равна вьюпорту, LCP не бывает никогда (LCP = H1; J/01 — 12 из 12 живых случаев), поэтому H1 со
   шрифтом тоже быстрый → §2.2. [проверено: замер; J/01; документация web.dev] [поправка X 24.09.2026: было «полноэкранный hero —
   в половине случаев не LCP» — `../10-web-integration/01-images-delivery.md` §4.1]
6. **Логотипы клиентов — настоящие SVG ≤ 30 КБ на ряд**; ИИ их не рисует → §2.3. [проверено: замер; практика]
7. **Фичи** — HTML-фрагменты UI или скриншоты; ИИ — серия иллюстраций/3D-иконок по эталону (`IMG-SERIES`), ≤ 120 КБ → §2.4. [проверено: замер; практика]
8. **OG — 1200×630 PNG/JPEG ≤ 300 КБ, текст — HTML-шаблоном** (рендер Playwright), ИИ — только фон; ключевое внутри 1100×530 → §2.7. [документация Facebook, ogp.me; консенсус вторичных для X]
9. **Фавиконы обычному сайту — 3 файла** (ico 32, SVG с тёмной темой, apple-touch 180); PWA — плюс манифест с 192, 512 и
   maskable 512 (зона 409 px); из векторного логотипа скриптом → §2.8, `../07-vector-svg-icons/03-icon-sets-and-patterns.md` §5.
   [практика: Evil Martians 21.01.2026; проверено: G/04] [поправка X 24.09.2026: было «набор из 6 файлов»]
10. **E-commerce**: галерея 4:5 или 1:1 из реальных пакшотов; ИИ — фон и сцена с контактной тенью; SSIM области товара ≥ 0,9 и
    ΔE ≤ 5 → §2.9. **Маркетплейс**: инфографика с кириллицей — шаблон HTML → PNG/WebP → §2.11. [спорно: пороги — позиция A, проверить в живой фазе]
11. **Форматы 2026**: AVIF + WebP; PNG — только мелкая прозрачность; SVG — логотипы и иконки; видео — H.264 MP4 (+ WebM первым
    `<source>`); GIF — нет; JPEG XL — только с 06.10.2026 (Chrome 155) и первым необязательным `<source type="image/jxl">` → §4.3.
    [документация caniuse, chromestatus; проверено: замер] [поправка X 24.09.2026: было «JPEG XL — нет» — H `08/04` §2, J `10/01` §1.3]
12. **`srcset`-лестница** 640…3840 (Next.js) и точный `sizes`; мастер hero — ступень 2K/4K самой модели, апскейл (Lanczos;
    генеративный — после проверки) до кодирования → §4.2. [документация Next.js; исследование WA 2024; проверено: H/02]
    [поправка X 24.09.2026: было «мастер 1–2 Мп апскейлить»]
13. **Движение — самая дорогая ступень**: петля 6–10 с, 1080p ≤ 1,5 МБ, телефон 720p ≤ 600 КБ, постер ≤ 120 КБ, пауза (WCAG 2.2.2),
    `prefers-reduced-motion` → постер без загрузки видео, `seam_ratio` ≤ 1,5 → §5. [проверено: A/02; документация W3C]
14. **Текст — HTML поверх кадра**; зона текста 35–45 % кадра, контраст ≥ 4,5:1 в самом слабом месте, иначе scrim; главный объект —
    в центральных 60 % мастера с запасом 10–15 % под кроп → §6. [документация WCAG; позиция A]
15. **Бюджеты**: первый экран ≤ 2,5 МБ десктоп / ≤ 1,5 МБ телефон, сессия ≤ 7/3 МБ, видео без клика ≤ 5/2 МБ (Q1 лидеров, а не
    медиана) → §7. [спорно: позиция A]
16. **План ассетов — YAML** (§8): бренд (токены, паспорт стиля, запрещённые маркеры), бюджеты, политика ИИ, слоты с вариантами
    (соотношение, размер, формат, max_kb, зона текста, фокус), движением, доставкой, приёмкой; два примера — SaaS и PDP. [мнение A]

## 1. Как пользоваться: от типа страницы к плану ассетов

Порядок для агента:

1. **Тип страницы** (§3) → типовая последовательность секций. Логика секций — UX (`../../ux/03-layout-placement/`,
   `../../ux/13-app-types/`); здесь только «какой визуал в какой секции».
2. **Слоты** каждой секции → карточка слота (§2): тип ассета, коды задач таксономии, соотношения и размеры (десктоп и
   телефон), движение, место под текст, бюджет веса, частота у лидеров (замер), где ИИ уместен.
3. **Лестница дешевизны** на каждый слот (ui 07/02 §1.2, дополнено для веба): текст → SVG/иконка → CSS-градиент или шейдер →
   картинка → видео → реалтайм-3D. Брать первую ступень, которая решает задачу слота; ИИ — способ сделать картинку или видео,
   а не ступень лестницы.
4. **План ассетов** (YAML, §8) — вход для спецификации ассета (D), маршрутизации (E, N), генерации и приёмки (K), доставки (J).
5. **Уместность ИИ** по слоту — из `03-ai-fit-trust-and-slop.md` §1 (люди, отзывы, товар «как есть», скриншоты — не ИИ).

Термины: **слот** — место на странице с ролью (hero, логотипы клиентов, фича); **ассет** — файл, который его заполняет
(картинка, видео, SVG, Lottie, шейдер); **информационная картинка** — показывает продукт, человека, результат, место
(на неё смотрят); **декоративная** — «оживляж» (её игнорируют — NN/g 2010, §2.2).

### 2.2. Hero

- **Что показывает**: продукт в деле (UI, товар, результат), место, человека (только реального) или бренд-абстракцию. Тип hero
  у лидеров (ручная разметка, 43 сайта): фото 11, видео live-action 5, скриншот UI 5, ИИ-изображение 5 (все — ИИ-компании),
  типографика 4, реалтайм-3D 4, рендер продукта 3, коллаж 2, иллюстрация 2, ИИ-видео 1, шейдер 1.
- **Геометрия (десктоп 1440×900)**: бокс hero — медиана 1,6:1 (Q1 1,5; Q3 2,0), занимает медиана 74 % первого экрана (Q1 46 %;
  Q3 99 %); полноэкранный (≥ 95 %) — у 12 из 40. Сплит «текст слева, картинка справа» — картинка ≈ 4:3–3:2, 600–800 CSS-px.
  Баннер-полоса e-commerce — до 4,6:1 (Ozon 1384×300).
- **Файл**: мастер ≥ 2560 px по длинной стороне (полноэкранный на 1440–1920 CSS-px при DPR 2 — 3840); `srcset` 640–3840
  (лестница Next.js: 640, 750, 828, 1080, 1200, 1920, 2048, 3840); отдаётся AVIF/WebP. Лидеры при DPR 1 получали медиану
  1440 px — ровно ширину экрана.
- **Телефон**: **отдельный кадр** 4:5 (1080×1350) или 9:16 (1080×1920) с собственной композицией — так у 8 из 10 измеренных
  сайтов (Allbirds `Desktop_16x9` → `Mobile_9x16`, Nike 828×1240, Практикум 960×1169, Seasats — мобильное видео 720×1280);
  бокс hero на Pixel 7 — 412×617–699 CSS-px (≈ 2:3).
- **Движение**: видео в hero — 10 из 43; петля 6–10 с, первый кадр = последний (`seam_ratio` ≤ 1,5), без звука, постер —
  первый кадр; на телефоне — картинка или облегчённая петля (Apple и Notion убирают видео на телефоне); `prefers-reduced-motion`
  → постер (§5).
- **Место под текст**: H1 и CTA — HTML поверх или рядом, не в картинке; зона под текст — спокойная (низкая детализация и
  контраст) на ≥ 35–40 % кадра, контраст текста ≥ 4,5:1 проверяется на реальном кадре (§6).
- **LCP**: hero-картинка — LCP-кандидат: без `loading="lazy"`, с `fetchpriority="high"` (или `<link rel=preload>` для CSS-фона);
  видимая часть hero = весь вьюпорт (100vh, под прозрачной fixed-шапкой) → LCP всегда H1 (правило Chromium; J/01 — 12 из 12
  живых случаев); hero меньше вьюпорта (шапка в потоке, `calc(100svh − 64px)`) → LCP — сама картинка; быстрый шрифт H1 — часть
  бюджета (`02-…` §5, `../10-web-integration/01-images-delivery.md` §4.1). [поправка X 24.09.2026: было «LCP может стать H1
  (7 из 12 полноэкранных)»]
- **ИИ**: ✅ атмосферный фон, сцена без людей, фон под скриншот (приём Cursor), абстракция; ⚠️ фото-сцена с продуктом — только
  композит реального пакшота (`IMG-EDIT`), с контактной тенью; ❌ «клиенты», «команда», сам товар, интерфейс.

### 2.3. Логотипы клиентов и партнёров

- 5–12 логотипов в ряд или бегущей строкой; монохром (цвет текста 40–60 % непрозрачности) или оригинальные цвета на
  нейтральном фоне; высота 24–40 CSS-px, выравнивание по оптическому весу, а не по высоте бокса.
- Формат — **SVG** (единицы КБ; ряд ≤ 30 КБ). У лидеров ряд весит медиану 59 КБ (Q1 22), Runway — 518 КБ PNG: антипример.
- Частота: 15 из 43 сайтов, у SaaS/ИИ — 9 из 13. Логотипы — **только настоящие и с разрешением**; ИИ не рисует и не
  «перерисовывает» чужие знаки (`VEC-TRACE` — только для собственного логотипа без исходника).

### 2.4. Фичи и «как это работает»

- Лидеры SaaS показывают **HTML-фрагменты интерфейса** (Linear, Notion — вёрстка, а не картинка) или скриншоты 16:10/4:3;
  схемы — SVG кодом; иконки — inline SVG (у 40 из 43 сайтов ≥ 5 иконок; медиана 42 на страницу).
- Картинка фичи: 560–800 CSS-px → файл 1200–1600 px, ≤ 120 КБ; телефон — та же картинка на 100 % ширины (360–412 CSS-px),
  `sizes` обязателен. Серия фич — единый стиль (`IMG-SERIES`): один ракурс, свет, фон, радиус (ui 07/02 §8.1).
- Короткие петли (UI-демо) — 3–8 с, `muted loop playsinline`, запуск при попадании в экран, пауза вне экрана.
- ИИ: ✅ иллюстрации и 3D-иконки по паспорту стиля (`IMG-ILLUSTR`, `IMG-ICON3D`), фоны карточек; ❌ «скриншоты» интерфейса.

### 2.5. Отзывы, кейсы, команда

- Отзыв = цитата + имя + должность + компания; фото 40–64 CSS-px (файл 128–192 px, ≤ 10 КБ). У лидеров фото в отзывах редки
  (4 из 43 по эвристике «≥ 2 круглых ≤ 160 px»: Cursor, Linear, Raycast, The Verge) — чаще логотип компании или только текст.
- Кейсы — фото клиента, объекта или результата (Stripe — аэрофото Hertz), цифры — текстом.
- «Команда», «офис», «производство» — настоящие фото. ИИ: ❌ лица, ❌ отзывы, ❌ «наш офис» (FTC 2024, ст. 50(4) AI Act —
  `03-…` §1.3, §3); ⚠️ фон обложки кейса без людей.

### 2.6. CTA-полоса, фоны секций, текстуры, подвал

- CTA-полоса и фоны — **CSS-градиент или шейдер** (0 байт картинок; крупный CSS-градиент есть у 22 из 43 сайтов), затем
  бесшовная текстура-плитка 256–512 px (≤ 30 КБ; зерно Linear — PNG поверх hero), затем картинка.
- Подвал — SVG-логотип, иконки соцсетей; тренд 2025–2026 — огромный вордмарк во всю ширину (Rylo, Cerebrium) — это текст/SVG.
- ИИ: ✅ абстрактные фоны и текстуры (`IMG-BG-ABSTRACT`, `IMG-TEXTURE`) с палитрой из токенов; проверить на пурпурный неон
  (IMG-M05) и «ИИ-глянец».

### 2.7. OG и соцсети

- **1200×630** (1,91:1) — 16 из 36 скачанных OG у лидеров; 2400×1260 (×2) — ещё 8. Facebook: минимум 200×200, крупная карточка
  ≥ 600×315, рекомендовано ≥ 1200×630, ≤ 8 МБ [документация Facebook]; X `summary_large_image`: 2:1, от 300×157 до 4096×4096,
  < 5 МБ, JPG/PNG/WebP/GIF [консенсус вторичных — docs.x.com переехал]. ogp.me: при `og:image` указывать `og:image:alt`,
  `:width`, `:height` [документация].
- Формат — PNG (графика, текст) или JPEG (фото), **не AVIF** (Weavy — единственный AVIF-OG в выборке); вес ≤ 300 КБ (медиана
  лидеров 132 КБ, Q3 324; Lightship — 8,4 МБ, антипример).
- Композиция: ключевое в центральной зоне (X может обрезать 1,91:1 до 2:1 — по 15 px сверху и снизу), текст ≥ 48 px на
  1200-ширине, логотип; **текст — HTML-шаблон, рендер Playwright** (Linear: `/api/og` генерирует PNG на лету), ИИ — только фон.
- Одна OG на страницу-шаблон (статьи, товары) — генерировать шаблоном; проверять адрес (Seasats — битый URL из склейки в шаблоне).

| Статика | по умолчанию; всё, что не выигрывает от движения | — | — |
| CSS-анимация, градиент | фоны, CTA, появление блоков | 0 байт | крупный CSS-градиент — 22 |
| SVG-анимация, Lottie (`VEC-ANIM`) | иконки фич, микро-иллюстрации, состояния | JSON/dotLottie ≤ 50–100 КБ | Lottie — 5 (Anthropic, Cerebrium, Lightship, Rylo, Weavy) |
| Синемаграф (`VID-CINEMAGRAPH`) | атмосфера без «событий»: пар, вода, листва в части кадра | как петля, но меньше движущихся пикселей → меньше КБ | — |
| Видео-петля (`VID-HERO-LOOP`) | продукт в деле, место, настроение | 6–10 с, 1080p ≤ 1,5 МБ, телефон 720p ≤ 600 КБ, постер ≤ 120 КБ | видимое видео — 20, в hero — 10 |
| Шейдер/WebGL (`VID-ABSTRACT` как альтернатива) | бренд-абстракция кодом (Stripe, Vercel) | JS ≤ 150–300 КБ | WebGL-контекст — 13, шейдер/3D-hero — 5 |
| Реалтайм-3D | продукт, который надо крутить | по 3d `02` §3.1 | 3D-hero — 4 |

Правила для любой ступени с автостартом [документация W3C; консенсус]:
1. Движение > 5 с, стартующее само, — **кнопка паузы** с доступным именем (WCAG 2.2.2); у лидеров — у 1 из 33 петель.
2. **`prefers-reduced-motion`**: включать движение в `no-preference` (а не выключать в `reduce`); при `reduce` — постер/статичный
   кадр **и не грузить видео** (у лидеров реагируют 4 из 16; Sunday замирает, но качает 60 МБ) — `../../ux/06-feedback-states-motion/03-motion-and-microinteractions.md` §7.
3. Пауза вне экрана (IntersectionObserver), `muted playsinline loop`, без звука; `preload="none"`/`metadata` для видео ниже
   первого экрана.
4. Петля бесшовна: `seam_ratio` ≤ 1,5 (или |Δ| ≤ 0,5/255 и ΔSSIM ≤ 0,005); монтажная — перезапуск на склейке (`02-…` §7.3).
5. Движение спокойное и непрерывное, без «событий» в фоне (VID-M18) и без «дрона по кругу» (VID-M07) — `03-…` §5.3.

## 6. Место под текст и безопасный кроп

- **Текст — HTML поверх или рядом**, никогда в пикселях картинки (кроме OG и инфографики, которые рендерятся шаблоном).
- **Зона под текст** задаётся в спецификации: сторона (слева / сверху / снизу / центр), доля кадра (35–45 % для hero), требование
  «спокойный фон» (низкая детализация и перепад яркости). На телефоне зона обычно сверху или снизу — поэтому отдельный кадр.
- **Контраст** проверяется на реальном кадре в самом слабом месте зоны текста: ≥ 4,5:1 для основного текста, ≥ 3:1 для крупного
  (WCAG 1.4.3); не хватает — подложка или затемняющий градиент (scrim) до нужного контраста (`../../ui/01-color/03-contrast.md`
  §6.2). Метрика: до вёрстки — альфа скрима по p99,9 яркости зоны, после вёрстки — F83 по худшему пикселю под буквами
  (`../06-art-direction-consistency/03-composition-for-web.md` §2.3, `../10-web-integration/03-text-over-media-and-effects.md` §1)
  [проверено] [поправка X 24.09.2026: было «к 95-му перцентилю яркости» — p95 проходит F83 лишь в 9 из 64 случаев]
- **Фокус и кроп**: мастер генерировать с запасом 10–15 % по краям (под кроп и `IMG-OUTPAINT`), главный объект — в центральных
  60 % кадра, если из мастера режутся 16:9, 4:5, 1:1 и 9:16; точка фокуса (x, y) пишется в план → `object-position` в CSS.
  Если объект в 60 % не помещается — отдельная генерация под телефон (так делают лидеры).
- **OG**: ключевое — внутри 1100×530 в центре 1200×630 (X режет до 2:1 — по 15 px сверху и снизу), текст ≥ 48 px.
- **Иконка maskable**: всё значимое — в круге 409 px из 512 (80 %) [S7].

## Частые ошибки

- **Генерировать hero без телефонного кадра** — обрезка 16:9 до 4:5 режет объект или текстовую зону; лидеры делают отдельный кадр.
- **Писать текст в картинку** (H1, цены, кириллица на упаковке) — модели ломают буквы (IMG-M12), текст не индексируется и не
  переводится → текст — HTML; OG и инфографика — шаблоном.
- **Ставить ИИ туда, где нужно доказательство**: отзывы, команда, офис, «скриншот» интерфейса, сам товар (`03-…` §1).
- **Выкладывать выход модели как есть**: PNG 1024² по 1–2,5 МБ в слот 194 px (Midjourney на своей главной) → кодирование и
  `srcset` обязательны.
- **`loading="lazy"` на hero** и отсутствие `fetchpriority="high"` — LCP 7–13 с у OpenAI и Linear.
- **Видео без постера, паузы и reduce** — у лидеров норма, у генератора — брак.
- **Картинка в каждой секции** — «оживляж» игнорируют (NN/g), он утяжеляет страницу и повышает шанс слопа; лестница дешевизны —
  сначала текст, SVG и CSS.
- **Логотипы клиентов PNG-файлами** (Runway — 518 КБ на ряд) или «нарисованные ИИ» логотипы.
- **OG в AVIF, OG 8 МБ, битый адрес OG** — всё это встречено у лидеров (Weavy, Lightship, Seasats).

### Ошибки нейросетей-агентов

- Размеры «по памяти»: фавиконы «16×16 и 32×32 PNG» или 20+ файлов из онлайн-генератора — актуален набор из 3 файлов, для PWA — плюс манифест с 192/512/maskable (§2.8) [поправка X 24.09.2026: было «из 6 файлов»];
  OG без безопасной зоны — X обрезает 1,91:1 до 2:1, ключевое держать в центральных 1100×530 (§2.7).
- `priority` у `next/image` — устарел в Next.js 16 (`preload` или `fetchPriority="high"`); `formats` по умолчанию — только WebP,
  AVIF надо включить (§4.2).
- «JPEG XL — современный формат» до 06.10.2026 (в Chrome 153 и Firefox по умолчанию выключен) и «JPEG XL не поддерживается»
  после 06.10.2026 (Chrome 155 включает по умолчанию) — обе ошибки; JXL только первым необязательным `<source>` (§4.3)
  [поправка X 24.09.2026].
- Генерировать hero одной картинкой 16:9 и резать под телефон — лидеры делают отдельный кадр (§2.2).
- Просить модель «добавить заголовок/цену на русском» — кириллица ломается; текст — HTML или шаблон (§2.7, §2.11).
- Писать в бриф «cinematic, epic, award-winning» вместо языка фотографии — даёт маркеры IMG-M02 и гомогенный стиль (`03-…` §7).

## Открытые вопросы

1. Частота слотов «фичи», «как это работает», «кейсы», «тарифы» в замере не считалась (эвристики нет) — нужна разметка секций
   (DOM-сегментация или VLM по контактным листам) — K или следующая волна A.
2. Бюджеты — позиция на 43 сайтах одного дня; для кампаний и e-commerce выборка мала (4 e-com, 2 Apple).
3. Порог «2× DPR достаточно» не проверялся слепым сравнением на ретине и телефоне DPR 3.
4. Шейдер-hero против картинки-hero для LCP и INP на слабом телефоне — нет своего замера (есть у 3d для 3D).
5. Требования маркетплейсов (Ozon, Wildberries) к инфографике карточек — не собраны (M, L).
