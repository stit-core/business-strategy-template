## Выжимка для агента

1. **LCP видео-hero — картинка-постер в `<picture>`**, видео — слой поверх после `load` и простоя (`js/hero-video.js`):
   LCP 124 мс десктоп / 100 мс Pixel 7 без троттлинга, 616 / 496 мс при CPU×4 + 1,6 Мбит/с → §3 `[проверено]`.
2. **Постер = декодированный кадр 0 финального AV1, через PNG → Pillow → AVIF** (36 КБ 1080p, 10 КБ 4:5 720): подмена без
   скачка (ΔE00 постер↔кадр 0 в странице — медиана 1,0–1,2); кадр мастера вместо кадра 0 сдвигает рябь (11 % пикселей > 3)
   → §3.1 `[проверено]`.
3. **Цвет: кодировать с ПОЛНЫМИ тегами BT.709** (`setparams=color_primaries=bt709:color_trc=bt709:colorspace=bt709:range=tv`) —
   тогда ΔE00 ≤ 1,23 во всех путях Chromium; без тегов HD H.264 уходит на 7,8, AV1 — на 7,9 в GPU-пути; `-colorspace bt709`
   в ffmpeg 7.1 пишет только матрицу — ошибка 7,2–7,4 → §2 `[проверено]`.
4. **Постер не делать `ffmpeg … poster.webp/.jpg` напрямую** (ΔE00 6,7–7,4: YUV уходит в WebP/JPEG как BT.601) и не отдавать PNG
   ffmpeg как есть (пишет cICP + gAMA, Chrome «тонирует» — 2,7–3,7) → §2.2 `[проверено]`.
5. **Источники: AV1 первым, H.264 всегда**; HEVC в Chrome на Linux без аппаратного VAAPI не играет ни в одной из 6 сборок Chromium, а
   с GPU-флагами `canPlayType` = «probably» при чёрном кадре — «probably» ≠ играет → HEVC только запасом альфы для Safari
   → §1 `[проверено: J/02; caniuse: HEVC 17,5 % полной поддержки, AV1 79 %]`.
6. **reduce, Save-Data, 2G → 0 байт видео**: JS не подставляет источники (`data-src`), `preload="none"`, без `autoplay` в HTML;
   смена «уменьшить движение» на лету — пауза и скрытие → §4 `[проверено]`.
7. **Вариант без JS — `<source media="(prefers-reduced-motion: no-preference) and (max-width: 699px)">`**: Chromium 153 выбирает
   по ширине и reduce, при reduce — 0 байт и постер; НО media не пересчитывается на лету, `poster` — один URL (на телефоне
   16:9-постер при 4:5-видео), кнопки паузы нет → минимум, не цель → §4.2 `[проверено]`.
8. **WCAG 2.2.2 — про длительность движения, а не длину клипа**: бесконечная петля 2 с «длится» > 5 с → кнопка паузы или стоп
   ≤ 5 с (флакон: 3 с + добег цикла, стоп на кадре 0, повтор по наведению/фокусу) → §5 `[документация W3C; проверено: J/06]`.
9. **Кнопка паузы**: видимая, 44 px, `aria-pressed`, имя меняется («Остановить/Запустить фоновое видео»), выбор помнится в
   `sessionStorage`, одна кнопка на все петли экрана (W3C best practice) → §5 `[проверено]`.
10. **Пауза вне экрана и в скрытой вкладке** (IntersectionObserver + `visibilitychange`) → §4.1 `[проверено]` [поправка X 24.09.2026: было «5.3» — в разделе 5 только 5.1–5.2, условие паузы — таблица 4.1].
11. **Тихую петлю кодек «замораживает»**: `motion_keep` (движение финала / мезонина) при AV1 CRF 36 — 0,77 (рассвет 1080p),
    0,50 (ночь), 0,48 и 0,24 (4:5 720); при H.264 23 — 0,91/0,80/0,83/0,56 → CRF по `motion_keep ≥ 0,75`: AV1 24–28, H.264 18–20
    → §6.1 `[проверено]`.
12. **При равном сохранении движения AV1 ≈ 0,5× H.264** (ночь 1080p: AV1 CRF 24 504 КБ / 0,83 против H.264 CRF 20 940 КБ / 0,93),
    а не 0,32× (равный SSIM, I) → §6.1 `[проверено]`.
13. **Атрибут `loop` даёт микро-заминку на стыке**: в headless интервал на стыке 66,7 мс против медианы 50 (+1 такт 60 Гц) →
    для тихой петли незаметно; бесшовно — только MSE (не проверялось) → §6.2 `[проверено]`.
14. **Видео с альфой — stacked alpha (цвет сверху, альфа снизу) → WebGL2** (`js/stacked-alpha.js`): 2 с 160×272 — AV1 12,5 КБ,
    HEVC 15,7, H.264 21,5; VP9-alpha 19,8 КБ (Safari не показывает); точность альфы после кодека = после кеинга (IoU 0,985)
    → §7 `[проверено: J/05d; Archibald 2024]`.
15. **До первого кадра и при reduce — статичный AVIF с альфой 2,2 КБ**; при reduce — ни байта видео (`data-src`) → §7
    `[проверено]`.
16. **Две петли (два состояния) — видео верхнего слоя грузить при первом взаимодействии**: без наведения — только основа;
    расхождение петель за 9 с — 1 кадр, подтяжка при > 2 кадрах → §8 `[проверено]`.
17. **Прокрутка по видео: GOP 8 ≈ all-intra по задержке при 28 % веса** (оборот 432p: 3,4 против 2,0 мс перемотки, 65 против 232
    КБ); AVIF-секвенция — точные кадры, 111 КБ и 48 запросов → §9 `[проверено]`.
18. **Звук снимать всегда** (`-map 0:v:0 -an`; у Veo, Omni, Wan 2.5/2.6, HappyHorse, Grok 1.5, H3 Max параметра звука нет, D2),
    метки вендора — `-map_metadata 0 -movflags use_metadata_tags+faststart` **одной строкой** (L) → §1.2 `[документация]`.
19. **Бюджет**: петля 1080p 6 с ≤ 1,5 МБ, телефон 720 ≤ 600 КБ (A); у нас 537 КБ AV1 / 789 КБ H.264 и 221 / 356 КБ; первый экран
    с видео 619 КБ десктоп и 310 КБ телефон → §10, `04-…` §1 `[проверено]`.

## 2. Цвет: теги BT.709 и постер

### 2.1 Что показывает браузер (J/02b: плашки красный 200/50/50, синий, бирюза, бежевый, тёмно-синий, серый; ΔE00 к исходнику, max)

| Видео (кодирование из RGB PNG) | CPU: shell / full / Google Chrome | GPU (ANGLE Vulkan, Iris Xe) |
|---|---|---|
| **полные теги BT.709** (`setparams=…`), H.264 / AV1 8 / AV1 10 / VP9, SD и HD | **1,03** | **0,82–1,23** |
| без тегов, SD 640×360: H.264 / AV1 8 | 1,11 / 1,11 | 0,63 / **7,91** |
| без тегов, HD 1280×720: H.264 / AV1 8 | **7,82** / 1,11 | **7,91** / **7,91** |
| «частичные» теги (`-colorspace bt709 -color_primaries … -color_trc …` в ffmpeg 7.1 → записана только матрица) H.264 / AV1 | **7,38** | **7,38** / 1,23 |

`[проверено]` Нетегированное видео — лотерея: браузер угадывает матрицу по разрешению (SD → BT.601, HD → BT.709) и пути
отрисовки, а ffmpeg из RGB по умолчанию пишет BT.601 → насыщенный фирменный цвет «съезжает» на ΔE00 ≈ 8 (видно глазом).

- **Выходы моделей чаще без тегов**: в C2/02 у 19 из 28 настоящих роликов вендоров нет `color_space`/`transfer`/`primaries`
  (в том числе Kling 1928×1072, ролики 2560×1440 и 1920×1080); с тегами BT.709 — 9 `[проверено: C2/02 results.json]`. Какую
  матрицу ставить в мезонин — по сравнению кадра 0 с входной картинкой (декод как BT.709 и как BT.601, медиана ΔE00
  насыщенных пикселей: на своём AV1 с тегом 709 — 0,79 против 1,43) → тест J-01 фазы 5 (0 ₽, на выходах I); до него для HD —
  BT.709 `[не проверено на выходах моделей]`.

```bash
# ffmpeg 7.1.5 · полные теги BT.709 и из RGB, и из YUV-мезонина · [проверено: J/02b, J/05; ffprobe: tv,bt709,bt709,bt709]
TAGS='scale=out_color_matrix=bt709:out_range=tv,setparams=color_primaries=bt709:color_trc=bt709:colorspace=bt709:range=tv'
# метки вендора (AIGC) — -map_metadata 0 -movflags use_metadata_tags+faststart ОДНОЙ строкой (L/02); CRF — по motion_keep (§6.1)
ffmpeg -i mezz.mp4 -map 0:v:0 -an -map_metadata 0 -vf "$TAGS,format=yuv420p10le" -c:v libsvtav1 -preset 6 -crf 28 -movflags use_metadata_tags+faststart hero.av1.mp4
ffmpeg -i mezz.mp4 -map 0:v:0 -an -map_metadata 0 -vf "$TAGS,format=yuv420p"     -c:v libx264 -preset slow -crf 23 -movflags use_metadata_tags+faststart hero.h264.mp4
ffprobe -v error -select_streams v:0 -show_entries stream=color_range,color_space,color_transfer,color_primaries -of csv=p=0 hero.av1.mp4
```

## 3. Постер, LCP и порядок загрузки

### 3.1 Разметка «картинка-постер + видео-слой»

```html
<!-- pages/02-video-hero.html · [проверено] -->
<section class="hero hero--screen" data-hero-video>          <!-- calc(100svh − 64px): hero — кандидат LCP (01 §4.1) -->
  <div class="hero__media">
    <picture>
      <source media="(max-width: 699px)" type="image/avif" srcset="video/dawn-4x5-720-poster.avif" width="720" height="900">
      <source media="(max-width: 699px)" type="image/webp" srcset="video/dawn-4x5-720-poster.webp" width="720" height="900">
      <source type="image/avif" srcset="video/dawn-1080p-poster.avif" width="1920" height="1080">
      <img src="video/dawn-1080p-poster.webp" width="1920" height="1080" alt="" fetchpriority="high">
    </picture>
    <video muted loop playsinline preload="none" aria-hidden="true" tabindex="-1" data-video>…</video>  <!-- §1.2 -->
  </div>
  …H1, текст…
  <button class="media-toggle" type="button" aria-pressed="false" hidden>…</button>                  <!-- §5 -->

```

- Почему `<picture>`, а не `poster=""`: у атрибута `poster` один URL — нет запаса формата (AVIF в Safari < 16 не покажется), нет
  арт-дирекшна (телефону — 16:9-постер при 4:5-ролике, J/04b), нет `fetchpriority`; `<img>` в `<picture>` — обычный LCP-кандидат
  с `srcset` `[проверено]`.
- Видео до первого кадра — `opacity: 0` (не кандидат LCP, J/01 §4.3 файла 01); `hero-video.js` открывает его по
  `requestVideoFrameCallback` (первый реально показанный кадр) → без чёрной вспышки `[проверено]`.
- Замер (J/04, без троттлинга): LCP = постер IMG 124 мс (десктоп) / 92 мс (Pixel 7; в J/06 — 100 мс); запрос видео через
  0,15 / 0,09 с после начала — после `load`; с CPU×4 + 1,6 Мбит/с — LCP 616 / 496 мс (страница 02), 652 / 512 мс (страница 00)
  `[проверено]`.
- Экран загрузки «пока грузятся видео» (ролик SLnGJ9iezYo) — не делать: он прячет H1 и постер, LCP уезжает к концу заставки
  (у лидеров Figma 22 с, Framer 19,9 с — A `01/02` §5.3) `[проверено: A; решение J]`.

## 4. Когда видео не грузить

### 4.1 Условия (все — 0 байт видео, проверено по журналу запросов)

| Условие | Как узнать | Результат J/04 |
|---|---|---|
| `prefers-reduced-motion: reduce` с начала | `matchMedia` | 0 запросов `.mp4` (десктоп, телефон) |
| reduce включили на лету | `RM.addEventListener('change')` | пауза + `display:none`, при выключении — снова играет |
| `navigator.connection.saveData` | Chromium не эмулирует — подменили объект | 0 запросов |
| `effectiveType` 2g/slow-2g | так же | путь кода тот же |
| hero вне экрана / вкладка скрыта | IntersectionObserver / `visibilitychange` | пауза / возобновление |

- «Уменьшить движение» — значит не **скачивать**, а не только не играть (у Sunday — 60 МБ при замершем кадре, A §9) → в разметке
  ни `src`, ни `autoplay`, ни `preload="auto"`; `preload="none"` + `data-src`. Ошибка найдена на своей странице 03: `<source src>`
  + `preload="auto"` при reduce скачали 25 КБ до того, как модуль JS успел убрать видео `[проверено]`.

### 4.2 Без JS: `<source media>`

```html
<!-- pages/02b-video-source-media.html · Chromium 153 · [проверено] -->
<video autoplay muted loop playsinline poster="video/dawn-1080p-poster.avif" aria-hidden="true">
  <source media="(prefers-reduced-motion: no-preference) and (max-width: 699px)" src="video/dawn-4x5-720.av1.mp4" type='video/mp4; codecs="av01.0.04M.10"'>
  <source media="(prefers-reduced-motion: no-preference)" src="video/dawn-1080p.av1.mp4" type='video/mp4; codecs="av01.0.08M.10"'>
  …H.264-запасы с теми же media…
</video>
```

- Десктоп → `dawn-1080p.av1.mp4`, Pixel 7 → `dawn-4x5-720.av1.mp4`; reduce → `networkState` 3 (нет источника), 0 байт, виден
  постер, LCP = VIDEO (постер) 100 мс `[проверено]`.
- Ограничения: media у `<source>` вычисляется при выборе ресурса — включение reduce на лету видео не остановит; постер один на
  все экраны; кнопки паузы нет → `page_accept.py` помечает FAIL по WCAG 2.2.2 `[проверено]`. Годится как «пол» для
  страниц без JS, шаблон по умолчанию — `02`.

## 5. Пауза и WCAG 2.2.2

- Критерий: движение, которое стартует само, **длится дольше 5 с** и показано вместе с другим содержимым, — механизм паузы,
  остановки или скрытия; «пауза только пока фокус на элементе» механизмом не считается; при нескольких движущихся элементах
  лучше **одна** кнопка на все [S1] `[документация]`.
- Длина клипа не важна: петля 2 с, повторяющаяся бесконечно, «длится» дольше 5 с. Два законных пути: кнопка паузы или
  остановка ≤ 5 с (G11/G152 для мигания; флакон на странице 03 — 3 с + добег цикла, стоп на кадре 0, повтор по наведению и
  фокусу) `[документация; проверено: J/06]`.

### 7.2 Код

```html
<!-- pages/03-alpha-object-hero.html · [проверено: Chromium 153, J/06] -->
<div class="object" data-stacked-alpha data-motion-seconds="3">
  <picture><source type="image/avif" srcset="alpha/bottle-still.avif"><img src="alpha/bottle-still.webp" width="160" height="272"
       alt="Флакон крема для рук VELMORA с золотой крышкой"></picture>

  <video muted loop playsinline preload="none" aria-hidden="true" tabindex="-1">
    <source data-src="alpha/bottle.stacked.av1.mp4"  type='video/mp4; codecs="av01.0.00M.08"'>
    <source data-src="alpha/bottle.stacked.hevc.mp4" type='video/mp4; codecs="hvc1.1.6.L60.B0"'>
    <source data-src="alpha/bottle.stacked.h264.mp4" type='video/mp4; codecs="avc1.64000d"'>
  </video>
</div>
<script type="module" src="js/stacked-alpha.js"></script>
```

- Шейдер: цвет — `texture(t, (x, y·0,5))`, альфа — яркость `(x, 0,5 + y·0,5)`, выход премультиплицирован; фильтрация LINEAR с
  отступом полтекселя от середины (без «перетекания» альфы в цвет; NEAREST ступенчат при масштабировании) `[проверено]`.
- Сборка stacked (I `09/02` §4; 3d `05` §3.15): `[0:v]format=pix_fmts=yuva444p[m];[m]split[a][b];[b]alphaextract[al];[a]format=rgb24[rgb];[rgb][al]vstack`
  + полные теги BT.709 (§2) — альфа-половина серая, матрица на неё не влияет, но цветная половина — да.
- Приём «парящий объект» (W5, I `09/02` §5): подложка AVIF + stacked-объект + HTML-текст + параллакс слоёв по прокрутке
  (`animation-timeline: scroll(root)`, только `no-preference` и `@supports`) — страница 03.

## Частые ошибки

- Постер из мастера или исходной картинки (рябь «прыгает» при старте); постер `ffmpeg … poster.jpg`/`.webp` (цвет −7 ΔE).
- Видео без полных тегов цвета (или с `-colorspace bt709` без `setparams`) — фирменный цвет в браузере другой, чем в постере.
- `autoplay` + `src` в HTML «с reduce в CSS» — видео всё равно качается; `preload="auto"` у скрытого альфа-видео.
- Одна `poster=""` на телефон и десктоп при разных роликах; `poster` в AVIF без запаса.
- Петля без кнопки паузы, потому что «клип всего 4 с» (движение бесконечно).
- AV1 CRF 36 на тёмной тихой петле без проверки `motion_keep` — движение исчезло, остался пульс.
- HEVC единственным форматом или первым `<source>` без H.264 за ним; вера в `canPlayType` = «probably».
- VP9-alpha как единственный путь прозрачности (Safari не покажет), GIF как запас альфы (256 цветов, альфа 1 бит).
- Две петли, обе грузятся сразу, хотя верхнюю видят только после наведения.
- **Ошибки нейросетей-агентов**: «HEVC играет во всех Chrome» (только с аппаратным декодером); «AV1 не поддерживается Safari»
  (с аппаратным — да, iPhone 15 Pro/M3+); `-crf` у VP9 без `-b:v 0`; `trim,setpts` без `-r` (теряет кадр, I); экран-заставка
  «для роскоши»; «reduce = `animation: none`» для `<video>` (видео CSS-анимацией не управляется).

## Открытые вопросы и противоречия

- Safari не проверялся (нет macOS): HEVC-stacked, `<source media>` у видео, `requestVideoFrameCallback`, `animation-timeline`.
  WebKit Playwright на Linux (GStreamer) не показывает кадры видео в canvas — не заменитель.
- Дизеринг 10-битного AV1 на 8-битном выводе: Chromium не дизерит (J/03 — ступень 0,35 против 0,04 у CSS-градиента); как
  ведёт себя HDR/10-битный путь дисплея — не проверялось.
- Видим ли «пульс» ключевого кадра глазом на реальной петле модели — фаза 5 (I); как и `motion_keep` на настоящих выходах.
- Бесшовная петля через MSE (без заминки `loop`) — не проверялась.
- Поведение `loop` на телефоне с аппаратным декодером, энергопотребление двух одновременных петель — не мерилось.
