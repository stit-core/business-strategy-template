## Выжимка для агента

1. **Бюджет первого экрана — ≤ 2,5 МБ десктоп / ≤ 1,5 МБ телефон** (Q1 лидеров, A); наши шаблоны: картинка-hero 129 / 117 КБ,
   видео-hero 594–619 / 253–310 КБ, объект с альфой 115 / 98 КБ — запас ×4–20 → §1 `[проверено]`.
2. **Видео, стартующее без действий пользователя, входит в «первый экран»** (грузится после `load` за секунды): видео-hero
   537 КБ AV1 из 619 КБ десктопа → бюджет видео 1080p ≤ 1,5 МБ, телефон ≤ 600 КБ (A) и сам первый экран считать с ним → §1.2
   `[проверено]`.
3. **Приёмка — одна команда на режим**: `python3 ../../scripts/ai-media/page_accept.py PAGE --out DIR [--mobile] [--throttle]
   [--contrast …]` → JSON и PASS/FAIL; код выхода 1 при провале → ворота CI/агента → §3 `[проверено]`.
4. **Что проверяется**: вес по CDP, LCP (элемент, файл, время, lazy, `fetchpriority`), CLS, TBT, `alt` и `width/height`,
   переотдача > 2, атрибуты видео, пауза для движения > 5 с (поведенчески, на 6-й секунде), reduce (0 байт видео, движение < 0,5 %),
   F83 по буквам и по кадрам видео, фавиконы → §3.2 `[проверено]`.
5. **Режимы минимум**: десктоп 1440×900 и Pixel 7 (оба с прогоном reduce) + один с троттлингом (CPU×4, 1,6 Мбит/с) для LCP;
   тёмная тема и вторые состояния (`--dark`, `--click`) — если меняют текст или скрим → §3.1 `[проверено]`.
6. **LCP в лаборатории — ориентир, не норма поля**: наши 72–144 мс без троттлинга и 496–984 мс с троттлингом; норма web.dev —
   ≤ 2,5 с на p75 поля (CrUX) → §2 `[проверено: J/06; документация]`.
7. **Кто LCP — решить заранее** (hero меньше вьюпорта → картинка; весь экран → H1) и проверить, что прогон видит именно его
   → `01-…` §4.1 `[проверено]`.
8. **Троттлинг DevTools не создаёт конкуренции** (режет каждый запрос отдельно) → для приоритетов — полоса на сервере
   (`99-raw/experiments/J/jlib.py` `Bucket`) или поле → §5 `[проверено]`.
9. **Байты — из `loadingFinished.encodedDataLength`**, куски `dataReceived` — только для незавершённых (видео с Range):
   сумма кусков + итог давала ×2 (537 КБ видео → 1073) → §5 `[проверено]`.
10. **Клик и прокрутка — это ввод: LCP после них не пишется** (прогон с кликом сразу после `load` — ни одной записи LCP) → вес и
    LCP мерить без действий, состояния — отдельными прогонами → §5 `[проверено: J/06; документация web.dev]`.
11. **Headless ≠ пользовательский браузер**: без GPU HEVC не играет, с GPU-флагами `canPlayType` врёт («probably» при чёрном
    кадре); WebKit Playwright ≠ Safari (кадры видео не читаются) → кодеки проверять пикселем → §5 `[проверено]`.
12. **Пауза проверяется поведением, а не разметкой**: что движется на 6-й секунде и есть ли видимая кнопка с именем
    «пауза/остановить/запустить»; страница 02b (`<source media>` без JS) честно проваливает WCAG 2.2.2 → §3.2 `[проверено]`.
13. **reduce проверяется байтами**: второй прогон с `reduced_motion: reduce` — 0 КБ `media` на всех шаблонах; найден и
    исправлен случай 25 КБ (`<source src>` + `preload="auto"` у альфа-видео) → §3.2 `[проверено]`.
14. **Типовые провалы → типовые исправления**: таблица §6 (lazy на LCP, CSS-фон без preload, всё из opacity 0, скрим по H1 при
    мелком кикере, горизонтальный скрим на телефоне, видео с `src` при reduce, петля без паузы) `[проверено]`.
15. **Живой сайт (конкурент, клиент) — `asset_inventory.py` (A) и `site_probe.py` (3d)**, файл видео — `video_loop_check.py`
    (I), картинка — `avif_pick.sh` (H), провенанс — `provenance_check.py` (L) → §4 `[документация: README утилит]`.

### 1.2 Как считать «первый экран»

- = все байты за `load` + 4–6 с без прокрутки и кликов (A: «до прокрутки»); видео-слой, стартующий после `load`, попадает в
  него — это честно: пользователь качает его, не сделав ничего `[проверено]`.
- Ленивые картинки ниже первого экрана в него не входят (загрузятся при прокрутке) — в шаблонах карточки 480w по 5–9 КБ.
- «Сессия» — отдельно (A: ≤ 7 / 3 МБ); видеоплатформы (HLS) качают, пока играет — A `02` §7.1.

### 1.3 Движение как бюджет

- Петли > 5 с — с кнопкой паузы (WCAG 2.2.2); одна кнопка на все движущиеся слои экрана; вторая петля (состояние) — по
  взаимодействию (`02-…` §8); прокрутка по кадрам — ≤ 150 КБ для 48 кадров 432p (J/09) `[проверено]`.

## 2. LCP: цель и лаборатория

- Цель поля — LCP ≤ 2,5 с на p75 визитов (web.dev [S1]); лаборатория показывает элемент и порядок загрузки, поле — реальную
  сеть. CrUX API требует ключ (не заводим) → поле не сверялось; A: у 43 лидеров лабораторная медиана 3,2 с `[документация]`.
- Лабораторные цели базы: ≤ 2,0 с десктоп, ≤ 2,5 с на CPU×4 + медленном 4G (A); шаблоны J: 0,5–1,0 с — потому что LCP-файл
  36–90 КБ и найден сканером предзагрузки `[проверено]`.
- Разбор LCP по этапам (web.dev): TTFB ≈ 40 %, задержка загрузки < 10 %, загрузка ≈ 40 %, задержка отрисовки < 10 % [S2] —
  у ИИ-hero обычно раздута «загрузка» (PNG модели) и «задержка отрисовки» (появление из opacity 0, `01-…` §4.3).

## 3. Приёмка страницы: `page_accept.py`

### 3.1 Запуск

```bash
# page_accept.py (J, 23.09.2026; Python 3.13, Playwright 1.63, Chromium 153 CfT, numpy, Pillow, scipy) · [проверено]
T=../../scripts/ai-media/page_accept.py; P=10-web-integration/pages/00-hero-summary.html
python3 $T $P --out acc --contrast ".hero h1" ".hero__lead" ".hero__kicker"      # 1440×900 DPR 1 + прогон reduce
python3 $T $P --out acc --mobile --contrast ".hero h1" ".hero__lead"             # Pixel 7 (412×839, DPR 2,625) + reduce
python3 $T $P --out acc --throttle --no-rm --wait 6000                           # CPU×4, 1,6 Мбит/с, RTT 150 мс — для LCP
python3 $T $P --out acc --dark --no-rm --contrast ".hero h1"                     # prefers-color-scheme: dark
python3 $T $P --out acc --click "[data-state-toggle]" --no-rm --contrast …       # второе состояние (LCP не смотреть)
python3 99-raw/experiments/J/06-pages-measure/run_all.py && python3 99-raw/experiments/J/06-pages-measure/summarize.py   # все страницы
```

- Утилита сама берёт `99-raw/tools/.locks/browser.lock` (ждёт до 900 с), локальный файл раздаёт встроенным HTTP-сервером с
  Range и закрывает его; результат — `accept_<режим>.json`, снимки `shot_<режим>.jpg`, `shot_rm_<режим>.jpg`; код выхода 0/1.

## 5. Ловушки замера

- **Троттлинг DevTools per-request**: `Network.emulateNetworkConditions` ограничивает каждый запрос отдельно — конкуренция
  ресурсов не воспроизводится (eager = `fetchpriority` = 2 388–2 392 мс); для приоритетов — общая полоса на сервере (J/01b) или
  WebPageTest/поле `[проверено]`.
- **Двойной счёт байт по CDP**: сумма `dataReceived.encodedDataLength` + `loadingFinished.encodedDataLength` → ×2; правильно —
  итог `loadingFinished`, куски — только для оборванных запросов (видео с Range; A: байты видео — верхняя граница) `[проверено]`.
- **Ввод останавливает LCP**: клик, прокрутка колесом, клавиатура; программная прокрутка — нет (A) → LCP снимать до действий
  `[проверено: J/06; документация web.dev]`.
- **Появление из `opacity: 0`** — записи LCP пропадают или указывают на мелочь; такой «хороший» LCP — ложный `[проверено]`.
- **Headless и кодеки**: без GPU HEVC нет; с `--enable-gpu` и VAAPI-флагами `canPlayType`/MediaCapabilities говорят «да», а кадр
  чёрный → кодек подтверждать пикселем после декода (`99-raw/experiments/J/02-codecs/probe.html`) `[проверено]`.
- **WebKit Playwright ≠ Safari**: на Linux (GStreamer) всё «probably», JXL декодирует, кадры видео в canvas пустые `[проверено]`.
- **Эмуляция телефона без троттлинга — оптимистична**: Pixel 7 в эмуляции быстрее десктопа (меньше пикселей); A: на реальном
  телефоне медленнее → для телефона — `--mobile --throttle` `[проверено: J/06; A]`.
- **Save-Data не эмулируется** Chromium — путь кода проверять подменой `navigator.connection` (J/04) `[проверено]`.
- **Один прогон — шум**: с общей полосой разброс ±1 с; решения по времени — медиана ≥ 3 прогонов `[проверено]`.

| `F83 «лид»: 2,79` | строка по ветвям дерева (телефонный кадр) | фокус → `object-position` 0,86, колонка 27ch | 01 |

| двойные байты видео | ошибка счёта в утилите | итог `loadingFinished` | утилита |

`[проверено]`

## Частые ошибки

- Мерить вес без видео-слоя («он же после load») или без reduce-прогона.
- Проверять только десктоп; телефон без троттлинга принимать за телефон.
- Считать `canPlayType("…hvc1…") === "probably"` доказательством воспроизведения.
- Сравнивать «вес за сессию» с Web Almanac (он меряет загрузку, A).
- Кликать и прокручивать до снятия LCP; опираться на один прогон.
- **Ошибки нейросетей-агентов**: «Lighthouse даст вес видео» (Range-запросы обрываются, нужен CDP, A); «троттлинг DevTools = реальная
  сеть»; бюджеты «по памяти» («страница 1–2 МБ»); «пауза нужна только для роликов длиннее 5 с» (движение, а не клип); «reduce
  = остановить анимацию» (нужно не качать).

## Чек-лист приёмки страницы

- [ ] `page_accept.py` PASS: десктоп 1440×900 и Pixel 7, оба с reduce-прогоном?
- [ ] С троттлингом LCP ≤ 2,5 с, элемент LCP — ожидаемый (hero или H1)?
- [ ] Первый экран ≤ 2 500 / 1 500 КБ вместе с видео-слоем; видео 1080p ≤ 1,5 МБ, 720 ≤ 600 КБ?
- [ ] reduce: 0 КБ видео, движение в покое < 0,5 %; на лету — пауза?
- [ ] Движение на 6-й секунде — только с видимой кнопкой паузы (или его нет)?
- [ ] F83 по буквам ≥ 4,5 / 3 во всех режимах, для видео — по кадрам; вторые состояния и тёмная тема — отдельными прогонами?
- [ ] Все `<img>` с `alt` и `width`/`height`; CLS 0?
- [ ] OG, фавиконы, XMP `DigitalSourceType` на производных (L) на месте?

## Открытые вопросы и противоречия

- Поле (CrUX/RUM) против лаборатории — не сверялось: нужен ключ CrUX API или RUM на живом сайте заказчика.
- Нет замера на реальном телефоне и в Safari; эмуляция Pixel 7 без троттлинга быстрее десктопа.
- Бюджеты A — Q1 лидеров одного дня (43 сайта); для кампаний и e-commerce выборка мала.
- `page_accept.py` не меряет INP (нужны действия пользователя) и энергопотребление петель.
