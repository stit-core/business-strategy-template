   `[проверено]` `[спорно: A §4 против 3d A/06]`.
2. **Тихая петля 6 с укладывается в бюджет с запасом ×2–5**: 720p — AV1 CRF 36–42 140–195 КБ, H.264 CRF 23–26 280–440 КБ;
   1080p — AV1 230–310 КБ, H.264 490–690 КБ (бюджет 1080p ≤ 1,5 МБ, телефон 720p ≤ 600 КБ) → §2 `[проверено]`.
3. **AV1 ≈ 0,32× H.264 при равном SSIM** (0,985 на 720p: 141 против 443 КБ); HEVC ≈ 0,5×, VP9 ≈ 0,7× → §2 `[проверено]`.
4. **Стартовые CRF**: H.264 `-preset slow -crf 23` (1080p) / 23–26 (720p); AV1 SVT `-preset 8 -crf 36–42`; VP9 `-crf 36
   -b:v 0`; потом глазами на 3 прохода петли → §2 `[проверено]` `[мнение]`. **После кодирования — `motion_keep` ≥ 0,75**
   (движение финала к мезонину): тихие, тёмные и маленькие петли при этих CRF «замерзают» (AV1 36: 0,24–0,77) → AV1 24–28,
   H.264 18–20 (J/05, `../10-web-integration/02-video-delivery.md` §6.1) [поправка X 24.09.2026 по J].
5. **Выход модели на сайт как есть не годится**: звук (AAC, у Veo и Omni — всегда), `moov` в конце (H3), 1928×1072 (Kling),

6. **`-map 0:v:0 -an`** снимает звук, **`-movflags +faststart`** ставит `moov` вперёд (проверено по порядку атомов:
   `ftyp moov free mdat`), **`-r <fps>`** — после любого `setpts` → §6 `[проверено]`.
7. **Kling 1928×1072 → `crop=1920:1072`**, без масштабирования (пересэмплинг не нужен, `object-fit: cover` скроет 8 px) → §6
   `[проверено]`.

9. **Против пульса у H.264 — `-tune grain`** (скачок 2,1 → 1,0 дБ, +18 % веса); короткий GOP (`-g 24`) — хуже и ×1,9 веса;

   на живой петле (8 с 720p + RIFE, шов мезонина 0,8) — AV1 CRF 26/28/30: 1 218 / 1 011 / 865 КБ, шов 2,42 / 2,40 / 2,72; H.264
   `-tune grain` CRF 20/22: 3 367 / 2 314 КБ, шов 1,54 / 1,76; телефон 4:5 — 3,2–3,3 при любом CRF → CRF выбирать по `motion_keep`
   ≥ 0,75 **и** шву ≤ 2,5; видимость пульса глазом не проверена → `99-raw/experiments/B/12-demo-assets/README.md`].
10. **Постер — из декодированного кадра 0 финального файла**, а не из мезонина: разница мезонин ↔ кадр 0 видео CRF 23 —
    MAD 1,57 уровня, в 11 раз больше шага петли → при старте видео постер «мутнеет» → §5 `[проверено]`.
11. **Постер 720p — AVIF q45–55: 18–29 КБ** (WebP q80 50 КБ, JPEG q82 102 КБ); бюджет A ≤ 120 КБ — с запасом → §5
    `[проверено]`.
12. **Прокрутка по видео: GOP 8 (×3 веса) вместо all-intra (×9,3 для фото-наезда)**: перемотка декодирует в среднем 3,5
    кадра; all-intra ещё и хуже по SSIM при том же CRF (0,967 против 0,982) → §7 `[проверено]`.
13. **Секвенция кадров для прокрутки** — AVIF q55 каждый 2-й кадр: 72 кадра 720p = 1,87 МБ (26 КБ/кадр), WebP q80 — 3,56 МБ
    → §7 `[проверено]`.
14. **Градиенты неба и света — AV1 10 бит** (`-pix_fmt yuv420p10le`): ступенька 0,11–0,13 кода против 0,29 у 8-битного
    исходника, и файл легче 8-битного AV1 (3,5–4,6 против 5,3 КБ) → §8 `[проверено]`. **Но это декод ffmpeg с
    дизерингом; в Chromium AV1 10 бит даёт ступень 0,354 (8-битный H.264 — 0,44–0,48, CSS-градиент — 0,04)** → 10 бит лишь
    смягчает бандинг; тёмный гладкий градиент — CSS, растр — с шумом поверх (J/03, `../10-web-integration/03-text-over-media-and-effects.md`
    §4.3) [поправка X 24.09.2026 по J].
15. **8-битный H.264 расширяет полосы градиента** (28 → 38 px); дизеринг до кодека съедается (30 px, а на CRF 18 — 27 px
    ценой ×5 веса); `gradfun` перед кодеком не помогает (35,5 px) → §8 `[проверено]` (как H/05b у картинок).
16. **Звук и метки**: любой ffmpeg (даже `-c copy`) выбрасывает C2PA Google; китайская метка `AIGC` выживает только с
    `-map_metadata 0 -movflags use_metadata_tags` (MP4) или в WebM — решает L → §6 `[проверено]`.
17. **Кодировать один раз из мезонина** (срезанный без потерь: `video_loop_check.py trim` с 24.09.2026 пишет x264 `-qp 0`;
    CRF 10 — только если диска нет, шов на нём не мерить): каждое перекодирование 4:2:0 добавляет потери и пульс → §3 `[мнение]`
    `[поправка X2 24.09.2026]`.

Материал — процедурная рябь по кадру A (движется вода, остальное неподвижно; `motion_med` 0,115, уровень Notion и Seasats),
144 кадра, 24 fps; 1080p — кадр A увеличен Lanczos (мягче натива). Эталон качества — исходник 4:2:0 без потерь.

| Кодек, CRF | 720p КБ (КБ/с) | SSIM | 1080p КБ (КБ/с) | SSIM |
|---|---|---|---|---|
| H.264 slow 20 | 694 (116) | 0,9894 | 1007 (168) | 0,9915 |
| H.264 slow 23 | **443 (74)** | 0,9852 | **687 (115)** | 0,9886 |
| H.264 slow 26 | 282 (47) | 0,9793 | 487 (81) | 0,9847 |
| H.264 slow 29 | 195 (33) | 0,9711 | 349 (58) | 0,9794 |
| HEVC medium 24 / 28 / 32 | 288 / 168 / 98 | 0,986 / 0,979 / 0,968 | 449 / 272 / 167 | 0,988 / 0,983 / 0,975 |
| VP9 good cpu 4, 31 / 36 / 41 | 313 / 217 / 150 | 0,985 / 0,980 / 0,974 | 522 / 364 / 253 | 0,987 / 0,984 / 0,979 |
| AV1 SVT preset 8, 30 | 279 (46) | 0,9902 | 464 (77) | 0,9912 |
| AV1 SVT preset 8, 36 | **195 (33)** | 0,9881 | **313 (52)** | 0,9894 |
| AV1 SVT preset 8, 42 | 141 (23) | 0,9854 | 228 (38) | 0,9876 |

- Равное качество (SSIM ≈ 0,985, 720p): H.264 CRF 23 — 443 КБ; VP9 CRF 31 — 313; HEVC ≈ CRF 26 — ≈ 230; AV1 CRF 42 — 141
  `[проверено]`.
- Лидеры отдают hero 1080p ≈ 150–200 КБ/с (A); наша тихая петля — 115 КБ/с H.264 CRF 23: у ИИ-видео с движением всего
  кадра вес выше — полнокадровый наезд 720p H.264 CRF 23 = 82 КБ/с (§7), выход моделей до перекодирования — 0,24–3,5 МБ/с
  (C2/02) `[проверено]`.
- Время кодирования 6 с ролика — 1–5 с на 4 потоках (Iris Xe машины, CPU) `[проверено]`.

```bash
# ffmpeg 7.1.5 · из срезанного мезонина loop_mezz.mp4 — [проверено]
ffmpeg -i loop_mezz.mp4 -map 0:v:0 -an -c:v libsvtav1 -preset 6 -crf 36 -pix_fmt yuv420p10le -movflags +faststart hero.av1.mp4
ffmpeg -i loop_mezz.mp4 -map 0:v:0 -an -c:v libx264 -preset slow -crf 23 -pix_fmt yuv420p -movflags +faststart hero.h264.mp4
ffmpeg -i loop_mezz.mp4 -map 0:v:0 -an -c:v libvpx-vp9 -crf 36 -b:v 0 -deadline good -cpu-used 2 -row-mt 1 hero.vp9.webm
```

(`-preset 6` у SVT-AV1 для финала медленнее и чуть легче `-preset 8` опытов; `-cpu-used 2` у VP9 — так же `[мнение]`.)

## 3. Мезонин и порядок операций

1. Выход модели → `ffprobe` (кодек, `pix_fmt`, размер, fps, звук, `moov`) → `loop`/`trim` (`01` §3) → **мезонин**: x264 CRF
   10 `yuv420p` `-r <fps>` (или без потерь `-qp 0`) — вход всех финальных кодеков и постера. Шов и дубль мерить только на
   мезонине без потерь (`-qp 0` 4:4:4) или на выходе модели: CRF 10 уже даёт ложный шов 2,08 у чистой петли (K/03)
   [поправка X 24.09.2026 по K].
2. Одно кодирование в каждый формат из мезонина; не кодировать AV1 из H.264 CRF 23 (двойные потери) `[мнение]`.
3. После кодирования — глазами 3 прохода петли и проверка пульса (§4); размеры — в паспорт ассета (K).

## 4. Пульс ключевого кадра на стыке петли

Петля по построению (шов исходника 0,98), 720p, 6 с, один GOP на весь ролик:

| H.264 CRF 18 | 950 | 3,27 / 3,90 | +2,51 |

| VP9 CRF 36 | 217 | 6,88 / 8,96 | +2,86 |

- Секвенция AVIF — точный кадр без декодера видео, но 1,9 МБ на 72 кадра 720p; для телефона — меньше кадров и размер
  (3d `05` §3.14) `[проверено]`.
- Перемотку по прокрутке, `currentTime` и подгрузку кадров проверяет J на тестовой странице.
- [поправка фазы 5, 25.09.2026: облёт 720p 121 кадр — AV1 GOP 1/4/8: 2 065 / 998 / 664 КБ, H.264 GOP 1/4/8: 3 172 / 1 660 / 1 264 КБ;
  секвенция 61 кадр AVIF 1280 — 1 250 КБ; рябь воды — 47 КБ на кадр AVIF 1280 (облёт — 20, крупная форма — 15–22); для мыши
  секвенция (0 отставания, ≈ 214 МБ раскодированных кадров), для касания — AV1 GOP 4 → `99-raw/experiments/B/10-scrub-delivery/bench_table.md`]

## 8. Бандинг градиентов (небо, свет, туман)

«Рассветное небо» — плавный градиент во float (≈ 36 кодов 8 бит на 720 px), 2 с 720p:

| Вариант | КБ | Ширина полосы, px (декод. в 8 бит) | Ступенька, коды (декод. 16 бит) |
|---|---|---|---|
| исходник 8 бит, округление | — | 28 | — |
| исходник 8 бит + TPDF-дизеринг ±1 | — | 1,5 | — |
| H.264 CRF 23 из 8 бит | 27,5 | **37,8** | — |
| H.264 CRF 23 из 8 бит + дизеринг | 60,3 | 30,2 | — |
| H.264 CRF 18 из 8 бит + дизеринг | 146,3 | 27,0 | — |
| H.264 CRF 23 + `gradfun` перед кодеком | 24,9 | 35,5 | — |
| AV1 CRF 36, 8 бит | 5,3 | 18,5 | — |
| **AV1 CRF 36, 10 бит** (из 8 бит / из 16 бит / из 8 + дизеринг) | 3,7 / 3,5 / 4,6 | 1,0 (ffmpeg дизерит при выводе в 8 бит) | **0,13 / 0,11 / 0,11** (8-битный исходник — 0,29) |

- ИИ-видео приходит 8-битным (кроме HEVC 10 бит Seedance 2.5 1080p): кодировать градиентные петли в **AV1 10 бит** даже из
  8-битного мезонина — точность сохраняется, файл меньше `[проверено]`.
- Дизеринг перед 8-битным кодеком не выживает (как у картинок — H/05b); зерно поверх видео — CSS-шумом, не в файле
  (`../08-image-post-processing/03-color-tiling-depth-layers.md` §3) `[проверено]`.
- Дизерит ли браузер 10-битный AV1 при выводе на 8-битный экран — проверено J/03: в Chromium ступень AV1 10 бит 0,354, CSS-
  градиент 0,042 (дизерит только CSS) → `../10-web-integration/03-text-over-media-and-effects.md` §4.3 [поправка X 24.09.2026].

## Частые ошибки

- Отдавать выход модели как есть: звук, `moov` в конце, 1928×1072, 7–18 МБ за 5 с.
- Кодировать AV1 из H.264 CRF 23 вместо мезонина — двойные потери.
- All-intra для прокрутки фото-видео (×9,3 веса) вместо GOP 8.
- Постер из исходной картинки или мезонина — «мутнение» при старте видео; постер JPEG 100 КБ вместо AVIF 20–30 КБ.
- «Лечить» бандинг дизерингом перед 8-битным H.264 — кодек его съедает.
- `trim …,setpts=…` без `-r` в MP4 — потерянный последний кадр (`01` §3.1).
- Ошибки нейросетей-агентов: «AV1 не поддерживается браузерами» (устарело; первым `<source>` с запасом H.264); «HEVC — для
  всех» (в Chrome зависит от платформы); `-crf` для VP9 без `-b:v 0` (режим ограниченного качества вместо постоянного); `-preset
  veryslow` в опытах (правило машины: SVT-AV1 `-preset 8`, `-threads 4`); VMAF «по памяти» — libvmaf в сборке нет.

## Чек-лист

- [ ] Звук снят (`-map 0:v:0 -an`), `moov` впереди (`+faststart`), размер стандартный?
- [ ] Финальные файлы — из срезанного мезонина, по одному кодированию на формат?
- [ ] AV1 первым `<source>`, H.264 запасом; вес 1080p ≤ 1,5 МБ, 720p ≤ 600 КБ?
- [ ] Градиенты — AV1 10 бит?
- [ ] Постер — кадр 0 финального файла, AVIF ≤ 120 КБ?
- [ ] Петля после кодирования просмотрена на пульс (3 прохода)?
- [ ] Для прокрутки — GOP 8 или секвенция AVIF, не all-intra?
- [ ] Метка `AIGC`/C2PA: решение L принято, мастер-оригинал сохранён?

## Открытые вопросы и противоречия

- Видим ли пульс ключевого кадра на экране (§4); помогает ли `-tune grain` так же на выходах моделей.
- Почему `-x264-params ipratio=1.0:pbratio=1.0` дал тот же размер (443,0 КБ) и те же метрики (перекрывается обёрткой libx264 в ffmpeg?) — не выяснено.
- Лестницы сняты на тихой петле и мягком 1080p (апскейл A): для полнокадрового движения и нативного 1080p веса выше —
  уточнить на выходах фазы 5 (I-09, I-15).
- Дизеринг 10-битного AV1 при выводе в браузере; поддержка AV1 в Safari (только устройства с аппаратным AV1) — J.
- VMAF не мерился (нет libvmaf); SSIM и PSNR на тихой петле насыщаются (0,98–0,99) — различия кодеков по SSIM малы.
