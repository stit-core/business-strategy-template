## Выжимка для агента

1. **Нативной альфы у видео-моделей нет** (даже ProRes 4444 у Runway — альфа «fully opaque»): путь — ровный ключ при
   неподвижной камере → кеинг → VP9-alpha + HEVC-alpha или stacked alpha → `../04-video-models/03` §10 `[документация]`.
2. **Цвет ключа — по оттенкам объекта**: золото, бронза, жёлтое, зелёное → пурпурный `#FF00FF`; красное, розовое,
   фиолетовое → зелёный `#00B140` → §1.1 `[проверено]` `[V:_Bc4g6fFMp0 07:07]`.
3. **Пурпурный прощает ошибку настройки, зелёный — нет**: `colorkey` с similarity 0,30 на зелёном съедает 71 % золота
   (10 % объекта), на пурпурном — 0,5 %; `chromakey` 0,25 на зелёном стирает объект целиком → §1.2 `[проверено]`.
4. **На сжатом выходе модели (4:2:0) лучший кеер — `chromakey`** (YUV): IoU 0,985 к эталонной альфе при similarity 0,10
   (зелёный) и 0,15 (пурпурный), blend 0,08 → §1.3 `[проверено]`.
5. **Ключ бери по медиане фона кадра**, а не по hex из промта: `video_loop_check.py chroma --key auto` → `key` → в кеер
   → §1.3 `[практика: H/01]` `[проверено: утилита]`.
6. **`hsvkey`: `sat` и `val` — не S и V из HSV**, подбирать сеткой (чистый вход: sat 0,7, val 0,6, similarity 0,3 — IoU
   0,997–0,999; неудачная пара sat 0,5, val 0,4 съедает 80 % золота) → §1.3 `[проверено]`.
7. **despill обязателен**: ореол ΔE00 6,4–10,6 → 4,5–6,4 (−30…−40 %); для зелёного — `geq` G ≤ max(R, B), а не фильтр
   `despill` (золото 12,6 против 15,4: фильтр уводит золото в медь) → §1.4 `[проверено]`.
8. **Рефлекс ключа на металле despill не снимает** (ΔE00 золота 12–17 при любом ключе): блестящее генерировать на цвете
   итоговой сцены или править цвет металла по маске после кеинга → §1.4 `[проверено]` `[V:_Bc4g6fFMp0 05:07]`.
9. **Матирование покадрово (u2netp) — запас для неровного фона, не замена ключу**: IoU 0,969 против 0,985, край в 2,5 раза
   хуже, мерцание края, 0,115 с/кадр 640×360 и 2,2 ГБ ОЗУ → §2 `[проверено]`.
10. **Альфа-видео легче, чем кажется**: 2 с 640×360 — stacked AV1 10,5 КБ, VP9-alpha CRF 40 16 КБ (CRF 30 — 30 КБ), stacked
    HEVC 18,7 КБ; альфа переживает кодек (MAE 0,08–0,15 ×1000) → §4 `[проверено]`.
11. **Проверяя VP9-alpha в ffmpeg, декодируй `-c:v libvpx-vp9` перед `-i`**: встроенный декодер альфу не читает
    (α = 255 везде) — ложный «альфа пропала» → §4 `[проверено]`.
12. **Синемаграф = генерация с `fixed_lens` + маска + петля в зоне движения**: маска замораживает неподвижное (дрейф
    6,4 → 0,25), но ползущую камеру внутри зоны движения не лечит (шов 2,7–5,1 после кроссфейда) → §3 `[проверено]`.
13. **Один очаг движения** для синемаграфа («leave everything exactly as is, only animate …»), для живого фона — перечень
    движения каждого элемента; это не противоречие → §3 `[V:SLnGJ9iezYo 03:05]` `[V:OA4xB5EY02g 30:43]`.
14. **Hero с парящим объектом — две картинки из одной генерации**: объект на ключе правкой + подложка удалением объекта
    по маске с дилатацией → i2v объекта с `fixed_lens` → кеинг → альфа-видео → параллакс слоёв (≈ 40 %) → §5
    `[V:BVMuRw8BgJg 00:33–08:33]` `[не проверено]`.
15. **GIF и PNG-секвенция — не запас для альфы**: Safari — HEVC-alpha (кодируется только на macOS) или stacked alpha + WebGL
    → §4 `[практика]` (3d A/06).
16. **Приёмка ключа по выходу модели**: фон ≥ 95 % пикселей в ΔE00 ≤ 5 от ключа во всех кадрах, дрейф центра ≤ 2 % ширины
    (`chroma`); после кеинга — съедено ≤ 1 %, ореол ≤ 1 % края (`alpha_check.py` H) → §1.5 `[мнение]`.

## 1. Хромакей для видео

### 1.1 Цвет ключа

Опыт I/03: бутылка (керамика + матовое золото колпачка и знака), 48 кадров 640×360, эталонная альфа, плиты на `#00B140`
и `#FF00FF` с рефлексами ключа на объекте; условия «чистый рендер» и «как выход модели» (виньетка −8 %, шум σ 2, H.264
CRF 23 4:2:0).

| Цвет объекта (преобладающий) | Ключ | Почему |
|---|---|---|
| золото, бронза, латунь, жёлтый, оливковый, зелёный | **пурпурный `#FF00FF`** | зелёный рефлекс превращает золото в оливковое (RGB 125/130/64 против 163/133/81), кеер путает его с фоном |
| красный, розовый, фиолетовый, пурпурный | зелёный `#00B140` | пурпурный ключ съест красное и розовое (по смыслу; на опыте не мерилось) `[мнение]` |
| белое, серое, чёрное, керамика, стекло | любой; зелёный — привычнее моделям | маска у обоих IoU ≥ 0,985 |
| блестящий металл, стекло, глянец | цвет итоговой сцены (без ключа) + матирование, или ключ + коррекция цвета металла | рефлекс ключа остаётся (ΔE00 12–17) |

### 1.2 Запас по `similarity`

| Кеер, «пересолено» | Зелёный: золото / объект / IoU | Пурпурный: золото / объект / IoU |
|---|---|---|
| `colorkey` 0,30 (RGB) | **70,8 %** / 10,0 % / 0,887 | **0,5 %** / 0,4 % / 0,977 |
| `chromakey` 0,25 (YUV) | **99,6–100 %** / объект исчез / 0,000 | 1,8–7,9 % / 0,6–1,5 % / 0,968–0,976 |
| `hsvkey` sat 0,5, val 0,4, sim 0,3 | 80 % / 12,5 % / 0,861 | 79–80 % / 12,6 % / 0,856 |

Вывод: на зелёном окно рабочих `similarity` узкое (0,06–0,15), ошибка стоит частей объекта; на пурпурном — широкое
`[проверено]`.

### 1.3 Кеер и параметры (лучшие по MAE альфы, с despill)

| Ключ / вход | Кеер ffmpeg | IoU | MAE ×1000 | Полоса края ×1000 | Съедено / золото |
|---|---|---|---|---|---|
| зелёный / чистый | `hsvkey=hue=142:sat=0.7:val=0.6:similarity=0.3:blend=0.08` | 0,997 | 0,50 | 25 | 0 / 0 % |
| зелёный / выход модели | `chromakey=0x00B140:0.1:0.08` | 0,985 | 0,98 | 49 | 0,10 / 0,50 % |
| пурпурный / чистый | `hsvkey=hue=300:sat=0.7:val=0.6:similarity=0.3` | 0,999 | 0,83 | 42 | 0 / 0 % |
| пурпурный / выход модели | `chromakey=0xFF00FF:0.15:0.08` | 0,985 | 0,82 | 41 | 0 / 0,003 % |

```bash
# ffmpeg 7.1.5 · зелёный ключ по выходу модели → кейнутый мезонин с альфой (PNG-секвенция или VP9-alpha) — [проверено]
KEY=$(python3 ../../scripts/ai-media/video_loop_check.py chroma in.mp4 --key auto | python3 -c "import json,sys;print('0x'+json.load(sys.stdin)['key'][1:])")
ffmpeg -i in.mp4 -vf "chromakey=$KEY:0.10:0.08,format=rgba,geq=r='r(X,Y)':g='min(g(X,Y),max(r(X,Y),b(X,Y)))':b='b(X,Y)':a='alpha(X,Y)'" \
       -an -c:v png keyed_%04d.png
# пурпурный ключ: chromakey=0xFF00FF:0.15:0.08, despill — вычесть общий избыток R и B над G:
#   geq=r='r(X,Y)-max(0,min(r(X,Y),b(X,Y))-g(X,Y))':g='g(X,Y)':b='b(X,Y)-max(0,min(r(X,Y),b(X,Y))-g(X,Y))':a='alpha(X,Y)'
```

- Ключ по медиане фона: плита `#00B140` после H.264 CRF 18 → `chroma --key auto` даёт `#00B03F`, `bg_ok_min` 0,992, дрейф
  объекта 1,5 % ширины `[проверено]`.
- `colorkey` (RGB) на чистом входе — IoU 0,980–0,993; на сжатом — 0,971–0,975, ореол выше; `chromakey` устойчивее к 4:2:0
  `[проверено]`.
- Кеер CbCr на numpy (H/01, `../08-image-post-processing/01` §3.3) — тот же класс, что `chromakey`: IoU 0,971–0,992 `[проверено]`.
- Мерцание края у всех кееров ≈ эталону (±0,7 ×1000) — на рендерах; у реальных выходов моделей «кипение» края
  `[не проверено]` — метрика `flicker_excess` в `key_lab.py`.

## 3. Синемаграф: неподвижное по маске, движение — петлёй

Путь `VID-CINEMAGRAPH`: кадр A → i2v с `fixed_lens` (Seedance 1.5 Pro, I-03/I-04; промт «один очаг движения») → маска зоны
движения (вода, огонь, пар) → стоп-кадр 0 для остального (`maskedmerge`) → петля зоны движения (срез или кроссфейд,
`01` §3) → кодирование (`03`).

| Шаг (I/02b: «выход модели» с ползущей камерой 0,03 px/кадр и экспозицией +2 %) | Дрейф неподвижных зон | ΔE00 зон | Шов / локальный |
|---|---|---|---|
| выход модели | 6,37 | 1,20 | 45,9 / 45,8 |
| + заморозка по маске | **0,25** (шум кодека) | 0,51 | 26,4 / 115 |
| + кроссфейд хвоста 12 кадров | 0,23 | 0,42 | 5,1 / 2,7 |

```bash
# ffmpeg 7.1.5 · синемаграф: [0] видео, [1] то же видео → стоп-кадр 0, [2] маска движения (белое — из видео, растушёвка 1–2 px)
# [проверено]
ffmpeg -i in.mp4 -i in.mp4 -loop 1 -i motion_mask.png -filter_complex \
 "[1:v]trim=end_frame=1,loop=loop=-1:size=1,setpts=N/24/TB[still];[2:v]format=gray,scale=640:360[m];\
  [0:v]format=yuv444p[v];[still]format=yuv444p[s];[m][v]scale2ref[m2][v2];[s][v2][m2]maskedmerge,format=yuv420p[out]" \
 -map "[out]" -frames:v 144 -r 24 -an -c:v libx264 -qp 0 cinemagraph_mezz.mp4    # -qp 0 вместо CRF 10 — поправка X2 24.09.2026 (K/03, M/03)
```

- Маска: зона движения + растушёвка 1–2 px; граница маски — по естественным краям (берег, рама окна), иначе заметен
  «шов» между живым и замёрзшим `[мнение]`.
- Проверка: `video_loop_check.py drift cinemagraph.mp4 --mask still_mask.png` → `drift_max` < 1,0 (шум кодека),
  `dE00_max` < 2; зона движения — `loop` (шов ≤ 1,5).
- Маска не исправляет камеру: если в зоне движения камера ползёт, шов остаётся (2,7–5,1) → только `fixed_lens`/«Locked
  camera» на генерации `[проверено]`.
- Сдвиг экспозиции модели по ходу ролика даёт разницу яркости на границе маски (ΔE00 до 0,5 за 6 с) — для длинных роликов
  подгонять цвет зоны движения к стоп-кадру `[мнение]`.

## 4. Поставка альфа-видео

| Поставка (2 с, 640×360, 24 fps) | Вес | Где играет | Как проверить альфу |
|---|---|---|---|
| VP9-alpha WebM, `-pix_fmt yuva420p -c:v libvpx-vp9 -crf 30…40 -b:v 0` | 30 / 16 КБ | Chrome, Firefox, Edge | `ffmpeg -c:v libvpx-vp9 -i in.webm …` (встроенный декодер альфу теряет) |
| stacked alpha (кадр ×2 по высоте: RGB сверху, альфа снизу) AV1 SVT CRF 40 | **10,5 КБ** | везде, где AV1 + WebGL2 | нижняя половина = альфа (MAE 0,15 ×1000 к исходной) |
| stacked alpha HEVC x265 CRF 28 `-tag:v hvc1` | 18,7 КБ | запас для Safari | — |
| HEVC-alpha нативно | — | Safari | кодируется только на macOS (VideoToolbox) `[практика]`; libx265 в ffmpeg 7.1.5 альфу молча отбрасывает `[проверено]` |
| H.264 на цвете фона страницы (без альфы) | 12,2 КБ | везде | если фон страницы однотонный — альфа не нужна |

```bash
# ffmpeg 7.1.5 · из PNG-секвенции с альфой — [проверено: I/03; команды 3d A/06, 05 §3.15]
ffmpeg -framerate 24 -i keyed_%04d.png -pix_fmt yuva420p -c:v libvpx-vp9 -crf 30 -b:v 0 -row-mt 1 -an obj_alpha.webm
ffmpeg -framerate 24 -i keyed_%04d.png -filter_complex \
  "[0:v]format=pix_fmts=yuva444p[main];[main]split[main][alpha];[alpha]alphaextract[alpha];[main][alpha]vstack" \
  -pix_fmt yuv420p -c:v libsvtav1 -preset 8 -crf 40 -movflags +faststart -an obj_stacked_av1.mp4
```

- Однотонный фон страницы → альфа не нужна: композит на цвете фона и обычный H.264/AV1 (12 КБ) `[проверено]`.
- Шейдер stacked-alpha (RGB — верхняя половина, альфа — нижняя, фильтрация NEAREST) и порядок `<source>` — 3d `05`
  §3.15 и агент J.

## 5. Hero с парящим объектом (рецепт W5 с числами I)

1. Картинка сцены (модель картинок) → **две картинки из одной**: объект на ключе правкой («Change only the background to a
   flat, uniform chroma-key …») и подложка — удалением объекта по маске с дилатацией (+≈ 9 % стороны, H/03)
   [V:BVMuRw8BgJg 00:33] (H-07, `../08-image-post-processing/01` §2.2).
2. i2v объекта: Seedance 1.5 Pro, `fixed_lens`, «floats up and down very slowly and slightly. No zoom, no spin, do not
   reposition the subject… The background stays a plain, flat, solid green» (I-06, 5,25 ₽).
3. Приёмка ключа (`chroma`), кеинг `chromakey` + despill (§1.3), петля объекта (`01` §3; парение — симметричное движение,
   пинг-понг допустим).
4. Альфа-видео (§4) поверх статичной подложки (AVIF) + параллакс слоёв ≈ 40 % по прокрутке/курсору (J) [V:BVMuRw8BgJg 08:33].
5. Переход объекта между двумя состояниями (крышка открывается) — два выровненных ключевых кадра на ключе (I-14).

## Частые ошибки

- Ключ `#00B140` под золотой или зелёный объект: «съеденные» части при первой же неточной similarity.
- Ключ по hex из промта вместо медианы фона кадра — модель не держит hex.
- `hsvkey` с «правильными» S и V из HSV — у ffmpeg другая шкала, ключ не срабатывает (IoU 0,07 — фон не вырезан).
- despill-фильтр на золоте (уводит в медь) вместо `geq` G ≤ max(R, B); отсутствие despill (ореол ΔE00 до 10).
- Ожидать, что despill уберёт рефлекс ключа на металле.
- Проверять VP9-alpha встроенным декодером ffmpeg и «находить», что альфа пропала.
- Маской «лечить» ползущую камеру синемаграфа.
- Ошибки нейросетей-агентов: «модель X отдаёт видео с альфой» (ни одна; ProRes 4444 Runway — альфа непрозрачна);
  «HEVC-alpha можно закодировать ffmpeg на Linux» (libx265 в ffmpeg 7.1.5 не принимает `yuva420p` и молча пишет `yuv420p` — альфа теряется без ошибки `[проверено]`; только stacked); GIF как запас для прозрачного
  видео; `despill` для пурпурного ключа (фильтр знает только green и blue).

## Чек-лист

- [ ] Цвет ключа выбран по оттенкам объекта (золото/зелень → пурпурный)?
- [ ] Выход модели: фон ≥ 95 % в ΔE00 ≤ 5, камера стоит, объект не дрейфует > 2 % ширины?
- [ ] Ключ взят по медиане фона (`chroma --key auto`), кеер `chromakey` с подобранной similarity?
- [ ] despill: зелёный — `geq` G ≤ max(R, B); пурпурный — вычет общего избытка R и B?
- [ ] Металл после кеинга сверен по цвету с эталоном/студийным кадром?
- [ ] Альфа проверена декодером libvpx (VP9) или по нижней половине (stacked)?
- [ ] Для синемаграфа: неподвижные зоны `drift_max` < 1, шов зоны движения ≤ 1,5?
- [ ] Фон страницы однотонный? Тогда без альфы — композит и обычное видео.

## Открытые вопросы и противоречия

- Держат ли модели ровный ключ (I-06): у рендера фон идеален, у модели — виньетка, шум, дрейф оттенка; пороги `chroma`
  (95 % в ΔE00 ≤ 5) — предложение.
- «Кипение» края у реальных выходов моделей (4:2:0, шум) — не измерено; нужен ли временной фильтр альфы.
- Коррекция цвета металла по маске после кеинга — гипотеза, не проверена.
- Пурпурный ключ и модели: рисуют ли модели ровный `#FF00FF` так же охотно, как зелёный хромакей (зелёный — «привычный»
  фон в данных) — не проверено; при провале — правкой картинки ключ на кадре, а не в промте видео.
- Видео-матирование высокого качества (RVM, MatAnyone) — только обзор; здесь не запускалось.
