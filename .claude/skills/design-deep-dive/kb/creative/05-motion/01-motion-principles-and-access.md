## Выжимка для агента

1. **Нормы движения приложений на сайте — умолчание L0, а не закон**: запреты ui и ux (появление при прокрутке, параллакс,
   бесконечные фоны, «один движущийся элемент», потолок 300–400 мс) выведены для рабочих экранов с частыми повторами;
   на маркетинговой странице их заменяют правила этого файла. Для сервисов нормы соседей в силе. → §2 `[практика]`
2. **Каждое движение относи к одному классу** — `one-shot` (разовое ≤ 5 с), `scroll-linked` (прогресс = позиция прокрутки),
   `loop` (самопроизвольное, бесконечное или > 5 с), `pointer` (только от указателя), `transition` (переход страниц и
   состояний): от класса зависят WCAG, бюджет внимания и reduce. → §1.3 `[практика]`
3. **WCAG 2.2.2 требует трёх условий сразу**: запуск автоматически (в том числе прокруткой в видимость и наведением) **и**
   дольше 5 с **и** параллельно с другим контентом. Разовое появление 300–1 200 мс под 2.2.2 не попадает; петля,
   стартующая при появлении, попадает. → §3.2 `[стандарт]`
4. **У каждой петли дольше 5 с рядом с контентом — механизм**: видимая пауза (одна на все петли страницы — лучшая практика
   W3C), остановка за ≤ 5 с (добег цикла, стоп на кадре 0) или показ без параллельного контента (только заставка).
   «Стоп, пока курсор или фокус на элементе» механизмом не считается. → §3.3 `[стандарт]`
5. **`prefers-reduced-motion` механизмом 2.2.2 не считается**: пауза нужна всем, reduce — дополнительно. → §3.3 `[стандарт: вывод из определения mechanism — прямо в Understanding 2.2.2 не сказано]`
6. **Вспышки — блокер на любом уровне**: не больше 3 в секунду; глитч-переходы, стробы, bloom, резкие склейки ИИ-видео,
   мигающий CTA проверяются по кадрам. → §3.4 `[стандарт]`
7. **2.3.3 (AAA) закрывается reduce**: всё, что движется от взаимодействия сверх самой прокрутки (параллакс, скраб, pin,
   наклон к курсору, переходы страниц), отключаемо — `prefers-reduced-motion` (C39, SCR40) или переключатель сайта (Gx).
   → §3.5 `[стандарт]`
8. **Reduce, not remove**: убрать самопроизвольное и пространственное движение (смещение, масштаб, поворот, параллакс,
   скраб, стаггер, перелёт), оставить прозрачность, цвет, мгновенные смены и весь смысл; скраб → дискретные «станции»,
   видео и 3D → постер, петли → стоп. → §4 `[консенсус]`
9. **Reduce пишется «от статики»**: анимации — только внутри `@media (prefers-reduced-motion: no-preference)` или ветки
   `gsap.matchMedia()`; JS слушает `change`; глобальный сниппет `* { animation-duration: .01ms !important }` — антипример.
   → §4.3 `[стандарт]` `[консенсус]`
10. **Reduce проверяй записью всей страницы**: у лидеров reduce гасит первый экран, а ниже движение остаётся (Stripe — 1 из
    13 пауз, Max Mara — появления почти везде); уважают reduce 4 из 21 страницы с движением. → §4.5 `[данные: C]`
11. **В reduce: 0 байт видео, 0 вызовов WebGL в покое, 0 бесконечных CSS-анимаций** (у Linear в reduce крутятся 76
    бесконечных анимаций в скрытых элементах — для батареи это движение). → §4.2 `[данные: C]`
12. **Контент видим без JS**: начальное скрытое состояние появления ставит скрипт (`html.js .reveal`), а не голый CSS
    `opacity: 0`; при отказе скрипта, в reduce и для роботов-скриншотеров страница полна. → §4.3 `[мнение вендора]` → E/01
13. **На L2 — переключатель «меньше движения»** на странице, он же единая пауза петель: три состояния (как в системе /
    полное / сокращённое), выбор помнится и побеждает настройку ОС в обе стороны. → §4.4 `[стандарт: пример Understanding
    2.3.3]` `[не проверено: объединение с паузой]`
14. **Бюджет внимания вместо «одного движущегося элемента»**: непрерывных движений (объектов-петель) одновременно в видимой
    зоне L0 ≤ 1, L1 ≤ 2, L2 ≤ 3; `one-shot`, `scroll-linked` и `pointer` в покое не считаются. → §5.2 `[данные: C]` `[не проверено]`
15. **Считай объекты, а не пятна маски**: дорожка бегущей строки из 8 логотипов — одно движение; маска записи — верхняя
    граница (> 12 областей — сигнал «шум»). → §5.1 `[данные: C]`
16. **Ни одной петли под читаемым текстом** (абзацы, лид, списки, формы, цены) и в секциях конверсии; под display-заголовком
    — только «дышащий» фон ≤ 2,5 % пикселей в секунду с контрастом F83 в худшем кадре. → §5.3 `[данные: C]` `[исследование]`
17. **Громкость петли**: «дыхание» ≤ 2,5 % меняющихся пикселей в секунду покоя; > 5 % — «громкий» слой: только первый
    экран, с паузой, reduce и без текста над ним без скрима. → §5.4 `[данные: C]`
18. **Пики и акценты**: L0 — пиков 0, акцент ≤ 1 (hero); L1 — пиков ≤ 2, акцентов ≤ 3; L2 — пиков 2–4, между пиками ≥ 1
    спокойная секция; два пика подряд не ставить. → §5.5 `[данные: C]` `[не проверено]`
19. **Колебания крупных объектов и фона: период ≥ 10 с или непериодический шум**; полоса 2,5–6 с (0,17–0,4 Гц) запрещена;
    амплитуда ≤ 2–4 % высоты объекта, при необходимости — полупрозрачность. «Парение» 3–4 с 3d попадает в пик тошноты.
    → §6.3 `[исследование]` `[документация]` + `[не проверено: перенос на экран]`
20. **Рассогласование с прокруткой дозируй**: слои параллакса — разница скоростей ≤ 40 % (фон до 24vh на экран прокрутки),
    текст едет со страницей, крупные объекты не масштабируются и не панорамируются на весь экран; скорость и направление
    прокрутки не меняются никогда. → §6.2 `[консенсус]` `[исследование: NN/g]` `[не проверено: числа]`
21. **Периферия дороже центра**: петли у краёв широкого экрана и полноэкранные «наплывы» — только L2 и с reduce. → §6.1 `[документация]`
22. **Пульсация CTA — не петля**: один-два импульса по событию (простой ≥ 8 с, конец сюжета), масштаб ≤ 1,05 или только
    свечение, всё за < 5 с; бесконечная пульсация — нарушение 2.2.2 и давление на пользователя. → §6.4 `[стандарт: пример
    Understanding 2.2.2]`
23. **Длительности маркетинга — по роли, а не по потолку приложений**: отклик 100–160 мс, наведение 150–250, появление
    элемента 400–700, сцена первого экрана 600–1 200 всего, раскрытие заголовка ≤ 1 000, сцена прокрутки — длиной прокрутки
    100–150vh на шаг, петли — секундами (строка 30–60 px/с, «дыхание» ≥ 10 с). → §7.1 `[консенсус]` `[данные: C]`
24. **Кривые**: вход — экспоненциальный ease-out `cubic-bezier(0.16, 1, 0.3, 1)`, выход короче входа на ≈ 25 %, перемещение по
    экрану — `cubic-bezier(0.65, 0, 0.35, 1)`, петли — `linear`, скраб — без кривой (прогресс = прокрутка) со сглаживанием
    ≤ 0,5–1 с или пружиной без перелёта. → §7.2 `[консенсус]`
25. **Пружины — на геометрии от указателя и жестов** (магнит, курсор, перетаскивание; bounce ≤ 0,2) **и на прогрессе
    прокрутки сцены** — только критически демпфированная, без перелёта: скраб ω 6,5 (95 % за 0,73 с), такт шагов с
    доигрышем ω 2,4–3,6; пружина с отскоком на прогрессе запрещена; текст, цвет и прозрачность не пружинят. → §7.3
    `[консенсус]`; прогресс — `[проверено]`
26. **Стаггер 40–80 мс, сумма ≤ 600 мс** на группу (сцена первого экрана — ≤ 1 200 мс всего); каскад — только если группа
    видна как список, не на каждой секции. → §7.4 `[консенсус]`
27. **Числа движения бери из токенов** `motion.marketing` (DTCG `duration`, `cubicBezier`, reduce-модификатор), а не
    изобретай: «красивые» 0.35s, 0.45s, 0.65s — примета генератора. → §7.5 `[практика]`
28. **Генераторы ошибаются предсказуемо**: fade-and-slide-up на каждой секции, анимация свойств раскладки (K3 — 13 из 13),
    `transition: all`, бегущая строка 155–164 px/с (K3) против 30–60 у лидеров, reduce только в CSS при JS-анимациях. → «Частые ошибки»
    `[данные: C, kimi]`

## 1. Что меняется на сайте

### 1.1. Разовый визит и частота

- Правило частоты приложений («hundreds of times a day» — Kowalski, Rauno Freiberg; «avoid adding motion to UI interactions
  that occur frequently» — Apple) выведено для действий, которые повторяются в рабочем дне (`../../ui/08-motion/02-what-to-animate-in-apps.md`
  §7.1) [S13]. На посадочной странице большинство движений человек видит **один раз**: сцена первого экрана, сюжет прокрутки,
  раскрытие продукта. Правило частоты на сайте применимо к тому, что повторяется: наведение и нажатие, переходы между
  страницами многостраничника (каждый переход — десятки раз за визит), меню, аккордеоны, карусели.
- Emil Kowalski разрешает цель **Explanation** только «marketing/onboarding», а бюджет «delight» — редким событиям; длительность
  «Marketing / explanatory — Can be longer» (`animate/SKILL.md`) [S21] `[мнение вендора]`. impeccable: в режимах Persuade и
  Experience «motion may carry the voice. Prefer one rehearsed focal sequence to repeated section reveals» [S23].
- Отсюда граница: **отклик интерфейса** (кнопки, поля, меню, фокус) на сайте живёт по нормам ui (`08/01` §1.2: 50–150 мс
  интерактив, 150–400 мс переходы); **подача** (сцены, появления, петли, прокрутка) — по этому файлу.

### 1.2. Что подача добавляет к нормам ui

## 3. WCAG 2.2: 2.2.2, 2.3.1, 2.3.3 — дословно и как читать на сайте

### 3.1. Тексты критериев [S1] [S2] [S3]

- **2.2.2 Pause, Stop, Hide (A)**: «For any moving, blinking or scrolling information that (1) starts automatically, (2) lasts
  more than five seconds, and (3) is presented in parallel with other content, there is a mechanism for the user to pause,
  stop, or hide it unless the movement, blinking, or scrolling is part of an activity where it is essential». Для
  автообновления — «(1) starts automatically and (2) is presented in parallel with other content» — **без исключения 5 с**.
- **2.3.1 Three Flashes or Below Threshold (A)**: «Web pages do not contain anything that flashes more than three times in any
  one second period, or the flash is below the general flash and red flash thresholds».
- **2.3.3 Animation from Interactions (AAA)**: «Motion animation triggered by interaction can be disabled, unless the
  animation is essential to the functionality or the information being conveyed». Motion animation — «addition of steps
  between conditions to create the illusion of movement or to give a sense of a smooth transition»; поправка errata:
  размытие (blurring) из определения **не исключается**.

### 3.2. «Запуск автоматически» — разбор случаев

Understanding 2.2.2: «"starts automatically" broadly refers to animations/updates that are not the direct result of a user's
intentional activation, for example, selecting a link or button» и «…when it starts as a result of an indirect interaction
(such as focusing/hovering over an element, or scrolling an element into view). Content that starts automatically from an
indirect interaction also potentially fails 2.3.3» [S1]. Пять секунд выбраны как время, за которое движение «успевает привлечь
внимание, но его ещё можно переждать» [S1].

### 3.3. Механизм паузы: что считается, что нет

- **Три законных пути** = поле `treatment.loop_control` A: `pause-button` (видимая кнопка; может ссылаться на общую
  кнопку страницы), `stops-within-5s` (движение само останавливается за ≤ 5 с — «добег цикла» и стоп на кадре 0; повтор по
  наведению и фокусу разрешён: это уже прямая активация), `not-parallel-content` (только заставка без другого содержимого).
  Правило site I: `loops ≥ 1` → `loop_control` обязателен [S18] `[стандарт]`.
- **Одна пауза на все петли** — лучшая практика W3C: «provide a single mechanism… that affects all these elements at the same
  time»; отдельные кнопки у каждой петли норму выполняют, но «won't result in a good user experience» [S1 стр. 93–95].
- **Не механизм**: остановка «only so long as a user has focus on it» [S1 стр. 73]; пауза только при наведении; reduce
  (пауза нужна и тем, у кого системная настройка не включена — частая ошибка агентов, `site 08/03` «Частые ошибки» п.13) [S18];
  про reduce Understanding 2.2.2 прямо не говорит — это вывод из определения механизма (управление на странице, доступное каждому)
  `[стандарт: вывод]` (сверка X по кэшу, отчёт X §5 № 2).
- **Длительность — это время движения, а не длина клипа**: петля 2 с, повторяемая бесконечно, «длится» дольше 5 с
  (`../../ai-media/10-web-integration/02-video-delivery.md` §5) [S16].
- **Кнопка**: видимая, ≥ 44 × 44 px на тач (≥ 24 × 24 — минимум 2.5.8), `aria-pressed`, имя меняется («Остановить
  движение» / «Запустить движение»), контраст значка ≥ 3:1 (1.4.11), не поверх текста; выбор помнится (`sessionStorage`,
  на L2 — `localStorage` вместе с переключателем §4.4); показывается, только когда движение действительно идёт [S16].
- **Проверка поведением**: что ещё движется на 6-й секунде после `load` (видео играет или меняется ≥ 0,5 % пикселей) и есть ли
  видимая кнопка с именем «пауза/остановить» — `page_accept.py` ai-media [S16]; для прокрутки — запись C по паузам (`█`).
- Практика рынка: пауза у непрерывного движения — 1 из 20 эффектных страниц, общего переключателя — 0 из 49 (C); у 10
  рыночных страниц site — кнопка паузы у одной [S20] [S18]. Норма базы требует механизм **явно** в `motion-spec` и `TASK`.

### 3.4. Вспышки (2.3.1) на маркетинговой странице

- Порог: не больше трёх общих и трёх красных вспышек в любую секунду, либо суммарная площадь одновременных вспышек ≤ 0,006 ср
  (≈ 25 % поля зрения 10°; прямоугольник 341 × 256 px при 1024 × 768); общая вспышка — пара противоположных изменений
  относительной яркости ≥ 10 % при тёмном состоянии < 0,80; красная — переход с R/(R+G+B) ≥ 0,8 и разностью > 0,2 в CIE 1976
  UCS; для HDR-видео — ≥ 20 кд/м² при тёмном < 160 кд/м² (ITU-R BT.1702) [S3] `[стандарт]`.
- Мигание чаще 3 раз в секунду — уже вспышка, а не «blinking»; выключатель не спасает: приступ наступает быстрее, чем
  человек нажмёт кнопку [S3] (`ux 06/03` §7.1) [S14].
- Где бьёт на сайтах: глитч-переходы и «стробы» между сценами, чёрно-белые мерцания в интро, bloom-вспышки WebGL, резкие
  склейки и молнии в ИИ-видео, мигающий CTA, быстрая смена слайдов в полноэкранном hero. Проверка — покадрово по записи
  (60 кадров/с) или инструментом (G15, PEAT); для ИИ-видео — до публикации (приёмка ai-media) [S16].
- Поле `flash_check: {method, result, checked_at}` в `treatment` для секций с видео и интро — предложение site I; I добавляет в
  v1 схемы [S18] `[практика]`.

### 3.5. 2.3.3 и прокрутка

- Understanding 2.3.3: «Moving new content into the viewport is essential for scrolling… Only add non-essential animation to the
  scrolling interaction in a responsible way. Always give users the ability to turn off unnecessary movement» [S2 стр. 34].
  Пример W3C: «Parallax scrolling with option to turn off unnecessary motion globally… The ability to turn off non-essential
  animations is a site-wide setting» [S2 стр. 44–45] — прямая опора CRV-AL-12 (§4.4).
- Три способа соответствия: не использовать ненужную анимацию; дать контрол выключения; использовать настройку reduce в ОС или
  браузере (техники C39 — CSS, SCR40 — JS, Gx — своя настройка) [S2] [S4] `[стандарт]`.
- Позиция базы: **reduce-ветка обязательна на всех уровнях** (CRV-AL-01, `treatment.reduce` при `effects` или
  `motion_level ≥ expressive`); переключатель на странице — обязателен на L2, рекомендован на L1 с `scroll-linked` в ≥ 2
  секциях `[не проверено]`.
- `prefers-reduced-motion` — Baseline Widely available с января 2020 [S5] (`ui 08/03` §1.1) `[документация]`: отсутствие
  ветки в 2026 году — дефект, а не «недоработка».

## 4. Reduce, not remove

### 4.1. Что убирать и что оставлять

| Оставить | Убрать или заменить |
|---|---|
| смену прозрачности ≤ 200 мс, цвет, мгновенные смены состояния | смещение > 8 px, масштаб > ±5 %, поворот, перелёт пружин |
| отклик интерфейса (наведение, нажатие, фокус) без смещения | параллакс, скраб с инерцией, pin-сцены, горизонтальные секции |
| ручное управление (прожектор под курсором, ручной поворот 3D) | самопроизвольные петли: бегущие строки, живые фоны, idle 3D, видео |
| индикаторы загрузки и прогресса (essential) | стаггер и каскады (всё — сразу) |
| весь смысл: тексты, цифры, CTA, конечные кадры сюжета | переходы страниц и View Transitions (или crossfade ≤ 200 мс) |

Основание: Val Head — безопасны «non-moving properties, like opacity, color, and blurs» (через `ui 08/03` §3.2) [S9] [S13];

reduce — замена способа перехода, а не удаление, CTA и обход Tab остаются [V:_ZdZh-ESOHY 04:05–05:05], «reduce ≠ no motion»
[V:UcXWY057YuQ 01:45]; 3d — таблица reduce по
приёмам (`09/03` §8) [S15]; W3C — «reduce motion feature» как способ соответствия 2.3.3 [S2] `[консенсус]`. Количественных
исследований пользы reduce нет (`ui 08/03` §11 п.4) — правила держатся на стандарте и консенсусе.

### 4.3. Как писать

```css
/* Chrome 153 · WebKit 2359 · 2026-09-24 · [проверено частично: E/01 — LCP при .01 и transform; E/03 — токены reduce и data-motion]
   Статика — по умолчанию; движение — только при no-preference и только когда скрипт готов (класс html.js). */
.reveal { opacity: 1; transform: none; }
@media (prefers-reduced-motion: no-preference) {
  html.js .reveal:not(.is-in) { opacity: 0; transform: translateY(var(--mm-shift-reveal, 16px)); }
  html.js .reveal { transition: opacity var(--mm-dur-reveal, 560ms) var(--mm-ease-out-expo),
                                transform var(--mm-dur-reveal, 560ms) var(--mm-ease-out-expo); }
  /* период = ширина дорожки / --mm-marquee-speed (40 px/с); скрипт пишет --mm-marquee-period на элемент */
  .marquee__track { animation: marquee var(--mm-marquee-period, 40s) linear infinite; }
}
:root[data-motion="reduced"] .marquee__track,            /* переключатель сайта побеждает ОС в обе стороны */
:root[data-motion="paused"] .marquee__track { animation-play-state: paused; }
```

```js
// GSAP 3.15.0 · 2026-09-24 · [проверено частично: E/02 — ветка matchMedia, pin с pinType "transform" (CLS 0); строки hero не проверялись]
const mm = gsap.matchMedia();
mm.add({ full: "(prefers-reduced-motion: no-preference)", reduce: "(prefers-reduced-motion: reduce)" }, (ctx) => {
  if (ctx.conditions.reduce || document.documentElement.dataset.motion === "reduced") return; // статика
  gsap.from(".hero .line", { yPercent: 100, duration: 0.9, ease: "expo.out", stagger: 0.06 });
  gsap.to(".story .frame", { scrollTrigger: { trigger: ".story", pin: true, pinType: "transform", scrub: 0.6, end: "+=300%" },
    xPercent: -75 });                                        // pinType "transform": CLS при прокрутке 0 вместо 1,6–2,0 (E/02)
  return () => {};                                           // при смене условий всё откатывается (mm.revert)
});
```

- **Порядок «от статики»**: анимации объявляются внутри `no-preference` (C39, обратный подход) — у браузера, который
  медиазапрос не понимает, движения нет (`ux 06/03` §7.2, web.dev) [S4] [S14] `[стандарт]`.
- **JS слушает изменение**: `matchMedia('(prefers-reduced-motion: reduce)').addEventListener('change', …)`; `gsap.matchMedia()`
  откатывает всё, созданное в ветке, при смене условия [S24]; видео — пауза и `display: none` на лету (ai-media J/04) [S16].
- **Отдельно выключать** то, что не покрывают токены: `@keyframes`-петли (`animation: none` или `animation-play-state: paused`),
  `scroll-behavior: smooth` → `auto`, View Transitions (проверка `matchMedia` до `startViewTransition` и
  `::view-transition-group(*) { animation: none }`), цикл WebGL (`setAnimationLoop(null)` после одного кадра), Lenis (сам) [S13] [S25].
- **Не писать** глобальный `*, *::before, *::after { animation-duration: .01ms !important; … }`: ломает `animationend`,
  выключает безопасные затухания, превращает перемещение в скачок (`ui 08/03` §3.3) [S13] `[консенсус]`; Hallmark делает так с
  150 мс — не копировать [S22].
- **Контент видим при отказе скрипта**: скрытое начальное состояние ставит скрипт (класс `html.js` в `<head>` до стилей
  появления) — impeccable: «Keep content visible in the default state so failed scripts do not hide the page» [S23]
  `[мнение вендора]`; проверка — прогон с отключённым JS.

### 4.4. Переключатель «меньше движения» (CRV-AL-12) и единая пауза

- **Где обязателен**: L2 — всегда; L1 — при ≥ 1 петле (как механизм 2.2.2) или ≥ 2 секциях `scroll-linked` `[не проверено]`.
  Образец Chrome: чекбокс «Reduce Animation» ставит класс на контейнер, громкие переходы заменяются [V:_ZdZh-ESOHY 06:08–07:10];
  Paquet: тяжёлое движение как режим по выбору («Vibe mode» Afterglo) [V:J6aNMFZogyk 19:34] `[кейс]`.
  Практика: переключателя нет ни у одной из 49 эффектных страниц C [S20] — норма требует его явно.
- **Что делает**: одна кнопка в шапке или у первой петли; состояния `data-motion` на `<html>`: нет атрибута — как в системе;
  `reduced` — reduce-ветка для всей страницы (петли стоят, скраб → станции, переходы без анимации); `full` — полное движение
  вопреки ОС. Выбор пользователя побеждает ОС в обе стороны (`ui 08/03` §3.6) [S13]; помнится в `localStorage` (L2) — при
  повторном визите страница не «взрывается» снова.
- **Он же механизм 2.2.2**: состояние `reduced` останавливает все петли сразу — «single mechanism… that affects all these
  elements at the same time» [S1]. Имя и `aria-pressed` меняются; клавиатура доступна; видна при любом уровне прокрутки (в
  липкой шапке) или повторяется у каждой секции с петлёй.
- **Интро и ворота**: содержимое доступно без интро — кнопка «Пропустить» видима с первой секунды, интро ≤ 3 с, при reduce
  интро нет (CRV-AL-12) [S19].

### 4.5. Как проверять reduce

- **Парой прогонов всей страницы**, а не первым экраном: у Stripe в reduce движется 1 пауза из 13, у Max Mara — разовые
  появления почти в каждой паузе, у Lisa — всё как было [S20] `[данные: C, n = 3 записи]`.
- **Критерии прохождения** (кандидаты C, приняты E): движение первого экрана ≤ 0,3 % пикселей в секунду; ни одной паузы с
  непрерывным движением (`█`) на всей записи; 0 запросов видео; 0 вызовов WebGL в покое; 0 бегущих бесконечных CSS-анимаций
  (в том числе в скрытых элементах); активных твинов GSAP ≤ 20 % обычного режима; содержимое и CTA видимы [S20].
- **Частые провалы по C**: WebGL под reduce рисует у 11 из 12, видео играет у 7 из 8, бегущая строка идёт у 2 из 5; три
  страницы в reduce двигаются **сильнее** (MTS Media 21,5 → 76,9 %) — ветка меняет сценарий, а не гасит его [S20].
- **Упоминание ≠ поддержка**: `prefers-reduced-motion` в CSS у 25 из 49 страниц, а итог «yes» — у 4 [S20].

## 5. Бюджет внимания

### 5.1. Что считается

- **Единица — непрерывное движение**: объект класса `loop`, который движется в покое в видимой зоне (дорожка бегущей строки,
  живой фон, видео-петля, Lottie-петля, idle 3D, анимированное зерно, крутящийся бейдж). `one-shot` после завершения,
  `scroll-linked` без прокрутки и `pointer` без указателя — 0.
- **Считать объекты, а не области маски**: запись C даёт связные области разницы кадров; бегущая строка из 8 логотипов — до 8
  областей, лента-градиент — 1–3; по записям медиана максимума 5 областей (Q3 12, max 19) [S20] `[данные: C]`. Маска — верхняя
  граница; > 12 областей — сигнал «шум», разбирать объекты по кадрам.
- **Механизм внимания**: движение ловится периферийным зрением и перехватывает внимание снизу вверх; сильнее — у «одушевлённого»
  движения со сменой позиции, чем у проявления на месте (Pratt, Radulescu, Guo, Abrams 2010, через `ux 06/03` §2.2) [S12]
  `[исследование]`; Paquet: «если движется один элемент — на него смотрят все», много движущегося — «headaches»
  [V:J6aNMFZogyk 04:14–05:16, 22:21] `[мнение]`; одновременные анимации конкурируют и обнуляют друг друга (NN/g, Hipmunk) [S14]; Apple — движение на краях
  поля зрения отвлекает и вызывает дискомфорт [S6] `[документация]`.

### 5.2. Потолки по уровню

| Уровень | Непрерывных движений в видимой зоне | Под читаемым текстом | Что типично укладывается |
|---|---|---|---|
| L0 | ≤ 1 | 0 | тихий синемаграф или строка логотипов с паузой |
| L1 | ≤ 2 | 0 | шейдерная лента + строка логотипов (Stripe: 2 объекта, 1,6 % пикселей) |
| L2 | ≤ 3 | 0 | живой фон + видео-петля + idle 3D; на телефоне — на 1 меньше |

Данные: у 15 из 23 записанных страниц hero неподвижен после входа; движется в покое у 8 (0,4–9,5 % пикселей, 2–15 областей);
сплошное движение во всех паузах — только у студии и кампании (Lisa, Max Mara) [S20] `[данные: C]`. Числа 1 / 2 / 3 —
`[не проверено]` A, согласованная с практикой лидеров; проверка на людях — живая фаза. **Телефон**: при той же доле движущихся пауз
областей в 2–5 раз больше (Stripe 12 → 42) — потолок на телефоне на 1 меньше, чем на десктопе, минимум 1 [S20] `[не проверено]`.

### 5.3. Ни одного движения под читаемым текстом

- **Читаемый текст** — абзацы, лид, списки, подписи цен и тарифов, поля форм, согласия, цитаты длиннее строки. Петля не
  проходит под его рамкой с отступом ≥ 24 px и не занимает ≥ 10 % площади его колонки в соседних 200 px `[не проверено]`.
- **Секции конверсии** (`lead-form`, `pricing`, калькулятор, квиз, `final-cta` с формой) — `loops: 0` (A: секции конверсии
  L0) [S19].
- **Display-заголовок на живом фоне** разрешён: фон «дышит» ≤ 2,5 % пикселей в секунду, контраст по F83 в худшем кадре
  (`../../ai-media/10-web-integration/03-text-over-media-and-effects.md` §1) [S16]; лид под заголовком — на скриме.
- Основание: kimi T7 «nothing moves under text the visitor is reading» [S17]; NN/g — движение текста и под текстом
  «makes reading hard» и укачивает, изменённая прокрутка + меняющийся текст — худшая юзабилити [S10] [S11] `[исследование:
  качественное]`.

### 5.4. Громкость петли

| Класс петли | Доля меняющихся пикселей видимой зоны в секунду покоя | Где разрешено | Данные C |
|---|---|---|---|
| «дыхание» | ≤ 2,5 % | любой уровень с петлями, в том числе под display-заголовком | Stripe 1,6 %, Lisa 0,48 %, Max Mara 1,63 % |
| заметная | 2,5–5 % | L1–L2, не под текстом | Moto Finance 1,59, Trevor Noah 1,84 % (hero) |
| громкая | > 5 % | только L2 и первый экран; пауза видна сразу; текст — на скриме | Squarespace 9,5 % и 7 областей (видео) |

Метрика — `motion_idle_pct` `effects_probe.py` и паузы `scroll_record.py` C; порог шума 0,2 %, изменение пикселя — 12/255;
медленные градиенты ±1–2 % светлоты под порогом не видны — «дыхание» ниже порога метода считается ≤ 0,5 % `[данные: C]` [S20].

### 5.5. Пики, акценты и ритм

Норма `accent` (вопрос A, `03-ambition-levels.md` §6.1): **акцент** — секция с одним приёмом малой силы (одноразовое появление
заголовка, split-раскрытие, «дышащий» фон, мягкий параллакс одного слоя), без закрепления и без скраба; **пик** — главный приём
сцены (pin-скраб, 3D-сцена, горизонталь, видео-скраб, секвенция, полноэкранный переход).

| Уровень страницы | Пиков | Акцентов | Правило соседства |
|---|---|---|---|
| L0 | 0 | ≤ 1 (hero) | — |
| L1 | ≤ 2 | ≤ 3 | два пика подряд — нет |
| L2 | 2–4 | ≤ 4 | между пиками ≥ 1 секция `calm` или `pause`; `peak` + `peak` подряд — только одна сквозная сцена |

Данные: «вау-переход» (≥ 10 % пикселей разом после шага прокрутки) — у 6 из 23 страниц, 1–4 на страницу из 12 шагов, больше 4
не встретилось; спокойные паузы между «вау» — у 21 из 23 [S20] `[данные: C]`. Числа акцентов — `[не проверено]`; `c1_check.py`
A считает пики, счёт акцентов добавляет K. Хореография ритма — `02` §1.

## 6. Вестибулярные факторы

### 6.1. Что провоцирует

1. **Доля поля зрения под движением**: «full-screen wipe… likely would [cause trouble]» (Val Head через `ui 08/03` §1.2) [S9];
   «scaling or panning large objects can be vestibular motion triggers» (MDN) [S5].
2. **Рассогласование направления и скорости с прокруткой**: параллакс, скролл-джекинг, горизонталь от вертикального колеса;
   W3C: движение сверх самой прокрутки может запустить вестибулярную реакцию [S2].
3. **Дистанция и масштаб за короткое время**: полёт камеры, зум на весь экран [S9].
4. **Частота колебаний 0,2–0,4 Гц** (период 2,5–5 с) — §6.3.
5. **Периферия**: Apple — движение на краях поля зрения «can make people feel like they or their surroundings are moving» [S6].

Последствия по W3C: «nausea, migraine headaches, and potentially needing bed rest to recover» [S2]. Масштаб: около 8 млн
взрослых в США с хроническими нарушениями равновесия и 2,4 млн — с хроническим головокружением (vestibular.org через Val Head,
`ui 08/03` §1.2) [S9] `[данные: вторичный пересказ]`.

### 6.2. Числа для приёмов прокрутки

| Приём | Правило | Метка |
|---|---|---|
| параллакс слоёв | разница скоростей слоёв ≤ 40 %: фон смещается не больше 24vh на 100vh прокрутки (ai-media стр. 03: фон 24vh, объект −12vh); текстовые слои едут со страницей; эффект срабатывает один раз и объекты остаются в конечных позициях (NN/g) | `[данные: у ai-media]` [S16], `[исследование: NN/g]` [S11], предел 40 % — `[не проверено]` |
| масштаб по прокрутке | объект ≥ 50 % видимой зоны: изменение масштаба ≤ 1,2× за 100vh; полноэкранный «влёт» камеры — только L2, с reduce-станциями | `[не проверено]` по [S5] [S9] |
| горизонталь в закреплении | ≤ 5 панелей; одна панель ≈ 100vh прокрутки; прогресс виден | `[мнение]` 3d, NN/g [S10] |
| скорость и направление прокрутки | не меняются никогда: pin со скрабом — да, замедление колеса, «поэкранное» перелистывание, виртуальная прокрутка — нет | `[исследование: NN/g]` [S10], A (`ambition-levels.yaml` L2 forbidden `scroll-speed-change`) |
| плавная прокрутка | только L2; хвост ≤ 1,0 с на шаг колеса; тач — нативный | `[данные: C 0,8–1,4 с]` [S20], `[документация: исходник Lenis]` [S25] |

### 6.3. Колебания: одно число для «парения»

- **Первоисточники**: Diels и Howarth 2013 (Human Factors 55(3):595–604): 24 участника, оптический поток колебаний вперёд-назад
  0,025–1,6 Гц по 20 мин — пик укачивания **0,2–0,4 Гц**, «frequencies around 0.2 to 0.4 Hz should be avoided» [S7]
  `[исследование]`. Golding, Mueller, Gresty 2001 (Aviat Space Environ Med 72:188–192): физическое колебание, 12 чувствительных
  участников, умеренная тошнота 8/12 при 0,1 Гц, 12/12 при 0,2 Гц, 7/12 при 0,4 Гц [S8] `[исследование]`. Apple HIG: «avoid
  showing an oscillation that has a frequency of around 0.2 Hz… If you need to show objects oscillating, aim to keep the
  amplitude low and consider making the content translucent» [S6] `[документация]`.
- **Правило базы**: периодическое качание, «парение», пульсация и покачивание камеры объектов крупнее ≈ 10 % видимой зоны и
  любого фона — **период ≥ 10 с** (≤ 0,1 Гц) или непериодический шум без доминирующей частоты (сумма синусов с периодами без
  общих делителей); полоса **2,5–6 с запрещена**; амплитуда ≤ 2–4 % высоты объекта, наклон ≤ 3°; это петля → механизм 2.2.2 и
  reduce. Мелкие объекты (≤ 10 % зоны) — период ≥ 6 с; шиммер скелетона 1,5–2 с — как у ui.
- **Поправка к 3d 07/04 §5**: «парение 3–4 с» лежит в пике Diels (0,25–0,33 Гц) → для сайта 10–16 с (hero-lazy 3d
  качается с периодом ≈ 16 с) [S15].
- **Оговорка**: исследования — полноэкранный поток и физическое движение по 20–30 мин; на странице объект занимает часть поля и
  виден секунды — перенос `[не проверено]`, но направление безопасное и дешёвое.

### 6.4. Пульсация CTA и сигналы внимания

- Бесконечная пульсация (масштаб 1,15–1,25 по `3d 07/04` стр. 232) — петля > 5 с рядом с контентом (2.2.2), масштаб > ±5 %
  (пространственное движение), и давление на решение (`../../ux/06-feedback-states-motion/04-dark-patterns-and-ethics.md`).
- Разрешено: **1–2 импульса** (масштаб ≤ 1,05 или свечение/подсветка без масштаба, 400–600 мс на импульс) **по событию** — конец
  сюжетной сцены, простой ≥ 8 с на экране с CTA, возврат к форме; серия < 5 с; в reduce — смена цвета без движения. Прямая опора:
  пример W3C «A form blinks an arrow near the submit button if a user finishes filling out the form but does not activate the
  submit button. The blinking stops after 5 seconds» [S1 стр. 117] `[стандарт]`; числа импульса — `[не проверено]`.

- Длительность перемещения растёт медленнее расстояния (MUI: 36 px → 192 мс, 600 px → 376 мс) — крупной сцене не нужно
  «пропорционально дольше» [S13].

### 7.2. Кривые

| Роль | Кривая | Токен | Источник |
|---|---|---|---|
| вход, появление, раскрытие | `cubic-bezier(0.16, 1, 0.3, 1)` (экспоненциальный ease-out) | `easing.out-expo` | Hallmark, impeccable [S22] [S23] |
| отклик интерфейса | `cubic-bezier(0.23, 1, 0.32, 1)` | `easing.out-strong` | Emil [S21] |
| перемещение по экрану, переходы страниц | `cubic-bezier(0.65, 0, 0.35, 1)` | `easing.in-out` | Hallmark [S22]; Emil `(0.77, 0, 0.175, 1)` — сильнее |
| уход насовсем | `cubic-bezier(0.7, 0, 0.84, 0)`, длительность ≈ 75 % входа | `easing.in` | Hallmark [S22]; ui §3.1 [S13] |
| бегущая строка, скраб | `linear` | `easing.linear` | ui §2.1, Emil [S13] [S21] |
| «дыхание» | `cubic-bezier(0.37, 0, 0.63, 1)` (sine in-out) | `easing.breathe` | `[практика]` |

- De Cock (Stripe): встроенные кривые «not strong enough», `linear` — «an insult to motion designers»; ease-out по умолчанию, ease-in-out —
  для перемещения на экране, ease-in — только уход за край; правила: «Stick to opacity and transform… Be cautious with will-change»
  [V:fZpTvZuysIo 21:11, 26:34–30:02] `[практика]`.
- Встроенные `ease-out` и `ease` слабы для подачи; `ease-in` на входе — никогда (Emil) [S21]; bounce и elastic на тексте и
  кнопках — «dated; signals template» (Hallmark) [S22] `[мнение вендора]`.
- Скраб: прогресс = прокрутка, сглаживание `scrub: 0.5–1` (GSAP «takes 1 second to catch up»), `damp` λ 4–6 или пружина без
  перелёта ω 6,5 (§7.3); дольше 1 с — сцена «отстаёт» от пальца [S24] [S15]. Такт шагов с доигрышем (1,2–2 с) — не
  скраб: сцена не следует за пальцем, а доигрывает такт сама (`02` §4.1.1).

### 7.3. Пружины

- Геометрия от указателя и жестов: магнит, следование курсора, наклон карточки, перетаскивание; `damp` λ 6–10 (99 % пути
  за 0,77–0,46 с, 3d H/21) или пружина с bounce ≤ 0,2 (Emil 0,1–0,3; Apple snappy 0,15) [S15] [S21] [S13].
- **Прогресс прокрутки всей сцены** — критически демпфированная пружина без перелёта: точное решение за шаг кадра, без
  рывка в начале, устойчива на любой частоте экрана; 95 % пути — за 4,74/ω с. Скраб — ω 6,5 (95 % за 0,73 с), такт шагов
  с доигрышем — ω 2,4–3,6 (95 % за 2,0–1,3 с; `02` §4.1.1). Пружина с отскоком на прогрессе сцены запрещена.
  Основание — движение по колесу без пружины заказчик назвал «резко, неплавно» `[проверено]`; реализация — 3d 16/02 §4
  (`../../3d/16-js-scenes/examples/stage-runtime.js`, `spring`).
- Не пружинят с перелётом: текст и заголовки, цвет, прозрачность, крупные фоны, всё в reduce (пружина → ease-out без
  перелёта) [S13]; прогресс сцены — только без перелёта (выше).
- Тактаров (HolyJS): переходы по времени закрывают 80–90 % задач, но прерываются «не натурально»; пружины прерываются
  естественно, но без точной длительности и неудобны в последовательностях → в `motion-spec` поле `model: time | spring`; сглаженное
  следование — P-контроллер `x += P·(target − x)`, `P ≈ 0.001·delta`; вход и выход — автомат entering → entered → exiting → exited
  [V:Ug_dwJa07Os 18:32–23:41, 27:49, 34:55–36:58] `[практика]`.

### 7.4. Стаггер и каскад

- Шаг 40–80 мс (Emil 30–80, Hallmark 60 по индексу), сумма на группу ≤ 600 мс; сцена первого экрана ≤ 1 200 мс вместе со
  всеми шагами [S21] [S22] `[консенсус]`.
- Каскад — только если группа видна как список (impeccable: «never reinterpret every scrolled section as a staggered list»)
  [S23]; > 8 элементов — первые 6–8 с шагом, остальные сразу (ui: Carbon 20 мс, ≤ 500 мс) [S13].
- В reduce стаггер = 0 [S13].

### 7.5. Токены `motion.marketing`

Группа добавлена в `../04-visual-language/marketing-tokens.json` (DTCG 2025.10: `duration` = `{value, unit}`, `cubicBezier` =
массив из 4 чисел, длины прокрутки — `number` в vh с CSS в `$extensions`) и `marketing-tokens.css` (переменные `--mm-*`, ветка
reduce `@media (prefers-reduced-motion: reduce)` и `:root[data-motion="reduced"]`). Reduce-значения каждого токена — в
`$extensions.org.design-deep-dive.reduce` (как модификатор резолвера `ui 08/03` §5.3) [S13]. Исполнитель берёт числа
только оттуда; K сверяет `transition-duration` и `animation-duration` страницы со шкалой.

## Частые ошибки

1. **Одинаковый fade-and-slide-up на каждой секции** (маркер 28 `ui 11/04`, почерк K3 и Lovable): 6 из 15 работ K3 прячут ≥ 10 %
   элементов до прокрутки [S17]. Лечение: система появления `02` §2.
2. **Анимация свойств раскладки** (`width`, `height`, `top`, `left`, `margin`) и `transition: all` — K3 13 из 13 и 5 из 15 [S17].
3. **Петля без механизма паузы** (бегущая строка, видео, живой фон) — самая частая сайтовая ошибка: пауза у 1 из 20 эффектных
   страниц [S20]; «декоративное видео не нужно ставить на паузу» и «достаточно reduce» — ошибки агентов (site I) [S18].
4. **Reduce только в CSS**, а движение — в JS (GSAP, Motion, WebGL, Lenis старой версии): медиазапрос цикл отрисовки не
   останавливает (WebGL под reduce рисует у 11 из 12) [S20].
5. **Reduce = «выключить всё»**: пустые блоки, пропавшие цифры и CTA, контент в `opacity: 0` навсегда.
6. **Глобальный сниппет `!important`** вместо замены пространственного движения (§4.3).
7. **Проверка reduce первым экраном**: ниже он не работает (Stripe, Max Mara) [S20].
8. **LCP-заголовок из `opacity: 0`** — метрика пропадает или врёт (ai-media J/01) [S16]; → `02` §7.
9. **Бегущая строка 155–164 px/с** (K3) при 30–60 у лидеров [S20]; дубли логотипов без `aria-hidden`.
10. **«Парение» 3–5 с крупного 3D-объекта** — в пике укачивания 0,2–0,4 Гц [S7].
11. **Пульсирующая кнопка «Купить» бесконечно** (`animate-ping`, `animate-pulse` Tailwind) — 2.2.2 и примета шаблона [S13].
12. **Живой фон под абзацем и формой**; видео-hero с белым текстом без скрима.
13. **Плавная прокрутка на L0–L1 и на телефоне**; скорость колеса изменена «для атмосферы»; якоря и поиск по странице сломаны.
14. **Счётчики «от нуля» в тарифах** и count-up на каждом числе.
15. **Claude и K3 по памяти**: `@studio-freight/lenis`, `new Lenis({ smooth: true })`, ScrollTrigger без `registerPlugin`,
    `useReducedMotion` не подключён к Motion-анимациям (`ui 08/03` §9.1) [S15] [S13].

## Открытые вопросы и противоречия

1. **Бюджет 1 / 2 / 3 и акценты** — согласованы с практикой лидеров (C), но на людях не проверены; счёт объектов по записи пока
   полуручной (маска даёт области) → K (`motion_check.py`), живая фаза.
2. **Перенос 0,2–0,4 Гц на объект страницы** — исследования про полноэкранный поток и физическое колебание 20–30 мин
   [S7] [S8]; правило §6.3 безопасно, но его польза для страницы не измерена `[не проверено]`.
3. **«Кино-hero» без текста в первые секунды** — параллельно ли это контенту (2.2.2)? W3C считает параллельным всё, что показано
   вместе с другим контентом; база требует паузу `[спорно]` [S18].
4. **Числа параллакса и масштаба** (≤ 40 %, ≤ 1,2× за 100vh) — выведены из практики ai-media и формулировок W3C, MDN, Val Head;
   исследований с порогами нет `[не проверено]`.
5. **Hallmark против ui**: reduce глобальным `!important` 150 мс (Hallmark) против запрета такого сниппета (`ui 08/03` §3.3) —
   база на стороне ui.
6. **Переключатель на L1** — рекомендация, а не норма: исследований, сколько людей им пользуется, нет; на L2 — норма по примеру
   Understanding 2.3.3 [S2].
7. **Reduce на iOS Safari и реальных телефонах** не проверялся (эмуляция Chromium) → живая фаза.
8. **Пользы reduce в числах нет** ни у одного источника (`ui 08/03` §11 п.4) — правила держатся на стандарте и консенсусе.
9. **Позиция `PLAN.md` «scroll-driven — основной инструмент подачи»** против практики (CSS scroll-driven — 2 из 49, ScrollTrigger —
   23 из 49) — разобрано в `02` §3 [S20].
