## Выжимка для агента

1. **Страница — ритм, а не набор эффектов**: чередуй секции `peak` / `accent` со спокойными (`calm`, `pause`); у 21 из 23 записанных
   эффектных страниц между «вау» есть покой, «вау-переходов» — не больше 4 на 12 экранов. → §1.1 `[данные: C]`
2. **Первый пик — в первых 2–3 экранах**, последний — до блока конверсии, а не на нём; финальный CTA — `accent`, форма и
   тарифы — L0. → §1.3 `[данные: C]` `[практика]`
3. **Спецификация хореографии пишется таблицей** «секция → роль → класс движения → триггер → свойства → длительность → reduce →
   телефон» до кода; видеофайл спецификацией не считается. → §1.4 `[практика]`
4. **Появление — система, а не fade на всём**: 2–3 примитива на страницу (подъём 8–24 px, раскрытие маской, горизонтальный
   сдвиг, счёт чисел, рисование линии), закреплённые за ролями; одинаковая подпись анимации на ≥ 5 секциях — маркер 28. → §2 `[мнение вендора]` `[данные: C]`
5. **Появление — один раз**: после срабатывания объект остаётся в конечном положении, при прокрутке вверх не переигрывается. →
   §2.3 `[исследование: NN/g]`
6. **Сдвиг появления 8–24 px, 400–700 мс, порог — 15–25 % элемента в зоне**, каскад 40–80 мс только у групп-списков. → §2.3 `[консенсус]`
7. **CSS scroll-driven — для DOM-эффектов, GSAP ScrollTrigger — только для того, чего CSS не делает**: закреплённая сцена со
   сложным сюжетом, синхрон с canvas, WebGL и видео. CSS scroll-driven есть во всех движках — Chrome 115, Safari 26, Firefox 159
   (2026-10-27); конечное состояние без поддержки остаётся для старых версий. В продакшене (2026-09) — у 2 из 49 эффектных
   страниц против 23 со ScrollTrigger. → §3 `[документация]` `[данные: C]`
8. **Без поддержки `animation-timeline` элемент показывает конечное состояние**, а не начальное (`@supports` + статика по
   умолчанию). → §3.3 `[данные: у 3d F2/08]`
9. **Сцена = экран**: pin-сцена со скрабом режется на шаги по 100–150vh, каждый шаг заканчивается читаемой «станцией»; L1 —
   одна сцена ≤ 150vh, L2 — ≤ 400vh и ≤ 5 шагов на закреплённую секцию. **Шаги с доигрышем** (`beats`) — второй класс:
   текст карточками идёт обычной прокруткой поверх закреплённого окна, такт включает карточка на линии 60 % окна, сцена
   доигрывает его сама за 1,2–2 с; шаг 0,5–0,6 экрана, 5–7 точек покоя, поле ≤ 450vh. → §4.1 `[мнение]`
   `[исследование: NN/g]` `[не проверено: потолки]`; `beats` — `[проверено]`
10. **Скраб сглаживай ≤ 0,5–1 с** (`scrub: 0.5–1`, `damp` или пружина без перелёта ω 6,5 — 95 % за 0,73 с), дольше — сцена
    «не слушается»; доигрыш такта `beats` — не отставание скраба; `snap` к станциям — только L2 и ≤ 0,4 с, на телефоне — нет.
    → §4.2 `[документация]` `[мнение]`
11. **Закрепляй через `position: sticky` или `pinType: 'transform'`**: обычный `pin` ScrollTrigger (`position: fixed`) дал CLS при прокрутке
    1,6–2,0, `sticky` и `transform`-закрепление — 0; `anticipatePin` CLS не лечит; на телефоне — `100svh`, `ignoreMobileResize`, короче шаги
    или без закрепления. → §3.5, §4.3–4.4 `[проверено]` `[документация]`
12. **Горизонтальная прокрутка — только L2, ≤ 5 панелей, прогресс виден**; на телефоне — вертикальная стопка или нативный свайп;
    в reduce — стопка. → §5 `[исследование: NN/g]` `[данные: C]`
13. **Параллакс — фон и периферия, не текст**: разница скоростей ≤ 40 %, CSS `animation-timeline: scroll()` под `@supports` и
    `no-preference`; тач — выключен или вдвое слабее. → §6 `[данные: у ai-media]` `[исследование: NN/g]`
14. **Плавная прокрутка (Lenis) — только L2 и только когда синхронизирует DOM и WebGL**; хвост ≤ 1,0 с на шаг, тач нативный,
    якоря, Tab и поиск по странице работают, reduce выключает. У продуктовых лидеров её нет (0 из 9). → §7 `[данные: C]` `[документация: исходник]`
15. **Скорость и направление прокрутки не меняются никогда**: ни замедления колеса, ни поэкранного перелистывания, ни виртуальной
    прокрутки (`scrollY` = 0 у 3 из 23 записей C ломает якоря и поиск). → §7.3 `[исследование: NN/g]` `[данные: C]`
16. **Переходы страниц — прогрессивное улучшение**: однодокументные View Transitions — Baseline 2025; кросс-документные —
    Chrome 126+ и Safari 18.2+, Firefox нет; анимация 300–500 мс, вся навигация ≤ 4 с (дальше Chrome пропускает переход). → §8 `[документация]`
17. **В многостраничнике переход повторяется десятки раз** — 250–400 мс, без «шторок» на каждом клике, фокус и объявление
    нового заголовка после перехода. → §8.3 `[практика]`
18. **Прелоадер — только L2-кампания по явному решению**: «Пропустить» видна сразу, ≤ 3 с, при повторном визите и в reduce — нет,
    заставка не двигает раскладку (у трёх эффектных страниц CLS ≥ 0,8 от интро). → §9 `[практика: решение заказчика 13]` `[данные: C]`
19. **LCP-заголовок не прячь**: из `opacity: 0`, за маской строк или скриптом он выпадает из LCP (LCP уезжает на лид в 5 раз меньше);
    `opacity: 0.01` и `clip-path` оставляют его кандидатом, но с временем раньше показа; честно — только `transform`. → §10 `[проверено]`
20. **Split-заголовок не должен быть LCP-элементом**: по словам он держится в LCP случайно (через пробелы), по строкам с маской —
    выпадает всегда. → §10 `[проверено]`
21. **Reduce-ветка показывает содержимое с первого кадра**: «скрыть скриптом и показать после загрузки» добавляет время показа к
    LCP (+300 и +1 200 мс в опыте). → §10 `[проверено]`
22. **«Вау» грузится после LCP и простоя** (WebGL, видео, секвенции), сцена первого экрана ≤ 1 200 мс. → §10 `[данные: у соседей]`

- **Hero — `accent`, не обязательно `peak`**: у 15 из 23 записанных страниц hero неподвижен после входа, «вау» начинается с

- **Последний пик — до блока конверсии**; финальный CTA — `accent` без формы или L0 с формой (A) [S3].
- **Пауза перед пиком и после** — секция `pause` или `calm` с отступом `space.section-l` (D) — «вдох» перед сценой `[практика]`;

- **Телефон**: пиков столько же или меньше, петель на 1 меньше (`01` §5.2), тяжёлые пики — постер или стопка кадров [S5].

## 2. Система появления вместо одинакового fade

### 2.1. Когда появление — приём, а когда клише

- **Клише** (маркер 28 `ui 11/04`; F13.4 Anthropic; почерк K3 — 6 из 15 работ прячут ≥ 10 % элементов): одна и та же анимация
  («fade-and-slide-up» 20–40 px, 600–1 000 мс) на каждой секции и каждом элементе; каскад на каждом списке; переигрывание при
  прокрутке вверх; содержимое скрыто до срабатывания скрипта [S1] [S7].
- **Приём**: появление подчинено ролям и концепции (Hallmark: «One orchestrated moment beats ten small ones»; impeccable:
  «one authored moment, not scattered effects and not one identical entrance on every section») [S8] [S9] `[мнение вендора]`.
- Практика: появление текста при прокрутке у 17 из 49 эффектных страниц, система ≥ 5 элементов — у 10 (max 244 элемента на
  странице) [S5] `[данные: C]`.

### 2.2. Система: 2–3 примитива, закреплённые за ролями

| Примитив (Hallmark reveal-ось) | Свойства | Кому | Длительность |
|---|---|---|---|
| подъём (fade-up) | `translateY(8–24px)→0` + `opacity .01→1` | лиды, карточки групп | 400–600 мс |
| раскрытие маской (type-unmask) | `clip-path: inset(0 0 100% 0)→inset(0)` | display-заголовки секций (не LCP) | 600–900 мс |
| горизонтальный сдвиг (sweep) | `clip-path: inset(0 100% 0 0)→inset(0)` или `translateX` | медиа, полосы, разделители | 500–800 мс |
| счёт числа (number-tick) | текст числа, `tabular-nums` | цифры доказательств, один раз | ≤ 1 500 мс |
| рисование линии (line drawing) | `stroke-dashoffset` | схемы, подписи, линии этапов | 600–1 200 мс |
| без появления (none) | — | `calm`, формы, цены, юридическое | — |

Hallmark перечисляет оси: fade-up stagger, horizontal sweep, type-unmask, number-tick, typewriter (только «терминальный» мир),
none — и советует брать 1–2 примитива на страницу [S8]. Раскрытие маской сложной формы (арка, капля, волна) — `clip-path: shape()`:
функция есть во всех движках и входит в Interop 2026 [S27] `[документация]`; без поддержки — `inset()` того же раскрытия `[практика]`. Правило базы: **2–3 примитива, разные у заголовков, медиа и групп;
`calm` без появления** `[мнение вендора]` → H ставит статус клише, K считает подписи анимаций.

### 2.3. Числа и поведение

- Порог срабатывания — 15–25 % элемента в зоне (`IntersectionObserver` `threshold: .2` или `rootMargin: "0px 0px -15% 0px"`);
  Emil: `margin: "-100px"`, `once: true` [S6] `[мнение вендора]`.
- Один раз: ScrollTrigger `once: true` (убивает триггер после первого прохода) или отписка наблюдателя [S11]; NN/g: после
  срабатывания «leave those objects in their final positions, instead of reanimating each object» [S12] `[исследование]`.
- Сдвиг 8–24 px (ui: 4–8 px в сервисах; генераторы — 20–40 px), длительность 400–700 мс, `out-expo`; каскад 40–80 мс, ≤ 6–8
  элементов, сумма ≤ 600 мс (`01` §7.4); шаг каскада без JS — `sibling-index()` (`01` §7.4).
- Быстрая прокрутка: элемент, который пролетели, показывается сразу (ScrollTrigger `fastScrollEnd: true` — при уходе быстрее
  2 500 px/с анимация доводится до конца) [S11].
- Контент видим без JS и в reduce (`01` §4.3); проверка — прогон с выключенным JS и «поиск по странице» находит весь текст.

### 2.4. Код: одноразовое появление без JS-зависимого контента

```html
<!-- Chrome 153 · WebKit 26 · 2026-09-24 · [проверено: 99-raw/experiments/E/01-lcp-reveal (правило видимости по умолчанию)] -->
<script>document.documentElement.classList.add('js')</script> <!-- в <head>, до стилей появления -->
<style>
@media (prefers-reduced-motion: no-preference) {
  html.js [data-reveal]:not(.is-in) { opacity: .01; transform: translateY(var(--motion-marketing-distance-shift-reveal, 16px)); }
  html.js [data-reveal="unmask"]:not(.is-in) { opacity: 1; transform: none; clip-path: inset(0 0 100% 0); }
  html.js [data-reveal] { transition: opacity var(--motion-marketing-duration-reveal) var(--motion-marketing-easing-out-expo),
    transform var(--motion-marketing-duration-reveal) var(--motion-marketing-easing-out-expo), clip-path var(--motion-marketing-duration-reveal) var(--motion-marketing-easing-out-expo); }
}
</style>
<script type="module">
const io = new IntersectionObserver((es) => es.forEach((e) => {
  if (!e.isIntersecting) return; e.target.classList.add('is-in'); io.unobserve(e.target);   // один раз
}), { rootMargin: '0px 0px -15% 0px' });
document.querySelectorAll('[data-reveal]').forEach((el, i) => io.observe(el));
</script>
```

- Появление начинается с `opacity: .01`, а не с 0 (элемент остаётся кандидатом LCP, `§10`); у LCP-заголовка появления нет вовсе.
- `animation-timeline: view()` для появления — это `scroll-linked`, а не одноразовое: оно переигрывается при прокрутке назад; брать
  его для мягких эффектов, которым возврат не мешает (наклон, параллакс карточки), а не для «появился и остался» [S19] `[данные: у 3d F2/08]`.

|---|---|---|---|
| полоса прогресса, мягкий параллакс слоя, наклон и проявление карточки, прилипающая стопка (`position: sticky` + `view()`) | CSS scroll-driven под `@supports ((animation-timeline: scroll()) and (animation-range: 0% 100%))` | 0 | идёт вне главного потока: тяжёлый JS её не тормозит (Chrome) [S14]; браузер без поддержки получает статику |
| закреплённая сцена со сложным таймлайном, горизонталь, синхрон с canvas, WebGL, видео-скраб | GSAP + ScrollTrigger | 41,9 (25,7 + 16,2) | то, чего CSS не делает: таймлайн из многих шагов с колбэками, `snap`, синхрон с canvas и WebGL, `matchMedia` [S11] `[проверено]` |
| плавная прокрутка с синхроном DOM и WebGL | + Lenis | + 4,9 | только L2 (§7) |
| прогресс для WebGL без обработчика `scroll` | `ScrollTimeline` в JS + запас на `scroll` | 0 | Chrome 115, Safari 26, Firefox 159; старые версии — запас (3d 09/03 §3.2) [S19] |

- **Основной инструмент подачи — движение, привязанное к прокрутке; реализация — CSS scroll-driven для DOM-эффектов под
  `@supports` и ScrollTrigger для того, чего CSS не делает** (закрепление со сложным сюжетом, синхрон с canvas); практика
  отстаёт от платформы — 2 из 49 против 23 из 49 (2026-09) `[данные: C]`.
- Не выбирать: Theatre.js (заморожен с 2024), `framer-motion-3d` (снят) — 3d 09/03 §1 [S19]; стек — G.

### 3.3. Запас без поддержки

- Без поддержки `animation-timeline` свойство игнорируется: элемент должен стоять в **конечном** состоянии. Антипример 3d F2/08:
  `.bar { transform: scaleX(0) }` по умолчанию — в браузере без поддержки (Safari до 26, Firefox до 159) полоса невидима навсегда;
  `.card` без анимации — видна (безопасно) [S19].
- Правило: начальное состояние анимации — только внутри `@supports` и `@media (prefers-reduced-motion: no-preference)`, статика — снаружи.

```css
/* Chrome 115+ · Safari 26+ · Firefox 159+ · без поддержки — статика · 2026-09-24 · [проверено] (Chromium 153, WebKit 2359) */
.story { height: 400vh; view-timeline: --story block; }
.story .pin { position: sticky; top: 0; height: 100vh; overflow: hidden; }
@supports ((animation-timeline: scroll()) and (animation-range: 0% 100%)) {
  @media (prefers-reduced-motion: no-preference) {
    .story .track { animation: slide linear both; animation-timeline: --story; animation-range: contain 0% contain 100%; }
  }
}
@keyframes slide { to { transform: translateX(calc(-100% + 100vw)); } }
@media (prefers-reduced-motion: reduce) { .story { height: auto; } .story .pin { position: static; height: auto; } }
```

### 3.4. Цена на главном потоке

Тяжёлый JS на странице: «the classic JavaScript version becomes janky… the CSS version is completely unaffected» (Chrome, опыт с
занятым главным потоком) [S14] `[документация]`. INP прокрутку не учитывает (web.dev: «INP does not consider scrolling») — цену
сцены видно только по длинным кадрам (LoAF) и частоте кадров при прокрутке → `03` §3 [S17]. Замер трёх реализаций одной сцены —
E/02 (§3.5).

### 3.5. Опыт E/02: одна сцена в трёх реализациях

Сцена: дорожка 6 карточек, заголовок, полоса; закрепление на 300vh; 3 прогона на режим; Chromium 153 и WebKit 2359
[S23] `[проверено]`.

| | CSS scroll-driven (`sticky` + `view-timeline`) | ScrollTrigger (`pin`, `scrub: 0.6`) | ScrollTrigger + Lenis |
|---|---|---|---|
| кадры при прокрутке, десктоп и Pixel 7 CPU ×4 | 60/с, 0 длинных | 60/с, 0 длинных | 60/с, 0 длинных |
| CLS при прокрутке, десктоп / телефон | **0 / 0** | **1,63 / 2,0** | 1,61 / 1,0 |
| хвост после шага колеса (Chromium / WebKit) | 50 / 250 мс | 50 / 250 мс | **850 / 1 050 мс** |
| отставание сцены от колеса на телефоне CPU ×4 (сдвиг дорожки на одном шаге) | −794 px | −758 px | **−88 px** |
| JS без сжатия / brotli | 0 | 114,7 КБ / 41,9 КБ | 133,0 КБ / 46,8 КБ |
| reduce | статика | статика (`gsap.matchMedia`) | статика, Lenis выключен сам |

- **Лёгкая сцена не стоит главному потоку ничего** ни в одной реализации — цена у лидеров (C) в содержимом сцен (WebGL, видео, сотни
  триггеров), а не в выборе CSS или ScrollTrigger.
- **Закрепление ScrollTrigger даёт CLS при прокрутке 1,6–2,0** (как лабораторная страница C — 1,99), `position: sticky` — 0; `anticipatePin: 1`
  не помогает, **`pinType: 'transform'` — CLS 0** на десктопе и телефоне. Правило: закрепление — CSS `sticky` (анимация на CSS scroll-driven
  или ScrollTrigger без `pin`) либо `pin` с `pinType: 'transform'`; возможное дрожание `transform`-закрепления проверять записью.
- **Lenis + скраб на медленном процессоре уводит сцену от колеса** и добавляет ≈ 1 с хвоста на шаг.

## 4. Закрепление (pin) и скраб

### 4.1. Сцена = экран

- **Шаг сцены — 100–150vh прокрутки**, каждый шаг заканчивается «станцией» — кадром, который можно прочитать и на котором можно
  остановиться (3d 07/04 §5 `[мнение]`; Тельтевский: жёсткая привязка оставляет пользователя «в нелепой промежуточной позе»,
  через 3d 09/03 п.17) [S19].
- **Потолки скраба**: L1 — одна закреплённая сцена ≤ 150vh (A `ambition-levels.yaml`) [S3]; L2 — ≤ 400vh и ≤ 5 шагов на
  секцию, ≤ 2 закреплённые секции подряд нет `[не проверено]`. NN/g: длинные скролл-джеки «severely exacerbated»
  дезориентацию, на Crypto.com (вся страница) дезориентированы все участники; меньше шагов до видимого изменения — меньше
  дезориентации [S13] `[исследование]`.
- **Не закреплять**: формы, тарифы, калькуляторы, текст длиннее 3 строк, юридическое (A: конверсия L0) [S3].
- **Сцену задавать долями прогресса и длиной прокрутки**: «duration» в таймлайне ScrollTrigger — доля длины прокрутки, а не время
  (0,5 + 2 + 0,3 = 2,8 на 1 000 px → 179 / 714 / 107 px), правка одной длительности сдвигает остальные; «the scroll is like a user
  controlled timeline»; закрепление — `position: sticky` на время сцены, скорость прокрутки не меняется [V:ufHQG7fDLQc 04:07, 09:13,
  14:18] `[практика]`. В `motion-spec`: `start`/`end` в % прогресса секции + длина в vh.
- **Текст в сцене не меняется при прокрутке**, пока его читают: NN/g — «altered scrolling rate… + changing text = worst usability» [S13].

#### 4.1.1. Шаги с доигрышем (`beats`)

Второй класс прокрутки рядом со скрабом — для сцены, где сюжет идёт станциями, а не следует за пальцем:

- **Текст — карточками обычной прокруткой** поверх закреплённого окна сцены (`position: sticky`); сцена не едет за
  прокруткой, а доигрывает такт до точки покоя сама. Основание — слово заказчика «один раз крутнул — произвело действие»
  `[проверено]`.
- **Такт** включает карточка, дошедшая до линии 60 % высоты окна; сцена доигрывает его пружиной без перелёта за 1,2–2 с
  (ω 2,4–3,6, `01` §7.3) `[проверено]`.
- **Шаг** — 0,5–0,6 экрана (≈ 480 px ПК, 420 px телефон): такт включается через 3–4 щелчка колеса. **Точек покоя 5–7**
  (≤ 6 переходов), **поле** ≤ 450vh `[проверено]`; числа телефона — `[кейс]`: реальные телефоны не мерились.
- **Прокрутка не перехватывается**: скорость и положение страницы не меняются, это не `snap` (§4.2) — доигрывает только
  сцена. В окне — рельс тактов, «Пропустить» и пауза; при reduce — раскадровка кадров точек покоя вместо закрепления.
- **Скраб с закреплением** — 100–150vh на шаг и потолки уровня выше; шаг 100–150vh у шагов с доигрышем — «долго крутишь,
  ничего не происходит».
- Реализация — рантайм сцен 3d (`../../3d/16-js-scenes/02-stage-runtime.md` §5, `../../3d/16-js-scenes/examples/stage-runtime.js`, режим `beats`).
- В спецификации движения — `scene.scroll_mode: beats` (до 7 точек покоя в `scene.stations`); потолок поля — токен
  `motion.marketing.scroll.pin-beats-max-vh` (450vh, уровень L2), по нему судит `spec_check.py` (MS-13).

### 4.2. Скраб, сглаживание, привязка к станциям

- `scrub: true` — прогресс = прокрутка; `scrub: 0.5–1` — догоняет за 0,5–1 с («takes 1 second to "catch up"») [S11]; дольше 1 с
  — сцена отстаёт от пальца и продолжает двигаться после остановки (то же, что хвост Lenis). Свой рантайм ведёт прогресс
  критически демпфированной пружиной без перелёта: ω 6,5 — 95 % пути за 0,73 с (`01` §7.3) `[проверено]`.
- Доигрыш такта у шагов с доигрышем (1,2–2 с, §4.1.1) — не отставание скраба: сцена не следует за пальцем, а сама доводит
  такт до точки покоя.
- `snap` к станциям меняет положение прокрутки без действия человека — это частичный перехват: L0–L1 — нет; L2 — только к станциям
  шага, длительность ≤ 0,4 с, задержка ≥ 0,2 с после остановки, на телефоне — нет `[мнение]` `[не проверено: числа]`. Шаги с
  доигрышем положение прокрутки не трогают — это не `snap`.
- Быстрая прокрутка через сцену: `fastScrollEnd`, `preventOverlaps` — чтобы соседние сцены не играли одновременно [S11].

### 4.3. Раскладка и CLS

- `pinSpacing` (по умолчанию padding) толкает следующий контент вниз; у родителя с `display: flex` или `position: absolute` отступ
  не работает — контент «заезжает» под сцену [S11] `[документация]`.
- `anticipatePin: 1` — закрепление без рывка при быстрой прокрутке (прокрутка рисуется в отдельном потоке, первый кадр закрепления
  запаздывает) [S11]; CLS он не убирает — убирает `pinType: 'transform'` или `sticky` (E/02: 1,6–2,0 → 0) [S23] `[проверено]`.
- CLS при прокрутке: max 0,24 на выборке C (Aardvark); лабораторная страница C/02 с закреплением дала 1,99 — сдвиги при
  закреплении считаются, если раскладка меняется [S5]; норма — CLS при прокрутке ≤ 0,1 (цель CWV) `[данные: C]`.

### 4.4. Телефон

- Высота: `100svh` (не `100vh`/`dvh`: панель адреса меняет высоту и сдвигает сцену) — D `hero-min-poster` [S4];
  `ScrollTrigger.config({ ignoreMobileResize: true })` [S11] `[документация]`.
- Шаги короче (≈ 100vh) или без закрепления: стопка кадров-станций; на телефоне движения у лидеров не меньше, а плотнее (C) —
  норма уводит от этого [S5].
- Горизонталь в закреплении на телефоне — нет (§5).

## 5. Горизонтальная прокрутка

- **Только L2** (A), ≤ 5 панелей, одна панель ≈ 100vh вертикальной прокрутки, прогресс-полоса или счётчик «2 / 5» видны; у C —
  2 страницы из 49 (ERA Residence, MTS Media) [S3] [S5].
- NN/g: горизонтальная развёртка без чтения текста раздражает меньше (похожа на карусель), но есть риск «как вернуться наверх»;
  липкая навигация служит «аварийным выходом» [S13] `[исследование]`.
- Колесо ведёт вертикальную прокрутку страницы, панели едут внутри закрепления; нативную горизонтальную прокрутку контейнера
  (`overflow-x`) колесом не подменять.
- Телефон — вертикальная стопка или нативный свайп-ряд с `scroll-snap-type: x mandatory`; reduce — вертикальная стопка; клавиатура —
  содержимое панелей достижимо Tab в порядке чтения.

## 6. Параллакс

- **Амплитуда**: разница скоростей слоёв ≤ 40 % — фон смещается ≤ 24vh на 100vh прокрутки, передний объект ≤ −12vh (ai-media
  страница 03) [S20]; текст едет со страницей; крупные объекты (≥ 50 % зоны) не масштабируются больше 1,2× за 100vh (`01` §6.2).
- **Где**: фон и периферийные картинки, «чтобы их было легко игнорировать»; эффект срабатывает один раз и объекты остаются в
  конечных позициях (NN/g) [S12] `[исследование]`.
- **Код**: CSS `animation-timeline: scroll(root)` с `animation-range: 0 100vh` под `@supports` и `no-preference` — без JS и
  обработчика прокрутки (ai-media 10/03 §4.4) [S20] `[данные: у ai-media]`; параллакс за курсором — только `(hover: hover) and
  (pointer: fine)` и не в reduce.
- **Телефон**: выключен или вдвое слабее (панель адреса и инерция тача делают его рывками) `[практика]`.
- **Reduce**: слои неподвижны относительно страницы (W3C: пример «Parallax scrolling with option to turn off») [S2].

## 7. Плавная прокрутка (Lenis)

### 7.1. Когда да, когда нет

- **Да** — L2, когда нужна синхронизация DOM и WebGL на каждом кадре (нативная прокрутка не синхронна с кадром; 3d 09/03 §1) [S19].
- **Нет** — L0–L1, страницы с формами и длинным чтением, лидогенерация, телефоны (у Lenis `syncTouch: false` по умолчанию — тач
  нативный) [S18] `[документация: исходник]`.
- Практика: плавная прокрутка на Lenis активна у 17 из 49 эффектных страниц (Lenis — 16, Locomotive на Lenis — 1; студии 6 из 9,
  культура 5 из 6), у продуктовых главных — 0 из 9; хвост
  0,8–1,4 с на шаг колеса против ≤ 0,06–0,27 с нативно; на телефоне не отключается ни у одной из 5 [S5] `[данные: C]`.
- Самый залайканный комментарий подборки трендов ui: «never ever ever hijack my scrollbar» (5 800) [S22] `[мнение]`.

### 7.2. Настройки (Lenis 1.3.26)

```js
// lenis 1.3.26 · gsap 3.15.0 · 2026-09-24 · [проверено]; lerp 0.15 — S1 2026-09-25 [проверено]
import Lenis from 'lenis';                                   // пакет lenis, не @studio-freight/lenis
const lenis = new Lenis({ lerp: 0.15, anchors: true,          // хвост ≈ 0,9 с по замеру; якоря плавно, а не мимо
  prevent: (node) => node.closest('[data-lenis-prevent], dialog, .map') }); // вложенные области прокручиваются сами
lenis.on('scroll', ScrollTrigger.update);
gsap.ticker.add((t) => lenis.raf(t * 1000)); gsap.ticker.lagSmoothing(0);   // один rAF на Lenis и ScrollTrigger
// respectReducedMotion: true — по умолчанию; syncTouch: false — по умолчанию (тач нативный)
```

- Хвост: 99 % пути за ln(100) / (−ln(1 − lerp) · 60) с — `lerp` 0,1 → 0,73 с, 0,12 → 0,6 с, 0,15 → 0,47 с `[не проверено: расчёт]`; норма —
  ≤ 1,0 с на шаг (C) [S5]; `duration` > 1,2 не задавать.
- Замер вместо расчёта (`motion_check.py` 0.1.3, десктоп Chromium 153, S1 2026-09-25): `lerp` 0,1 → 1,28 с, 0,12 → 1,09–1,13 с
  (провал ворот ≤ 1 с, EG-PERF-03), 0,15 → 0,90 с, 0,2 → 0,72 с — формула занижает хвост в 1,75–1,9 раза; **умолчание базы —
  `lerp: 0.15`** (токен `motion.marketing.scroll.lenis-lerp`), другое значение — только с замером хвоста (X-10)
  `[проверено]`.
- Проверить руками: поиск по странице (Ctrl+F) доводит до найденного, Tab прокручивает к фокусу, якоря и «назад» работают, модальные
  окна и карты прокручиваются сами (`prevent`), `scroll-behavior: smooth` в CSS не включён одновременно.

### 7.3. Никогда

- Менять скорость колеса и направление прокрутки, перелистывать «по экрану», вести прокрутку внутри canvas (`scrollY` = 0 — у Illoca,
  Squarespace Foundations, Siena: якоря, поиск и «прокрутка к блоку» не работают) [S5] [S13] `[данные: C]` `[исследование: NN/g]`.
- Перехватывать «назад» (ui 11/03 §7.2) [S22]. De Cock (Stripe): «it's totally fine to trigger some animations based on the scroll
  position but please never ever interrupt my workflow» [V:fZpTvZuysIo 21:48] `[практика]`.

## 8. Переходы страниц

### 8.1. Поддержка на 2026-09-24

| Вид | Поддержка | Как включить | Практика C |
|---|---|---|---|
| однодокументные View Transitions (`document.startViewTransition`) | Baseline 2025, Newly available с октября 2025 (MDN) | SPA-роутер, смена состояния блока | `startViewTransition` в коде роутеров 16 из 49, в дизайне — 1 |
| кросс-документные (MPA) | Chrome 126+, Safari 18.2+, Firefox нет (межстраничные переходы — в Interop 2026 [S27]) | `@view-transition { navigation: auto; }` на обеих страницах, только same-origin | 0 из 49 |
| Barba, Swup | все (перехват ссылок + fetch) | библиотека, 300–500 мс | Barba 4, Swup 1 из 49 |

Источники: MDN [S17], Chrome for Developers [S16], C [S5] `[документация]` `[данные: C]`.

### 8.2. Правила

- **Прогрессивное улучшение**: без поддержки — обычная навигация, ничего не ломается; `@supports` и проверка
  `document.startViewTransition` [S16].
- **Образец «общая ось»** (Chrome I/O 2025): старая страница — fade-out 90 мс `cubic-bezier(0.4, 0, 1, 1)` + сдвиг влево 30 px за
  300 мс `cubic-bezier(0.4, 0, 0.2, 1)`; новая — fade-in 210 мс `cubic-bezier(0, 0, 0.2, 1)` с задержкой 90 мс + сдвиг справа 30 px
  за 300 мс; в reduce — только кроссфейд [V:UcXWY057YuQ 12:33] `[документация]`.
- **Анимация 300–500 мс**, общий элемент (карточка → страница кейса, миниатюра → hero) — единственный повод для сложного перехода
  (ui 08/02 §5.3) [S1]; «шторка на весь экран» — только L2-кампания.
- **Бюджет навигации ≤ 4 с**: «If a navigation takes too long–more than four seconds in Chrome's case–then the view transition is
  skipped with a TimeoutError» [S16] `[документация]`; значит, переход не маскирует медленную страницу.
- **`<link rel="expect" blocking="render" href="#…">`** задерживает первый кадр новой страницы до нужного элемента — ставить только на
  элемент первого экрана, иначе растёт FCP и LCP [S16] `[документация]`.
- **Reduce**: `@media (prefers-reduced-motion: reduce) { @view-transition { navigation: none; } }` и проверка `matchMedia` до
  `startViewTransition`; в Barba и Swup — переход без анимации или crossfade ≤ 200 мс (ui 08/03 §3.4) [S1].

### 8.3. Многостраничник: переход повторяется

- Переход видят на каждом клике — это «частое» действие (правило частоты применимо, `01` §1.1): 250–400 мс, без повторяющегося
  интро и без блокировки ввода; первая загрузка сайта может быть богаче, повторные переходы — короче `[практика]`.
- После перехода — фокус на новом `<h1>` или в начало `<main>`, заголовок страницы и `aria-live`-объявление обновлены, прокрутка
  восстанавливается при «назад» (Barba и Swup делают это не сами) `[практика]`; аналитика считает просмотр (site).
- Prefetch по наведению ускоряет переход, но добавляет байты (C: Next.js +0,9 МБ по наведению у Vercel) — считать в бюджете сессии [S5].

## 9. Прелоадер и интро

- **Только L2-кампания по явному решению** (`site-brief` `policies.preloader: on` + обоснование; решение заказчика 13) [S24];
  на продуктовых и лидогенерирующих страницах — нет (3d 01/02 п.26, ai-media 10/02 — экран-заставку не делать) [S19] [S20].
- **Не прятать смысл**: H1, CTA и LCP-элемент в HTML под заставкой; заставка — слой `position: fixed` поверх, уходит `opacity`/`clip-path`,
  раскладку под собой не двигает (у Terminal Industries, Obys, ERA CLS до прокрутки 0,89–1,0 — интро и прелоадеры) [S5] `[данные: C]`.
- **«Пропустить» видна с первой секунды**, интро ≤ 3 с, при повторном визите (`localStorage`) и в reduce — нет (CRV-AL-12) [S3].
  Chrome «Accessible Animation»: «avoid complex loaders or auto playing videos» — заставка до контента означает ожидание и
  вестибулярный риск [V:_ZdZh-ESOHY 01:03–02:04] `[документация]`.
- **2.2.2**: прелоадер как единственное содержимое, пока ввод невозможен, паузы не требует; заставка поверх уже видимого hero —
  параллельна, нужна пауза или ≤ 5 с (`01` §3.2) [S2].
- **Ворота «Enter»** без контента — только кампания-мир по решению (A); LCP тогда — экран ворот (C: Miu Miu) [S3] [S5].

## 10. LCP-безопасное появление первого экрана

Опыт E/01 (Chromium 153, 9 вариантов × десктоп, телефон CPU ×4, reduce × 3 прогона) [S23] `[проверено]`:

| Как появляется H1 (LCP по умолчанию) | Что видит LCP | Честность |
|---|---|---|
| без анимации | H1 в первом кадре | эталон |
| `transform: translateY(24px) → none` | H1 в первом кадре, текст виден сразу | честно — **рекомендовано** |
| `clip-path: inset(0 0 100% 0) → inset(0)` | H1 в первом кадре, хотя первый кадр пуст | LCP раньше показа на длительность раскрытия |
| `opacity: .01 → 1` | H1 в первом кадре | то же |
| `opacity: 0 → 1` (CSS или WAAPI) | **H1 не кандидат**; LCP = лид (в 5 раз меньше) | метрика врёт, CrUX пишет не тот элемент |
| split по строкам за маской `overflow: hidden` | **H1 не кандидат** | то же |
| split по словам (inline-block, из `opacity: 0`) | H1, но только площадь пробелов (104 тыс. вместо 211 тыс. px²) | случайно; другая разметка split — выпадет |
| скрыт скриптом (`html.js .h1 { opacity: 0 }`), показ анимацией | **H1 не кандидат** | метрика врёт |
| скрыт скриптом, показ без анимации (частая reduce-ветка) | H1 в момент показа: **+300 и +1 200 мс** | реальная задержка LCP |

Правила:
- **LCP-элемент (обычно H1 или постер) — без анимации или только `transform` ≤ 24 px**; остальное первого экрана (лид, CTA, медиа)
  появляется после — от `opacity: .01` и `transform`, сцена ≤ 1 200 мс (`01` §7.1).
- **Split, маска строк, `opacity: 0`, скрытие скриптом — не на LCP-элементе**; если нужен кинетический H1 — сделать LCP-элементом
  постер или картинку hero осознанно (ai-media 10/01 §4.1: hero меньше вьюпорта) [S20].
- **Reduce — содержимое видно в первом кадре**, никакого «покажем после загрузки».
- **Тяжёлое «вау» — после LCP и простоя**: WebGL, видео, секвенции, 3D — после `load` + `requestIdleCallback` (CRV-AL-09;
  ai-media: LCP видео-hero — постер, видео слоем после `load`) [S3] [S20].
- Совпадает с ai-media J/01 для картинок: из `opacity: 0` картинка не кандидат, из `0.01` — кандидат [S20] `[данные: у соседа]`.

## Частые ошибки

1. **Fade-and-slide-up 20–40 px на каждой секции и каждом элементе** (K3, Lovable, шаблоны AOS): маркер 28; лечение — §2.
2. **Переигрывание появления при прокрутке вверх** (`toggleActions: "play reverse play reverse"`, `once: false`).
3. **Содержимое в `opacity: 0` до срабатывания скрипта**: отказ JS, поиск по странице и скриншотеры видят пустую страницу.
4. **H1 из `opacity: 0` или split-маской** — LCP уезжает на мелкий элемент (§10).
5. **CSS scroll-driven без `@supports`** и с начальным состоянием по умолчанию — в браузере без поддержки (Safari до 26, Firefox до 159)
   элемент невидим навсегда (§3.3).
6. **Pin-сцена на 800–1 000vh** без станций и без прогресса; текст в сцене меняется во время чтения.
7. **Lenis на лендинге услуг и на телефоне**, `duration: 2`, сломанные якоря и Ctrl+F; `new Lenis({ smooth: true })` и
   `@studio-freight/lenis` у Claude и K3 по памяти [S19].
8. **Горизонтальная прокрутка на телефоне** в закреплении; колесо подменяет нативную горизонталь контейнера.
9. **Параллакс текста** и крупных объектов с масштабом; параллакс на тач-экране.
10. **Переход страницы 800–1 200 мс со шторкой на каждом клике** многостраничника; фокус после перехода остаётся на старой ссылке.
11. **Прелоадер ради «эффектности»** на продуктовой странице; интро без «Пропустить»; заставка сдвигает раскладку (CLS 0,9–1,0).
12. **Генератор ставит все приёмы сразу**: курсор, плавная прокрутка, split на каждом заголовке — уровень L2 «по счётчику», а ритма нет (C) [S5].

- CRV-CH-01 Роли секций (`peak`, `accent`, `support`, `calm`, `pause`) назначены, пики и акценты — в норме уровня, между пиками есть покой?
- CRV-CH-02 Первый пик — в первых 2–3 экранах, последний — до блока конверсии; конверсия — `calm`?
- CRV-CH-03 Хореография записана таблицей §1.4 (класс, триггер, свойства, мс, кривая, reduce, телефон)?
- CRV-CH-04 Появление — 2–3 примитива по ролям, один раз, сдвиг 8–24 px, 400–700 мс, каскад только у групп?
- CRV-CH-05 Без JS и при быстрой прокрутке весь текст виден (`html.js`, `fastScrollEnd`)?
- CRV-CH-06 CSS scroll-driven — под полной проверкой `@supports`, без поддержки — конечное состояние; ScrollTrigger — только для того,
  чего CSS не делает (закрепление со сложным сюжетом, синхрон с canvas)?
- CRV-CH-07 Pin-сцены со скрабом: шаги 100–150vh со станциями, L1 ≤ 150vh, L2 ≤ 400vh и ≤ 5 шагов; шаги с доигрышем: шаг
  0,5–0,6 экрана, 5–7 точек покоя, поле ≤ 450vh, рельс, «Пропустить», пауза; формы и тарифы не закреплены?
- CRV-CH-08 Скраб сглажен ≤ 1 с, пружина прогресса — без перелёта; `snap` — только L2, ≤ 0,4 с, не на телефоне?
- CRV-CH-09 CLS при прокрутке ≤ 0,1; на телефоне `100svh`, `ignoreMobileResize`, короче шаги или без pin?
- CRV-CH-10 Горизонталь — только L2, ≤ 5 панелей, прогресс виден, на телефоне и в reduce — стопка?
- CRV-CH-11 Параллакс ≤ 40 %, только фон и периферия, текст неподвижен относительно страницы, на тач — слабее или нет?
- CRV-CH-12 Плавная прокрутка только на L2, хвост ≤ 1 с, тач нативный, якоря, Tab, Ctrl+F и «назад» работают, reduce выключает?
- CRV-CH-13 Переходы страниц — прогрессивное улучшение, 300–500 мс (многостраничник 250–400), фокус и заголовок после перехода, reduce — без анимации?
- CRV-CH-14 Прелоадер — только L2-кампания по решению, «Пропустить» с первой секунды, ≤ 3 с, не при повторе, без сдвига раскладки?
- CRV-CH-15 LCP-элемент без анимации или только `transform`; split, маска строк, `opacity: 0` и скрытие скриптом — не на нём?
- CRV-CH-16 WebGL, видео, секвенции и 3D стартуют после LCP и простоя?

## Открытые вопросы и противоречия

1. **Потолки pin-сцен L2 (≤ 400vh, ≤ 5 шагов) и «первый пик в 2–3 экранах»** — из практики C и NN/g, без измерения на людях `[не проверено]`.
2. **`snap` к станциям** — перехват или помощь? NN/g не разбирает `snap` отдельно; позиция базы — только L2 и коротко `[мнение]`.
3. **Браузеры без CSS scroll-driven** (Safari до 26, Firefox до 159) — их доля у аудитории проекта не мерилась; пока она заметна,
   смысловое содержимое держит конечное состояние без анимации. Поведение в Firefox 159 стендом не проверено: опыты шли в
   Chromium и WebKit.
4. **LCP при `clip-path` и `opacity: .01`** — метрика раньше показа; Chromium может поменять правило (как с энтропией картинок,
   ai-media 10/01 §4.2) — перепроверять раз в полгода.
5. **Split-заголовок и LCP** — проверен один вариант разметки (inline-block слова с пробелами между спанами); SplitText 3.13+ с
   `aria` и `mask` — не проверялся (живая фаза или F).
6. **Переход страниц и аналитика, фокус, восстановление прокрутки в Barba и Swup** — не мерились (G, site).
7. **Шаги с доигрышем и уровни.** Поле ≤ 450vh выше потолков закрепления скраба (токены `pin-l1-max-vh` 150 и `pin-l2-max-vh`
   400 в `../04-visual-language/marketing-tokens.json`); класса нет в `../01-creative-direction/ambition-levels.yaml`, а
   `../09-ai-execution-evaluation/motion-spec.schema.json` держит у сцены 2–6 станций при 5–7 точках покоя — уровень класса и
   поле спецификации не решены.
