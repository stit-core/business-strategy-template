# 04 · Где живёт набор: холст Claude Design, код сайта, лабораторная страница, статичная копия и проверки

Один набор проходит три дома: холст Claude Design, где движение видит и принимает заказчик; код сайта `<org>/site`, где
оно становится островом страницы; лабораторную страницу приёма — тот же код в обычном HTML. Файлы `motion-kit.js` и
`motion-kit.css` и разметка `data-mk` не меняются — меняется только обвязка: адаптер в логике артборда, модуль острова,
`<script>` страницы. Как устроен рантайм сцен 3D в тех же домах — `../../3d/16-js-scenes/06-where-it-runs.md`; что
исполняет холст — `../../claude-design/05-design-artifacts/03-what-canvas-runs.md`.

## Выжимка для агента

1. **Один набор на все дома**: `motion-kit.js` — классический скрипт с одним глобальным `MotionKit`, без `export`, без
   сети; годится файлом поддержки холста и модулем острова; разметка `data-mk` и спецификация движения — те же.
   `[проверено: страница]` → §1, §2
2. **Холст**: файл `project/lib/<имя>.js` строкой после строки поддержки холста (support.js); CSS набора — в
   `<helmet><style>` правилами по атрибутам и `@keyframes`; адаптер в логике артборда — `MotionKit.mount(root, {host: root, isLive: viewMode})`, строка
   состояния, `destroy` в `componentWillUnmount`. Образец — `examples/artboard-adapter.dc.html`. `[не проверено на холсте]`
   → §1
3. **Холст запрещает интерфейс скриптом** (`innerHTML`, `appendChild`), `<iframe>` и сеть: набор узлы не создаёт, не
   ходит в сеть и не тянет библиотек — правило типа соблюдено по построению. `[проверено: motion_smoke static]` → §1
4. **Обзор холста неподвижен, статичная копия без логики**: в обзоре набор ставит `still` — конечные состояния; в копии
   логики нет — нет и корня набора, видны конечные состояния. `[проверено: без JS]` → §1.3, §4
5. **Сайт**: CSS набора — в слой стилей, модуль острова — после `load` в простое, выбор движения ведёт остров
   предпочтений (`toggle: false`), разбиение текста и числа счётчиков — компонент при сборке. `[практика]` → §2
6. **Лабораторная страница** — копия файлов набора рядом со страницей приёма; её проверяют `motion_smoke.py --root --page`
   и `motion_check.py`, её запись — видео-референс и доказательство для заказчика. `[проверено: демо]` → §3
7. **Проверки**: `motion_smoke.py` (8 режимов) — поведение набора; `motion_check.py` — ворота уровня и сверка со
   спецификацией; `spec_check.py spec` — примитивы и опции спецификации. `[проверено]` → §4

## 1. Холст Claude Design

### 1.1. Файлы

- **Скрипт набора — файл поддержки** `motion-kit.js` в папке `lib` проекта холста (копия `examples/motion-kit.js` без
  правок) строкой `<script src="./lib/motion-kit.js"></script>` в `<head>` после строки поддержки холста (support.js).
  Глобальное имя одно — `MotionKit`; логика артборда проверяет его и пишет строку состояния (cd 05/03 §3.2). Инструмент
  `Artifact` публикует файл, который сессия написала или прочитала целиком: набор — свой файл в 46 КБ, это путь.
- **CSS — в `<helmet><style>`**: правила по атрибутам `[data-mk…]`, `[data-mk-on]`, `[data-motion]` и `@keyframes`
  набора — так движение артборда заказчик принимал в Play. Весь `motion-kit.css` (41 КБ) или вырезка нужных разделов без
  правок: у образца — разделы 1–5, 8, 9, 13 между метками `/* motion-kit.css: начало вырезки … */` и `/* … конец вырезки */`;
  `motion_smoke.py` (static) сверяет вырезку строками с `motion-kit.css`. `[проверено: сверка]`
- **Разметка** — атрибуты `data-mk` на элементах артборда; куски разбиения текста и дубль бегущей строки пишет автор
  артборда. Узлы скриптом не строятся.

### 1.2. Адаптер в логике артборда

```js
class Component extends DCLogic {
  componentDidMount() {
    this._alive = true;
    const root = this._root;                                   // ref корня: <div class="a-root" ref="{{ setRoot }}">
    if (typeof MotionKit === 'undefined' || !root) { this.note({ kit: 'не исполнен: глобального имени MotionKit нет' }); this.push(); return; }
    this._kit = MotionKit.mount(root, {
      host: root, remember: false, level: 'L1',                // выбор движения — на корне: соседние артборды его не видят
      isLive: () => MotionKit.viewMode(root),                  // обзор — still, Play — full
      onState: (i) => { this.note({ kit: 'исполнен — версия ' + i.version, mode: i.mode }); this.push(); }
    });
    this._timer = setInterval(() => { if (this._kit) { this._kit.refresh(); } }, 1500);   // режим холста меняется без resize
  }
  componentWillUnmount() { this._alive = false; clearInterval(this._timer); if (this._kit) { this._kit.destroy(); } }
  // note() и push() — строка состояния; setState только при изменении: реже перерисовка артборда
}
```

- **Носитель выбора** — корень артборда (`host: root`): `data-motion` не уходит на соседние артборды; хранилище
  выключено (`remember: false`).
- **Признак Play** — эвристика `MotionKit.viewMode(root)` рантайма 3D (3d 16/02 §10): окно не выше 1700 px и
  страница или предок прокручиваются дальше окна на 40 px; опрос раз в 1,5 с — `refresh()` заново ищет окно прокрутки,
  новые элементы `[data-mk]` и режим. Без смены режима `refresh()` сцены не трогает: такт доигрывает пружиной, а не
  прыгает к точке покоя. `[проверено: motion_smoke desk — refresh() посреди доигрыша такта]`
- **Строка состояния** — «Набор: исполнен — версия 0.5.0 · режим full · прокрутка element · появления 3 из 7 ·
  предупреждения нет»: сбой видно словами.
- **`destroy()` в `componentWillUnmount`** снимает слушатели и всё, что набор поставил.

### 1.3. Обзор, Play и статичная копия

| режим холста | что набор делает | что видно |
|---|---|---|
| обзор (не Play) | `isLive` — нет → `data-mk-on="still"` | конечные состояния, петли стоят, сцены — конечный кадр |
| Play | `full` (или `reduced` по выбору и системе) | движение; что видно при запуске — сразу в конечном состоянии |
| статичная копия (`dc_to_html.py`) | логики нет — корня набора нет | конечные состояния; CSS-вход первого экрана и полоса прогресса — CSS |

Обзор считается неподвижным (cd 05/03 §1): анимация по кадрам там не проверена, движение набора в обзоре выключено.

### 1.4. Что на холсте не проверено

Всё живое на claude.ai — `[не проверено на холсте]`: Play владелец аккаунта не нажимал. По шагам:

- исполнение файла поддержки `motion-kit.js` и глобального `MotionKit` (проба `Motion-Libs` с другим своим файлом —
  `[проверено на claude.ai]`, cd 05/03 §1);
- окно прокрутки артборда в Play (`scrollerOf`), высота окна (`--mk-vh`), `position: sticky` и CSS-шкалы во внутреннем окне;
- сохранность атрибутов и переменных набора при перерисовке артборда логикой (`setState`);
- команды кнопок окна (`command`, `commandfor`), View Transitions и `@starting-style` на холсте;
- эвристика `viewMode` для артборда страницы с набором.

Как проверить: опубликовать `artboard-adapter.dc.html` с файлом поддержки `motion-kit.js` в папке `lib` на приватном
холсте (cd 05/03 §6), владелец жмёт Play и называет строки состояния, где стоит «не …». До пробы движение на холсте показывают ещё и записью
лабораторной страницы (§3).

## 2. Код сайта

Сайт `<org>/site` — Astro: исполняемый код страницы — острова реестра островов с основанием, страницами и бюджетом
brotli (правила — код-репо сайта, его `CLAUDE.md`).

- **CSS** — в слой стилей сайта (`@layer motion` после слоя компонентов), числа — из `tokens.css` дизайн-системы:
  набор берёт `--motion-marketing-*`, где имя токена каноническое; чего в ДС нет, берётся запасное значение набора.
  `[практика]`
- **Модуль острова** — `import './motion-kit.js'` (классический скрипт присваивает `window.MotionKit` и модулем);
  монтирование после `load` в простое — LCP рисует HTML:

```js
// скрипт острова движения: набор после LCP в простое; выбор движения ведёт остров предпочтений — toggle: false
import './motion-kit.js';
function start() { window.__mk = window.MotionKit.mount(document, { toggle: false, level: 'L1' }); }
function idle(fn) { if ('requestIdleCallback' in window) { requestIdleCallback(fn, { timeout: 2000 }); } else { setTimeout(fn, 200); } }
if (document.readyState === 'complete') { idle(start); } else { window.addEventListener('load', () => idle(start), { once: true }); }
```

- **Выбор движения** — остров предпочтений (`<org>/site/src/features/preferences/`): `data-motion` на `<html>` из `localStorage` до
  первой отрисовки, кнопки `[data-motion-set]` с `aria-pressed`. Набор с `toggle: false` кнопки не трогает, а слушает
  `data-motion` наблюдателем и `prefers-reduced-motion`. Пауза сайта — «Меньше» (`reduced`); `paused` остров не хранит
  (`01` § Открытые вопросы). `[исходник]`
- **Разбиение текста и числа** — компонент при сборке: куски `<span>` по словам или строкам с доступным текстом,
  число счётчика — `fact:<id>` из фактов продукта. Скрипт текст не режет.
- **Строка реестра островов**: основание — момент спецификации движения (`motion-spec.yaml#/sections/<id>`), страницы,
  бюджет — 8,0 КБ JS и 4,9 КБ CSS brotli в сжатом виде (`01` §8); чужих origin набору не нужно — политика безопасности
  страницы не расширяется. `[практика]`
- **Переход между страницами** — CSS `@view-transition` в слое стилей сайта, имя снимка корень получает только при
  разрешённом движении; `<ClientRouter/>` сайт не подключает (`<org>/site/.claude/rules/shared-ui.md`) — набор
  монтируется заново на каждой странице. Правила перехода набора (`02` §7.2) — те же. `[исходник]`
- **Скрипт — только остров реестра** `ISLANDS`: инлайн-скрипта в `<body>` у сайта нет, хеш тела — в CSP; вызов `mount` —
  внутри модуля острова, а не строкой страницы. `[исходник]`
- **Ворота страницы** — `motion_check.py` на собранной странице по уровню и `page_gates.py --motion` (вердикт 2.2.2,
  вспышек, reduce).

## 3. Лабораторная страница

Приём, которого заказчик должен увидеть живым до кода, — лабораторная страница `…/design/<surface>/motion/lab/<id>/`
(`../../../references/phases.md`, этап `motion`):

- рядом со страницей — копии `motion-kit.js` и `motion-kit.css`, своя `look.css` облика проекта; разметка — `data-mk` и
  DOM-контракт спецификации (`data-section`, `data-slot`, `data-moment`);
- проверка — `motion_smoke.py --root <папка> --page index.html` (режимы `static,desk,rm,reduced,nojs,phone`) и

  `[data-mk-on="full"]` нет. Проверки макета, сверка текстов и судья видят полный текст. `[проверено: nojs — скрытого

- **Чем проверять**:

## Частые ошибки

- **Набор кодом логики артборда без файла** — в код его переносят копированием и правками; файл поддержки по умолчанию.
- **`data-motion` на `<html>` холста** — выбор уходит на все артборды страницы холста; носитель — корень артборда.
- **Разбиение скриптом на холсте** — тип запрещает строить интерфейс скриптом; куски — разметкой.
- **Утверждение движения по обзору холста** — обзор неподвижен; принимают в Play или по записи лабораторной страницы.
- **Второй обработчик кнопок на сайте** — набор с `toggle: true` рядом с островом предпочтений; на сайте `toggle: false`.
- **Набор до LCP** — модуль острова после `load` в простое.

## Открытые вопросы

- **Проба набора на холсте** не делалась: §1.4 — список шагов.
- **Имена токенов движения сайта.** В `tokens.css` шаблона сайта — `--motion-marketing-duration-hover`,
  `-duration-page`, `-easing-out`, `-easing-in-out`: у базы кривая входа — `easing.out-expo`; где имени базы в ДС нет,
  набор берёт своё запасное значение, а не значение ДС.
- **`paused` на сайте** — `01` § Открытые вопросы.
- **Скорость строки в `motion_check.py`** (EG-A11Y-19) меряется на шагах прокрутки с петлёй в окне, пока строка не
  попадёт в окно (до шести шагов). Живого прогона ворот на демо с бегущей строкой нет: сверка с замером
  `motion_smoke.py` (40,0 px/с) открыта.
