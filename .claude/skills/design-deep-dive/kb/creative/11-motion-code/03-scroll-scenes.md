# 03 · DOM-сцены прокрутки: `scrub` · `beats` · `glide` · `play` на пружине сцен 3D

DOM-сцена — секция `data-mk="scene"`, чей прогресс набор пишет в CSS-переменную `--mk-p` (0…1), а такт — в атрибут
`data-beat`. Облик сцены — CSS автора от этих двух значений: линия рисуется `stroke-dashoffset: calc(1 - var(--mk-p))`,
узел светится, когда прогресс прошёл его долю, подпись такта встаёт по `data-on`. Режимы, геометрия и пружина — те же,
что у рантайма сцен 3D (`../../3d/16-js-scenes/02-stage-runtime.md` §3–§7): DOM-сцена и 3D-сцена на одной странице
ведут себя одинаково под пальцем. Прокрутку набор не перехватывает. Примитивы без сцены — `02`, контракт — `01`.

Слова раздела: **окно** — липкая часть сцены `[data-mk-stage]` высотой H; **точка покоя** — значение прогресса, на котором
сцена стоит; **такт** — переход к следующей точке покоя; **поле** — длина прокрутки закреплённой сцены.

## Выжимка для агента

1. **Прогресс → `--mk-p`, такт → `data-beat`, подписи → `data-on`**: сцена — разметка и CSS автора, набор пишет одну
   переменную на кадр и только при изменении. `[проверено]` → §1
2. **Пружина — дословно рантайма 3D**: критически демпфированная, точное решение за шаг; без рывка и перелёта; 95 % пути
   — за 4,74/ω с. Замер: такт ω 3 — 95 % за 1,50–1,53 с, перелёта нет, точка покоя ±1,4·10⁻³ через 2,4 с.
   `[проверено: motion_smoke desk]` → §2
3. **Четыре режима**: `scrub` — прогресс = прокрутка, ω 6,5; `beats` — шаги с доигрышем, ω 2,4–3,6; `glide` — путь с
   инерцией, ω 2, только карты и маршруты; `play` — играет сама 9 с один раз, нужна пауза. `[проверено: scrub, beats;
   glide, play — демо]` → §3
4. **Такт — карточка на линии 60 % окна**: шаг 480 px ПК, 420 телефон; заставка 0,78 H; последняя карточка — шаг + хвост
   0,45 H + выход 0,45 H; 5–7 точек покоя; поле ≤ 450vh (`scroll.pin-beats-max-vh`, L2). `[проверено: такты 0 → 4 по
   одному]` → §4
5. **Закрепление — `position: sticky`** под шапкой, без pin-spacer: CLS при прокрутке 0,0035 на демо. `[проверено:
   motion_check EG-PERF-02]` → §5
6. **Один источник прогресса на сцену**: внутри DOM-сцены всё движение — от `--mk-p`; свои CSS-шкалы внутри сцены не
   ставят; у шкал набора `view-timeline-inset: 0px`. `[практика]` → §5.3
7. **Внутреннее окно холста**: набор берёт ближайший прокручиваемый контейнер, высоту окна — его `clientHeight`
   (`--mk-vh`), слушает прокрутку документа с перехватом. `[проверено: страница]`, `[не проверено на холсте]` → §5.4
8. **Reduce, «Меньше», без JS и обзор холста — конечный кадр**: `--mk-p` = 1, окно не липнет, карточки тактов — текстом,
   рельса и «Пропустить» нет; это станции вместо движения. `[проверено: rm, reduced, nojs]` → §6
9. **DOM-сцена и 3D-сцена делят страницу**: разные атрибуты, одна пружина, между сценами — статичный блок; внутри места
   3D прогресс ведёт рантайм 3D. `[практика]` → §7

## 1. Разметка

```html
<section data-mk="scene" data-mk-mode="beats" data-mk-beats="0,0.299,0.585,0.835,1" data-mk-tempo="3">
  <div data-mk-stage>                                        <!-- окно: липкое под шапкой, высота — окно минус шапка -->
    <svg aria-hidden="true">…<path pathLength="1" style="stroke-dasharray: 1; stroke-dashoffset: calc(1 - var(--mk-p))"/></svg>
    <i class="node" style="--t: 0.299"></i>                 <!-- светится, когда --mk-p прошёл --t: CSS автора -->
    <nav data-mk-rail aria-label="Такты сцены"><button data-mk-dot aria-label="Такт 1"></button>…</nav>
    <button data-mk-skip>Пропустить сцену</button>
    <div data-mk-veil aria-hidden="true"></div>              <!-- выход: окно гаснет в фон места -->
  </div>
  <div data-mk-steps>                                        <!-- карточки идут обычной прокруткой поверх окна -->
    <div data-mk-beat data-group="beat-0">…заставка…</div>
    <div data-mk-beat data-group="beat-1">…такт 1…</div>
    …
  </div>
  <div data-mk-story>…кадры станций для reduce (по желанию)…</div>
</section>
```

| атрибут сцены | что | по умолчанию |
|---|---|---|
| `data-mk-mode` | `scrub` · `beats` · `glide` · `play` | `scrub` |
| `data-mk-beats` | точки покоя через запятую (`beats`); их нет — сцена идёт как `scrub` | — |
| `data-mk-tempo` | ω пружины | `scrub` 6,5 · `beats` 3 · `glide` 2 |
| `data-mk-length` | путь `scrub` и `glide`, vh (поле = окно + путь) | 150 |
| `data-mk-exit` | длина выхода, px | 0,45 H при `[data-mk-veil]` |
| `data-mk-dur` | длительность `play`, с | 9 |
| `data-mk-range` | отрезок прохода `a,b`, который становится прогрессом 0…1 | `0,1` |

| внутри сцены | что |
|---|---|
| `[data-mk-stage]` | окно; у `play` не липнет |
| `[data-mk-steps] > [data-mk-beat]` | карточки тактов (`beats`); их высоты задают поле (§4) |
| `[data-mk-k="n"]` | подпись такта n в окне: `data-on` — когда такт n, `--mk-fill` — путь до следующего |
| `[data-mk-seg="a,b"]` | надпись на отрезке прогресса: `data-on` на отрезке; набор ставит `--mk-a`, `--mk-b` — CSS считает свою долю `clamp(0, (var(--mk-p) - var(--mk-a)) / (var(--mk-b) - var(--mk-a)), 1)` |
| `[data-mk-rail] > [data-mk-dot]` | рельс тактов: `aria-current="step"` у текущего; только ПК и от 3 тактов |
| `[data-mk-skip]` | «Пропустить»: прокрутка к низу поля минус шапка |
| `[data-mk-veil]` | затемнение выхода: прозрачность `--mk-veil` |
| `[data-mk-story]` | раскадровка: видна без full, скрыта в full |

`--mk-p` зарегистрирована (`@property`, `<number>`, наследуется): дети читают её в `calc()`, `transform`, `color-mix()`,
`offset-distance` — путь точки по маршруту: `offset-path: path(…); offset-distance: calc(var(--mk-p) * 100%)`.

## 2. Пружина

Та же функция, что в `../../3d/16-js-scenes/02-stage-runtime.md` §4 и `../../3d/16-js-scenes/examples/stage-runtime.js` — дословно; совпадение
проверяет `motion_smoke.py` (static):

```js
function spring(x, v, target, w, dt) {           // examples/stage-runtime.js: [x, v] через dt секунд
  var d = x - target, e = Math.exp(-w * dt), c = v + w * d;
  return [target + (d + c * dt) * e, (v - w * c * dt) * e];
}
```

- Стоп — когда |x − цель| < 4·10⁻⁴ и |v| < 1,6·10⁻³; `--mk-p` пишется только при изменении; без движения — 0 кадров.
- Без рывка в начале и без перелёта: быстрый жест через несколько тактов доводит сцену до последнего такта одним
  движением. Пружина с отскоком для прогресса прокрутки запрещена (05/01 §7.3).
- 95 % пути — за 4,74/ω с (02-stage-runtime.md §4):

| ω | 6,5 | 3,6 | 3,2 | 3 | 2,8 | 2,6 | 2,4 | 2 |
|---|---|---|---|---|---|---|---|---|
| 95 % пути, с | 0,73 | 1,32 | 1,48 | 1,58 | 1,69 | 1,82 | 1,98 | 2,37 |

- Замер на `demo.html` (Chromium, колесо по 120 px, выборка 40 мс): такты 1–4 сцены ω 3 — 95 % пути за 1,497–1,533 с,
  кривая монотонна, перелёта нет, через 2,4 с до точки покоя ≤ 1,4·10⁻³; скраб ω 6,5 — прогресс монотонен при прокрутке
  вперёд, через 1,2 с после остановки разрыв 3·10⁻⁴ `[проверено: motion_smoke desk]`. Расчёт: x(t) в точке 1 с при 30 и
  144 Гц совпадает до 10⁻⁹ — пружина не зависит от частоты кадров `[проверено: selftest]`.

## 3. Режимы

| режим | прогресс | как ведёт | параметры | где | метка |
|---|---|---|---|---|---|
| `scrub` | доля прокрутки поля: `(шапка − r.top) / (r.height − H)` | пружина ω 6,5 — 95 % за 0,73 с | `data-mk-length` 100–150vh на шаг | сцена-объяснение, предмет, круговая шкала | `[проверено]` |
| `beats` — шаги с доигрышем | такт: последняя карточка, чей центр прошёл линию 60 % окна; цель — точка покоя такта | пружина ω `tempo` 2,4–3,6 (1,3–2,0 с) | `data-mk-beats`, `data-mk-tempo` | процесс, история станциями, туннель карточек | `[проверено]` |
| `glide` — путь с инерцией | доля прокрутки поля минус выход | пружина ω 2, хвост 2,4 с | `data-mk-length`, `data-mk-exit` | только карта и маршрут | `[кейс]` у 3d, демо — `[проверено: страница]` |
| `play` — играет сама | время: старт при видимости ≥ 40 % полосы, один раз | `0,5 − 0,5·cos(π·t / dur)`, финал держится | `data-mk-dur` 9–10 с | короткая история-полоса | `[проверено: страница]` |

- `scrub` и `glide`: поле = окно + путь (`--mk-len` в px, набор считает от высоты окна); `beats`: поле — сумма карточек
  тактов (§4). Прогресс закреплённой сцены считается от низа шапки (`opts.header` или `--mk-header`).
- `play` дольше 5 с рядом с контентом — нужна пауза (WCAG 2.2.2): общая пауза набора сдвигает время проигрыша на свою
  длину; в бюджете внимания `play` — петля, пока играет.
- Слушатель прокрутки один — на документе, `passive` и `capture` (ловит и внутренние окна); пачка событий — один кадр.

## 4. Такты, станции, рельс, «Пропустить», выход

- **Такт** (`beats`) — последняя карточка `[data-mk-beat]`, чей центр прошёл линию 60 % высоты окна; цель — её точка
  покоя из `data-mk-beats`; подпись `[data-mk-k]` такта получает `data-on`, рельс — `aria-current`; `data-beat` на сцене —
  для CSS автора. Замер: колесо по 120 px — такты 0 → 1 → 2 → 3 → 4 по одному `[проверено]`.
- **Карточки и поле**: заставка — 0,78 H; шаг — `--mk-step-h` 480 px (телефон 420): такт через 3–4 щелчка колеса;
  последняя — шаг + 0,9 H (хвост 0,45 H и выход 0,45 H). Окно 828 px (900 минус шапка 72): пять точек покоя — 646 + 4 ×
  480 + 745 ≈ 3,3 тыс. px ≈ 370vh ≤ `scroll.pin-beats-max-vh` 450 (02-stage-runtime.md §5). `[проверено: демо]`
- **Точки покоя — по смыслу картинки**: у демо линия из пяти узлов, точки покоя — доли длины пути у узлов (0; 0,299;
  0,585; 0,835; 1): такт кончается ровно на узле. Последние ≈ 8 % — спокойный кадр.
- **Станции в спецификации** — `scene.stations` с якорями `data-group` карточек (`anchor: beats.beat-1`) и
  `scene.scroll_mode: beats`; до 7 точек покоя.
- **Рельс** — только ПК и от 3 тактов; клик — прокрутка так, чтобы карточка такта встала на линию 60 %. **«Пропустить»**
  — к низу поля минус шапка. Прокрутка кнопками — плавная в full, мгновенная иначе.
- **Выход**: на последних `exit` px окно гаснет в фон места — `--mk-veil = xo² · 0,94` у `[data-mk-veil]` — и только
  потом уезжает (02-stage-runtime.md §7).

## 5. Закрепление, длины, окно прокрутки, один источник прогресса

### 5.1. Закрепление

`position: sticky; top: var(--mk-header)` у окна, `height: calc(var(--mk-vh, 100svh) - var(--mk-header))`; у `beats`
карточки идут поверх окна (`margin-top: −H`). Pin-spacer нет — CLS при прокрутке на демо 0,0035 (EG-PERF-02) `[проверено]`;
`pin` ScrollTrigger (`position: fixed`) дал бы 1,6–2,0 (05/02 §3.5).

### 5.2. Длины по токенам

| что | токен | значение |
|---|---|---|
| шаг скраба | `scroll.step-vh` | 120vh (100–150) |
| сцена со скрабом L1 | `scroll.pin-l1-max-vh` | ≤ 150vh, одна на страницу |
| закреплённая секция L2 | `scroll.pin-l2-max-vh` | ≤ 400vh |
| шаги с доигрышем | `scroll.pin-beats-max-vh` | ≤ 450vh (L2) |
| сглаживание скраба | `scroll.scrub-smoothing-s` | 0,6 с; пружина ω 6,5 — 0,73 с до 95 % |

`spec_check.py` (MS-13) сверяет `scene.length_vh` с этими потолками по уровню секции.

### 5.3. Один источник прогресса

- Внутри DOM-сцены всё движение ведёт `--mk-p`: свои `view()`-шкалы на элементах сцены не ставят — два источника
  расходятся.
- CSS `view()` по умолчанию учитывает `scroll-padding` страницы (его ставят под липкую шапку): прогресс CSS-шкалы у
  закреплённой сцены отстаёт от прогресса, который JS считает по `getBoundingClientRect`. Все шкалы набора —
  с `view-timeline-inset: 0px` (`view(block 0px)`); у закреплённых сцен — только JS-прогресс. `[практика]`

### 5.4. Внутреннее окно

На холсте прокрутка идёт во внутреннем окне. Набор берёт ближайший предок с `overflow-y: auto | scroll`, который
прокручивается (`opts.scroller` — явно), окно — его прямоугольник и `clientHeight`; ставит `--mk-vh` на корень — высоты
окна сцены, кадра до вылета и горизонтали считаются от него, а не от `100vh` вкладки. CSS-шкалы `scroll(nearest)` и
`view()` берут то же окно сами. `[проверено: на странице; на холсте — не проверено]`

## 6. Reduce, без JS, обзор холста, телефон

- **Конечный кадр**: без full у сцены `--mk-p: 1` из CSS, окно не липнет, карточки идут текстом под окном, рельс и
  «Пропустить» скрыты, `[data-mk-story]` виден. Это станции вместо движения (05/01 §4.2, стратегия `stations`).
  `[проверено: rm, reduced, nojs — sticky 0, --mk-p = 1]`
- **При смене режима на лету** («Меньше» в шапке) набор снимает `--mk-p`, `data-beat`, `data-on` — сцена встаёт в конечный
  кадр; обратно — прогресс считается заново и садится без пружины.
- **Телефон**: шапка 64 px, шаг 420 px, рельса нет; портретная композиция окна — CSS автора. `[проверено: phone]`

## 7. DOM-сцена и 3D-сцена на одной странице

- **Разные атрибуты**: место 3D — `section[data-stage]` (рантайм `StageRuntime`), DOM-сцена — `[data-mk~="scene"]`
  (набор); оба слушают прокрутку документа с перехватом и ведут прогресс одной пружиной — под пальцем они одинаковы.
- **Внутри места 3D прогресс ведёт рантайм 3D**; подписи тактов — его `data-on` и `--fill` (3d 16/02 §13).
  Обёртка места 3D DOM-сценой дала бы два источника прогресса.
- **Ритм**: между двумя сценами — статичный блок (3d 16/02 §14); пиков — по уровню (05/01 §5.5).
- **Пределы**: живых 3D-сцен ≤ 2 на ПК и 1 на телефоне (контексты WebGL); у DOM-сцены контекстов нет; сцена `play` —
  петля в бюджете внимания набора.
- **Пауза**: общая пауза набора (`data-motion="paused"`) стопорит `play` DOM-сцен; у места 3D — своя кнопка `[data-pause]`.

| что | чем |
|---|---|

| скраб монотонен и догоняет | `motion_smoke.py` desk (`scrub`) |

Рельс, «Пропустить» и затемнение выхода живая проверка не покрывает — их проходят руками на странице и в Play.

## Частые ошибки

- **Шаг 100–150vh у сцены с доигрышем** — «долго крутишь, ничего не происходит»; шаг `beats` — 480 / 420 px.
- **Своя `view()`-шкала внутри сцены** — второй источник прогресса; всё — от `--mk-p`.
- **Сцена идёт за прокруткой там, где нужен такт** — «втупую прокрут»; станции сюжета — `beats`.
- **`play` без паузы** — нарушение WCAG 2.2.2.
- **Точки покоя «на глаз»** — такт кончается мимо узла картинки; доли считают по длине пути.
- **Липкое окно без конечного кадра в reduce** — пустое поле прокрутки; без full набор снимает закрепление сам.

## Открытые вопросы

- **Общая пауза и рантайм 3D.** `StageRuntime` не слушает `data-motion="paused"`: на странице с обеими сценами связку
  (наблюдатель атрибута → пауза мест 3D) пишет обвязка страницы. Кандидат — чтение `data-motion` рантаймом 3D.
- **Шкала `view()` и `scroll-padding`.** Расхождение CSS-прогресса закреплённой сцены с JS-прогрессом при
  `scroll-padding-top` — `[практика]`; число расхождения на демо не мерилось.
- **Числа телефона** — эмуляция Chromium: реальные телефоны не мерились.
