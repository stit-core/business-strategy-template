## Выжимка для агента

1. **Центр — законен при ≤ 4 элементах** (eyebrow, H1, лид, CTA); всё остальное — от одной левой вертикали. Поправка к
   `../../ui/05-layout-grid/04-alignment-whitespace-composition.md` §1.5 для сайта. → §1.2 `[консенсус: Бирман, ui 05/01 §7.3, Hallmark]`
2. **Асимметрия — через колонки, а не через «съехало»**: 7/5, 5/7, 8/4 или `1.2fr 1fr 0.8fr`; одна грань сетки ломается
   намеренно (вылет, цитата, число). → §1.1 `[мнение вендора: Hallmark]`
3. **Полный вылет в середине страницы — приём**, если он пауза или пик ритма; ui «полноширинное только наверху» — для
   приложений. `overflow-x: clip` на `html, body`. → §1.3 `[мнение вендора]`
4. **Hero выбирается по `text_media`**: text-left/right (split 6/6 или 5/7), text-over (скрим обязателен), text-under,
   text-only (типографический), media-led (продукт или кадр главнее). → §2.1
5. **Высота hero — по политике первого экрана site**: `offer-cta` — `min-height: min(85svh, max(60svh, 38rem))` и край
   следующей секции виден; `poster` — `100svh` с признаком продолжения; `vh` и `dvh` для hero не использовать. → §2.2
   `[документация: web.dev, site 03-03 §2.4]` `[мнение вендора: Hallmark, Emil]`
6. **Содержимое hero помещается в 1280×800**: eyebrow + H1 + лид (≤ 3 строк) + CTA без прокрутки; `padding-block-end ≥
   1,3 × padding-block-start`. → §2.2 `[мнение вендора: Hallmark gate 44]`
7. **Зона текста в кадре 35–45 %, текст слева, объект в правой трети**; телефон — свой кадр 4:5 или 9:16 и текст над или под
   медиа, если зона не спокойная. → §2.3 `[проверено]`
8. **Текст поверх медиа — только со скримом-градиентом под колонкой** и проверкой F83 по буквам; альфу задаёт самый мелкий
   текст. → §2.4 `[проверено]`
9. **Мобильный hero — перекадрирован, а не сжат**: одна колонка, DOM «текст → медиа» одинаков на всех страницах, наклоны
   и вылеты снимаются < 60rem. → §2.5 `[практика: site blocks.yaml]`
10. **Отступы секций — «этажи» 64–160 px**: `space.section-m` 64→112 по умолчанию, `section-l` 80→160 у пауз и после смены
    фона, `section-s` 48→64 у служебных; ui `space.stack.section` 24 px на сайте не применять. → §3.1 `[мнение: Бирман 80 px]`
11. **Ритм фонов — система, а не чередование «белый/серый»**: тинт одного семейства — свободно; инверсия (тёмная пауза) —
    ≤ 2 на страницу (пауза + финал), кроме `theme: mixed` по решению арт-директора. → §3.2 `[спорно: Бирман vs Schoger vs taste]`
12. **Стык секций — градиентом в цвет следующей** (96–120 px), а не жёсткой гранью у медиа-hero; сверху — 140 px под
    прозрачную шапку. → §3.3 `[проверено: глазом: ai-media J/06]`
13. **Прозрачная шапка поверх hero**: контраст ≥ 4,5:1 к кадру в худшей точке, при прокрутке — непрозрачная сплошная (не
    стекло); ≤ 80 px десктоп, ≤ 64 телефон. → §4 `[стандарт]` `[практика: site 03-03 §4.1]`
14. **Смена числа колонок между соседними секциями** разрывает ложные связи (4 → 3); ≤ 2 одинаковых раскладок подряд
    («зигзаг» текст/картинка — не больше 2 подряд). → §3.4 `[мнение: Бирман; taste]`
15. **Формы, баннер cookie, попапы — короткий визуал поверх логики site**: форма в hero — фон по уровню, сама форма L0;
    баннер cookie ≤ 25–30 % высоты телефона (у рынка RU медиана 22,8 %), не закрывает CTA; попапы захвата выключены.
    → §5 `[данные: site M]` `[практика: решение заказчика 13]`

## 1. Сетка, асимметрия, вылет

### 1.1. Сетка и контейнер

- Контейнер 1280 (`size.container`) + поля 16→48 (`space.page-x`), модель Carbon Editorial: при > 1440 контейнер
  центрируется, поля растут (ui 05/01 §7.1) `[практика: система]`. 12 колонок, гаттер 24 (≥ 1024 — 32) (ui 05/01 §4).
- Колонка текста не шире 1040 (`size.hero-text-max`); абзац — 65ch (ui 02/03 §3); лид — 34em.
- Асимметрия задаётся долями: split 6/6, 5/7 (медиа шире), 7/5; фичи — `1.2fr 1fr 0.8fr` или 12-колоночная сетка с разными
  span вместо `repeat(3, 1fr)` `[мнение вендора: Hallmark layout-and-space]`. Три карточки и bento — законные архетипы при
  реальном содержании: в bento первый блок крупнее, 2–3 ячейки с визуалом, число ячеек = числу пунктов (taste 4.7)
  `[мнение вендора]`; некликабельная карточка без тени-кликабельности (ux 04/04 §3.1).
- Смена числа колонок между соседними секциями (4 → 3) — против ложных связей (ui 05/04 §8.3, Бирман [V14 1:12:55]) `[мнение]`.
- **Составная сетка** — вариант к 12 равным колонкам для редакционных секций L1–L2: две сетки наложены, колонки — разности их линий в
  `fr`: 2+3 → `grid-template-columns: 2fr 1fr 1fr 2fr` (самая гибкая), 3+4 → `3fr 1fr 2fr 2fr 1fr 3fr`, 4+6 — «разворот журнала» на
  широком десктопе; ширины блоков берутся то из одной сетки, то из другой; 12 равных колонок — «монотонный ритм» (Andy Clarke,
  [V:5MMm5DUjh78 27:39], [V:5MMm5DUjh78 31:45]; расчёт `fr` сверен W2 со слайдами) `[практика]`. Что составная сетка выглядит менее
  шаблонно, не измерено `[не проверено: слепая оценка — живая фаза W2 № 2]`.

### 1.2. Центр и левая вертикаль

| Когда центр законен | Когда нет |
|---|---|
| ≤ 4 элементов (eyebrow, H1, лид, CTA), `text-only` или `text-over` hero, манифест, финальный CTA | секция с текстом длиннее 3 строк, списки, формы, фичи с описаниями |
| жанр editorial/atelier с одним сломом выравнивания (Hallmark) | «всё по центру» на каждой секции (примета K3 и генераторов) |

Hallmark: не больше двух центрированных элементов в hero, иначе gate 6; kimi `k3_checks.py` помечает центрированный hero как
major — на сайте это предупреждение уровня L0, а не запрет (PLAN «Поправки», строка kimi) `[мнение вендора]`.

### 1.3. Полный вылет (full-bleed) в середине страницы

- Полноширинная медиа-полоса или фон секции на всю ширину — пауза ритма (`visual_role: pause`) или пик (`peak`);
  `composition.bleed: full`. Текст внутри всё равно в контейнере.
- Вылет за край с одной стороны (`bleed: edge`, приём E1 Hallmark: медиа на 10–20 % за край) — только ≥ 60rem; на телефоне
  снимается (site `blocks.yaml` hero-media below_60rem) `[мнение вендора]`.
- Страховка: `html, body { overflow-x: clip }` — сохраняет sticky, в отличие от `hidden` `[мнение вендора: Hallmark gate 34]`.

## 2. Hero «текст ↔ медиа»

### 2.1. Варианты

| `text_media` | Структура site (`block:`) | Колонки ≥ 60rem | display-роль H1 | Условие |
|---|---|---|---|---|
| `text-left` / `text-right` | `hero-media` split, product-frame | 6/6 или 5/7 (медиа шире) | m (≤ 36 зн.) | объект в кадре на противоположной трети |
| `text-over` | `hero-media` background, video-loop | текст ≤ 1040, зона 35–45 % кадра | l, xl | скрим-градиент + F83 по буквам (§2.4); `background.text_contrast` |
| `text-under` | `hero-media` poster-image | медиа во всю ширину, текст ниже | l, m | кадр без места под текст; LCP — картинка |
| `text-only` | `hero-text` statement-cta, marquee | текст ≤ 1040 | xl, l, poster | LCP 2,3 с — самый быстрый тип (ai-media 01/02) |
| `media-led` | `hero-media` scene-3d, `product-showcase` | медиа 7–12 колонок, текст короче | m, s | продукт доказывает первый экран; тяжёлое — после LCP |

Типы hero у 43 лидеров: фото 11, видео 5, скриншот 5, ИИ-картинка 5, типографика 4, 3D 4 (ai-media 01/01 §2.2) `[данные]`.
Порядок выбора медиа: продукт > фото сцены > шейдер/градиент > петля > 3D (там же) `[практика]`.

### 2.2. Высота hero: одно правило из трёх норм

| Норма | Значение | Где верна |
|---|---|---|
| kimi | ≤ 80vh при 1440×900, следующая секция видна | `offer-cta` |
| Hallmark | 70–90 % первого экрана, `clamp(60vh, 75dvh, 88dvh)`; 100vh/100dvh — примета (gate 6) | `offer-cta`, но dvh прыгает |
| Emil | `min-height: 100svh`: «dvh resizes as the URL bar collapses… svh is stable» | `poster` на телефоне |

Правило (сведено с site `../../site/03-page-structure/03-first-screen-and-mobile.md` §2.4):
```css
/* Chromium 153 · 2026-09-24 · [проверено расчётом: коробка 540–765 px при 900; svh = vh в headless] */
.hero--offer  { min-height: min(85svh, max(60svh, 38rem)); } /* first_screen_policy: offer-cta, offer-cta-header */
.hero--poster { min-height: 100svh; }                          /* policy poster: кампания L2, портфолио, letter */
/* высота по содержимому, если оно выше: не фиксировать height; vh и dvh для hero не использовать */
```
Заметка: `clamp(60vh, 75dvh, 88dvh)` Hallmark на практике равен 75dvh (dvh всегда между svh и lvh), то есть прыгает вместе с
панелью браузера `[не проверено: вывод из определений; реальный телефон]`. Проверка: на 1280×800 и 1440×900 видны
eyebrow, H1, лид, CTA и край следующей секции; `padding-block-end ≥ 1,3 × start` (Hallmark gate 44); верхний отступ hero ≤ 96 px
(taste 4.7) `[мнение вендора]`.

### 2.3. Зона текста и фокус кадра

- Кадр hero: зона текста 35–45 %, плотность краёв ≤ 0,06, объект в правой трети (shift_x ±0,15–0,2 у 3D), насыщенный цвет —
  только на главном; 80 % фиксаций — левая половина экрана 1920 → текст слева (NN/g) — `../../ai-media/06-art-direction-consistency/03-composition-for-web.md`
  §1, §3; `../../3d/06-materials-lighting-render/02-lighting-camera-composition.md` §5.3 (ссылкой) `[данные: у соседей]`.
- `composition.text_media` → `text_zone` плана ассетов ai-media: text-left ⇒ зона слева 0–0,40; text-over ⇒ зона + скрим;
  text-under ⇒ кадр без зоны.
- Фокус в боксе `cover` — формула `object-position` ai-media 06/03 §3.2 (ссылкой); из 16:9 в 9:16 остаётся 31,6 % ширины —
  телефону свой кадр.

### 2.4. Текст поверх медиа

Порядок: композиция (спокойная зона) → цвет текста по зоне → скрим-градиент под колонкой → проверка F83 по буквам и по
кадрам видео (0/25/50/75 %) — ai-media 10/03 §1–2 (ссылкой). Числа, которые нужны вёрстке: скрим тёмный 0,62 у края → 0 к
64–68 %, светлый 0,46 → 0; на телефоне сверху вниз 0,80 → 0,66 (48–50 %) → 0 (82–84 %); ровная плашка 0,5 — «серая коробка»;
ветви и блики под строкой не лечатся цветом — сдвиг фокуса и колонка уже `[проверено]`. Токены:
`color.scrim.dark`, `color.scrim.light`, `gradient.under-nav`. Проверка: `page_accept.py … --contrast ".hero h1" ".hero__lead"
".hero__kicker"` на десктопе и `--mobile`.

### 2.5. Мобильный hero

- < 60rem: одна колонка; порядок «текст → медиа» или «медиа → текст» одинаков на всех страницах проекта; визуальный порядок =
  DOM (без `order`); наклоны, вылеты, обрезки снимаются (site `blocks.yaml` conventions, hero-media) `[стандарт: WCAG 1.3.2]`.
- < 40rem: кадр 4:5 (1080×1350) или 9:16; видео — только вертикальный файл; H1 ≤ 4 строк, CTA выше черты первого экрана
  с учётом шапки ≤ 64 px и баннера cookie (site 03-03 §1.4, §5.3) `[данные]`.
- Текст поверх медиа на телефоне — только в спокойной зоне кадра, иначе `text-under`.

## 3. Ритм и фоны секций

### 3.1. Отступы — «этажи»

| Токен | 360 → 1440 | Роль секции (`visual_role`) |
|---|---|---|
| `space.section-s` | 48 → 64 | `chrome`, `calm` короткие (логотипы, stat-strip), шаги sticky-stack |
| `space.section-m` | 64 → 112 | `support`, `calm` — по умолчанию |
| `space.section-l` | 80 → 160 | `pause`, `peak`, первая секция после смены фона, финальный CTA |

Основания: Бирман — 80 px между «этажами» при макете 1024 и нижнее поле плашки больше верхнего (20/40) [V14 31:43, 41:02];
kimi `brief.yaml` — 96/64 без источника; Hallmark — шкала до 144; NN/g — «сегодняшние страницы слишком разрежены» (ui 05/04 §7).
Отсюда два ограничения: `section-l` не больше чем у каждой третьей секции; внутри секции — правило 1×/2× (ui 05/04 §3.1)
`[мнение]` `[исследование: NN/g]`. Нижний отступ секции может быть до 1,3 × верхнего (секция «садится» на следующую).

### 3.2. Фоны: тинт, инверсия, медиа

| `background.kind` | Когда | Норма |
|---|---|---|
| `surface`, `transparent` | по умолчанию | фон страницы; хрома ≤ 0,03 на L0 (ui 01/06 §1.7) |
| `tint` | группа секций одной темы, смена «этажа» | тот же оттенок, ΔL 2–4 % (Hobday ≤ 7 % светлая, ≤ 12 % тёмная; ui 11/03 §4.4) |
| `inverse` | тёмная пауза, манифест, финальный CTA, подвал | ≤ 2 на страницу (пауза + финал); `section-l` до и после |
| `gradient`, `mesh-gradient`, `grain` | пик, CTA-полоса, hero без фото | цвет и контраст — `03-color-surfaces-product.md` §3 |
| `image`, `video-loop`, `shader`, `webgl-3d` | пики по уровню (`ambition-levels.yaml`) | эффекты — F; стык — §3.3 |

Противоречие источников: Бирман — «чередование белый/серый — костыль» [V14 1:06:43]; Schoger — чередование «особенно уместно
на маркетинговых страницах» [V01 30:39], [V04 22:22]; taste — «Page Theme Lock: секции не инвертируются», кроме одного
Color Block Story. Позиция базы `[спорно]`: чередование ради разделения — костыль (разделяют отступ и заголовок); смена фона
как событие ритма (пауза, пик, финал) — приём; инверсий ≤ 2, если `page.theme` не `mixed`. У эффектных сайтов тёмный первый
экран — 25 из 49 (51 %, C, финал) `[данные]`.

### 3.3. Стыки секций

- Медиа-hero → следующая секция: градиент 96–120 px в цвет следующего фона (`gradient.seam-to-next`), сверху 140 px под
  прозрачную шапку (`gradient.under-nav`) — ai-media 10/03 §4.2 `[проверено: глазом у соседа]`.
- Перекрытие: карточка или кадр заходит на стык отрицательным отступом (`composition.overlap: true`) — глубина без теней
  (Schoger [V01 20:31], [V04 15:50]) `[мнение]`.
- Сплошной фон через несколько секций — `background.continues: true` (одна «этажная» плоскость), отступ между ними `section-s`.

### 3.4. Повторы и ритм

Не больше двух одинаковых раскладок подряд («зигзаг» текст/картинка — ≤ 2 подряд, taste 4.7); на 8 секций — ≥ 4 семейства
раскладок `[мнение вендора]`; распределение пиков и пауз — `ambition-levels.yaml` `section_distribution`, хореография — E.

## 4. Прозрачная шапка поверх hero (визуал; логика — site)

- До прокрутки: фон шапки прозрачный, под ней `gradient.under-nav` (0,55 → 0 за 140 px) на фото и видео; текст ссылок и
  логотип ≥ 4,5:1 (крупный ≥ 3:1) к кадру в худшей точке — проверка `page_accept.py --contrast "header a"` `[стандарт: 1.4.3]`.
- После начала прокрутки: сплошной `color.surface.base` (или inverse у тёмного сайта), граница 1 px или тень `elevation.raised`
  ui; стекло на липкой шапке — только `surface.glass-light` (≥ 72 %, blur 16) и не поверх hero: полупрозрачная липкая шапка даёт
  низкий контраст (NN/g через site 03-03 §4.1) `[исследование]`.
- Высота ≤ 80 px десктоп, ≤ 64 телефон; липкие слои ≤ 20 % высоты телефона; `scroll-padding-top` = высоте шапки
  (WCAG 2.4.11) — site 03-03 §4.2–4.4 `[стандарт]`. Прозрачная шапка у обычных посадочных — 17 % страниц (site M: 18 из 103)
  `[данные]`. Смена фона шапки — переход 150–200 мс, при reduce — мгновенно (нормы движения — E).

## 5. Формы захвата, cookie-баннер, попапы (коротко)

- **Форма в hero** (`block:hero-form`): фон и визуал первого экрана по уровню страницы до L1, сама форма — L0 без эффектов
  (`ambition-levels.yaml` `hero_form_rule`); поле ≥ 44 px высотой на телефоне, подписи над полями, контраст границы поля
  ≥ 3:1 (ui 09/04 `border.strong`); форма на медиа — на сплошной подложке `radius.media`, не на стекле.
- **Баннер cookie** (`block:cookie-banner`): немодальный, снизу или в потоке сверху, ≤ 25–30 % высоты телефона (у рынка RU
  медиана 22,8 %, p90 38,3 %; intl медиана 39,3 % — site M `pages.csv`, n = 11 и 5) `[данные]`; не закрывает hero-CTA;
  кнопки «Принять» и «Отклонить» равного веса (право — site); цвет — `surface`/`inverse` страницы, без стекла.
- **Попапы захвата и exit-intent** — выключены по умолчанию (решение заказчика 13; ux README №10); чат-виджет не
  раскрывается сам поверх первого экрана (site 03-03 §4.5).

## Частые ошибки

1. `min-height: 100vh` hero с одной фразой по центру (примета генераторов; Hallmark gate 6, kimi LOOK-HERO-CENTER).
2. Всё по центру на каждой секции; три одинаковые карточки как основа страницы.
3. Отступ секций 24–48 px «из токенов кабинета» — лендинг выглядит как админка; или 160 px везде — пустой шаблон.
4. Чередование белый/серый у каждой секции вместо ритма; 3+ инверсии без концепции.
5. Текст поверх фото без скрима или с серой плашкой 0,5; проверка контраста по среднему цвету.
6. Десктопный кадр 16:9 на телефоне — объект уехал, текст на небе.
7. Шапка-стекло поверх hero; прозрачная липкая шапка.
8. Вылет за край без `overflow-x: clip` — горизонтальная прокрутка на телефоне.

## Чек-лист

- [ ] `composition` секции заполнен (align, asymmetry, bleed, text_media, height) и не противоречит структуре блока site?
- [ ] Центр — только при ≤ 4 элементах?
- [ ] Hero: политика site → `min-height` по §2.2; на 1280×800 видны eyebrow, H1, лид, CTA и край следующей секции?
- [ ] Текст поверх медиа: скрим-градиент, F83 по буквам на десктопе и телефоне, по кадрам видео?
- [ ] Телефон: свой кадр, одна колонка, DOM-порядок не переставлен, вылеты сняты?
- [ ] Отступы секций — токены `space.section-*`, `section-l` не чаще каждой третьей?
- [ ] Инверсий ≤ 2 (или `theme: mixed` по решению), стыки градиентом в цвет следующей секции?
- [ ] Шапка: прозрачная только над hero, контраст ≥ 4,5:1, при прокрутке — сплошная?
- [ ] Баннер cookie ≤ 25–30 % высоты телефона и не закрывает CTA?

## Открытые вопросы и противоречия

1. Чередование фонов: Бирман vs Schoger vs taste — позиция «событие ритма, ≤ 2 инверсии» `[спорно]`; проверить на рубрике K.
2. `svh` против `dvh` в hero на реальных iOS/Android с панелью браузера — не проверено (headless не имеет панели).
3. Число 64 → 112 для `section-m` — синтез мнений (Бирман 80 при 1024, kimi 96, Hallmark 96/144), замера отступов на живых
   сайтах нет (C не мерил) — кандидат в замер K/C.
4. Центрированный hero: kimi `k3_checks.py` — major; позиция базы — допустим при ≤ 4 элементах; сводит I (предложение kimi).
