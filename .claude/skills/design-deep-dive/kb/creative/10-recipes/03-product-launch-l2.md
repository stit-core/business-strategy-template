## Выжимка для агента

1. **L2 для продукта — только флагманский запуск по явному решению** (`landing-product` → L2 с `ambition.source`); иначе L1 (рецепт 02). `[практика: A]` → §1
2. **История до формата**: герой — зритель, конфликт, развязка; 3D — средство показать механику продукта, а не «центр». `[V:yAWFjiaK1Ek 04:38] [мнение]` → §2
3. **Три-четыре сцены в ритме «спокойно ↔ вау»**: hero (акцент) → пик 1 → спокойно → пик 2 → акцент DOM → спокойно; конверсия — L0. `[данные: C через E 05/02 §1]` → §4
4. **Текст, цифры, призыв — в HTML с первого кадра**; LCP — постер своего рендера (`<img fetchpriority=high>`), не canvas. `[проверено: J/02 — EG-PERF-08]` → §5
5. **Один холст на страницу, `position: fixed`, рендер только по вводу** (прокрутка, указатель, одно «пробуждение»): 0 кадров в покое. `[проверено]` → §6
6. **Сглаживание сцены — по времени (τ 90 мс, после 0,28 с без ввода — 30 мс) с отсечкой 0,45 с после ввода**, а не по кадрам: на SwiftShader и CPU ×4 кадровое сглаживание тянет хвост 1–2 с; motion_check 0.1.2+ снимает счётчик на +0,5 с. `[проверено]` → §6
7. **Станции — доли `at`, шаги стоят там же**: `top: calc(var(--at) * (100% - 100svh) + 50svh)`; шаг между станциями ≤ 150vh прокрутки. `[проверено: J/02, spec_check MS-13]` → §5
8. **Плавной прокрутки нет**: сцены на родной прокрутке, хвост только у картинки; `cliche:smooth-scroll-default` не берём. `[проверено]` → §6
9. **Сборка и разборка — из модулей с общей кинематикой**: невидимые шарниры + видимые модули с матрицей «шарнир × разнос», 3 вызова на модуль. `[проверено]` → §6
10. **Скан внутрь — плоскость отсечения в системе детали + светящаяся кромка в шейдере** (`onBeforeCompile`), корпус `DoubleSide`. `[проверено]` → §6
11. **Без WebGL, без JS и в reduce — те же станции картинками** (свой рендер, 7–16 КБ WebP каждая); three.js не грузится. `[проверено]` → §5
12. **WebGL2 проверять на том же холсте и отдавать контекст three**: без второго контекста, без ошибки в консоли, без 125 КБ зря. `[проверено: J/02 — EG-FB-06]` → §6
13. **Переключатель «Меньше движения» обязателен** (L2, CRV-AL-12): кнопка `aria-pressed` поверх `motion.js` F2, выбор помнится. `[проверено: J/02 — EG-A11Y-03, -12]` → §6
14. **Бюджет примера: сессия 0,37 МБ, первый экран 0,34 МБ, three в бандле 123 КБ br, шрифты 187 КБ** — в 20–60 раз легче якорей L2. `[проверено]` → §8
15. **Честный потолок кода** (после светового прохода J/04): свет и материал — «уверенный предметный рендер» (студия PMREM, лак, тень, фон, свет по сюжету), идея и ясность — на уровне якорей; атмосфера (туман, объёмный свет, bloom), микродеталь модели и запечённый GI — ниже, их даёт ассет (CAD, Blender, KTX2) и дни доводки. `[мнение: J2, один судья]` → §9

## 2. Концепция и направления

- **Тезис**: «Движется только сам продукт и только по вашей прокрутке: рука разбирается на модули, собирается поворотом колец
  и открывает сустав; текст стоит». `[практика: пример J/02]`
- **История** (NYT, [V:yAWFjiaK1Ek 10:59–11:02]): герой — инженер цеха; конфликт — классический робот требует интегратора и
  месяцев; развязка — модули собирает сам инженер за 30 минут и программирует рукой. Бренд — средство ([V:yAWFjiaK1Ek 14:14]).
- **Главный приём**: сборка из модулей по прокрутке (`3d:01-01#3.5` «взрыв-схема и сборка») + скан-проявление начинки.
- **Направления** (3): A «Сборочный чертёж» — тёмная студия, белые модули, сигнальный оранжевый замок (выбрано); B «Цех ночью» —
  световые трассы траектории (ближе к hubtown — риск `cliche:neon-glow`); C «Паспорт изделия» — светлая бумага, изометрия.
- «Вау» ставится в первые 2–3 экрана (пик 1 начинается сразу после hero), последний пик — до цены и формы (E 05/02 §1.3).

|---|---|---|---|---|---|---|
| hero | one-shot | load + сцена готова | лид, кнопки, факты: 16 px + opacity; рука «просыпается» 1,2 с, `sin(π·ease)` | — | постер той же позы | рука вверху кадра, текст внизу |

| story-inside | scroll-linked | скраб | скан 0,06–0,52 (плоскость y ≤ c, кромка 18 мм); слои расходятся 0,6–0,92 | 0,3 · 0,64 · 0,95 | 2 станции-картинки | масштаб 1,9 |
| product-demo | one-shot | in-view 20 % | 5 точек по 60 мс + путь `stroke-dashoffset` 900 мс | — | конечное | стопка |

`treatment`: `page.motion_system = {thesis, primitives: [fade-up, line-draw], smooth_scroll: false, reduce_toggle: true}`;
у пиков `effects: [effect:3d-scene]`, `reduce.strategy: stations`, `mobile.strategy: simplified`, `budget.load: after-lcp`.

Дополнения J2 (сцена v2): в story-modules модуль садится с «зависанием» 7 см над гнездом и дожимом (доли 0,2–0,86 отрезка модуля),
поворот кольца — щелчком (перелёт ≈ 11 %), кольцо загорается при фиксации и гаснет при разборке, висящие модули кренятся от скорости
прокрутки (пружина ζ 0,8, ≤ 5,7°, затухает за ≈ 0,41 с), камера на станциях идёт дугой (разнос — обход сбоку, сборка — ниже, первое
движение — наезд 8 %); в story-inside генератор волн делает 3 оборота на сцену, колесо — 1/12 навстречу. Телефон (`quality: low`):
те же движения без карты теней и Physical; первый экран — затемнение снизу в слое hero (`.hero::after`, 22 % → 0,82–0,9), иначе H1
лежит на белых корпусах (EG-A11Y-27: 1,0:1 у v1). Моменты motion-spec (`uniform:*`) не менялись — это вторичные слои тех же моментов.

## 6. Эффекты, стек и код

Эффекты: `effect:3d-scene` (L2), `effect:hero-entrance-once`, `effect:motion-toggle` (F2), `effect:svg-line-draw` (путь в
интерфейсе). Стек: HTML + CSS; `three@0.186.1` бандлом esbuild (580 КБ / **123 КБ br** после светового прохода J2, `legal-comments=eof` —

```js
/* three 0.186.1 · Chromium 153 · 2026-09-25 · [проверено] рендер по требованию, хвост ≤ 0,45 с */
function frame(now) {
  raf = 0; if (!alive || !isReady) return;
  const dt = Math.min(0.05, Math.max(0.001, (now - (lastFrame || now - 16)) / 1000)); lastFrame = now;
  const since = now - lastInput, late = since > 280;
  const k = 1 - Math.exp(-dt / (late ? 0.03 : 0.09));        // по времени, не по кадрам; к концу хвоста — быстрее, без рывка
  cur.t += (state.t - cur.t) * k;
  const cut = since > 450;                                   // motion_check 0.1.2+ снимает счётчик на +0,5 с после шага
  let settled = Math.abs(state.t - cur.t) < 0.002 || cut;
  if (settled) cur.t = state.t;
  const quiet = draw(cur.t, dt, cut);                        // вернёт амплитуду пружин инерции
  if (quiet > 0.002 && !cut) settled = false;
  renderer.render(scene, camera);
  if (settled) lastFrame = 0; else raf = requestAnimationFrame(frame);   // в покое — ни одного кадра
}
```

### 8.1. Почему S в прогоне 1 — ложные и что сделано

`motion_check.py` 0.1 снимает один кадр на паузу через 0,7 с после шага и сравнивает счётчик вызовов WebGL с прошлой паузой: кадры,
нарисованные во время прокрутки, засчитываются как «петля в покое». В примере: время сглаживания переведено на секунды (отсечка
0,6 с), станции холста — на доли `at` без DOM-якоря, WebGL проверяется до import. Предложение K — два снимка внутри паузы
(отчёт J §6); до исправления детектора — исключение `x-gate-exception {id: EG-A11Y-16, why, who: J, until: motion_check 0.2}`.
Доказательство — зонд покоя (перехват `drawElements/drawArrays`, два снимка в одной
паузе): в 5 точках прокрутки 0 вызовов за 1,2 с покоя (`idle_probe_desk.json`). Пример считается прошедшим ворота K: 0 B,
S — только ложные детектора с доказательством.

**Итог (J2):** K2 исправил детектор по этим пунктам (motion_check 0.1.2: два снимка в паузе на +0,5 и +1,2 с, станции холста кадром,
EG-A11Y-11 без скрипта переключателя, радиогруппа и `[data-motion-toggle]` видны; 0.1.3 — F83 со стилями из `examples/_shared/` и контраст над живым
фоном). Прогон 3 на сцене v2 — 0/0/0 без исключений, **исключение снято**. Из-за снимка на +0,5 с хвост кадров в сцене укорочен до
0,45 с (τ 90 → 30 мс после 0,28 с без ввода), иначе последние кадры хвоста попадали бы между снимками. Новая находка прогона:
текст первого экрана на телефоне над 3D (EG-A11Y-27) — у v1 H1 1,0:1, исправлено затемнением в слое hero (§5, выжимка п. 21).

## Частые ошибки

1. WebGL-«центр» без задачи — у K3 11 из 15 работ (PLAN риск 4); проверка: «если убрать холст, что потеряет рассказ?».
2. Холст рисует каждый кадр в покое — у 20 из 31 наградного сайта с WebGL (C 01 §13); батарея телефона и ложные «петли».
3. LCP на canvas или заставке «Enter» — метрика и человек ждут 5–20 с (unseen, hubtown в замере 3d).
4. Текст станции внутри canvas — не читается поиском и ИИ-краулерами (CRV-AL-04); у нас текст — HTML-панели.
5. Сглаживание по кадрам (`cur += (t - cur) * 0.16`) — на медленном GPU хвост тянется 1–2 с; брать время и отсечку.
6. Второй контекст ради проверки WebGL — на телефоне L2 разрешён один; проверять на том же холсте и передавать `context`.
7. Широкий display «для техно» — выглядит игровым; узкий экземпляр 58–62 % и вес 700–760 — инженерный.
8. `forceContextLoss()` при выключении движения, а затем повторный `getContext` на том же холсте — контекст потерян; нужен новый холст.
9. Станции в `motion-spec` с DOM-якорем для fixed-холста — зонд меряет край холста, а не сцену.
