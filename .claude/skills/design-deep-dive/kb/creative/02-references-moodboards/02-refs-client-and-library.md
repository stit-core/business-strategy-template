## Выжимка для агента

1. **В сервисы входит только заказчик**: `refs_client.py login <сервис>` в его терминале открывает обычное окно Brave без
   автоматизации; агент `login` не запускает никогда, пароли и токены не берёт, даже если их предлагают. → §2.1 [проверено]
2. **Cookie и токены не читать, не печатать, не копировать**; `status` показывает только имена и сроки; своих запросов с
   заголовками авторизации к Dribbble, Behance, Dprofile не собирать — данные только из DOM, серверного HTML и ответов,
   которые страница получает сама (`page.on("response")`). → §2.2, §8 [практика: правило заказчика]
3. **Режим сервиса решает заказчик**: «поиск» (клиент листает выдачу сам), «ассистент» (только ссылки заказчика), `off`;
   на 24.09.2026: Dribbble — «поиск», Dprofile — «поиск» (с 16:24, риск п. 11.3 принят заказчиком), Behance — `off`. → §1.2 [практика: решение заказчика]
4. **Движок — Brave 153** и для окна входа, и для `search`/`get` (`launch_persistent_context(executable_path=Brave,
   headless=True)`): вход через Google в Chrome for Testing не проходит; профиль одного сервиса — одним движком. → §2.1 [проверено]
5. **Автоматизацию не маскировать**: без stealth, без подмены UA (`HeadlessChrome/153`), без правки `navigator.webdriver`
   (остаётся `true`); антибот не обходить. → §2.2 [практика: правило заказчика] [проверено]
6. **Слот браузера клиента — отдельный**: `$DDD_HOME/locks/browser-refs.lock`, один браузер клиента на
   машину; удержание ≤ 280 с на вызов или партию; перед запуском ≥ 3 ГБ свободной памяти. → §2.3 [практика: решение оркестратора] [проверено]

8. **Челлендж, капча, 401/403 → стоп без повтора и пауза сервиса 6 ч**; 429 → пауза по Retry-After, не меньше 1 ч; снять

9. **Сухой режим перед новым запросом**: `--dry-run` печатает адрес, число порций, слот, профиль, куда лягут записи; сети

    `material`, `imagery`, `effect` из `art-direction` A. → §6.1 [стандарт: site-brief v0; A]
18. **«Чего не брать» — поле `dont_take`** (в задании — `avoid`; имя как в `site-brief references[]`, чтобы запись
    переносилась в бриф без переименования). → §6.1 [практика: решение B]
19. **Автор — только имя и ссылка на профиль** (атрибуция); город, соцсети, статистику автора не сохранять: Dribbble
    п. 7.7 запрещает собирать «User information, including account names». → §6.2 [спорно]
20. **Галереи и сайты — только разрешённое `robots.txt`**, разбор по RFC 9309 (самое длинное правило, `*` и `$`, `?`
    буквально); `urllib.robotparser` ошибочно закрывает Awwwards SOTD. → §4.4 [стандарт: RFC 9309] [проверено]
21. **Are.na — через API v3**: чтение публичного канала без токена (гость — 30 запросов в минуту на IP, клиент — ≤ 24);
    выгрузка — только в `private`-канал (по умолчанию новый канал `closed` = виден всем). → §7.2 [документация: Are.na v3]
22. **Вход не рвётся от Ctrl+C**: браузер в своей сессии процессов; 1-й Ctrl+C — «закройте окно, я жду», 2-й — доводка
    без закрытия окна; прерванный вход доводят `login --finalize` или `status`. → §2.1 [проверено]
23. **Видео чужих работ не качать**: в записи — ссылка на медиа, превью — постер или наш снимок кадра. → §5.2 [практика: правило]
24. **Интерактивный запрос — секунды, а не минуты**: одна загрузка 15–18 с (из них 10–16 с — интервал), запрос из 2–3
    загрузок — 30–55 с на 34–68 кандидатов. → §3.4 [проверено]
25. **Галерея — список сайтов, а не картинок**: запись галереи — сам сайт (`site-<домен>`, один сайт из разных галерей —
    одна запись), награда с датой — `awards[]`, страница галереи — `source_url`; скриншоты и описания галереи не
    сохраняются (CSSDA, Minimal Gallery, Landingfolio, Lapa Ninja, Land-book запрещают), превью — наш снимок сайта
    (`--shots K`). → §4.4 [проверено: B/02 офлайн; условия площадок]
26. **Данные галереи — из её же страницы**: DOM, состояние, которое сервер положил в HTML (FWA `caseMenu`, Recent — seroval),
    ответы ленты, которые страница запросила сама; своих запросов к API галерей нет. → §4.4 [проверено]
27. **Движение референса — замером, командой `motion <ref|URL>`**: клиент зовёт `motion_probe.py probe` подпроцессом и
    пишет строки «что взять» паспорта в `values.measured` записи (способ `probe`, `values.passport` — id паспорта);
    закрыто защитой, входом или robots.txt — пометка «сайт смотрит человек» без чисел, защита — ещё и пауза хоста;
    сбой — запись не меняется; записи нет — сначала `get`. → §7.3 [проверено: самопроверка]

## 1. Зачем клиент и какие у него режимы

### 1.1. Задача

Заказчик хочет «зайти во фронтенд… реализовать клиента на Питоне, чтобы не открывать браузер постоянно» (чат с
оркестратором 24.09.2026 ≈ 14:20–14:50). Клиент собирает кандидатов в мудборд (30–60 референсов на направление, процедура —
`03` §1) со своих аккаунтов заказчика и складывает их в локальную библиотеку с превью, палитрой и подписями «что взять».
Официального пути нет: Dribbble API v2 отдаёт только шоты авторизованного пользователя («List the authenticated user's
shots», `GET /shots/:id` — «returns only shots owned by the currently authenticated user»), Behance новых ключей не выдаёт, у
Dprofile публичного API нет [S2][S12]. Поэтому для трёх площадок клиент браузерный, а для Are.na — через API [S5].

### 1.2. Режимы и решения заказчика

| Режим | Что делает клиент | Команды | Риск условий |
|---|---|---|---|
| «поиск» (`search`) | сам открывает выдачу по запросу, листает 1–5 порций, пишет кандидатов | `search <сервис> "<запрос>"` | выше: автоматический доступ к выдаче |
| «ассистент» (`assistant`) | открывает только ссылки, которые собрал заказчик (файл, Are.na), и обогащает их | `get <URL>`, `enrich <файл>`, `arena pull` | ниже: одна страница на ссылку заказчика |
| `off` | к сервису не ходит | — | нет |

| Сервис | Режим 24.09.2026 | Основание |
|---|---|---|
| Dribbble | «поиск» | заказчик выбрал «поиск» с человеческой частотой после объяснения п. 7.1, 7.2, 7.11 условий (оркестратор, ≈ 15:00) |
| Behance | `off` | «давай пока без беханса» (заказчик, 15:33); адаптер не проверен вживую |
| Dprofile | «поиск» (с 16:24) | заказчик: «я хочу чтобы ты сам искала на дипрофайле»; дословно знал п. 11.3 («Не использовать скрипты (программы) для автоматизированного сбора Информации и/или взаимодействия с Сайтом»), риск блокировки аккаунта и вопрос «личных некоммерческих целей» (п. 11.1, 11.3) — риск принял он; до ответа (15:04–16:24) был «ассистент» + `hold` |
| Are.na | API | Acceptable Use разрешает интеграции, запрещает «scraping or bulk data collection» [S5] |

Режим хранится в коде (`DEFAULT_MODES`) и в `~/.config/creative-refs/modes.json` (600); меняет его только решение
заказчика: `refs_client.py mode <сервис> search|assistant|off [--clear-hold] --why "<кто и когда решил>"` (строка в журнале).

## 2. Архитектура

### 2.1. Вход заказчика и профиль

```text
// refs_client.py login · Brave 153 · 2026-09-24 · [проверено: B/03 dry-run, B/04 cookie, B/05 Ctrl+C]
заказчик: refs_client.py login dribbble
  → ~/.config/dribbble/ (700) ; profile/ (700) ; .profile.lock (flock на время окна)
  → /opt/brave.com/brave/brave --user-data-dir=<profile> --password-store=basic --no-first-run --no-default-browser-check
     --window-size=1280,900 https://dribbble.com/session/new      (своя сессия процессов, без отладочного порта)
  → заказчик входит (почта или Google), ждёт ≈ 30 с (база cookie пишется раз в ≈ 30 с), закрывает окно
  → ожидание выхода всех процессов профиля → права 700/600 → login.json (время, движок, без секретов) → status
```

- **Почему Brave, а не Chromium Playwright.** Первый вход 24.09 15:22 через окно Chrome for Testing не прошёл: заказчик
  пошёл через Google, и сессии не осталось (у accounts.google.com — только `__Host-GAPS`, `OTZ`). Google не пускает вход в
  сборки для тестирования — это наблюдение, а не документ `[кейс]`. С Brave вход прошёл (15:28–15:30, `user_session_token`
  до 2026-10-08). Опыт B/04: окно Brave `--headless=new` на временном профиле, 38 с, SIGTERM → Playwright с
  `executable_path=Brave` на том же профиле видит постоянные cookie `_octo`, `logged_in`; UA `HeadlessChrome/153`,
  `navigator.webdriver = true`, `navigator.brave = true` [проверено].
- **Оговорка Playwright.** `executable_path` — «Path to a browser executable to run instead of the bundled one… Note
  that Playwright only works with the bundled Chromium, Firefox or WebKit, use at your own risk» [S7]. Сейчас Brave и
  Playwright на одном Chromium 153 (Brave 153.1.95.101, Playwright chromium-1243); Brave обновляется сам — после
  обновления мажорной версии повторить опыт B/04 и один `search --pages 1`; сбой → `--engine chromium` (вход через Google
  там не работает, почта и пароль — да) `[документация]` `[проверено: B/04 на 153]`.
- **Шифрование cookie.** `--password-store=basic` в окне и у Playwright (флаг по умолчанию) → один ключ; cookie без срока
  (сеансовые) между запусками не живут — «запомнить меня» обязательно (разведка оркестратора [S12]).
- **Ctrl+C.** Раньше SIGINT из терминала убивал и Python, и окно (одна группа процессов), и шаги после окна не
  выполнялись (так 24.09 оборвались входы Dribbble и Dprofile). Теперь окно — `start_new_session=True`; 1-й Ctrl+C
  печатает «Закройте окно браузера — я жду», 2-й доводит вход без ожидания (окно остаётся открытым); `login --finalize` и
  `status` (если `login.json` нет) доделывают права, `login.json`, журнал [проверено: B/05 — см. README опыта].
- **Смена движка.** Профиль, созданный одним движком, другим не открывается: `login` и `search` отказываются и подсказывают
  переименовать профиль (старый Chromium-профиль Dribbble — `~/.config/dribbble/profile.chromium-20260924`).

### 2.2. Поиск и карточка в фоне

```text
// refs_client.py search/get · Brave 153 · Playwright 1.63 · 2026-09-24 · [проверено]
wait_memory(≥ 3 ГБ, ≤ 5 мин) → flock browser-refs.lock (≤ 900 с) → flock ~/.config/<сервис>/.profile.lock (≤ 60 с)
  → launch_persistent_context(profile, executable_path=Brave, headless=True, viewport=1440×900)
  → page.on("response"): документы главного кадра (статус, x-amzn-waf-action, retry-after), картинки CDN площадки,
     JSON выдачи по шаблону адаптера   — заголовки запросов и cookie не читаются
  → goto(выдача) → проверка блокировок → карточки из DOM (+ JSON, который страница получила сама)
  → порции прокруткой колесом (5–8 шагов по 350–550 px, пауза 250–600 мс) → проход за превью → превью, палитра, dHash
  → штатное закрытие (браузер дописывает базу cookie) → права 700/600 → запись в библиотеку под flock
```

- Данные берутся из того, что браузер уже получил: DOM, серверный HTML, ответы `xhr/fetch`, которые шлёт сама страница
  (Dprofile — `m-search/cases`, Behance — `v3/graphql`). Своих запросов к API сервиса клиент не строит: Dribbble 7.11,
  константа `Access-Token` Dprofile и `authorization: Bearer` Behance остаются внутри страницы [S1][S3][S4][S12].
- Видимое окно (`--headed`) — только по согласию заказчика через оркестратора (задание B); по умолчанию — безголовый режим.

### 2.3. Блокировки и ресурсы общей машины

| Ресурс | Правило | Число |
|---|---|---|
| слот браузера клиента | `$DDD_HOME/locks/browser-refs.lock`; другие утилиты и агенты его не берут | 1 браузер клиента на машину |
| общий замок браузера | утилиты замера: `$DDD_HOME/locks/browser.lock` (каждая утилита берёт его сама); клиент референсов его не берёт — у него свой слот `browser-refs` | вместе с клиентом ≤ 2 браузера (контракт v2 §4) |
| профиль сервиса | `~/.config/<сервис>/.profile.lock`; открыт в окне входа → клиент отказывается | ожидание ≤ 60 с |
| удержание | на вызов или партию `enrich` (≤ 12 ссылок) | ≤ 280 с |
| память | `MemAvailable` перед запуском | ≥ 3 ГБ, ожидание ≤ 5 мин |

Почему отдельный слот: в 15:36–15:48 24.09 запросы клиента ждали общую очередь 104–275 с, `get` — больше 10 мин (≈ 12
агентов тройки мерят сайты); после перевода на `browser-refs.lock` ожидание 0 с, запросы — 12–48 с [проверено].

## 3. Частоты, пауза, журнал, сухой режим

### 3.1. Частоты

| Что | Число | Основание |
|---|---|---|
| интервал между загрузками страниц одного сервиса | 10 с + U(0; 6) с | Dribbble 7.2: не больше запросов, «than a human can reasonably produce… by using a conventional online web browser» [S1]; задание B |
| что считается загрузкой | переход на страницу, порция прокрутки, проход за превью | каждое может вызвать запрос выдачи |
| порций на запрос | 3 по умолчанию, ≤ 5 | 30–60 кандидатов на направление (`03` §1) = 1–2 запроса по 2–3 порции |
| страниц в сутки | Dribbble 60, Behance 40, Dprofile 60, галерея 40 | ≈ 15–20 мин активного просмотра человеком; Dribbble API для сравнения — 1 440 запросов в сутки [S2] |
| Are.na API | ≤ 24 запроса в минуту | гостевой лимит 30/мин на IP [S5] |

Счётчики — `99-raw/cache/refs/state.json` (под flock, без секретов); `refs_client.py limits` показывает режим, страницы за
сутки и паузы. Для сервисов со входом и галерей ключ частот и пауз — сервис; для «сайтов» — хост (`site:<домен>`, 40
страниц в сутки на хост): блок одного сайта не останавливает остальные (24.09 403 у dattstudio.com поставил на паузу все
сайты — исправлено) [проверено: library-example].

### 3.2. Блокировки площадки: стоп без повтора

| Сигнал | Что делает клиент |
|---|---|
| 202 + `x-amzn-waf-action: challenge` (AWS WAF Dribbble) или 403 | ждёт до 20 с, пока браузер **сам** выполнит скрипт челленджа и перезагрузит страницу; нет 200 → пауза 6 ч |
| 429 | пауза по `Retry-After`, не меньше 1 ч |
| 401 / 403 после ожидания | пауза 6 ч |
| капча-вызов: iframe капчи на «пустой» странице (< 1 500 символов) или не-200, активный `bframe`, DataDome, Arkose, GeeTest | пауза 6 ч; невидимый reCAPTCHA v3 или Turnstile форм на обычной странице — **не** блок (Awwwards SOTD 24.09: ложная пауза, детектор исправлен) |

| 5xx, тайм-аут | стоп вызова без паузы и без повтора |

Челлендж AWS WAF Dribbble проходит сам: браузер исполняет скрипт, как у человека; с сессией заказчика 24.09 челленджа не
было ни разу (6 запросов, 16 загрузок) [проверено]. У Land-book и Lapa Ninja безголовый браузер получает челлендж

## 5. Превью, дубли, палитра

### 5.1. Откуда превью

| Случай | Источник | Размер |
|---|---|---|
| карточка выдачи | тело ответа, который страница загрузила сама (`harvest` после каждой порции) | Dribbble: 320×240 или 400×300 — браузер выбирает по `sizes` карточки при DPR 1 |
| страница работы | главное медиа по геометрии (§5.2) из ответа страницы | до 800×600 |
| видео-работа | постер из ответа или наш снимок кадра элемента | до 800 px |
| сайт | наш снимок первого экрана 1440×900 | 800×500 (в `library-example` — 400×250) |
| сайт из галереи | только наш снимок сайта (`--shots K`, `get`); картинки галереи — никогда (§4.4) | 800×500 |
| Are.na | картинка блока с CDN Are.na | до 800 px |

Формат — WebP q80, длинная сторона ≤ 800 px, файл `previews/<id>.webp` (600); средний размер превью выдачи Dribbble —
≈ 11 КБ. Картинки с альфой заливаются белым.

### 5.2. Главное медиа — по геометрии

`get` выбирает самый крупный видимый `img` или `video` с CDN площадки в первых 1,5 экрана (≥ 240×160). Картинка → тело
ответа; видео → постер или `page.screenshot(clip=…)` элемента. Прежний вариант «самая большая картинка страницы» на видео-шоте
Dribbble взял рекламный баннер студии «Let's Collaborate» 800×269 вместо шота — чужое изображение под чужой подписью;
после правки превью — сам шот, 800×600 [проверено].

### 5.3. Дубли

- Канонический id из адреса: `…/shots/27190142-AI-Project…?utm=…` → `dribbble-shot-27190142`; повторная находка
  дописывает `found[]` (≤ 10), не дублирует запись; поля заказчика (`take`, `dont_take`, `roles`, `notes`, `boards`) при
  слиянии не теряются.
- Перцептивный хэш dHash (9×8 в оттенках серого, 64 бита): уменьшение 640→320 px — 0 бит разницы, зеркальная картинка — 48
  бит; кандидат в дубль — ≤ 6 бит (`lib dedup --threshold 6`) [проверено: самопроверка]. Порог 6 — `[не проверено]` для превью
  320–800 px; проверить на 100+ записях библиотеки.

### 5.4. Палитра

k-means в OKLab (перевод `../../scripts/lib/color.py`: `rgb2oklab`, `oklab2rgb`), превью 64×64 = 4 096 точек, k-means++ с зерном
0, ≤ 20 итераций, k ≤ 5, кластеры < 2 % отброшены → `preview_meta.palette[{hex, share, L, C, h}]` и `tags.color` по
убыванию доли. Проверка: картинка «половина синего, половина жёлтого» → 2 кластера по 50 % [проверено: самопроверка].
Цвета площадки (у Dribbble — 8 цветов шота) хранятся отдельно в `tags.source_colors`. Палитра превью — ориентир для
мудборда, не замер бренда: точные цвета сайта-референса — `measure_ui.py` (kimi 07/03 §2.1 [S9]).

### 6.1. Поля

| Поле | Что | Пример |
|---|---|---|
| `id` | стабильный kebab-id; в брифе — `ref:<id>` | `dribbble-shot-27190142`, `site-lusion-co` |
| `source`, `url`, `source_url` | площадка (id из `sources.yaml`), канонический адрес, где найдено | `dribbble`, `https://dribbble.com/shots/27190142-…` |
| `title`, `author`, `author_url`, `published_at` | подпись и атрибуция; дата — если площадка её показывает | `2026-03-17` |
| `captured_at`, `first_captured_at` | когда снято | ISO 8601 с часовым поясом |
| `preview`, `preview_meta` | путь от корня библиотеки; размер, байты, dHash, источник, палитра | `previews/<id>.webp` |
| `media`, `media_url` | `image`, `video`, `gif`, `site`; ссылка на медиа (не скачивается) | `…/file/df37….mp4` |
| `tags` | `style[]`, `effect[]` (`effect:<id>` из `effects.yaml` F), `section_type[]` (`block:<id>` из `blocks.yaml` site или `section-role:<id>`), `device[]`, `mood[]`, `color[]`, `era`, `source_tags[]`, `source_colors[]` | `effect:marquee-logos`, `block:hero-media-split` |
| `roles[]` | для чего годится: словарь `site-brief` v0 + `color`, `material`, `imagery`, `effect` (как `art-direction` `$defs/reference` A) | `composition` |
| `rights` | `use: internal-only`, `do_not_publish: true`, `license`, `holder`, `terms` | `terms: "dribbble.com/terms ред. 2025-03-17: п. 7.1, 7.2, 7.11, 11"` |
| `take[]`, `dont_take[]`, `notes` | что взять (объект + свойство + число), чего не брать, что работает словами | «заголовок слева в 2 строки ≈ 96 px» |
| `values` | значения текстом — форма `values` записи референса арт-дирекции: `measured` (строки «что взять» замера движения), `estimated`, `method` (`probe`), `passport` (id паспорта движения); пишет `motion` (§7.3), в записи — последний замер | `method: [probe]`, `passport: example.com-0f1e3c78` |
| `probe` | итог последнего замера движения: `status` (`ok`, `static`, `partial`; закрыто — `blocked`, `login`, `robots`), `words` — словами, `note` — чем закрыто, `at` и `viewport` — когда и в каком окне, `mobile`, `unseen` — что замер не видит | `status: blocked`, «закрыто защитой — сайт смотрит человек» |
| `boards[]`, `found[]`, `stats`, `awards[]`, `description` | мудборды; как найдено; снимок лайков и просмотров; награды `[награда]` | `found: [{mode: search, q: …, rank: 3}]` |

Схема — `refs-library.schema.json` (JSON Schema 2020-12, `additionalProperties: false`); 170 живых записей Dribbble 24.09
проходят её без ошибок [проверено: jsonschema 4.26, venv-B]. Правила схемы для замера: закрытый сайт (`probe.status`
`blocked`, `login`, `robots`) — без способа `probe` в `values`; способ `probe` — с `values.passport` и итогом замера
`ok`, `static` или `partial` [проверено: самопроверка].

### 6.2. Согласование с site и вопросы

- `ref:<id>` — пространство, предложенное site (`site-brief.schema.json` `$defs/reference.ref`, шаблон
  `^ref:[a-z0-9]+(-[a-z0-9]+)*$`); наш `id` ему соответствует. Выгрузка в бриф — `lib export --format brief --board <имя>`
  → `references: [{ref, url, role, take, dont_take, values, source: creative-library, captured, note}]` [S10]: `values` —
  строки замера движения (`measured`), способ и паспорт (`method`, `passport`) из записи и палитра снимка
  (`estimated`), форма — как у записи референса арт-дирекции (`../09-ai-execution-evaluation/art-direction.v1.schema.json`
  `$defs/reference`); `captured` — дата и окно замера, без замера — дата записи; закрытый сайт — в `note` словами «сайт
  смотрит человек».
- `role` в брифе одна, в записи — список пригодных ролей (`roles[]`); при выгрузке берётся первая — выбирать осознанно
  (`03` §3). Роли `color`, `material`, `imagery`, `effect` — в словаре ролей брифа (`role` в `$defs/reference` схемы
  `../../site/10-playbooks-contracts/schemas/site-brief.schema.json`).
- Автор: Dribbble п. 7.7 запрещает «Collecting or harvesting … User information, including account names» [S1]; Behance
  PST 2.1 — «collect other people's information without their consent» [S3]. Храним минимум для атрибуции (имя и ссылка на
  профиль) `[спорно]`; при отказе — `author: null`, атрибуция по ссылке на работу.

Take или Do not take (kimi 07/03 §1–3 [S9]). Процедура отбора — `03`.
Замер движения записи (→ §7.3) идёт в обе выдачи: в board.md и на карточке мудборда — строки замера с паспортом, датой и

строки ниже» и строками под ней; закрытый сайт — словами «сайт смотрит человек», без чисел.

### 7.2. Are.na API v3

- База `https://api.are.na`, `Authorization: Bearer <personal access token>` (скоупы `read` по умолчанию, `write` — для
  выгрузки); токен — файл `~/.config/arena/token` (600; при правах шире клиент откажется); клиент читает его сам и нигде не
  печатает [S5].
- `arena pull <канал>` — `GET /v3/channels/{slug}/contents?per=100&page=N` (≤ 3 страниц): блок со ссылкой-источником →
  запись площадки (Dribbble-шот из канала заказчика становится `dribbble-shot-<n>` без захода на Dribbble), картинка блока
  → превью. Это самый мягкий путь «ассистента»: заказчик сохраняет в Are.na, клиент читает API.
- `arena push <мудборд> --channel <slug>` — `POST /v3/channels {title, visibility: "private"}` (если канала нет) и `POST
  /v3/blocks {value: <URL>, title, description: Take / Do not take, original_source_url, channels: [{id}]}`; канал не
  `private` → отказ. Новый канал по умолчанию `closed`, то есть **виден всем** — поэтому `private` явно [S5].
- Ограничения: «This API is intended for building applications that integrate with Are.na, not for scraping or bulk data
  collection» [S5]; поиск по всему Are.na (`GET /v3/search`) — «Premium Only»; лимиты в минуту: гость 30 (на IP), Free 120,
  Premium 300, Supporter 600; чтение и запись — раздельные бюджеты, у записи ещё часовой.
- Аккаунта и токена Are.na у заказчика на 24.09.2026 нет (открытый вопрос 8 плана) → `push` работает в режиме плана.

### 7.3. Замер движения референса: `motion`

`motion <ref|URL> [--mobile] [--frames] [--dry-run]` — числа движения сайта, который заказчик отметил ради движения
(роль `motion`), снимает замер, а не глаз: клиент зовёт `motion_probe.py probe`
(`../03-live-sites-measured/03-reference-motion-probe.md` §6.1) и переносит итог в запись.

| Шаг | Что делает клиент |
|---|---|
| запись | id (`site-…`, `ref:site-…`) или адрес: запись с этим id, адресом или ссылкой, по которой её завели; записи нет — отказ с подсказкой `get <URL>`: запись заводит «ассистент» (наш снимок первого экрана, robots.txt, частоты), `motion` её дополняет |
| что мерится | живой сайт; работа Dribbble, Behance, Dprofile, страница галереи без адреса сайта, блок Are.na — отказ: их движение не референс сайта |
| частоты | ключ хоста `site:<домен>`, как у `get`: хост на паузе — стоп без повтора; интервал 10 с + U(0; 6) с, 40 страниц в сутки |
| замер | `motion_probe.py probe <адрес> [--mobile] [--frames]` подпроцессом, Python окружения скилла; robots.txt, отсев защиты и входа без ожидания и повтора, общий замок браузера и свободная память — правила утилиты (§8 действует и для неё); слот `browser-refs` клиент не берёт — браузер открывает утилита |
| код 0 — снято | строки «что взять» паспорта (объект, свойство, число, id момента в скобках) → `values.measured`; `values.method: [probe]`; `values.passport` — id паспорта (`<хост>-<хеш адреса>`, папка `$DDD_HOME/out/creative/motion-probe/<id>/`); `probe` — статус, время и окно, что замер не видит (WebGL, canvas, видео, SVG SMIL, Lottie, iframe) |
| движения не найдено, снято частично | тоже код 0: способ и паспорт без строк или с частью строк, итог словами — в `probe.words` |
| код 3 — закрыто | защита, вход или robots.txt: в `probe` — «закрыто … — сайт смотрит человек» и причина из паспорта, чисел нет, строки прошлого замера уходят; защита — ещё и пауза хоста 6 ч (429 — 1 ч), снять — решение заказчика: `resume site:<домен>` |
| сбой | код 2: запись не меняется, причина — в выводе утилиты |

- В записи — последний замер: повторный (и с `--mobile`) заменяет строки прошлого, паспорт той же страницы утилита
  пишет в ту же папку. Паспорт и кадры (`--frames`) остаются в выходе утилиты и в git не идут; в запись — только числа
  строками.
- `take` команда не трогает: «брать» из строк замера выбирают с заказчиком и записывают `lib tag --take`.
- Выгрузки: бриф и арт-дирекция (`lib export --format brief`, §6.2) — `values` с `measured`, `method`, `passport` и
  `captured` — дата и окно замера; передача (`handoff`) и мудборд (`board`) — строки замера с паспортом (§7.1); закрытый
  сайт — словами «сайт смотрит человек».
- Коды выхода: 0 — снято, 3 — закрыто, 2 — сбой; отказ (нет записи, не сайт) — 1, хост на паузе — 4, лимит в сутки — 5.

## 8. Безопасность и условия площадок

| Правило клиента | Почему |
|---|---|
| вход только заказчиком, окно без автоматизации и без отладочного порта | решение заказчика 3; безопасность учётных данных |
| cookie, токены, заголовки не читаются; `status` — имена и сроки | решение 3; самопроверка ищет в коде `cookies(`, `document.cookie`, `storage_state`, `add_init_script`, `user_agent=` — 0 совпадений |
| без stealth и подмены UA, `webdriver` не трогать | Dribbble 7.12 (обход ограничений), Behance PST 6.4 («may not conceal or obscure your identity» — для API) [S1][S3] |
| антибот не обходить: стоп и пауза | Dribbble 7.12; задание B |
| частота человеческая, лимиты в сутки | Dribbble 7.2, 7.5 [S1]; Dprofile 11.3 «Не нарушать работоспособность Сайта» [S4] |
| чужие работы — только в библиотеке заказчика; в базу — ссылка и «что взять» | решение 4; Dribbble 11 («copy, reproduce … publicly display»); Dribbble API: «Scraping, copying, saving, or storing our data is strictly prohibited» [S1][S2] |
| удаление по просьбе автора — за 24 ч | правила API Dribbble и Behance PST 6.1 (для API) — применяем и к библиотеке `[практика]` |
| видео не качать | вес, права |

Что заказчик принял и чего нет (24.09.2026): риск Dribbble для «поиска» — принят (оркестратор объяснил п. 7.1, 7.2, 7.11);

вынесены в отчёт B для решения.

## Частые ошибки

- Агент просит у заказчика пароль, токен или «лог с cookie», чтобы «быстрее» собрать запрос к API — запрещено (решения 3–4);
  в логах сети заказчика 24.09 были живые токены, их не трогали.
- Запуск `login` агентом или открытие окна входа «за заказчика» с автоматизацией (`--remote-debugging-port`, Playwright) —
  вход через автоматизированное окно Google к тому же не пустит.
- Маскировка: `user_agent=` без `HeadlessChrome`, `--disable-blink-features=AutomationControlled`, stealth-плагины,
  `navigator.webdriver = false` — прямо против Dribbble 7.12 и правил заказчика.
- Повтор после 403 или капчи «ещё разок» — вместо паузы; перебор прокси; быстрые параллельные вкладки одного сервиса.
- Удержание браузерной блокировки на весь прогон вместо партии ≤ 280 с — общая машина стоит.
- `currentSrc` ленивой картинки как адрес превью (`data:image/gif` 1×1) и чтение тел ответов в самом конце, когда буфер уже
  вытеснен — превью теряются (22 из 68 до правки).
- «Самая большая картинка страницы» как превью работы — баннер студии или чужой шот под подписью автора.
- Превью сайта из галереи — скриншот галереи (CSSDA, Minimal Gallery, Landingfolio, Lapa Ninja, Land-book это запрещают);
  или `get` страницы списка галереи — наш снимок чужих скриншотов. Превью — только наш снимок самого сайта.
- Образец DOM «ссылка с картинкой внутри» как основа адаптера: теряет карточки, где картинка вне ссылки (Httpster — 0 из
  24); данные карточки брать из самой карточки и состояния страницы (Recent, FWA).
- Одна и та же галерея по двум адресам: Recent (`recent.design`) — прежний Godly (`godly.website` → Recent), а godly.design
  — другой сайт; в выборку C — оба, но с разными `source`.
- `urllib.robotparser` для `robots.txt` с `?` в правилах — ложный запрет (Awwwards SOTD) или ложное разрешение.
- Превью или запись чужой работы в папке базы, в артефакте, в отчёте картинкой.
- Ctrl+C в терминале входа убивает окно, и шаги после входа не выполняются (было дважды 24.09) — теперь окно в своей сессии.
- Профиль Chromium открыт Brave (или наоборот) — сессия не читается или ломается профиль.
- Ошибки нейросетей-исполнителей: K3 и Claude подставляют «похожие» картинки со стоков хотлинком вместо референса из
  библиотеки (`kimi 07/03` §6.3); референс превращается в ассет страницы — запрещено решением 4.

## Открытые вопросы и противоречия

- **Dribbble: «поиск» против условий.** 7.1 (scraping), 7.2 (частота), 7.11 (доступ средствами, не предоставленными
  сервисом) и правило API «saving, or storing our data is strictly prohibited» [S1][S2] против решения заказчика — риск
  принят заказчиком; позиция базы — человеческая частота, только внутренняя работа, удаление по просьбе. `[спорно]`
- **Dribbble 7.7 и поле `author`** — имена аккаунтов ради атрибуции; вынесено заказчику (отчёт B). `[спорно]`
- **Dprofile: «поиск» против п. 11.3** — риск принят заказчиком 24.09.2026 16:24 (включая риск блокировки аккаунта и
  «личные некоммерческие цели» п. 11.1, 11.3); позиция базы — человеческая частота, только внутренняя работа. `[спорно]`
- **Behance не проверен вживую**: пройдёт ли безголовый Brave с профилем заказчика JS-челлендж Fastly — неизвестно.
- **Превью выдачи мелкие** (320×240): поднять до 640 можно `device_scale_factor=2` (удвоит байты картинок) — не делали;
  пока крупное превью — через `get` отобранных работ.
- **Порог dHash 6 бит** — гипотеза; на библиотеке из сотен записей проверить долю ложных дублей.
- **Лайки Dribbble** в выдаче не извлекаются (селектор); просмотры — да.
- **Brave против Playwright**: совместимость держится на одинаковой мажорной версии Chromium (153); после автообновления
  Brave — перепроверка (опыт B/04), иначе запасной движок.
- **Сессия Dribbble живёт до 2026-10-08** (`user_session_token`): повторный вход — заказчиком; клиент увидит «вход виден:
  false» и напишет в журнал.
- **Галереи**: проверены офлайн и вживую (B/02, 24.09 17:59–18:05: 173 записи, 0 картинок галерей); пагинация CSSDA и
  SiteInspire вживую не проверялась. **FWA — hold** до решения заказчика: II.4 «you may not create a database in any form
  whatsoever of these web pages» (`GALLERY_HOLD` в клиенте; снятые записи остаются) `[спорно]`.
- **Теги Awwwards — самоотчёт авторов при подаче** (GSAP у 18 из 31 SOTD 25.08–24.09.2026), теги стека Recent — определяет
  площадка; для частот приёмов (H) — только с этой оговоркой, а замер живого сайта (C) главнее. `[данные]`
- **CSSDA запрещает копировать «any content and data»**: даже ссылка + награда — данные CSSDA; держим минимум (сайт,
  название, WOTD с датой), без баллов, описаний, дизайнеров и скриншотов. `[спорно]`
- **Are.na push создаёт блок по URL**: сервер Are.na сам загрузит страницу источника (для Dribbble — его краулер); вариант
  загрузки нашего превью (`/v3/uploads/presign`) кладёт копию чужой работы в Are.na (пусть и private). Выбор — заказчику.
