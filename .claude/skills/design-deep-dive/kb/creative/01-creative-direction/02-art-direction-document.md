## Выжимка для агента

1. **Один документ — один мир сайта**: маркетинг и продукт — два документа; многостраничник — один, страницы различаются
   `treatment` и уровнем. → §1, §7.5 `[практика]`
2. **Порядок**: входы → уровень → концепция → территории → 3–5 направлений → выбор → визуальный язык, движение, эффекты,
   решения, исключения, бюджет, проекции. → §2 `[практика]`
3. **Статус честный**: `approved` — только с подписью заказчика (`approved_by` — роль, `approved_at`); молчание заказчика —
   `proposed` и строка «Going with». → §3, §7.1 `[проверено]`
4. **Уровень → паспорт визуала**: L0 → `boldness: restrained`, L1 → `balanced`, L2 → `bold`; `one_bold_move` — главный приём
   выбранного направления одной строкой. → §4.1 `[проверено]`
5. **Запретная полоса — с причиной**; бренд-акцент в полосе 270–320° не меняют, а ограничивают долей `except_share_max`. →
   §4.1, §5.4 `[проверено]`
6. **Маркеры ai-media**: оставшиеся запреты — `forbidden_markers` (`IMG-Mnn`, `VID-Mnn`), снятые умолчания —
   `lifted_markers` со ссылкой на решение. → §4.1, §5.3 `[проверено]`
7. **Фон кодом → `abstract.policy: code-first`**; `video.tempo` на L0–L1 `still`/`slow`, на L2 `slow`/`medium`; значения
   `fast` в паспорте нет — не выдумывать. → §4.1 `[проверено]`
8. **3d получает роль и среду**: `role_in_story`, `series_style`, `page_background` = фон секции, настроение света,
   бюджет по уровню; физика света и материалов — у 3d. → §4.2 `[практика]`
9. **kimi получает проекцию**: тезис → `design_system.style` и `visual_thesis`, оси → `paper`/`display_style`,
   `motion_system.level` → `decisions.motion.level` ≤ `motion_cap`; `cinematic` — только с готовыми роликами или рендером. →
   §4.3 `[документация]`
10. **site получает `treatment`**: страница — `art_direction_ref` и система движения; секция — уровень ≤ страницы,
    `visual_role`, `motion_level`, эффекты; секции конверсии — L0. → §4.4 `[проверено]`
11. **Пять проверок H на каждый записанный приём** (концепция, бренд, исполнение, эпоха, единственность); `note` — предмет
    или число. → §5.1–5.2 `[практика]`
12. **`use` и `twist` — без единого `fail`** (схема); `twist` называет поворот; для `avoid` хватает одного `fail`. → §5.2
    `[проверено]`
13. **Записывать 2–5 решений**: главный приём, снятые приметы, колею категории; реестр H целиком не копировать. → §5.2
    `[практика]`
14. **Каждый ключ `--allow` — с решением** (`decisions[].k3_allow`), иначе предупреждение. → §5.3 `[проверено]`
15. **Запрет без проверки не работает**: у `avoid` в `bans` — конкретный паттерн и проверка результата (маркер K3,
    детектор H, взгляд K). → §5.4 `[практика]`
16. **Решение принадлежит сайту**: тёплое поле — `twist` у «Лесной обжарки», `avoid` у «Кварца». → §5.4 `[проверено]`
17. **Числа профиля не копировать**: в документе — id `<page_type>@L<n>`, траты и исключения; числа — `budgets.yaml` P
    (страница) и `ambition-levels.yaml` (подача). → §6.1 `[документация: site P v0]`
18. **У каждой траты — `load`**: `eager` — только LCP и то, без чего первый экран не читается; «вау» — `after-lcp`;
    тяжёлое необязательное — `on-interaction`. → §6.2 `[проверено]`
19. **Исключение бюджета** — только слой подачи, с компенсацией в `why` и подписью; LCP, INP, CLS не исключаются; вес
    страницы — механизм site `x-gate-exception`; больше двух исключений — пересмотреть уровень. → §6.3 `[не проверено]` для порога
20. **Версии**: minor — уточнение; major — новое направление, уровень, бренд или мир; прежняя версия → `superseded`. → §7.2
    `[практика]`
21. **Пересмотр не реже раза в 6 месяцев**: `criteria.epoch` каждого `use` и `twist` — по свежему реестру H. → §7.3 `[мнение]`
22. **Смена бренда — major**: пересобрать палитру, шрифты, полосы, решения по бренду, проекции; концепция и территории
    остаются при том же механизме продукта. → §7.4 `[практика]`
23. **Утверждённый паспорт ai-media не правится молча**: новая версия паспорта или второй паспорт мира. → §7.6 `[спорно]`
24. **Перед сдачей — `ad_check.py`**: 0 ошибок схемы, паспорта и правил; предупреждения закрыты решениями. → §8
    `[проверено]`

## 1. Что это и где в конвейере

Формат №5 контракта тройки v2 (§3 п.5), владелец — creative. Один документ на мир сайта (маркетинг и продукт — два
документа, как два паспорта визуала у ai-media 06/01 §1). Документ собирает концепцию, направления и выбор
(`01-concept-and-directions.md`), уровень и профиль (`ambition-levels.yaml`), решения визуального языка (D), систему
движения (E), эффекты по секциям (F), решения о приёмах по критериям H — и **питает** паспорт визуала ai-media, бриф и
паспорт серии 3d, пакет kimi и `treatment` секций плана site.

## 3. Статусы и правила схемы

- `draft` → `proposed` (направления показаны; нужна одна `recommended`) → `approved` (нужны `choice`, `approved_by`,
  `approved_at`, `visual_language`, `motion_system`, `handoff`) → `superseded`.
- Решение `use` или `twist` не может иметь проваленный критерий (схема); остальные правила — `ad_check.py`: пары
  направлений различаются ≥ 2 осями, тёплое или антиква ≤ 1, семейств территорий ≥ 3, буквальных ≤ 1, макроструктуры —
  словарь site, эффекты по уровню (списки из `treatment.v0`), движение ≤ уровня и `motion_cap`, плавная прокрутка только L2,
  `boldness` по уровню, `budget_profile` = тип@уровень, контраст палитр ≥ 4,5:1, акцент в запретной полосе — предупреждение,
  `--allow` без решения — предупреждение `[проверено]`.

## 5. Решения о приёмах и клише

### 5.1. Пять проверок: вопрос и пример

Критерии — H (`PLAN.md`, «Стартовые позиции базы» §2; реестр `cliche-registry.yaml` и детекторы — `08-uniqueness-anti-slop/`,
волна 2) [S2]. Документ записывает **исход проверки для этого сайта**, а не норму: один объект `decisions[]` на приём.

| Критерий (`criteria.*`) | Вопрос | `pass` в примерах | `fail` в примерах |
|---|---|---|---|
| `concept` | связь с идеей одной фразой без «современно», «красиво» | «страница делает то, что делает лампа» — свет теплеет по прокрутке («Кварц») | латте-арт крупным планом «потому что кофе» («Лесная обжарка») |
| `brand` | цвет и материал — из бренда или выбраны здесь с причиной; дефолт генератора (270–320° без бренда, крем `#F4F1EA` + терракота) — провал | тёплая нейтраль из токенов бренда («Лесная обжарка») | кремовый фон при словах заказчика «никакого бежевого» («Кварц») |
| `execution` | измеримо: без бандинга, в бюджете веса и FPS, контраст, reduce, телефон; своя форма, а не пресет инструмента | CSS scroll-driven + `@supports`; без поддержки и при reduce — два кадра («Кварц») | прелоадер прячет LCP и CTA («Лесная обжарка» L2) |
| `epoch` | статус в реестре H: свежий / насыщен с ГГГГ / датирован ГГГГ; насыщенный — только `twist` или малая доза, датированный — только осознанная отсылка | «насыщено с 2025: без терракоты и без антиквы» (тёплое поле) | стоковый интерьер под вуалью («Отвес») |
| `singularity` | один главный приём на сцену; кластер из ≥ 3 клише — провал | «единственное тёплое пятно — фон» | крем + контрастная антиква + терракота вместе (кластер 1, `../ui/11-styles-trends/04-anti-slop-ui.md` §4.1) |

### 5.2. Формат записи

```jsonc
// art-direction v0 · examples/art-direction-forest-roast-l0.json · 2026-09-24 · [проверено]
{ "id": "d-warm-field", "technique": "cliche:warm-paper", "decision": "twist",
  "criteria": {
    "concept":     {"result": "pass", "note": "поле — штукатурка стены из кадра"},
    "brand":       {"result": "pass", "note": "тёплая нейтраль из токенов бренда"},
    "execution":   {"result": "pass", "note": "контраст текста 15:1"},
    "epoch":       {"result": "pass", "note": "насыщено с 2025: без терракоты и без антиквы"},
    "singularity": {"result": "pass", "note": "единственное тёплое пятно — фон"} },
  "why": "Тёплое поле оставлено как свойство кадра, но без двух других признаков кластера (антиква, терракота)",
  "k3_allow": "warm" }
```

- **`decision`**: `use` — все пять `pass` или `na`; `twist` — насыщенный приём с **названным поворотом** (в `why` — что
  меняется против дефолта); `avoid` — достаточно одного `fail`. Схема запрещает `use` и `twist` с `fail`
  (`$defs/decision`, `if/then`) `[проверено: A/01, случай n3]`.
- **`technique`**: `effect:<id>` (`effects.yaml` F; до волны 2 — 29 временных id `treatment.v0.schema.json` `x-effect-ids-v0`),
  `cliche:<id>` (реестр H), `k3:<ключ>` (примета K3) или слово до реестра; слова в id переводит I в v1.
- **`na`** — критерий неприменим (бренд у приёма без цвета и материала). `note` у каждого `pass` и `fail` — предмет или
  число («контраст 15:1», «без антиквы»), иначе проверка не воспроизводится.
- **Что записывать** (2–5 решений на документ; в примерах 2–4): главный приём и пики (`use`); каждую снятую примету K3 или
  умолчание соседа (`twist`/`use` + `k3_allow` или `lifted_markers`); колею категории (`concept.rut`) и приёмы, которые
  исполнитель поставит сам, — `avoid`. Реестр H целиком в документ не копировать.
- В пяти примерах 14 решений: `use` 3 (свет по прокрутке и 3D-просмотр «Кварца», плавная прокрутка L2), `twist` 4 (тёплое
  поле ×2, ряд цифр «Окошка», буквальная линия-отвес), `avoid` 7 (кремовый фон, моно-подписи, латте-арт, прелоадер, вечный
  слоу-мо пара, дашборд в рамке браузера, стоковый интерьер под вуалью) `[проверено]`.

### 5.3. Куда уходит решение

| Решение | Поле `art-direction` | Сосед | Проверка |
|---|---|---|---|
| `avoid` визуального маркера | `exclusions.forbidden_markers` (`IMG-Mnn` — 25, `VID-Mnn` — 18: `../ai-media/01-web-assets-landscape/03-ai-fit-trust-and-slop.md` §5.2–5.3) [S4] | `visual-dna exclusions.forbidden_markers` | подсхема паспорта, A/01 |
| `avoid` оттенка | `exclusions.forbidden_hues` (+ `except_share_max`, если в полосе бренд) | `visual-dna palette.forbidden_hues` | `ad_check`: акцент в полосе — предупреждение |
| `avoid` паттерна | `exclusions.bans` — предметно («рамки браузера и телефона», а не «без ИИ-вида») | kimi `design_system.bans`, Do's and Don'ts `DESIGN.md`; `visual-dna exclusions.banned_words` | K (волна 3) |
| `use`/`twist` приметы K3 | `decisions[].k3_allow` и `exclusions.k3_allow` | `mockup_checks.py --allow`; бриф site `ambition.allow.markers` (C1) | `ad_check`: `--allow` без решения — предупреждение |
| снятие умолчания L0 соседа | `exclusions.lifted_markers[] {marker, decision_ref}` (пример: `LOOK-BG-WARM` ← `d-warm-field`) | ai-media, 3d, ui — только для этого сайта | ссылка на `decisions[].id` |
| `use` эффекта | `effects_by_section`, `treatment.effects` секции | F (`effects.yaml`), E (motion-spec), I | `ad_check`, `c1_check`: эффект ≤ уровня секции |

### 5.4. Правила

- **Запрет без проверки не работает**: «запрет смещает вероятность, но не исключает» (ui 11/04 §4.3) [S9] — у каждого `avoid` в
  `bans` должна быть проверка результата: маркер K3, детектор H или взгляд K `[практика]`.
- **Решение принадлежит сайту**: тёплое поле — `twist` у «Лесной обжарки» (бренд тёплый) и `avoid` у «Кварца» (запрет
  заказчика). Реестр H задаёт условия, документ — исход; копировать решения между сайтами нельзя.
- **Сначала `decisions`, потом эффекты секций**: эффект без решения проходит в `treatment` без концепции.
- **Бренд не меняют ради полосы**: ультрамарин «Кварца» `#2B3BFF` (OKLCH H 268°) у края полосы 270–320° — полоса
  записывается с причиной, акцент остаётся (`01-concept-and-directions.md` §8.3) `[проверено]`.

## 6. Бюджет и исключения

### 6.1. Что документ хранит, а что нет

- **Хранит** id профиля (`ambition.budget_profile` = `budget.profile` = `<page_type>@L<n>`), список крупных трат
  (`budget.spend`) и исключения с подписью (`budget.overrides`). Для многостраничника — профиль главной посадочной; профили
  остальных страниц живут в их `page-plan` (`page.budget_profile`).
- **Не хранит чисел профиля** — одно место правды на слой: «страница» — `../site/07-seo-geo-performance-analytics/budgets.yaml`
  (P; разрешение профиля в 5 шагов: профиль → уровень → исключения типа страницы → «уровень ≤ сайта» и правило лидогенерации →
  доля 3D по 3d, эффекты по creative) [S8]; «подача» — `ambition-levels.yaml` `levels[].budgets.effects` (наш; у P — поле
  `effects_ref`). Слои и числа — `03-ambition-levels.md` §4.
- `ad_check.py` сверяет профиль с `inputs.page_type` и уровнем (`budget_profile ≠ page_type@level` — ошибка, случай n13).

### 6.2. `budget.spend`: на что уходит бюджет

Позиция — всё, что грузится в первом экране, и всё крупнее ≈ 20 КБ: `what`, `kb` (на проводе: br, AVIF), `device`
(`mobile` | `desktop` | `both`), `load` (`eager` | `after-lcp` | `on-visible` | `on-interaction`). `eager` — только
LCP-кандидат и то, без чего первый экран не читается; «вау» — `after-lcp` (CRV-AL-09); тяжёлое необязательное —
`on-interaction` (3D-просмотр по кнопке).

| Пример (профиль) | `eager` | `after-lcp` / `on-visible` | `on-interaction` | Эффекты, десктоп |
|---|---|---|---|---|
| «Лесная обжарка» L0 (`landing-product@L0`) | кадр hero 70 + синемаграф пара 20 | — | — | ≈ 90 КБ |
| «Отвес» (`landing-lead-services@L1`) | фото прораба 90 + SVG линии 4 | — | — | ≈ 94 КБ |
| «Окошко» (`landing-saas@L1`) | скриншот расписания 120 | 3 состояния 240, gsap + ScrollTrigger 40 | — | ≈ 400 КБ |
| «Кварц» (`landing-product@L1`) | фото прототипа 150 | 2 кадра книги 160 | model-viewer 240, GLB 800 | ≈ 550 КБ + 3D по нажатию |
| «Лесная обжарка» L2 (`landing-campaign@L2`) | постер 120 | секвенция 3 500 (тел. 1 500), GLB 600, JS 45 | — | ≈ 4 265 КБ |

Тот же бренд на L2 тратит в ≈ 47 раз больше, чем на L0, а меняются макроструктура, стратегия цвета и движение, не палитра
`[проверено]`. `spend` — заявка, а не замер: фактический вес меряют `page_accept.py` и `page_gates.py` site.

### 6.3. `budget.overrides`: исключение с подписью

```jsonc
// art-direction v0 · examples/art-direction-kvarts.json · 2026-09-24 · [проверено: A/01; вес — 3d A/03: @google/model-viewer 4.3.1 + three 0.183 = 240 КБ br]
"overrides": [{ "metric": "effects.js_3d_kb_br.mobile", "value": 240,
  "why": "model-viewer 4 весит 240 КБ br при потолке 200; грузится только по нажатию «Рассмотреть» и не входит в первый экран",
  "approved_by": "арт-директор (Claude), пример" }]
```

1. **Только слой подачи**: `metric` — путь в `levels[].budgets.effects` (`effects.<метрика>.<устройство>`).
2. **Исходы не исключаются**: LCP, INP, CLS — ворота страницы site; превышение `poor` (4 000 мс, 500 мс, 0,25) — блокер
   SG-PERF без исключений (`page-gates.yaml`) [S8].
3. **Вес страницы — механизм site**: SG-WEIGHT-01…07 имеют серьёзность S — исправить или записать в `page-plan`
   `x-gate-exception {id, why, who}`; `budget.overrides` этого не заменяет.
4. **`why` называет компенсацию** (загрузка по нажатию, вне первого экрана, облегчённый телефон), а не «так красивее».
5. **`approved_by`** — роль: арт-директор (Claude) — в пределах профиля страницы; заказчик — если растёт вес первого
   экрана или меняется уровень.
6. **Больше двух исключений** на документ — признак неверного уровня или приёма: пересмотреть их `[не проверено]`.

Иерархия ворот (контракт тройки v2 §2) [S1]: ворота страницы (site) выше ворот эффектов (creative, K — `effect-gates.yaml`,
волна 3) и ассетов (ai-media, 3d); ворота ассета не блокируют страницу за чужие байты; доля 3D и видео — ворота
соседей (SG-WEIGHT-08, серьёзность D) `[документация: site P v0]`.

## 7. Жизненный цикл

### 7.1. Статусы

| Статус | Когда | Обязательно по схеме | Кто переводит |
|---|---|---|---|
| `draft` | пишутся входы, концепция, территории, направления | `inputs`, `ambition`, `concept`, `territories` 5–9, `directions` 3–5, `lifecycle` | Claude |
| `proposed` | направления показаны заказчику | + одно направление с `recommended: true` | Claude после показа |
| `approved` | выбор подписан | + `choice`, `approved_by`, `approved_at`, `visual_language`, `motion_system`, `handoff` | заказчик подписывает, Claude записывает |
| `superseded` | заменён новой major-версией | у нового документа — `lifecycle.supersedes` | Claude |

- `choice.chosen_by: default` (заказчик молчит, работает рекомендация — строка «Going with») — статус остаётся `proposed`:
  работа идёт, подписи нет (`01-concept-and-directions.md` §7.1).
- «Паспорт собирает машина, утверждает человек» (ai-media 06/01) [S3] — так же здесь: Claude не ставит себе `approved`;
  `approved_by` — роль у заказчика, имя — только с согласия.

### 7.2. Версии

- `lifecycle.version` — `major.minor`, каждая смена — строка `history[] {version, date, change, by}`.
- **minor** — уточнение без смены направления: секция или эффект в пределах уровня, правка токена, новое `avoid`,
  исключение бюджета.
- **major** — новое направление; смена уровня (L1 → L2); смена бренда (новый цвет, шрифт, `brand_status` none → verified);
  новый мир (продукт после маркетинга); смена `page_type` главной страницы. Прежняя версия → `superseded`; подпись не
  переносится.
- Пример «Кварца»: 0.1 — четыре направления показаны; 1.0 — выбрано A с главным приёмом из B (`merged_from: [b]`).

### 7.3. Пересмотр — не реже раза в 6 месяцев

- `review_by` — не позже 6 месяцев от `approved_at` (в примерах — 2027-03-24): реестр H пересматривается раз в 6 месяцев
  (`PLAN.md` §2) [S2], а «способ отличиться» доходит до корпуса генераторов за 12–18 месяцев (ui 11/04 §5) [S9] `[мнение]`.
- При пересмотре: `criteria.epoch` каждого `use` и `twist` — по свежему реестру H; приём стал «насыщен» → `twist` с
  поворотом или замена (minor); направление целиком попало в кластер дефолтов (ui 11/04 §4.1) → новое направление (major);
  поддержка и версии библиотек (scroll-driven, View Transitions, GSAP) — по `stack.yaml` G.

### 7.4. Смена бренда

| Поле | Что сделать | Основание |
|---|---|---|
| `inputs.brand_status`, `brand_expression_mode`, `must_keep` | обновить по брифу (`brand.expression` site-brief) | C1 |
| `visual_language.palette`, `type`, `accent_rule` | пересобрать; шрифт без кириллицы — замена с причиной | kimi 07/03 §4.4 |
| `exclusions.forbidden_hues` | пересчитать: новый акцент в полосе — `except_share_max` | `01-concept-and-directions.md` §8.3 |
| `decisions` | перепроверить критерий `brand` у каждого решения | §5 |
| `handoff.*` | пересобрать проекции; паспорт ai-media — новая версия | §7.6 |
| `concept`, `territories` | оставить, пока механизм продукта тот же | `on_brand_change` в примерах |

Смена бренда — всегда major.

### 7.5. Один документ — один мир

- Маркетинг и продукт — **два документа**, как два паспорта у ai-media (06/01 §1) [S3]; одна система бренда на всех точках контакта — [S13]; общие у них бренд и `must_keep`.
- Многостраничник — один документ на мир: страницы различаются `treatment` и уровнем страницы (`ambition.by_page`);
  внутренняя страница L0 — «сдержанная подача в той же визуальной системе сайта, а не „без дизайна“» (решение 20 site).
- Кампания L2 того же бренда — отдельный документ с той же территорией: «Лесная обжарка» L0 и L2 — одна территория
  «утренний стол», разные направления, макроструктуры (`photographic` → `scroll-story`), стратегии цвета (`restrained` →
  `committed`) и бюджет ≈ ×47 `[проверено]`. Смена уровня без смены мира — major того же документа.

### 7.6. Конфликт с паспортом визуала ai-media

- **Правда по полям §4.1** (характер, `boldness`, `one_bold_move`, запретные полосы и маркеры, `abstract`, `video.tempo`,
  композиция, предметы, материалы) — в `art-direction`; **ремесло кадра** (грейд, свет, камера, баланс белого, приёмка) —
  в паспорте ai-media.
- Утверждённый паспорт не правится молча: если новый `art-direction` ему противоречит (демо ai-media `boldness: restrained`
  против кампании L2), ai-media выпускает новую версию паспорта (`draft` → `approved` человеком) или второй паспорт мира
  кампании.
- Кто разрешает спор двух утверждённых документов — открытый вопрос для ai-media и S `[спорно]`.

## Частые ошибки

1. **Документ-мудборд**: картинки и прилагательные без `decisions`, `exclusions`, `budget` — исполнитель (K3, Claude)
   заполняет пустоты своим дефолтом: «слоп берётся из отсутствия решений» (ui 11/04 §4.2). Лечение: решения по колее и
   обязательные блоки `approved`.
2. **Claude утверждает сам себя** (`approved` без подписи или с `approved_by: "Claude"`). Лечение: схема требует роль и
   дату; молчание заказчика — `proposed`.
3. **Числа профиля скопированы в документ** — через неделю расходятся с `budgets.yaml` P. Лечение: только id профиля.
4. **`--allow` без решения** — снятая примета K3 проходит проверку без концепции. Лечение: `decisions[].k3_allow`.
5. **Запрет словами** («без ИИ-вида», «не шаблонно») — не проверяется ни K3, ни K. Лечение: конкретный паттерн и маркер.
6. **`boldness` паспорта не по уровню**: демо-паспорт `restrained` отдан кампании L2. Лечение: §4.1 и новая версия паспорта.
7. **Сменили бренд — оставили полосы и решения**: новый акцент в запретной полосе, критерий `brand` — по старому цвету.
   Лечение: §7.4, major-версия.
8. **Один документ на маркетинг и продукт** — рабочие экраны получают L2-движение. Лечение: два документа; сервисы —
   нормы ui и ux (движение kimi `none`).
9. **Исключение для исхода** («LCP 3,5 с — ради сцены»). Лечение: исходы не исключаются, «вау» — после LCP (CRV-AL-09).
10. **Траты без `load`** — всё `eager`, первый экран раздут секвенцией. Лечение: `after-lcp`, `on-interaction`.
11. **Эффект раньше решения**: `effect:shader-bg` в `effects_by_section` без строки в `decisions`. Лечение: §5.4.
12. **`cinematic` для K3 без готовых роликов** — исполнитель изображает «кино» анимацией CSS. Лечение: `cinematic` только с
    роликами ai-media или рендером 3d, иначе `expressive` (kimi 07/01 §6.2).
13. **Нет даты пересмотра** — через год на сайте «насыщенный» приём как `use`. Лечение: `review_by` ≤ 6 месяцев.
