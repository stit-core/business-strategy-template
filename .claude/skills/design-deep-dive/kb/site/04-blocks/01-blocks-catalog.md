## 1. Как устроен каталог

### 1.1. Роль, блок, вариант, подача

| Уровень | Что задаёт | Кто владелец | Где |
|---|---|---|---|
| Роль секции (`section_role`) | вопрос посетителя и место в сюжете | C (порядок), B (id) | `../03-page-structure/01-narratives-and-section-order.md` §1.2 |
| Блок (`block`) | назначение и набор слотов (анатомия) | E (v0.9), J (v1) | `blocks.yaml` |
| Вариант (`variants[].id`) | раскладка или состав той же анатомии (split, фон, плакат; сетка, лента) | E | `blocks.yaml` |
| Подача (`treatment`) | композиция, типографика, цвет, движение, эффекты | creative | `block-treatments.yaml` (после C1) |
| Текст слота | формулы, длины, запреты | text | `../../text/04-copy-by-block/copy-slots.yaml` |
| Медиа и 3D слота | код задачи, формат, генерация, доставка | ai-media, 3d | `../../ai-media/01-web-assets-landscape/01-asset-slots-by-page-type.md` §8, `../../3d/12-recipes/` |

- Одна роль — разные блоки: `testimonials` → `testimonial-cards`, `testimonial-single`, `review-aggregate`; один блок —
  разные роли: `stat-strip` → `proof-stats`, `feature-grid` → `benefits`, `audience`, `solution` (поле `serves`).
- 84 блока (v1; v0.9 — 83) в 16 семействах словаря B; этот файл — 7 семейств (шапка и навигация, первый экран, доказательства, ценность,
  оффер, призывы, подвал — 55 блоков), `02` — остальные 28.

### 1.2. Анатомия: элементы, группы, обязательность

- **Элемент** — `{id, slot}`: `id` локальный в блоке (он же `site_slot_id` copy-deck text), `slot` — id словаря (вид —
  text, media, 3d, data, action). **Группа** — повторяемый набор (карточка, шаг, отзыв, пара «вопрос — ответ»): в плане
  элемент группы адресуется `группа.элемент` (`step.title`), экземпляр — `группа-N` (`step-1`). [проверено]
- **Обязательность**: `true` — без элемента блока нет; `if-fact` — только при факте; `if-available` — при наличии у
  заказчика (телефон, медиа); `by-variant` — задаёт вариант (`adds`, `drops`).
- **Длина текстового слота** — класс порядка величины (label ≤ 3 слов · phrase 4–10 · sentence 11–25 · paragraph 26–80 ·
  long > 80), выведенный скриптом из `copy-slots.yaml` text (опыт E/02); точные длины и формулы — только у text.
- **data-элемент** — ссылка на факт нужного вида (`fact_kinds` из `facts.schema.yaml` text, 22 вида); в плане он связывает
  факт с текстом и медиа (`binds`). Блоки с `requires_facts: true` без фактов не строятся.
- **Подпись ссылки секции** — необязательный текстовый элемент `<id ссылки>-label` рядом со ссылкой (`all` →
  `all-label`, `route` → `route-label`): называет, что откроется.
- **Готовое сообщение мессенджера** — необязательный текстовый элемент `messenger-prefill` у блоков с действием: на него
  ссылается `target.prefill` действия с целью-мессенджером.
- **alt** — у каждой информационной картинки (`media_role: informational`) есть парный элемент со слотом `image-alt`:
  в той же группе, у элемента блока — на уровне блока; у большинства блоков он необязательный. Картинка без пары —
  предупреждение BL-14 `site_validate.py`.

### 1.3. Сквозные конвенции (14 правил `conventions` в `blocks.yaml`)

| Правило | Суть | Метка |
|---|---|---|
| Порядок DOM | визуальный порядок секций = DOM на всех экранах; ряды «текст ↔ медиа» меняют сторону колонкой сетки при DOM «текст → медиа» | [стандарт] WCAG 1.3.2, 2.4.3 |
| Заголовки | один H1 (hero или статья); секции — H2; карточки и шаги — H3; уровни не пропускать | [стандарт] WCAG 1.3.1 |
| Ориентиры | `<header>` — шапка сайта; hero и секции — `<section aria-labelledby>` в `<main>`; `<footer>` — подвал | [практика] |
| Логотип | слева и ведёт на главную, в том числе на посадочной без меню | [исследование] ux 02-02 §7 |
| Факты | числа, отзывы, логотипы, цены, люди — только `fact:` | [практика] (контракт §3 п. 10) |
| Повтор призыва | одно действие, несколько мест; второй путь иным стилем | [консенсус] |
| Телефон | свернуть (accordion), в колонку (stack), лентой с видимым краем (rail), перекадрировать (reframe); смысл не убирать | [документация] |
| Две границы | 60rem — раскладка (сетки в колонку, наклоны и обрезки снимаются, липкое отлипает); 40rem — типографика | [мнение вендора] Hallmark |
| Цели касания | ≥ 24 × 24 CSS px или зазор — WCAG 2.2 AA (2.5.8); на таче каждая цель ≥ 44 × 44 зоной нажатия, видимый контрол может быть меньше (2.5.5 AAA) | [стандарт] |
| HTML первым | смысловой текст, цены, условия, ответы, призывы — в исходном HTML | [документация] |
| Пауза | автодвижение > 5 с — пауза; карусели сами не листаются; reduce — статичный кадр | [стандарт] WCAG 2.2.2 |
| LCP | кандидат LCP без `loading=lazy`; 3D и видео — после LCP с постером | [документация] |
| Разнообразие | две секции не повторяют блок в одном варианте (кроме призывов и форм) | [мнение вендора] Hallmark |
| Подача отдельно | визуал и движение — creative; site — анатомия, порядок, ворота | [практика] (контракт §2) |

- Поправка к `../../kimi-research/99-raw/cache/repos/Nutlope__hallmark/skills/hallmark/references/component-cookbook.md`
  («All hit targets ≥ 44 × 44 px below 40 rem (WCAG AA)») для сайта: уровень AA требует 24 × 24 (WCAG 2.2, 2.5.8), 44 × 44 —
  уровень AAA (2.5.5); база держит 44 для главных призывов и полей телефона как практику, а блокер ворот — 24, потому что
  проверки не должны выдавать рекомендацию за норму.
- Поправка к `../../ui/` (`ui_audit.py`, проверка J8 «`<header>` ≤ 120 px») для сайта: порог относится только к
  шапке сайта (`<header>`, landmark banner); hero размечается `<section>` в `<main>` и под порог не попадает, потому что
  hero — первая секция содержания, а не шапка (PLAN, поправка 15).

## 3. Первый экран

### 3.1. Какой hero под задачу

| Задача | Блок и вариант | Когда | Обязательные элементы сверх H1 | Риск |
|---|---|---|---|---|
| Продукт в деле | `hero-media` `product-frame` | SaaS, приложение | подзаголовок, призыв, настоящий скриншот, alt | тяжёлый скриншот — LCP 7,5 с у лидеров |
| Результат | `hero-media` `split` или `before-after` ниже | ремонт, клининг, обучение | фото «после» с разрешением | подлинность (I) |
| Сцена | `hero-media` `background` или `poster-image` | гостиница, кампания L2 | кадр 16:9 + кадр телефона 4:5/9:16 | ложный пол; ИИ-сток |
| Типографика | `hero-text` `statement-cta` | манифест, B2B-услуга без визуала | подзаголовок, призыв | «пусто» при `solution-aware` |
| Плакат-заявление | `hero-text` `marquee` | кампания L2, бренд | признак продолжения, призыв в шапке | политика `poster` — не для ЛУ под рекламу |
| Форма | `hero-form` | лидогенерация с расчётом, вебинар, лист ожидания | форма ≤ 3 видимых полей, согласие, строка «что дальше» | поля без ценности обмена |
| Поле продукта | `hero-input` | ИИ-продукт, анализатор, поиск | поле, результат без входа, призыв после результата | «демо» за регистрацией |
| Число | `hero-stat` | B2B с защищаемой метрикой | число, подпись, источник, словесный H1 | выдуманное число |
| Цитата | `hero-quote` | B2B с сильными отзывами | цитата, подпись, отзыв с разрешением | отзыв без разрешения |
| Письмо | `hero-letter` | основатель, личный бренд | проза ≥ 60 слов, подпись, человек с согласием | политика `poster` |
| Видео | `hero-media` `video-loop` | процесс или настроение | постер, пауза, вертикальный файл телефона | вес; пауза > 5 с |
| 3D | `hero-media` `scene-3d` | товар с неочевидной формой, кампания L2 | постер того же ракурса; призыв работает до 3D | TBT на телефоне |
| Слайдер | `hero-carousel` `manual` | несколько равных реальных акций (лучше сетка) | постоянный H1, ручное листание, пауза | второй слайд не видят |

Источник выбора — C 03 §3.1; LCP по типу hero у 43 лидеров: типографика 2,3 с, фото 3,3 с, ИИ-картинка 4,6 с, скриншот
7,5 с, коллаж 12,5 с (замер ai-media) [данные].

### 3.2. Правила анатомии hero

- **H1 — словесный заголовок с категорией** (или категория в надзаголовке рядом): слоган без категории — у 5 из 30 живых
  страниц [проверено]; число (`hero-stat`), цитата (`hero-quote`), образ — рядом с H1. [практика]
- **Базовые элементы** (C 03 §3.1): надзаголовок (по желанию), заголовок H1, подзаголовок, подпись главного призыва, второй
  путь (по желанию), строка у кнопки (что будет, снятие риска), микродоказательство из факта, медиа десктопа и телефона.
  Ядро первого экрана ≤ 40 слов (text `hero-core`). [проверено: text D]
- **Политика первого экрана — поле плана** (`offer-cta`, `offer-cta-header`, `poster`), вариант hero её подтверждает:
  `marquee`, `poster-image`, `letter` — только `poster`; при `paid-search` и у ЛУ — всегда `offer-cta`. [практика: C 03 §2.2]
- **LCP**: у `split` и `product-frame` кандидат — картинка (eager, `fetchpriority=high`, `width`/`height`); у `background`
  под прозрачной шапкой и у шейдера — H1 (быстрый шрифт — P). 3D и видео — после LCP, с постером того же ракурса.
  [документация: web.dev; данные: ai-media 01/01 §2.2]
- Поправка к `../../3d/01-web-3d-landscape/02-when-3d-budgets-loading.md` §1.3 («прайсинг и лиды — 3D вредит»)
  для сайта: 3D в первом экране лидогенерации допустим, если LCP — H1 или постер, а призыв и форма работают до загрузки 3D;
  в блоках тарифов и форм 3D не ставится, потому что правило уровня страницы отсекает законный приём (PLAN, поправка 22).

### 3.3. Спорная гранулярность (ответ на открытый вопрос B)

- **`hero-letter` — отдельный id**: набор слотов другой (проза ≥ 60 слов, подпись автора, `person-ref`, призыв после текста).
- **`hero-carousel` — отдельный id со статусом «не для главного сообщения»**: другой набор (повторяемые слайды); вариант
  один — `manual`; главное предложение — в постоянном H1 вне слайдов. [консенсус: C 03 §3.1]
- **`hero-media` — один id на семь вариантов** (split, фон, плакат, продукт в рамке, видео, 3D, иллюстрация): набор слотов
  общий, меняются раскладка и вид главного медиа (правило B: раскладка — вариант).

### 3.4. Телефон

- Свой кадр 4:5 (1080×1350) или 9:16 (1080×1920) — так у 8 из 10 измеренных сайтов [данные: ai-media]; видео — только
  вертикальный файл; при `save-data` — постер. На 60rem обрезка «за край экрана» (H7) и наклон мокапа (H8) снимаются.
- Выше черты первого экрана (экран − шапка − липкая панель − safe area − баннер cookie): заголовок, призыв или начало формы,
  у ЛУ — цена «от» и телефон. C/02: баннер или окно перекрывали первый экран у 15 из 27 страниц. [проверено]

### 4.1. Логотипы и числа

- Логотип клиента — файл владельца с разрешением, не генерируется (ai-media `01/01` §2.1: ❌); меньше 4 — сильнее один
  кейс или отзыв. Бегущая строка логотипов — вариант подачи при паузе (WCAG 2.2.2), а не запрет (поправка B к kimi `05-03 §5.3`).
- Ряд цифр — 2–5 чисел, у каждого подпись объекта счёта и источник с датой; анимированный счётчик показывает в HTML
  конечное значение (иначе краулер и читалка видят 0). «Выдуманное большое число хуже никакого» (Hallmark 04). [практика]

### 4.2. Отзывы и рейтинги

- Отзывы на сайте читают, но подозревают отбор «лучших» и сверяют со сторонними площадками: за 20 сессий слово «reviews»
  прозвучало более 40 раз [исследование: NN/g 2019, n = 20] → честные отзывы + рейтинг площадки с датой и ссылкой
  (`review-aggregate`). Разметка отзывов о себе на своём сайте — решение H (правила поисковиков).
- Цитата — дословно из `facts.yaml` (`verbatim`), подпись — в объёме разрешения (`permission.shows`); ИИ-лица и
  «Анна, 34 года» — запрещено (решение заказчика 15; I). Видеоотзыв — с субтитрами (WCAG 1.2.2; I).
- Карусель отзывов не листается сама; лента на телефоне — с видимым краем и кнопками.

### 4.3. Кейсы, награды, документы

- Кейс: результат числом с базой и сроком, **рядом — типичный результат** (text 02/03 §5.4): в примере «Окошко» — 14 % → 6 %
  у одного барбершопа и среднее по 212 салонам рядом (`04-blocks/examples/page-plan-saas-okoshko.yaml#keis`).
- Награда — признание жюри `[награда]`, не доказательство конверсии; документы — номер и срок текстом, скан — превью.

### 5.1. Против шаблона

- «Hero → 3 фичи → отзывы → тарифы → CTA» — у 1 из 30 живых страниц; ИИ-страницы 2026 ушли к новому шаблону «ряд чисел ↔
  фичи» [проверено]. Правило: блок ценности выбирается по вопросу секции и по тому, какие доказательства и кадры есть;
  на странице две секции не повторяют `feature-grid` в одном варианте. [мнение вендора: Hallmark] 
- SaaS: продукт показывают `product-showcase`, `feature-alternating` (`claim-proof`), `feature-tabs`; карточки с
  иконками — дополнение, не показ. Иконки — декоративные (alt пустой), без «искр» и абстракций. [практика]

### 5.2. Раскладка и доступность

- Ряды «текст ↔ медиа»: DOM во всех рядах «текст → медиа», сторона меняется колонкой сетки; на телефоне медиа во всех рядах
  с одной стороны текста. Вкладки — WAI-ARIA tabs (стрелки, `role=tablist`), содержимое всех вкладок в HTML; липкая колонка
  (Hallmark F2) не перехватывает прокрутку и на 60rem становится линейными парами «текст + кадр».
- Бенто: 6/4 колонки → 2 (крупные плитки на 2) → 1 колонка по важности; текст в картинки плиток не запекать.

| `pricing-cards` | SaaS и подписки с самообслуживанием | > 4 тарифов (нужно сравнение); «Contact sales» на всех | имя, для кого, цена, условия, состав одинаковым набором, призыв |
| `pricing-table` | прайс услуг; цены типовых случаев | цен нет в фактах | строка «услуга — цена» с единицей, что входит, дата прайса |

| `comparison-table` | `solution-aware`: подходы; страница сравнения; 3+ тарифа | непроверенные факты о конкуренте | до 5 колонок, признаки строками, дата и источник |
| `offer-details` | что именно входит — рано | «всё включено» без списка | входит / не входит |
| `key-facts` | курс, мероприятие, товар: 2–6 параметров | доказательство числами | `<dl>` параметр — значение |
| `promo-offer` | реальная акция с датой или живым остатком | акции нет | условия, срок, призыв |
| `guarantee` | высокий воспринимаемый риск, гарантия в договоре | «100 % результат» | условия, как воспользоваться, документ |

### 6.1. Цена рано и честно

- Цена — информационная потребность № 1, в том числе у B2B; без цены участники уходили к конкурентам, скрытая цена читается
  как уклонение [исследование: NN/g 2013]. У ЛУ цена — 2–4-я секция (C/01: медиана позиции 0,31) [проверено].
- Нет точной цены — «от» с условиями, диапазон или **цены типовых случаев** (`pricing-table` `typical-scenarios`: «двушка
  54 м² — от …»). У SaaS с продажей через менеджера — «от» или калькулятор, а не «по запросу» на всех тарифах. [практика]
- Тарифы: не больше 2 рядом на телефоне; обе цены (месяц и год) в HTML; «Популярный» — только с основанием (доля выбора —
  факт); условия отмены и возврата — рядом (I). Механика тарифов — `../../ux/04-components-patterns/09-settings-permissions-admin.md` §10.

### 6.2. Калькулятор или типовые случаи

- Калькулятор — при 1–3 понятных параметрах (площадь, комнаты, мастера; 4–5 — с причиной) и формуле заказчика; итог — на странице без
  контакта, со строкой об ориентировочности. Сложнее — цены типовых случаев: «most pricing tools proved complex,
  time-consuming, and error prone», их заполняют немногие вовлечённые [исследование: NN/g 2013]. Механика, поля и порог — F 01 §5.4 [практика].

### 6.3. Сравнение

- Таблица сравнения — для выбора из немногих вариантов по нескольким признакам: статичная — до 5 вариантов; колонки —
  варианты, строки — признаки, подписи строк слева; короткие значения без «игры слов»; липкие заголовки колонок на длинных
  таблицах; «показать только различия» и краткая таблица + подробная отдельно [практика: NN/g 2024].
- «Главная проблема сравнительных таблиц — содержание, а не дизайн»: пустые и несогласованные значения делают таблицу
  бесполезной [практика: NN/g 2024] → каждая строка — факт или вывод из факта; о конкуренте — только проверяемое с
  датой (text: класс утверждения comparison — legal required; I).
- Телефон: 2 колонки (мы и выбранная альтернатива) + переключатель, или карточки по варианту — хуже для сравнения, но лучше
  горизонтальной прокрутки. [практика: NN/g 2024] Сравнение таблиц в продукте — `../../ux/04-components-patterns/01-data-tables.md` §1.4.
- Не нужна: для дешёвых, простых, не исключающих друг друга или уникальных предметов. [практика: NN/g 2024]

### 6.4. Акции и срочность

- Акция — только с `valid.until` факта или живым остатком из системы заказчика; таймер без сброса и с датой текстом рядом;
  «старая» цена — только реальная цена прошлого периода (I; text `price-old`). Лживые таймеры — 157 из 393 в выборке ux
  (`../../ux/06-feedback-states-motion/04-dark-patterns-and-ethics.md`). В примере «Отвес» акция живёт в строке
  объявления с условием снятия после даты.

### 6.5. Гарантия и снятие риска

- Условия текстом (на что, срок, что будет, где записано), ссылка на договор; рядом с ценой или перед формой при высоком
  риске (C 01 §3.2). Нарисованные печати и «100 % гарантия результата» — нет. Механика снятия риска — F.

## 7. Призывы

### 7.1. `cta-band` и финал

- Промежуточная полоса — после довода (цена, доказательство), на страницах длиннее 3 экранов; у живых страниц промежуточная
  форма или полоса — 14 из 30, финальный призыв — 12 из 30 [проверено]. Финал — повтор главного обещания и второй путь
  для не готовых (материал, пример сметы, вопрос в поддержку).
- Финал ЛУ — форма (`lead-form` вариант `final`) или полоса с каналами; SaaS — полоса с пробным периодом и строкой «без
  карты». Две равные кнопки разных действий — нет.

### 7.2. `sticky-cta` и `capture-popup`

- Липкая панель — телефон, страница > 3 экранов, одно главное действие; ≤ 72 px + safe area; прячется при видимом призыве
  hero, форме, финале и клавиатуре; `scroll-padding-bottom` (WCAG 2.4.11); во встроенных браузерах соцсетей — запас снизу.
  [практика: C 03 §4.3; исследование: ux 09-04 §4.14]
- Окно захвата: по умолчанию выключено (решение заказчика 15); допустимо только по нажатию посетителя (`on-click`) как
  модальный `<dialog>`. Google: навязчивые окна мешают людям и поиску; вместо полноэкранных — баннеры на малую часть экрана;
  не закрывать всю страницу, не уводить на отдельную страницу за вводом [документация: Google Search Central, снимок
  2026-09-24]. Условия автопоказа — F с доказательствами, решение — заказчик.

## 8. Подвал

- Утилитарные ссылки (контакты, политика ПД, условия) — в подвале каждой страницы, даже если они есть наверху: за контактами
  идут прямо в подвал [исследование: NN/g 2019]; реквизиты продавца и документы согласия — требования I.
- Варианты: `minimal` (лендинг: реквизиты, правовые ссылки, контакты одной-двумя строками — Hallmark Ft2, Ft1), `site`
  (многостраничник: навигация по разделам — G; карта сайта целиком — только при ≈ 25 страницах и меньше, иначе ссылка на
  карту), `statement` (кампания), `newsletter-first` (контентный сайт). Четыре колонки «по привычке» — отпечаток ИИ (Ft3
  Hallmark) [мнение вендора].
- Ошибки подвала по NN/g: больше двух уровней иерархии, неясные ярлыки («Ресурсы» вместо «Контакты»), «свалка» ссылок, мелкий
  нечитаемый шрифт, **скрытый или свёрнутый подвал** [исследование: NN/g 2019] → на телефоне подвал — список, реквизиты и
  правовые ссылки видимы без раскрытия; аккордеон групп ссылок — только у подвала многостраничника [спорно].
- Награды и отзывы в подвале — для малоизвестных компаний, «слишком много — красный флаг» [исследование: NN/g 2019].

## Частые ошибки

- **Шаблонный порядок и шаблонный хвост**: «фичи → 3 отзыва → 3 тарифа → лозунг» или «ряд чисел ↔ фичи» по всей странице.
- **Выдуманные доказательства**: «10 000+ клиентов», «Нам доверяют» с чужими логотипами, ИИ-лица в отзывах и команде,
  рейтинг без площадки и даты, «старая» цена без периода.
- **Hero без категории**: слоган вместо «что это»; число или цитата вместо H1; анимированный по буквам заголовок.
- **Ложный пол**: hero 100vh с медиа и без признака продолжения; на телефоне — картинка без текста и призыва.
- **Скриншот интерфейса из ИИ** или мокап несуществующего экрана в SaaS.
- **Три одинаковые карточки как показ продукта**; «шаблонный бенто» из иконок; ряды «медиа → текст» в DOM.
- **Цена в конце у лидогенерации** или «по запросу» при известной цене «от»; сложный калькулятор вместо типовых случаев.
- **Сравнение «у нас всё ✓, у них всё ✗»**, таблица картинкой, горизонтальная прокрутка на телефоне без подсказки.
- **Таймер, который сбрасывается**; «только сегодня» каждый день.
- **Меню сайта, блог и соцсети в шапке посадочной под рекламу**; логотип по центру без ссылки на главную.
- **Липкая шапка + липкая панель + мессенджеры + баннер cookie** закрывают треть экрана и поле в фокусе.
- **Подвал без реквизитов и политики**, свёрнутый аккордеоном; четыре колонки подвала на одностраничном лендинге.
- **Генераторы и агенты**: `<header>` вокруг hero, два H1, `100vh` и всё по центру, карусель с автопрокруткой, текст в
  картинках, `loading=lazy` у кандидата LCP.

## Чек-лист

- [ ] У каждой секции — блок из `blocks.yaml` и вариант; блок отвечает на вопрос роли?
- [ ] Блоки доказательств, акций, гарантий и тарифов опираются на `fact:`; нет факта — блока нет?
- [ ] Главный призыв повторяется, второй путь оформлен иначе; шапка посадочной под рекламу — `landing-minimal`?
- [ ] Hero выбран по задаче; H1 словесный с категорией; ядро ≤ 40 слов; кандидат LCP без lazy?
- [ ] У hero свой кадр телефона; заголовок и призыв выше черты с баннером cookie?
- [ ] Числа — с подписью, источником и датой; отзывы дословно с разрешением; рейтинг — с площадкой, датой и ссылкой?
- [ ] Показ продукта SaaS — настоящими скриншотами, а не одними карточками?
- [ ] Цена у ЛУ — во 2–4-й секции; калькулятор — не больше 3 параметров (4–5 — с причиной), иначе цены типовых случаев?
- [ ] Таблица сравнения — до 5 колонок, признаки строками, согласованные значения, дата и источник?
- [ ] Акция — с реальной датой; «старая» цена — реальная?
- [ ] Липкие слои ≤ 20 % экрана телефона; `scroll-padding`; липкая панель прячется у формы и клавиатуры?
- [ ] Подвал: реквизиты, политика ПД, контакты — видимы без раскрытия на всех страницах?
- [ ] `<header>` только у шапки; hero и секции — `<section>` в `<main>`; один H1; DOM = визуальный порядок?
- [ ] Две секции не повторяют один блок в одном варианте (кроме призывов и форм)?

## Открытые вопросы и противоречия

1. **Раскладку по тексту не отличить** (E/04: 43 % секций живых страниц — до семейства): частоты вариантов hero и сеток
   ценности даст только выборка M с кадрами (`page_anatomy.py`), `pages.csv` ещё не выпущен на 14:30.
2. **Меню на посадочной** — данные «за» только кейсы; NN/g требует явного пути на главную для сайтов [спорно] (C 02 §2.3).
3. **Свёрнутый подвал на телефоне**: NN/g (2019, десктоп) против практики мобильных аккордеонов — база: реквизиты и правовые
   ссылки видимы всегда, группы ссылок многостраничника — по решению G [спорно].
4. **Калькулятор против типовых цен**: NN/g 2013 (B2B, старое наблюдение) против практики квиз-калькуляторов рынка РФ
   (C/01: у 3 из 11 ЛУ расчёт в hero) — база: ≤ 3 параметров, 4–5 — с причиной (F 01 §5.4); проверка — A/B в живой фазе (P).
5. **Цели касания**: Hallmark пишет 44 px как AA — ошибка источника; ворота site — 24 px (AA), 44 — практика (K решит профиль).
6. **Сравнение с конкурентом по имени** — право (I) и формулировки (text); база по умолчанию сравнивает подходы.
7. **Эффект блоков на конверсию не измерен** ни одним источником с методикой — частоты C/01 и E/04 не нормы; проверка —
   A/B вариантов блоков в живой фазе (P).
