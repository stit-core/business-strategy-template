## Выжимка для агента

1. **Смысл страницы — в HTML ответа сервера**: H1, текст, цены, условия, главный CTA, навигация `<a href>`, canonical,
   meta robots, OG и JSON-LD приходят без JS (SSR, SSG или пререндер); JS улучшает, но не приносит смысл. `[документация]` +
   `[проверено]` → §1.3
2. **Несжатый HTML ≤ 2 МБ, H1 и текст — в начале документа**: Googlebot читает первые 2 МБ каждого файла; без base64-картинок
   и мегабайтных инлайн-SVG и JSON. `[документация]` + `[проверено: H/01 — у двух страниц Яндекса H1 на 2,4 МБ]` → §1.1
3. **Для Яндекса SSR обязателен**: рендеринг JS — бета «на усмотрение робота»; с SSR ставь «не выполнять»; текст только в
   `<noscript>` Яндекс не индексирует. `[документация]` → §1.2
4. **Один HTML людям и ботам**: без dynamic rendering («workaround… not a recommended solution») и без подмены по UA

5. **Коды ответа честные**: индексируемая — 200; несуществующий URL — 404 (не 200 и не редирект на главную); удалённая —
   404 или 410; переезд — 301. `[документация]` → §1.5

## 1. Как поисковик получает страницу

### 1.1. Google: обход → очередь рендера → индекс

- Три фазы: crawling, rendering, indexing; страницы с кодом 200 встают в очередь рендера (headless Chromium) — «may stay on
  this queue for a few seconds, but it can take longer» [S1]. Ссылки Google находит только в `<a href>`; маршруты `#/…` —
  нет [S1]. `[документация]`
- «server-side or pre-rendering is still a great idea… **not all bots can run JavaScript**» [S1]; Google рендерит JS «for
  multiple years now» (журнал изменений 2026-03-04 [S13]) — для Google JS не катастрофа, для остальных ботов — да (§1.3,
  `02-geo-ai-search.md` §3). `[документация]`
- **Предел загрузки**: Googlebot для Поиска читает первые **2 МБ** поддерживаемого файла и 64 МБ PDF; каждый CSS и JS —
  отдельно с тем же пределом; считается по несжатым данным; остальное отбрасывается [S2] (обн. 2026-02-03). Прочие краулеры
  Google — по умолчанию 15 МБ [S3]. В подкасте Google звучало 15 МБ — документация точнее `[V:kype1JQbrks 08:18]`.
  `[документация]`
- **Индексация по мобильной версии**: большинство запросов Googlebot — смартфон [S2]; мобильная версия — тот же основной
  контент, те же robots meta, разметка и метаданные; аккордеоны и табы — можно; **«Don't lazy-load primary content upon user
  interaction»** — контент, который грузится по клику, свайпу или вводу, Google не увидит [S46]. `[документация]`
- Кэш: WRS может игнорировать заголовки кэша → отпечаток содержимого в имени файла (`main.2bb85551.js`) [S1].

### 1.2. Яндекс: SSR по умолчанию, рендеринг — бета

- Вебмастер → «Индексирование → Рендеринг страниц JavaScript β»: по умолчанию «На усмотрение робота Яндекса» — робот «может
  оценить качество и полноту контента на странице с JavaScript и без и загрузить ту, которая может оказаться более
  полезной»; **«Запретите рендеринг, если на сайте реализован SSR… или пререндеринг»**; рендеринг нагружает сервер [S24].
  Ресурсы для рендера грузит `YandexRenderResourcesBot` (robots.txt для ресурсов игнорирует, если страница доступна) [S23].
- Ожидание контента — `window.YandexRotorSettings` (`WaiterEnabled`, `IsLoaded`, `IsError`, `FailOnTimeout`,
  `NoJsRedirectsToMain`) [S24] — костыль для CSR, не план для генератора.
- **`<noscript>` Яндекс не индексирует** («как и `noindex`, запрещает индексирование») [S25] → фолбэк «без JS» — обычный HTML,
  а не `<noscript>`; `<noindex>…</noindex>` прячет часть текста только от Яндекса [S25].
- Региональные версии по IP: «Робот Яндекса обходит сайт с IP-адреса одного конкретного региона… часть содержимого не будет
  проиндексирована» → любая страница доступна роботу независимо от IP [S29]. `[документация]`

### 1.3. Что обязано быть в HTML ответа сервера

| Элемент | Google | Яндекс | ИИ-боты (OpenAI, Anthropic, Perplexity) | Правило |
|---|---|---|---|---|
| H1, основной текст, цены, условия | увидит после рендера (с задержкой) | только при бета-рендеринге | не увидят (JS не исполняют — `02` §3) | сервером; поле плана `seo.ssr_required: true` |
| Главный CTA и форма (текст кнопки, поля) | после рендера | как выше | не увидят | сервером; поведение — JS |
| Навигация шапки и подвала | только `<a href>` | так же | так же | `<a href="/путь">` на каждой странице |
| canonical, meta robots | JS может вставить, но не менять | вставку JS не гарантирует | нет | в `<head>` сырого HTML |
| JSON-LD | прочтёт и вставленный JS | `[спорно]` | нет | в сыром HTML; 2 % сайтов вставляют JS'ом [S36] |
| OG-теги | — | — | превью мессенджеров JS не исполняют | в `<head>`, в первых 1 МБ [S35] |

Замер: у 9 % страниц корпуса нет H1 в сыром HTML, у 8 % < 50 слов (оболочки SPA и антибот-заглушки); у M H1 в сыром HTML — 54
из 67, у 8 из 33 страниц с ценами часть цен появляется только после JS `[проверено: H/01; данные M]`. Web
Almanac 2025: медиана разницы «отрисовано против сырого» — 18 % слов на десктопе, 16 % на телефоне [S36] `[данные]`. У
многостраничников G/01 подменю в исходном HTML — у 4 из 18, панелей мега-меню — ни у одного, телефон stamus — только в браузере
[S49] `[проверено]`.

### 1.4. SSR, SSG, CSR, пререндер — что выбирать

| Ситуация | Решение | Почему |
|---|---|---|
| Лендинг, сайт услуг, маркетинговый сайт SaaS | SSG (статическая сборка) или SSR; Tilda и подобные конструкторы — серверный HTML по умолчанию | весь смысл в HTML, TTFB мал, нет двух версий |
| Страница с частыми изменениями цен и наличия | SSR или SSG с перестроением по событию + IndexNow | свежесть без JS |
| React/Vue-SPA уже есть | пререндер маршрутов при сборке (одинаковый HTML всем) | не dynamic rendering |
| Эффекты, 3D, скролл-сцены | текст сцен — HTML в разметке, WebGL и canvas — поверх | `../../3d/01-web-3d-landscape/02-when-3d-budgets-loading.md §6.1` |
| Подстановка заголовка по UTM | вариант выбирается на сервере до первой отрисовки из белого списка; вариант по умолчанию — полноценный | `../03-page-structure/02-length-goal-message-match.md §3.3`; ИИ-боты увидят умолчание |

- **Не делать**: отдельный HTML для ботов (dynamic rendering — «workaround and not a recommended solution» [S47]); подмену
  текста по UA — это клоакинг [S11]; «LLM-версию» страницы в Markdown — двойная работа, ломается незаметно
  `[V:Vkn3R6DUJ34 14:19–15:07]`. `[документация]`

### 1.5. Доступ: коды ответа, TLS, антибот, CDN

- **Коды**: 404 для несуществующего, 401 за логином; soft 404 в SPA — JS-редирект на URL с серверным 404 или `noindex` [S1];
  Bing: «Use 302 redirects only for very short-term changes (less than 2 days)» [S33]. Страница 404 обязана отдавать HTTP 404
  (вопрос E) — `head-kit.yaml` `hk-access-404`; мягкая 404 — у 2 из 19 многостраничников G/01 [S49]; для SPA — серверный 404
  или JS-редирект на URL с серверным 404 [S50]. Ботам не отдавать 5xx «чтобы закрыть» раздел — Google снизит обход всего
  сайта [S50]. `[документация]`
- **Антибот-заглушки**: на корпусе клиент без JS получал JS-проверку (alfabank.ru — `<js-challenge-loader>` и
  `noscript`-редирект), пустую страницу Qrator с `noindex, nofollow` в meta и `X-Robots-Tag` (t-j.ru), заглушку DDoS-Guard
  (invitro.ru) `[проверено]`. Поисковых ботов такие системы обычно пускают по спискам; ИИ-боты без JS получат заглушку,
  если их нет в списке `[не проверено]`. Правило: белый список по IP-спискам из `crawlers.yaml` (`ip_list_url`) и обратному DNS
  (Google, Яндекс, Apple, Common Crawl). `[практика]`
- **Cloudflare**: managed robots.txt дописывает `Disallow` для Amazonbot, Applebot-Extended, Bytespider, CCBot, ClaudeBot,
  Google-Extended, GPTBot, meta-externalagent и строку `Content-signal: search=yes, ai-train=no` [S34]; **с 2026-09-15 у новых
  доменов Training и Agent по умолчанию блокируются на страницах с рекламой, а многоцелевые Googlebot, Applebot, bingbot
  блокируются у тех, кто запретил Training** [S34]. Проверка — «Проверка URL» в Search Console после любого изменения
  настроек бота. `[документация]` (поставщик инфраструктуры о своём продукте)
- **TLS**: tbank.ru, tochka.com, alfabank.ru с российского адреса отдают сертификат «Russian Trusted Sub CA»; клиент без
  этого корня (Python, Chromium у M) не устанавливает соединение `[проверено]`. Правило: общепризнанный сертификат —
  основной, НУЦ — дополнительный (если нужен). Что получают боты с зарубежных адресов — проверить в живой фазе. `[не проверено]`

## 2. Управление обходом и индексацией

### 2.1. robots.txt: RFC 9309, Google и Яндекс

| Вопрос | RFC 9309 [S5] | Google [S4] | Яндекс [S23] |
|---|---|---|---|
| Выбор группы | токен без учёта регистра; несколько групп — сливаются; нет своей → `*` | «most specific user agent»; `googlebot/1.2` ≡ `googlebot`; группа агента и `*` не сливаются | строки с подстрокой `Yandex` или `*`; есть `Yandex` → `*` не учитывается; есть группа робота → `Yandex` и `*` не учитываются |
| Кто игнорирует `*` | — | AdsBot-Google, AdsBot-Google-Mobile, Mediapartners-Google | YandexAdditional, YaDirectFetcher, YandexMetrika, YandexMobileBot и др. («Учитывает общие правила — Нет») |
| Конфликт allow/disallow | длиннее побеждает; равные — allow | так же | — |
| Поля | user-agent, allow, disallow; прочие — «other records» | только user-agent, allow, disallow, sitemap; **crawl-delay не поддерживается** | + `Clean-param` (параметры, межсекционная); `Crawl-delay` не учитывает с 2018-02-22 — скорость задаётся в Вебмастере [S51] |
| 4xx | «may access any resources» | как нет файла (кроме 429) | — |
| 5xx, сеть | полный запрет | 12 ч без обхода, до 30 дней старая копия, после — как без файла, если сайт доступен | — |
| Размер, кэш | ≥ 500 KiB, кэш ≤ 24 ч | 500 KiB, кэш до 24 ч (`max-age` меняет) | — |

- Google распознаёт, но **не исполняет** 12 полей: `clean-param`, `content-signal`, `content-usage`, `crawl-delay`, `domain`,
  `host`, `noarchive`, `nofollow`, `noindex`, `request-rate`, `revisit-after`, `visit-time` (`kUnsupportedTags`,
  google/robotstxt, коммит 4af32e5 от 2026-02-19 [S6]; `[V:DchuJS7JWvk 03:20]`) → `noindex` — метатегом, не строкой
  robots.txt. `[документация]`
- HTML вместо robots.txt (заглушка SPA) Google всё равно разбирает, прочие парсеры сбиваются `[V:DchuJS7JWvk 22:11]` —
  aspro.cloud отдаёт HTML на `/robots.txt` `[проверено]`. Web Almanac 2025: 200 — 84,9 %, 404 — 13,3 %, 5xx — 0,1 %,
  > 500 КБ — 0,1 % сайтов [S36] `[данные]`.
- **Не закрывай** CSS, JS, картинки и API/XHR, нужные для отрисовки: «Google Search won't render JavaScript from blocked files» [S1],
  «that includes API calls that are necessary to load content» [S50];
  Applebot и Яндекс тоже рендерят. **Disallow ≠ noindex**: запрещённый URL «may still index… without a snippet» [S4].
- Шаблон и политики для ИИ-ботов — `crawlers.yaml` (`policies`, `robots_txt_rules`); выбор политики — поле брифа
  `search.ai_bots_policy`.
- **Бесконечные пространства** (поиск по сайту, календари, фильтры, сортировки): новый сайт — одно `Disallow` на шаблон
  (`/search?`), категории и метки — открыты; URL уже в индексе — сначала `noindex` при открытом обходе, после выпадения —
  `Disallow`; вместе на одном URL они не работают [S50] (`crawlers.yaml` `rt-infinite-spaces`). `[документация]`

### 2.2. meta robots и X-Robots-Tag

- Google: `name="robots"` или только `googlebot`, `googlebot-news` (прочие имена игнорирует); правила `noindex`, `nofollow`,
  `none`, `nosnippet`, `max-snippet`, `max-image-preview`, `max-video-preview`, `notranslate`, `noimageindex`,
  `unavailable_after`, `indexifembedded`; `noarchive`, `nocache` не используются; при конфликте — «the more restrictive rule
  applies»; **meta robots в `<body>` тоже исполняется** [S7]. `nosnippet` и `max-snippet` ограничивают и ИИ-функции (`02` §2).
- Яндекс: `noindex`, `nofollow`, `none`, `noarchive`, `index|follow|archive`, `all`; **«Разрешающие директивы имеют приоритет
  в сочетании с запрещающими»** (пример: `all` + `noindex, follow` → индексирует) [S26] — противоположно Google. Правило: на
  странице одна директива без противоречий. `[документация]`
- X-Robots-Tag — для PDF и не-HTML; можно с префиксом агента (`googlebot: nofollow`) [S7]. Если URL закрыт в robots.txt,
  meta и заголовок не прочтут ни Google, ни Яндекс [S7], [S26].
- Web Almanac 2025: meta robots на 47 % страниц, чаще всего лишнее `index, follow` (Yoast по умолчанию); X-Robots-Tag — 0,6 %
  [S36]. Генератор не пишет `index, follow` (это умолчание).

### 2.3. Canonical и параметры

- Google: редирект и `rel="canonical"` — сильные сигналы, sitemap — слабый; не robots.txt, не URL removal, не разные canonical
  разными способами, не фрагмент; само-ссылающийся canonical; ссылки внутри сайта — на канонический URL; canonical
  принимается только в `<head>`; абсолютный URL; JS не меняет canonical из HTML [S8]. `[документация]`
- Яндекс: canonical — рекомендация; **«Указывайте канонический адрес в пределах одного домена»**; при смене HTTP на HTTPS
  canonical «больше не поддерживается» — только редирект [S27]. Служебные параметры (`yclid`, `gclid`, `openstat`, сессии) — `Clean-param`
  в robots.txt; `utm_*` и `ysclid` Яндекс, по справке, удаляет сам [S51] (Google строку не исполняет [S6] — ему canonical).
- Яндекс, «Настройка GET-параметров» (Вебмастер → Индексирование): параметры, которые нашёл робот, с отметкой «учитывать
  или нет» — тот же выбор, что `Clean-param`, в кабинете; найденные роботом — на весь сайт, добавленные вручную — на сайт,
  главную или раздел; вступает в силу в течение недели; при расхождении с robots.txt робот выполняет правило, которое
  запрещает индексировать адрес с параметром [S53]. `[документация]` Правило параметров живёт в `Clean-param` robots.txt —
  в коде сайта, одно на все среды; кабинет — сверка: служебный параметр, который нашёл робот, а в `Clean-param` его нет,
  дописывается туда (`head-kit.yaml` `hk-ya-get-params`). `[практика]`
- Варианты под рекламу (`../03-page-structure/02-length-goal-message-match.md §3.3–3.4`): один URL + параметр + белый список
  вариантов; canonical без параметров; вариант сервером; смысл предложения для робота и человека одинаковый. Отдельные
  URL-копии под объявления — canonical на основную или `noindex`, но **AdsBot и YaDirectFetcher не закрывать** (`crawlers.yaml`).
- Замер корпуса: canonical есть у 84 % страниц (EN 96 %, RU 74 %), на себя — 82 % `[проверено]`; Web Almanac — 68 % [S36].

### 2.4. Sitemap и IndexNow

- Sitemap: UTF-8, абсолютные URL, ≤ 50 000 URL или 50 МБ несжатого на файл (иначе индекс sitemap); **«Google ignores
  `<priority>` and `<changefreq>`»**; `<lastmod>` используется, если «consistently and verifiably… accurate» [S9] → `lastmod` =
  реальная дата изменения содержимого, не «сегодня» на каждый запрос (так делает шаблон higgsfield — антипример [S43]).
  В sitemap — только канонические индексируемые URL (Bing — то же [S33]); `thank-you-page`, 404, `noindex` — не включать.
- `Sitemap: https://…/sitemap.xml` в robots.txt; для Google — Search Console, для Яндекса — Вебмастер. Замер G/01 (20
  многостраничников): sitemap не объявлен в robots.txt у 4, URL с редиректом — у 6, относительные `<loc>` — у 1, sitemap kontur
  отвечает 301 на главную [S49] → `head-kit.yaml` `hk-site-sitemap`. `[проверено]`
- **IndexNow**: Яндекс и Bing принимают уведомления о новых, изменённых и удалённых URL (ключ-файл на сайте; `yandex.com/indexnow`)
  [S48], [S33]; Google IndexNow не использует. Для небольшого сайта Яндекс советует «Переобход страниц» в Вебмастере [S48].

### 2.5. Языки: hreflang и lang

- Google: HTML `<link>`, HTTP-заголовок или sitemap — равноценны; каждая версия ссылается на себя и все прочие; без взаимных
  ссылок — игнор; `x-default` — для выбора языка и автоперенаправления; ISO 639-1 (+ ISO 3166-1 alpha-2); **«Google doesn't use
  hreflang or the HTML lang attribute to detect the language»** [S10].
- Яндекс: **«больше не поддерживает файл Sitemap для языковых версий»** — только разметка в HTML; регион можно указать и по
  ISO 3166-2:RU [S28]. → Для обоих: `<link rel="alternate" hreflang>` в `<head>`. G/01: hreflang в `<head>` — у 6 из 19
  многостраничников, только в sitemap — у heisenbug (Яндекс таких связей не увидит) [S49].
- `<html lang>` — BCP 47 (`ru`, `en`, `ru-RU`), не `ru_RU` (это формат `og:locale`); на корпусе `lang` отсутствует у 9 %
  страниц `[проверено]`. Структура языковых версий и переключатель — G (`../06-multipage-ia/`).

## 4. Структурированные данные в 2026

### 4.1. Правила Google и Яндекса

- Google: JSON-LD рекомендован; **«Don't mark up content that is not visible to readers of the page»**; не вводить в
  заблуждение (фейковые отзывы, чужое имя); без обязательных свойств — нет rich result; разметка на той странице, которую
  описывает; самый конкретный тип; картинки в разметке доступны для обхода; «make sure all structured data items are
  complete» (если размечены отзывы — все видимые) [S14]. `[документация]`
- Google для ИИ-функций: «Structured data isn't required for generative AI search, and there's no special schema.org markup
  you need to add… it helps with being eligible for rich results» [S12]; Bing: разметка «may support clearer grounding but does
  not guarantee visibility… must accurately reflect visible content» [S33]. Значит, разметка — ради rich result и однозначности
  сущности, а не «ради ИИ». `[документация]`
- Разметка раздувает HTML («specifically not for users… can increase the bloat considerably» `[V:kype1JQbrks 18:30]`) → только
  типы из `head-kit.yaml` `page_types` (поле плана `seo.structured_data`). `[мнение]` (Illyes) + предел 2 МБ [S2]
- Подтипы, допустимые вместо типа страницы, — поле `structured_data_subtypes` в `head-kit.yaml` (`home-multipage`:
  `LocalBusiness` вместо `Organization` у сайта услуг).
- Яндекс: справка «JSON-LD» — данные в теге `script`, ключи и значения чувствительны к регистру; из JSON-LD Яндекс берёт
  навигационную цепочку сниппета (`BreadcrumbList` «в формате JSON-LD»: `name`, `url`, `position`, рекомендовано до трёх
  элементов) и вопросы-ответы мобильной выдачи (`QAPage` — страница с одним вопросом и ответами пользователей); проверка —
  валидатором Вебмастера [S52]. `[документация]` Сам валидатор перечисляет микроформаты, Schema.org, Open Graph, микроданные
  и RDFa и проверяет требования сервисов Яндекса; структурированный сниппет — после переобхода, «около двух недель» [S32].
  Главные каналы данных об организации у Яндекса — Яндекс Бизнес и фиды (§4.4).
- Замер: JSON-LD у 65–71 % страниц (EN 75–88 %, RU 55–56 %), микроданные у RU 39–45 %; Web Almanac 2025 — разметка на 50 % главных,
  JSON-LD 43 %, только через JS — 2 % [S36] `[проверено]` + `[данные]`.

- **Отзывы о себе** (вопрос E): «If the entity that's being reviewed controls the reviews about itself, their pages that use

  structured data or through an embedded third-party widget (for example, Google Business reviews…)» [S16]; «Don't aggregate

  Отзывы показываются текстом с источником и датой (механика — F, подлинность — I). `[документация]`

- **Event** (вопрос E): одна страница — одно событие, уникальный URL, «bookable to the general public», «must take place in a

  Великобритания, США [S17]. Для RU-мероприятия и вебинара разметка — ради однозначности, не ради выдачи. `[документация]`

### 4.3. Сущность организации

- `Organization` один раз с `@id` (`https://домен/#org`), остальные узлы ссылаются `{"@id": …}`; `sameAs` — только свои
  открывающиеся профили (Яндекс Бизнес, Google Business Profile, 2ГИС, VK, Telegram, YouTube, Wikidata при наличии элемента)
  — из поля брифа `search.profiles`; `legalName`, `taxID` (ИНН) — как в реквизитах подвала (I). Роль сущности для ИИ-ответов —
  `02-geo-ai-search.md` §4. `[документация]` + `[практика]`
- Замер: Organization или подтип — 54–58 % страниц, `sameAs` — 35–41 % (RU 15–27 %) `[проверено]`.

### 4.4. Яндекс: Бизнес, фиды, форматы

- **Яндекс Бизнес** — источник региона сайта, адреса, телефона, часов и рейтинга в выдаче и картах; сайт указывается в профиле
  организации [S29], [S31]. Для лидогенерации услуг и сайта услуг (приоритет 1 заказчика) это важнее JSON-LD. `[документация]`
- **«Услуги»** (обновлено 2026-09-11): карточки исполнителей с ценой, описанием, рейтингом, числом отзывов, контактами;
  формируются «на основе обработки данных поискового робота или переданных фидов»; фид YML в Вебмастере (исполнители,
  услуги, один тип цены — `exact`, `from`, `is_free`, `is_negotiable`) или профиль в Яндекс Бизнесе [S31]. Скрыть страницу из
  темы «Услуги» — `<meta name="yandex" content="disallow-extended-services-display">` [S26]. `[документация]`
- «Карточка юрлица или ИП» — из данных ФНС и реестров (интеграция сайтов удалена 2026-07-01) [S31]; `keywords` Яндекс по-прежнему
  называет среди учитываемых метатегов («может влиять на соответствие страницы поисковым запросам») [S26] — Google его не
  использует; писать — по желанию, без набивки.

## 5. Спам-политики, ИИ-контент, особенности Яндекса

### 5.1. Google и Bing: что считается спамом (2026)

- Спам — в том числе «attempting to manipulate generative AI responses in Google Search» (уточнено 2026-05-15) [S11], [S13].
  Для генератора сайтов опасны: **cloaking** (текст только для UA поисковика); **doorway abuse** («multiple domain names or
  pages targeted at specific regions or cities that funnel users to one page»); **hidden text** (белое на белом, за экраном,
  font-size или opacity 0; аккордеоны, табы, слайдеры, подсказки — можно); **keyword stuffing** («Blocks of text that list
  cities and regions»); **scaled content abuse** (генерация ИИ многих страниц без ценности, синонимайзинг, сшивка, перевод);
  **back button hijacking** (с 2026-04-13); **scam and fraud** («intentionally displaying false information about a
  business») [S11]. `[документация]`
- Bing: злоупотребления — клоакинг, дубли, скрейпинг, «Keyword Stuffing and Artificially Engineered Language… to trigger
  citations», автогенерация в масштабе, вводящая разметка, **«Prompt Injection and AI Manipulation»** [S33]. `[документация]`
- ИИ-текст: Google оценивает пользу, а не способ создания; масштабная генерация без ценности — scaled content abuse [S11], [S12];
  Яндекс: нейросети «не должны подменять» автора, ИИ-текст не негатив, если проверен экспертом (ЭПОС [S30]; пост 2025-03-28 —
  через text). Слова и подпись автора — text (`../../text/07-seo-geo-copy/02-seo-pages-articles-meta.md §5`).

### 5.2. Страницы «услуга × город» и SEO-тексты

- `seo-landing-page` (словарь B) законна, если у города или отрасли свои факты: работы, отзывы, цены, сроки, адрес
  (`../02-site-types/01-site-and-page-taxonomy.md`, строка `seo-landing-page`); клон с заменой топонима — doorway [S11];
  «SEO-текст» со списком городов в подвале — keyword stuffing [S11]. `[документация]`
- Google против Яндекса: Google — отдельные страницы под вариации запроса «primarily to manipulate» — scaled content abuse
  [S12]; Яндекс советует «увеличивайте количество релевантных страниц» (через text [S42]) → совместимо только как «новая
  страница — новый интент и новые факты». `[спорно]`
- SEO-текст и перелинковка — в хвосте страницы, после главного призыва (медиана позиции 0,73–0,85 на живых страницах —
  `../03-page-structure/01-narratives-and-section-order.md` п. 19). `[проверено]`

### 5.3. Особенности Яндекса

- **Регион**: учитывается по геозависимым запросам; источники — Вебмастер (с модерацией) и Яндекс Бизнес; для модерации —
  контакты и доставка «на видном месте», **полный адрес с индексом и телефонным кодом города, не картинкой**; несколько
  филиалов — адреса и телефоны каждого, можно поддомены; регион не исключает показ в других [S29]. `[документация]`
- **«Коммерческие факторы»** — термин отрасли, официального списка нет `[мнение]`. Официально Яндекс (ЭПОС) просит прозрачности
  бизнеса: «реальный адрес компании, ее реквизиты, все необходимые контакты», специализацию, сертификации, портфолио, отзывы;
  работающую функциональность без «мешающих или раздражающих элементов»; удобство на всех устройствах; цели в Метрике;
  товар «не в наличии» или без доставки в регион «будет проигрывать» [S30]. Для страницы это: реквизиты и контакты в подвале
  (I), цены и условия текстом (F, text), рабочие формы (F), регион в Вебмастере. `[документация]`
- Вебмастер: регион, рендеринг JS («не выполнять» при SSR), «Проверка ответа сервера», «Переобход страниц», IndexNow,
  «Видимость сайта в Алисе AI» (`02` §6); Метрика — P.

## 6. SEO против подачи: правила приоритета

Конфликт (аудит KIMI §4 п.17): SEO-аудит higgsfield требует ≥ 200 слов, ключ в H1 и описательные H2 [S43], Hallmark — hero
≤ 7 слов и сцены по 3–6 слов. Правила ниже его снимают: подача решает первый экран, SEO — HTML страницы целиком.

### 6.1. Приоритеты

| Ситуация | Правило | Метка |
|---|---|---|
| Короткий hero (3–10 слов) | допустим, если H1 — обещание страницы (что, для кого) и ниже первого экрана есть индексируемый текст: у лидеров RU лендинг ≈ 480 слов при заголовке 4,5 слова (text D); «≥ 200 слов» — ориентир на страницу, не на hero | `[проверено: корпус text D]` + `[практика]` |
| H1 | ровно один, в сыром HTML, = слот плана `seo.h1`; стилизованный «кинетический» заголовок — тот же H1 текстом, эффект поверх | `[документация]` + `[проверено: H/01 — 9 % без H1]` |
| Скролл-сцены, WebGL, 3D, canvas, видео-hero | текст сцены — HTML в разметке (визуально поверх или рядом), WebGL-текст — только дубль существующего HTML; видео — с текстовой подписью | `[документация]` 3d §6.1, `[практика]` |
| Анимация появления | финальное состояние видимо; текст в DOM с загрузки; ничего не прятать навсегда (opacity 0 без действия — hidden text) | `[документация]` [S11] |
| Контент по клику (табы, «показать ещё», модалки) | содержимое в HTML с загрузки, клик только раскрывает; не догружать по клику основной текст | `[документация]` [S46] |
| Иерархия заголовков | H2 — секции (не «Преимущества» ради стиля, а смысл — text); уровни не прыгать ради размера — размер задаёт CSS | `[практика]` |
| Тяжёлая страница «вау» (L2) | HTML ≤ 2 МБ, H1 и текст в первых сотнях КБ; медиа и сцены — внешними файлами; бюджет — P | `[документация]` [S2] |
| Прелоадер и заставка | контент в HTML под заставкой, заставка не блокирует обход и LCP (P) | `[практика]` |
| SEO-текст | в хвосте, после главного призыва; без списков городов | `[проверено]` + [S11] |

### 6.2. Одна страница или несколько

- Отдельная страница — новый интент и новые факты (правило C: различаются ≥ 2 из предложения, осведомлённости, возражений,
  локальных фактов — `../03-page-structure/02-length-goal-message-match.md §3.4`); иначе — вариантные слоты на одной
  странице с canonical без параметров (§2.3). `[практика]`
- Лендинг ловит один кластер спроса; десятки запросов (услуги, города с фактами, статьи) — многостраничник (G, B).

### 6.3. «SEO-фундамент» или «SEO + хаб статей» (правило для брифа)

Вопрос харнесса из ролика kimi: «SEO foundation only (Semantic HTML, meta/OG tags, Event schema markup, sitemap, fast loads) /
SEO + article hub» `[V:p1J5uWcn3hI 15:27]` (дайджест `../../kimi-research/91-videos/digests/p1J5uWcn3hI.md`).

| Условие | Решение |
|---|---|
| Трафик — реклама, карты, рекомендации; спроса «по проблеме» мало | фундамент: всё из `head-kit.yaml`, sitemap, Вебмастер, Search Console |
| Есть спрос `search-problem` (словарь B), эксперт с опытом и ресурс на 2–4 материала в месяц | хаб: статьи с реальным автором и фактами (text `02`), перелинковка к услугам (G) |
| Статьи предлагается генерировать ежедневно без человека | нет: scaled content abuse [S11], выдумки `[V:p1J5uWcn3hI 24:51]`; только черновики на согласование |

## 7. Проверка и измерение

- **До запуска**: `geo_probe.py URL --render` (доступ ботов, robots.txt, head, H1 и текст без JS, JSON-LD, 2 МБ) → Search Console
  «Проверка URL» (отрисованный HTML глазами Googlebot) и Вебмастер «Проверка ответа сервера» → валидаторы разметки (Rich Results
  Test Google, валидатор микроразметки Яндекса) → sitemap в обоих кабинетах; регион и Яндекс Бизнес.
- **После релиза шаблона**: повтор `geo_probe.py` на 3–5 страницах каждого шаблона; Search Console «Индексирование страниц» и
  отчёты rich results; Вебмастер «Страницы в поиске», «Диагностика».
- **Не индексируется** — порядок разбора: отрисованный HTML («Проверка URL»; без кабинета — Rich Results Test) → ресурсы,
  закрытые robots.txt, включая API → посредники (CDN, кэш: 10–20 повторов, заголовки `Age`, `X-Cache`, `CF-Ray`) → код
  несуществующего URL; инструмент удаления Search Console — не решение [S50]. `[документация]`
- **ИИ-видимость** (отчёт Google о генеративном ИИ, «Видимость сайта в Алисе AI», Bing AI Performance, реферы и логи ботов) —
  `02-geo-ai-search.md §6`; события и цели — P (`events.yaml`).

## Частые ошибки

1. **Сайт-SPA без SSR**: пустой `<div id="root">` — Google дождётся рендера, Яндекс может нет, ИИ-боты — никогда (duolingo.com,
   megaplan.ru, aspro.cloud на замере) `[проверено]`.
2. **Мегабайтный HTML**: инлайн-стили, base64-картинки, данные гидратации — H1 уезжает за 2 МБ (practicum.yandex.ru,
   alice.yandex.ru/station) `[проверено]`.
3. **Антибот-заглушка с `noindex` для клиентов без JS** (Qrator, JS-challenge) — боты без белого списка получают пустую
   страницу `[проверено]`.
4. **`/robots.txt` отдаёт HTML или 5xx** (заглушка SPA, падение бэкенда) — 5xx = полный запрет обхода.
5. **`Disallow` вместо `noindex`** для «спасибо» и служебных — URL остаётся в выдаче без сниппета; и наоборот, `noindex` на
   странице, закрытой в robots.txt, не прочтут.
6. **Именная группа бота с `Allow: /` без служебных `Disallow`** — открывает закрытые пути; `crawl-delay`, `noindex`, `host`
   в robots.txt «для Google» — не работают [S6].
7. **canonical относительный, на главную со всех страниц, на URL с UTM или меняется JS'ом**; второй canonical из плагина.
8. **Sitemap с `lastmod` = сегодня на каждый запрос, `priority` и `changefreq`** (шаблон higgsfield) — Google `lastmod` перестаёт
   верить, остальное игнорирует.
9. **FAQPage, SearchAction, HowTo «для полноты»**, отзывы о себе в `AggregateRating`, рейтинг Яндекс Карт в разметке.
10. **Event для онлайн-вебинара «ради сниппета»**, SoftwareApplication с выдуманным рейтингом — выдумка в разметке = обман (I).
11. **Клоны «услуга × город»** с заменой топонима и абзац со списком городов в подвале.
12. **Текст сцены в canvas или картинке**, заголовок кинетической типографикой без HTML-текста; адрес и телефон картинкой.
13. **Мобильная версия без части текста** (вырезано, а не свёрнуто) — индексация по мобильной версии.
14. **Сертификат только НУЦ Минцифры** на сайте, которому нужен зарубежный поиск и ИИ.
15. **Смешанные директивы** `<meta name="robots" content="all">` и `noindex` в плагине — Яндекс индексирует, Google нет.

## Чек-лист

- [ ] H1, текст, цены, условия, главный CTA и навигация — в HTML сервера (`geo_probe.py`: нет `csr-shell`, `no-h1-in-raw`)?
- [ ] Несжатый HTML ≤ 2 МБ, H1 в начале документа (нет `html-over-2mb`)?
- [ ] Индексируемые страницы — 200, несуществующий URL — 404, удалённые — 301, 404 или 410?
- [ ] Антибот, CDN и WAF пускают YandexBot, Googlebot и ботов из `search.ai_answers` (нет `antibot-challenge`)?
- [ ] Сертификат проверяется общепризнанными корнями (нет `tls-untrusted-chain`)?
- [ ] `/robots.txt` — 200 и `text/plain` или 404; только поддерживаемые поля; именные группы повторяют служебные запреты?
- [ ] CSS и JS для отрисовки не закрыты; `noindex` не сочетается с `Disallow`?
- [ ] На странице нет противоречивых директив robots, нет `noindex` в виджете в `<body>`?
- [ ] Canonical один, абсолютный, на себя, без параметров, в сыром HTML; варианты под рекламу — один URL?
- [ ] Sitemap: канонические индексируемые URL, честный `lastmod`, строка в robots.txt, отправлен в оба кабинета?
- [ ] hreflang (если есть языки) — в HTML, взаимный, с `x-default`; `lang` в формате BCP 47?
- [ ] head по `head-kit.yaml`: title, description, OG (абсолютный og:image, в первых 1 МБ), twitter:card?
- [ ] JSON-LD только типов из `page_types`, значения видимы и совпадают с фактами; нет FAQPage ради сниппета и отзывов о себе?
- [ ] Для Яндекса: регион в Вебмастере, профиль Яндекс Бизнеса с сайтом, адрес и телефон текстом; для услуг — решение по фиду «Услуги»?
- [ ] Страницы «услуга × город» — с локальными фактами; SEO-текст без списков городов, в хвосте?
- [ ] Короткий hero, но индексируемый текст ниже; эффекты и сцены — поверх HTML-текста?
- [ ] Поиск по сайту и фильтры закрыты одним `Disallow` на шаблон; API для контента открыты; директивы одинаковы в 10–20 повторах?
- [ ] Проверено в Search Console «Проверка URL» и в Вебмастере «Проверка ответа сервера»?

## Открытые вопросы и противоречия

1. **Google против Яндекса по директивам robots**: Google — строгая побеждает, Яндекс — разрешающая [S7], [S26]. Позиция базы —
   не смешивать; поведение Bing и ИИ-ботов при конфликте не описано.
2. **JSON-LD у Яндекса**: справка называет для JSON-LD навигационную цепочку, вопросы-ответы и Почту [S52]; берёт ли Яндекс
   из JSON-LD организацию (`Organization`, `LocalBusiness`) сверх Яндекс Бизнеса, не сказано, а список форматов валидатора
   JSON-LD не называет [S32]; адрес элемента цепочки у Яндекса — `url`, у Google — `item`. Для RU-сайтов микроданные
   встречаются в 39–43 % страниц. Проверить валидатором Яндекса на примерах `head-kit.yaml` — нужен вход в Вебмастер
   (заказчик) → живая фаза.
3. **Что видят зарубежные боты на сайтах с сертификатом НУЦ** — не проверено (сервер может выбирать сертификат по адресу).
4. **Антибот-системы и ИИ-боты**: какие RU-антиботы (Qrator, DDoS-Guard, Servicepipe) пропускают OAI-SearchBot, PerplexityBot,
   Claude-SearchBot по спискам — данных нет; нужен тест с логами на своём сайте.
5. **Предел 2 МБ у Яндекса** не опубликован; у Meta — OG в первых 1 МБ; у ИИ-ботов пределы не опубликованы.
6. **Google и Яндекс о страницах под вариации запроса** — Google против, Яндекс за «больше релевантных страниц» (через text) —
   сведено правилом «новая страница — новый интент и факты» `[спорно]`.
7. **Пользу FAQPage и других типов для ИИ-ответов** никто не измерил (Google: «no special schema.org markup» [S12]).
8. **Выборки H/01 и H/02 смещены** (корпус текстов, посадочные M); доли — фон, не рынок; пересчёт H/02 на итоге M2 (X2, 69 страниц) сдвинул доли на 0–6 п. п., у зарубежных — до 17 п. п. (добавились 14 зарубежных страниц, из них 7 — шаблоны многостраничников), правила те же.
