Утилита: `../../scripts/site/geo_probe.py` — robots.txt по ботам `crawlers.yaml` (с цепочками групп Яндекса, Apple, AdsBot),
`/llms.txt`, head, H1 и текст без JS, JSON-LD, антибот-заглушка, TLS, 2 МБ; `--render` (доля текста без JS, H1, призыв и цены
только после JS), `--ua-probe`; самопроверка 33/33. Опыты: `99-raw/experiments/H/00-sources` (сырые таблицы первоисточников
ботов), `H/01-geo-probe-corpus-d` (116 страниц корпуса text D), `H/02-geo-probe-sample-m` (52 посадочные выборки M; пересчёт X2 — 69 из 70 итоговой). Строки
SEO и GEO `page-gates.yaml` (SG-SEO-01…04, SG-GEO-01…02) ведёт H по `head-kit.yaml`.

Выжимка H:
1. Смысл страницы — в HTML ответа сервера (SSR, SSG): ИИ-боты JS не исполняют, Яндекс рендерит JS только бета-опцией.
2. Несжатый HTML ≤ 2 МБ, H1 и текст — в начале документа: Googlebot читает первые 2 МБ каждого файла.
3. GEO стоит на SEO: ИИ-ответы Google и Яндекса строятся из поискового индекса; ChatGPT опирается на Bing, Claude — на Brave.
4. Поисковых ИИ-ботов не закрывать; обучение — отдельными токенами по `search.ai_bots_policy` (молчание = `allow-all`).
5. Из ИИ-ответов Google выводит только переключатель Search Console (с 2026-08-31), из Алисы AI — поимённый `YandexAdditional`.
6. Реальные барьеры на выборках — не robots.txt, а антибот-заглушки, сертификат НУЦ без общепризнанного, CSR-оболочки, HTML > 2 МБ.
7. FAQ-сниппеты Google сняты 2026-05-07; отзывы о себе звёзд не дают; Event — только офлайн; размечать только видимое.
8. Для Яндекса организация — Яндекс Бизнес и регион в Вебмастере; адрес и телефон — текстом; услуги — фид YML «Услуги».
9. `llms.txt` по умолчанию не делать (Google не использует, польза не доказана); мерить встречаемость в отчётах платформ.
10. «+40 % от GEO-приёмов» — не правило (лаборатория, выдуманный текст); ИИ-сводки снижают клики (Pew: 8 % против 15 %).

Утилиты: `../../scripts/site/page_gates.py` (ворота по профилю из JSON `page_anatomy.py`/`page_accept.py`, самопроверка 64/64, v1.2),
`../../scripts/site/ab_plan.py` (выборка, недели, MDE, SRM, FPR, анализ, подглядывание; самопроверка 35/35). Опыты —

Выжимка P:
1. Блокируют исходы (LCP > 4 с, CLS > 0,25, INP-сценарий > 500 мс, индексируемость, право), вес — предупреждение по профилю.
2. Приёмка телефона — лаборатория CPU×4 + 1,6 Мбит/с + RTT 150 мс, медиана 3 прогонов; поле — p75 раздельно по устройствам.
3. Профиль `<page_type>@L<n>`; первый экран телефона L0/L1/L2 — 1,5/2,0/2,5 МБ, лидогенерация услуг — всегда 1,5 МБ.
4. До ввода — только CMP; счётчики после согласия; карты, чат, видео, запись — фасадом по видимости или нажатию.
5. Весовые ворота соседей (page_accept, kimi F2, 3d WEB-04) дают ложные блокеры: 3, 3, 2 из 10 страниц M (P/02, ворота v0; на воротах v1.2 — 5, 5, 3).
6. Главная метрика — действие и его качество из CRM; макро-событие — после ответа сервера 2xx.
7. A/B считать до старта (`ab_plan.py`): при 300 визитах в день видны только эффекты ≥ +35–50 %.
8. Не подглядывать (14 просмотров → 22 % ложных побед); SRM p < 0,0005 → стоп; FPR при 10 % успешных идей — 22 %.
9. Эффект > +30 % от правки — искать ошибку (закон Твимана); 0,01 < p < 0,05 — повторить.
10. Малый трафик — пятисекундный тест, тест с людьми, опросы (канон ux `12/04`), A/B — только крупные развилки.
