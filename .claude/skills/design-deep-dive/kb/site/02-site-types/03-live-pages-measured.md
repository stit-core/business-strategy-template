## 1. Метод

### 1.1. Утилита и сценарий

`page_anatomy.py` (Playwright 1.63, Chromium 153.0.8010.12, `channel=chromium`, ANGLE GL,
`--disable-blink-features=AutomationControlled`): одна страница × одно устройство — отдельный процесс под двумя
блокировками браузера, `MemAvailable` ≥ 3 ГБ. Сценарий:

1. десктоп 1440×900 DPR 1 (UA Chrome 153 без «Headless»); телефон — Playwright «Pixel 7» (412×839, DPR 2,625) **с CPU ×4**
   (как Lighthouse mobile), сеть без замедления; `locale` и `Accept-Language` — `ru-RU` или `en-US` по рынку;
2. `load` (до 60 с) → 5 с простоя → метрики «первого экрана» (байты по CDP, LCP, CLS, долгие задачи) и кадр;
3. cookie-баннер: 40+ селекторов платформ согласия, фиксированные слои с «cookie/куки/метрика», теневой DOM; до действия
   пишутся кнопки, модальность, доля экрана, трекинг и cookie; действие — «Отклонить» → «×» → скрытие CSS (§1.6);
4. попап захвата — Esc → «×» → скрытие CSS; прокрутка колесом до конца (6–45 шагов по 0,8 экрана) с тремя срезами
   фиксированных слоёв (липкая шапка, липкий призыв, чат);
5. разбор DOM (секции, призывы, формы, шапка, подвал, заголовки, мета, JSON-LD, платформа) и контактный лист секций;
6. лабораторный INP (`--inp`): меню → якорь CTA → раскрыть FAQ → фокус в поле **без ввода**; мера — худшее
   взаимодействие по своему наблюдателю Event Timing (`durationThreshold` 16 мс) и `onINP` web-vitals 6.2.2;
7. текст без JS: тело ответа главного документа против отрисованной страницы (слова, h1, главный CTA, заголовки, цены,
   мета, JSON-LD).

Сегментация — развёртка обёрток до полос ≥ 50 % ширины (на телефоне ≥ 85 %); «только заголовок» приклеивается к следующей
полосе, мелкие — к предыдущей; хвост с ©, ИНН/ОГРН или ≥ 6 ссылками — подвал. Классификатор — баллы по признакам
(заголовок, id/class, текст, структура: форма, логотипы, числа, цены в карточках, аккордеон, шаги, карта, время, видео,
длинный текст), top-3 с причинами в JSON; роли и блоки — `vocabulary.yaml` ред. 2; классы пересчитываются без браузера
(`--reclassify`), правка v1.1 — §1.5.

### 1.4. Годность строк, перемер, блокировки

- Партия M: 13:01–15:16, 140 прогонов, 1 падение (`us-pilot` на телефоне: страница сама ушла по адресу). В 13:59–14:30 VPN
  «моргал» (таймауты `goto`, пустые ответы, `ERR_TIMED_OUT`); с 14:02 каждый прогон пишет пробу маршрута до и после.
- Перемер M2 (15:24–17:37): все строки с признаками сбоя, кроме подтверждённых свойств страниц; прежний JSON сохранён рядом
  (`anatomy_<устройство>.json.try1`, колонка `attempt`). Свойства страниц, а не сети: **Ozon Seller — HTTP 403 антибота** на
  обоих устройствах; **T-Bank Black — сертификат «Russian Trusted Sub CA» (НУЦ Минцифры)**, Chromium без российского корня
  отвечает `ERR_CERT_AUTHORITY_INVALID` [проверено: `openssl s_client`, издатель сертификата, 2026-09-24]; у rostovbuh.ru
  адрес услуги из `sitemap.xml` и ссылка меню отдают 404 — шаблон заменён другой услугой из меню.
- Годность (`make_csv.py`): строка исключается (`valid=0`, `exclude`) только по признакам самой страницы — `chrome-error`,
  HTTP 4xx, заглушка антибота, пустой DOM (< 50 слов), ≥ 10 сбойных запросов. Событие `load` не наступило за 60 с при
  разобранном DOM — строка годна для структуры, призывов, форм и SEO, но не для скорости и веса (`speed_valid=0`,
  `note=load-timeout`; колонки скорости в CSV пусты). **Проба маршрута через эхо-сервисы ненадёжна**: при нормальной загрузке
  страницы одна из проб часто не отвечала (≈ 500 вызовов за день — вероятно, ограничение частоты), поэтому она идёт только в
  `note=route-probe-fail`, а `net` берётся по стране сервера.
- Сегментация сорвалась (`seg_flag=fail`: подвал или общая обёртка проглотили страницу) на 4 прогонах — строки годны
  для призывов, форм, SEO и скорости, но не для частот секций.
- **Блокировка браузера.** Общую блокировку тройки делят оркестратор и агенты creative; встроенный `dual_lock` партии
  опрашивал её раз в 2 с и проигрывал агентам с блокирующим `flock -w 900` — партия вышла по тайм-ауту 900 с. Остаток
  снят драйвером `rerun.py` с блокирующим `flock` на обе блокировки и `timeout 270` на прогон; `dual_lock` исправлен на
  блокирующее ожидание с тайм-аутом (как `flock -w`) [проверено].

### 1.6. Что утилита не делает

**«Принять» на cookie-баннере не нажимается никогда** (отступление от задания в пользу приватности: согласие — только с
разрешения заказчика): «Отклонить» → чистое «×» → скрытие баннера CSS без выбора (`cmp_action=hidden`). Формы не
отправляются, в поля ничего не вводится (для INP — только фокус), по рекламе не кликали, попапы закрываются Esc или «×».
Поэтому данные о трекинге описывают страницу **без согласия или после отказа** — худший для владельца и лучший для
посетителя случай; поведение после «Принять» — в «Что проверить в живой фазе».

## 3. Структура страницы: длина, роли, последовательности (для C и E)

### 3.3. Последовательности

- Частые пары (десктоп, повторы подряд свёрнуты): `hero → benefits`, `benefits → testimonials`, `benefits → pricing`,

## Частые ошибки

Замер:
- **Мерить главную бренда и называть это лендингом** — у главных нет формы, квиза, тарифов и общего хвоста посадочной
  (аудит MEDIA §4.10); здесь 51 из 72 страниц — посадочные и страницы услуг.
- **Нажимать «Принять» в cookie-баннере** ради «чистого» кадра — это согласие от имени посетителя и искажение данных о
  трекинге; здесь «Отклонить», иначе «×», иначе скрытие CSS.
- **Не закрыть баннер и попап** — они попадают в LCP (у ai-media Tilda: LCP = текст баннера, 34 с) и перекрывают клики
  сценария INP.
- **Считать форму невидимой по размеру тега `form`** — у форм с плавающими полями высота тега 0; видимость — по полям.
- **Пороги от `innerWidth` на телефоне** — страница шире экрана расширяет область Chrome (569 вместо 412 px) и ломает
  сегментацию и клики; пороги — от ширины устройства, переполнение — отдельный признак.
- **Брать заголовок секции только из h2** — надзаголовок бывает h2, а сам заголовок — h3; учитывать визуально крупные.
- **Принять логотип компании на карточках услуг за стену логотипов клиентов** — нужны разные файлы и отсутствие фото.
- **Ждать поле CrUX от PSI API без ключа** — квота 0 (2026-09-24); и CrUX не видит Яндекс Браузер.
- **Один прогон = истина** — сети, A/B-тесты страниц и ленивые загрузки меняют вес и LCP от прогона к прогону.
- **Считать молчание пробы-эхо сбоем страницы** — эхо-сервисы ограничивают частоту; годность — по признакам самой страницы
  (§1.4).
- **Брать замок браузера своим опросом или `flock`** — замок браузера — `kbpaths.lock` с ожиданием, утилита
  берёт его сама (§1.4).
- **Брать за кнопку «Отклонить» контейнер обеих кнопок** — равенство кнопок баннера тогда всегда «нет» (§6).
- **Мерить INP одним случайным кликом после загрузки** — медиана 1 взаимодействие и 0 % > 200 мс: это нижняя граница (§8).
- **Верить ролям секций без порога уверенности** — роль верна в ≈ 60 %, при `conf` ≥ 0,5 — в 87–92 % (§1.5).
- **Сравнивать скорость до и после смены сети** — другой провайдер и другие страницы (§1.3, §8).

Генерация (что из данных следует для агента-сборщика; нормы — у C, E, F, H, I, P):
- Делать форму без ссылки на политику и без отдельного согласия на ПД — у 9 из 17 русских посадочных с формой нет никакого
  элемента согласия (раздел 5).
- Ставить Метрику и пиксели до выбора в баннере, если баннер предлагает выбор (раздел 6).
- Отдавать заголовки, цены и призывы только скриптом — H и GEO требуют их в сыром HTML (раздел 7).
- Прятать шапку на телефоне без кнопки меню и без телефона — у лидогена РФ телефон в шапке — норма рынка (раздел 4).
- Отдавать JSON-LD или цены только скриптом (5 зарубежных страниц — JSON-LD из JS; у четверти русских страниц с ценами
  40 % цен и больше — из JS) (§7); делать посадочную клиентским рендером без текста в HTML (3 страницы) (§7).
- Считать уведомление о cookie согласием: у русских посадочных баннер — только уведомление, трекинг — до выбора (§6).
- Отдавать телефону те же 2–3 МБ, что десктопу, не проверив TBT с замедлением CPU ×4 (у посадочных медиана 375 мс) (§8).

## Открытые вопросы и противоречия

1. **Лаборатория против поля не сделана**: PSI без ключа — 429, квота 0; CrUX API без ключа — 403 «unregistered callers»
   (2026-09-24, 12:10 и 16:22). Нужен ключ заказчика; для РФ поле CrUX смещено (нет Яндекс Браузера) — нужны и данные
   Метрики своих сайтов (живая фаза).
2. **После «Принять» не мерили**: какие трекеры добавляются после согласия и соблюдают ли страницы отказ шире двух случаев —
   неизвестно (нужен прогон с разрешения заказчика).
3. **Одна точка наблюдения**: русские страницы — с российского адреса, зарубежные — из ЕС (Литва). Баннер показали 6 из
   24 зарубежных страниц; много это или мало для ЕС, без замера из США и из РФ не сказать; T-Bank выдаёт сертификат НУЦ
   Минцифры с российского адреса — всем ли, не проверено.
4. **Классификатор**: роль верна в ≈ 60 %, блок — в ≈ 35 %, разметчик один; последовательности и частоты ролей — оценки с
   этой погрешностью, частоты блоков — подсказка.
5. **INP**: сценарий после загрузки, медианно одно взаимодействие; мобильный TBT посадочных 375 мс говорит о рисках
   отзывчивости, которых сценарий не поймал.
6. **Недобор выборки**: Tilda — 2 страницы из 72, видимых квизов — 0 (только всплывающие), онлайн-записи — 0, waitlist —
   2, многостраничников — 7 (в задании 8–10), личного бренда и корпоративного сайта — нет.
7. **Рынок против закона** [спорно]: 9 из 17 русских посадочных с формой — без элемента согласия, трекинг до выбора на всех
   страницах с баннером (РФ 11 из 11, зарубежные 6 из 6) при 152-ФЗ в ред. 156-ФЗ (с 01.09.2025) и ePrivacy — частота на
   рынке не делает практику допустимой; оценка — у I.
8. **Замер против поправки №17 `PLAN.md`**: медиана первого экрана посадочной — 3,3 МБ на десктопе и 2,9 МБ на телефоне,
   то есть порог 2,5 МБ превышает больше половины посадочных — подтверждает, что 2,5 МБ не может быть нормой без профиля.
9. **Смена сети в 14:30**: влияние провайдера на TTFB и LCP русских страниц не отделено от смены набора страниц.
