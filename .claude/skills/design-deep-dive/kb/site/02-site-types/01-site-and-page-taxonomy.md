## Выжимка для агента

1. **Тип определяй по двум осям**: `site_type` (весь сайт: одна посадочная или многостраничник какого рода) и `page_type`
   (каждая страница); форма страницы (`macrostructure`) и уровень подачи (`ambition_level`) — отдельные оси, не тип. → §1 [практика]
2. **Сначала действие, потом тип**: главное действие брифа (`action`) и его порог (`commitment`) выбирают ветку дерева; тип
   без действия — дефект брифа (вопрос заказчику). → §6 [практика] (NN/g 2024: макроконверсия задаётся целью бизнеса)
3. **Одна посадочная — один `page_type` и одно макро-действие**; вторичные действия — только micro (цены, видео,
   подробнее). → §3 [практика]
4. **Лидогенерация услуг РФ** (приоритет 1): `landing-lead-services` или `services-site`; действия `lead-request`,
   `call`, `callback-request`, `message`, `booking`, `request-quote`; реквизиты (юр. наименование, адрес, телефон, ОГРН,
   ИНН) — в подвале по умолчанию: для юридических услуг, ремонта техники, займов, билетов Яндекс Директ требует их
   обязательно. → §3.1 [документация: Яндекс Директ, 2026-09-24]
5. **Трафик Директа и Google Ads** → никаких всплывающих окон захвата (Директ запрещает pop-up и pop-under, формы связи
   допускает), без заглушек, акция из объявления — на странице; объявление не ведёт прямо на файл или почту. → §3.1, §3.9
   [документация: Яндекс Директ; Google Ads Policies, 2026-09-24]
6. **SaaS** (приоритет 2): лендинг `landing-saas` для платного трафика и кампаний, `saas-marketing-site` для постоянного
   присутствия; обязательны цены (или примерные цены по сценариям), интеграции, безопасность и сценарии по сегментам.
   → §2, §3.2 [исследование: NN/g 2013, 2016]
7. **Кампания и запуск L2** (приоритет 3): `landing-campaign` или `campaign-site`; цель — внимание и одно действие; вау-сцены
   допустимы, но смысловой текст, цена и CTA — в HTML до эффектов. → §3.4 [практика] (PLAN «Главные риски» п. 7)
8. **Корпоративный многостраничник** (приоритет 4): главная, «О компании» (сводка + подстраницы), направления или услуги,
   проекты или кейсы, контакты, политика ПД; «Контакты» — в шапке и в подвале. → §2, §4 [исследование: NN/g 2019]
9. **Главная многостраничника ≠ посадочная**: её задача — кто вы, что делаете, куда идти; под рекламу строй отдельный
   лендинг. → §4.1 [исследование: NN/g 2024; мнение вендора: Unbounce 2024]
10. **Главная — L1 по умолчанию**: NN/g советует минимум движения и без заставок; L2 — только главная кампании, студии или
    события по решению заказчика. → §4.1 [спорно: NN/g 2024 против цели «вау» — creative]
11. **«О компании»** — 4 уровня: слоган на главной → сводка 1–2 абзаца → подстраницы (миссия, история, команда, новости,
    вакансии) → ссылки в подвале; объясни, что компания делает, одной фразой. → §4.3 [исследование: NN/g 2019, 70+ пользователей]
12. **«Контакты»**: телефон и почта обязательно, адрес с регионом, часы и срок ответа; форма — только вдобавок, 3–5 полей;
    без регистрации. → §4.3 [исследование: NN/g 2019, 20 пользователей, 40 сайтов]
13. **Цены**: у B2B цена — информационная потребность № 1; нельзя точную — примерные цены типовых сценариев, а не сложный
    калькулятор. → §4.2 [исследование: NN/g 2013]
14. **Сравнение и тарифы**: статичная таблица — до 5 вариантов, больше — выбор пользователем; на телефоне — вкладки.
    → §4.2 [практика: NN/g 2024]
15. **«Спасибо»** обязателен у каждой формы: что будет дальше и когда, контакты, следующий шаг; номер заявки, если есть.
    → §5.1 [документация: GOV.UK]
16. **404**: без жаргона «404» в заголовке, без обвинения посетителя; пути на главные разделы и контакт. → §5.2 [документация: GOV.UK]
17. **Политика обработки ПД** — на любой странице, где собирают данные (152-ФЗ ст. 18.1 ч. 2); юридический набор —
    `legal-page` (детали — I). → §5.3 [стандарт: 152-ФЗ ред. от 26.07.2026]
18. **Лендинг внутри многостраничника** — `page_type` лендинга + `site_type` сайта: логотип ведёт на главную, шапка
    упрощена, подвал с реквизитами сохранён. → §7.1 [практика] (NN/g 1996: подсайт связан с родителем)
19. **«Сайт + личный кабинет»** — два пакета с общим DESIGN.md: сайт (site) и сервис (ux, ui). → §7.2
    [практика] (kimi 07/01 §2.2)
20. **Интернет-магазин целиком — вне рамок**; промо товара без каталога и корзины — `landing-product`. → §7.3 [практика] (решение 8 PLAN)
21. **Сайт-история, кино-скролл** — не тип, а форма: `macrostructure: scroll-story` у `landing-campaign` или
    `landing-product`, уровень L2. → §7.4 [практика] (kimi 07/01 §2.2)
22. **Не выводи тип из шаблона генератора**: «hero → фичи → CTA» — медиана, а не тип; 34 паттерна `landing.csv` не содержат
    гарантий, возражений, условий и перечня услуг. → §8 [проверено: опыт B/01]
23. **Примеры страниц — не нормы**: главные крупных брендов (замеры соседей) — не посадочные; норма длины и порядка —
    C по замеру M. → §3 [практика] (аудит MEDIA §4.10)
24. **Нет подходящего типа** — не придумывай id: ближайший тип + заметка «## Для B» (волна 1) или «## Для J» (волны 2–3).
    → `02-vocabulary-and-crosswalk.md` §3 [практика]

## 1. Оси классификации

| Ось | Пространство | Кто задаёт значения | Пример |
|---|---|---|---|
| Тип сайта | `site_type` (9 в рамках + 5 вне) | B, J | `services-site` |
| Тип страницы | `page_type` (33 + 3 вне), поле `class`: landing, multipage, content, utility | B, J | `service-page` |
| Жанр текста | поле `page_type.genre` = жанр text (landing, site-page, article) | text | `site-page` |
| Форма страницы | `macrostructure` (29; семейства grid, document, poster, flow) | C (свод), B (id) | `sales-longread` |
| Первый экран | `first_screen_policy` (offer-cta, offer-cta-header, poster) | C | `offer-cta` |
| Уровень подачи | `ambition_level` L0, L1, L2 | creative | `L1` |
| Действие | `action` (23; `level`, `commitment`) | B; события — P | `booking` |
| Осведомлённость и трафик | `awareness`, `traffic_temperature`, `traffic_source` | B; смысл — A, text | `problem-aware`, `maps-local` |

Правила: тип страницы выбирается из цели и действия, форма — из типа, осведомлённости и подачи (C), уровень — из брифа
(creative). Одна страница — один `page_type`; лендинг внутри сайта остаётся лендингом (§7.1). Пары «главная SaaS» и
«лендинг SaaS» — разные типы: у главной задача навигации и доверия, у лендинга — одно действие (§4.1).

## 3. Лендинги (`class: landing`)

Общее для всех: одна цель и одно macro-действие; призыв повторяется (шапка, первый экран, после доказательств, финал, липкий
на телефоне — поправка 1 PLAN, F); у каждой формы — `thank-you-page` и ссылка на политику ПД (§5). Роли и порядок секций —
C (`../03-page-structure/01-narratives-and-section-order.md`), блоки — E. Длина ниже — ориентир B по механизму («чем выше
цена и риск решения и ниже осведомлённость, тем длиннее») [практика]; нормы длины — C по замеру M (`pages.csv`).

### 3.1. `landing-lead-services` — лидогенерация услуг (приоритет 1)

- **Цель бизнеса**: заявка или звонок на услугу (локальную или B2B), дальше — продажа менеджером.
- **Действия**: macro — `lead-request`, `call`, `callback-request`, `message`, `booking`, `request-quote` (квиз или
  калькулятор); micro — `view-pricing`, `read-more`, `watch-video`.
- **Трафик и осведомлённость**: `paid-search` и `search-category` с городом (тёплый, `solution-aware`), `maps-local`
  (горячий), `paid-social` и `paid-display` (холодный, `problem-aware`), `retargeting`. Горячему — короче и контакт выше;
  холодному — проблема и доказательства до формы (A, C).
- **Длина и формы**: средняя или длинная; кандидаты `sales-longread`, `form-first` (короткая вокруг формы при горячем
  трафике), `quiz-funnel` (квиз как главный путь; качество лидов — F).
- **Роли-кандидаты** (порядок — C): `hero`, `problem`, `services` или `offer`, `pricing` (цены «от»), `how-it-works` (этапы
  работы), `case-studies` или `portfolio` (работы «до/после»), `testimonials` (с площадками: `review-aggregate`), `team`,
  `awards-press` (лицензии, СРО — блок `credentials`), `guarantee`, `objections`, `faq`, `lead-form`, `contacts`,
  `footer` с реквизитами.
- **Право** (I): согласие на обработку ПД отдельным документом с 01.09.2025 (156-ФЗ) и политика на странице формы; реквизиты
  для тематик из списка Директа; медицина, юристы, финансы — отраслевые оговорки (`disclaimer`).
- **Примеры** (2026-09-24, корпус text): qlean.ru (клининг), dodofranchise.ru (франшиза), rotorooter.com/austin/ (город ×
  услуга); страницы услуг среднего рынка — brplaw.ru/bankrotstvo, cleanon.ru/novosibirsk/generalnaya-uborka/.

### 3.2. `landing-saas` — SaaS или ИИ-продукт (приоритет 2)

- **Цель**: регистрация, пробный период или демо; дальше — активация в продукте (`../ux/05-flows-journeys/01-onboarding-and-first-run.md`).
- **Действия**: macro — `sign-up`, `start-trial`, `request-demo` (B2B); micro — `view-pricing`, `watch-video`,
  `explore-product` (песочница, `hero-input`), `log-in` (служебное).
- **Трафик**: `search-category`, `paid-search`, `search-brand`, `ai-answer`, `referral`, `paid-social` (холодный).
- **Длина и формы**: средняя; `bento-grid`, `workbench`, `stat-led`, `feature-stack` (трио Hallmark для B2B SaaS); B2B —
  блоки интеграций, безопасности, сценариев по ролям [исследование: NN/g 2016].
- **Роли-кандидаты**: `hero`, `proof-logos`, `product-demo`, `benefits`, `how-it-works`, `integrations`, `audience`,
  `testimonials`, `case-studies`, `pricing`, `comparison`, `faq`, `final-cta`.
- **Примеры**: bitrix24.ru, kontur.ru/diadoc, e-kontur.ru; basecamp.com, buffer.com (корпус text, 2026-09-24).

### 3.3. `landing-product` — промо товара

- **Цель**: покупка, предзаказ или переход к продавцу; без каталога и корзины (иначе — вне рамок).
- **Действия**: macro — `purchase`, `preorder`, переход к продавцу (`read-more` на маркетплейс — micro); micro —
  `watch-video`, `explore-product` (3D, конфигуратор).
- **Длина и формы**: длинная у дорогих товаров («как у Apple»: хайлайты, секции-истории, сравнение моделей —
  `../ai-media/01-web-assets-landscape/01-asset-slots-by-page-type.md §3.2`); `photographic`, `scroll-story`, `catalogue`.
- **Роли**: `hero`, `product-demo`, `specs`, `benefits`, `comparison` (модели), `testimonials`, `pricing`, `guarantee`,
  `faq`, `final-cta`. 3D и секвенции — `../3d/12-recipes/00-how-to-use.md §1`.
- **Право**: сведения о продавце и условия дистанционной продажи (ЗоЗПП; I). Примеры: alice.yandex.ru/station; arc.net.

### 3.4. `landing-campaign` — кампания, запуск, спецпроект (приоритет 3)

- **Цель**: внимание, запоминание бренда и одно действие (покупка, регистрация, лист ожидания, участие в акции).
- **Действия**: macro — `purchase`, `preorder`, `event-registration`, `join-waitlist`, `subscribe`; «запомнить бренд» — не
  действие (метрики охвата — P).
- **Трафик**: `paid-social`, `influencer`, `social-organic`, `paid-display` — холодный, `unaware`; поэтому первый экран
  образный, а смысл и призыв — до конца первой сцены или в шапке (политика первого экрана — C).
- **Формы**: `scroll-story`, `manifesto`, `photographic`, `marquee-hero`; уровень L2 по умолчанию (решение заказчика 15).
- **Право**: правила акции и срок (честная срочность — F, I); маркировка рекламы у интеграций (38-ФЗ ст. 18.1 — I).
- **Пример**: oatly.com (корпус text).

| `landing-waitlist` | почта или предоплата до запуска | `join-waitlist`, `preorder` | холодный, `paid-social`, `influencer` | короткая; `marquee-hero`, `form-first` | `hero` + `email-capture`, `product-demo`, `proof-stats` (только реальные числа) | обещание без доказательств — формулировки text | выборка M |
| `landing-lead-magnet` | контакт в обмен на материал | `download`, `subscribe` | `paid-social`, `paid-search`, `social-organic` | короткая | `hero`, что внутри материала (`lead-magnet`), `audience`, `testimonials`, `lead-form` | согласие на рассылку отдельно; объявление Google Ads не ведёт прямо на файл | выборка M |

- Поправка к `../kimi-research/07-brief-handoff/01-from-app-description-to-brief.md §2.2` для сайта: маршрут `landing`
  ведёт не в анатомию ассетов ai-media, а в этот файл (тип) и C (порядок), потому что `01/01 §3` описывает ассеты лидеров,
  а не логику страницы.

## 4. Страницы многостраничника и спутники (`class: multipage`, `content`)

### 4.1. Главная (`home-multipage`)

- **Задача**: кто вы и что делаете (логотип слева вверху, слоган о деле, отличие от конкурентов), примеры содержания,
  пути к разделам и главное действие; простая, без заставок и лишнего движения [исследование: NN/g «Homepage Design:
  5 Fundamental Principles», 2024].
- Главная не заменяет посадочную под рекламу [мнение вендора: Unbounce 2024; практика]; кампания ведёт на свой лендинг.
- Примеры: invitro.ru, medsi.ru, alfabank.ru/sme/ (корпус text).

### 4.2. Коммерческие спутники

| `page_type` | Цель | Macro-действие | Обязательное содержание | Источник | Примеры |
|---|---|---|---|---|---|
| `services-index-page` | выбор услуги | `read-more` → `service-page` | услуги группами, цена «от», ссылка на каждую | практика | medsi.ru/services/ |
| `service-page` | заявка на одну услугу | `lead-request`, `call`, `booking` | что входит, цена или «от», этапы, сроки, доказательства по услуге, форма, контакты | практика; NN/g 2013 (цена) | brplaw.ru/bankrotstvo |
| `seo-landing-page` | поисковый спрос «услуга × город или отрасль» | как у `service-page` | уникальная польза для города или отрасли, цены региона; не клон с заменой топонима | H (спам-политики), практика | cleanon.ru/novosibirsk/generalnaya-uborka/ |
| `pricing-page` | выбор плана | `sign-up`, `start-trial`, `request-demo` | планы с ценой, что входит, сравнение (статичная таблица ≤ 5 планов), вопросы об оплате | NN/g 2013, 2024 | linear.app/pricing, bitrix24.ru/prices/ |
| `feature-page` | понять функцию | `sign-up` | что делает, как выглядит (настоящий интерфейс), для кого, переход | практика | linear.app/features |
| `use-case-page` | узнать себя | `request-demo`, `sign-up` | сценарий роли или отрасли, результат, кейс | NN/g 2016 (сегменты) | slack.com/solutions/sales |
| `comparison-page` | выбрать между нами и X | `sign-up` | честная таблица, кому подходит X, источники данных о конкуренте с датой | практика; право сравнения — I | выборка M |
| `alternatives-page` | найти замену X | `read-more`, `sign-up` | несколько вариантов с критериями, наш — среди них | практика; `[мнение вендора]` у SEO-блогов | clickup.com/blog/asana-alternatives/ |
| `case-page`, `case-list-page` | доверие через результат | `lead-request` | клиент, задача, решение, результат из фактов, цитата с разрешением; список — фильтр по отрасли и услуге | практика; факты — text | stripe.com/customers |
| `form-page` | отдельная заявка (демо, расчёт, бриф) | `request-demo`, `request-quote` | что получит посетитель, поля по F, что будет дальше | GOV.UK (подтверждение), F | linear.app/contact/sales |

### 4.3. Страницы доверия и связи

| `page_type` | Обязательное | Источник |
|---|---|---|
| `about-page` | что делает компания — одной фразой; сводка 1–2 абзаца вверху; подстраницы или разделы (миссия, история, руководство и команда, новости, вакансии); реальные фото; честные отзывы со ссылками на внешние площадки | [исследование: NN/g 2019, 3 раунда, > 70 пользователей, 100 сайтов] |
| `contacts-page` | телефон и почта (не только форма), адрес с регионом и ссылкой на карту, часы и часовой пояс, срок ответа, каналы по отделам; форма 3–5 полей вдобавок; ссылка «Контакты» в шапке и подвале | [исследование: NN/g 2019, 20 пользователей, 40 сайтов] |
| `team-page` | фото, имя, специализация и опыт; только реальные люди с разрешением (I) | практика; поправка 18 PLAN |

## 5. Служебные страницы (`class: utility`)

### 5.1. `thank-you-page`

Страница подтверждения обязана: номер заявки (если есть), **что будет дальше и когда**, контакты, ссылки на то, что
понадобится дальше, способ сохранить запись [документация: GOV.UK «Confirmation pages»]. Для сайта сверх этого — одно
следующее действие (подписка, материал, запись в календарь), событие цели аналитики (P). Поправка к GOV.UK для сайта:
ссылка на форму отзыва о сервисе не обязательна, потому что это требование госуслуг.

### 5.2. `not-found-page`

Заголовок «Страница не найдена», без жаргона «404» и обвинения посетителя, пути на главные разделы, поиск на большом сайте,
контакт [документация: GOV.UK «Page not found pages»; исследований мало — там же]. Юмор — дело голоса бренда (text); GOV.UK
его запрещает для госуслуг, для маркетингового сайта это `[спорно]`. Сервер отдаёт код 404, а не 200 (H). Пример
настоящей 404: qlean.ru/reviews (2026-09-24).

### 5.3. `legal-page`

Политика обработки ПД публикуется на страницах сайта, с которых идёт сбор данных [стандарт: 152-ФЗ ст. 18.1 ч. 2, ред. от
26.07.2026]; согласие — отдельный документ с 01.09.2025; cookie, оферта, условия акции — по юрисдикции. Состав, формулировки
и даты редакций — I (`../08-legal-trust-a11y/01-law-ru-eu.md`); файл права — «не юридическое заключение».

## 6. Дерево выбора типа по брифу

```text
0. Бриф: главное действие (action) известно?  нет → вопрос заказчику (A: 03-site-brief.md); не выдумывать
1. Нужен ли каталог, корзина, оплата многих товаров? да → ecommerce-store (вне рамок); промо одного товара → 3.3
2. Нужен ли личный кабинет или сервис после входа? да → два пакета: сайт (site) + web-app (ux, ui), общий DESIGN.md
3. Сколько задач у сайта?
   ├─ одна задача, один источник спроса, срок кампании → landing-site
   │   ├─ услуга, заявка или звонок (РФ) ................ landing-lead-services (3.1)   приоритет 1 заказчика
   │   │     горячий трафик (карты, бренд) → form-first; холодный → sales-longread; расчёт сложный → quiz-funnel
   │   ├─ цифровой продукт: регистрация, пробный, демо ... landing-saas (3.2)            приоритет 2 заказчика
   │   ├─ физический товар без каталога ................ landing-product (3.3)
   │   ├─ запуск, акция, «вау», бренд .................. landing-campaign (3.4), L2       приоритет 3 заказчика
   │   │     несколько глав-страниц → campaign-site
   │   ├─ событие или вебинар .......................... landing-event
   │   ├─ курс .......................................... landing-course
   │   ├─ приложение .................................... landing-app
   │   ├─ продукта ещё нет .............................. landing-waitlist
   │   └─ материал за контакт ........................... landing-lead-magnet
   └─ несколько задач, постоянное присутствие, поиск → многостраничник
       ├─ локальные или профессиональные услуги ......... services-site                 приоритет 1 заказчика
       ├─ SaaS или цифровой продукт ..................... saas-marketing-site           приоритет 2 заказчика
       ├─ компания, B2B, производство, холдинг .......... corporate-site                приоритет 4 заказчика
       ├─ работы — главный довод ....................... portfolio-site
       ├─ регулярное событие ........................... event-site
       ├─ человек-эксперт .............................. personal-brand-site
       └─ школа, много программ ........................ school-site
4. Для каждой страницы карты (G): page_type → macro-действие → форма (C) → уровень (creative) → профиль бюджета (P)
5. Проверка: у каждой формы есть thank-you-page и ссылка на политику; у сайта — legal-page и 404
```

Признаки для ветки 3 [практика]: одностраничник выбирают при одном действии, одном сегменте и рекламном трафике; многостраничник
— при нескольких услугах или сегментах, поисковом спросе на каждую услугу (`seo-landing-page`), нужде в доверии
(команда, лицензии, отзывы) и постоянном присутствии. Услуги с поиском «услуга + город» почти всегда тянут
многостраничник: одна страница не ответит на десятки запросов (H, G).

## 7. Пограничные случаи

1. **Лендинг внутри многостраничника.** `page_type` лендинга (например, `landing-course` на `school-site`), `site_type`
   сайта; логотип ведёт на главную, шапка упрощена (путь к разделам не мешает действию), подвал с реквизитами и политикой
   сохранён; в карте сайта — отдельный шаблон (G). NN/g против «микросайтов», оторванных от родителя [мнение: NN/g 1996,
   устарело по дате, механизм в силе].
2. **«Сайт + личный кабинет».** Два пакета задач с общим DESIGN.md и разными TASK.md
   (`../kimi-research/07-brief-handoff/01-from-app-description-to-brief.md §2.2`); вход в продукт — `log-in` (micro) в шапке сайта;
   регистрация с сайта — `sign-up`, дальше — онбординг ux.
3. **Интернет-магазин против промо.** Каталог, корзина, оформление — вне рамок; промо-страница товара и кампании — в рамках
   (`landing-product`, `landing-campaign`); переход «Купить» к продавцу или на маркетплейс — ссылка, не корзина.
4. **Сайт-история, кино-скролл, 3D-мир** — `macrostructure: scroll-story` + L2 у `landing-campaign` или `landing-product`
   (у kimi — `landing` + `decisions.motion: cinematic`); тип не меняется.
5. **Вебинар против конференции** — один `page_type: landing-event`; различия — в форме (короткая регистрация против
   программы со спикерами) и действии (`event-registration` против `purchase`).
6. **Страница-мост (bridge page), «всё в одной ссылке» (мультиссылка)** — не типы базы: Google Ads не пускает страницы,
   «созданные только чтобы отправить дальше» [документация: Google Ads Policies]; мультиссылка для соцсетей — кандидат в v1.
7. **Студия: главная = портфолио.** Корпус text размечает главные студий как `portfolio-page`; у site допустимо и так, и
   `home-multipage` + `site_type: portfolio-site` — важен сюжет «работы первыми».

## 8. Что говорят словари рынка и генераторов

- **Unbounce** делит лендинги на 13 «типов», смешивая цель (lead capture, click-through), форму (long-form, video) и роль
  (homepage, 404, thank you) [мнение вендора] (2024-06-07); у site это три оси: `page_type`, `macrostructure`, служебный
  `page_type` (`crosswalk.tsv`).
- **Tilda Education**: «формула конверсионного лендинга» из 5 групп (первый экран → рассказ о проекте → понятные выгоды →
  блоки доверия → целевое действие) и 25 функциональных блоков [мнение вендора] (2024) — совпадает с группами ролей
  `section_role.group` (promise → value, offer → proof, risk → action).
- **ui-ux-pro-max `landing.csv`**: 115 уникальных терминов 34 паттернов покрыты словарём полностью, но задействуют 26 из 42 ролей; ролей
  `guarantee`, `objections`, `offer`, `services`, `awards-press`, `integrations`, промежуточного `cta-band` нет ни в одном
  паттерне [проверено: опыт B/01].
- **Корпус text** (177 страниц): `page_type` размечен 13 значениями, все совпадают с id site; главные студий размечены как
  `portfolio-page` (§7.7).

## Частые ошибки

1. Генератор выбирает «SaaS-скелет» для любого брифа: у лидогенерации услуг нет цены «от», этапов, реквизитов и гарантий.
2. Главная сайта используется как посадочная под рекламу: смешаны навигация и одно действие, message match ломается.
3. Кампания L2 без смысла в HTML: образ есть, а что продаётся и куда нажать — только в canvas или после прелоадера.
4. Лендинг без `thank-you-page`, политики ПД и 404 — «одна страница» понята буквально.
5. Выдуманные типы и id («promo-landing», «final_cta», «how») вместо словаря — ломают связку плана, ассетов и текстов
   (опыт B/03: 4 из 8 id секций брифа «Кварц» самодельные).
6. Всплывающее окно захвата на трафике Директа — нарушение правил площадки (кроме формы связи).
7. «Контакты» — только форма без телефона и почты; реквизиты спрятаны или отсутствуют там, где Директ их требует.
8. Страница-клон «услуга × город» с заменой топонима — спам-сигнал (H), а не `seo-landing-page`.
9. Цены скрыты «по запросу» на B2B и в услугах — посетитель уходит к конкуренту (NN/g 2013).
10. Интернет-магазин собирается как лендинг: корзина, каталог и оплата — вне рамок и без канонов ux.
11. Тип выводится из отрасли («банк → корпоративный»), а не из действия: у банка есть и продуктовые лендинги
    (alfabank.ru/everyday/debit-cards/alfacard/ — `landing-product`).

## Чек-лист

- [ ] У брифа есть главное действие из `action` и его порог?
- [ ] `site_type` и `page_type` каждой страницы — id словаря (проверено `vocab_lint.py`)?
- [ ] Одна посадочная — одно macro-действие, вторичные — только micro?
- [ ] Есть `thank-you-page` у каждой формы и `not-found-page`?
- [ ] Политика ПД доступна со страницы каждой формы (152-ФЗ ст. 18.1 ч. 2)?
- [ ] Реквизиты в подвале для лидогенерации услуг и тематик Директа?
- [ ] На трафике Директа нет pop-up и pop-under, акция из объявления есть на странице?
- [ ] Главная многостраничника отвечает «кто вы, что делаете, куда идти», а реклама ведёт на свой лендинг?
- [ ] У SaaS есть цены (или примерные цены), интеграции, безопасность, сценарии по сегментам?
- [ ] «Контакты»: телефон, почта, адрес, часы, срок ответа; ссылка в шапке и подвале?
- [ ] Лендинг внутри сайта связан с ним (логотип → главная, подвал с реквизитами)?
- [ ] Магазин и ЛК вынесены из пакета сайта?

## Открытые вопросы и противоречия

1. **NN/g против «вау»**: главная — минимум движения и без заставок (NN/g 2024) против цели заказчика «насыщенно»;
   позиция: главная многостраничника L1, L2 — кампании и студии по решению (creative решает уровни).
2. **GOV.UK против маркетинга** на 404 и «спасибо»: запрет юмора и обязательная ссылка на отзыв — нормы госуслуг; для сайта
   `[спорно]`, решает голос бренда (text) и F.
3. **Длина по типам** в §3 — ориентир по механизму, не замер: норму задаёт C по `pages.csv` M; `landing-waitlist`,
   `landing-lead-magnet`, `comparison-page`, `team-page`, `reviews-page`, `thank-you-page`, `legal-page` — без проверенных
   живых примеров на 2026-09-24 (ждут выборки M).
4. **Реферальная страница, мультиссылка, страница акции партнёра** — нет id; кандидаты в v1 (J), если заказчику нужны.
5. **Сравнение с конкурентом** (`comparison-page`): допустимость по 38-ФЗ ст. 5 (некорректное сравнение) — вопрос I.
6. Источник NN/g о подсайтах — 1996 год; механизм подтверждают более новые правила «логотип → главная» (ux), но
   прямого свежего исследования по лендингам внутри сайта не найдено.
