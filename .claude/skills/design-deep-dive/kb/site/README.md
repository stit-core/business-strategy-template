## Как пользоваться (для агента)

Единица базы: папка → `README.md` (файлы и выжимка на 10 строк) → файл → «Выжимка для агента» (15–40 правил с меткой и
`→ §`) → разделы → «Частые ошибки» → «Чек-лист» → «Открытые вопросы и противоречия» → «Источники»; большой файл читай нужным
разделом (`grep -n '^#'` → `sed -n`). Обозначения: `03/01 §3.2` — папка `03-…`, файл `01-…`, раздел 3.2 (`§2 п. 3` — пункт
списка); `[проверено]` — опыт `99-raw/experiments/C/01-…`; `[V:<id> mm:ss]` — дайджест `91-videos/digests/<id>.md`;
В-NN, С-NN — строки реестра аудита; `step:<id>` — шаг процедуры 10/01; `SITE-<БЛОК>-<NN>` — пункт чек-листа 09/02; `SG-*` —
строка ворот `page-gates.yaml`; `AIL-NN` — маркер `ai-landing-markers.yaml`; `DEF-NN` — дефект 09/02 §4; `LR-RU-NN`,
`LR-EU-NN` — требование `legal-requirements.yaml`; `SITE-R-01…08` — оси `site-rubric.json`; `<page_type>@L<n>` — профиль
`budgets.yaml`. Серьёзность — по маршруту «визит → действие»: **B** — ломается действие, закон или посетителя обманывают
(страница не отдаётся); **S** — трение, потеря доверия, исход хуже профиля (исправить или записать `x-gate-exception` в плане);
**D** — улучшение. Чужой id — с пространством имён (`block:`, `slot:`, `section-role:`, `fact:`, `effect:`, `copy-rule:`,
`task:`, `recipe:`). Два файла расходятся — действует «Реестр разрешённых противоречий» ниже. Схемы и образцы — v1 в
`10-playbooks-contracts/`: файл другой версии `site_validate.py` не принимает.

### Сценарий 1. Собрать сайт с нуля

Процедура 10/01 — 13 шагов «шаг → артефакт → проверка → дефекты DEF, которые шаг предотвращает»; пропуск по типу заказа —
10/01 §1.2; шаги `intake`, `proof`, `page-plan`, `plan-check`, `gates` не пропускаются никогда.

1. **Бриф** (`step:intake`, 10/01 §2): поля, вопросы, минимум по типу — 01/03; схема `10-playbooks-contracts/schemas/site-brief.schema.json`,
   образец — `10-playbooks-contracts/examples/lead-services-otves/site-brief.yaml`. ≤ 7 вопросов за раз (о подаче ≤ 2), у каждого
   умолчание; пустое поле — допущение «Going with». Проверка: `python3 ../../scripts/site/site_validate.py site-brief.yaml` (SB-*).
2. **Доказательства** (`step:proof`, 10/01 §3): анкета `../text/02-strategy-messaging/proof-intake.md` → `facts.yaml`
   (`../text/02-strategy-messaging/facts.schema.yaml`); подлинность и сбор — 08/02 §1, §5; честные замены — 05/02 §1.
3. **Тип сайта и уровень** (`step:site-type`, 10/01 §4): дерево — 02/01 §6; плейбук — 10/02 (9 посадочных) или 10/03 (7
   многостраничников); уровень — решение 20: `python3 ../../scripts/site/page_gates.py --resolve landing-lead-services --site-level L1
   --hot-mobile-share 0.6 --price-band mid`.
4. **Карта** (`step:site-map`, 10/01 §5): 06/01 (карты по типам, шаблоны, модель контента), 06/02 (навигация, перелинковка,
   адреса, языки); схема `10-playbooks-contracts/schemas/site-map.schema.json`; образец —
   `10-playbooks-contracts/examples/corporate-b2b-stalkon/site-map.yaml`. У лендинга карты нет — `pages.list` брифа.
5. **План каждой страницы и шаблона** (`step:page-plan`, 10/01 §6; 12 подшагов — 04/03 §5): цель, трафик, осведомлённость → три
   формы страницы из разных семейств → политика первого экрана → роли → блоки → слоты → факты, действия, события. Читать: 03/01
   (порядок), 03/02 (длина, цель, объявление), 03/03 (первый экран, телефон), `04-blocks/blocks.yaml` и 04/01–02 (блоки), 05/01 и
   `05-conversion-funnels/lead-forms.yaml` (призывы, формы), 05/02 (доказательства, цены), 07/01 и `head-kit.yaml` (SEO), 07/02
   и `crawlers.yaml` (GEO), 07/03 и `budgets.yaml` (бюджет), 07/04 и `events.yaml` (события), 08/01 и `legal-requirements.yaml`
   (право), 08/03 (доступность). Схема `10-playbooks-contracts/schemas/page-plan.schema.json`.
6. **Сёстры** (`step:sister-sync`, 10/01 §7): copy-deck text по `section_id` и `slot_id`
   (`../text/10-templates-recipes/copy-deck.schema.json`), treatment creative (`treatment:1`), план ассетов —
   `python3 ../../scripts/site/plan_to_assets.py plans/home.yaml --out asset-plan.home.yaml --check`, 3D — `recipe:` 3d.
7. **Входной контроль** (`step:plan-check`, 10/01 §8): `python3 ../../scripts/site/site_validate.py <папка проекта>` (PJ-*, SB-*, SM-*,
   PL-*) и блок SITE-PRE (09/02 §2): непройденный B — не собирать.
8. **Пакет для кода** (`step:package`, 10/01 §9): после приёмки макета на холсте —
   `python3 ../../scripts/project/ready.py build <slug> <surface>` → манифест `design/<surface>/ready.yaml` (единицы, `open`,
   пункты `after_build` с блоками I–L); свежесть — `ready.py check`. Многостраничник — единицы по `build_order`, первой —
   главная.
9. **Сборка, ворота, правки, приёмка, измерение** (10/01 §10–§11): страницы собирает `<org>/site` из снимка стратегии, ворота —
   `page_gates.py --brief --plan --ready` (сценарий 2), дефект файла стратегии — правка здесь и новый снимок (сценарий 3);
   заглушек нет (DEF-48); цель — успех сервера (у формы без JS — визит «спасибо» после 303); A/B — только если
   `python3 ../../scripts/site/ab_plan.py size --base 0.03 --mde-rel 0.2 --visits-per-day 300` даёт выполнимую длительность;
   редизайн — по частям.

### Сценарий 2. Проверить готовую страницу

Порядок (09/02 §1.4; 09/03 §1.1): **план (SITE-PRE) → ворота → маркеры и сверка фактов → эксперт → судья → люди**; отдельная
сессия, свои замеры, отчёт исполнителя не принимается, ноль находок — неудачная проверка.

1. **Замер** (`free -g` ≥ 3 ГБ; утилита берёт замок браузера сама): `python3 ../../scripts/site/page_anatomy.py URL OUT --mobile --inp --label
   <page_type>` и десктоп; исходы — `python3 ../../scripts/ai-media/page_accept.py URL --out DIR --mobile --throttle` (блокировку site берёт
   сама). Исходы — с троттлингом, вес — отдельно без него, CLS — прокруткой всей страницы (09/02 §6.3).
2. **Боты и SEO**: `python3 ../../scripts/site/geo_probe.py URL --out DIR --render`; многостраничник — `python3 ../../scripts/site/ia_probe.py
   https://site --out DIR`. **Контраст по узлам**: `python3 ../../scripts/site/run_axe_targets.py ID URL ru OUTDIR`.
3. **Ворота**: `python3 ../../scripts/site/page_gates.py --profile <page_type>@L<n> --anatomy OUT --accept DIR --geo F --ia F --axe F
   --plan plan.yaml --html page.html --jurisdiction ru` → `accepted` / `accepted_with_notes` / `blocked` (63 строки v1.3; SG-PERF-16 — постер видео-hero и LCP — утилитой не проверяется, вручную).
4. **Чек-лист** SITE-* (09/02 §3; 248 пунктов): B из DOM и SCR — подтвердить кадром или сырым HTML; быстрый набор (09/02 §7, 23
   пункта) — только для итераций; проверки ux — только через `09-ai-generation-evaluation/ux-marketing-profile.tsv`.
5. **Маркеры** `09-ai-generation-evaluation/ai-landing-markers.yaml` (09/01 §3–§4): маркер ловит решение без причины, `allow` в
   брифе или плане делает приём законным. **Факты**: каждое число, отзыв, логотип, цена — слот `data` с `fact:` (SITE-PRF-01);
   тексты — `../../scripts/text/claims_check.py`.
6. **Эксперт** (09/03 §2): восемь вопросов, шесть линз, конгруэнтность, прокси пятисекундного теста; находка — что, где,
   правило, доказательство, серьёзность, наименьшая правка; ≤ 12 за проход.
7. **Судья** `09-ai-generation-evaluation/site-rubric.json` (09/03 §4–§5): другого семейства, без контекста создания; 3 прогона —
   сортировка, 11 — решение; SITE-OUT-10 — оси ясности, пути к действию и честности ≥ 3.
8. **Вердикт**: 0 непройденных B; S исправлены или в `x-gate-exception` (причина, автор, срок); D — списком; текст, визуал,
   ассеты — у владельцев (`COPY-*`, `CRV-*`, приёмка ai-media и 3d); ворота страницы выше ворот эффектов и ассетов.

### Сценарий 3. Исправить сгенерированную страницу

1. **Находка → DEF-NN** (09/02 §4: «Предотвращает шаг», «Ловят», «Маркер»): выдуманный отзыв — DEF-06 (`step:proof`), шаблонный
   порядок секций — DEF-02 (`step:page-plan`), призыв под баннером на телефоне — DEF-08 (`step:build-loop`).
2. **Правка — в артефакт шага, где дефект рождается** (бриф, `facts.yaml`, карта, план, copy-deck, treatment), а не только в
   вёрстку; ворота — последний рубеж. Один дефект — одна правка, ≤ 7 пунктов за итерацию (10/01 §10.3).
3. **Пересборка и регресс**: `site_validate.py` по проекту → пакет `ready.py build` → сборка `<org>/site` по новому снимку →
   полный повтор сценария 2; вердикт — по новому прогону. Две итерации без прогресса — менять стратегию (10/01 §10.3).

## Выжимка: 56 правил и 15 «практика и спорное»

Отбор — кандидаты аудита (отчёт X §5) после пересчёта X2 и X2b; каждое правило сверено скриптом S2 с файлом и разделом (разделы
и числа). В основном блоке — `[стандарт]`, `[документация]`, `[консенсус]`, `[исследование]` с числом, `[проверено]` (у
составного правила — метка каждой части); `[практика]`, `[кейс]`, `[спорно]`, `[мнение вендора]` — блок «Практика и спорное».

**1. Бриф** (`step:intake`, `step:proof`)

1. **Бриф — один YAML по схеме v1**; холст получает его проекцию (вход холста по `x-canvas-map`), код — сам бриф снимком;
   открытые вопросы в проекцию не уходят. `[проверено]` → 01/03 §1, §7; `references/claude-design.md § Вход холста`
2. **Ни одного числа, отзыва, логотипа, рейтинга, цены и человека не из `facts.yaml`**: нет факта — нет блока; обязательный вид
   — факт или `missing[].blocking: true`, иначе страница не публикуется. `[проверено: A/01 N1, N12; E/03]` → 01/03 §2.7, §6; 08/02 §1
3. **Целевое действие — одно macro-id** пространства `action`; вторая цель — `secondary_actions`, иным стилем.
   `[проверено: A/01 N2, N16]` → 01/03 §2.3
4. **Стимул — только со сроком**: `offer.incentive_ref` требует факта с `valid.until`; таймер без реальной даты запрещён.
   `[проверено: A/01 N7, N13]` → 01/03 §2.5

**2. Тип сайта и карта** (`step:site-type`, `step:site-map`)

5. **Главная многостраничника — маршрутизатор** («кто вы, что делаете, куда идти»), не посадочная: рекламу — на отдельную
   посадочную. `[исследование: NN/g 2024]` `[консенсус]` → 02/01 §4.1; 03/02 §3.1
6. **Карта — до планов страниц**: шапка, подвал, крошки, поиск — один раз в `site-map.chrome`; у раздела с подстраницами — хаб.
   `[консенсус: NN/g]` `[стандарт: WCAG 3.2.3, 3.2.6]` → 06/01 §1, §3.4; 06/02 §1.5
7. **У каждой индексируемой страницы ≥ 1 входящая ссылка**; меню, крошки, пагинация — `<a href>` в HTML сервера.
   `[документация: Google, Яндекс]` `[проверено]` → 06/02 §3.5–§3.6
8. **Логотип слева ведёт на главную на каждой странице**; крошки — с глубины ≥ 2, на телефоне одной строкой; навигация только за
   гамбургером на десктопе или за ⌘K — нет (находимость 27 % против 48 %, 179 участников). `[исследование: NN/g 2016–2024]` →
   06/02 §1.1–§1.3, §2.1
9. **Адреса — строчные, через дефис, глубина ≤ 3 сегментов**; смена — 301 на равноценный; второй язык — `/en/`, переключатель —
   самоназвание, без автоперенаправления. `[документация: Google, Яндекс]` `[проверено]` → 06/02 §4–§5
10. **Серия «услуга × город» — только с локальными фактами** и местом в иерархии; клон с заменой топонима — дорвей.
    `[документация: Google spam policies]` → 06/01 §3.6; 07/01 §5.2

**3. План страницы** (`step:page-plan`)

11. **Порядок секций — из вопросов посетителя** (тип → осведомлённость → источник → макроструктура → роли); «hero → фичи →
    отзывы → тарифы → CTA» без причины — дефект (1 из 30 живых страниц). `[консенсус]` `[проверено]` → 03/01 §3.1
12. **Первый экран — «что это, для кого, что сделать» и обещание продолжения**: 57 % времени — выше сгиба, 74 % — в двух
    экранах, 81 % — в трёх; hero без признака продолжения — ложный пол (6 из 8). `[исследование: NN/g]` → 03/03 §1.1, §2.2
13. **Ядро первого экрана — ≤ 40 слов** (100 % лидеров RU, 88–92 % EN). `[проверено: text D]`
    (`../text/03-corpus-measured/02-measurements.md` §2.5) → 03/03 §1.2
14. **Первый экран проверять с баннером cookie на 390×844**: у 15 из 27 живых страниц его перекрывает баннер или окно, у 3
    баннер прячет призыв. `[проверено]` → 03/03 §1.4
15. **Посадочная продолжает обещание объявления** (предмет, цена, город, акция); акция из объявления — на странице.
    `[документация: Яндекс Директ, Google Ads]` → 03/02 §3.1; 05/03 §2.1
16. **На телефоне контент равен десктопному** — сворачивать, а не вырезать; порядок DOM = визуальный.
    `[документация: Google mobile-first]` `[стандарт: WCAG 1.3.2]` → 03/03 §5.1–§5.2
17. **Липкие слои не закрывают фокус целиком** (`scroll-padding`) `[стандарт: WCAG 2.4.11]`; шапка, панель и баннер вместе
    ≤ 20 % высоты телефона `[практика]` (живые страницы: медиана 7,7 %, максимум 30,6 % `[проверено]`) → 03/03 §4.2, §4.4

**4. Блоки**

18. **Блок — только из `blocks.yaml` v1 (84)**; в hero — словесный H1 с категорией, ровно один H1; `<header>` — только шапка
    сайта, секции — `<section>` в `<main>`. `[стандарт: WCAG 1.3.1]` `[проверено]` → 04/01 §1.3, §3.2
19. **Цена у лидогенерации — во 2–4-й секции**; у B2B — цены типовых сценариев, не «по запросу». `[исследование: NN/g 2013]`
    `[проверено: C/01 — медиана позиции 0,31]` → 03/01 §3.2; 05/02 §2.1–§2.2

**5. Конверсия и формы**

20. **Одно действие — много мест призыва** (шапка, hero, после цены и доказательств, финал, липкий на телефоне); второй путь —
    иным стилем; «одна primary» — правило приложения. `[консенсус]` `[проверено: M — медиана 4 призыва]` → 05/01 §1; 02/03 §4
21. **Подпись призыва называет результат нажатия**, одно имя действия на странице и в письмах («Подробнее» — слабый запах;

## Как обновлять

Порядок — `PLAN.md` «Как расширять базу». Коротко: правило — в файл владельца темы (таблица владения `_common.md`) с меткой и
`→ §`, в выжимку файла и при необходимости сюда; новый id — через `vocabulary.yaml` (только добавления и `deprecated`) и
строки `crosswalk.tsv`, проверка `vocab_lint.py` и `vocab_lint.py --check-crosswalk`; блок — `blocks.yaml` и
`site_validate.py --all`; пункт чек-листа — Markdown 09/02 →
`checklist_export.py`; ворота — `page-gates.yaml` → `page_gates.py --selftest`; требование права — `legal-requirements.yaml` с
редакцией закона; боты — `crawlers.yaml` раз в квартал. После правок: `python3 ../../scripts/maint/orch_check.py all`,
`python3 ../../scripts/maint/check_links.py`, `python3 ../../scripts/site/site_validate.py --all`, `python3 ../../scripts/site/checklist_export.py
--check`.
