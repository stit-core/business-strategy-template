# Словарь перевода жаргон → язык бизнеса

Словарь один на оба режима (`.claude/rules/guiding.md` §4):

- **клиентский режим** — оркестратор общается с клиентом **только** правой
  колонкой; жаргон — внутренняя кухня, клиенту не звучит;
- **аналитический режим**, в котором работают аналитик и дизайнер, — слово
  профессии остаётся (бриф, арт-дирекция, дизайн-система, макет), правая
  колонка даёт ему пояснение в полфразы, а идентификатор, статус латиницей
  и имя файла идут в скобках после слова и только когда они человеку нужны —
  вызвать команду, найти файл.

Разделы после таблиц — от «Главное про метрики» до конца — о разговоре с
клиентом.

## Сущности

| жаргон | бизнес |
|---|---|
| слой / артефакт / kind | «тема» / «то, что мы собираем» |
| business / profile | «ваш бизнес» / «чем заняты и как зарабатываете» |
| offering / channel | «что продаёте» / «как привлекаете и доставляете» |
| competitor | «кто на рынке делает похожее» |
| current-metric | «ваши числа сейчас» / «текущие показатели» |
| business-problem (реестр) | «задачи для бизнеса» / «что решаем и за что отвечаем»; их может быть несколько |
| segment | «группа ваших клиентов» (по общим работам, не по возрасту/полу) |
| job / работа | «что клиент пытается сделать» |
| solution | «чем он это делает сейчас» |
| segment-problem / трение | «где клиенту тяжело» |
| factor (SWOT) | «сильные и слабые стороны, тренды и угрозы» |
| strength / weakness | «сильная сторона» / «слабая сторона» |
| trend / threat | «куда движется рынок» / «что угрожает» |
| bet | «идея-ставка» / «за счёт чего сделаем шаг» |
| goal | «цель» / «к чему стремимся» |
| metric | «показатель» / «число, по которому поймём» |
| baseline / target | «сейчас столько» / «хотим столько» |
| balancing / guardrail | «что нельзя ухудшить» |
| subject | «на чьё поведение влияем» |
| motivation | «что им важно / что их беспокоит» |
| hypothesis | «наша ставка: если сделаем X — будет Y, потому что Z» |
| task | «как проверим» |
| vision / capability (продукт) | «зачем продукт и для кого» / «что продукт умеет» |
| surface | «где продукт работает» / «точка, где клиент пользуется продуктом» (сайт, мобильное приложение, бот, админка, API) |
| web-kind (`landing` · `site` · `app`) | «лендинг» / «сайт из нескольких страниц» / «веб-сервис, личный кабинет» |
| object / action | «вещи, с которыми работает пользователь» / «что он с ними делает» |
| постура | «сколько времени пользователь проводит в продукте и основная ли это работа» |
| project-map / стык продуктов | «как ваши продукты связаны» / «эти два продукта обмениваются данными» |

## Поля и процедуры

| жаргон | бизнес |
|---|---|
| slug / kind / status | не упоминается |
| draft / stable | «в работе» / «закрыто» |
| proposed | «предложено — ждёт вашего решения» |
| assumed | «черновик исполнителя — вы его ещё не смотрели» |
| checked | «проверено — осталось ваше „утверждаю“» |
| approved | «утверждено» |
| гейт | «стоп-правило» — то, без чего дальше не идём: ваше «да» тратам, подтверждённые факты, принятый макет |
| находка проверки (код правила, error · warning · hint) | «что нарушено, чем это грозит и как исправить» |
| attribution | «как поймём, что это наш вклад, а не сезон/рынок» |
| acceptance | «как договоримся считать, что получилось» |
| source истины | «откуда берём это число» |
| promote draft → stable | «закроем эту тему?» |
| phase / фаза / режим | «тема» / «блок» |
| research / рой | «помощники поищут в интернете» — с согласия клиента (`research-business.md`) |
| escalation | «передать аналитику» |
| branch / push | «отдельная папка для аналитика» / «отправить» |
| исполнитель / имя скила / файла | не упоминается (клиент видит одну беседу) |

## Главное про метрики (проговаривать)

- «Число — это **цель**, к которой стремимся, не обещание. Сделать проект
  целиком — обещаем; что число точно сдвинется — нет, на это влияет и
  внешнее.»
- Не «целевое значение метрики» — а «к какому числу хотим прийти».
- Не «критерий приёмки» — а «как заранее договоримся, что считать
  успехом, чтобы потом не спорить».

## Чего никогда не говорить

- «Это draft / stable», «slug в kebab-case», «по методологии…».
- «Гарантируем рост числа» (метрика — цель, не гарантия).
- «Spawn agent / рой», «передаю в скилл X».

## Как формулировать критерии и anti-patterns

Вместо «нарушен критерий (про мир, не про вас)» →
> «Это звучит как ваше действие, а не как то, куда движется рынок. Может,
> это скорее идея, что нам сделать?»

Вместо «метрика подана как гарантия» →
> «Давайте запишем это как цель, к которой стремимся. Гарантировать само
> число рискованно — на него влияет и то, что вне нашего контроля.»

## Если клиент использует жаргон

Подхватываем его язык, не «переучиваем», но остаёмся на пол-шага проще.
