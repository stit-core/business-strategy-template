# REVIEW

> Последний результат проверок и приёмки макета одной поверхности: паспорт последней итерации холста, вердикт и
> одобрение заказчика по каждой странице или экрану, итог по пунктам критериев приёмки. Файл —
> `docs/projects/<slug>/design/<surface>/review/REVIEW.md`; рядом в той же папке — машинные отчёты этой итерации
> (проверки, метки находок, кадры, сравнение кадров, свежий аудит). Одобрение привязано к отпечатку артбордов и
> источников своей страницы или экрана: правка единицы после одобрения его снимает — так статус всегда описывает
> текущий макет, а пересборка входа, служебные даты `ARTIFACTS.md`, запись `starter` и правка соседней единицы
> одобрение не трогают.

## Что REVIEW НЕ

- ❌ Журнал итераций: файл — последний результат, прошлые итерации — в git; папок по итерациям нет.
- ❌ Список критериев приёмки: его собирает сборщик входа холста
  (`docs/projects/<slug>/design/<surface>/input/ACCEPTANCE.md`) по роду поверхности и уровню; здесь — итог по пунктам.
- ❌ Кадры PNG: они вне git и пересоздаются из HTML-копий холста.
- ❌ Вердикт или одобрение, поставленные руками: вердикт следует из проверок, одобрение — слово заказчика.

## Паспорт итерации

Файл начинается с передней части YAML — паспорта последней итерации (cd 06/03 §7):

```yaml
---
stage: <этап>                          # mockup · fix · widths · motion · audit · acceptance
model: {id: <модель>, effort: <уровень>}
artifacts:                             # адреса и релизы типов — как в ARTIFACTS.md на момент итерации
  design: {url: <ссылка>, version: <version id публикации>, release: <релиз типа>}
  design_system: {url: <ссылка>, version: <version id публикации>, release: <релиз типа>}
  contract: <версия контракта>
synced:                                # слияние живой версии перед публикацией
  read_at: <дата>
  customer_edits: 0                    # сколько правок заказчика нашлось в живой версии
  lifted: {tokens: 0, texts: 0, facts: 0, plan: 0, assets: 0}   # сколько правок поднято в источник по роду правки
  force: false                         # true — только по прямой просьбе заказчика отбросить названную версию
checks: {critical: 0, major: 0, minor: 0, W: 0, markers: 0, rubric_min: {}, diffshots_unexpected: 0}
items: {}                              # пункты пакета правок: {N1: fixed · not-fixed · blocked · regressed}
decision: <решение>                    # accept · fix · rollback · change-strategy · stop
reason: <причина решения одной строкой>
hashes: {canvas: <отпечаток исходников холста>, input: <отпечаток входа>}
---
```

Числа паспорта — из файлов итерации (ответы инструмента, отчёты проверок, сравнение кадров), а не из пересказа. W —
вес открытых находок, по нему судят о прогрессе итераций (cd 06/03 §5).

Ответ инструмента называет два разных числа, у каждого своё поле: `version` — версия самого артефакта, `version id`
ответа публикации этой итерации, записывается только здесь; `release` — релиз типа, значение «release» в строке типа
ответа чтения артефакта, то же, что в колонке «релиз типа · контракт» `ARTIFACTS.md`. Перепутанные числа прячут дрейф
типа: по `release` видно, на какой версии типа получен результат.

## Приёмка

- `страница или экран` — id страницы плана или slug экрана · обяз.
- `артборды` — артборды холста этой страницы или экрана: файлы исходников `canvas/project/<Имя>.dc.html` через запятую
  (имена даёт холст); отпечаток одобрения единицы считается по её артбордам и источникам · обяз.
- `вердикт` — `accepted`: нет непройденных пунктов B и S; `accepted_with_notes`: B нет, каждое S исправлено или
  записано; `blocked`: есть непройденный B · обяз.
- `одобрил` — роль заказчика, одобрившего страницу или экран; `дата` — когда · обяз. при `accepted` и
  `accepted_with_notes`.
- `отпечаток` — отпечаток одобрения: артборды единицы и её источники — у страницы план, её тексты, план ассетов и файлы
  слотов, спецификация движения, факты, бренд и арт-дирекция; у экрана файл экрана, его блоки и каркас, его строки
  `texts.md`, бриф на вид; у обеих токены и карта решений ДС. Поля, правка которых не меняет ни макет, ни содержание,
  в отпечаток не входят: запись решения (статус, утверждение, `starter`) и машинное значение факта `machine` —
  проекция `canonical`, её равенство формулировке держит `claims_check.py lint-facts`. Текущий печатает
  `ready show <slug> <surface>` по колонке `артборды`; не совпал с текущим — одобрение снято · обяз.
- `открыто` — открытые `[PLACEHOLDER]` и демо-факты, пункты «после сборки»; последние уходят в манифест готовности
  поверхности (`ready.yaml`, `after_build`) · опц.

| страница или экран | артборды | вердикт | одобрил | дата | отпечаток | открыто |
|---|---|---|---|---|---|---|
| `<page-id или screen-slug>` | `<Имя>.dc.html`, `<Имя>.dc.html` | `accepted` \| `accepted_with_notes` \| `blocked` | <роль> | <дата> | <отпечаток> | <заглушки, демо-факты, «после сборки»> |

Пункт S записывается одним из двух способов: исключением ворот в плане страницы (`x-gate-exception` с `why`, `who`,
`until` — только для S) или строкой итога ниже с тем, кто его принял.

## Пункты ACCEPTANCE

- `id` — пункт критериев приёмки (`A1`, `I1`, …) · обяз.
- `страница или экран` — единица, к которой относится итог: непройденный пункт с единицей держит одобрение только
  этой страницы или экрана; пусто — пункт всей поверхности, он держит все принятые единицы; у пункта `ST-<экран>-…`
  единица — экран из id · опц.
- `где` — `макет` \| `после сборки` · обяз.
- `итог` — `пройдено` \| `не пройдено` \| `принято с записью: <роль>` \| `не проверялось: нет просьбы` \|
  `после сборки` · обяз.
- `доказательство` — кадр, отчёт проверки, строка файла · обяз. при `пройдено` и `не пройдено`.

| id | страница или экран | где | итог | доказательство |
|---|---|---|---|---|
| `<id>` | `<page-id или screen-slug>` \| — | `макет` \| `после сборки` | <итог> | <кадр, отчёт, строка> |

## Когда меняется

- Пишут этапы холста — макет, раунд правок, промежуточные ширины, движение, приёмка — и утилиты `kit` после
  каждой итерации. Проверки артефакта идут только по просьбе заказчика (`ARTIFACTS.md`, «Проверки макета»); без неё
  пункты, которым нужна проверка артефакта, получают итог «не проверялось: нет просьбы».
- `/design-audit` файл не пишет: он сверяет отпечаток одобрения с текущими артбордами и источниками единицы и вердикт —
  без открытых B и S без записи у этой единицы.
- Репозиторий кода и сквозной аудит считают макет принятым при `accepted` или `accepted_with_notes`, если отпечаток
  одобрения совпадает с текущим.
- У кабинета первые принятые экраны становятся эталонными — `starter` в `system.yaml`; одобрение эта запись не
  снимает.
